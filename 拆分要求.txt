目标：拆分后每个模块可独立进入开发，前后端可并行，模块间可按契约对接
================================================================================

0  系统当前功能具体逻辑
   - 从 project_ana.md 按模块裁剪，每个模块文档包含且仅包含该模块负责的功能规格
   - 保留完整的业务规则、页面交互、状态机、校验规则
   - 标注该功能涉及的跨模块调用点（调谁、被谁调、强/弱依赖）
   - 明确 V1/V2 边界，V2 功能仅做说明不展开设计

1  模块后端架构
   - 模块职责边界（负责什么 / 不负责什么）
   - 模块依赖关系（只能依赖谁、禁止依赖谁，参照代码依赖 DAG）
   - 包结构（api / controller / facade / service / mapper / entity / enums / convert / support）
   - 模块内分层规范（Controller 不编排业务、Service 不跨模块直连 mapper）
   - 错误码前缀与枚举范围

2  接口设计以及报文
   - 每个接口的完整定义：HTTP Method + URL + 请求体(ReqDTO) + 响应体(RespDTO/VO)
   - 请求体字段：字段名、类型、是否必填、校验规则、字典取值范围、示例值
   - 响应体字段：字段名、类型、说明、嵌套结构
   - 分页接口统一使用 pageNo/pageSize/sortBy/sortDir，标注默认值与上限
   - 导入/导出接口标注文件格式、模板字段、最大行数、异步阈值
   - 错误响应示例（含业务校验失败、权限不足、状态冲突等场景）

3  模块的表结构
   - 每张表的完整 DDL：字段名、字段类型、长度、NOT NULL、DEFAULT、COMMENT
   - 主键策略（自增/雪花/UUID）
   - 唯一约束（UK）、普通索引（IDX）、联合索引
   - 外键说明（逻辑外键，不建物理外键，但必须标注关联关系）
   - 审计字段统一规范：created_by / created_time / updated_by / updated_time
   - 流程类表必备字段：business_key / process_instance_id / current_task_id / status
   - 归属字段：owner_org_id 等
   - 分区/归档策略（如 audit_log 按月分区）

4  模块对外提供的接口（API / Facade）
   - 每个模块的 *Api / *QueryApi 接口清单（Java 方法签名级）
   - 方法名、入参 DTO、返回 DTO、异常定义
   - 调用约束（是否允许批量、是否幂等、是否有缓存）
   - 明确哪些是同步强依赖(S)、哪些是异步弱依赖(W)
   - 领域事件清单：事件名、payload 结构、发布时机（事务后）、消费方

5  接口契约要"字段级可执行"
   - 每个 DTO 字段必须标注：类型、是否必填、长度/精度、校验注解（如 @NotBlank / @Size / @Pattern）
   - 字典类字段必须标注字典编码和有效取值枚举
   - 金额/比例字段必须标注精度（如 DECIMAL(18,2)）和业务约束（如 >= 0）
   - 日期字段必须标注格式（yyyy-MM-dd / yyyy-MM-dd HH:mm:ss）和时区处理
   - 文件上传字段必须标注格式白名单、单文件大小上限、总文件数上限
   - 关联字段（如 customer_id）必须标注来源接口和校验逻辑

6  数据模型"约束级"定义
   - DDL 可直接执行建库建表（含 CREATE TABLE / CREATE INDEX / COMMENT）
   - 权限表（PT_ROLE_BIZ_SCOPE）的 DDL 与种子数据
   - 数据范围（DATA_SCOPE）枚举值必须映射到具体 SQL 过滤条件模板
     例：SELF_CREATED -> WHERE created_by = #{empId}
         ORG_SUBTREE -> WHERE owner_org_id IN (SELECT org_code FROM ext_org_info WHERE path LIKE CONCAT(#{orgPath}, '%'))
   - sys_control 表的维度与版本控制约束
   - 业务状态枚举必须映射到表字段取值（如 lead_status: DRAFT/PENDING/APPROVED/REJECTED）

7  并发、事务、一致性策略
   - 按场景标注事务边界：
     * 流程发起（业务主表保存 + Flowable startProcess 同事务）
     * 认领（cust_claim 插入 + touch_task 创建 同事务）
     * 批量导入（原子性：任一行失败整批回滚）
     * KPI 计算（批量写入 kpi_result + 更新 sys_control 同事务）
   - 并发控制：
     * 客户认领的争抢模式：乐观锁/唯一约束防重复认领同机构
     * 流程任务 Claim：依赖 Flowable TaskService.claim 的内置互斥
     * sys_control 版本更新：同维度同日期唯一约束
   - 幂等策略：
     * 导入批次号去重
     * 事件消费按 eventId 去重
     * 触达日志/照片上传请求去重
   - 最终一致性场景：
     * 流程结束通知（事务后事件）
     * 权限缓存失效广播（≤5分钟生效窗口）
     * 指标级联刷新（异步任务队列）

8  审计与合规"可核对"
   - 高危动作清单（每模块标注哪些接口属于高危）：
     EXPORT / IMPORT / DELETE / TRANSFER / EXECUTE_SQL / RECALC / PERMISSION_CHANGE / JOB_TRIGGER
   - 审计日志最小字段集：
     action / resource_type / resource_id / business_key /
     operator_emp_id / operator_org_id / request_time / ip / user_agent /
     before / after / reason（TRANSFER/DELETE/IMPORT/RECALC/CONFIG 必填）
   - 审计日志落库方式：同步写 audit_log 表 + 异步归档
   - 每个高危接口的审计记录示例（便于开发自测验证）
   - 权限变更可追溯：PT_ROLE_BIZ_SCOPE / PT_ROLE_RESOURCE 变更前后快照

9  初始化数据与迁移策略
   - 字典种子数据（sys_dict）：所有预置字典项的 SQL INSERT 脚本
     包括：行业类型、集团类型、客户类型、企业类型、岗位、业务种类、指标维度、计算频率等
   - 角色种子数据（PT_ROLE）：V1 默认角色定义
     系统管理员 / 客户经理 / 经营机构负责人 / 公司部人员 / 零售部人员 /
     中后台员工(资财) / 中后台员工(科技) / 中场支持部门秘书 / 中场支持部门人员 /
     授信审查人员 / 授信批复人员 / 分行行长
   - 资源种子数据（PT_RESOURCE）：所有接口资源的 RESOURCE_URL + RESOURCE_METHOD 登记
   - 角色-资源绑定种子数据（PT_ROLE_RESOURCE）：V1 默认角色权限矩阵对应的绑定关系
   - 角色-BizType-数据范围种子数据（PT_ROLE_BIZ_SCOPE）：按 2.1.2 矩阵生成
   - Flowable 流程定义初始部署：
     * 线索审批流程 BPMN XML
     * 资产投放审批流程 BPMN XML
     * 中场支持流程（场景A/场景B）BPMN XML
     * 触达任务流程 BPMN XML
     * 目标修正审批流程 BPMN XML
     * 分配关系调整审批流程 BPMN XML
   - 工作流配置种子数据：
     * biz_process_map 初始映射
     * wf_node_candidate_conf 节点候选人配置
     * wf_node_form_conf 节点表单绑定
     * wf_timeout_rule 超时规则配置
   - 工作日历初始数据（sys_calendar）：当前年度工作日/非工作日
   - 数据迁移策略：
     * 版本号管理（建议 Flyway / Liquibase）
     * 增量脚本命名规范：V{version}__{description}.sql
     * 回滚策略：每个迁移脚本必须有对应的回滚脚本或说明
