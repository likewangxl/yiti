# 零售经营总览：设计、数据口径与验收

## 面向领导的经营判断

本页服务分行行长、分管零售行领导与零售部门负责人。沿用分行经营总览的蓝紫视觉、中央陕西地图和两侧分析结构，但以独立 `retail-overview-v1` 表达零售业务。复用布局不等于复用全行指标。

| 领导需要判断什么 | 首屏证据 | 可推动的经营动作 |
| --- | --- | --- |
| 零售客户资产是否稳定增长 | 零售 AUM、储蓄余额、储蓄月日均、同口径趋势 | 判断客户资产沉淀与时点冲量的差异，要求机构解释波动 |
| 客户基础是否有质量 | 价值客户数、客户层级的人数与资产分布 | 对重点客群保有、升级和流失原因组织分析 |
| 规模能否转化为贡献 | 零售营业收入、收入目标完成与缺口 | 关注收入贡献与资产规模是否匹配，核对产品与客户经营原因 |
| 哪些机构贡献大、哪些需要推动 | AUM、净增、目标完成率的领先/落后排序 | 在同口径、同层级机构中确定督导对象，避免仅奖励规模大的机构 |
| 增长是否伴随风险 | 个人贷款余额、个贷不良率及变化 | 对资产质量恶化机构要求专题分析，结合风险部门明细核查 |
| 今天有哪些明确事项需要协调 | 来源明确的关注事项、数量、责任归属、期限 | 对客户流失、投诉处置、风险跟进等来源已确认事项推动闭环 |

AUM 是客户金融资产总量，不等于利润，也不与储蓄相加。贷款余额反映个人资产业务规模，不表示贷款质量好。不良率下降也可能来自分母扩张或处置；本页不据单一比率推断风险已经解除。机构排名不直接作为绩效结论，比较前需核对机构层级、目标口径、覆盖与统计期。

> 当前接口接入阶段：库内没有可核验的 AUM 构成来源，也没有经业务确认的价值客户门槛。运行页保留“零售 AUM”和“价值客户”卡片，分别显示“暂无数据源”和“口径未配置”；不以存款或贷款伪造 AUM。已接入的零售一般性存款余额、月日均、营业收入、个人贷款和个贷不良率继续按接口来源展示；其中存款余额/月日均的当前计算定义含 RAND()，须明确标注测试。

本轮不把营销电话次数、手机银行注册量、产品销量、内部审批单量放在第一优先级。代发客户、手机银行活跃、财富中收、贷款逾期与新增不良、投诉关闭率等适合后续基于可靠来源做专题明细；不能把当前客户分层或不良率替代这些尚未提供的指标。

## 内容与交互

1. 顶部保留原六项并补充月日均：零售 AUM、储蓄存款余额、零售营业收入、价值客户、个人贷款余额、个贷不良率。金额为亿元，客户为万户，比率为百分数。单项保留日期/较上期变化能力。
2. 左侧：储蓄经营（月日均与时点余额）、客户分层（层级名称/客户数/AUM）、重点经营关注。
3. 中央：授权机构在陕西的分布、来源指定范围的存款余额/月日均趋势；地图/城市选择只筛选机构分析，KPI 与趋势不变更原始范围。当前来源固定本级机构，不能称全辖汇总。
4. 右侧：按实际已绑定的存款余额/月日均或 AUM 切换对比，支持经营层级筛选；混合机构仅作数值对照，不求和；目标显示同口径实际、目标、完成率与差额，未接入时保留紧凑状态。
5. 机构详情仅展示本机构可得指标。未定位或缺城市资料的机构仍能通过列表查找；无本机构数据不复用全辖数值。
6. 目标必须同期间、同机构范围、同业务口径。目标金额直接标注“距目标”或“超目标”；目标有效而实际值缺失时显示“实际待更新”。真实比率可超过 100%，进度条仅视觉限制在 0–100%；目标缺失或不大于零不计算完成率。未提供时间进度基准时不自动宣判目标落后。
7. 关注事项展示来源给出的数量、责任和期限，整行可点击或通过键盘打开详情。详情展示事项、数量、责任、截止、授权范围和数据日期；有可用来源时展示事项说明与协调要求，缺失显示“未提供”。不自动创建任务、不按文案推断逾期，不把可能重叠的事项数量求和。
8. 桌面首屏优先完整呈现经营重点，地图与趋势保留可读高度。机构长列表使用有界滚动或分页，避免 114 条混合机构撑高整屏；客户与目标缺源提示紧凑展示。窄屏自然堆叠，长机构名不截断关键身份，面板不得重叠。

## 零售绑定契约

使用现有大屏保存、预览、发布、版本和数据源查询接口，无新增表或业务 REST 路径。`presentation={"type":"CODE","template":"retail-overview-v1"}` 必须显式保存；不得根据标题包含“零售”改写指标含义。零售模板使用 RETAIL 屏和 RETAIL 数据源；分行和零售槽互斥，共享 `branches` 仅用于机构目录。

| 槽位 | 字段 | 口径要求 |
| --- | --- | --- |
| `retailAum` | `value`，可选 `change/date` | 零售客户金融资产总量；资产纳入范围与去重口径由业务源确认 |
| `retailDeposit` | 同上 | 储蓄时点余额；不得映射全行存款 |
| `retailDepositAverage` | 同上 | 当前统计月日均余额；按业务源实际日数计算，不用时点余额替代 |
| `retailRevenue` | 同上 | 零售营业收入，期间由来源确认；不能用 AUM、手续费或利润代替 |
| `retailValueCustomers` | 同上 | 按本行已确认门槛统计的去重价值客户；不硬编码全国通用门槛 |
| `retailLoan` | 同上 | 个人贷款余额；信用卡等是否纳入需与风险比率分母对齐 |
| `retailNplRate` | 同上 | 个贷不良率；`change` 表示百分点变化，不能与百分比增速混同 |
| `retailTrend` | `date`；`aum/deposit` 至少一项，可选 `depositAverage` | 同期、同口径序列，不用插值补缺失，不混合月末与月累计 |
| `retailSegments` | `name/customers/aum` | 同一时点的客户层级；互斥/覆盖范围需业务确认，页面不擅自求总 |
| `retailRanking` | `orgCode/name`；`aum/deposit` 至少一项；可选 `average/date/increase/rate/nplRate` | deposit 为存款、average 为存款月日均；两者差额不叫净增。净增和完成率仅在同口径来源绑定时展示；同层级机构比较，缺失不当零 |
| `retailAttention` | `label/count`；可选 `owner/deadline` | 已确认的事项及原始数量，不由页面创造风险事件或处理结论 |
| `retailTargets` | `name/actual/target` | 金额类目标，统一亿元；名称写清指标及期间，如“年度零售收入” |
| `branches` | 复用现有机构身份字段 | 授权目录/坐标/城市；零售界面不消费旧的分行经营指标 |

金额输入显式选择 `YUAN/TEN_THOUSAND/HUNDRED_MILLION`，输出统一亿元。客户数输入 `COUNT/TEN_THOUSAND_COUNT`，输出万户。关注数量只接受 `COUNT`。比例输入 `PERCENT/RATIO`，输出百分数；不良率变化显示百分点，其余单项变化显示百分比。

零、负净增、缺失和查询失败必须区分；非数值、无限值、多行单值、重复机构或日期必须暴露问题，不取第一行、不隐式加总。实际来源可能有不同更新批次，首屏日期不能单独证明全部槽位同期，接入验收须逐槽核对。

NAMED_GROUP 延续服务端授权机构集合、发布快照绑定身份与受控查询；零售机构排名只能使用带可靠机构编码的机构宽表。没有授权目录，不从名称或演示坐标补机构身份。读取失败、403、换屏和迟到响应沿用清空与代际隔离。

## 实施与验收边界

用户已授权按现有分行大屏设计开发零售版，直接在当前 `feat/code-screen-panorama` 的工作树做兼容增量，保留之前未提交改动。开始前的差异及被修改文件副本保存在 `/tmp/yiti-retail-qa/baseline`。主代理负责业务口径、模板集成、契约和最终验收，Luna 子代理分别负责展示、数据层和后端纯校验。

开发预览：`/#/screen-preview/retail`；沿用分行预览的独立开发态入口，明确标识“本地演示 · 非业务数据”，固定示例不调用业务 API。生产使用原 `/#/screen/:screenCode`，仍需屏级权限及已保存/发布配置。

浏览器需验证桌面 1920/1366/1280、窄屏 390、城市筛选、机构搜索/详情/Escape、排名指标/顺序、目标越界、刷新及两种预览切换。记录实际 CLI 命令、route 注册、原始 console/网络摘要和截图。纯单元测试与构建证明代码能力，演示预览证明视觉/交互；二者不等于真实指标已接入。

本轮不自动保存、发布或迁移远端零售屏，不运行数据库 DML/IT。上线前需逐槽确认业务定义、期间、组织范围、单位、数据源条线、更新批次与授权账户，再通过原草稿/发布流程启用新模板。运行后端必须包含新的模板校验器，旧后端拒绝新模板时不能只重发前端配置。正式取数按已发布包模板，草稿预览按草稿模板；来源编辑按实际引用该来源的草稿、发布及归档包分别校验，元数据变更也保留草稿/发布各自模板约束。未发布模板变更不能覆盖正式模板的口径保护。
