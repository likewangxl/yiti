# docs/testing 测试资料指导

本文件约束 `docs/testing/` 下的 API 测试资料，继承 `../AGENTS.md` 与仓库根 `AGENTS.md`。

## 目录定位

- `test-data.sql`：历史 API 测试种子，不是当前数据库初始化入口。
- `api-test.sh`：历史 curl 集成脚本，不是当前全量回归或发布门禁。
- `interface-design-check.md`：时间点核对报告，仅供追溯，不持续代表代码现状。
- 当前自动化测试入口以各 Maven 模块、bootstrap IT、前端测试和根目录 `AGENTS.md` 为准。

## 使用前核实

- 先检查脚本实际连接地址、库名、凭据、端口、API 路径、认证方式和测试数据前缀；不得照抄历史硬编码配置。
- 不得为了让旧脚本运行而修改项目端口、代理、数据库连接或真实数据。
- 脚本与当前源码、OpenAPI 或真实响应冲突时，以当前实现和权威契约为准，并明确脚本未验证，而不是改写结果。
- 旧脚本只覆盖部分认证、治理和工作流能力，不能据此宣称平台全量验证通过。

## 数据安全

- `test-data.sql` 若需修改，必须符合根目录可执行 SQL 白名单，只能使用事务控制、`INSERT`、`UPDATE`；检查查询和验收证据外置。
- 对任何数据库写入先确认目标。`yiti_test` 也需先只读盘点并取得写入授权；禁止把测试成功当作 `yiti` 写入授权。
- 测试数据使用唯一、可检索、可清理的前缀，不包含真实客户、员工、账号、手机号、身份证或金额数据。
- 清理动作必须在获准范围内并可恢复；不得为复用历史脚本而执行宽泛删除、清库或重建。

## 执行与证据

- 后端单元/集成测试按根目录 Surefire/Failsafe 规则运行；跨模块测试先刷新 SNAPSHOT，避免旧 JAR 假失败。
- 前端功能、交互、样式或 API 契约改动必须使用官方 `playwright-cli` 验收真实页面，并归档命令、路由/拦截器、console、requests/response 和截图。
- curl 集成验证至少记录服务进程/工作目录、实际请求目标、状态码、关键响应和认证上下文；端口监听或单条成功响应不等于完整验证。
- 明确区分真实联调、开发态 mock、只读检查、取消路径、未运行测试和基线失败。
- 证据中不得输出明文密码、Session、Token 或生产敏感数据。
