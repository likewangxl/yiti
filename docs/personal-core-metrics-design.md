# 个人核心指标：选择与取数口径

## 决策

个人经营大屏默认关注本人业务规模、存款持续贡献和近期增减，不再以“是否配置 KPI 考核方案”作为展示经营数据的前提。保留原 KPI 指标查询契约，另提供个人经营核心指标查询，由工作台指标桥接消费。经营卡片采用本人最新导入记录，并在卡片组内使用同一条快照，明确区分于考核发布版本及结算结果。

| 优先候选 | 员工关心的问题 | 展示约束 |
| --- | --- | --- |
| 对公一般性存款余额 | 我目前承担多少存款业务？ | 保留库内原名称；不把对公值改名为全部存款。 |
| 一般性存款月均余额 | 本月存款贡献是否稳定？ | 使用指标宽表已有结果，不由前端对时点余额求平均。 |
| 一般性存款年日均余额 | 全年持续贡献如何？ | 不与月均或时点余额相加。 |
| 一般性存款月均余额较上月 | 存款贡献较上月增加还是减少？ | 直接显示增减额；不再为增量指标计算二次环比。 |
| 对公一般性贷款余额 | 我目前承担多少信贷业务？ | 仅本人结果；不从机构余额按人数分摊。 |
| 对公一般性贷款余额较上月 | 贷款规模最近净变化多少？ | 不改称新增投放额或审批金额。 |

以零售一般性存款余额、月均、年日均、余额较上月，对应对公存款月均、年日均、余额较上月，以及同业存款余额、余额较上月作为有限备选。默认候选中本人有实际值的指标优先，其次选择有值的备选；未产出结果的默认候选最后保留空值，最多六项。零值是真实结果，不能因为为零就替换或隐藏。

本轮不臆造营业收入、AUM、客户数或绩效收入。后续若加入这些指标，需先确定员工维度定义、数据来源和归属口径。

## 实现约束

- 运行时从当前启用、未删除的 `EMP` 指标定义中匹配候选名称；不硬编码历史指标编码、宽表槽号或金额。
- 槽位必须在受支持范围内；同规范化名称出现多个不同定义时，不任意选择其中一个。
- 当前登录身份是认证域 `USER_ID`，必须通过 `UserApi` 解析本人 `username` 工号，再查询 `EMP_INDEX_RESULT.emp_id`。不能把内部用户 ID 直接当宽表工号；映射缺失或不一致时不得猜测其他身份。
- 经营数据限定本人、非未来数据日期，按数据日期、更新时间、版本和主键稳定选择最新导入记录。所有当期指标来自同一条快照，不逐指标拼接不同版本；比较日期也分别选择该员工当日的记录。不修改或推进 `SYS_CONTROL`，原 KPI 发布版本查询保持独立。
- 查询候选数量有上限，使用批量投影减少数据库往返，避免遍历全部指标逐项查询导致工作台聚合超时。
- 非增量指标可比较本人上月末最新导入结果，页面明确显示“较上月末”；缺少历史值或历史值为零时不计算变化百分比。保留原始指标名、单位和有效数据日期。
- 单位未配置时显示“单位未配置”，不默认认定为元或万元，也不擅自除以一万。
- 经营默认指标不自动关联考核目标，不套用未确认的完成率公式。原考核查询保持独立；目标与完成率为空时页面说明“未关联考核目标”。
- 某账号没有员工结果时保留空值，并明确提示；不存在个人数据日期时不伪造为今天，也不能用其他员工或演示值填充。员工指标结果与主办客户清单不是同一归属口径，不能相互冒充。
