# 分行总览 loanRate 可选槽位契约

日期：2026-09-21

## 范围

分行总览新增独立的 `loanRate` 单值比例槽位，展示标签为“零售贷款目标完成率”。该槽位是可选绑定，历史 14 个分行槽位的顺序和发布包兼容性保持不变；旧包省略 `loanRate` 时仍按原契约校验。

## 数据口径

`loanRate` 只读取自身绑定的 `fields.value`，单位只接受 `PERCENT` 或 `RATIO`。运行时按绑定单位转换为统一百分比展示：`PERCENT` 原值直接作为百分数，`RATIO` 原值乘 100。不得从 `loan`、旧 `rate` 或列名推导贷款目标完成率；没有独立来源时保留缺失态。

## 契约落点

- 前端 `bindings.js` 注册独立 `loanRate` `METRIC_CARD`，并把它放入全局构建顺序；`BRANCH_SLOT_ORDER` 继续保留历史 14 项。
- 前端 `dataAdapter.js` 只在单值槽位分支适配 `loanRate`，不会写入或覆盖 `rate`。
- 后端 `CodeScreenPresentationValidator` 将 `loanRate` 纳入分行允许槽位、指标标签/来源可用性字段白名单、`value` 必填字段和比例单位校验。
- 运行时包槽位过滤和来源展示元数据已支持 `loanRate`；发布包只有显式存在且绑定有效数据源的该组件才进入请求队列。
- 绑定管理页保留旧 14 项默认布局，并提供单独的可选 `loanRate` 入口；未选择该入口时不会写入组件或增加预检项。

## 证据与限制

前端专用单元测试为纯内存测试，覆盖注册、比例换算、空值 `NO_VALUES`、与旧 `rate` 独立等场景。当前真库没有贷款目标来源，本契约不伪造数据，也未执行数据库写入、配置发布或真实联调。Java 专用单元测试已由主代理执行，4项全部通过；后端已重新构建并启动。新槽位仍未绑定实际贷款来源，真实页面验证的是明确缺失态。
