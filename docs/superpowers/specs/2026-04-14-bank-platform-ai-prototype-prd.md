# 银行省分行一体化营销与绩效管理平台 AI 原型生成 PRD

## 1. 文档定位





这是一个面向银行省分行的一体化营销与绩效管理平台，覆盖门户入口、客户营销、业务申请、绩效计算、报表分析、权限治理和流程协同。

### 2.2 V1 业务目标

- 提供统一门户，解决“系统多、入口散”的问题
- 将线索、认领、触达、资产投放、中场支持串成完整线上闭环
- 实现绩效指标、KPI、目标、调整、回算、报表的一体化后台
- 为客户经理提供可用的移动 H5 工作入口

### 2.3 V1 原型必须覆盖的模块

| 模块 | 原型要求 |
|---|---|
| 工作台与导航 | 必做 |
| 客户营销中心 | 必做 |
| 业务申请中心 | 必做 |
| 绩效计算中心 | 必做 |
| 报表分析中心 | 必做 |
| 认证授权与权限配置 | 必做 |
| 系统治理与运维后台 | 必做 |
| 工作流中心（待办/已办/办理/配置） | 必做 |
| 移动 H5 | 必做核心场景 |

### 2.4 V1 明确不做或不重点表现

- 移动端自定义 Dashboard 布局
- 自动营销日程
- 离线能力
- 二次分配
- 360 环评

这些可以在原型中不出现，或以“V2 敬请期待”占位，不应作为可操作主流程。

## 4. AI 原型生成总约束

### 4.1 视觉方向


- 视觉气质：稳重、专业、可信、克制，不要互联网消费产品风格
- 主基调：浅色背景为主，深蓝/墨蓝作为品牌主色，辅以灰白层次
- 状态色：绿色表示正常，黄色表示预警，红色表示超时/风险，蓝色表示可操作或当前激活
- 字体感觉：信息密度高，但层级明确；标题要稳，正文要清晰，数字卡片要突出
- 组件风格：卡片、表格、标签、抽屉、时间线、审批步骤条、图表并存，圆角不宜过大
- 风险操作：删除、导入、重算、执行 SQL、手动触发任务、转交等操作必须有明显风险提示

### 4.2 PC 端基础布局母版

- 左侧为一级导航栏，宽度建议 220-240
- 顶部为全局栏，放 Logo、搜索入口、通知铃铛、用户信息
- 内容区顶部为页面标题、面包屑、右侧主操作按钮
- 标题下方通常是筛选条
- 核心内容区优先采用“表格/卡片 + 右侧抽屉详情”或“主内容 + 右侧流程/详情侧栏”
- 列表型后台页面统一采用“筛选条 + 表格 + 分页 + 批量操作”

### 4.3 H5 基础布局母版

- 顶部为标题栏与返回
- 首页为工作台卡片流，不做复杂侧边导航
- 页面内优先使用卡片列表、折叠面板、分段切换
- 高价值操作按钮固定在底部，如“提交”“触达完成”“发起支持”
- 触达办理页面必须留出拍照打卡与日志录入的突出入口

### 4.4 全局状态体系

| 状态 | 表现建议 |
|---|---|
| Loading | 骨架屏，优先做局部骨架，不要整页阻塞 |
| Empty | 空状态插画或轻图标 + 解释文案 + 主 CTA |
| Error | 保留中文错误提示与 `traceId` 展示位 |
| No Permission | 锁图标 + 无权限说明，不建议只是空白 |
| Readonly | 历史信息区显示只读标签，隐藏写操作 |
| High Risk | 弹窗必须包含风险说明、原因输入框、二次确认按钮 |
| Async Running | 用状态条、批次标签、进度标识表现 |

### 4.5 全局交互原则

- 所有关键提交、删除、导入、导出、转交、重算都要二次确认
- 所有流程型页面都要表现“当前节点、发起人、发起时间、处理人、SLA 状态”
- 所有表格型页面都应具备分页、筛选、空状态、错误态
- 跨机构全量历史只能表现为只读，不应在视觉上暗示可编辑
- 候选人未签收时可看不可改，原型中要明确区分“可领取”和“待办理”

## 6. 核心端到端流程

### 6.1 客户经理主链路

工作台 -> 线索录入/导入 -> 审批通过形成客户 -> 待认领客户池认领 -> 自动生成触达任务 -> 触达成功 -> 弹窗选择是否发起中场支持 -> 视情况继续发起资产投放 -> 在工作台/报表中查看个人结果

### 6.2 经营机构负责人主链路

工作台待办 -> 审批本机构线索/贷款 -> 查看机构客户与触达管理视图 -> 查看机构报表与驾驶舱

### 6.3 中场支持链路

客户经理发起支持 -> 场景 A 直接到产品负责人 -> 场景 B 先到部门秘书派单 -> 支持人员办理 -> 流程结束通知发起人

### 6.4 绩效后台链路

配置指标 -> 试运行 -> 立即执行 -> 配置 KPI -> 配置目标 -> 导入数据 -> 日跑/手工触发计算 -> 分配关系调整或目标修正 -> 自动回算 -> 报表查询

### 6.5 运维治理链路

配置字典/工作日历/流程节点/SLA -> 监控调度 -> 审计高危动作 -> 通过 SQL 探查排查问题

## 7. 页面级原型规格

## 7.1 工作台与流程中心

### 7.1.1 工作台首页

- 终端：PC / H5
- 主要角色：全员，尤其是客户经理
- 页面结构：
  - 顶部欢迎区与快捷搜索
  - 待办区
  - 通知区
  - 指标卡片区
  - 新增流程快捷入口区
- 待办区字段：
  - 流程名称
  - 发起人
  - 发起时间
  - 当前任务标题
  - 红黄绿灯状态
  - 超时信息
- 通知区字段：
  - 标题
  - 100 字摘要
  - 发送时间
  - 已读/未读
- 指标卡片字段：
  - 指标名称
  - 当前值
  - 目标值
  - 完成率
  - 趋势
- 快捷入口：
  - 系统预设入口：新增线索、资产投放、中场支持
  - 用户自定义入口：支持增删排序
- 交互：
  - 点击待办进入对应办理页
  - 点击未读通知自动标记已读并跳详情
  - 点击更多进入完整列表页
  - 指标卡片失败时只降级该区块
- H5 特殊要求：
  - V1 固定只展示 4 张关键卡片
  - 强化待办与通知入口

### 7.1.2 我的待办 / 我的已办

- 页面结构：
  - 顶部筛选条：业务类型、状态、关键词
  - 主表格
  - 右侧或下钻到详情页
- 待办表格列：
  - 标题
  - 业务类型
  - 发起人
  - 发起机构
  - 发起时间
  - 当前节点
  - 到达节点时间
  - SLA 状态
  - 是否可领取
- 已办表格额外列：
  - 完成时间
  - 审批结果
  - 审批意见
- 交互：
  - 候选任务显示“签收”按钮
  - 已签收任务显示“办理”按钮
  - 列表支持按 SLA 颜色快速筛选

### 7.1.3 任务处理页

- 这是流程中心最重要的“处理台”
- 页面采用双栏布局：
  - 左侧：业务正文
  - 右侧：流程概览与操作区
- 右侧固定展示：
  - 流程标题
  - 发起人
  - 发起时间
  - 当前节点
  - 黄灯时间点
  - 红灯时间点
  - 当前 assignee / 候选组
- 操作区根据身份变化：
  - 候选人未签收：只展示“签收”
  - 当前 assignee：展示“审批通过”“驳回”“转交”
  - 参与者：只读
- 转交弹窗：
  - 接收人选择器
  - 原因输入框
  - 风险提示：转交不重置红绿灯计时
- 时间线：
  - 发起
  - 签收
  - 审批
  - 转交
  - 结束

### 7.1.4 通知中心

- 终端：PC / H5
- 页面结构：
  - 顶部状态筛选：全部 / 未读 / 已读
  - 右上角“全部标记已读”
  - 列表卡片或表格
- 每条通知展示：
  - 标题
  - 类型
  - 摘要
  - 生成时间
  - 已读状态
- 点击逻辑：
  - 自动标记已读
  - 如存在 link_url，则跳到业务详情

## 10. 交给原型 AI 的执行要求

### 10.1 输出物

- 一套 PC 主端高保真原型
- 一套 H5 核心原型
- 一套共享组件样式
- 关键流程的连线说明

### 10.2 出图要求

- 不要只出静态首页，必须覆盖列表、详情、表单、弹窗、空状态、错误态、成功态
- 每个关键流程至少覆盖“入口页 + 办理页 + 结果态”
- 必须把红黄绿灯、未读红点、状态标签、审批时间线做成统一视觉系统
- 必须区分“只读历史”和“可编辑办理”
- 必须区分 PC 与 H5 的信息密度和交互重心

### 10.3 如果 AI 一次性上下文不够

按以下顺序分批生成：

1. 工作台 + 客户营销主链路
2. 业务申请链路
3. 绩效与报表
4. 权限与系统治理后台
