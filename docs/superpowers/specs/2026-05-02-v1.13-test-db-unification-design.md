## § 2. 设计方案（阶段 1 五步）

### 2.1 步骤 1 — 清理 26 张小写双胞胎

**手段**：执行仓库已存在的 V1.12 两个 patch（之前从未在 windows 用户环境真正落地）：
- `docs/superpowers/sql/2026-05-01-v1.12-drop-customer-lowercase-tables.sql`
- `docs/superpowers/sql/2026-05-01-v1.12-schema-column-drift-fix.sql`（兜底，已无 drift 也是 NO-OP）

**前置**：先 `mysqldump onepl_test_bootstrap` 完整备份到 `docs/superpowers/sql/backup/2026-05-02-v1.13-onepl-test-bootstrap-pre-cleanup.sql.gz`。

**验证**：`SHOW TABLES` 后小写双胞胎归零，仅剩 67 大写 + QRTZ_* + ACT_*/FLW_* + flyway_schema_history*。

### 2.2 步骤 2 — perf 解绑 yiti + 启用 Quartz JDBC

**改 `performance-engine-center/src/test/resources/application-test.yml`**：
- `spring.datasource.url`: `jdbc:mysql://localhost:3306/yiti...` → `jdbc:mysql://localhost:3306/onepl_test_bootstrap...`
- 新增 `spring.quartz` 段（提炼自 `bootstrap/application.yml`）：`job-store-type=jdbc` / `initialize-schema=never` / `org.quartz.jobStore.driverDelegateClass=StdJDBCDelegate` / `tablePrefix=QRTZ_` / `isClustered=true` / `clusterCheckinInterval=20000` / `misfireThreshold=60000` / `instanceName=BranchPlatformScheduler` / `instanceId=AUTO`
- `PerformanceFlywayTestBase` 的 `@TestPropertySource` 已指向 onepl_test_bootstrap，与本步骤一致，无需改

**风险评估**：perf 56 IT 中以前默写到 `yiti` 的，改后默写到 `onepl_test_bootstrap`；表结构两库一致 → 行为应不变。

### 2.3 步骤 3 — portal 解绑 yiti

**改 `portal-content-center/src/test/resources/application-test.yml`**：
- url 从 yiti 改 onepl_test_bootstrap

防御性修改（当前 IT=0），避免未来新增 IT 又落到开发库。

### 2.4 步骤 4 — V1.13 init 脚本（幂等全量）

**新建 `docs/superpowers/sql/2026-05-02-v1.13-onepl-test-bootstrap-init-v2.sql`**：
- CREATE DATABASE IF NOT EXISTS `onepl_test_bootstrap` + utf8mb4
- USE `onepl_test_bootstrap`
- SOURCE 9 个 ddl-*.sql + ddl-quartz.sql + seed-v1.sql + workflow-seed-v1.sql + V1.12 两 patch
- 全部 DDL `CREATE TABLE IF NOT EXISTS` + V1.12 patch 自带 INFORMATION_SCHEMA 检查 → **可重复执行**
- 头部注释：用法 / 何时跑 / 与 `2026-04-28-onepl-test-bootstrap-init.sql` 的关系（替代）

旧 `2026-04-28-init.sql` **保留**（标记 deprecated 注释指向 v2），不删除以保留历史。

### 2.5 步骤 5 — 阶段 1 验证

跑：
```
mvn -pl performance-engine-center verify
mvn -pl bootstrap test
mvn -pl report-analytics-center verify
```

预期：
- perf 56 IT 不退化（行为应与 yiti 时一致，因为 onepl_test_bootstrap schema 一样）
- **MetricScheduledE2EIT 4 用例可能仍 fail**（业务层 quartz 注入是否成功取决于 spike #1b 的真根因）—— 此为预期，不阻塞 V1.13 # 1 交付
- bootstrap V1.11 # 1 5 IT 仍全绿
- report 70 IT 仍全绿
