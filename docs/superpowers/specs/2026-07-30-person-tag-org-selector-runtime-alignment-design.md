# 业务标签机构多选与运行版本对齐设计

## 背景与根因

业务标签详情的“新增成员”弹窗当前同时接受员工工号和机构编号文本。机构编号不便于业务人员识别，本次将机构录入改为按机构名称搜索的多选下拉。

同步排查确认，当前运行环境还存在三个已在源码修复、但未进入运行时的问题：

1. 机构导入模板表头和示例仍为机构号；
2. Excel 填写机构名称时提示机构不存在；
3. 员工详情的员工姓名显示为 `—`。

这些现象由同一个构建部署问题造成。`bootstrap` 以单模块方式启动时，从本地 Maven 仓库加载业务模块 JAR；当前运行的 `system-governance-center` JAR 生成于 2026-07-24，而机构名称导入、模板更新和员工姓名回显源码均在 2026-07-29 提交。

运行时 JAR 的类结构证明：

- `PersonTagOrgImportRow` 和 `PersonTagOrgMemberImportRow` 仍暴露 `orgDeptNo`；
- 模板示例仍写入 `0101`；
- `PersonTagImportService` 仍调用 `OrgApi.getOrgsByDeptNos()`；
- `PersonTagMemberRespDTO` 没有 `displayName`；
- `PersonTagService` 的员工成员组装逻辑只返回工号，没有调用 `UserApi.getUsersByUsernames()`。

当前源码已经具备机构名称模板、按名称唯一解析和员工姓名批量补全逻辑，相关 48 项后端测试通过。因此这三项问题不再重复修改业务实现，通过全量安装最新模块并重启后端完成运行版本对齐。

## 目标

1. “新增成员”弹窗的机构条件改为可搜索、多选的机构名称下拉。
2. 用户按机构名称识别和筛选机构，不需要手工输入 `deptNo`。
3. 保持后端与数据库的机构成员标识为 `EXT_ORG_INFO.DEPT_NO`。
4. 使当前源码中已有的机构名称导入模板、名称解析和员工姓名回显进入实际运行环境。
5. 通过测试和运行时检查防止把前端交互问题与 stale JAR 问题混为一谈。

## 非目标

- 不修改 `PERSON_TAG_REL` 表结构，不冗余保存机构名称。
- 不改变新增成员接口的 `orgDeptNos` 请求字段。
- 不改变员工成员仍按工号批量输入的规则。
- 不改变“修改机构”弹窗及其 `orgDeptNo` 更新接口。
- 不新增机构搜索接口；现有机构树接口已经提供机构名称和 `deptNo`。
- 不重复实现已经存在于当前源码的机构名称导入和员工姓名查询逻辑。

## 方案选择

### 采用：前端名称多选，内部提交机构编号

前端复用 `getOrgTree()` 获取机构树，将其扁平化为机构候选项。下拉按机构名称搜索和展示，以 `deptNo` 作为选项值，保存时继续提交：

```json
{
  "usernames": ["100001"],
  "orgDeptNos": ["0101", "0102"]
}
```

优点是交互满足名称选择诉求，同时不改变后端契约、存在性校验和数据库存储口径。用户选择的是明确的机构记录，也避免后端再处理名称重名歧义。

### 未采用：新增接口直接接收机构名称

该方案需要新增 `orgNames` 请求字段、名称唯一性错误码及解析逻辑。机构重名时无法仅靠文本确定用户意图，而且与已确认的多选下拉交互重复，增加不必要的接口改动。

### 未采用：新增远程机构搜索接口

远程搜索适合无法一次加载的超大机构数据集，但当前系统已有多个页面使用完整机构树，且本功能只在打开新增弹窗时按需加载。现阶段新增接口没有必要。

## 前端设计

### 数据加载

- “新增成员”弹窗首次打开时按需调用 `getOrgTree()`。
- 同一页面会话中缓存成功加载的候选项，后续打开弹窗不重复请求。
- 递归扁平化机构树，生成 `{ deptNo, name, code }` 候选项。
- 排除 `deptNo` 为空的机构；按 `deptNo` 保序去重。

### 交互

- 原“机构编号”多行文本框替换为 `el-select`。
- 开启 `multiple`、`filterable`、`clearable` 和折叠标签能力。
- 表单标签和占位文案均使用“机构名称”。
- 选项主文案展示机构名称；辅助展示 `deptNo`，用于区分重名机构。
- 已选值保存为 `memberAdd.orgDeptNos`，保存时直接提交，不再对机构输入调用文本分割函数。
- 员工工号文本框与逗号、换行拆分规则保持不变。

### 异常处理

- 机构树加载期间禁用下拉并展示加载状态。
- 加载失败时清空候选项并提示“机构列表加载失败，请重试”；员工工号仍可单独提交。
- 没有员工工号且没有选择机构时，提示“请至少输入一个员工工号或选择一个机构”。
- 后端仍负责最终存在性校验，防止机构在候选项加载后被删除或变更。

## 后端与数据流

新增成员链路保持不变：

1. 前端以名称展示机构候选项；
2. 用户选择后，前端取候选项的 `deptNo`；
3. `POST /api/admin/sys/person-tags/{tagId}/members` 继续接收 `orgDeptNos`；
4. `PersonTagService.addMembers()` 通过 `OrgApi.getOrgsByDeptNos()` 批量校验；
5. 校验通过后将 `deptNo` 写入 `PERSON_TAG_REL.ORG_DEPT_NO`；
6. 详情查询再按 `deptNo` 实时补全机构名称。

因此本次多选下拉不需要修改后端录入逻辑。

## 运行版本对齐

当前源码与运行中 JAR 不一致。实现和测试完成后，在仓库根目录执行：

```bash
mvn clean install -DskipTests
```

随后重启 `bootstrap` 后端。仅运行 `mvn test` 或在 `bootstrap` 目录执行 `mvn spring-boot:run` 不会更新本地 Maven 仓库中的业务模块 JAR。

重启后检查运行时类与接口行为：

- 机构全局导入模板为“标签名称 / 机构名称”，示例为机构名称；
- 指定标签机构成员模板为“机构名称”，示例为机构名称；
- 机构名称导入按名称唯一匹配后写入对应 `deptNo`；
- 员工详情响应包含 `displayName`，前端能够展示姓名。

## 测试与验收

### 前端

- 打开新增成员弹窗时加载机构树并生成有效、去重的机构候选项。
- 机构下拉支持按名称过滤和多选。
- 选择机构后仍按 `{ usernames, orgDeptNos }` 调用新增成员接口。
- 未输入员工且未选择机构时不调用接口。
- 机构列表加载失败时显示提示，并允许仅提交员工。
- 既有员工姓名列、机构导入和成员维度切换测试继续通过。

### 后端

- 保留并运行 `AdminPersonTagControllerTest`、`PersonTagImportServiceTest`、`PersonTagServiceTest` 和 `UserFacadeBatchQueryNPlusOneTest`。
- 确认机构名称模板、名称唯一解析、`displayName` 回显测试通过。
- 全量安装后核对本地 Maven 仓库 JAR 的生成时间和 DTO 方法，确保不再加载 2026-07-24 的旧类。

### 验收结果

- 新增成员弹窗不再要求用户输入机构编号。
- 机构选择后能够成功新增，关联表仍保存正确的 `deptNo`。
- 下载的两类机构模板均使用机构名称。
- 使用存在且唯一的机构名称可以成功导入。
- 员工详情能够展示 `PT_USER.USERCHNNAME`；基础数据本身无姓名时才显示 `—`。
