# 业务标签机构名称导入与员工姓名展示设计

## 背景

业务标签当前支持员工、机构两个成员维度：

- 员工关联在 `PERSON_TAG_REL.USERNAME` 中保存 `PT_USER.USERNAME`；
- 机构关联在 `PERSON_TAG_REL.ORG_DEPT_NO` 中保存 `EXT_ORG_INFO.DEPT_NO`。

现有机构 Excel 导入要求填写机构号，使用者难以确认编号；员工详情只显示工号，缺少姓名辅助识别。本次调整机构导入的输入口径和员工详情的展示字段，不改变关联表结构及既有成员维度。

## 目标

1. 两个机构导入入口统一使用机构名称：
   - 全局导入模板：`标签名称 + 机构名称`；
   - 指定标签成员导入模板：`机构名称`。
2. 导入时按 `EXT_ORG_INFO.ORG_NAME` 精确匹配并校验名称存在性、唯一性。
3. 唯一匹配后仍把对应 `DEPT_NO` 保存到 `PERSON_TAG_REL.ORG_DEPT_NO`。
4. 员工维度详情同时展示工号和 `PT_USER` 中的员工姓名。
5. 所有关联数据补全均使用批量查询，避免 N+1。

## 非目标

- 不修改 `PERSON_TAG_REL`、`EXT_ORG_INFO` 或 `PT_USER` 表结构。
- 不在关联表中冗余保存机构名称或员工姓名。
- 不改变员工导入仍按工号匹配的现有规则。
- 不改变手工新增、修改机构成员仍按机构编号提交的现有接口。
- 不改变全局导入的追加语义、成员导入的按维度全量覆盖语义及原子校验规则。

## 方案选择

采用现有跨模块 API：

- 机构名称解析使用 `OrgApi.getOrgsByNames()`；
- 员工姓名解析使用 `UserApi.getUsersByUsernames()`。

不在 `system-governance-center` 中直接访问认证模块的 Mapper 或实体，保持模块间只通过 `*Api` 交互。也不在标签关联表冗余名称，避免机构或员工改名后产生历史脏数据。

## 机构名称导入

### Excel 模型与模板

`PersonTagOrgImportRow` 的机构列由“机构号”改为“机构名称”，属性改为表达名称语义。`PersonTagOrgMemberImportRow` 同步调整。

模板示例改为真实可读的机构名称：

- 全局机构模板示例：`重点机构 / 城东支行`；
- 标签机构成员模板示例：`城东支行`。

前端下载文件名保持不变，避免影响用户已有操作路径。

### 解析和校验

导入服务先对机构名称去除首尾空格，再将去重后的名称集合一次传入 `OrgApi.getOrgsByNames()`。返回结果按 `OrgDTO.orgName` 分组：

- 无匹配：该行错误为“机构名称在系统中不存在”；
- 匹配一条：取该条记录的 `deptNo` 作为最终成员标识；
- 匹配多条：该行错误为“机构名称不唯一”；
- 同一标签下同一机构名称在文件中重复，或成员导入中同一名称重复：按现有文件内重复规则报错。

校验阶段保留 Excel 原始行号和机构名称，用于返回可定位的错误明细。任一行错误时整体不写库，也不清理指定标签的存量成员。

唯一匹配通过后，后续查重和写库都使用解析得到的 `deptNo`：

- 全局导入继续按 `(tagId, deptNo)` 判断存量关联并跳过；
- 成员导入继续先删除该标签的 ORG 维度关联，再批量写入解析后的 `deptNo`。

## 员工详情姓名补全

`PersonTagMemberRespDTO` 新增 `displayName`，语义与 `UserDTO.displayName` 保持一致。

员工详情分页时：

1. 读取当前页 `PERSON_TAG_REL`；
2. 收集并去重当前页 `username`；
3. 一次调用 `UserApi.getUsersByUsernames()`；
4. 建立 `username -> displayName` 映射并组装 DTO。

如果存量关联的工号已无法在 `PT_USER` 找到，仍返回工号，`displayName` 为 `null`，避免单条脏关联阻断整个详情页。

前端员工维度表格调整为：

- 工号；
- 员工姓名，空值显示 `—`；
- 操作。

删除确认等既有员工标识逻辑仍以工号为准。

## 错误处理

沿用 `PersonTagImportResultDTO.RowError` 返回行级错误，不新增 HTTP 状态或数据库错误码。机构维度文案统一从“机构号”调整为“机构名称”：

- 机构名称不能为空；
- 机构名称在文件内重复；
- 机构名称在系统中不存在；
- 机构名称不唯一。

重名机构不做任意选择，防止错误绑定。

## 测试

### 后端

- 全局机构导入按机构名称唯一匹配并写入对应 `deptNo`；
- 指定标签机构成员导入按机构名称唯一匹配并全量覆盖 ORG 维度；
- 机构名称不存在时返回对应行错误且不写库；
- 机构名称匹配多条时返回“不唯一”且不写库；
- 文件内重复机构名称仍返回重复错误；
- 下载的两类机构模板表头和示例均为机构名称；
- 员工详情按页批量查询用户并返回 `displayName`；
- 用户不存在时保留工号且姓名为空；
- 控制器 JSON 契约包含 `displayName`。

### 前端

- 员工详情表包含“员工姓名”列并绑定 `displayName`；
- 姓名为空时展示 `—`；
- 既有员工、机构维度切换和导入调用行为保持不变。

## 兼容性与影响

- 旧的“机构号”Excel 模板将不再符合新表头，需要重新下载模板后导入。
- 数据库存储口径不变，既有机构关联无需迁移。
- 详情接口仅新增可选响应字段，对现有调用方保持向后兼容。
- 查询机构和员工均按当前批次或当前页批量执行，不引入逐行查询。
