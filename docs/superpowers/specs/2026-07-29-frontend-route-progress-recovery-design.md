# 前端路由进度条容错设计

## 背景

主平台路由在 `beforeEach` 中把顶部进度条推进到 70%，仅在
`afterEach` 中完成并隐藏。路由视图使用动态 `import()` 懒加载；当视图模块请求
长期挂起或加载失败时，导航无法进入 `afterEach`，旧页面继续显示，进度条永久停在
70%。该请求属于前端静态资源而不是 `/api`，所以后端不会产生对应错误日志。

Playwright 已通过阻塞 `/src/views/report/Dynamic.vue` 稳定复现：

- 进度条保持 `width: 70%`、`opacity: 1`；
- 阻塞期间没有 `/api` 请求；
- 请求失败后 Vue Router 报
  `Failed to fetch dynamically imported module`，进度条仍不复位。

## 目标

1. 动态路由模块加载失败时立即关闭进度条并给出一次用户可见提示。
2. 路由导航超过 15 秒仍未结束时关闭进度条并提示加载超时。
3. 防止前一次导航的延迟隐藏定时器误清除下一次导航的进度条。
4. 保持正常导航现有的“70% → 100% → 隐藏”视觉效果。

## 非目标

- 不取消路由懒加载，不扩大首屏包体。
- 不自动刷新页面，避免刷新循环和未保存数据丢失。
- 不修改 `vite.config.js`、后端接口或数据库连接池配置。
- 不处理后端菜单与前端路由不一致问题；该问题单独治理。

## 方案

### 进度控制器

新增 `src/router/routeProgress.js`，导出 `createRouteProgress(options)`。
控制器统一拥有进度条 DOM、完成动画定时器和 15 秒看门狗定时器：

- `start()`：取消旧完成动画和旧看门狗，显示进度条并设置为 70%，启动新的
  15 秒看门狗。
- `done()`：取消看门狗，把进度推进至 100%，300 毫秒后隐藏并归零。
- `fail()`：取消全部定时器并立即隐藏归零；返回本次是否仍处于活动状态，用于避免
  超时提示后又重复显示失败提示。
- 看门狗触发时先隐藏归零、结束活动状态，再调用 `onTimeout`。

每次 `start()` 都会取消前一次 `done()` 留下的延迟隐藏定时器，确保连续导航时旧
定时器不能覆盖新状态。

### 路由接入

`src/router/index.js` 保留现有鉴权守卫，只替换内联进度条实现：

- `beforeEach` 继续在鉴权前调用 `progress.start()`；
- `afterEach` 调用 `progress.done()`；
- 新增 `router.onError`。发生动态模块加载等路由异常时调用 `progress.fail()`，
  记录控制台错误，并通过 Element Plus 显示“页面加载失败，请刷新后重试”；
- 看门狗的 `onTimeout` 显示“页面加载超时，请刷新后重试”。

超时后若同一次模块请求又失败，`fail()` 返回非活动状态，不重复弹出失败提示。

## 测试设计

新增 happy-dom 环境的 Vitest 回归测试，覆盖真实进度条 DOM 状态：

1. 路由异常回调发生后，70% 进度条立即隐藏归零，并只提示一次。
2. 导航持续 15 秒未完成时，进度条隐藏归零并只提示一次超时。
3. 前一次导航进入完成动画后立即开始新导航，旧的 300 毫秒定时器不能清除新导航
   的 70% 状态。
4. 正常导航仍然先达到 100%，随后隐藏归零。

严格执行 TDD：先运行新增测试并确认因缺少错误处理/看门狗而失败，再实现最小代码
使其通过。随后运行完整 `npm test`、`npm run build`，并用 Playwright 重跑正常
导航与动态模块失败场景。

## 验收标准

- 正常导航不出现常驻进度条。
- 动态路由模块请求失败后 1 秒内进度条不可见，页面出现明确错误提示。
- 永久挂起的路由请求在 15 秒时进度条不可见，页面出现明确超时提示。
- 连续快速导航不会被上一轮动画定时器提前清除进度状态。
- 前端单元测试和生产构建通过，现有用户未提交改动不被覆盖。
