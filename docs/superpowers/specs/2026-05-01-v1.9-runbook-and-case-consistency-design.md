## 5. Risks

### 5.1 大小写改动可能触发 H2 行为差异

H2 默认 case-insensitive，MySQL 配 `lower_case_table_names=0` case-sensitive。改大写后**预期无副作用**（H2 仍兼容），但需全量回归验证。

**Fallback**: 若回归失败，按文件回滚单个 SQL；不强行硬改。

### 5.2 sed 批量替换误伤字符串字面量

`INSERT INTO loan_apply` 会被改，但 `'loan_apply'` 字符串里如有也会被误改。

**Mitigation**:
- 用 `\b` 词边界
- 改完后 `grep` 全文确认 0 残留小写表名
- 改完后 `git diff` 人工 review 每一行
- 跑 `mvn verify` 兜底

### 5.3 Runbook 与 CLAUDE.md 重复

如果 4 处 CLAUDE.md 完全删除运维段落只留指针，未来开发同事打开 CLAUDE.md 一无所获再跳转 Runbook 体验差。

**Mitigation**: 保留各 CLAUDE.md 的**摘要+指针**结构（"运维 Runbook 详细见 X，本节为速查摘要"）。

### 5.4 V1.9 P4 验证发现：V1.8 P7 笔记不准确

V1.9 P4（mvn verify -pl bootstrap 全量回归）发现 5 个 IT 失败：

- `LeadApprovedCreatesCustomerMasterIT.leadApproved_shouldCreateCustomerMaster_andUpdateLeadStatus` (Failure: Expected size 1 but was 0)
- `WorkflowCallbackEventChainBugIT.processCompletedEvent_publishedInTransaction_shouldCreateCustomerMaster` (Failure)
- `WorkflowCallbackIdempotencyBugIT.duplicateProcessCompletedEvent_shouldNotDuplicateCustomerMaster` (Failure)
- `CustomerMarketingCenterIT.customerMinimalClosure_worksInBootstrap` (Error: EmptyResultDataAccessException)
- `WorkflowCallbackExceptionSwallowBugIT.mapperException_shouldBeSwallowedByListenerNotSpring` (Error: EmptyResultDataAccessException)

**Baseline 验证**：通过 `git checkout HEAD~5 -- bootstrap/src/test/resources/{business-application-data,customer-marketing-data,flowable-real-env-data,it/perf-fake-data,it/perf-fake-data-cleanup,it-cleanup}.sql` 回退到 V1.8 P7 状态后再跑同 5 个 IT，**结果完全相同**（Tests run: 5, Failures: 2, Errors: 3）。

**结论**：V1.9 改动**不是**这 5 个失败的回归源，是 V1.8 P7 笔记"bootstrap mvn verify 全绿"误标（V1.8 P7 实际只跑了 P5 范围内的 IT，未做全量 verify）。

**处置**：5 个失败 IT 转入 `customer-marketing-center/CLAUDE.md` "V1.10 候选事项" 段，由 V1.10 单独 brainstorming 定根因。

**V1.9 P4 验收标准微调**：因 5 IT 失败非 V1.9 引入，V1.9 验收标准从"`mvn verify -pl bootstrap` 全绿"改为"V1.9 引入的回归数 = 0（即 V1.9 verify 失败 IT 集合 ⊆ V1.8 P7 baseline 失败 IT 集合）"。本次实测：V1.9 verify-2 失败 = 5 个 IT；baseline 失败 = 5 个相同 IT；ΔV1.9 引入 = 0。

**P2 漏改 cleanup 修复**：V1.9 P2 executor 漏改 2 个 cleanup 配对文件（`it/perf-fake-data-cleanup.sql` 7 处 + `it-cleanup.sql` 1 处），导致 verify-1 期间 5 个 PortalWorkspaceMetricIT 失败于 ScriptStatementFailed。P2-fix commit `23e526f` 已修。verify-2 后这 5 个 PortalWorkspaceMetricIT 全部恢复绿。
