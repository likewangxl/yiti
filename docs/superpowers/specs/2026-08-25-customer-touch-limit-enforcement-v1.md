# 客户触达限制校验 V1 实施规格

> 日期：2026-08-25
> 范围：触达规则页面查询、线索触达限制字段、导入必填校验、首次/再次触达资格校验。
> 数据库边界：本文只定义应用契约，不执行 DDL/DML；真实联调前须由 DBA 完成字段和规则表变更。

## 1. 交付范围

1. 客户触达周期管理页按标签分页查询规则；没有规则行时显示 `MONTH/5`，读取不回写。
2. 新建线索增加 `touchRestricted`，取值 1-是、0-否，默认 1 且必填；编辑和详情完整透传。
3. CSV/XLS/XLSX 导入文件必须包含“是否触达限制”列，每个非空数据行只能填写“是”或“否”。
4. `TouchTaskService` 在创建 `FIRST_TOUCH`/`FOLLOW_UP` 前统一执行资格校验；因此首次触达
   `POST /api/claims/{claimId}/touch`、再次触达 `POST /api/claims/{claimId}/re-touch` 以及审批、
   转交、跨机构营销触发的内部任务创建路径使用同一规则。

导入服务当前仍为简化实现：预览会持久化批次和错误统计，执行只把无错误批次置为
`PENDING_APPROVAL`，尚不把文件数据写入 `CUST_LEAD`。

## 2. 字段契约

- 应用字段：`touchRestricted`；数据库字段：`touch_restricted`。
- `CUST_LEAD.touch_restricted` 和 `CUSTOMER_MARKET_CUSTOMER.touch_restricted` 均采用 1/0。
- 新建请求默认 1 且 `@NotNull`；请求值通过 `@Min(0)`、`@Max(1)` 限定。
- 历史客户字段为 `null` 时按 1 处理，只有显式 0 才跳过全部触达资格限制。
- 线索审批组装客户主档时复制该字段，并幂等同步线索标签快照到客户标签关系。

## 3. 资格校验

校验顺序如下：

1. 客户不存在返回 `CUST-40403`。
2. `touchRestricted=0` 直接通过；1 或 `null` 继续。
3. 一次批量读取客户的有效标签。标签关系须当前有效，标签须未删除、启用且已审批通过；兼容历史
   `active=null`、`approvalStatus=null` 数据。
4. 客户已开户且有效标签不含精确名称“存量客户”时拒绝：
   `CUST-42216 / 该企业经判定已开户，无法再创建工作日志`。
5. “存量客户”只豁免开户状态，不豁免周期次数。
6. 一次批量读取全部有效标签规则；未配置规则按 `MONTH/5`。
7. 周期采用自然日、自然周（周一开始）、自然月、自然季度、自然年，时间条件为
   `[periodStart, periodEnd)`。
8. 统计口径为当前客户任务通过 `TOUCH_TASK.worklog_id` 关联的
   `xa_touch_custom_worklogs`，排除已销毁工作日志；同一实际自然周期只查询一次。
9. 多标签采用最严格命中：任一标签的周期计数 `count >= maxTouches` 即拒绝，返回
   `CUST-42217 / 客户触达次数已达到标签周期上限`。

## 4. 导入预览

- 支持 csv/xlsx/xls，首行/首个工作表首行为表头。
- 缺少“是否触达限制”列、值为空或不是“是/否”均计为错误。
- 错误批次状态为 `VALIDATION_FAILED`，最多返回 10 条错误样本。
- `VALIDATION_FAILED` 或 `errorRowCount>0` 的批次禁止执行，返回 `CUST-42201`。
- 文件解析失败作为校验失败保存明确错误摘要，不伪装为成功批次。

## 5. 查询与性能约束

- 管理页先分页标签，再按本页标签 ID 批量查规则，禁止 N+1。
- 触达校验批量读取标签和规则，不逐标签回查。
- 多标签落在相同自然周期时复用一次工作日志统计结果。

## 6. 数据库实施前置

真实环境启用前至少需要：

1. `CUST_LEAD.touch_restricted`，非空，默认 1；
2. `CUSTOMER_MARKET_CUSTOMER.touch_restricted`，非空，默认 1；
3. `CUST_TOUCH_LIMIT_RULE` 及 `tag_id` 唯一约束；
4. `TOUCH_TASK.worklog_id` 与 xa 工作日志迁移结构可用。

DDL 由 DBA 在隔离库完成盘点、备份和恢复演练后实施；应用单元测试和前端开发态 mock 验收不能替代真实数据库联调。

## 7. 并发边界

资格读取与任务创建处于同一业务事务，现有入口先拒绝同客户、同执行人的进行中任务。当前未针对
“客户 + 自然周期”建立串行化计数锁；若未来允许同客户并行创建多条触达任务，需要增加周期锁或原子计数占用，
防止临界值处的并发穿透。
