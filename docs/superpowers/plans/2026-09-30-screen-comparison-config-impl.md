# 信息卡比较数据配置改造方案

## 需求与范围

为大屏信息卡增加可保存的昨日、上月末、上年末比较来源配置，贯通编辑、DTO校验、受控历史查询、计算与真实渲染。继续使用当前简化的组件配置页面，不增加布局设计、新建、发布管理或任意SQL编辑能力。不改数据库结构，不新增REST URL或权限资源，不运行数据库脚本。

当前实现只配置主值，比较历史由运行时查找其他区块或既有兼容逻辑取得，不能作为显式比较配置。本方案以现有保存协议作兼容扩展，旧配置缺省继续按旧路径渲染。

## 配置协议

在 `canvasStyle.presentation.display.comparisons` 保存按实际配置区域键索引的类型化对象。可配置键为已有 METRIC_CARD/COMPLETION 的componentId，以及分行顶部overview-deposit、overview-loan、overview-settlementDeposit。

```json
{
  "business-retail-deposit-balance": {
    "enabled": true,
    "historyBlockId": 57,
    "valueFields": ["测试_直营零售存款"],
    "dateField": "data_date",
    "sourceUnit": "YUAN"
  }
}
```

- enabled=false 表示显式关闭比较，允许仅保存该布尔字段，不再回退旧比较。
- enabled=true 必須选择现有画布内受控LINE_TREND历史区块、日期字段、指标字段和源单位。
- valueFields为1到8个不重复字段；普通卡仅一个，金额总额可对同单位分项求和。完成率不得多字段求和。
- 只允许金融金额/数量/百分数已支持单位，不允许AUTO和未知单位。未知键、未知属性、类型错、空值、重复字段和越界区块均拒绝保存。
- 不使用通用Object绕过类型契约；DTO、前端闭合校验和当前组件树引用校验同步扩展。

## 页面交互

在相关卡片的主值配置下增加可折叠的“比较数据”。初始状态保留现有比较，用户明确启用自定义配置后填写历史区块、指标字段、日期字段和源单位；可关闭比较或恢复原配置。比较基期固定显示为昨日、上月末、上年末，不开放无关公式、增量手填或动态时间口径。

历史来源只能选择当前大屏已绑定的可用历史区块；展示字段来自该区块的数据源已声明元数据，指标与日期角色区分。用户修改主值后提示核对比较指标，不无声修改其他卡。原有dirty、取消、切屏、版本冲突和权限范围保留。

结算性存款主值仍沿用当前受控运行映射；比较来源可以显式配置，金额分项通过valueFields求和，未取得可核对当前值时显示待接入，不借用一般存款或演示值伪装完整联调。

## 受控取数

复用 `/api/screen/data` 的既有RANGE、dateFrom/dateTo、screenCode/blockId、previewState和batchId契约。不创建直接dsId查询或跨屏权限旁路。

先完成当前值正常查询，取得后端数据日期，再以数据日期的上年末至当前日查询已配置历史区块；相同区块同上下文去重。完整批次模式继承当前可信batchId与机构上下文。结果单独存于model.comparisonResults，不能覆盖用于增长曲线的普通blockResults。

配置来源改变触发必要的历史重载；只改标题不额外查询。过期请求、切屏/退出后的迟到响应废弃。403/401保持fail-close，其他历史取数失败只令比较不可用，不将主值补零或伪装成功。

## 计算和渲染

- 基期按后端数据日期计算：前一自然日、上月末、上年末，不能按电脑今天计算，也不等同于去年同日。
- 指定历史区块必须同时存在唯一当前日和唯一基期行；日期重复、单位冲突、缺字段、非数值、缺记录、当前历史值与卡片当前值不一致均保持待接入。
- 金额和数量先统一基准单位，再计算当前值减基期值，最后格式化，保留正、负、零，不在已舍入展示文本上做差。
- 百分数比较采用百分点差，区分RATIO与PERCENT输入，不计算相对增长率；显式配置的比较显示百分点，旧配置的既有显示不无关改写。
- 顶部总额卡显示真实基期值和增量；业务卡、收入卡、完成率卡使用同一解析器。显式关闭时真正隐藏比较区域；显式配置失败不回退自动扫描或演示历史。
