# 经营大屏管理视角改造

日期：2026-09-08。主目标是先完成分行代码化经营大屏及地市、支行下钻，之后优化零售维度；用户已明确退役拖拽设计器，并要求自行审核、发布、核验后交付。

## 业务判断与信息结构

系统的绩效中心维护指标、目标、KPI 结果，客户营销中心管理线索、触达、客户认领和资产立项，工作流负责审批。大屏应回答规模是否增长、目标差多少、哪些机构需要干预、客户和经营结构是否合理、有哪些事项需要协调。业务来源不同，不能把审批任务数量当客户数，也不能用对公贷款替代全行贷款。

分行采用核心经营结果、存款增量/月均、业务结构、中央机构地图、经营趋势、机构多指标对照与短板提醒。右侧的目标圆环与重复排名表合并，优先完整展示数值、差距和机构名称。地市展示独立市级汇总、机构达标分布、多指标比较及可搜索下钻；支行展示指标、同城位置、变化和可核实关注项。图形服务于比较，采用经营矩阵、矩形份额、趋势及数字差距，避免圆环和柱状图重复占据空间。

零售保持独立 AUM、储蓄、价值客户、收入、个贷、不良率语义。不得将全行来源默认解释为零售，也不得把城市筛选后的机构列表误称为城市汇总。

## 实施边界

- 保留当前代码模板、角色/机构范围、草稿、版本冲突保护、预览、发布与回滚。
- 删除拖拽编辑器与其专用依赖，历史已发布包保留必要只读渲染，不删除服务端发布记录；旧管理地址继续兼容。
- 默认绑定来自已授权来源及明确语义，保留修改入口和手工配置。不同单位、时点/月均、全行/条线、汇总/明细不可互换；不能为填满页面随意选择来源。
- 新增真实草稿数据核验，取数身份来自服务端已保存块；未保存变更不得拿旧草稿结果当当前结果。缺失、零、负数、重复、日期及机构覆盖分别校验。
- 主代理负责口径、集成与最终审核；Luna 按独立文件所有权完成分行视图、默认绑定、拖拽编辑器退役及数据核验，先红测后实现。

## 本轮实时核对

读取本地真实后端的大屏、数据源、指标定义、机构目录和当前发布包，原始证据受限保存于 `/tmp/yiti-screen-leadership-qa`。当前目录 5 屏、16 数据源；分行 SCR_PROVINCE 仍是历史发布包，草稿版本 72。该状态只代表核对时刻。

当前目标完成率源 9016 为 SQL 常量；M_0266 实际是一般性存款月均余额较上月，不能作为时点余额净增；贷款字段 M_0347 仅为对公一般性贷款。ACTIVE ORG 指标目录未提供可直接确认的全行客户、营收和真实目标完成率。市级汇总与机构画像仍需真实口径，不能按机构名称推断城市、按父子机构盲加总。

共享业务来源未经证实不能伪装为完整接入；发布验收须明确哪些配置已真实可用、哪些存在外部数据缺口。页面演示 fixture 只用于视觉交互验证，不作为真实经营数据证据。
