# 经营大屏真实机构与数据源接入方案

状态：只读核查后的实施建议，尚未实施。核查日期：2026-09-08。

目标是让已确认的代码化大屏使用真实机构、真实地理位置和已维护的数据源。机构画像负责“是哪家机构、归属哪里、位于哪里”；指标数据源负责“某日、某口径的指标是多少”；两者以 `orgCode` 关联，不以中文名称匹配。

## 机构与地图接入

### 机构目录

1. 复用机构管理目录的编码、名称及有效状态；名称更新自然反映到大屏，不维护另一份前端支行名单。
2. 补齐可展示经营机构的城市、经营性质、经营归属和地图信息。部门不作为支行点位；组织层级与经营等级分别处理，不能仅按层级或名称推断。
3. 运行时继续使用服务端授权后的 `panoramaInstitutions`，不直接调用全量管理接口绕过屏级范围。授权目录左连接指标；缺指标保留机构并显示“暂无数据”，不丢失机构、不填零。
4. `cityCode` 表达地理城市，`ownerOperatingOrgCode` 表达经营隶属。城市归属不能由经营隶属替代，经营隶属也不自动授予下级机构访问权。

### 定位优先级

| 条件 | 处理 | 展示 |
| --- | --- | --- |
| 已有合法且校验通过的坐标 | 使用保存坐标；坐标系须明确并统一到现有 GCJ02 契约 | 正常支行点位，详情显示位置来源 |
| 没有坐标，但有详细地址 | 服务端或受控批处理按省、市、区县、街道门牌解析；校验匹配城市和精度后形成候选位置 | 校验通过后标注；存在歧义的候选进入待核对列表 |
| 只有城市/区县级地址 | 只能用于区域归属；不得把区域中心当作支行营业位置 | 城市统计与机构列表保留，标记“待精确定位” |
| 无地址、解析失败、重名或跨城匹配 | 保留原始记录并提示补充或人工选点 | 列表可查询和查看指标，不伪造地图位置 |

建议在机构管理中增加：详细地址、地址来源、定位来源、定位状态、匹配精度、定位时间，以及地址解析预览/候选点确认。人工核定的坐标优先于后续自动解析，地址变更后标记需重新核对。地址和定位的存储需正式的数据模型决策，不能塞入 `remark`、前端常量或浏览器缓存充当主数据；不回写外部同步组织表。

地址解析在资料维护时进行，并按所选服务的使用条款管理缓存/保存；不要每次打开大屏都重复调用外部服务。现有路径未发现 geocoder 实现。可接入行内位置服务；若采用高德，其 Web 服务地理编码接口支持结构化地址、城市约束及匹配级别，需部署端配置服务 Key。官方资料：[地理编码 API](https://lbs.amap.com/api/webservice/guide/api/georegeo)。本次仅核对文档，未向地图服务发送机构资料。

省级维持城市聚合，市级展示已定位支行；点位密集时聚合，放大后展开。未定位机构要纳入城市列表和未定位数量，点击后查看档案/指标；城市本身未知的机构另列“城市待维护”，不能静默消失。

## 数据绑定与口径

沿用现有 14 个语义槽、数据源维护、草稿/发布快照及 `screenCode + blockId` 身份。一个数据源可以服务多个组件，每个组件映射明确的字段、原始单位、日期和范围。地图位置来自机构档案，点位颜色、大小、弹窗指标来自指标绑定；不要求每个图表重复维护名称和坐标。

建议管理端提供按展示区域排列的绑定清单，每行显示“数据源 → 字段 → 原始单位 → 日期/范围 → 校验状态”，选择机构字段时固定使用 `org_code`。兼容候选可预填，但口径有歧义时不能按别名自动确认。

### 现有来源的可复用性

| 展示需求 | 现有候选 | 接入前处理 |
| --- | --- | --- |
| 分行存款月均余额 | 9010“全省存款聚合”、9014“机构指标汇总”的 M_0265 | 可作为月均余额候选；核验原始单位和汇总机构口径，不能用作时点余额 |
| 存款净增 | 9010/9011 的 M_0266、9014 的分条线较上月指标 | M_0266 的业务名称是月均余额较上月，旧别名却称“净增”；必须改成准确标签，或选择真正的时点余额较上月指标 |
| 存款、贷款余额 | 9014 的对公/零售存款以及对公一般性贷款字段 | 对公贷款不能直接显示成全行贷款总量；先确认总量或分条线展示语义 |
| 机构排名、支行指标 | 9015“机构指标按机构统计”，9011“机构存款排名” | 9015 提供按机构宽表基础，但按首个指标排序；须取得完整候选后按所选指标取 TOP10，不能先截断。9011 只选了固定 10 个机构且主要是月均字段，不能直接声称全辖余额 TOP10 |
| 分行、支行趋势 | 9012“机构指标按日期统计”、既有宽表查询能力 | 9012 当前没有配置 `groupBy=DATE`，名称不能证明已按日期聚合。必须生成每日期一行的正确范围序列；支行趋势显式带授权 orgCode，不能把多机构逐行结果当作单机构趋势 |
| 对公/零售结构 | 9014 的分条线字段 | 核验可比较且互斥的组成口径，再映射/转换为 `name/value`；不能把基础性、结算性、一般性等可能重叠的类别相加 |
| 目标完成率 | 9016“存贷款余额完成率” | 当前 SQL 直接返回 3 个常量，旧画布也实际绑定了它；必须更换为真实目标与实际值或权威完成率来源 |
| 流程与经营关注 | 9005“在途流程概览” | 仅有任务总数查询，不代表待审批、超时等多种事项；其直接查 ACT_RU_TASK 属存量依赖问题。当前架构禁止 report 直接调用 workflow，需先明确符合模块依赖方向和机构范围的受控来源，不能新增跨模块私表直读 |
| 市级汇总 | 未发现可直接确认的城市汇总源 | 需确认城市与统计主体对应关系及去重口径，提供每城市一行；父级汇总机构与下属支行不能同时累加 |
| 客户总量、营收 | 此次数据源配置中未发现可直接确认的相应来源 | 补充权威指标来源；之前的示例值不进入真实模式 |

以上为配置候选，不是已经执行并核对数值的正式绑定。宽表指标定义、fieldMeta 的显示单位与真实 rows 单位还须交叉核对；不能因列别名带“亿元”就将原始数值认定为亿元。

**需要开发的契约缺口**：当前 `ScreenDatasourceServiceImpl.ensureNamedGroupDatasourceSafe` 将 NAMED_GROUP 数据源限定为 `ORG_INDEX_RESULT` 宽表。现有查询输出并不直接提供事项分类、业务构成的 `name/value`、每城市唯一行等模型；因此 `attention`、`composition`、`citySummary` 不能靠简单字段选择全部接通。须先设计受控查询或受限结果转换能力，继承同一授权范围和发布身份，并补齐保存、发布、运行及回滚校验；不能以改成 GLOBAL 或放开任意 SQL 绕过。14 槽已有字段契约只证明能声明绑定，不代表 14 槽已具备可用真实来源。

### 范围与日期

- 建议真实省/市/支行链路采用明确的机构范围，但不能把旧 GLOBAL/SUBJECT 数据源原样挂到 NAMED_GROUP 屏。须通过现有后端范围校验，配置与授权机构组一致的来源；不得为接入而放松校验器。
- 省级总量、市级总量、支行排名可能使用不同统计粒度。机构目录的展示覆盖与指标的汇总范围分开定义，消除上下级重复计算。
- 把“业务日期、机构范围、指标定义”作为一组绑定约束。某个来源落后于其他来源时逐项提示日期，不用一个“最新”标签掩盖跨日数据。
- 日均/月均余额不是时点余额，金额净增不是增长率。完成率聚合应依据目标和实际口径计算，不能直接平均支行百分比。
- 未绑定、查询失败、无记录、真实零值分别展示；401/403 清除旧数据，禁止以演示值或旧缓存遮盖。

## 建议实施顺序与验收

1. **主数据核对**：确认详细地址来源和营业机构范围，形成逐机构的城市/归属/定位缺口清单；核验已有 7 条画像，其他记录不能直接默认为支行。
2. **真实机构目录**：补充正式地址/定位契约与管理能力，完成授权目录的前后端传递；先验收真实名称、机构数、未定位数量和城市列表，不依赖指标全部到位。
3. **数据源适配**：先冻结 NAMED_GROUP 下事项、构成、城市汇总的受控取数/转换契约，再依据上表形成明确的槽位配置候选，优先完成有真实来源的存款月均、分条线余额、机构比较和趋势；补齐真实净增、目标、客户、营收及城市汇总。无来源的区域显示真实缺失状态。
4. **配置预检**：检查字段角色/单位、范围、日期、重复机构和截断风险；列出可绑定、需改造、缺来源各项。复制为新配置候选可避免无意改变旧发布屏引用的数据源。
5. **真实草稿联调**：使用有权限的实际账号核对机构清单，逐项比对来源结果；覆盖省→市→支行、未定位列表、负数/零/空值、失败重试和越权拒绝。
6. **发布验收**：后台数据核对和官方 playwright-cli 真实请求验收完成后，走既有草稿保存/原因发布流程切换展示入口。保留演示入口用于视觉验收，但真实业务入口不能落到 `/screen-preview`。

涉及代码的工作遵循 Sol 规划、Luna 按冻结契约做 TDD、Sol 最终审查。地址存储若需 schema 变化，由 DBA 按项目规则实施；不生成 DDL 或借运行时自动修改结构。真实画像、机构组、共享数据源和发布配置的写入须按现有权限、审计及目标库验证门禁执行，本方案不代表已实施这些写入。

验收必须分别给出：可展示机构数、已定位数/未定位原因、指标行覆盖、数据日期、槽位绑定状态及逐层汇总口径；不能仅凭地图有点、图表有数就认定真实接入完成。
