# 对公经营总览：页面与数据源设计

本页面向分管行领导、公司业务管理部门及机构负责人。复用省分行、零售大屏的蓝紫视觉、陕西机构地图、趋势和双侧经营分析，采用独立 `corporate-overview-v1` 模板。首要回答存贷款是否增长、资金沉淀是否稳定、规模能否形成收入、客户基础是否扎实、哪些机构需要推动、风险与协调事项如何跟进。

## 展示与管理动作

| 展示 | 管理问题与口径 |
| --- | --- |
| 对公存款余额、对公贷款余额 | 对公资产负债规模；不能以全行或零售数替代 |
| 对公存款月日均 | 观察持续资金沉淀；日均与时点分别展示，不用月底余额替代日均 |
| 对公营业收入 | 本年累计、已确认的条线收入归属；不是利润，不用投放金额替代 |
| 有效对公客户 | 业务确认的有效标准、按客户唯一编码去重；不以账户、线索或审批单数量替代 |
| 对公不良率 | 不良余额/同口径贷款余额；变化单位为百分点，不能当百分比增速 |
| 重点客群信贷分布 | 展示重点客群客户数与贷款余额；如科技、绿色、普惠等分类交叉，不累计为总量 |
| 机构经营对照 | 按对公存款余额、较上月净增、年度目标完成率切换领先/短板；同层级同期间比较 |
| 对公经营目标 | 实际、目标、完成率和差额；目标需与实际同指标、同范围、同期间 |
| 重点协调事项 | 如重点项目落地、存款到期维护、风险客户跟进；仅展示来源给出的数量、责任人与期限，不自动生成风险结论或任务 |

地图与城市选择只筛选机构对照，不改变全辖 KPI 与趋势范围。机构详情仅消费授权机构自身数据，缺失不以全辖数据填充。金额统一亿元，客户数统一万户；零、负净增、空值和请求失败分别保留。目标可超过100%，进度条仅限制视觉长度，目标缺失或不大于零不计算完成率。

## 数据源交付契约

以下是待绑定的数据产品设计，不是已存在物理表声明，也不代表真实数据已经接入。不新增业务数据库表。通过已有受控 WIDE_TABLE/指标来源及 screen 绑定、预览、发布能力接入；上游业务信息通过所属模块公开 QueryApi 或获准同步数据产品提供，不跨模块直接联表。

所有来源使用 `bizLine=CORP`，按服务端授权机构范围过滤。建议数据产品有明确的业务日期、期间、来源批次/版本、指标定义和责任部门；这些元数据不能仅靠页面当前时间证明。单值来源必须在当前范围恰好返回一行；机构明细须保留真实机构号，历史序列按日期唯一。不能同时加总省分行、地市、支行等父子层级。

| 建议数据源 | 槽位 | 字段 | 来源责任与粒度 |
| --- | --- | --- | --- |
| 对公经营指标汇总 | `corpDeposit`、`corpDepositAverage`、`corpLoan`、`corpRevenue`、`corpCustomers`、`corpNplRate` | `value`，可选 `change/date` | 财务/绩效结果、客户口径与风险结果；每指标、业务日期、授权经营范围一行 |
| 对公存贷款月末趋势 | `corpTrend` | `date`，`deposit/loan`至少一个 | 与首屏同口径的月末序列；月日均不混为时点余额，缺月不插值 |
| 对公重点客群信贷 | `corpSegments` | `name/customers/loan` | 公司业务及客户数据产品，客群×日期×授权范围；跨客群可重叠，须注明 |
| 对公机构经营对照 | `corpRanking` | `orgCode/name/deposit`；可选 `increase/rate/nplRate` | 同层级机构宽表；净增为较上月，完成率为对公存款年度目标完成率 |
| 对公经营目标进度 | `corpTargets` | `name/actual/target` | 绩效目标与已确认实际结果，金额类目标统一亿元；名称写明指标与期间 |
| 对公重点协调清单 | `corpAttention` | `label/count`；可选 `owner/deadline` | 公司部门确认的协调汇总、资产立项/风险跟进的获准结果；数量不可盲目求和 |
| 授权机构目录 | `branches` | `orgCode`及名称、城市、经纬度等既有身份字段 | auth机构画像及授权目录交集，仅用于机构身份与定位 |

金额输入支持 `YUAN/TEN_THOUSAND/HUNDRED_MILLION`；客户支持 `COUNT/TEN_THOUSAND_COUNT`；比例支持 `PERCENT/RATIO`；协调数量仅 `COUNT`。单值 `change` 除不良率外是较上期百分比变化，不良率为百分点差；输入RATIO时均转换为百分数单位。明确禁止零售AUM、储蓄及全行来源自动匹配为对公数值。

项目历史核验曾识别 M_0277 为对公一般性存款、M_0347 为对公一般性贷款，但历史记录不等于当前来源已核实可用。一般性存贷款也不自动代表全部对公存贷款。自动推荐优先依据明确语义、条线、字段角色与单位，不用历史字段编号硬凑完整页面。未确认的有效客户、收入、目标、风险指标保持待接入。

## 页面入口与权限

- 开发视觉入口：`/#/screen-preview/corporate`，明确“本地演示 · 非业务数据”。
- 大屏中心：服务端逐屏授权后返回 `SCR_CORP_OVERVIEW`、`corporate-overview-v1`、`DEMO`；受保护页面 `/#/screen-pages/corporate-overview-v1` 再次复核目录授权，沿用零售现有演示展示模式。
- 实际来源运行：通过现有 `/#/screen/:screenCode` 的草稿/发布包选择对公模板、按可信 `blockId/bindSnapshots` 取数；不会把中心演示数据回填为正式结果。
- 管理页选择CORP屏，使用对公模板和已授权CORP来源；仍执行草稿版本冲突、保存/发布验证。后端兼容版本必须先部署，旧服务不能启用新模板。

本轮不执行数据库DML，不改动已有真实发布包。页面和绑定能力、开发预览、实际来源接入及发布是不同验收项。

## 自动绑定的语义元数据

自动配置只使用明确声明的字段语义，不根据“对公来源”等数据源名称推断。指标列在受控配置的 `metrics` 或 `fieldMeta` 中声明 `semantic`、原始 `unit` 及字段角色。例如对公存款余额声明 `semantic: "corpDeposit"`，贷款声明 `semantic: "corpLoan"`，客户声明 `semantic: "corpCustomers"`；指标编码必须选择实际指标目录中的已确认条目，不能把示例名当成已存在编码。

趋势复用 `corpDeposit/corpLoan` 语义并提供日期维度；排名净增使用 `corpDepositIncrease`，完成率使用 `corpDepositRate`。客群名称使用 `corpSegmentName`；协调列使用 `corpAttentionLabel/corpAttentionCount/corpAttentionOwner/corpAttentionDeadline`；目标列使用 `corpTargetName/corpActual/corpTarget`。已有手工绑定保留，元数据不足时由管理页明确选择字段并核对口径，不自动写入来源或替换现有绑定。
