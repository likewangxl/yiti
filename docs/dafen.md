

## 银行内部评价模块设计方案

### 一、 模块概述

本模块用于实现银行内部多层级、多角色的相互评价。核心特点为：

- **双标签体系**：每个人员拥有“被评价身份”和“评价人身份”两套独立标签，灵活定义评价关系。
- **以被评价人为中心的关系配置**：为每一类被评价人（如营销正职）单独配置有权评价的群体及其权重。
- **组内平均、组间加权**：同一评价人组内多人时取平均分，各组按权重汇总最终得分。
- **手工发起、一次性打分、不允许修改**：评价任务由管理员手动发起，评价人打总分，提交后不可修改。
- **分数下限控制**：最低分为10分，低于此值系统阻止提交。

### 二、 标签体系设计

人员档案中新增两个标签字段，两者枚举值统一维护，但人员可分别拥有。

**2.1 标签库（字典表）**

| 标签ID | 标签名称       | 标签类型       |
|--------|----------------|----------------|
| 101    | 省分行正行长   | 评价人标签     |
| 102    | 省分行副行长   | 评价人标签     |
| 201    | 支行行长       | 被评价人标签   |
| 202    | 营销正职       | 被评价人标签   |
| 203    | 部门正职       | 被评价人标签   |
| …      | …              | …              |

> **人员示例**：张三，被评价标签=营销正职；评价人标签=省分行副行长。表示张三被评时按营销正职规则接收评价，同时他作为省分行副行长有权评价他人。

### 三、 评价关系配置（设置页面）

管理员进入该页面，对每一类“被评价人”定义它的评价人组合及权重。

**3.1 主列表页**

展示所有已配置的评价关系规则，每行一条：规则名称、被评价人标签、评价人组数、权重总计（必须100%）、状态（启用/停用）。提供“新建规则”按钮。

**3.2 新建/编辑规则页**

1. **选择被评价人标签**：下拉选择，例如“营销正职”。不可重复建立相同标签的规则。
2. **添加评价人组**：
   - **组类型一：按标签选人**  
     选择评价人标签（如“省分行正行长”），设置该组所占权重（如50%）。保存后，该标签下所有人员都将成为评价人。
   - **组类型二：按组织选人（员工组）**  
     不选标签，直接设定“被评价人所属部门的所有员工”为一个组，设置权重（如20%）。
   - 可添加多个组，支持拖拽排序（仅影响展示）。
3. **权重校验**：页面底部实时显示总权重，必须等于100%才能保存。
4. **完成保存**：保存后，系统自动生成评价关系配置记录。

**3.3 存储方式**

评价人组配置中，“按标签选人”记录标签ID，“员工组”用特殊标识（如组类型=2）。具体人员不在此处展开，待任务发起时动态解析。

### 四、 评价任务管理

采用手工发起的方式，便于控制时机与范围。

**4.1 发起任务**

管理员进入“评价任务管理”页面，点击“新建任务”：
- 选择本次评价覆盖的被评价人范围：可按部门勾选、按被评价人标签批量选取。
- 系统依据“被评价人-评价规则”自动生成待评价清单。
- 确认发起后，在评价人端显示待办。

**4.2 任务有效期**

可设定截止日期，过期自动关闭。

**4.3 状态流转**

待评价 → 已评价（所有人完成）或进行中。不展示结果（按需求暂不展示评分结果）。

### 五、 评价人打分界面

评价人登录系统，进入“我的评价”菜单。

**5.1 列表展示**

按“被评价人所在部门”分组显示所有待评价对象。类似：

```
- 桃园路支行 (待评2人)
- 科技部 (待评1人)
- 分行营业部 (待评3人)
...
```

点击部门展开人员清单：
```
科技部
  - 李四（部门正职） [待评价]
  - 王五（部门副职） [待评价]
```

**5.2 打分页面**

点击具体人员进入打分：
- 显示被评价人基本信息（姓名、部门、岗位）。
- **评分输入框**：仅一个总分输入框，限制输入整数，范围10~100分。输入低于10分时弹窗提示“分数不能低于10分”并阻止提交。
- **提交按钮**：点击后直接提交，无评语，提交后该条记录状态变为“已评价”，不可再修改。同时更新任务完成进度。

**5.3 进度提示**

在列表页可看到每个人员的评价状态（已评/未评），并可筛选。

### 六、 评分计算规则

当一次评价任务中所有评价人对某被评价人都提交后（或任务截止后），系统自动计算最终得分，存入结果表（留待后续展示）。

**计算公式**：
1. 对于评价规则中的每个评价人组：
   - 收集该组所有评价人的打分。
   - 计算该组的**平均分**（四舍五入保留一位小数）。
   - 组得分 = 平均分 × 该组权重
2. 被评价人总得分 = 各组得分之和，范围10~100。

**示例**（营销正职）：
- 省分行正行长组（权重50%）：只有1人打分80，组得分 80×0.5 = 40
- 省分行副行长组（权重30%）：3人打分70,80,90，平均80，组得分 80×0.3 = 24
- 部门员工组（权重20%）：10人平均85，组得分 85×0.2 = 17
- **总分** = 40+24+17 = 81

### 七、 数据表设计

**7.1 标签字典表 (eval_tag)**
| 字段名 | 类型 | 说明 |
|--------|------|------|
| tag_id | int | 主键 |
| tag_name | varchar | 标签名称 |
| tag_type | tinyint | 1-被评价人标签, 2-评价人标签 |

**7.2 人员标签关联 (staff_tag)**
| 字段名 | 类型 | 说明 |
|--------|------|------|
| staff_id | int | 人员ID |
| tag_id | int | 标签ID（可拥有多个） |

（通过 tag_type 区分人员同时拥有的两种标签）

**7.3 评价关系规则主表 (eval_rule)**
| 字段名 | 类型 | 说明 |
|--------|------|------|
| rule_id | int | 主键 |
| be_eval_tag_id | int | 被评价人标签ID |
| rule_name | varchar | 规则名称 |
| status | tinyint | 启用/停用 |

**7.4 规则-评价人组明细表 (eval_rule_group)**
| 字段名 | 类型 | 说明 |
|--------|------|------|
| group_id | int | 主键 |
| rule_id | int | 所属规则 |
| group_type | tinyint | 1-按标签, 2-部门员工 |
| eval_tag_id | int | 当type=1时的评价人标签ID |
| weight | decimal(5,2) | 权重百分比（如50.00） |
| sort_order | int | 排序 |

**7.5 评价任务表 (eval_task)**
| 字段名 | 类型 | 说明 |
|--------|------|------|
| task_id | int | 主键 |
| task_name | varchar | 任务名称 |
| start_date | datetime | 开始时间 |
| end_date | datetime | 截止时间 |
| status | tinyint | 0-未开始,1-进行中,2-已结束 |

**7.6 任务-被评价人明细 (eval_task_target)**
| 字段名 | 类型 | 说明 |
|--------|------|------|
| target_id | int | 主键 |
| task_id | int | 所属任务 |
| be_eval_staff_id | int | 被评价人ID |
| rule_id | int | 使用的规则ID（生成时即确定） |
| final_score | decimal(5,1) | 最终得分（计算后填入） |

**7.7 评价打分记录 (eval_score)**
| 字段名 | 类型 | 说明 |
|--------|------|------|
| score_id | int | 主键 |
| task_id | int | 任务ID |
| target_id | int | 关联的 task_target |
| eval_staff_id | int | 评价人ID |
| group_id | int | 所属评价人组 |
| score | int | 打分（10-100） |
| submit_time | datetime | 提交时间 |

> 说明：一张打分记录一旦提交，不可更新或删除。通过 target_id 和 eval_staff_id 可确保同一评价人对同一被评价人只打一次分。

### 八、 界面流程与交互要点

**流程总览**：  
标签维护（基础数据） → 配置评价关系规则 → 管理员手工发起评价任务 → 评价人登录看到待办 → 按部门-人员逐一点击打分 → 提交后不可修改 → 管理员可在任务结束后查看进度（不展示分数）。

**关键交互细节**：
- **设置页面权重和必须为100%**：增加、删除组时实时计算并提示。
- **打分输入校验**：前端限制只能输入10-100的整数；后端同样校验。
- **不允许修改**：评价人提交后，该条评分记录即固定；页面列表对应项灰化显示“已评”。
- **匿名性**：所有打分记录均记录评价人ID，不匿名（系统内可溯源，但结果暂不展示）。
- **无评语**：界面不提供文本输入框。

### 九、 扩展性与后续规划

当前需求暂不展示评价结果，但数据已存储完整。后续可扩展：
- 个人得分报告与排名
- 多维度指标（替换总分框为指标矩阵）
- 评价周期定时任务
- 移动端适配
