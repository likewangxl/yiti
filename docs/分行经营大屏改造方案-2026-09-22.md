版本：V1.0，业务与技术联合评审稿；日期：2026-09-22。

> 后续范围约束（2026-09-22）：用户明确要求“除大屏展示内容外，不修改其他功能组件代码”。本稿保留为完整业务需求背景，其中绩效、指标库、目标、导入、机构治理等跨模块改造不再属于本次执行授权。实际执行以 [大屏限定范围执行计划](screen-display-refactor/EXECUTION_PLAN.md) 和同目录 `SCOPE.json` 为准；原人日估算也不能直接沿用为本轮排期。

## 1. 编制依据与建议结论

本方案依据用户提供的《分行经营数据大屏系统需求沟通会·会议纪要》、用户补充的“数据源配置直观化，组件标题、展示内容、数据均可配置”要求，以及本次仓库源码核对形成。

- 需求材料：`C:/Users/51799/Downloads/分行经营数据大屏系统需求沟通会·会议纪要.md`。
- 代码基线：`feat/code-screen-panorama`，提交 `dced49aaec6220b56991d774b0cae8435115d795`。
- 会议纪要标注会议时间为 2026-09-22；口头描述为“昨天展示”。本稿按纪要归档日期命名，实际会议日期及“周一大会”的具体日期另行确认，不据此承诺交付日。
- 本次完成需求分析和静态源码核对，未连接数据库、启动页面、执行数据导入或复跑业务测试。以下“已有能力”表示源码存在相应实现，不能等同于现网已开通或目标库已具备数据。
- 会议中的行动项是本方案的需求依据，不视为本轮已授权实施、数据库变更或发布。纪要内的总行支付二期进展、领导宣讲安排属于背景事项，不纳入本次系统开发范围。

建议将本次改造定义为：**保留已认可的经营大屏视觉基础，建设统一组件配置、统一业务取数和统一机构导航。**

具体采用以下方向：

1. 以组件为操作入口。用户选中某张指标卡、排名或地图，在同一个配置面板完成标题、内容、指标/KPI、机构与时间范围、展示格式及跳转设置。
2. 以指标编码、KPI 方案与目标方案为数据身份。表名、宽表槽位、SQL、返回列映射收敛到后台适配层，普通配置人员不需要理解。
3. 以“地域/机构层级 × 综合/公司/零售条线”组织页面。保留省、市、机构下钻，并让公司/零售切换继承当前机构和周期。
4. 以发布版本固定配置及口径。页面、数据集定义、指标名称快照、公式、KPI/目标版本一起发布；修改共享来源不会直接改变已发布页面。
5. 分阶段建设。先完成口径与数据盘点，再打通取数、组件配置和导航，最后迁移、对账和切换；大会展示版本单独限定范围。

本次不建议恢复一个任意拖拽、任意脚本的通用低代码平台。首期支持受控模板中的组件增删、显隐、顺序、规格和数据配置，既保留当前视觉效果，也能覆盖会议提出的变化。完全自由布局作为后续独立需求评估。

## 2. 现状核对：哪些能复用，哪些必须改造

### 2.1 当前真实结构

后端仍为 Spring Boot 模块化单体。指标、KPI、目标和结果由 `performance-engine-center` 管理；大屏配置、发布和查询由 `report-analytics-center` 管理；机构画像、机构组和权限由 `auth-permission-center` 管理。前端为 `xanzc_frontend`。

当前代码化大屏采用固定 Vue 模板，绑定保存为 `ChartWidget` 节点：`propValue.bindingKey` 标识槽位，`bindJson` 保存 `dsId / period / fields / units`。配置链路包含独立数据源管理、页面绑定、页面元数据/角色设置、草稿验证和发布。

这能解释用户感受到的混乱：用户实际要配置“存款完成率组件”，系统却要求先理解数据源类型、宽表、字段与槽位，再到另一处绑定页面内容。改变字段别名也不保证改变页面标题。

### 2.2 关键事实与改造影响

| 核对项 | 当前源码事实 | 改造判断 |
| --- | --- | --- |
| 组件身份与标题 | `bindings.js` 固定声明分行、公司、零售槽位；生成绑定节点时写入默认 `styleJson.title`；`PanoramaDashboard.vue` 仍有固定区块标题 | 单改输入框不能覆盖运行时。需同时改变配置契约、保存校验、发布包、数据模型和组件渲染 |
| 页面展示声明 | `CodeScreenPresentationDTO` 目前只有 `type`、`template` | 缺少统一的组件展示配置与版本化模型 |
| 数据源类型 | 已存在 WIDE_TABLE、KPI_RESULT、KPI_DETAIL，以及特定的 M98_STAT、FREE_REPORT、CUSTOM_SQL 适配 | 用户界面需要改成业务选择器；新增经营大屏数据不得无条件沿用所有历史来源 |
| KPI 机构组配置 | `Datasources.vue` 在命名机构组下禁用 KPI_DETAIL；后端 `ScreenNamedGroupDatasourcePolicy` 已允许 schema2 + ORG + SNAPSHOT + SINGLE | 前后端能力表达不一致。优先采用服务端能力清单，避免再维护两套静态禁用规则 |
| 指标状态 | `PerfMetricDef.status`、指标状态变更接口和 ACTIVE/DISABLED 逻辑已存在 | 会议的“增加状态”应落实为补齐有效期、失效管理和引用检查，不重复建同义字段 |
| 指标容量 | 实际 `MetricSlotService` 按维度分配 L1=1～200、L2=201～300、L3=301～400；类型处理器上限为 400 | “核心指标约 400 个”不是可直接套用的容量结论；还要盘点维度、层级、占用、历史保留和临时指标增长 |
| 完成率 | 大屏 `ScreenQueryEngine` 使用 `actual/target×100`；绩效明细 `KpiScoreCalcService` 使用 `(actual-base)/target×100` | 存在明确公式差异。先统一业务口径与公式标识，不能只把数据源切到 KPI 就认为完成 |
| KPI 结果 | `PERF_KPI_SCORE` 包含实际值、目标值、基础值、权重和得分；旧 KPI_RESULT 查询主要为员工总分 | 机构总分、单项得分、业务完成率必须分开，不能把员工总分直接接作机构完成率 |
| 导入 | 已有 KPI_SCHEME、TARGET_PLAN、KPI_SCORE、METRIC_DEF、METRIC_RESULT 等策略；现有目标方案导入新建时默认 EMP，`kpiSchemeId` 为空 | 可以复用解析和校验能力，但“一次导入机构 KPI＋目标”需要补关联、机构维度和整体事务，不能简单串联现有导入接口 |
| 配置发布 | 已有草稿、发布包、归档、`canvas_version` 乐观锁 | 应复用；新增配置与数据集版本必须一起校验、发布、回滚 |
| 数据源修改 | `ScreenDatasourceServiceImpl.update` 允许对已发布引用的数据源原地修改查询语义，并重新校验和审计 | 页面发布包不等于完整冻结了取数语义。新方案需增加不可变数据集修订版 |
| 数据一致性 | `usePanoramaData` 已有请求去重、并发限制、切换代际、分行批次锁定等机制 | 保留并推广；不是所有历史查询源都已有同等的不可变批次保证 |
| 机构画像 | 已有 `orgNature`、`operatingLevel`、经营归属、城市、坐标和版本 | 复用画像和授权目录，不能凭机构名称是否含“小微”自行过滤 |
| 地图/排名 | 已有省市地图、城市打开及机构选择；当前经营矩阵仍使用 TOP10 结果路径 | 改为全量授权机构逻辑列表、手动滚动和按业务指标切换；同时解除查询端截断影响 |
| 数据模式 | 当前入口代码支持分行 TEST、公司/零售 TEST 或 LIVE，支行页有测试/存量路径 | 不能概括成“全是模拟”或“全是真实”。迁移前必须逐组件核对来源、日期、覆盖与业务签认 |

### 2.3 需要先纠正的实现理解

当前仓库文档中还残留“两张屏”“零售 DEMO”等旧说明，但入口代码已包含三种代码模板；此前旧设计器文件路径也不能继续作为当前入口依据。后续开发以本次源码定位为基础，同时更新相关操作指南和接口文档。

## 4. 页面与导航改造

### 4.1 用两个维度表达导航

纪要称“四级导航”，文字同时列出了分行、公司/零售、市地图、支行、支行公司/零售，不能机械实现为必须顺次点击的五页单链。建议按以下结构组织：

```text
工作台 / 大屏中心
└─ 分行综合总览 ── 条线切换 ── 分行公司 / 分行零售
   └─ 点击地市：市级地图与经营摘要（继承综合/公司/零售）
      └─ 点击机构：机构综合总览 ── 条线切换 ── 机构公司 / 机构零售
```

城市是地理分组，一级/二级分行是经营组织层级，两者独立建模。不能把一个城市直接等同于一个分行，也不能根据机构编码长度推断层级。

建议共享上下文：`screenCode、scopeLevel、orgCode、cityCode、bizLine、period、releaseId、snapshotId`。路由携带可公开的选择参数，服务端重新解析和授权；`snapshotId` 为服务端签发/验证的查询快照标识，不能作为绕过权限的凭证。

- 公司/零售切换保留当前机构和统计周期，不跳回全省。
- 地市/支行跳转保留来源面包屑；浏览器返回恢复地图缩放、选中机构及排名指标。
- 直链打开先验证当前账号对目标屏、机构、条线的权限；无权时进入明确拒绝状态，不回退到其他机构数据。
- 参数缺失按发布配置选默认页；非法参数报错；不得继续使用代码里的示例机构号作为默认业务机构。
- 旧 `/screen-pages/:template`、`/branch-operating?orgCode=...` 链接保留兼容适配。新 URL 最终形式在路由设计时统一，避免为每个机构复制页面。

### 4.2 页面组件清单

| 页面 | 首期组件 | 关键行为 |
| --- | --- | --- |
| 分行综合 | 核心指标卡、完成情况、业务结构页签、省级地图、机构排名、趋势 | 存款/贷款/营业收入/中收按核定口径配置；结构切公司/零售；地图进入城市 |
| 分行公司/零售 | 条线指标卡、条线完成情况、机构排名、地图、趋势 | 复用骨架，指标集合与口径独立，不用全行指标替换条线指标 |
| 市级地图 | 本市经营摘要、地图机构点、机构列表 | 默认仅可访问的真实机构；返回上层保持筛选；无有效机构城市不可进入空白页 |
| 机构综合 | 本机构核心指标、完成情况、业务结构、趋势 | 所有组件固定当前 orgCode；统计不得误回退到分行总量 |
| 机构公司/零售 | 对应条线指标、完成情况、趋势 | 复用条线模板并应用机构上下文；员工排名暂不纳入 |

地图省级采用较大默认视野和深色风格；机构页采用较紧凑的地图占位与适配边界，二者分别配置，不共用一个缩放常量。着色指标与排名选中指标一致，并显示日期、单位和图例；缺数用中性色，不视为最后一名。

### 4.3 排名与轮播规则

1. 总分和存款/贷款/客户等单项为指标页签，点击后立即切换当前榜单并暂停自动切项；可显式恢复轮播。建议默认间隔 10 秒，可配置。
2. 每张榜单展示全部可参与比较的授权机构，采用自然纵向滚动，必要时前端虚拟列表；不把虚拟渲染误当成数据只取一屏。
3. 数据接口返回范围总数、可排名数和缺数机构数。服务端分页时必须拉取完整快照或使用同一排序快照分页；不能只展示接口默认前 N 条。
4. 轮播切换的是“指标榜单”，不是把机构按五家分组轮播。滚轮、拖动、触摸和键盘都可访问全部行。
5. 默认从高到低展示正向完成率；逆向指标按经确认的规则。并列建议使用竞赛排名 `1、2、2、4`，机构编码作为稳定次序，不改变并列名次。
6. 缺失、零目标或口径不适用的机构放入“未参与排名”，说明原因；合法零值保留参与，不得过滤成无机构。
7. 鼠标悬停或键盘焦点进入榜单时暂停动画；页面隐藏或离开后停止定时器。

## 5. 统一配置中心：用户如何配置一个组件

### 5.1 操作页面

在现有“大屏管理”入口升级出“经营大屏配置”，普通用户以页面和组件为起点。原始“数据源管理”保留为技术/高级维护入口，并逐步转换为有版本的“可复用数据集”。

```text
顶部：页面/机构模板选择｜草稿版本｜校验｜预览｜发布｜版本历史
左侧：页面结构与组件列表      中间：实时页面预览       右侧：当前组件配置
      核心指标区                   点击选中组件              基础与标题
      完成情况区                   缺数据就地提示            展示内容
      业务结构区                                            指标与数据
      地图区                                                范围与周期
      排名区                                                格式与交互
                                                            校验与来源
```

右侧先显示业务字段，高级物理映射按权限折叠。选择指标后自动展示名称、口径、单位、维度、有效期、最近可用日期；配置人员无需先去另一页创建数据源。

### 5.2 每个组件可配置的内容

| 配置组 | 可配置项 | 约束 |
| --- | --- | --- |
| 标题 | 自动指标名/自定义标题、副标题、说明、图例名、表头 | 空覆盖值回退自动名称；支持清除覆盖；不允许标题改变指标编码或统计口径 |
| 内容 | 指标卡数量与顺序、主副指标、趋势系列、表格列、结构页签、排名指标项 | 使用该组件支持的角色和基数；不能随意把单值绑定成多行表 |
| 数据 | 指标库、KPI 方案/明细/总分、目标方案，或经批准的组合数据集 | 全部使用稳定编码/ID及修订版；不凭名称猜测，不允许任意 SQL |
| 计算 | 实际值、目标、基础值、完成率、差额、同比/环比 | 选择绩效域已登记的计算规则；大屏只格式化，不复制财务公式 |
| 范围 | 当前机构、授权机构集合、经营层级、公司/零售、必要的业务维度 | 前端配置只能收窄，实际范围由服务端取交集 |
| 周期 | 数据日期、年/季/月、最新完整日期、趋势区间 | 目标周期与结果日期匹配；跨年和阶段目标有明确选择规则 |
| 格式 | 原始单位只读、显示单位、小数位、千分位、正负色、百分数格式 | 禁止 COUNT 当金额；RATIO/PERCENT 转换由元数据确定，避免乘两次 100 |
| 交互 | 切项轮播、间隔、点击跳转、面包屑、是否显示返回 | 跳转只能选白名单页面动作，不能注入任意脚本或绕开权限 |
| 显示与布局 | 显隐、顺序、受控大小规格、空态文案、说明提示 | 布局模板保证可读和不溢出；关键信息如数据性质不能被隐藏 |

组件类型首期覆盖：指标卡、完成率/水位图、趋势图、结构占比页签、排名表、地图、明细表。一个组件可有多个指标/系列；一个指标可被多个组件引用，不为每次引用重复建指标或复制原始数据。

### 5.3 标题与口径的优先规则

默认标题取所绑定指标在当前发布修订版中的业务名称；多指标组件默认取模板业务标题，系列分别取指标名称。

标题解析顺序为：机构特定覆盖 → 当前页面组件覆盖 → 已发布模板默认 → 指标名称快照。管理页显示每项配置“继承自何处”，支持恢复继承。

更换指标后，自动标题随候选指标变化；已有自定义标题保留但标记“请核对与新指标是否一致”，发布前确认。原始名称、编码、口径和单位始终可查看，避免仅改标题就把“公司有效户”伪装成“全部客户数”。指标库改名生成新元数据修订，已发布页面不静默变更，配置人员在升级预览中确认。

### 5.4 示例：配置“公司存款目标完成率”

1. 在分行公司模板上选中完成率组件。
2. 选择“来自 KPI 明细”，选择 KPI 方案、存款指标、机构维度和目标方案。
3. 系统展示实际值、目标值、基础值、周期及可用公式；选择经确认的“余额目标完成率”或“净增目标完成率”。
4. 标题默认采用业务指标名称，可以改成“公司存款目标完成率”；格式选百分比两位小数，开启实际值与目标值辅助显示。
5. 范围设为“当前页面机构”，无需逐个支行复制配置。
6. 即时预览显示原始数值、计算过程、数据日期和效果；若目标为空，显示“目标未配置”，禁止补成 0%。
7. 保存草稿后执行真实数据校验，再预览并发布。改变标题、切换指标和保存数据集均不会绕过发布步骤。

### 5.5 配置校验分三层

- 输入时：即时检查标题长度、单位、组件支持字段、格式和必填项，不查询数据库也能指出配置错误。
- 保存/预览时：服务端核对来源、权限、指标有效性和配置版本；试查真实结果并返回行数、粒度、覆盖、重复、缺值及日期。
- 发布时：对本次完整配置重新检查引用和口径，给出变更摘要和受影响页面清单。阻断错误必须修复；数据过期等告警允许按已批准发布策略处理并保留提示，不能统一忽略。

## 6. 组件配置与数据源的技术边界

### 6.1 三层模型

| 层次 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 业务指标目录 | 指标稳定编码、名称、口径、单位、来源、有效期；KPI 与目标关系 | 页面位置和颜色 |
| 数据集定义 | 选哪些指标、结果形状、维度、周期、聚合/公式规则和数据修订；受控查询适配 | 某一个页面的标题、字体和点击动作 |
| 组件配置 | 如何展示、显示哪些项、标题、列/系列、单位换算、交互，以及引用哪个数据集修订 | 定义新的财务事实或直接编辑业务值 |

用户看到的是一个操作面板，后台仍保持这三层分工。共享数据集可以被多个页面复用；只改某一组件标题，不影响其他页面；修改共享取数规则先生成新修订，并显示被哪些组件引用。

“数据可配置”在正式页面中指选择来源、口径、条件、公式和周期；不开放直接输入任意经营值。业务数据修正走指标/目标导入和审批。演示数据采用独立数据模式与醒目标识。

### 6.3 数据集版本与页面发布

现有 `RPT_SCREEN_DATASOURCE` 可保留为来源身份表；建议新增不可变修订实体（建议名称 `RPT_SCREEN_DATASET_REVISION`），保存配置、输出契约、元数据快照、来源类型、版本、摘要哈希和创建审计。最终物理结构须依据目标库只读盘点后确定。

发布包固定数据集修订及公式/指标契约修订；运行查询按该修订解析。当前 mutable 数据源不得作为新发布包的最终查询事实来源。

保存继续使用 `canvas_version`；数据集草稿另有版本校验。发布时检查被引用修订未改变，生成页面快照并原子提交。发生并发冲突返回 409 和差异摘要，不自动覆盖他人修改。

配置回滚恢复页面与引用的数据集/口径修订；数据日期默认仍按原查询策略更新。若需复现历史经营值，必须另行指定已保留的数据快照，不能把“配置回滚”宣称为“业务数据回滚”。

## 7. 统一指标、KPI 与目标取数

### 7.1 取数职责

推荐链路：业务指标/方案/目标维护与导入 → 绩效域结果计算及快照 → 公开只读查询 API → 报表域组装组件结果 → 前端展示。

`performance-engine-center` 负责数值来源、公式、版本、结果粒度和口径；`report-analytics-center` 负责授权后的组件编排与查询，不新增对绩效私有表的直接读取。现有 `ScreenQueryEngine` 的相关直接查询是迁移对象，不是新功能的复制模板。

在现有 `MetricApi / MetricQueryApi / KpiApi / TargetApi / BranchDashboardBatchQueryApi` 上评估扩展，或增加范围清晰的 `OperatingMetricQueryApi`。新接口至少支持：

- 一组机构 × 一组指标 × 数据期间的批量查询，避免每张卡片独立扫库。
- 机构 KPI 总分、明细实际值、目标值、基础值、得分和已登记完成率规则。
- 明确的 KPI 方案、目标方案、方案修订和结果批次选择。
- 数据来源、口径版本、时间、单位、缺失/过期/不适用状态与覆盖信息。
- 对空机构集返回空或拒绝，不把空集合解释为全量。

前端不能提交宽表槽位、任意 SQL 或未经批准的计算表达式。公开查询 API 接收服务端确认后的授权机构范围，不能从浏览器请求直接透传成可信参数。

### 7.2 完成率口径统一

现有两种公式均可能在特定业务下正确，但不能用于同一个指标而不作说明。建议建立以下可选业务规则，并由指标/KPI 契约绑定规则代码与修订：

| 规则 | 公式 | 适用条件 |
| --- | --- | --- |
| 余额/绝对量目标 | 实际值 ÷ 目标值 × 100% | 目标本身是期末余额、累计收入或绝对户数 |
| 净增目标 | （实际值－基础值）÷ 净增目标 × 100% | target 字段明确存储“要求净增额” |
| 期末目标转增量 | （实际值－基础值）÷（期末目标－基础值）× 100% | target 字段存储期末目标且业务要求评价净增完成情况 |
| KPI 总分 | 按方案定义输出总分 | 单位为分，不默认转为百分比 |
| 逆向/自定义考核 | 引用已批准的绩效规则 | 风险率等越低越好的指标，禁止套用正向完成率 |

例如实际值 120、基础值 50、目标字段 100：绝对量完成率是 120%；若目标 100 表示净增目标，完成率是 70%。如果目标 100 表示期末目标而评估净增，则为 140%。这些数值仅用于解释公式，不作为业务测试数据。

统一规则还必须涵盖：

1. 匹配键包含机构、指标、条线、数据期间、KPI方案、目标方案及修订；同一指标存在多个目标方案时，不取“第一个命中”。
2. 从 `PERF_KPI_SCORE` 读取实际/目标快照时必须同批；如业务选择最新批准目标，应先重算或生成新快照，不能把旧 KPI 实际值与新目标静默拼接。
3. 空值、零目标、负目标和分母为零分别说明。没有经批准的特殊公式时返回“不适用/待配置”，不能填成 0%、100% 或无穷大。
4. 真实完成率可为负或超过 100%；视觉水位可限制在 0～100，但数值、提示、排序使用原始结果。
5. 先用原始单位和高精度十进制计算，再格式化。金额换成万元/亿元不能改变比例；0.125 的 RATIO 与 12.5 的 PERCENT 均应显示 12.5%。
6. 集团/城市汇总完成率优先取经过确认的上级 KPI 结果；若允许从下级汇总，应先汇总相同口径且互斥机构集合的分子、分母再计算，禁止简单平均完成率。
7. 总分、单项得分和完成率分别声明单位；已有权重计分结果不得再乘一次权重。总分缺少必需考核项时，不将残缺和当作完整总分。

建议把计算规则统一下沉绩效域，由 KPI 明细页与大屏共同消费。同一机构、日期、方案、指标在两个页面上的结果必须一致。

### 7.3 一次导入的业务流程

“一次导入”应解释为一份业务维护成果由多处复用；仅导入方案和目标不会凭空产生今后每天的实际经营结果，实际指标仍需上游计算或周期导入。

建议统一导入向导支持一个工作簿/一个任务中的三个逻辑区域：方案、指标项、机构目标。用户已有拆分文件时，也可在一次导入任务中选择多份文件建立关联。

| 区域 | 必需业务字段 | 处理原则 |
| --- | --- | --- |
| 方案 | 方案编码/名称、适用年度/周期、条线、适用机构维度 | 编码为身份，名称为展示；新增/修订明确区分 |
| 指标项 | 指标编码、口径、权重/计分规则、完成率规则 | 只引用有效且维度兼容指标；不按重复名称自动匹配 |
| 机构目标 | 目标方案编码、KPI方案编码、机构编码、指标编码、周期/阶段、目标、基础值 | 必须关联到确定方案；机构分支使用 ORG，不沿用 EMP 默认值 |

执行流程：上传 → 全量解析与跨区域校验 → 展示新增/变更/冲突预览 → 明确提交 → 一次配置事务生效 → 异步结果计算 → 展示计算完成度 → 大屏使用同一结果。

前置校验包括：重复编码、重名未匹配、不存在/失效指标、单位冲突、机构越权、周期重叠、目标缺失、同键多值、权重与公式合法性、方案归属不一致。校验失败时保留可下载错误明细，不部分激活方案。

复用已有导入解析与写入器，但新增“整个导入任务”事务边界和版本绑定：现有单个策略的 all-or-none 不等于多个策略串联后的原子性。已发布方案应创建新修订，不直接覆盖其历史口径。文件哈希、业务键与导入修订共同构成幂等判断；同一内容重复提交返回已有结果，不把合法后续修订误判为重复。

大型文件可先保存在受控文件区并完成校验，提交数据库配置时保持事务可控。文件归档失败、计算失败和配置保存成功是不同状态；计算未完成不能显示“已全部可用”。不要求用户给每一张大屏重新上传相同数据。

### 7.4 业务结构占比

2026-09-23 用户调整展示需求：业务结构分为“公司”“零售”“中间收入”三个部分，替代原先按存款、贷款、营业收入分类展示的三个页签。

- 公司部分分别展示公司存款占核定存款总量、公司贷款占核定贷款总量；零售部分分别展示零售存款占核定存款总量、零售贷款占核定贷款总量。四项占比各用对应业务总量作分母，不能将存款与贷款加总，也不能将公司与零售相加后默认当作核定总量。
- 存款和贷款分别使用同周期、同机构范围、可换算的金额单位。若核定总量缺失、为零，或分子缺失、为负、单位冲突，则显示不可计算；已核定总量与公司、零售合计有差额时，保留“其他/未归属”或缺口说明。
- 中间收入部分计算“中间业务收入 ÷ 营业收入 × 100%”。两项收入须来自明确绑定的指标、同机构、同期间且单位可换算；营业收入为零或任一来源缺失、为负、单位冲突时显示不可计算。不能用公司、零售营业收入或利润推断中间业务收入。
- 中间收入和营业收入的指标编码、统计期间与来源尚待业务签认；在配置前显示“数据待接入”，不得展示模拟百分比。中收同比仍需另行确认同口径历史数据。
- 公司/零售点击动作按条线标识跳转；三个部分支持手动切换、暂停与恢复轮播。

## 8. 指标库治理与核心/临时指标设计

### 8.1 建议采用的增量方案

会议提出“核心表＋临时新增表＋中间映射”，核心诉求是稳定核心口径并可接纳突发新增指标。建议保留现有 `PERF_METRIC_DEF` 作为系统内统一运行目录，在它上面增加 CORE/TEMP 来源分类和有效期/修订引用；核心指标通过 CORE 视图和独立维护权限管理。

另设持久化的临时指标治理记录及来源映射，承接手工导入、审核、来源编码和正式指标编码转换；通过审核的临时指标注册到统一运行目录，保留 TEMP 标识。这样 KPI、目标与大屏仍使用同一指标编码，而不是各自做一次表间匹配。

这是对会议物理拆表建议的低侵入实现建议，**不把它冒充为已获业务确认的决定**。如业务明确要求核心定义表绝不包含任何临时指标，可采用双定义表＋统一目录服务，但必须同步改造 KPI/目标导入、引用校验、查询和计算，工作量另行上调。

这里的“临时”是业务指标生命周期类别，对应正式的持久化治理实体，不是投产 DML 中建立 SQL 临时表/中转表再回填。结构设计与实施遵守仓库 DBA 变更流程，本方案不生成 DDL。

### 8.2 逻辑实体建议

| 逻辑对象 | 主要字段 | 与现有结构的关系 |
| --- | --- | --- |
| 统一指标定义 | 稳定编码、名称、口径、单位、维度、CORE/TEMP、条线、启停状态、有效期、定义修订 | 扩展/关联 PERF_METRIC_DEF，不创建第二个同义启停字段 |
| 临时指标治理记录 | 导入批次、外部编码/名称、申请人、用途、建议口径、有效期、审核状态、结果编码 | 新增正式业务实体；未确认不能直接参与发布 |
| 指标来源映射 | 来源系统、源编码、统一指标编码、维度、单位转换规则、有效期、修订 | 一份稳定映射供绩效域使用；重名不自动映射 |
| 指标定义修订 | 名称/口径/公式/单位快照、修改原因、生效期 | 支持跨年失效与历史口径查询 |
| 结果存储定位 | 指标编码、维度、存储类型、槽位或行式存储标识、有效期间 | 技术细节不暴露给大屏用户 |

最终物理表名、字段、唯一键、索引和现有字段复用，以目标库只读盘点后形成的数据模型评审稿为准。

### 8.3 指标生命周期

业务界面分为“待确认、有效、失效、已归档”视图。其中待确认是治理记录的工作流状态；现有指标启停继续使用兼容状态值，避免混用定义审核状态与运行状态。

- 核心指标由限定角色手工维护，变更必须显示 KPI、目标、派生指标、数据集和页面引用影响。
- 临时指标导入后先进行重复/冲突检查和映射确认，有效期必填；同义指标优先复用，口径不同则建立新编码。
- 有效期结束后禁止新的当前期绑定，历史期间仍能查到当时有效的定义和结果；失效不等于删库。
- 已发布屏引用失效指标时产生告警并要求迁移；当前数值不能无限沿用已失效口径。是否继续展示最后已批准历史快照由明确策略决定，并标识日期及状态。
- 停用、归档和释放存储槽位不是同一动作。未验证历史引用和数据映射前，不能因停用就把槽位给另一个指标。
- 临时指标转核心时保留稳定编码和历史关联；确需换码使用有有效期的显式映射，不能改名字就认为迁移完成。

### 8.4 宽表容量与扩展路径

当前 400 个槽位按指标层级划分，单一维度的一级指标最多占 200 个。因此，即便只有“约 400 个指标”，也可能先遇到一级指标区间耗尽；也可能因指标跨维度分散而尚有空间。必须先盘点，不能仅凭总数量判断。

建议保留已有宽表和已稳定核心指标映射，避免首轮搬迁历史结果；新增临时指标优先设计可扩展的行式结果存储，粒度为“指标编码＋主体类型/编码＋数据日期＋业务版本/结果批次”。行式存储由绩效域统一结果查询接口封装，页面不感知。

这部分不能只新增一张表：指标启用/槽位分配、指标结果导入、KPI 取实际值、趋势查询、批次组装和旧宽表查询都要能识别存储类型。先为临时手工导入指标打通完整读写计算链，再评估自动计算指标扩展；不在本次顺带重写所有计算策略。

实施前输出容量表：每维度×层级的可用/占用/失效未释放数量、核心清单、未来一年新增预估和历史结果保留要求。若首期容量充足，可分阶段交付行式路径，但未交付前应明确“临时指标仍受容量限制”，不能宣称核心/临时治理已完全解决扩容。

## 9. 机构范围、地图与数据口径

### 9.1 两套集合分别管理

必须分清“页面显示哪些机构”和“上级汇总包含哪些业务”：不显示小微/社区节点，不自动意味着从上级总额中扣除它们的业务。

- 展示集合：账号授权 ∩ 屏级授权 ∩ 命名机构组直接成员 ∩ 有效机构画像 ∩ 已确认经营层级/性质规则。
- 数据贡献集合：由经批准的经营汇总口径决定，可能包含归属于一个经营机构的下属网点，但不得自动因此授予其明细查看权。
- 使用上级已汇总值时，不再叠加其下属机构值；确需现场汇总，只能对互斥的贡献主体集合求和。
- 命名机构组本身不自动展开子树；需要展示下级机构时应明确配置授权成员，不能因为地图下钻就扩大权限。

### 9.2 地图的数据与状态

地图只标记授权、有效、符合展示规则且有可信坐标的机构。不存在的网点不生成占位点；无数据的真实有效机构不等同于“不存在”，建议保留节点并显示“暂无该指标”，是否隐藏由业务明确确认。

缺坐标机构不能伪造位置，也不能从经营总量里消失：仍出现在本市授权机构列表/待定位区域，允许通过列表进入详情。城市归属也缺失时进入待维护清单，不猜测地市。

坐标继续沿用项目的 GCJ-02 契约；新增位置来源必须标明并校验，不重复转换。继续复用既有 WebGL 地图与 SVG 降级能力，降级仍可完成城市、机构跳转。

排名着色的机构集合、数值、周期、公式与列表一致。不同权限账号只看自己的授权范围；图例和“全省排名”字样必须与实际范围一致，局部授权不能标成全省排名。

## 10. 查询一致性、性能和权限

### 10.1 同一刷新使用同一快照

建议将当前分行批次机制推广成统一查询快照。首次加载由服务端确定页面发布版本、数据集修订、指标/KPI/目标结果修订、统计期间、机构集合及各来源截至时间，后续组件使用同一 `snapshotId` 查询。

一个令牌本身不能制造数据一致性。对原来会原地重算的 KPI 明细，应在绩效域保存不可变输出或结果修订，才能让后续请求继续读取同一版本；仅把最新时间塞进响应不构成快照。

- 同页数据不得每个组件分别取各自的“全库最新一天”。选择最近完整且符合该页面必需项的日期。
- 已有 `batchId` 可映射到新快照中的来源批次，保留历史行为；无法提供不可变结果的旧数据源不得伪称具备快照一致性。
- 周期性指标允许不同来源更新时间，但必须符合契约并显示各自截至时间；不能把营销当前数与上月金融数合成同一历史事实。
- 请求失败可保留上次完整快照并明确标注旧日期，但不能混用本轮部分新数据和上轮其他指标生成新汇总；权限失效必须清空旧数据。

### 10.2 质量状态

组件输出统一携带 `value/unit、dataDate、sourceAsOf、metricRevision、formulaRevision、coverage、quality` 等字段。至少区分：正常、合法零值、未配置、缺数据、重复数据、目标无效、口径不匹配、已过期、权限拒绝。

其中缺数据是业务事实，不按网络错误统一重试；权限拒绝不能回退模拟值。覆盖不足的合计、分母缺失的比例、存在重复主体的排名不能标为正常。

### 10.3 性能设计与建议验收基准

- 以数据集和相同查询上下文合并请求，一组机构/指标一次查询，不按组件数量倍增数据库扫描。
- 首屏优先加载核心指标和当前视野机构；趋势和钻取详情按需加载。沿用现有并发限制、请求代际和迟到响应丢弃。
- 排名全量与查询限额联动；大机构集使用可验证的快照分页，前端虚拟列表不改变完整排名语义。
- 缓存键包含授权范围指纹、发布版本、数据集修订、条线、周期和结果批次；不能跨用户复用未经范围隔离的数据。
- 新增大屏缓存使用独立命名空间，不擅自改变项目共享主 CacheManager 的 TTL/容量。
- 建议先按 50/200 家机构、20/50 个组件、10/30 个并发会话建立测试矩阵；这些是测试档位，不代表当前业务规模或已验证容量。
- 建议目标：预生产匹配硬件下核心首屏 P95≤3 秒、全页主要内容≤5 秒，缓存命中切项≤1 秒，地图操作连续可用；基线测量后共同冻结验收阈值。

### 10.4 权限与审计

角色按能力区分查看、组件配置、指标/数据集维护和发布；是否需要双人复核由业务/管理制度决定，首期至少权限分离、操作原因和变更审计齐全。

预览与正式查询使用同一后端授权链路。配置权限不自动等于查看全部机构数据；预览不得通过手填机构编码越权。新增接口登记 `PT_RESOURCE` 和 `@BizAuth`，继续保持同角色交集、机构画像有效性及 Fail Close；管理员不能绕过屏级限制。

来源被停用/撤销授权后，即使旧发布包固定了修订，运行时仍要执行当前权限和紧急禁用检查。不可变历史不能变成绕过即时停用的通道。

数据库结构必须先对实际目标库只读盘点，再提出最小字段/索引/唯一约束变更。旧实体注释不能代替真实 schema。由 DBA 按仓库规则实施获批结构变更，不新增 Flyway 或可执行 DDL 脚本；业务初始化走获准接口或受控白名单 DML。

## 12. 迁移、灰度发布与回退

### 12.1 先建立迁移台账

盘点所有相关屏、草稿/发布版本、组件、绑定的数据源、引用机构组、数据日期、KPI/目标方案、TEST/LIVE身份及归档引用。每个现有组件给出下列去向之一：直接迁移、补业务映射后迁移、保留旧版、退出新入口。

迁移台账至少包含：旧 screenCode/blockId/dsId、旧标题与来源、目标组件ID/数据集修订、指标/公式匹配依据、单位、权限、迁移问题和业务确认人。只从确定字段/编码映射，不根据中文相似标题批量猜测。

### 12.2 分步切换

1. 建立旧配置快照、配置哈希和对账清单；备份范围遵守现有授权和数据库管理要求。
2. 先部署支持 V2/V3 的后端校验、查询与前端解析，新入口关闭，旧版本继续工作。
3. 将一个已核定机构范围的分行综合屏转为 V3 草稿；固定旧数据源语义成候选修订；不原地覆盖旧发布包。
4. 在同一数据期间/范围下执行新旧双读对账。标题调整可以不同，业务值/范围/单位/公式差异必须逐项解释。
5. 完成分行→市→机构和公司/零售全路径验证后，按试点角色/屏幕启用新入口。服务端能力和前端开关一起控制，不能只隐藏按钮。
6. 扩展到其余模板/机构，形成业务签认记录，再切换正式入口。
7. 旧选择页从主导航退出，旧URL保留授权兼容跳转；存量旧屏与归档有明确保留周期。

共享数据源的旧编辑接口若继续运行，不能更改 V3 已固定的修订。对迁移中的数据源修改应提示影响并要求再校验；迁移快照过期则重新生成候选，不覆盖新发生的用户修改。

### 12.3 回退条件与动作

发生口径对账不一致、机构越权、关键页面无法打开或数据完整性严重异常时，关闭新入口并切回旧页面发布指针；保留本次草稿、问题记录及数据修订以便修复。

配置回退不删除新结构，不自动回滚 KPI/目标业务数据。若一次导入写入有误，使用可追踪的业务修订/批准的补偿流程，避免配置回退连带破坏后续已发生的业务变化。

## 14. 验收标准与测试清单

### 14.1 配置能力验收

- 同一组件能独立修改标题、主副指标、系列/列、数据来源、周期、单位和交互；保存重开不丢失，预览与发布一致。
- 更换指标时名称/单位/维度校验正确；自定义标题需确认；没有兼容来源时给出具体原因。
- 一个数据集被两个页面引用：修改一个组件标题不影响另一个；数据集生成新修订不会改变旧发布页；升级引用时展示影响。
- 旧schema2完整可读；schema3未知字段、未知组件、跨屏blockId、非法数据集引用被拒绝；并发编辑返回409且本地修改可恢复。
- 显隐/顺序/规格调整后的所有最终页面，无遮挡、截断、溢出或不可读文字。
