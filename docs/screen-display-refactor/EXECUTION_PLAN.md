本文件的“执行”指后续用户发出开始实施指令后的工作。本轮仅生成计划及范围文件，不代表已修改或验收业务功能。

## 1. 首先执行的范围规则

用户最新限制：**“除大屏展示内容外，不要修改其他功能组件的代码。”**

本次允许的功能范围是分行/地市/机构的综合、公司、零售经营大屏，以及直接服务于它们的组件配置、草稿保存、预览、发布和现有数据只读消费。大屏专属后端适配仅限这些展示配置所必需的改动，不扩展上游业务能力。

配套文件：

- [SCOPE.json](SCOPE.json)：机器可读的文件范围与内容限制，默认拒绝未列路径。
- [START_PROMPT.md](START_PROMPT.md)：可复制给 Codex 的执行指令。
- [原业务改造方案](../分行经营大屏改造方案-2026-09-22.md)：只作需求背景，跨模块内容已被本轮范围限制覆盖。

规则优先级：用户最新边界 → 仓库/目录 AGENTS.md → 本执行计划与范围清单 → 原业务方案。任何执行者不得以“为了大屏能跑起来”为理由扩大代码范围。

### 1.1 可以改什么

1. 三类经营大屏及其市/机构展示：标题、内容、数据绑定、单位、趋势、排名、结构页签、地图和页面内导航。
2. 大屏专属配置页面：统一组件选择、预览和配置面板，复用现有保存/发布接口。
3. 报表模块中被明确列入清单的大屏专属类：展示配置校验、序列化、保存/发布、配置快照及现有查询结果适配。
4. 对应的大屏测试和文档。

即使文件在允许目录中，每个任务仍须冻结自己的实际修改文件清单；不能借目录权限顺手重构整个文件夹。

### 1.2 明确不能改什么

- 指标库、KPI、目标、导入/导出、绩效计算、客户营销、工作流、党建、云盾、业务申请的代码与测试。
- 认证、Session、RBAC、机构画像/机构组管理、用户和角色维护。
- 工作台、个人看板、公共侧栏/顶栏、公共组件、共享工具、全局样式、路由守卫和 HTTP 拦截器。
- 普通报表、自由报表、SQL 探查、任务调度、文件/对象存储及共享缓存配置。
- POM、package/锁文件、Vite/Vitest 配置、应用启动配置、端口、代理、数据库连接、AGENTS.md。
- 数据库结构、数据修复脚本、指标补录、目标导入和 KPI 重算。不能通过调用其他功能的写接口绕过“不修改其代码”的限制。

本轮不改 `src/router/index.js`。使用现有大屏路由和 query 参数实现导航；不改工作台按钮，只使用现有大屏中心入口。

`src/views/screen/personal/` 以及 `screen/admin/OrgProfiles.vue、OrgGroups.vue、OrgLocationDialog.vue` 虽位于 screen 目录，仍是明确保护区。旧坐标画布 `ScreenRenderer.vue` 和其通用组件不列入默认修改清单。

### 1.3 超范围时如何继续

先收集“具体需求、现有契约、缺少字段/能力、最小外部改动、影响范围”证据，登记 `BLOCKED_SCOPE`；只暂停依赖该能力的子任务，继续其他可独立完成的任务。不能自行扩展 SCOPE.json，不能假装删除需求后完成。

对未具备数据的组件，配置与空态可以实现并测试；真实取数验收必须标记 `BLOCKED_DATA`，不能以演示值、任意兜底或仅单测通过替代。

### 3.1 复用点与需要注意的现状

- 配置入口已是 `panorama/PanoramaBindings.vue`；不能重新按已删除的旧 DesignerV2 路径实施。
- `CanvasStyleDTO` 已有 `metricLabels` 和 `sourceAvailability`，优先兼容，不再另建一套语义相同的全局字段。
- 现有 `canvas_version`、草稿/发布JSON、发布日志、`blockId`、`bindSnapshots`、服务端机构授权继续有效。
- 现有排名有TOP10路径，数据源管理前端与机构KPI后端能力矩阵不完全一致，需要在大屏内部修正表达。
- 现有数据源可原地更新；配置快照必须明确冻结哪些内容，不能承诺未冻结的KPI/目标业务结果。
- 既有测试profile并不都指向同一个测试库；单凭文件名带test不能安全启动真库测试。

### 3.2 首期协议选择：不升级全局运行协议

为减少共享改动，本轮**保留现有根渲染包 schemaVersion=2 与 runtimeSchemaVersion=2**；新展示配置使用 `canvasStyle.presentation.displaySchemaVersion=1` 作为可选子协议。原方案的根schema3本轮不直接执行。

新行为必须显式启用。未带 displaySchemaVersion 的旧包继续走现有路径；未知展示版本拒绝并提示，不自动当旧配置解释。

S02冻结如下语义：

| 对象 | 必须包含的职责 |
| --- | --- |
| 展示组件实例 | `componentId、componentType、layoutRegion、order、visible`，可选标题/说明/格式/交互 |
| 组件内容 | 主副字段、趋势系列、排名候选、结构页签、表格列；是类型化字段，不是任意脚本 |
| 数据引用 | 一个或多个既有 `blockId` 及字段角色；保存新组件前可用客户端ID建立关联，blockId由服务端返回 |
| 来源元数据 | 指标编码/名称、单位、维度、条线、口径、输出形状；只能来自明确保存的元数据或现有API |
| 范围上下文 | 已授权机构、城市、条线、日期/周期；只能收窄服务端权限 |
| 配置快照 | 服务端生成的数据源定义摘要/快照及hash，绑定到本页发布包，不接受客户端伪造 |

一个源绑定可被多个展示组件引用，同一指标可多处展示。增删“展示组件”不等于删除共享数据源；最后一个引用解除后也不得自动删除它。

旧 `propValue.bindingKey` 继续作为旧槽位兼容信息；新实例通过稳定componentId和服务端blockId映射，不从标题反推身份。只在新展示分支支持多个同类组件，不全局移除旧固定槽位校验。

标题优先级：组件自定义标题 → 已绑定指标名称快照 → 已存在metricLabels覆盖/模板默认。迁移时将旧metricLabels作为明确的自定义覆盖导入，避免原本的定制标题被新优先级覆盖。多指标组件的容器标题与系列名称分别配置。

### 3.3 取数与计算规则

- 标准来源仅提供现有指标宽表、现有机构KPI细项，以及它们已返回的实际值、目标值和完成率；不把旧员工KPI总分冒充机构结果。
- 现有安全矩阵允许的配置才提供选择；不为解锁选项放宽权限矩阵、SQL白名单、主体约束或LIMIT。
- 机构组KPI细项必须符合当前服务端固定组合；不假装EMP/TREND组合已获得支持。
- 新增展示绑定不提供任意CUSTOM_SQL。旧来源保留只读兼容，能否迁入标准来源由S01清单决定。
- 不改变 `ScreenQueryEngine` 原公式。选择完成率结果时同时显示公式含义；指标卡的单位换算、舍入和结构占比等展示计算必须有显式规则。
- 不调用上游导入/重算来补齐演示。不够用的指标保留缺失态，登记外部依赖。

### 3.4 配置快照与数据批次的边界

S04可在现有发布JSON中生成只针对本屏的新来源快照，避免改共享数据源后改变新发布屏的查询定义；不新增表。快照由服务端从已校验来源生成，不能信任浏览器传入的SQL或权限数据。

运行时仍检查当前数据源是否启用、当前账号和机构范围是否有效。配置快照不冻结权限，也不免除紧急停用。

不可变查询定义不等于不可变业务结果。已有分行batchId链路继续锁定；没有结果修订/批次的KPI源只能如实标注当前查询日期与一致性能力，不制造无事实支撑的snapshotId。本轮不承诺全来源原子快照。
