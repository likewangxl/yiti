# 系统治理中心 -- 后端架构

---

## 1. 模块职责边界

### 1.1 负责

- 字典管理（CRUD + 缓存）
- 工作日历配置（按天管理工作日/休息日、年初初始化、批量导入）
- 任务调度监控（配置管理、手动触发、执行日志）
- 审计日志（同步写入、查询、导出）
- 通知消息（发送、查询、已读/未读管理）
- 系统配置 KV（键值配置管理 + 缓存）
- 文件管理（MinIO 上传/下载、业务关联、MD5 去重）
- 数据探查框（受控只读 SQL 执行）
- 慢查询告警（通过 common-db 中的 SlowSqlInterceptor 提供阈值配置）

### 1.2 不负责

- 不负责登录认证（由 auth-permission-center 处理）
- 不负责具体业务审批逻辑（由 workflow-center 处理）
- 不负责权限模型定义（RBAC 模型由 auth-permission-center 定义）
- 不负责业务数据的读写（各业务模块自行管理）
- 不负责 Flowable 流程引擎（由 workflow-center 封装）

## 4. 分层规范

### 4.1 各层职责

| 层级 | 注解 | 职责 | 允许调用 | 禁止 |
|:---|:---|:---|:---|:---|
| Controller | `@RestController` | 接收HTTP请求、参数校验、返回ResponseWrapper | Facade / Service | 直接调用 Mapper；包含业务逻辑 |
| Facade | `@Service` | 实现 api 包中的接口，供其他模块调用 | Service | 直接调用 Mapper；包含复杂业务逻辑 |
| Service | `@Service` | 核心业务逻辑、事务管理 | Mapper、其他 Service、外部 Api | 直接返回 Entity 给 Controller |
| Mapper | `@Mapper` | 数据库访问、SQL 执行 | 无 | 包含业务逻辑 |
| Entity | POJO | 数据库表映射 | 无 | 包含业务方法 |

### 4.2 调用链路

```
外部模块 ──> api/*Api.java (接口) ──> facade/*Facade.java (实现) ──> service/*Service.java ──> mapper/*Mapper.java

HTTP请求 ──> controller/*Controller.java ──> service/*Service.java ──> mapper/*Mapper.java
```

### 4.3 对象转换规范

| 转换方向 | 说明 |
|:---|:---|
| Entity -> DTO | 在 Service 层完成，使用 convert 包中的转换器 |
| ReqDTO -> Entity | 在 Service 层完成 |
| Entity 不出 Service 层 | Controller/Facade 只接触 DTO |

### 4.4 事务管理

| 场景 | 事务策略 |
|:---|:---|
| 字典 CRUD | Service 层方法加 `@Transactional`，写操作后清缓存 |
| 日历批量操作 | 批量更新使用 `@Transactional`，控制批次大小 |
| 审计日志写入 | 同步写，`@Transactional(propagation = REQUIRES_NEW)` 独立事务 |
| 通知发送 | 异步（事务提交后执行），使用 `@TransactionalEventListener` |
| 文件上传 | 先写 MinIO，再写数据库，失败时回滚（数据库 + MinIO 清理） |
| 任务手动触发 | 先写日志（RUNNING），再触发任务，任务完成/失败回调更新日志 |

## 5. 缓存策略

### 5.1 缓存项清单

| 缓存 KEY 模式 | 数据 | TTL | 清除时机 |
|:---|:---|:---|:---|
| `gov:dict:{dictType}` | 某类型下所有启用字典项 | 10 分钟 | 该类型字典项增删改时 |
| `gov:dict:all` | 所有字典类型列表 | 10 分钟 | 任何字典项变更时 |
| `gov:config:{configKey}` | 系统配置值 | 10 分钟 | 配置更新时 |
| `gov:calendar:{year}` | 某年全部工作日集合 | 24 小时 | 日历变更时 |

### 5.2 缓存失效策略

- 写操作后主动清除对应缓存 KEY（`RedisTemplate.delete()`）。
- 缓存穿透保护：查询不存在的 dictType 时缓存空结果，TTL 1 分钟。
- 不使用 `@Cacheable` 注解，全部手动管理缓存（显式优于隐式）。

## 6. 错误码定义

前缀 `GOV`，遵循全局错误码规范。

### 6.1 客户端错误（4xxxx）

| 错误码 | HTTP 状态码 | 说明 |
|:---|:---|:---|
| GOV-40001 | 400 | 字典类型不存在 |
| GOV-40002 | 400 | 字典编码已存在（dict_type + dict_code 唯一冲突） |
| GOV-40003 | 400 | 字典项不存在 |
| GOV-40401 | 404 | 配置项不存在 |
| GOV-40402 | 404 | 调度任务不存在 |
| GOV-40403 | 404 | 通知不存在 |
| GOV-40404 | 404 | 文件不存在 |
| GOV-40901 | 409 | 调度任务状态冲突（已暂停无法暂停 / 运行中无法再次触发） |
| GOV-40902 | 409 | 日历日期已过期不允许修改 |
| GOV-40903 | 400 | 文件格式不在白名单 |
| GOV-40904 | 400 | 文件大小超限 |
| GOV-40905 | 400 | 配置值类型校验失败 |

### 6.2 SQL 探查错误（422xx）

| 错误码 | HTTP 状态码 | 说明 |
|:---|:---|:---|
| GOV-42201 | 422 | SQL 语法校验失败（非 SELECT 语句） |
| GOV-42202 | 422 | SQL 执行超时 |
| GOV-42203 | 422 | SQL 访问了白名单外的表/Schema |

### 6.3 服务端错误（5xxxx）

| 错误码 | HTTP 状态码 | 说明 |
|:---|:---|:---|
| GOV-50001 | 500 | MinIO 存储异常（连接失败/上传失败/下载失败） |
| GOV-50002 | 500 | 调度任务执行异常 |

### 6.4 错误码枚举实现

```java
package com.bank.branch.platform.governance.enums;

import com.bank.branch.platform.common.web.exception.BizException;
import lombok.AllArgsConstructor;
import lombok.Getter;

/**
 * 系统治理中心错误码枚举
 * 前缀 GOV，按 HTTP 状态码分段
 */
@Getter
@AllArgsConstructor
public enum GovErrorCode {

    // --- 400 Bad Request ---
    DICT_TYPE_NOT_FOUND("GOV-40001", "字典类型不存在"),
    DICT_CODE_DUPLICATE("GOV-40002", "字典编码已存在"),
    DICT_ITEM_NOT_FOUND("GOV-40003", "字典项不存在"),

    // --- 404 Not Found ---
    CONFIG_NOT_FOUND("GOV-40401", "配置项不存在"),
    JOB_NOT_FOUND("GOV-40402", "调度任务不存在"),
    NOTIFICATION_NOT_FOUND("GOV-40403", "通知不存在"),
    FILE_NOT_FOUND("GOV-40404", "文件不存在"),

    // --- 409 Conflict ---
    JOB_STATUS_CONFLICT("GOV-40901", "调度任务状态冲突"),
    CALENDAR_DATE_EXPIRED("GOV-40902", "日历日期已过期不允许修改"),

    // --- 400 Validation ---
    FILE_TYPE_NOT_ALLOWED("GOV-40903", "文件格式不在白名单"),
    FILE_SIZE_EXCEEDED("GOV-40904", "文件大小超限"),
    CONFIG_VALUE_TYPE_MISMATCH("GOV-40905", "配置值类型校验失败"),

    // --- 422 SQL Probe ---
    SQL_NOT_SELECT("GOV-42201", "SQL语法校验失败：仅允许SELECT语句"),
    SQL_TIMEOUT("GOV-42202", "SQL执行超时"),
    SQL_SCHEMA_DENIED("GOV-42203", "SQL访问了白名单外的表"),

    // --- 500 Server Error ---
    MINIO_ERROR("GOV-50001", "MinIO存储异常"),
    JOB_EXECUTION_ERROR("GOV-50002", "调度任务执行异常");

    private final String code;
    private final String message;

    /**
     * 抛出业务异常
     */
    public BizException toException() {
        return new BizException(this.code, this.message);
    }

    /**
     * 抛出业务异常（附加详情）
     */
    public BizException toException(String detail) {
        return new BizException(this.code, this.message + "：" + detail);
    }
}
```

## 9. 关键实现要点

### 9.1 审计日志切面与 AuditFacade 的关系

审计日志的写入有两种路径：

1. **AOP 切面自动写入**：`common-aop` 中的 `AuditLogAspect` 拦截 `@AuditLog` 注解的方法，自动收集请求信息后调用 `AuditApi.log()` 写入。
2. **业务代码手动调用**：业务模块在复杂逻辑中手动构建 `AuditLogCmd` 并调用 `AuditApi.log()`。

governance 模块中的 `AuditFacade` 实现 `AuditApi` 接口，负责实际的数据库写入。

### 9.2 文件上传流程

```
1. Controller 接收 MultipartFile
2. Service 校验文件格式（白名单）和大小（上限）
3. 计算文件 MD5
4. 查询是否存在相同 MD5 的文件
   ├── 存在 → 复用已有 file_object 记录（不重复上传 MinIO）
   └── 不存在 → 上传到 MinIO → 写入 file_object 记录
5. 如果传入了 bizType+bizId → 写入 biz_file_rel 关联记录
6. 返回 FileObjectDTO
```

### 9.3 SQL 探查安全流程

```
1. Controller 接收 SQL 语句
2. Service 进行 SQL 语法校验（仅允许 SELECT）
3. 解析 SQL 中引用的表名，校验是否在 Schema 白名单内
4. 设置超时（Statement.setQueryTimeout）
5. 通过独立只读 DataSource 执行 SQL
6. 强制追加 LIMIT（如果用户未指定或超出最大值）
7. 审计日志记录（SQL内容 + 耗时 + 行数）
8. 返回结果集
```

### 9.4 通知异步发送

```java
// 业务模块调用 NotifyApi 发送通知时，通知在事务提交后异步处理
// 使用 Spring 的 @TransactionalEventListener(phase = AFTER_COMMIT)
// 确保业务事务成功后才发送通知，避免事务回滚导致"幽灵通知"
```

### 9.5 字典缓存双写一致性

```
写操作：
1. 更新数据库（@Transactional）
2. 删除 Redis 缓存 KEY（gov:dict:{dictType}）
3. 删除 Redis 缓存 KEY（gov:dict:all）

读操作：
1. 查 Redis 缓存
2. 缓存未命中 → 查数据库 → 写入 Redis 缓存（TTL 10分钟）
3. 缓存穿透保护：不存在的 dictType 缓存空结果（TTL 1分钟）
```
