# 系统治理中心后端架构

## 1. 架构定位

系统治理中心是 Spring Boot 模块化单体中的治理模块，由 `bootstrap` 统一启动。它持有字典、配置、日历、调度、审计、通知、文件和人员/机构标签的实现与数据；业务模块通过公开 API/DTO 使用这些能力。

```text
Controller / REST
        │
        ▼
Service（事务、校验、数据范围、外部副作用）
        │
        ├── Mapper / MyBatis-Plus ── 治理自有表
        ├── Quartz Scheduler ─────── QRTZ_* + JobExecutionLogger
        ├── ObsStorageClient ─────── 华为云 OBS
        ├── MemoryCacheService ────── Caffeine 进程内缓存
        └── auth API ───────────────── 当前用户、组织、用户解析
        ▲
        │
Facade / api（跨模块稳定契约）
```

## 2. 依赖方向

### 2.1 Maven 依赖

当前 `system-governance-center/pom.xml` 的生产依赖为：

- `common-web`、`common-trace`、`common-security`、`common-aop`、`common-db`；
- `auth-permission-center`，用于公开的用户、组织、当前用户和数据范围能力；
- MyBatis-Plus、Spring Boot Quartz、Caffeine、Knife4j；
- 华为云 OBS SDK；Apache POI 与 EasyExcel，用于 Excel 导入/导出。

测试依赖只服务本模块测试，不改变生产依赖方向。

### 2.2 模块边界

- 治理模块只能依赖 `common` 与 `auth-permission-center`，不得依赖业务模块。
- 业务模块只能依赖治理 `api/` 中的 `DictApi`、`CalendarApi`、`ConfigApi`、`JobApi`、`AuditApi`、`NotifyApi`、`FileApi`、`PersonTagApi` 及其 DTO。
- 跨模块实现放在 `facade/`，内部实体、Mapper、SQL 和 Service 不构成公共契约；不允许跨模块直接 Join 治理私有表。
- Quartz 是平台调度的唯一实现边界；业务模块注册 Job 时使用 `JobApi`，不另建调度基础设施。

## 3. 分层与包结构

```text
com.bank.branch.platform.governance
├── api/                 对外 Java 接口与 DTO
├── facade/              API 实现、实体到 DTO 的转换
├── controller/          REST 入口和参数校验
├── service/             业务规则、事务与外部调用编排
├── mapper/              治理自有表的数据访问和必要自定义 SQL
├── entity/              治理自有表映射
├── config/              Caffeine 与 Quartz 装配
├── storage/             OBS 客户端与文件类别
├── listener/            Quartz 执行日志监听
├── handler/             common-aop 审计事件处理器
└── enums/               治理状态和错误码
```

Controller 不持有跨模块私有实现；Facade 不向调用方泄漏治理实体；Service 是写入、目标实体权限检查、事务和外部副作用的边界。

## 4. 缓存架构

`MemoryCacheService` 使用 Caffeine，当前 Cache 统一设置 `maximumSize=10000`、`expireAfterWrite=1小时`。字典、配置和年度日历各自使用带前缀的键；`put` 的时长参数为兼容签名，实际采用 Cache 的统一过期策略。

所有写操作在数据库成功后清除受影响的键。缓存未命中回源数据库并写入缓存；缓存不可用时应以数据库行为为准，不把缓存当作持久数据，也不在治理模块引入跨实例缓存协议。

## 5. Quartz 架构

- `spring-boot-starter-quartz` 由 Spring Boot 装配，使用 JDBC JobStore；运行配置以 `bootstrap/src/main/resources/application*.yml` 为准。
- `QuartzConfig` 注入 `AutowiringSpringBeanJobFactory`，使 Job 可获得 Spring Bean；同时注册全局 `JobExecutionLogger`。
- `JobService.syncJobsOnStartup` 从 `SYS_JOB_CONF` 读取启用配置，创建/覆盖 JobDetail 与 CronTrigger；单条配置装配失败只记录并继续。
- `JobExecutionLogger` 在 Job 生命周期回调写 `SYS_JOB_RUN_LOG`，并更新任务最近执行时间；监听器内部异常隔离，不能阻止业务 Job 执行。
- JDBC JobStore 的集群行锁和 Quartz 状态表负责调度一致性；停止应用时按配置等待运行中的 Job 完成。
- Scheduler 缺失时，启动同步可安全跳过；显式注册/触发/暂停/恢复操作应返回对应治理错误，不得假装操作成功。

## 6. 文件存储架构

`FileService` 只保存元数据与业务关联，内容由 `ObsStorageClient` 统一访问 OBS。上传流程为扩展名/大小校验 → 流式计算 MD5 → 命中则复用元数据 → 未命中则写 OBS → 插入元数据 → 可选绑定业务关联；元数据插入失败时清理本次新对象。

下载支持 Service/API 读字节、写调用方流和生成 OBS 临时预签名 URL。REST 下载当前由 Controller 直接读取字节并写附件响应。删除操作同时删除对象、元数据和关联，调用方必须先确认该文件没有其他业务用途。

`obs.enabled=false` 时仍装配 `ObsStorageClient`，但对象读写和预签名操作显式失败，避免在隔离环境误触远端存储。访问密钥只从运行配置注入，不进入源码、文档或日志。

## 7. 审计架构

common-aop 的 `AuditLogAspect` 采集 `@AuditLog` 方法的动作、资源、理由、Trace、请求、响应和耗时，交给 `AuditLogHandler`。治理模块的 `GovAuditLogHandler` 是持久化处理器，将事件映射为 `AuditLogCmd` 并调用 `AuditLogService`。

- `serviceManaged=true` 的方法由业务 Service 自己提供前后快照或结构化审计，切面不重复记录。
- `AuditLogService.log` 在 `REQUIRES_NEW` 事务中落库，审计写入失败由切面边界隔离并记录服务端日志。
- 请求参数、快照和错误信息进入持久层前必须脱敏、截断并保持可检索；客户端只接收统一错误信息。

## 8. 鉴权与数据范围

- 管理端 Controller 使用 `@BizAuth(bizType=SYS_CONFIG, action=...)`，资源登记、白名单和 `@BizAuth` 必须与当前权限配置同步。
- 公共字典/日历查询和用户自服务接口只在源码明确开放的范围内免管理端授权；免 `@BizAuth` 不等于绕过认证或可以访问其他用户数据。
- 列表、详情、导出和高危操作都在后端应用统一数据范围；写操作在 Service 按目标实体再次校验。
- SQL 探查、导入、导出、调度触发、配置变更和删除使用独立 URL/动作/审计理由，权限解析异常必须拒绝请求。

## 9. 错误与降级

Controller 只负责请求校验和统一响应，Service 使用 `GovErrorCode` 表达业务失败。数据库、OBS、Quartz、解析等技术异常记录服务端日志并转换为面向调用方的治理错误；不得把 SQL、堆栈、凭据或对象存储响应原文写入客户端。

外部用户/组织解析失败时，标签成员和任务操作人名称可以为空而不改变主数据；OBS 禁用时文件操作失败关闭；Scheduler 不可用时触发/暂停/恢复显式失败。所有降级都必须保留 Trace 与可审计的操作结果。
