# 系统治理中心初始化与运行配置要求

> 本文件只记录当前实现所需的资源、配置和初始化核对项，不提供可执行 SQL。结构、数据和权限资源的实施必须分别由 DBA/权限管理员按审批结果完成。

## 1. 配置来源与安全要求

- 后端配置权威来源是 `bootstrap/src/main/resources/application*.yml`，代码中的固定校验值以对应 Service/Storage 类为准。
- 不在文档、源码、日志或初始化数据中保存访问密钥、密码、Token、Cookie 或真实对象存储凭据；部署通过受控配置注入。
- 配置变更需要 `SYS_CONFIG/CONFIG` 资源、操作理由和审计；变更后清除对应本地缓存并通过运行检查确认生效。
- `spring.quartz.jdbc.initialize-schema`、Session JDBC 初始化等结构开关保持关闭自动建表，由 DBA 管理目标表结构。

## 2. 权限资源要求

所有标注 `@BizAuth` 的管理端方法必须登记匹配的 `PT_RESOURCE`（URL、HTTP 方法和动作），并绑定经过审批的角色。当前资源分组如下：

| 资源组 | 路径 | `BizType` | `BizAction` |
| --- | --- | --- | --- |
| 字典管理 | `/api/admin/sys/dicts` 及其子路径 | `SYS_CONFIG` | `CONFIG` |
| 配置管理 | `/api/admin/sys/configs` 及其子路径 | `SYS_CONFIG` | `READ`、`CONFIG` |
| 日历管理 | `/api/admin/sys/calendar` 及其子路径 | `SYS_CONFIG` | `READ`、`CONFIG`、`IMPORT` |
| 任务管理 | `/api/admin/sys/jobs` 及其子路径 | `SYS_CONFIG` | `READ`、`CONFIG`、`JOB_TRIGGER` |
| 审计查询/导出 | `/api/admin/sys/audit-logs` 及其子路径 | `SYS_CONFIG` | `READ`、`EXPORT` |
| 文件管理 | `/api/admin/sys/files` | `SYS_CONFIG` | `READ` |
| 标签管理 | `/api/admin/sys/person-tags` 及其子路径 | `SYS_CONFIG` | `LIST`、`CONFIG`、`DELETE`、`IMPORT` |
| SQL 探查 | `/api/admin/sql-probe` 及其子路径 | `SYS_CONFIG` | `READ`、`EXECUTE_SQL` |

字典/公共日历查询与用户通知、业务文件入口由源码明确作为公共或自服务路径；是否进入认证白名单必须与 `AuthenticationFilter.WHITELIST`、`WebMvcAuthConfig` 和实际资源配置共同核对，不能根据“未标注 `@BizAuth`”自动放开。

## 3. 对象存储配置

`ObsStorageClient` 要求配置以下键：

| 配置键 | 要求 |
| --- | --- |
| `obs.enabled` | 对象操作总开关；禁用时操作返回 `GOV-50301` |
| `obs.endPoint` | OBS 服务端点，由部署环境注入 |
| `obs.accessKey`、`obs.secretKey` | 受控凭据，不写入仓库和日志 |
| `obs.bucketName` | 目标桶 |
| `obs.presignExpireSeconds` | 预签名 URL 有效秒数；未配置时实现默认 600 |

文件上传的扩展名白名单和 50 MB 单文件上限由 `FileService` 固定校验；Tomcat multipart 配置需覆盖单文件上限，当前请求上限为 60 MB。具体环境可收紧，不能放宽到绕过 Service 校验。

## 4. Session 与数据库连接

- Spring Session 使用 JDBC，表名为 `SPRING_SESSION`；`initialize-schema` 保持 `never`，表由 DBA 按目标库 schema 管理。
- 治理自有表为 `SYS_DICT`、`SYS_CALENDAR_DAY`、`SYS_JOB_CONF`、`SYS_JOB_RUN_LOG`、`SYS_CONFIG_KV`、`USER_NOTIFICATION`、`FILE_OBJECT`、`BIZ_FILE_REL`、`AUDIT_LOG`、`PERSON_TAG`、`PERSON_TAG_REL`。
- 应用连接时区、字符集、连接池和账号来自活动 profile；文档不固化数据库地址、口令或单机现场。
- `PT_USER`、`EXT_USER_ORG`、`EXT_ORG_INFO` 和指标计算任务表属于其他模块，初始化治理数据时只按公开契约验证其可用性。

## 5. Quartz 运行配置

Quartz 配置必须保持以下语义：

| 配置项 | 要求 |
| --- | --- |
| `spring.quartz.enabled` | 需调度时启用；禁用时注册/触发/暂停/恢复应显式失败或按源码安全跳过 |
| `spring.quartz.job-store-type` | `jdbc`，与目标库共享持久化表 |
| `spring.quartz.auto-startup` | 由部署策略决定；启用时与启动同步配合 |
| `spring.quartz.overwrite-existing-jobs` | 保持 Job 配置覆盖语义 |
| `spring.quartz.wait-for-jobs-to-complete-on-shutdown` | 关闭时等待运行中的 Job 完成 |
| `spring.quartz.jdbc.initialize-schema` | `never`，不由应用自动建表 |
| `org.quartz.scheduler.instanceName/instanceId` | 集群实例名固定、实例 ID 自动生成 |
| `org.quartz.jobStore.tablePrefix` | `QRTZ_` |
| `org.quartz.jobStore.isClustered` | `true` |
| `org.quartz.jobStore.driverDelegateClass` | `org.quartz.impl.jdbcjobstore.StdJDBCDelegate` |
| `org.quartz.jobStore.clusterCheckinInterval`、`misfireThreshold` | 按现场可靠性与审批配置，变更需运维记录 |

`SYS_JOB_CONF` 是业务任务配置来源；配置行必须能解析 `quartz_job_class`、Cron 和 misfire 策略。应用通过 `JobExecutionLogger` 记录执行日志，初始化不需要预置固定 Job 数量。

## 6. 应用内固定策略

以下不是初始化数据，不能写入 `SYS_CONFIG_KV` 假装可动态调整；变更必须修改代码并同步契约/测试：

- Caffeine Cache：最大条目数 10000，统一写入后一小时过期；字典、配置和年度日历写成功后清除对应键。
- SQL 探查：SQL 最长 5000 字符，只接受 `SELECT` 开头；自动限制 1000 行，进程内最多 3 个并发，JDBC 查询超时 30 秒。
- 标签 Excel 导入：EMP 使用工号，ORG 使用机构业务编号/名称解析；导入校验失败整体不写入。

## 7. 初始化核对顺序

1. 读取当前活动 profile，确认数据库、Session、Quartz 和 OBS 配置来自受控来源；不得把凭据复制到文档或命令行记录。
2. 由 DBA 只读核对治理自有表、Quartz 表和 Session 表的实际 schema；差异进入独立审批，不在本文件补结构脚本。
3. 由权限管理员按第 2 节核对每个管理端 URL/方法、资源状态、角色绑定和 `@BizAuth` 动作。
4. 由应用负责人核对 `SYS_JOB_CONF` 中实际任务配置、`allow_manual_trigger`、Cron、Job 类和 Scheduler 运行状态。
5. 由运维以最小权限验证字典/日历读取、文件对象开关、审计写入和通知自服务；验证结果记录 Trace 和审批单号。

## 8. 禁止事项

- 不在本文件提交 DDL、删除/覆盖数据脚本或自动结构升级命令。
- 不用环境快照、样例数据或固定条目数代表生产初始化完成。
- 不把权限资源、配置值、Job 配置和数据库结构混在一次无审批操作中。
