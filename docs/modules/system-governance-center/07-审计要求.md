## 1. 本模块高危动作清单

| 序号 | 接口 | HTTP方法 | 动作（biz_action） | 审计级别 | 说明 |
|:---:|:---|:---|:---|:---|:---|
| 1 | /api/admin/sys/jobs/{jobId}/trigger | POST | JOB_TRIGGER | **高危，必须审计** | 手动触发定时任务，可能影响数据计算 |
| 2 | /api/admin/sys/sql-probe/execute | POST | EXECUTE_SQL | **高危，必须审计** | 直接执行 SQL 查询，存在数据泄露风险 |
| 3 | /api/admin/sys/audit-logs/export | POST | EXPORT | **高危，必须审计** | 导出审计日志，涉及敏感操作记录 |
| 4 | /api/admin/sys/dicts | POST | CONFIG（新增字典） | 需审计 | 新增字典类型或字典项 |
| 5 | /api/admin/sys/dicts/{id} | PUT | CONFIG（编辑字典） | 需审计 | 编辑字典值/标签/状态 |
| 6 | /api/admin/sys/dicts/{id} | DELETE | CONFIG（删除字典） | 需审计 | 逻辑删除字典项 |
| 7 | /api/admin/sys/calendar/{date} | PUT | CONFIG（修改日历） | 需审计 | 修改工作日/休息日标记 |
| 8 | /api/admin/sys/calendar/import | POST | IMPORT（批量导入日历） | **高危，必须审计** | 批量修改工作日历，影响全行业务计算 |
| 9 | /api/admin/sys/configs/{configKey} | PUT | CONFIG（修改系统配置） | 需审计 | 修改系统配置参数 |

### 高危操作特殊要求

| 要求 | 说明 |
|:---|:---|
| 独立 URL | 高危接口使用独立 URL 路径，不与普通 CRUD 共用 |
| 单独授权 | 在 PT_RESOURCE 中独立注册，需单独绑定角色权限 |
| reason 必填 | 高危操作请求体中 `reason` 字段为必填项 |
| 单独审计 | 必须记录完整的请求参数和操作原因 |

## 3. 审计服务实现要点

### 3.1 AuditLogService 核心职责

`AuditLogService` 是审计日志的统一落库实现，为全平台所有模块提供审计记录能力。

```java
/**
 * 审计日志服务
 * 提供审计日志的统一写入和查询能力
 */
public interface AuditLogService {

    /**
     * 记录审计日志（核心方法）
     * 使用独立事务写入，不影响业务事务
     */
    void log(AuditLogCreateDTO dto);

    /**
     * 分页查询审计日志
     * 支持按 empId/bizType/bizAction/时间范围 等条件过滤
     * 查询结果需应用 DATA_SCOPE 数据范围控制
     */
    PageResult<AuditLogVO> pageQuery(AuditLogQueryDTO query);

    /**
     * 导出审计日志
     * 高危操作，需单独审计
     */
    void export(AuditLogExportDTO exportDTO, HttpServletResponse response);
}
```

### 3.2 @AuditLog 注解 + AOP 自动捕获

```java
/**
 * 审计日志注解
 * 标注在 Controller 方法上，通过 AOP 自动捕获请求信息并写入审计日志
 */
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface AuditLog {
    /** 业务类型 */
    String bizType();
    /** 业务动作 */
    String bizAction();
    /** 是否高危操作（高危操作 reason 必填） */
    boolean highRisk() default false;
}
```

**AOP 切面处理流程**：

```
1. 方法执行前：
   - 从 ThreadLocal 获取 CurrentUserContext（emp_id, emp_name）
   - 从 HttpServletRequest 获取 IP、UserAgent、URL、Method
   - 从 MDC 获取 trace_id
   - 序列化请求参数（脱敏处理）

2. 方法执行后：
   - 记录 response_status（成功=200）
   - 计算 execution_time

3. 方法异常时：
   - 记录 response_status（对应错误码）
   - 记录 error_msg

4. 最终（finally）：
   - 调用 AuditLogService.log() 写入审计记录
   - 写入失败仅记录 ERROR 日志，不影响业务
```

### 3.3 手动调用 AuditApi.log()

对于无法通过注解覆盖的场景（如批处理内部、定时任务内部），提供手动调用方式：

```java
// AuditApi 对外接口（供其他模块调用）
public interface AuditApi {

    /**
     * 手动记录审计日志
     * 用于无法使用 @AuditLog 注解的场景
     */
    void log(String bizType, String bizAction, String resourceUrl,
             String requestParams, Integer responseStatus, String reason);
}
```

**典型使用场景**：
- 定时任务执行时的审计（无 HTTP 请求上下文）
- 批量操作中需要记录每一步的审计
- 跨模块调用时由调用方记录审计

### 3.4 请求参数脱敏规则

审计日志中的 `request_params` 字段必须经过脱敏处理：

| 字段类型 | 脱敏规则 | 示例 |
|:---|:---|:---|
| 手机号 | 保留前3后4，中间用*替代 | `138****5678` |
| 身份证号 | 保留前3后4，中间用*替代 | `310***********1234` |
| 银行账号 | 保留后4位，前面用*替代 | `************5678` |
| 金额 | 不脱敏（审计需完整记录） | `1000000.00` |
| 密码 | 全部替换为 `******` | `******` |
| SQL 语句 | 不脱敏（SQL探查需完整记录） | 原样保存 |

### 3.5 append-only 强制约束

- `audit_log` 表为**只追加（append-only）**，这是审计日志的核心安全要求
- **不可修改**：Mapper 层不提供 UPDATE 语句
- **不可删除**：Mapper 层不提供 DELETE 语句（物理删除仅限 DBA 通过 DROP PARTITION）
- **不可篡改**：trace_id + created_time 可用于追溯验证
- **Service 层强制**：AuditLogService 只暴露 `log()`（写入）和 `pageQuery()`/`export()`（查询/导出），不暴露任何修改/删除方法

## 4. 审计日志保留策略

### 4.1 在线保留期

| 数据类型 | 在线保留期 | 说明 |
|:---|:---|:---|
| audit_log | 12 个月 | 满足监管审计和内部审计要求 |
| 高危操作记录 | 24 个月（建议） | JOB_TRIGGER / EXECUTE_SQL / EXPORT 等高危操作建议延长保留 |

### 4.2 归档流程

```
1. 每月月初（建议每月2日凌晨），由定时任务触发归档检查
2. 检查 audit_log 表中超过 12 个月的分区
3. 导出超期分区数据至冷存储（如 OSS/NAS）
   - 导出格式：Parquet 或 CSV + GZIP
   - 文件命名：audit_log_YYYYMM.parquet.gz
4. 验证导出数据完整性（行数对比）
5. DROP 对应分区释放空间
6. 记录归档操作审计日志
```

### 4.3 分区建议

```sql
-- 按月分区（created_time）
ALTER TABLE audit_log PARTITION BY RANGE (TO_DAYS(created_time)) (
  PARTITION p202601 VALUES LESS THAN (TO_DAYS('2026-02-01')),
  PARTITION p202602 VALUES LESS THAN (TO_DAYS('2026-03-01')),
  PARTITION p202603 VALUES LESS THAN (TO_DAYS('2026-04-01')),
  -- ...按月追加
  PARTITION p_future VALUES LESS THAN MAXVALUE
);
```

- 每月通过定时任务自动创建下月分区（建议提前 2 个月创建）
- 分区管理可纳入 `sys_job_conf` 统一调度

### 4.4 容量预估

| 指标 | 估算值 |
|:---|:---|
| 日均审计记录数 | 约 5,000 ~ 10,000 条（取决于用户活跃度） |
| 单条记录大小 | 约 1 KB（含 request_params） |
| 月度数据量 | 约 150,000 ~ 300,000 条（150 MB ~ 300 MB） |
| 12 个月在线数据 | 约 1.8 GB ~ 3.6 GB |

## 5. 其他模块审计接入指南

其他业务模块接入审计日志，只需以下步骤：

### 步骤 1：在 Controller 方法上添加 @AuditLog 注解

```java
@PostMapping("/{id}/submit")
@BizAuth(bizType = BizType.LEAD, action = BizAction.WRITE)
@AuditLog(bizType = "LEAD", bizAction = "SUBMIT", highRisk = false)
public R<Void> submitLead(@PathVariable String id) {
    leadService.submit(id);
    return R.ok();
}
```

### 步骤 2：高危操作确保 reason 必填

```java
@PostMapping("/{jobId}/trigger")
@BizAuth(bizType = BizType.SYS_CONFIG, action = BizAction.JOB_TRIGGER)
@AuditLog(bizType = "SYS_JOB", bizAction = "JOB_TRIGGER", highRisk = true)
public R<Void> triggerJob(@PathVariable String jobId,
                          @RequestBody @Valid JobTriggerRequest request) {
    // highRisk=true 时，AOP 会校验 request 中的 reason 不为空
    jobService.triggerJob(jobId, request.getReason());
    return R.ok();
}
```

### 步骤 3：无法注解的场景手动调用

```java
@Autowired
private AuditApi auditApi;

public void batchProcess(List<Item> items) {
    for (Item item : items) {
        // 业务处理
        process(item);
        // 手动记录审计
        auditApi.log("BATCH", "PROCESS",
            "/internal/batch/" + item.getId(),
            JsonUtils.toJson(item), 200, "批量处理");
    }
}
```
