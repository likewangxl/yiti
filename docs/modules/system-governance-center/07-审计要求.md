# 系统治理中心审计要求

## 1. 目标与原则

审计日志用于回答“谁在什么时间、以什么理由、对什么资源做了什么、结果如何”。治理模块负责接收 common-aop 事件、保存结构化记录、提供受控查询和导出。

- 高危操作必须独立授权、独立资源和独立审计动作。
- 日志内容必须可追踪但不可泄露敏感信息；客户端只收到统一错误信息。
- 记录为追加型数据，治理 REST 不提供编辑和删除。
- Trace、操作人工号、业务类型和动作是关联日志的最小索引信息。

## 2. 审计入口

### 2.1 通用切面

common-aop 的 `@AuditLog` 注解字段为：

| 字段 | 语义 |
| --- | --- |
| `action` | 审计动作 |
| `resourceType` | 资源类型 |
| `reasonRequired` | 是否要求调用参数中有理由 |
| `serviceManaged` | 是否由业务 Service 在自己的事务中写完整审计 |

`AuditLogAspect` 在方法成功或异常结束时采集动作、资源、当前操作人、请求 URL/方法/IP/User-Agent、MDC `traceId`、理由、耗时、响应状态和异常摘要，并交给 `AuditLogHandler`。请求上下文不存在时，URL/IP 等字段可为空。

### 2.2 治理持久化处理器

`GovAuditLogHandler` 是 `@Primary` 的持久化处理器，将 `AuditLogEvent` 映射为 `AuditLogCmd` 并调用 `AuditLogService`。映射必须保持以下对应关系：

| 事件 | 持久化字段 |
| --- | --- |
| `action` | `bizAction` |
| `bizType`；缺失时 `resourceType` | `bizType` |
| `requestUrl`；缺失时 `resourceId` | `resourceUrl` |
| `requestMethod`、`requestParams` | 同名字段 |
| `traceId`、`operatorEmpId`、IP、User-Agent | 同名/操作人字段 |
| `reason`、`responseStatus`、`errorMsg`、耗时 | 同名字段 |
| `targetType`、`targetId`、`before`、`after`、`addedItems`、`removedItems` | 对应结构化审计字段 |

普通切面事件的处理异常由切面捕获并记录服务端日志，不应替换主业务响应；`serviceManaged=true` 的方法不再由切面补写空快照记录，业务 Service 必须自行调用审计服务。

## 3. 当前高危动作矩阵

| 功能 | REST 资源 | `BizType` | `BizAction` | 理由/审计要求 |
| --- | --- | --- | --- | --- |
| 字典新增、编辑、逻辑禁用、状态 | `/api/admin/sys/dicts...` | `SYS_CONFIG` | `CONFIG` | 记录目标字典类型、编码和前后状态 |
| 日历日期设置、年份初始化 | `/api/admin/sys/calendar...` | `SYS_CONFIG` | `CONFIG` | 记录日期/年份、状态和结果；年初始化需确认覆盖影响 |
| 日历 Excel 导入 | `/api/admin/sys/calendar/import` | `SYS_CONFIG` | `IMPORT` | 记录文件名、行数、成功/跳过结果 |
| 配置更新 | `/api/admin/sys/configs/{configKey}` | `SYS_CONFIG` | `CONFIG` | `reason` 必填；敏感值只记脱敏摘要或哈希 |
| 任务手动/协调触发 | `/api/admin/sys/jobs/{jobId}/trigger` | `SYS_CONFIG` | `JOB_TRIGGER` | `reason` 必填；记录 jobKey、操作人和日期参数 |
| 任务暂停/恢复 | `/api/admin/sys/jobs/{jobId}/pause|resume` | `SYS_CONFIG` | `CONFIG` | 记录任务、目标状态和 Scheduler 结果 |
| 审计日志导出 | `/api/admin/sys/audit-logs/export` | `SYS_CONFIG` | `EXPORT` | 记录筛选条件、操作人和导出结果 |
| SQL 探查 | `/api/admin/sql-probe/execute` | `SYS_CONFIG` | `EXECUTE_SQL` | 只记脱敏/截断 SQL、理由、行数和耗时 |
| 文件删除、标签删除/成员删除 | 对应业务资源 | 业务动作由资源登记定义 | `DELETE` | 记录目标 ID、关联影响和结果 |
| 标签及成员导入 | `/api/admin/sys/person-tags/.../import` | `SYS_CONFIG` | `IMPORT` | 记录维度、文件信息、写入/跳过/错误摘要 |

新增或修改高危接口时，必须同步 `@BizAuth`、`PT_RESOURCE`、`@AuditLog`/Service-managed 审计和本矩阵；不能只在前端隐藏入口。

## 4. 字段与脱敏规范

### 4.1 最小记录字段

`AuditLogCmd` 至少应正确填充：

`traceId`、`empId`、`empName`、`bizType`、`bizAction`、`resourceUrl`、`requestMethod`、`requestParams`、`responseStatus`、`errorMsg`、`ipAddress`、`userAgent`、`executionTime`、`reason`、`targetType`、`targetId`、`beforeSnapshot`、`afterSnapshot`、`addedItems`、`removedItems`。

`AuditLogDTO` 对外返回上述可展示字段及 `id`、`createdTime`，不返回 `userAgent`。审计查询条件为 `empId`、`bizType`、`bizAction`、起止日期和关键词。

### 4.2 敏感内容

写入日志、审计、异常和导出前必须处理：

- 手机号、证件号、账号、邮箱和姓名等个人信息按统一脱敏策略保留必要辨识度；
- 密码、密钥、Token、Cookie、OBS 凭据永不写入；
- SQL 探查只记录经长度控制的语句摘要/结果元数据，不把结果集中的敏感值复制到日志；
- `beforeSnapshot`、`afterSnapshot`、集合差异只保留审计必需字段；
- 异常响应对外使用治理错误码，堆栈仅保留在受控服务端日志；
- 导出文件沿用查询权限和脱敏字段，不因导出而扩大数据范围。

### 4.3 长度与格式

请求参数、快照、错误摘要和理由要限制长度，结构化差异使用可解析 JSON。时间统一按应用业务时区格式化；Trace 使用请求链路中的 `traceId`，不能每个审计层重新生成。

## 5. 事务和失败语义

- `AuditLogService.log` 使用 `Propagation.REQUIRES_NEW`，外层业务回滚时仍能保留审计记录。
- 由 Service-managed 方法写入的完整审计属于业务事务的一部分：审计写入失败时应使高危变更失败并回滚，避免出现无追踪的状态变更。
- 普通切面写入失败由 common-aop 记录服务端错误并隔离，不能吞掉业务异常，也不能把失败请求记为成功。
- Quartz `JobExecutionLogger` 同样隔离日志内部异常，Job 的业务结果不能因治理日志写入失败而被篡改。
- 批量通知、文件 OBS 操作和 Excel 导入具有各自的部分成功/补偿语义，审计必须记录实际结果，不能把“请求已接收”写成“全部完成”。

## 6. 查询、导出和数据范围

审计查询、详情和导出均使用 `SYS_CONFIG/READ` 或 `SYS_CONFIG/EXPORT` 授权，并在后端按统一数据范围过滤。SQL 探查历史仅查询当前操作人记录。

导出接口直接返回 Excel 附件，受服务实现的最大行数限制；导出前再次执行权限校验，筛选条件、操作人工号、响应状态和 Trace 必须可在审计记录中关联。

## 7. 实施检查清单

- [ ] Controller 的路径、`@BizAuth`、`PT_RESOURCE` 和动作一致。
- [ ] 写入/删除/导入/导出/触发接口有明确理由策略。
- [ ] 目标记录、前后快照或新增/移除集合已经定义且脱敏。
- [ ] 失败路径写入响应状态和错误摘要，不泄露堆栈。
- [ ] Service-managed 审计与业务事务边界已测试；普通切面异常不会改变主流程。
- [ ] 查询、详情、导出都经过后端数据范围检查。
- [ ] 日志、审计和导出内容没有凭据、完整敏感个人信息或未控制的 SQL 结果。
