# 系统治理中心依赖契约摘要

> 本文只描述当前源码和模块 POM 中已经存在的依赖边界。接口完整签名以
> [04-对外API契约.md](04-对外API契约.md) 和 `system-governance-center/src/main/java/.../api`
> 为准；不复制内部实现、实体或表结构。

## 1. 模块依赖方向

治理中心的生产依赖由本模块 `pom.xml` 确定：

| 依赖 | 用途与边界 |
| --- | --- |
| `common-web`、`common-trace`、`common-security`、`common-aop`、`common-db` | 统一 Web 响应、链路、认证/数据范围、审计切面、MyBatis-Plus 与事务基础设施 |
| `auth-permission-center` | 通过 `UserApi`、`OrgApi` 等公开 API 完成用户/机构解析；管理端鉴权复用统一安全基础设施 |
| Caffeine、Quartz、Huawei OBS SDK、MyBatis-Plus、POI/EasyExcel | 本模块实现的本地缓存、JDBC 调度、对象存储、持久化和文件处理能力 |

治理中心不依赖 workflow、portal、customer、business、performance、report、red
或 soap 等业务模块；业务模块只能通过治理 `api/*Api` 和 `api.dto` 调用治理能力。

## 2. 治理对外 API

以下接口是跨模块稳定边界，均为同 JVM Spring Bean 调用，不是远程协议：

| 接口 | 能力 | 主要调用方（按当前源码） |
| --- | --- | --- |
| `DictApi` | 启用字典查询、标签翻译、批量查询、值校验 | portal、customer、performance、report、red、soap |
| `CalendarApi` | 工作日判断、工作日计数、年度日历读取、加工作日 | workflow |
| `ConfigApi` | 按字符串、默认值或目标类型读取启用配置 | 由需要配置读取的模块按 API 使用；无写方法 |
| `JobApi` | 读取、注册、注销、触发和查询任务运行状态 | performance、red |
| `AuditApi` | 结构化审计写入与受数据范围约束的查询 | portal、performance、report |
| `NotifyApi` | 单条/批量通知、未读计数和通知查询 | workflow、portal、customer、performance |
| `FileApi` | OBS 文件上传、下载、关联、解除关联、删除及元数据读取 | portal、customer、performance、report、red |
| `PersonTagApi` | 按标签读取员工工号、机构编号和标签摘要 | performance |

方法签名、参数约束、返回 DTO 和失败码不在本表重新定义；发生变更时必须同步
04 文档，并检查所有调用方编译与契约测试。

### 2.1 调用语义

- 字典、配置、日历读取使用治理中心进程内 Caffeine 缓存；缓存不是跨实例或跨模块的权威状态。
- `CalendarApi` 的日期参数和正向工作日偏移约束见 04；调用方不得把空值或零偏移解释成默认日期。
- `JobApi.registerJob` 以 `jobKey` 覆盖业务配置；Quartz 不可用时是否只落业务配置由实现决定，调用方应检查返回值和运行状态。
- `NotifyApi.batchSendNotifications` 逐条处理，单条失败不应被调用方误认为整批回滚；需要提交后发送时由调用方控制事务事件时机。
- `FileApi` 的对象写入有 OBS 外部副作用；上传结果的 `newlyCreated` 用于补偿判断。删除会移除对象、元数据和全部关联，调用方必须先确认无其他用途。
- `AuditApi.log` 写入追加型审计记录；治理 Service 使用新事务保存，调用方必须在进入 API 前完成敏感信息脱敏。
- `PersonTagApi` 返回的 EMP 成员是 `PT_USER.USERNAME`，ORG 成员是 `EXT_ORG_INFO.DEPT_NO`；标签名称/成员解析失败不得凭空构造结果。

## 3. auth-permission-center 集成

治理源码当前直接注入的认证公开 API 是：

| API | 当前用途 |
| --- | --- |
| `UserApi` | 任务操作人名称、标签 EMP 成员校验与名称解析 |
| `OrgApi` | 标签 ORG 成员校验与名称解析 |

管理 Controller 的 `@BizAuth`、`DataScopeContext` 和请求身份由 common-security
与 auth-permission-center 的统一拦截器提供。治理模块不直接引用 auth 的 mapper、entity、内部
service 或私有表；未知身份、机构解析失败和数据范围异常按统一安全策略 Fail Close。

治理依赖的业务类型和动作以现行 `BizType`/`BizAction` 枚举、Controller 注解及
`PT_RESOURCE` 配置为准。新增管理端点必须同时登记资源，不得用“未标注注解”推导公开。

## 5. 调用方约束

- 只能依赖公开 `api/*Api`、`api.dto`；禁止依赖治理 entity、mapper、controller、内部
  service、Quartz 实现类或直接访问治理表。
- 跨模块调用应使用接口公开的 DTO 和统一异常；不能通过 `Object`、反射或字符串类名绕过类型契约。
- 文件调用方必须处理 OBS 禁用/失败、文件不存在和对象补偿；不得自行拼接 OBS URL。
- 调度调用方必须使用注册/触发 API 和受控 Job 配置，不得写 `SYS_JOB_CONF` 或 Quartz 表。
- 审计、通知、导入、导出和删除等高风险调用必须提供完整理由、目标和结果信息，并遵循
  07 文档的审计与脱敏要求。
- 本文中的调用方列表是源码核对结果，不是允许新增依赖的清单；新增跨模块依赖需先评估循环
 依赖、数据范围、事务和错误传播，再更新 POM、API、资源和文档。

## 6. 失败边界

- auth 用户/机构公开 API 不可用时，标签解析和任务操作人补全可能失败；不得降级为未经校验的
 账号或机构值。
- Quartz 未启用或注册失败时，业务任务配置与实际调度状态可能暂时不一致；由运维按 Runbook
 只读核对后处理。
- `obs.enabled=false` 或 OBS 请求失败时，文件对象能力不可用；数据库元数据不能被当作对象
 读取成功的证明。
- 治理本地缓存只在当前实例失效；修改后的读取应以服务实际返回为准，不在调用方缓存永久副本。
- 同步 API 的业务异常按统一错误码传播；调用方不得捕获后伪造成功响应或跳过必要审计。
