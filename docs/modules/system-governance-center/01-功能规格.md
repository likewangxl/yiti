# 系统治理中心 -- 功能规格

> 模块定位：支撑域模块，为全平台提供基础治理能力。负责字典管理、工作日历、任务调度、审计日志、通知消息、系统配置、文件管理。不负责登录认证，不负责具体业务审批逻辑，不负责权限模型定义。

---

## 1. 模块概述

系统治理中心（system-governance-center）是全平台的基础治理支撑模块，承担以下核心职责：

| 功能域 | 说明 | 对应表 |
|:---|:---|:---|
| 字典管理 | 维护系统所有下拉选项的统一配置 | sys_dict |
| 工作日历 | 管理全年工作日/休息日安排 | sys_calendar_day |
| 任务调度 | 管理定时任务配置与执行监控 | sys_job_conf、sys_job_run_log |
| 审计日志 | 记录与查询所有高危操作日志 | audit_log |
| 通知消息 | 统一的站内通知收发与管理 | user_notification |
| 系统配置 | 键值型运维级配置管理 | sys_config_kv |
| 文件管理 | 统一文件上传/下载/业务关联 | file_object、biz_file_rel |
| 数据探查 | 受控的只读SQL执行能力 | 无独立表，审计走 audit_log |

**依赖关系：**
- 依赖 common（基础层）
- 依赖 auth-permission-center（S 强依赖，获取当前用户、权限校验）
- 被以下模块依赖：workflow-center、performance-engine-center、portal-content-center、report-analytics-center、customer-marketing-center、business-application-center

## 2. 字典管理（对应 project_ana 4.6.3）

### 2.1 功能描述

维护系统所有下拉框的选项数据。字典为全行共享配置数据，由"科技部"指定角色（BACK_TECH）统一管理。

### 2.2 数据模型

V1 使用 `sys_dict` 单表存储（dict_type 作为分组，不拆 sys_dict_item）。

| 字段 | 说明 | 示例 |
|:---|:---|:---|
| dict_type | 字典类型（大写下划线命名） | `INDUSTRY` |
| dict_code | 字典编码（类型内唯一） | `IT` |
| dict_label | 字典标签（显示名称） | `信息技术` |
| dict_value | 字典值（存储/传输值） | `IT` |
| sort_order | 排序号 | `1` |
| status | 状态 ACTIVE/DISABLED | `ACTIVE` |
| remark | 备注 | `信息技术行业` |

**唯一约束：** `dict_type + dict_code` 联合唯一。

### 2.3 业务规则

1. 禁用状态（DISABLED）的字典项在所有选择场景中**不可见、不可选**；但已存储的历史数据中引用了该值时仍需能解析显示。
2. dict_type 命名规范：全部大写字母 + 下划线，正则 `^[A-Z_]+$`。
3. 字典删除采用**逻辑删除**（将 status 改为 DISABLED），不做物理删除。
4. 字典数据属于高频读取场景，通过 Redis 缓存（TTL 10 分钟），变更时主动清除缓存。

### 2.4 权限要求

| 操作 | BizAuth 注解 | 可操作角色 |
|:---|:---|:---|
| 查询字典类型列表 | `@BizAuth(bizType=SYS_CONFIG, action=READ)` | BACK_TECH、SYS_ADMIN |
| 查询指定类型的字典项 | 无需 @BizAuth（公共只读数据） | 所有登录用户 |
| 新增/编辑/删除/启用/禁用 | `@BizAuth(bizType=SYS_CONFIG, action=CONFIG)` | BACK_TECH |

## 3. 工作日历配置（对应 project_ana 4.6.4）

### 3.1 功能描述

设置全年的工作日、休息日及调休安排。主要应用场景为工作流红绿灯超时计算时需剔除非工作日。

### 3.2 数据模型

使用 `sys_calendar_day` 表，以日期（date 类型）为主键，逐天记录工作日/休息日状态。

| 字段 | 说明 |
|:---|:---|
| day | 日期（主键，date 类型） |
| is_workday | 是否工作日：1=工作日，0=休息日 |
| remark | 备注（如"国庆节"、"国庆调休"） |

### 3.3 交互设计

1. **日历视图**：以月为单位展示，每天一个格子，颜色区分工作日（蓝）/休息日（灰）。
2. **点击切换**：点击某天可切换工作/休息状态。
3. **批量导入**：支持 Excel 导入国家法定节假日安排（格式：日期 + 是否工作日）。
4. **年初初始化**：基于常规周末（周六日为休息日，周一至周五为工作日）生成全年 365/366 天日历。

### 3.4 业务规则

1. **已过去日期不允许修改**：今天及以前的日期不可更改，返回 `GOV-40902`。
2. **年初初始化幂等**：若目标年份已有数据，需提示是否覆盖（覆盖仅影响未来日期）。
3. **批量导入覆盖策略**：导入的日期覆盖已有记录（仅影响未来日期），不删除未涉及日期。

### 3.5 被调用场景

| 调用方模块 | 场景 | 调用接口 |
|:---|:---|:---|
| workflow-center | 红绿灯超时计算（剔除非工作日） | `CalendarApi.countWorkingDays()` |
| workflow-center | 计算工作日截止日期 | `CalendarApi.addWorkingDays()` |
| performance-engine-center | 绩效日历窗口 | `CalendarApi.isWorkingDay()` |

### 3.6 权限要求

| 操作 | BizAuth 注解 | 可操作角色 |
|:---|:---|:---|
| 查询日历（按月） | 无需 @BizAuth（公共只读数据） | 所有登录用户 |
| 切换工作/休息状态 | `@BizAuth(bizType=SYS_CONFIG, action=CONFIG)` | BACK_TECH |
| 年初初始化 | `@BizAuth(bizType=SYS_CONFIG, action=CONFIG)` | BACK_TECH |
| 批量导入 | `@BizAuth(bizType=SYS_CONFIG, action=IMPORT)` | BACK_TECH |

## 4. 任务调度监控（对应 project_ana 4.6.5）

### 4.1 功能描述

管理及监控系统所有定时任务的配置、运行状态、执行日志，并提供手动触发入口。

### 4.2 数据模型

**任务配置表 `sys_job_conf`：**

| 字段 | 说明 |
|:---|:---|
| id | 任务ID |
| job_key | 任务唯一标识（如 `PERF_DAILY_CALC`） |
| job_name | 任务名称 |
| cron_expr | Cron 表达式 |
| status | 状态 ACTIVE/PAUSED |
| allow_manual_trigger | 是否允许手动触发（1=允许，0=禁止） |
| last_run_time | 上次执行时间 |
| next_run_time | 下次执行时间 |

**任务执行日志表 `sys_job_run_log`：**

| 字段 | 说明 |
|:---|:---|
| id | 日志ID |
| job_id | 任务ID |
| trigger_type | 触发类型 SCHEDULED/MANUAL |
| reason | 触发原因（手动触发必填） |
| start_time | 开始时间 |
| end_time | 结束时间 |
| status | 运行状态 RUNNING/SUCCESS/FAILED |
| error_msg | 错误信息（失败时记录） |

### 4.3 页面组成

1. **任务列表页**：展示所有任务配置，包含任务名称、Cron 表达式、状态、上次执行时间、操作按钮（暂停/恢复/手动触发）。
2. **执行日志页**：按任务查询执行日志，支持分页、按状态/时间范围筛选。
3. **手动触发入口**：针对 `allow_manual_trigger=1` 的任务，提供手动触发按钮，触发时必须填写原因。

### 4.4 V1 定时任务清单

| 任务 KEY | 任务名称 | Cron 表达式 | 归属模块 |
|:---|:---|:---|:---|
| PERF_DAILY_CALC | 每日指标计算 | `0 2 * * *`（每日凌晨2点） | performance-engine-center |
| WF_TRAFFIC_LIGHT_UPDATE | 红绿灯状态更新 | `0/30 * * * *`（每30分钟） | workflow-center |
| DATA_SYNC_TRIGGER | 数据同步触发 | `0 1 * * *`（每日凌晨1点） | system-governance-center |
| RESOURCE_REFRESH_REMIND | 通讯录/产品资料库60天更新提醒 | `0 8 * * 1`（每周一上午8点） | portal-content-center |

### 4.5 业务规则

1. **JOB_TRIGGER 属于高危动作**：手动触发任务必须单独授权、单独审计、必填 reason。
2. **并发保护**：同一任务不允许同时运行两个实例（status=RUNNING 时禁止再次触发），返回 `GOV-40901`。
3. **暂停/恢复**：暂停后定时调度停止，但仍可手动触发（如果 allow_manual_trigger=1）。
4. **日志保留**：执行日志按需归档，默认保留 90 天。

### 4.6 权限要求

| 操作 | BizAuth 注解 | 可操作角色 |
|:---|:---|:---|
| 查询任务列表 | `@BizAuth(bizType=SYS_CONFIG, action=READ)` | BACK_TECH、SYS_ADMIN |
| 查询执行日志 | `@BizAuth(bizType=SYS_CONFIG, action=READ)` | BACK_TECH、SYS_ADMIN |
| 手动触发任务 | `@BizAuth(bizType=SYS_CONFIG, action=JOB_TRIGGER)` | BACK_TECH（高危、需审计） |
| 暂停/恢复任务 | `@BizAuth(bizType=SYS_CONFIG, action=CONFIG)` | BACK_TECH |

## 5. 审计日志（对应 project_ana 4.6.1.5）

### 5.1 功能描述

记录所有高危动作的操作日志，为安全审计和合规追溯提供支撑。

### 5.2 高危动作清单

| 动作枚举 | 说明 | reason 必填 |
|:---|:---|:---|
| EXPORT | 数据导出 | 否 |
| IMPORT | 数据导入 | 是 |
| DELETE | 数据删除 | 是 |
| TRANSFER | 数据转交 | 是 |
| EXECUTE_SQL | 执行自定义SQL | 否（SQL本身作为审计参数） |
| RECALC | 重新计算 | 是 |
| PERMISSION_CHANGE | 权限变更 | 否 |
| JOB_TRIGGER | 手动触发任务 | 是 |
| CONFIG | 系统配置变更 | 是 |

### 5.3 审计日志最小字段集

| 字段 | 来源 | 说明 |
|:---|:---|:---|
| trace_id | MDC | 链路追踪ID |
| emp_id | CurrentUserContext | 操作人工号 |
| emp_name | CurrentUserContext | 操作人姓名 |
| biz_type | @BizAuth 注解 / 参数 | 业务类型 |
| biz_action | @BizAuth 注解 / 参数 | 业务动作 |
| resource_url | HttpServletRequest | 资源URL |
| request_method | HttpServletRequest | 请求方法 |
| request_params | 切面拦截（脱敏后） | 请求参数 |
| response_status | 响应 | HTTP状态码 |
| ip_address | HttpServletRequest | IP地址 |
| user_agent | HttpServletRequest | 用户代理 |
| execution_time | 切面计时 | 执行耗时(ms) |
| reason | 请求体 | 操作原因（高危必填） |

### 5.4 落库方式

**同步写入 audit_log 表**。不走异步消息队列，确保审计日志与业务操作在同一事务上下文中可追溯。

### 5.5 审计日志查询

支持以下筛选维度：

| 筛选条件 | 类型 | 说明 |
|:---|:---|:---|
| empId | String | 按操作人工号精确查询 |
| bizType | String | 按业务类型精确查询 |
| bizAction | String | 按动作类型精确查询 |
| startTime / endTime | datetime | 按时间范围查询 |
| keyword | String | 模糊搜索（resource_url / request_params） |

### 5.6 权限要求

| 操作 | BizAuth 注解 | 可操作角色 |
|:---|:---|:---|
| 查询审计日志 | `@BizAuth(bizType=SYS_CONFIG, action=READ)` | SYS_ADMIN、BACK_TECH |
| 审计日志详情 | `@BizAuth(bizType=SYS_CONFIG, action=READ)` | SYS_ADMIN、BACK_TECH |
| 导出审计日志 | `@BizAuth(bizType=SYS_CONFIG, action=EXPORT)` | SYS_ADMIN（高危、需审计） |

## 6. 通知消息（对应 project_ana 4.1.1）

### 6.1 功能描述

平台统一的站内通知系统，接收来自流程事件、系统事件、业务事件的通知并推送给目标用户。

### 6.2 通知来源

| 来源 | notify_type | 典型场景 |
|:---|:---|:---|
| 流程结束事件 | WORKFLOW | 审批通过/驳回/转交通知 |
| 系统事件 | SYSTEM | 任务调度异常告警、资料库更新提醒 |
| 业务事件 | BUSINESS | 客户线索分配、触达任务创建 |

### 6.3 数据模型

使用 `user_notification` 表。

| 字段 | 说明 |
|:---|:---|
| id | 通知ID |
| emp_id | 接收人工号 |
| title | 通知标题 |
| content | 通知内容 |
| notify_type | 通知类型 SYSTEM/WORKFLOW/BUSINESS |
| biz_type | 关联业务类型（可选，用于跳转） |
| biz_id | 关联业务ID（可选，用于跳转） |
| link_url | 跳转链接 |
| is_read | 是否已读 1=已读 0=未读 |
| read_time | 阅读时间 |

### 6.4 交互设计

1. **通知列表**：分页展示，字段含标题、通知类型、内容摘要、生成时间、已读状态。
2. **已读/未读筛选**：支持按已读/未读状态过滤。
3. **点击通知**：点击后自动置为已读，若 link_url 非空则跳转到业务详情。
4. **全部已读**：提供"全部标记为已读"操作。
5. **工作台卡片**：工作台首页展示未读通知数量卡片。
6. **移动端 H5**：通知列表与详情同步支持 H5 页面。

### 6.5 业务规则

1. 通知天然按当前用户（emp_id）过滤，无需额外数据范围控制。
2. 查看通知详情时自动标记为已读。
3. 通知发送允许异步（事务提交后发送），但不丢失。
4. 通知无删除功能（V1），仅有已读/未读状态切换。

### 6.6 权限要求

| 操作 | BizAuth 注解 | 说明 |
|:---|:---|:---|
| 查询我的通知列表 | 无需 @BizAuth | 天然按 emp_id 过滤 |
| 查询未读数量 | 无需 @BizAuth | 天然按 emp_id 过滤 |
| 标记已读 | 无需 @BizAuth | 仅能操作自己的通知 |
| 通知详情 | 无需 @BizAuth | 仅能查看自己的通知 |

## 7. 系统配置KV（运维级配置）

### 7.1 功能描述

管理系统级键值配置，供运维和科技部人员使用。不用于业务参数（业务参数由各业务模块自行管理）。

### 7.2 数据模型

使用 `sys_config_kv` 表。

| 字段 | 说明 |
|:---|:---|
| id | 配置ID |
| config_key | 配置键（唯一） |
| config_value | 配置值（支持长文本） |
| value_type | 值类型 STRING/JSON/NUMBER/BOOL |
| status | 状态 ACTIVE/DISABLED |
| remark | 备注 |

### 7.3 V1 典型配置项

| config_key | value_type | 默认值 | 说明 |
|:---|:---|:---|:---|
| `page.default.size` | NUMBER | `20` | 分页默认大小 |
| `page.max.size` | NUMBER | `100` | 分页最大大小 |
| `export.max.rows` | NUMBER | `50000` | 导出最大行数 |
| `cache.dict.ttl.minutes` | NUMBER | `10` | 字典缓存TTL（分钟） |
| `slow.sql.threshold.ms` | NUMBER | `5000` | 慢SQL告警阈值（毫秒） |
| `file.upload.max.size.mb` | NUMBER | `10` | 文件上传大小限制（MB） |
| `file.upload.allowed.types` | JSON | `["pdf","doc","docx","xls","xlsx","png","jpg","jpeg"]` | 文件上传允许的格式 |
| `sql.probe.timeout.seconds` | NUMBER | `30` | SQL探查超时（秒） |
| `sql.probe.max.rows` | NUMBER | `1000` | SQL探查最大返回行数 |
| `sql.probe.allowed.schemas` | JSON | `["onepl"]` | SQL探查允许的Schema |

### 7.4 业务规则

1. config_key 全局唯一。
2. 配置变更属于 CONFIG 动作，需审计并填写 reason。
3. 配置值需根据 value_type 做类型校验（如 NUMBER 类型的值必须是合法数字）。
4. 配置数据通过 Redis 缓存（TTL 10 分钟），变更时主动清除缓存。

### 7.5 权限要求

| 操作 | BizAuth 注解 | 可操作角色 |
|:---|:---|:---|
| 查询配置列表 | `@BizAuth(bizType=SYS_CONFIG, action=READ)` | BACK_TECH、SYS_ADMIN |
| 更新配置值 | `@BizAuth(bizType=SYS_CONFIG, action=CONFIG)` | BACK_TECH |

## 8. 文件管理

### 8.1 功能描述

提供统一的文件上传、下载、业务关联管理能力。所有模块需要文件存储时统一通过 governance 提供的 FileApi 进行操作。

### 8.2 数据模型

**文件对象表 `file_object`：**

| 字段 | 说明 |
|:---|:---|
| id | 文件对象ID |
| file_name | 文件名 |
| file_size | 文件大小（字节） |
| file_type | 文件类型（MIME 或扩展名） |
| storage_path | MinIO 存储路径 |
| bucket_name | MinIO 存储桶名称 |
| md5_hash | MD5 哈希值（用于去重） |
| uploaded_by | 上传人工号 |
| uploaded_time | 上传时间 |

**业务附件关联表 `biz_file_rel`：**

| 字段 | 说明 |
|:---|:---|
| id | 关联ID |
| biz_type | 业务类型（BizType 枚举值或业务域标识） |
| biz_id | 业务ID |
| file_object_id | 文件对象ID |
| file_role | 文件用途 ATTACHMENT/PHOTO/... |

**唯一约束：** `biz_type + biz_id + file_object_id` 联合唯一。

### 8.3 存储方案

- **存储引擎**：MinIO 8.5.7（本地对象存储）。
- **存储桶策略**：按业务类型分桶或统一桶 + 路径分类（V1 使用统一桶 `branch-platform`）。
- **存储路径规则**：`/{bizType}/{yyyy}/{MM}/{dd}/{uuid}.{ext}`。
- **下载方式**：通过 MinIO 预签名 URL（有效期 1 小时）。

### 8.4 业务规则

1. **格式白名单**：仅允许上传白名单内的文件格式（从 `sys_config_kv` 读取 `file.upload.allowed.types`），不在白名单内返回 `GOV-40903`。
2. **大小限制**：单文件不超过 10MB（从 `sys_config_kv` 读取 `file.upload.max.size.mb`），超限返回 `GOV-40904`。
3. **MD5 去重**：上传前计算 MD5，若已存在相同 MD5 的文件则复用已有 file_object 记录，不重复上传到 MinIO。
4. **业务关联**：文件上传后通过 `biz_file_rel` 与具体业务对象关联，一个文件可被多个业务对象引用。
5. **删除策略**：删除文件时先解除所有 biz_file_rel 关联，若无其他引用则从 MinIO 删除实际文件。

### 8.5 被调用场景

| 调用方模块 | 场景 |
|:---|:---|
| portal-content-center | 文档管理中的文件上传/下载 |
| customer-marketing-center | 触达日志照片上传 |
| business-application-center | 业务申请附件上传 |
| workflow-center | 审批附件 |

### 8.6 权限要求

| 操作 | 说明 |
|:---|:---|
| 上传文件 | 所有登录用户均可上传 |
| 下载文件 | 所有登录用户均可下载（文件级权限由业务模块控制） |
| 删除文件 | 由业务模块按业务权限判断后调用 FileApi |

## 9. 数据探查框（对应 project_ana 4.5.3）

### 9.1 功能描述

为科技部人员提供受控的只读 SQL 执行能力，用于数据排查和问题定位。由 governance 模块提供 SQL 执行引擎，不依赖其他模块。

### 9.2 安全约束

| 约束项 | 规则 |
|:---|:---|
| SQL 类型 | 仅允许 SELECT 语句，禁止 INSERT/UPDATE/DELETE/DDL |
| LIMIT 强制 | 后端自动追加 LIMIT（默认 1000 行，从 sys_config_kv 读取） |
| Schema 白名单 | 仅允许访问白名单内的 Schema（从 sys_config_kv 读取） |
| 超时控制 | SQL 执行超时默认 30 秒（从 sys_config_kv 读取），超时自动终止 |
| 并发限制 | 同一时刻最多允许 N 个探查并发（V1 默认 3 个） |

### 9.3 业务规则

1. 属于 `EXECUTE_SQL` 高危动作，必须审计。
2. 审计日志中记录完整 SQL 语句、执行耗时、返回行数。
3. SQL 语法校验在执行前完成，非 SELECT 语句返回 `GOV-42201`。
4. 执行超时返回 `GOV-42202`。
5. 访问白名单外的表返回 `GOV-42203`。

### 9.4 权限要求

| 操作 | BizAuth 注解 | 可操作角色 |
|:---|:---|:---|
| 执行 SQL | `@BizAuth(bizType=SYS_CONFIG, action=EXECUTE_SQL)` | BACK_TECH |
| 查询探查历史 | `@BizAuth(bizType=SYS_CONFIG, action=READ)` | BACK_TECH |
