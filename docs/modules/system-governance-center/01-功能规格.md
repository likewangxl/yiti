# 系统治理中心功能规格

## 1. 职责与边界

系统治理中心负责平台级、可复用的治理能力：

| 能力 | 负责内容 | 数据归属 |
| --- | --- | --- |
| 字典 | 字典项查询、维护、启停和标签解析 | `SYS_DICT` |
| 配置 | 系统键值配置读取、管理端更新和类型转换 | `SYS_CONFIG_KV` |
| 日历 | 工作日判断、日历查询、日期设置、初始化和 Excel 导入 | `SYS_CALENDAR_DAY` |
| 调度 | `SYS_JOB_CONF` 管理、Quartz 注册/触发/暂停、执行日志 | `SYS_JOB_CONF`、`SYS_JOB_RUN_LOG` 与 Quartz 表 |
| 审计 | AOP 事件接收、审计日志持久化、查询和导出 | `AUDIT_LOG` |
| 通知 | 用户通知写入、未读查询和已读管理 | `USER_NOTIFICATION` |
| 文件 | 文件校验、华为云 OBS 对象读写、业务关联和元数据查询 | `FILE_OBJECT`、`BIZ_FILE_REL` |
| 标签 | 员工/机构标签及 Excel 导入 | `PERSON_TAG`、`PERSON_TAG_REL` |
| SQL 探查 | 受限只读查询和执行审计 | 审计日志；不提供通用写库能力 |

模块内通过 Service/Facade 访问自己的 Mapper 和表；其他模块只能依赖本模块 `api/` 中的公开 API 与 DTO，不得引用实体、Mapper、内部 Service 或直接访问本模块私有表。

统一响应、分页、Trace、鉴权、数据范围和异常格式遵循 `docs/common-dev-guide.md`。REST 的完整路径、请求字段、响应字段和错误码以 [03-接口设计与报文](03-接口设计与报文.md) 为准，跨模块 Java API 以 [04-对外API契约](04-对外API契约.md) 为准。

## 2. 字典

### 2.1 使用场景

- 公共查询按 `dictType` 返回启用项，项按 `sort_order` 升序排列。
- 管理端支持新增、部分更新、逻辑禁用和显式设置 `ACTIVE`/`DISABLED`。
- `(dict_type, dict_code)` 必须唯一；禁用项不参与公开查询、标签解析和合法性校验。
- `DictApi.getDictLabel` 查不到项时返回传入的 `dictCode`，便于已有数据展示；`getDictItem` 返回空 `Optional`。
- 读取使用进程内 Caffeine 缓存；写操作成功后清除对应字典类型缓存。缓存是性能优化，不是跨实例一致性协议。

### 2.2 权限与审计

公共查询不声明管理端 `@BizAuth`；管理端接口使用 `BizType.SYS_CONFIG`，新增/更新/启停/逻辑禁用属于 `CONFIG` 操作，均须通过统一资源授权和审计要求。写入 Service 仍需按目标记录做二次校验。

## 3. 工作日历

### 3.1 规则

- `SYS_CALENDAR_DAY.day` 是自然主键，`is_workday` 为 `1`（工作日）或 `0`（休息日）。
- 单日判断命中记录时使用记录值；无记录时按周一至周五为工作日、周六日为休息日。
- 管理端按年或月查询；公共端按月查询。
- 单日设置只允许今天及未来日期，过去日期返回 `GOV-40301`；不存在的日期会创建，存在的日期会更新，并清除对应年份缓存。
- 年初始化是按指定年份重置后按自然周规则重建，调用前必须确认该年份已有人工调整不会被保留。
- Excel 导入解析“日期、是否工作日、备注”三列，过去日期跳过，其余日期按存在则更新、不存在则插入处理，并清除受影响年份缓存。

### 3.2 公开计算 API

`CalendarApi` 提供工作日判断、区间工作日计数、指定年份记录和向后推算工作日。Facade 对空日期及零步数做参数校验；`countWorkingDays(from, to)` 在 `from >= to` 时返回 `0`。

## 4. 系统配置

- 管理端提供配置分页查询和按 `configKey` 更新；更新请求必须包含配置值和修改原因。
- `SYS_CONFIG_KV.config_key` 唯一，`value_type` 为 `STRING`、`JSON`、`NUMBER` 或 `BOOL`，状态为 `ACTIVE`/`DISABLED`。
- `ConfigApi` 只提供读取：原始字符串、带默认值读取和按类型转换读取。缺失配置返回空值/默认值，强类型读取缺失或转换失败分别使用治理错误码。
- 读取缓存键按配置键隔离，更新后清除对应键；配置内容不得在日志、文档或响应之外泄露凭据。

## 5. 调度治理

### 5.1 配置与生命周期

`SYS_JOB_CONF` 以 `job_key` 唯一标识 Job，保存显示名、Cron、Quartz Job 类、misfire 策略、状态和是否允许触发。状态为 `ACTIVE`/`PAUSED`；`JobApi.registerJob` 负责校验、写配置并在 Scheduler 可用时注册 JobDetail/CronTrigger，同一 `jobKey` 为覆盖语义；`unregisterJob` 解除 Quartz 注册并移除配置记录。

运行配置 `governance.scheduler.allowed-job-keys` 是可选的精确 JobKey 允许集合。未设置或集合为空时保持既有调度行为；集合非空时，只有集合内的 JobKey 可以注册、触发或恢复到 Quartz，启动同步会跳过其他 `ACTIVE` 配置。拒绝发生在配置写入、执行日志写入和 Quartz 调用之前，返回 `GOV-40303`，不修改 `SYS_JOB_CONF` 或 Quartz 表。

### 5.2 执行与操作

- 应用启动时读取 `ACTIVE` 配置同步到 Quartz；单条配置错误记录日志并继续处理，其余任务仍可启动。
- 全局 `JobExecutionLogger` 在 Job 开始时写 `RUNNING`，结束时更新 `SUCCESS`/`FAILED` 和 `last_run_time`；自动触发的操作人标识为 `SYSTEM`，手动触发透传当前操作人和原因。
- 管理端可查询配置和执行日志、手动触发、暂停、恢复。手动或业务协调触发必须同时通过 `allow_manual_trigger` 和 Scheduler 可用性检查；触发类型仅允许 `MANUAL`/`AUTO`。
- 允许集合启用时，启动同步、声明式注册、按 Key 触发、按 ID 触发、恢复和底层 Quartz 注册均执行同一 JobKey 门禁；空集合不改变默认行为，Scheduler 不可用时仍按既有降级语义处理。
- Quartz JDBC JobStore 和 `QRTZ_LOCKS` 提供集群调度的一致执行；业务模块不得自建并行调度器或绕过 `JobApi` 写执行日志。

## 6. 审计日志

- 需要记录的 Controller/Service 使用 common-aop `@AuditLog`；`GovAuditLogHandler` 将 AOP 事件映射到 `AuditLogCmd`。
- 高危操作（配置变更、导入、导出、手动/协调触发、SQL 探查、删除等）使用独立资源和动作授权，理由字段按接口要求填写。
- 审计记录包含操作人、业务动作、URL/方法、Trace、脱敏请求参数、响应状态、耗时、异常和目标/前后快照等；日志记录不得暴露手机号、证件号、凭据、完整敏感 SQL 或异常堆栈给客户端。
- `AuditLogService.log` 使用独立事务写入；审计写入异常由统一切面隔离，不应替换主业务响应。直接由高危 Service 调用审计 API 时，应按调用方事务策略处理失败。
- 审计日志只提供查询和导出，不在治理接口提供修改或删除。

## 7. 通知

- `NotificationCmd` 写入接收人工号、标题、内容、类型和可选业务跳转信息，未指定类型时默认为 `SYSTEM`。
- 用户 REST 查询、未读计数、单条已读、全部已读和详情均从 `DataScopeContext` 取得当前工号；详情仅允许读取本人通知并在成功读取后标记已读，不通过错误响应泄露他人通知是否存在。
- `NotifyApi.batchSendNotifications` 按条发送，单条失败记录服务端日志并继续，不把部分成功伪装成全量成功。业务方如需提交后通知，可在自己的事务边界使用事务事件监听器。

## 8. 文件

### 8.1 对象与关联

- 文件内容由 `ObsStorageClient` 读写华为云 OBS；数据库保存原文件名、大小、类型、对象路径、桶名、MD5、上传人和上传时间。
- `BIZ_FILE_REL` 维护业务类型、业务 ID、文件对象和文件角色的关联，三元组唯一；绑定幂等，解绑只解除该关联。
- 上传按扩展名白名单和 50 MB 上限校验，以 MD5 去重。新对象写入 OBS 后再落库，元数据插入失败时尝试删除本次新对象。
- 删除文件会删除 OBS 对象、文件元数据及全部关联；当前实现不做引用计数，调用方删除前必须确认其他业务不再使用该文件。
- REST 下载当前直接读取 OBS 字节并写入附件响应；`FileApi.getDownloadUrl` 另返回 OBS 临时预签名 URL，实际有效期由 `obs.presignExpireSeconds` 配置决定。

### 8.2 外联开关

`obs.enabled=false` 时保留 Bean 以便应用装配，但所有对象操作明确返回 `GOV-50301`；启用 OBS 时不得在代码、文档或日志记录访问凭据。

## 9. 员工/机构标签

- `PERSON_TAG.tag_name` 全局唯一；关联表用 `dim_type=EMP/ORG` 区分员工工号和机构业务编号。
- EMP 成员使用 `PT_USER.USERNAME`；ORG 成员使用 `EXT_ORG_INFO.DEPT_NO`。展示姓名/机构名时由公开的用户/机构 API 实时解析，不把名称作为关联主键。
- 管理端支持标签 CRUD、成员分页、新增/修改/删除；删除标签级联删除关联。新增同维度已存在成员按幂等语义跳过。
- 全局 Excel 导入按维度追加，缺少的标签可自动创建；指定标签的成员导入只替换该维度，另一维度不受影响。两类导入均在校验通过后原子写入并返回行级错误。
- 业务模块通过 `PersonTagApi` 按标签 ID 获取去重员工工号/机构编号或回显标签，不得直连标签表。

## 10. SQL 探查

- 独立资源 `/api/admin/sql-probe` 仅接受去空白后以 `SELECT` 开头的语句，请求最长 5000 字符。
- 服务端自动补充 `LIMIT 1000`（请求中已含 `LIMIT` 时不重复追加），使用 JDBC 查询超时 30 秒和进程内最多 3 个并发许可。
- 执行与当前操作人工号写入 `SQL_PROBE/EXECUTE_SQL` 审计日志，结果返回列名、行、行数和耗时；探查历史只能查询当前用户记录。
- SQL 探查属于高危能力，必须独立授权、原因/备注按权限策略留痕，并由运维审批后使用；不可把它当作结构变更、数据修复或通用写库接口。

## 11. 共同非目标

- 不在本模块文档维护版本流水、日期回填说明、环境快照或易漂移的数量统计。
- 不把数据模型文档当作结构变更脚本；结构实施和权限资源变更须按 DBA/安全审批流程执行。
- 不在治理模块复制业务域状态机或跨模块私表查询；跨模块交互只走公开 API/DTO/事件。
