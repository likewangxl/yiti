# 报表分析中心 -- 依赖契约摘要

> 版本：V1 | 最后更新：2026-04-10
> 模块代号：report-analytics-center
> 本文档摘录自被依赖模块的对外 API 契约，仅供快速查阅。
> **如有冲突，以源模块的 `04-对外API契约.md` 为准。**

---

## 0. 依赖关系总览

```
            ┌────────────────────────────┐
            │  report-analytics-center   │
            │    （本模块，V1 最下游）    │
            └─────────────┬──────────────┘
                          │
        ┌─────────────────┼────────────────┐
        │                 │                │
        ▼                 ▼                ▼
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ auth-        │  │ governance-  │  │ performance- │
│ permission   │  │ center       │  │ engine-      │
│ -center  (S) │  │         (S)  │  │ center   (S) │
└──────────────┘  └──────────────┘  └──────────────┘
        │
        ▼
┌──────────────┐
│ customer-    │
│ marketing-   │
│ center   (S) │
└──────────────┘
```

**依赖等级**：

- **S (Strong)**：强依赖，本模块必须调用，故障时本模块不可用；
- **W (Weak)**：弱依赖，故障时可降级。

**模块地位**：report-analytics-center 是 V1 的**最下游模块**，依赖 4 个模块，但**不被任何模块依赖**。

**依赖数量**：4 个（全部强依赖）
- auth-permission-center（S）
- system-governance-center（S）
- customer-marketing-center（S）
- performance-engine-center（S）

## 1. 依赖 auth-permission-center（强依赖 S）

来源：`docs/modules/auth-permission-center/04-对外API契约.md`

### 1.1 CurrentUserApi（会话上下文）

| 方法签名 | 入参 | 出参 | 用途 |
|:---|:---|:---|:---|
| getCurrentUserContext() | 无 | CurrentUserContext | 获取完整权限上下文（含工号/机构/角色/数据范围） |
| getCurrentEmpId() | 无 | String | 获取当前登录员工工号 |
| getCurrentOrgCode() | 无 | String | 获取当前登录员工机构编码 |
| getCurrentRoles() | 无 | Set\<String\> | 获取当前用户角色集合 |
| isSystemAdmin() | 无 | boolean | 是否系统管理员 |
| hasRole(String roleCode) | R_ADMIN 等 | boolean | 是否拥有某角色 |

**本模块使用场景**：

- 保存方案时获取 `empId` 归属；
- SQL 探查判定是否有 R_BACK_TECH 权限；
- 行长仪表盘判定是否为 R_BRANCH_PRESIDENT；
- 数据范围控制（每个读接口都必须调用）。

### 1.2 BizScopeApi（数据范围）

| 方法签名 | 入参 | 出参 | 用途 |
|:---|:---|:---|:---|
| resolveScope(empId, bizType) | empId, "REPORT" | DataScopeType | 解析报表业务的数据范围类型 |
| resolveOrgScope(empId, bizType) | empId, "REPORT" | Set\<String\> | 解析有权访问的机构编码集合 |
| resolveEmpScope(empId, bizType) | empId, "REPORT" | Set\<String\> | 解析有权访问的员工工号集合 |
| resolveCustScope(empId, bizType) | empId, "REPORT" | Set\<String\> | 解析有权访问的客户 ID 集合 |

**本模块使用场景**：

- 动态查询时过滤用户可见的对象（员工/机构/客户）；
- 导出时校验请求的对象是否在数据范围内；
- 仪表盘按用户数据范围过滤。

**`DataScopeType` 枚举**（参考 auth 契约）：

```
SELF        - 仅本人
BRANCH      - 本分行
SUB_BRANCH  - 本支行
ORG_SUBTREE - 机构子树
CUSTOM      - 自定义
ALL         - 全部
NONE        - 无
```

### 1.3 OrgApi（组织架构）

| 方法签名 | 入参 | 出参 | 用途 |
|:---|:---|:---|:---|
| getOrg(orgCode) | orgCode | Optional\<OrgDTO\> | 查询机构详情 |
| listOrgs(orgCodes) | Set | List\<OrgDTO\> | 批量查询 |
| getOrgSubtreeCodes(orgCode) | orgCode | Set\<String\> | 机构子树（含自身和所有后代） |
| getOrgChildren(orgCode) | orgCode | List\<OrgDTO\> | 直属下级 |
| getOrgParentPath(orgCode) | orgCode | List\<OrgDTO\> | 向上父级路径 |

**本模块使用场景**：

- 机构维度报表：获取目标机构的子树所有机构编码；
- 仪表盘排行榜：获取行长所在分行的所有直属下级；
- 对象树元数据：构建机构选择器。

### 1.4 UserQueryApi（员工信息）

| 方法签名 | 入参 | 出参 | 用途 |
|:---|:---|:---|:---|
| getUser(empId) | empId | Optional\<UserDTO\> | 员工信息（含姓名/机构/角色） |
| listUsers(empIds) | Set | List\<UserDTO\> | 批量查询 |

| searchUsers(keyword, limit) | "张三",50 | List\<UserDTO\> | 员工搜索（对象选择器） |

| 方法签名 | 入参 | 出参 | 用途 |
|:---|:---|:---|:---|
| log(AuditLogCmd) | 审计命令 | void | 写入审计日志（同步） |
| logAsync(AuditLogCmd) | 审计命令 | void | 写入审计日志（异步，仪表盘用） |

**AuditLogCmd 字段**（参考 governance 契约）：

```
action            // EXPORT / EXECUTE_SQL / READ / DOWNLOAD

operatorEmpId     // 操作人
```

**本模块使用场景**：

- 所有导出接口：`log(EXPORT)`；
- SQL 探查：`log(EXECUTE_SQL)`（必须同步写）；
- 行长仪表盘：`logAsync(READ)`（避免影响响应时间）；
- 文件下载：`log(DOWNLOAD)`。

## 5. 订阅的领域事件

本模块通过 `common-web` 的 `@EventListener` 订阅以下事件：

### 5.1 performance.sys-control.updated.v1

**来源**：performance-engine-center

**触发时机**：指标数据版本更新（通常在批量计算完成后）

**事件 Payload**：

```json
{
  "eventId": "evt-20260306-001",
  "eventType": "performance.sys-control.updated.v1",
  "eventTime": "2026-03-06T02:00:00+08:00",
  "dim": "EMP",
  "cycleType": "DAILY",
  "dataDate": "2026-03-05",
  "version": 20260305001
}
```

**本模块处理**：

1. 清除所有 `report:dashboard:*` 缓存（影响仪表盘数据）
2. 清除 `report:metric:*` 缓存（影响指标元数据）
3. 记录事件处理日志

**处理要求**：

- 幂等（按 eventId 去重）；
- 异步（不阻塞事件总线）；
- 失败重试 3 次，仍失败则记录告警。

### 5.2 performance.kpi-calc.completed.v1

**来源**：performance-engine-center

**触发时机**：KPI 计算任务完成

**事件 Payload**：

```json
{
  "eventId": "evt-20260306-002",
  "eventType": "performance.kpi-calc.completed.v1",
  "eventTime": "2026-03-06T03:00:00+08:00",
  "cycleType": "MONTHLY",
  "dataDate": "2026-03-05",
  "affectedEmpCount": 200,
  "affectedOrgCount": 15
}
```

**本模块处理**：

- 清除对应周期的仪表盘缓存（如 `report:dashboard:president:*`）；
- 可选：预热热点仪表盘（行长视图）。

### 5.3 governance.dict.updated.v1

**来源**：system-governance-center

**触发时机**：字典维护接口更新字典

**事件 Payload**：

```json

  "eventId": "evt-20260306-003",
  "eventType": "governance.dict.updated.v1",
  "eventTime": "2026-03-06T10:00:00+08:00",
  "dictType": "METRIC_LEVEL",
  "action": "UPDATE"

```

**本模块处理**：

- 清除 `report:dict:{dictType}` 缓存。

### 5.4 governance.config.updated.v1

**来源**：system-governance-center

**触发时机**：系统配置更新（特别是 `sql.probe.*` 和 `report.*` 前缀的配置）

**事件 Payload**：

```json
{
  "eventId": "evt-20260306-004",
  "eventType": "governance.config.updated.v1",
  "eventTime": "2026-03-06T11:00:00+08:00",
  "configKey": "sql.probe.schema.whitelist",
  "oldValue": "...",
  "newValue": "..."
}
```

**本模块处理**：

- 如 `configKey` 以 `sql.probe.` 或 `report.` 开头，清除本地 Caffeine 缓存，下次读取时从远程拉取最新值。

## 6. 不发布的领域事件

**重要**：V1 的 report 模块**不发布任何领域事件**。

**理由**：

- 报表是"最下游的消费者"，其动作（查询/导出）不应触发其他模块响应；
- 保存方案、SQL 探查等操作是用户私有行为，与其他模块无关；
- 即使是审计事件也通过 `AuditApi.log` 直写，而非领域事件。

**V2 可能引入**：

- `report.export-task.completed.v2`：供门户首页"我的任务"展示；
- `report.dashboard.accessed.v2`：供数据治理平台统计报表使用率。

## 7. 调用约束

### 7.1 强制规则

| 规则 | 说明 |
|:---|:---|
| 必须通过 Api 调用 | 所有跨模块数据获取必须通过 `*Api`/`*QueryApi`，禁止直连 Mapper |
| 禁止 JOIN 其他模块的表 | 即使在 SQL 探查中也禁止 JOIN `cust_lead`/`kpi_result` 等 |
| 禁止调用 Controller | 不能通过 HTTP 调用其他模块的 REST 接口 |
| 禁止引入 ServiceImpl | Maven 依赖只能是 `*-api` artifact，不能是 `*-core`/`*-service` |
| 必须处理空值 | Api 返回 `Optional` 时必须检查，返回 List 时必须处理空集合 |
| 必须设置超时 | 所有 Api 调用必须配置超时（默认 3 秒） |
| 必须幂等 | 事件订阅必须做 eventId 去重 |

### 7.2 失败处理

| 场景 | 本模块处理策略 |
|:---|:---|
| Api 返回 Optional.empty() | 视业务需要降级（如指标元数据缺失，显示"未知指标"） |
| Api 抛出 RuntimeException | 包装为 `BusinessException("RPT-5001", "上游服务异常")` |
| Api 调用超时 | 熔断 30 秒，触发告警 |
| 事件订阅处理失败 | 记录日志，进入死信队列（V2 引入） |

### 7.3 缺失能力的处理

如遇 Api 未暴露的能力需求：

1. **先与源模块协商**：提 Issue 或设计评审请求扩展 Api；
2. **不得绕过调用**：严禁直接读其他模块的表或 Mapper；
3. **临时降级**：可用 `ConfigApi` 存储的静态配置顶替（V1 常见做法）；
4. **V2 规划**：记录到本模块的 TODO 列表，V2 统一处理。

**典型缺失能力示例**：

- customer-marketing-center 的 `TouchTaskQueryApi` V1 未实现 → 触达汇总报表先返回静态数据或 404；
- performance-engine-center 的 `estimateRowCount` V1 未实现 → 统一走异步导出；
- auth-permission-center 的 `BizScopeApi.resolveCustScope` V1 未实现 → 客户维度权限先按"全部可见"处理（需审计）。

## 8. 版本兼容性

### 8.1 Api 版本策略

- 被依赖的 Api 遵循 **"新增不减少"** 原则：新版本可增加方法或字段，但不得删除或修改现有方法签名；
- 如需破坏性变更，必须发布新方法（如 `getCurrentUserContextV2`），保留旧方法至少一个版本；
- 本模块调用的 Api 版本以 `pom.xml` 中的依赖版本为准。

### 8.2 DTO 兼容性

- 新增字段不影响旧客户端（Jackson 默认忽略未知字段）；
- 删除字段需评估影响面；
- 字段类型变更是破坏性变更，需升级主版本。

## 9. 性能与 SLA

### 9.1 对上游 Api 的性能要求

| Api | 响应时间要求 | 降级策略 |
|:---|:---:|:---|
| CurrentUserApi.* | < 10ms（本地缓存） | 无法降级，失败 = 拒绝请求 |
| MetricApi.getEmpMetricValues | < 100ms | 超时返回 NULL 值 |
| MetricApi.batchGet* | < 500ms（100 对象 × 20 指标） | 超时分批重试 |
| KpiApi.* | < 200ms | 超时返回 NULL |
| CustomerQueryApi.listCustomers | < 300ms（50 个客户） | 超时返回部分结果 |
| AuditApi.log | < 50ms | 不降级，必须成功 |
| AuditApi.logAsync | < 10ms（入队） | 入队失败降级为同步 |
| FileApi.upload | < 5s（10MB 文件） | 失败重试 1 次 |

### 9.2 本模块对外 SLA

- 仪表盘查询 P95 < 500ms（命中缓存时 < 50ms）
- 动态查询 P95 < 2s
- SQL 探查 P99 < 35s（含等待 + 执行）
- 异步导出 P95 < 3min
