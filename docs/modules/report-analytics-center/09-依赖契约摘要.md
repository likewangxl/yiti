# 报表分析中心 — 依赖契约摘要

> 模块：report-analytics-center
> 规则：本文只列当前源码实际使用的跨模块公开 API 和数据边界；方法参数与 DTO 以提供方源码为准，冲突时以提供方契约为准。

## 1. 依赖总览

report-analytics-center 依赖 common、auth-permission-center、system-governance-center、customer-marketing-center 和 performance-engine-center。它是下游查询模块，当前没有面向其他模块的公共 API，也不应被其他业务模块作为查询中转层依赖。

跨模块调用只允许使用提供方 api 包中的公开接口和 DTO，不引用 mapper、entity、内部 service 或私有表。

## 2. auth-permission-center

| API | 用途 |
|---|---|
| CurrentUserApi | 当前用户、工号、机构、角色和管理员上下文 |
| BizScopeApi | REPORT、REPORT_DYN_EMP、REPORT_DYN_ORG 等报表数据范围 |
| OrgApi | 机构、机构树和机构名称查询 |
| UserApi | 员工候选、用户名称和用户信息查询 |
| OrgGroupApi | 大屏命名机构组及成员范围校验；读取有效经营画像并投影代码化大屏最小机构目录 |
| ResourceApi | 大屏配置所需的资源权限校验 |

报表的列表、详情、动态查询、导出、自由报表和大屏取数均以当前用户范围为准。范围为空、异常或无法确认时按 Fail Close 处理；前端传入的对象集合不能替代此校验。

代码化大屏的目录以服务端授权成员集合为准，画像 API 返回的额外机构不得加入目录，授权成员缺少有效画像时拒绝。机构组成员不自动递归展开全部下级支行；展示下级机构需要相应组配置和用户数据范围共同允许。坐标缺失、坐标系未确认或明确标注为演示的点位不绘制，机构仍保留在授权列表中。

## 3. system-governance-center

| API | 用途 |
|---|---|
| DictApi | 查询报表元数据和字典项 |
| AuditApi | SQL 探查、导出、大屏配置及发布等动作审计 |
| FileApi | 文件上传、绑定、下载地址、文件内容和文件名 |

FileApi 是报表文件和公告附件的对象访问边界。报表任务只保存文件标识或引用，不自行访问对象存储。高危配置和 SQL 操作需要服务层审计原因；AuditApi 或 FileApi 不可用时按对应 Service 的失败或 Fail Close 语义处理。

## 4. customer-marketing-center

| API | 用途 |
|---|---|
| CustomerQueryApi | 客户搜索、客户池和客户指标查询所需的客户信息 |
| TouchTaskQueryApi | 触达任务机构汇总 |

上述调用只读。客户和触达状态由 customer-marketing-center 维护，report 只按查询参数和数据范围展示或登记导出任务。

## 5. performance-engine-center

| API | 用途 |
|---|---|
| MetricApi | 指标定义、指标值、当前日期和指标元数据 |
| MetricQueryApi | 动态查询所需的员工、机构或客户指标快照 |
| KpiApi | KPI 方案和绩效汇总查询 |
| AllocApi | 当前/历史分配及原业绩分配预览 |

指标、KPI 和分配结果由 performance-engine-center 计算和维护。report 不复制其计算逻辑，不写入其业务表；分配调整历史查询使用当前明确登记的只读表例外，不扩大为跨模块写入。

## 6. 接口与数据范围要求

1. 使用公开 API 时传递当前请求所需的维度、对象、日期和范围上下文，不在 report 侧拼接提供方私有 SQL。
2. 上游 API 返回空数据、错误或超时的处理以具体 Service 实现为准；不能把部分数据包装成全量成功。
3. report 自有表的事务不能跨越上游写操作；本模块没有审批写入口。
4. 新增 Controller、DTO、鉴权或资源时，必须同步提供方契约、PT_RESOURCE 和模块接口文档。
5. 提供方接口名称、DTO 字段和资源编码可能随源码调整，本文不维护重复的完整方法签名或数量清单。
