# 报表分析中心 — 功能规格

> 模块：report-analytics-center
> 定位：报表、分析和受控查询支撑域
> 口径：本文只描述当前源码提供的能力；接口细节以同目录接口文档和源码为准。

## 1. 职责边界

报表分析中心读取上游业务数据，维护自身的查询、导出、自由报表和大屏配置。它不写入客户、触达、绩效、审批等上游业务状态，也不作为其他业务模块的查询中转层。

### 当前职责

- 动态查询：按员工、机构或客户维度选择对象和指标，应用报表数据范围后返回结果。
- 固定报表：提供行长、机构、员工仪表盘，以及触达汇总、绩效汇总、客户池汇总。
- 历史与业务查询：提供 AMAS 审批、分配调整、数据导入、公告和业绩分配预览等只读查询。
- 查询方案：用户保存、读取、更新和删除自己的动态查询方案。
- 受控 SQL 探查：在独立只读数据源上执行受限查询，记录历史并支持受控导出。
- 导出：动态查询、触达、绩效和客户池汇总登记导出任务；提供任务查询、取消和下载入口。
- 自由报表：导入 Excel，维护批次和行数据，并按数据范围提供查询及下载。
- 大屏：维护屏元数据、数据源、画布、角色白名单、地图点位和发布归档，提供发布态或草稿态渲染包。

### 不负责的事项

- 不承担上游业务数据的新增、修改、审批或计算。
- 不直接调用 workflow-center 处理报表查询。
- 不提供面向其他模块的 report 公共 API；跨模块读取应使用上游模块的公开查询 API。
- 不把缓存或导出任务表当作上游业务事实来源。

## 2. 功能规格

### 2.1 动态查询与方案

查询维度为 EMP、ORG、CUST。指标元数据来自 performance-engine-center，员工、机构和客户对象分别通过对应公开查询 API 获取。查询和导出均按当前用户的 REPORT 数据范围校验，不能仅依赖前端隐藏对象。

方案是用户私有数据。列表和详情只能读取本人方案；更新使用版本字段做乐观并发控制；删除只影响本人方案。

### 2.2 固定报表与历史查询

- Dashboard 提供 president、org、emp 三种视角。
- 触达、绩效和客户池汇总提供分页查询，并分别提供导出提交入口。
- AMAS 价格审批、业绩调整审批、分配调整申请、数据导入、公告和分配预览均为只读查询。
- 数据湖实体只作为当前查询实现的只读数据源；没有 REST 入口的内部查询不写成外部契约。

### 2.3 导出与文件

导出任务保存操作人、参数、类型和状态。任务查询、取消和下载先校验操作人归属；只有成功且存在文件引用的任务允许下载。文件由 system-governance-center 的 FileApi 管理，报表模块不自行实现对象存储。

动态查询的 export-file 入口直接返回 Excel 文件流；动态查询、触达、绩效和客户池的任务提交入口返回任务标识和当前状态。不要把提交任务等同于文件已经生成，实际状态以任务记录为准。

### 2.4 SQL 探查

SQL 探查只接收只读查询，使用配置的表白名单、禁用关键字、长度和嵌套深度校验，并通过只读数据源执行。执行历史按本人可见，包含状态、耗时和行数等结果信息；查询失败、超时和并发受限都更新终态并记录审计。

SQL 导出单独登记任务并在线程池中执行，生成文件后通过 FileApi 上传和绑定；任务和文件下载都做本人归属校验。

### 2.5 自由报表

操作人导入 Excel 后形成批次、列定义和行数据。相同报表名称再次导入时，在同一事务内替换该操作人的旧批次数据，不删除共享文件对象。列表、列定义、数据查询、原始文件下载和过滤后文件下载均遵守批次状态及 REPORT 数据范围；禁用批次对非操作人不可见，启用、删除仅限操作人。

### 2.6 大屏

大屏由元数据、画布区块、数据源、地图点位、访问角色和发布归档组成。

- 创建大屏只建立元数据和空画布；画布通过独立保存入口维护。
- 画布保存写草稿，使用画布版本做乐观锁。
- 发布把已校验的组件、区块绑定和数据源快照合成为不可变渲染包，并写发布归档。
- 运行时默认读取发布包；带草稿预览参数时只允许具备管理权限的用户读取草稿。
- 数据源删除、已发布引用变更、屏访问角色覆盖等操作必须经过服务层的引用、范围和权限校验。
- 运行时取数再次校验屏范围、角色白名单和 REPORT 数据范围；校验异常按 Fail Close 处理。

## 3. 统一安全要求

所有 REST 方法使用 REPORT 业务类型和对应 BizAction，并登记匹配的 PT_RESOURCE。列表、详情、导出和大屏运行时均应用服务层数据范围。SQL 执行、SQL 导出、大屏数据源试跑/列探测、发布、回滚、访问角色变更和删除等敏感动作使用独立授权与审计；日志中的 SQL、账号、文件和业务敏感字段按统一脱敏规则处理。
