# 报表分析中心 — 功能规格

> **模块编号**: report-analytics-center
> **模块类型**: 支撑域模块（Supporting Domain）
> **模块定位**: 纯只读的数据查询/分析中心
> **版本**: V1.0
> **最后更新**: 2026-04-10

---

## 1. 模块概述

### 1.1 模块定位
**报表分析中心（report-analytics-center）** 是银行省分行一体化营销与绩效管理平台的**纯只读支撑域模块**，为全平台提供统一的数据查询、报表展示、SQL探查能力。

### 1.2 核心职责
| 职责 | 说明 |
|------|------|
| 动态指标查询 | 按维度（人员/机构/客户）自由组合指标的自助查询 |
| 固定管理报表 | 预置分行行长仪表盘等固定模板报表 |
| SQL探查 | 面向科技部特定角色的受限 SQL 查询工具 |
| 查询方案管理 | 用户个人查询方案的保存与快速调用 |
| 异步导出 | 大数据量报表的异步导出任务 |
| 快照任务（V1 可选） | 支持将常用查询结果做快照落地 |

### 1.3 业务价值
- 为分行行长、经营机构负责人、客户经理、中后台资财等角色提供统一的数据视图
- 降低数据分析对业务模块的直接压力
- 为科技部提供受控的 SQL 探查通道，避免直连生产库
- 支撑绩效计算结果、客户池数据、触达任务完成情况的多维分析

### 1.4 非目标（明确不做的事）
- **不承担业务数据写入**：所有写操作交由业务模块
- **不承担审批流转**：由 workflow-center 处理
- **不作为业务查询中转站**：其他模块不能借道 report 查询另一个模块的数据
- **不做实时聚合计算**：聚合由 performance-engine-center 完成，report 只读取 sys_control 的有效版本

## 2. 核心只读约束（架构红线）

### 2.1 只读原则
1. **报表模块不反向写业务数据**
   - 报表模块不持有任何业务状态
   - 报表模块的所有 Service 方法必须是只读的（无副作用）
   - 例外：仅允许写入本模块的两张表（`rpt_saved_query`、`sql_probe_history`）

2. **报表模块不承担审批流转**
   - 报表结果的审批/签发（如月度报表签批）应由 workflow-center 承接
   - 报表只提供"生成数据"的能力

3. **报表模块不作为业务查询中转站**
   - 禁止出现"workflow 调 report 查客户信息"这种反模式
   - 如果 A 模块需要 B 模块的数据，必须直接调用 B 模块的 `*QueryApi`

### 2.2 依赖方向约束
```
允许：report → customer / performance / governance / auth  （单向调用）
禁止：customer / performance / workflow / portal → report  （反向依赖）
```

**违反此约束视为架构违规，Code Review 必须拒绝。**

### 2.3 数据来源规则
- **允许**：调用 `customer-marketing-center` 的 `CustomerQueryApi`
- **允许**：调用 `performance-engine-center` 的 `PerformanceQueryApi`、`MetricQueryApi`、`SysControlQueryApi`
- **允许**：调用 `system-governance-center` 的 `DictQueryApi`、`AuditQueryApi`
- **允许**：调用 `auth-permission-center` 的 `OrgQueryApi`、`DataScopeApi`、`PermissionQueryApi`
- **禁止**：直接通过 MyBatis Mapper 查询其他模块的私有表（如 `cust_*`、`perf_*`、`wf_*`）
- **禁止**：在 report 模块定义其他模块的 Entity 类

## 3. 动态指标查询（对应 project_ana 4.5.1）

### 3.1 交互流程
1. **选维度**：用户进入"动态指标查询"页面，左侧显示树形导航
   - 维度分类：`EMP`（人员）/ `ORG`（机构）/ `CUST`（客户）
2. **选指标**：从该维度下的可用指标库中勾选多个指标
   - 指标库来自 `performance-engine-center.MetricQueryApi.listMetricsByDim(dim)`
   - 指标支持分组（如"存款类指标"、"贷款类指标"、"中收类指标"）
3. **选对象**：从该维度下选择多个具体对象
   - 人员维度：从 `auth-permission-center.EmpQueryApi` 获取，受数据范围约束
   - 机构维度：从 `auth-permission-center.OrgQueryApi` 获取机构树
   - 客户维度：从 `customer-marketing-center.CustomerQueryApi` 获取
4. **选数据日期**：单选一个数据日期
   - 必须是 `sys_control` 表中有效版本对应的日期
   - 非有效日期不允许选择
5. **执行查询**：点击"查询"按钮执行
6. **结果展示**：
   - 默认以表格展示（行=对象，列=指标）
   - 支持切换为柱状图、折线图、饼图
   - 支持列排序、列筛选
7. **保存方案**：可将当前查询配置保存为方案

### 3.2 查询方案保存（PT-表：`rpt_saved_query`）
- **保存内容**：指标组合、维度、对象列表、方案名
- **不保存的内容**：数据日期（每次查询时重新选择）
- **数量限制**：每用户最多保存 10 条，超出则系统自动删除最旧的一条
- **方案归属**：方案属于创建者个人，不支持跨用户共享
- **一键重载**：点击保存的方案后，自动回填维度/对象/指标，用户只需选择日期即可查询

### 3.3 查询约束
| 约束项 | 值 |
|--------|---|
| 单次查询最多对象数 | 100 个 |
| 单次查询最多指标数 | 20 个 |
| 结果最大行数 | 500 行（超出需用异步导出） |
| 查询超时 | 15 秒 |
| 默认数据日期 | 最近一个有效版本的日期 |

### 3.4 数据范围过滤
动态查询的对象列表受 `DATA_SCOPE` 约束：
- `SELF`：只能查自己（客户经理场景）
- `ORG_SUBTREE`：只能查本机构及下级机构的对象（经营机构负责人）
- `ALL`：全行（分行行长、中后台资财）

## 4. 固定管理报表（对应 project_ana 4.5.2）

### 4.1 分行行长仪表盘
#### 4.1.1 权限约束
- **访问角色**：仅"分行行长"角色可访问
- **数据范围**：`ALL`（全行）
- **URL**：`/api/reports/dashboard/president`
- **权限控制**：`@BizAuth(bizType=REPORT, action=READ)` + 角色白名单校验

#### 4.1.2 仪表盘内容
| 区块 | 内容 | 数据来源 |
|------|------|----------|
| 全行存款趋势 | 近 12 个月存款余额折线图 | `perf_kpi_snapshot` (sys_control 有效版本) |
| 全行贷款趋势 | 近 12 个月贷款余额折线图 | `perf_kpi_snapshot` (sys_control 有效版本) |
| 机构业绩排名 | 各主要机构业绩达成率排名（前 20） | `perf_org_summary` |
| 十大客户贡献度 | 按综合贡献度排序的 Top10 客户 | `customer-marketing-center.CustomerQueryApi` + `perf_customer_contribution` |
| 核心汇总指标 | 总存款、总贷款、中收、AUM 等关键指标 | `perf_kpi_snapshot` |

#### 4.1.3 数据刷新机制
- 数据源：`sys_control` 最新有效版本
- 刷新时机：`sys_control` 版本切换时清除缓存
- 事件订阅：`performance.sys-control.updated.v1`

### 4.2 其他预置报表
#### 4.2.1 触达任务监控报表
- **对应 project_ana 4.2.7**：跨机构汇总触达任务完成情况
- **权限**：分行行长、中后台资财可访问
- **数据来源**：调用 `customer-marketing-center.TouchTaskQueryApi.summary()`
- **报表内容**：
  - 按机构统计触达任务创建数、完成数、完成率
  - 按任务类型统计
  - 按时间段（近 7 天 / 近 30 天）统计

#### 4.2.2 绩效汇总报表
- **权限**：分行行长、中后台资财可访问
- **数据来源**：调用 `performance-engine-center.PerformanceQueryApi.summary()`
- **报表内容**：
  - 按机构/团队汇总绩效达成情况
  - 指标达标率分布
  - 环比/同比变化

#### 4.2.3 客户池统计报表
- **权限**：各级有数据范围的用户可访问（受 DATA_SCOPE 约束）
- **数据来源**：调用 `customer-marketing-center.CustomerQueryApi.poolSummary()`
- **报表内容**：
  - 客户池内客户数
  - 客户分层分布（VIP / 普通 / 潜在）
  - 新增/流失趋势

## 5. 数据探查框（对应 project_ana 4.5.3）

### 5.1 权限约束
- **使用角色**：仅"科技部数据探查员"角色可访问
- **权限标识**：`SYS_CONFIG + EXECUTE_SQL`
- **角色分配**：由系统管理员单独授权，不在默认角色列表中

### 5.2 SQL 执行限制（V1 必须实现）
| 限制项 | 值 | 说明 |
|--------|---|------|
| 允许语句类型 | 仅 `SELECT` | 禁止 INSERT/UPDATE/DELETE/DDL |
| 强制 LIMIT | 最大 1000 行 | 用户未加 LIMIT 时系统自动追加 |
| Schema 白名单 | 见配置 `sql.probe.schema-whitelist` | 默认仅允许 `rpt_*`、`perf_*` 只读视图 |
| 禁用关键字 | DROP, DELETE, UPDATE, INSERT, TRUNCATE, ALTER, CREATE, GRANT, REVOKE, CALL, EXEC | 使用 JSqlParser 解析校验 |
| 单次查询超时 | 30 秒 | 由 `statement.setQueryTimeout` 控制 |
| 并发数上限 | 10 | 由 Semaphore 控制 |
| SQL 最大长度 | 5000 字符 | 前端 + 后端双重校验 |

### 5.3 审计要求（PT-表：`sql_probe_history`）
每次 SQL 执行（不论成功或失败）必须记录：
| 字段 | 说明 |
|------|------|
| `id` | 主键 |
| `emp_id` | 执行人 |
| `sql_text` | 完整的 SQL 文本（脱敏后） |
| `remark` | 执行原因（必填，即 reason） |
| `execution_time_ms` | 执行耗时（毫秒） |
| `row_count` | 返回行数 |
| `error_msg` | 错误信息（失败时） |
| `created_time` | 执行时间 |

### 5.4 高危动作标识
SQL 探查属于 `EXECUTE_SQL` 高危动作：
- 必须独立 URL：`/api/reports/sql-probe/execute`
- 必须单独授权：角色白名单 + `@BizAuth` + 数据范围
- 必须单独审计：审计日志写入 `sys_audit_log`，`reason` 必填
- 日志告警：慢查询（>5s）和错误 SQL 需触发 `system-governance-center` 的告警

## 6. 跨模块调用点标注

### 6.1 被调用模块清单
| 被调模块 | 调用的 Api | 用途 |
|----------|-----------|------|
| `customer-marketing-center` | `CustomerQueryApi` | 客户基本信息查询 |
| `customer-marketing-center` | `TouchTaskQueryApi` | 触达任务统计 |
| `performance-engine-center` | `MetricQueryApi` | 指标定义、指标树 |
| `performance-engine-center` | `PerformanceQueryApi` | 指标计算结果 |
| `performance-engine-center` | `SysControlQueryApi` | 有效数据版本查询 |
| `system-governance-center` | `DictQueryApi` | 字典查询（维度、指标分类） |
| `system-governance-center` | `AuditApi` | 审计日志写入 |
| `auth-permission-center` | `EmpQueryApi` | 员工信息 |
| `auth-permission-center` | `OrgQueryApi` | 机构树 |
| `auth-permission-center` | `DataScopeApi` | 数据范围计算 |
| `auth-permission-center` | `PermissionQueryApi` | 权限校验 |

### 6.2 调用规范
- 所有跨模块调用必须通过 `*Api` / `*QueryApi` 接口
- 禁止使用 `@Autowired` 注入其他模块的 `Mapper` 或 `Entity`
- 调用失败时采用 Fail-Close 策略：降级为空结果 + 错误提示

## 7. 性能约束

### 7.1 查询性能要求
| 接口类型 | 响应时间要求 | 备注 |
|----------|-------------|------|
| 动态指标查询 | < 2 秒 | 500 行内 |
| 仪表盘查询 | < 1 秒 | 使用缓存 |
| 查询方案 CRUD | < 200 ms | |
| SQL 探查 | < 30 秒 | 硬超时 |
| 异步导出启动 | < 500 ms | 只返回 taskId |

### 7.2 数据量限制
| 项 | 限制 |
|----|------|
| 动态查询结果最大行数 | 500 行 |
| 同步导出最大行数 | 5000 行 |
| 异步导出最大行数 | 100000 行 |
| 报表时间范围 | 最多 1 年 |
| 单次查询对象数 | 100 个 |
| 单次查询指标数 | 20 个 |

### 7.3 缓存策略
| 缓存对象 | Key | TTL | 失效条件 |
|----------|-----|-----|---------|
| 仪表盘数据 | `report:dashboard:president:{dataVersion}` | 30 分钟 | sys_control 版本切换事件 |
| 指标树 | `report:metric-tree:{dim}` | 1 小时 | 指标定义变更事件 |
| 有效数据版本 | `report:valid-data-version` | 5 分钟 | sys_control 更新事件 |

### 7.4 数据来源优先级
1. **优先使用 `sys_control` 有效版本**：不做实时聚合
2. **有效版本不可用时**：返回错误 `RPT-40004`（数据版本不可用）
3. **不查询未进入有效版本的数据**：避免读到中间态

## 8. 权限矩阵（BizType = REPORT）

| 角色 | BizType | DataScope | 允许的 Action | 说明 |
|------|---------|-----------|--------------|------|
| 分行行长 | REPORT | ALL | READ, LIST, EXPORT | 全行数据 |
| 经营机构负责人 | REPORT | ORG_SUBTREE | READ, LIST, EXPORT | 本机构及下级 |
| 客户经理 | REPORT | SELF | READ, LIST | 个人指标查询 |
| 中后台员工（资财） | REPORT | ALL | READ, LIST, EXPORT | 全行数据 |
| 科技部数据探查员 | SYS_CONFIG | - | EXECUTE_SQL | 仅 SQL 探查权限 |

### 8.1 特殊规则
- 分行行长仪表盘额外校验角色，非分行行长即使有 REPORT + ALL 权限也不能访问
- SQL 探查不使用 REPORT BizType，而是使用 SYS_CONFIG + EXECUTE_SQL

**无**。报表模块不发布任何领域事件。

## 10. 异常处理

### 10.1 Fail-Close 策略
- 权限缓存失效时：拒绝访问，返回 `RPT-40301`
- 跨模块调用失败时：返回空结果 + 错误提示，不抛出异常到前端
- `sys_control` 版本不可用时：返回 `RPT-40004`

### 10.2 用户友好错误
所有错误码必须配置对应的中文提示，前端直接展示给用户。
