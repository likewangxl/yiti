# 个人经营驾驶舱

个人入口为 `/#/personal-dashboard`；工作台、大屏中心继续使用该入口。页面保留个人核心指标，删除待办、客户清单和业务进度。主体为左侧趋势图、右侧个人占机构比例、底部指标目标完成情况。

## 展示口径

- 默认展示全部指标的多色折线。全部模式使用 `(观测值 - 期内首个有效值) / abs(期内首个有效值) × 100%`，便于比较不同单位的指标。基期为零或缺失时不计算增长率。
- 点击顶部指标卡切换该指标的实际值曲线，保留颜色；“显示全部指标”恢复多指标视图。
- 范围为近7日、近6月、近一年，管理端可设置默认范围。近7日包含今天及前6天；近6月、近一年分别包含当前月及前5、11个月，按每月最后一条观测展示。缺失日/月保持缺口，不插值、不伪造历史值。
- 机构占比为个人当前值除以机构值；单位与数据日期必须一致，机构值必须大于零。目标完成情况同样要求目标和当前值单位、日期一致；目标大于零才计算，超额比例如120%原样显示，进度条最多填满。
- 未配置、来源无权限、错误批次、无效日期、重复日期或单位不匹配时保留缺口。最新日期的空值不回退旧日期冒充最新值。

## 管理步骤

1. 进入“大屏管理 → 个人经营驾驶舱”，或 `/#/screen-admin/designer?tab=personal`。
2. 首次使用可创建专属配置：固定屏编码 `PERSONAL_COCKPIT`，`viewLevel=PERSON`，条线 `COMMON`，范围模式 `LEGACY_CONTEXT`。不会自动改动已有经营屏。
3. 设置页面与各区域标题、默认日期范围；添加/删除/排序指标，配置编码、名称、显示单位和颜色。
4. 每项指标分别配置当前值、历史趋势、机构对比、目标值的数据源、值字段、日期字段及单位。未接入的来源可保持未绑定。可选输出列从现有数据源目录取得。
5. 当前值、趋势和目标使用员工主体来源；机构对比使用机构主体来源。只接受共用条线、主体范围的受控 `WIDE_TABLE`、`KPI_RESULT`、`KPI_DETAIL`，不接受跨主体聚合或自定义SQL。历史来源须支持时序。单位需由配置人员核实，前端不猜测金额量级，也不自动将百分比转换为比例。
6. 保存草稿后独立回读内容及版本。再进入预览核对真实数据；预览页明确标记“尚未发布”。新建屏通过“查看角色设置”维护角色白名单，使用已有独立权限变更接口及审计原因；管理员也必须满足屏级白名单和数据范围。
7. 有发布权限的人员填写原因、确认发布。普通修改未保存时禁止发布；版本冲突保留当前编辑，需重新读取后再处理。

机构角色授权和数据源连接不由前端模拟。来源目录、草稿读取失败时禁止创建/覆盖未知配置。新建、保存、角色变更、发布均须依照环境的数据库操作门禁执行。

## 存储与接口复用

不新增表、SQL或REST端点。复用现有屏元数据、画布保存/发布、角色白名单和取数接口。

- 标准 `TextLabel` 节点 `personal-cockpit-settings` 的 `propValue.personalDashboard` 保存版本1的展示设置及指标绑定声明。
- 每个有效绑定对应一个标准 `ChartWidget / TABLE_LIST` 节点，使用稳定节点ID并保留原 `blockId`。字段映射为 `bindJson.fieldMap.{value,date}`。删除指标时只删除个人专属节点，保留无关素材。
- 通用画布协议版本由服务端决定。发布态v1从可信 `bindSnapshots` 读取 `dsId`；v2按 `screenCode + blockId` 取数；草稿按服务端确认的 `previewState=draft + blockId` 取数。拒绝损坏包、身份不匹配和缺失快照。
- `/screen/data` 返回 `columns: string[]` 和二维 `rows`。历史请求使用现有 `period=RANGE` 加 `dateFrom/dateTo`，其它来源使用 `LATEST`。员工、机构上下文只来自新读取的 `/auth/current-user`，不接受URL覆盖。
- 仅屏不存在（`RPT-43004`）或服务端确认尚未发布时保留工作台顶部快照，并提示配置缺失。401、403、坏包或一般网络错误不得触发此回退。

实现入口：`xanzc_frontend/src/views/screen/personal/`、`xanzc_frontend/src/api/personalCockpit.js`。后台权限、审计、版本锁和统一数据范围仍由原有服务承担。

## 验证边界

单元测试覆盖真实二维响应、双协议快照、日期范围、单位/日期一致性、身份失效、配置保存回读和权限失败关闭。浏览器使用官方 `playwright-cli` 验证图表切换、管理回显、草稿及发布视图；开发态模拟数据仅验证交互和契约，不能作为真实数据接入或实际发布成功的证明。
