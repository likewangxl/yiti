# 大屏数据配置改造计划

## 目标与边界

业务人员独立选择业务指标、周期和展示方式，技术人员维护底层接入及指标口径。基于当前已有受控数据源、屏级权限、草稿 CAS 与运行时查询建设；不新增数据库结构、不扩大权限、不修改上游业务数据、不自动发布或重写现有发布包。业务目录是已有授权定义的业务视图，不是新增物理连接管理器；范围由当前屏决定，用户不能借表单扩大机构范围。

2026-10-15：组件配置不再使用“选择数值指标”列表。当前入口改为从绩效指标定义选择指标，并按结果表生成或复用宽表数据源。下面阶段 B 记录的是改造前的候选列表方案。

## 阶段与验收

### A：技术数据源维护安全

- 先写稳定失败测试，再实现六类来源的类型化回填/保存、后端允许的命名组组合、策略保留与编辑。
- 未知来源、未知配置版本、无法解析配置必须阻止保存，不能回退空配置覆盖原定义。
- 清理跨数据源列候选；增加名称/类型/状态筛选；当前表单可调用原有高危试跑接口，但必须沿用独立权限和审计原因。
- M98 仅固定 profile/SUMMARY；FREE_REPORT 仅现有 TEST_BRANCH 批次；不得增加任意表、SQL、批次替代能力。
- 验收：六类往返、扩展字段与策略保留、非法配置拒绝、试跑不自动保存、单位与范围门禁。

### B：业务指标选择与组件配置

- 从当前屏允许的现有数据源及显式字段元数据构建可搜索业务候选，展示指标名、来源说明、原始单位、能力和不可选原因。
- 普通模式选择业务指标，只有来源/语义/单位可证明时才预填；不凭中文名称猜单位，不把多个来源拼成同一指标。
- 高级字段配置保留，展示单位与原始单位分离；未知口径或单位须明确由技术人员维护，不伪装可用。
- 不改变后端授权边界；业务人员仍须获准使用现有屏配置读取/保存资源，不授予 SQL 执行或数据源写权限。
- 验收：搜索、合法候选/禁用说明、来源与字段联动、已有绑定保留、清空/切屏/权限失败不污染状态。

### C：数据核验与发布稳定性

- 在组件页接回已保存草稿核验：未保存编辑不得被当作已核验；核验只读，不保存、不发布。
- 展示返回日期、行数、零值/缺失、机构覆盖及服务端质量状态；结构通过不等于口径正确。失败或范围不明保持 fail-close。
- 所有新发布 CODE 大屏均写入不可变 sourceDefinition；后续数据源编辑不改变新发布包查询语义。停用/实时授权仍由当前配置控制。
- 旧发布包保持兼容，明确需经用户核对后重新发布；不自动修改旧包。
- 验收：过期、部分覆盖、无质量、错误、竞态、保存后核验；对公/零售/分行发布定义快照与查询兼容。

### D：集成验证与交付

- 主代理审查真实 diff，独立运行相关测试与前端构建；后端变更只运行确认不连接真库的单元测试，必要时刷新本地依赖。
- 官方 playwright-cli 验证真实页面并归档命令、route-list、console、请求/响应摘要和截图；开发态 mock 必须列出完整路由并标注非联调。
- 当前内置浏览器访问曾被工具安全策略拒绝：不得通过其他浏览器或 CLI 绕过该拒绝。在限制解除前完成独立代码验证，浏览器验收保持待完成，不宣称验收通过。
- 新旧运行 JAR 分开记录；代码改造不等于运行后端已更新。任何现有配置保存/发布和数据库操作均遵守原有门禁。
- 聚焦提交只包含本次文件/差量，保留任务开始已有布局、趋势及文档改动；未通过适用验收不标记完成。

## 非本次自动实施内容

物理跨库/API 接入、生产角色授权、旧屏重新发布、数据采集调度恢复、缺失历史补录。必要时提出可审核方案；不通过降低质量阈值或伪造数据消除告警。
