# 报表分析中心 — 初始化与配置要求

> 模块：report-analytics-center
> 说明：本文只记录当前启动和运行所需的依赖、配置和授权要求，不提供一次性 SQL、种子脚本或未验证能力清单。数据库结构由目标库 schema 和 DBA 流程管理。

## 1. 模块依赖

启动 report-analytics-center 前应具备：

- common-web、common-security、common-trace、common-aop、common-db；
- auth-permission-center 的当前用户、组织、用户、数据范围、资源和机构组公开 API；
- system-governance-center 的字典、审计和 FileApi；
- customer-marketing-center 的客户和触达任务查询 API；
- performance-engine-center 的指标、指标快照、KPI 和分配预览查询 API；
- 主数据源、SQL 探查专用只读数据源和 MyBatis 配置。

依赖以 report-analytics-center/pom.xml 及实际 api 包为准。不得通过初始化脚本创建跨模块私有表或授权 report 访问上游内部实现。

## 2. 数据库和文件能力

- report 自有表必须已经按目标 schema 建立：保存方案、探查/导出任务、自由报表、大屏配置和发布日志。
- SQL_PROBE_HISTORY 和 SQL_PROBE_EXPORT_TASK 需要可写；SQL 探查查询连接必须使用独立只读数据源。
- 报表文件、自由报表原始文件、SQL 导出文件和公告附件使用 governance FileApi；FileApi 的对象、下载和绑定能力必须可用。
- 上游业务表、数据湖表和 PERF_ALLOC_ADJUST 查询例外只读；report 不通过启动初始化写入这些表。
- 不在本模块维护数据库迁移文件、可执行 DDL 或固定种子数据。

## 3. 运行时配置

### 3.1 SQL 探查

以下配置由当前安全校验和探查服务读取：

- rpt.sql.probe.whitelist-tables
- rpt.sql.probe.forbidden-keywords
- rpt.sql.probe.max-rows
- rpt.sql.probe.max-sql-length
- rpt.sql.probe.max-subquery-depth
- rpt.datasource.read-only.url
- rpt.datasource.read-only.username
- rpt.datasource.read-only.password
- rpt.datasource.read-only.driver-class-name
- rpt.datasource.read-only.max-active
- rpt.datasource.read-only.min-idle
- rpt.datasource.read-only.query-timeout

表白名单和禁用关键字必须与 SQL 安全策略一致；只读账号不得具备写权限。具体值按部署环境配置，不能从本文复制到生产。

### 3.2 大屏取数

当前大屏查询引擎读取：

- rpt.screen.whitelist-tables
- rpt.screen.forbidden-keywords
- rpt.screen.max-rows

大屏 SQL 必须经过白名单、禁用关键字、模板参数、业务条线和数据范围校验。未在白名单内或无法证明安全的表、字段和绑定拒绝执行。

### 3.3 线程池和缓存

- sqlProbeExportExecutor 必须可创建并用于 SQL 导出后台执行；拒绝或执行异常要能落任务失败状态。
- rptCacheManager 使用当前 report 的 Caffeine 配置作为默认 CacheManager，供仪表盘、汇总和元数据查询加速。
- 缓存不是权限、任务、发布包或业务数据初始化来源；不得用缓存配置替代数据库和权限配置。

## 4. 权限和审计

- 每个 report Controller 方法都要有 REPORT BizAction，并在 PT_RESOURCE 登记相同 URL、方法和动作。
- SQL 执行与导出、数据源试跑和列探测、大屏发布与回滚、屏角色白名单、删除等高风险资源必须独立授权，且服务层要求审计原因。
- 屏运行时除了 REPORT 权限，还要校验屏级角色白名单、机构组、业务条线和数据范围；不能配置管理员旁路。
- AuditApi、CurrentUserApi 和 BizScopeApi 不可用时，涉及身份、范围或高危写入的操作按当前 Service 的 Fail Close 语义处理。
- 初始化授权只登记当前 Controller 实际使用的资源，不复制历史资源名、一次性脚本路径或未经源码确认的角色数量。

## 5. 验收

部署后应按实际环境检查：主数据源可读写自有表、探查数据源为只读、FileApi 可上传/绑定/下载、AuditApi 可记录高危动作、PT_RESOURCE 与 Controller 对齐、屏范围和 REPORT 数据范围生效。任何未验证的配置不写成已完成能力。
