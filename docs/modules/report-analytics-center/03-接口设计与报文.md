## 通用说明

### 请求头
| 请求头 | 必填 | 说明 |
|--------|------|------|
| `Authorization` | 是 | Bearer Token |
| `X-Trace-Id` | 否 | 全链路 TraceID（未提供时由网关生成） |
| `Content-Type` | 是 | application/json |

### 统一响应结构
```json
{
  "code": 0,
  "msg": "success",
  "data": { ... },
  "traceId": "abcd-1234"
}
```

### 错误响应示例

所有错误统一使用 `CommonResult<Void>` 包装，`code` 字段为 HTTP 状态码同值（非零），`errorCode` 字段为模块前缀错误码（参见 `docs/common-dev-guide.md §2`）。以下是本模块的典型错误响应场景：

#### 场景 1：资源不存在（404 类）
```json
{
  "code": 40001,
  "msg": "查询方案不存在",
  "errorCode": "RPT-40001",
  "data": null,
  "traceId": "abcd-1234"
}
```

```json
{
  "code": 40302,
  "msg": "无权使用 SQL 探查功能，仅限 R_BACK_TECH 角色",
```

### 错误响应字段说明

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|---|---|
| `code` | Integer | 是 | HTTP 状态码同值数字（如 40001、40302、42200、50001） |
| `msg` | String | 是 | 用户可见的错误消息（中文，可直接展示给前端） |
| `errorCode` | String | 是 | 模块前缀错误码，格式 `RPT-{HTTP}{SEQ}`（参见 §完整错误码清单） |
| `data` | Object \| null | 否 | 业务相关的错误上下文，**422 类通常包含 fieldErrors 数组** |
| `traceId` | String | 是 | 全链路追踪 ID，用户报错时可据此查日志 |

### 错误码命名规则

| HTTP 段 | 含义 | 本模块典型使用 |
|---|---|---|
| 40001-40099 | 资源不存在 / 业务状态错误 | `RPT-40001` 查询方案不存在、`RPT-40004` 数据版本不可用 |
| 40301-40399 | 授权失败 | `RPT-40302` SQL 探查权限不足、`RPT-40305` 数据范围越权 |
| 42200-42299 | 参数校验失败 / 业务规则冲突 | `RPT-42200` 字段校验、`RPT-42001`~`RPT-42008` SQL 探查各类失败、`RPT-42207` 导出超限 |
| 50001-50099 | 系统内部错误 | `RPT-50001` 系统错误、`RPT-50002` 导出文件生成失败 |

## A. 动态指标查询

### A.1 GET /api/reports/query-dimensions — 获取可查询维度与指标树

**用途**：前端进入动态查询页面时，获取当前维度下可用的指标树。

**权限**：`@BizAuth(bizType = REPORT, action = READ)`

**请求参数（Query）**：
| 字段 | 类型 | 必填 | 校验 | 说明 |
|------|------|------|------|------|
| `dim` | String | 是 | EMP/ORG/CUST | 维度 |

**响应 DTO：`QueryDimensionRespDTO`**
| 字段 | 类型 | 说明 |
|------|------|------|
| `dim` | String | 维度 |
| `dimName` | String | 维度中文名 |
| `metrics` | List\<MetricTreeNodeDTO\> | 可用指标树（嵌套结构） |

**`MetricTreeNodeDTO`**（树节点）
| 字段 | 类型 | 说明 |
|------|------|------|
| `groupCode` | String | 分组编码（叶子节点为空） |
| `groupName` | String | 分组名称 |
| `metricCode` | String | 指标编码（叶子节点必填） |
| `metricName` | String | 指标名称 |
| `unit` | String | 单位（如"万元"、"%"） |
| `description` | String | 指标说明 |
| `children` | List\<MetricTreeNodeDTO\> | 子节点 |

**示例请求**：
```
GET /api/reports/query-dimensions?dim=EMP
```

**示例响应**：

### A.2 POST /api/reports/dynamic-query — 执行动态查询

**用途**：执行动态指标查询，返回表格数据。

**权限**：`@BizAuth(bizType = REPORT, action = LIST)`

**请求体 DTO：`DynamicQueryReqDTO`**
| 字段 | 类型 | 必填 | 校验 | 说明 |
|------|------|------|------|------|
| `dim` | String | 是 | `@NotBlank` `@Pattern(EMP/ORG/CUST)` | 维度 |
| `subjectIds` | List\<String\> | 是 | `@NotEmpty` `@Size(max=100)` | 对象 ID 列表 |
| `metricCodes` | List\<String\> | 是 | `@NotEmpty` `@Size(max=20)` | 指标编码列表 |
| `dataDate` | LocalDate | 是 | `@NotNull` | 数据日期（单选） |

**响应 DTO：`DynamicQueryRespDTO`**
| 字段 | 类型 | 说明 |
|------|------|------|
| `dim` | String | 维度 |
| `dataDate` | LocalDate | 数据日期 |
| `dataVersion` | String | sys_control 版本号 |
| `columns` | List\<MetricColumnDTO\> | 指标列定义 |
| `rows` | List\<Map\<String,Object\>\> | 数据行（key=metricCode 或 subject 字段） |
| `rowCount` | Integer | 行数 |
| `executionTimeMs` | Integer | 查询耗时 |

**`MetricColumnDTO`**
| 字段 | 类型 | 说明 |
|------|------|------|
| `metricCode` | String | 指标编码 |
| `metricName` | String | 指标名称 |
| `unit` | String | 单位 |
| `dataType` | String | 数据类型：NUMBER/PERCENT/CURRENCY |
| `precision` | Integer | 小数位数 |

### A.3 POST /api/reports/dynamic-query/export — 异步导出动态查询结果

**用途**：大数据量导出走异步任务。本模块所有 EXPORT 接口**强制走异步路径**（即使命中行数 < 5000）。

**权限**：`@BizAuth(bizType = REPORT, action = EXPORT)` — 高危动作

**请求体**：同 `DynamicQueryReqDTO`，额外字段：
| 字段 | 类型 | 必填 | 校验 | 说明 |
|------|------|------|------|------|
| `fileName` | String | 否 | `@Size(max=200)` | 导出文件名前缀（无扩展名）；默认按 §I.2 生成 |
| `reason` | String | 是 | `@NotBlank` `@Size(max=500)` | 导出原因（审计用） |

**导出规范**：遵循 [附录 I 导出接口统一规范](#i-导出接口统一规范附录)
- **强制异步**：无论行数多少均返回任务 ID
- **硬上限**：500000 行，超过拒绝（`RPT-42207`）
- **文件名**：`rpt_dynamic_{filterHash}_{yyyyMMddHHmmss}.xlsx`（或用户自定义 `fileName`）
- **列定义**：动态生成，按请求 `dim` + `metricCodes[]` 顺序展开（详见 §I.4）
- **返回**：`R<ExportTaskRespDTO>`（完整 DTO 字段见 §I.3）

**响应 DTO：`ExportTaskRespDTO`**（完整字段见 §I.3）
| 字段 | 类型 | 说明 |
|------|------|------|
| `taskId` | String | 异步任务 ID |
| `bizType` | String | `REPORT` |
| `reportType` | String | `DYNAMIC_QUERY` |
| `status` | String | 初始状态 `PENDING` |
| `estimatedRows` | Long | 预估行数 |
| `statusUrl` | String | 状态查询 URL |
| `createdTime` | LocalDateTime | 创建时间 |
| `expireAt` | LocalDateTime | 链接过期时间（24 小时） |

**示例响应**：
```json
{
  "code": "0",
  "msg": "success",
  "data": {
    "taskId": "EXP202604101530223a9b",
    "bizType": "REPORT",
    "reportType": "DYNAMIC_QUERY",
```

## I. 导出接口统一规范（附录）

> **说明**：本模块是唯一面向所有核心域数据的**查询+导出中心**，导出是其核心能力。A.3 `/api/reports/dynamic-query/export` + E.1/E.2 `export-tasks/*` 已实现完整的异步导出架构；本章节在此基础上补齐同步/异步分支、列定义规范、错误码、审计细节，并落地 `docs/common-dev-guide.md §8.2 第 5 条`（"超过 5000 行必须走异步导出"）。

### I.1 同步 / 异步分支规则

**本模块与其他模块的差异**：因为报表查询面向跨模块的聚合数据，数据量往往远超业务模块，因此：
- 除"仪表盘摘要类接口"外，**所有 `action = EXPORT` 接口强制走异步路径**
- A.3 `/api/reports/dynamic-query/export` 即为异步专用端点（已设计）
- 固定报表（C.1-C.4）如需导出，需在 V2 补充对应 `/export` 异步端点

| 命中行数 N | 处理方式 | 响应类型 | 说明 |
|---|---|---|---|
| N ≤ 5000 | **可选** 同步流式返回 | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` | 仅小维度快速导出场景 |
| 5000 < N ≤ 500000 | 异步任务（默认） | `R<ExportTaskRespDTO>` | 默认路径 |
| N > 500000 | 拒绝 | `RPT-42207` | 引导用户增加过滤维度 |

**报表模块硬上限 500000 行**（区别于其他模块），原因是报表常见于跨机构/跨周期聚合查询。

**判定流程**：
1. 进入导出接口先执行 `SELECT count(*)`（含 DATA_SCOPE 过滤）
2. 按行数命中分支
3. 异步分支：写入 `report_export_task` 表（见 05-表结构DDL.md 相关章节），状态 `PENDING → RUNNING → SUCCESS / FAILED`
4. 异步完成后：上传 Excel 到对象存储（**2026-07-19 订正**：底层已是华为云 OBS，`system-governance-center.ObsStorageClient` 基于 `com.obs.services.ObsClient` 实现；本模块代码注释仍沿用历史的"MinIO"措辞，实际经由 `governance.FileApi` 统一封装，物理存储不是 MinIO），持久化 `file_object_id`，更新 `report_export_task.download_url`
5. 通过 `NotifyApi.sendUserNotify` 通知发起人

### I.2 文件命名规则

格式：`rpt_{business}_{filterHash}_{yyyyMMddHHmmss}.xlsx`

| 片段 | 说明 | 示例 |
|---|---|---|
| `rpt` | 固定前缀 | `rpt` |
| `{business}` | `dynamic` / `dashboard` / `touch_summary` / `perf_summary` / `custpool_summary` | `dynamic` |
| `{filterHash}` | 请求参数 MD5 前 8 位 | `a3f9b2c4` |
| `{yyyyMMddHHmmss}` | 导出时刻 | `20260410153022` |

用户侧可通过 A.3 请求中的 `fileName` 字段自定义前缀，系统会追加时间戳。

### I.4 列定义规范

动态查询导出的列是**由请求中的 `metricCodes[]` 动态决定**的，无法静态定义，因此本模块采用"字段字典 + 动态编排"的方式：

1. 每个 `metricCode` 在 `perf_metric_def` 表中定义了中文名（`metric_name`）和格式规则（`format_pattern`）
2. 导出时按请求顺序生成列
3. 前几列固定：维度（EMP 时为员工工号/员工姓名/所属机构；ORG 时为机构编码/机构名称；CUST 时为客户 ID/客户名称）
4. 后续列按 `metricCodes[]` 顺序展开

#### 动态列头生成示例（DynamicQueryReqDTO）

```json
{
  "dim": "EMP",
  "subjectIds": ["E10001", "E10002"],
  "metricCodes": ["M_DEPOSIT_BAL", "M_LOAN_BAL", "M_FEE_INCOME"],
  "cycleType": "MONTHLY",
  "cycleDate": "2026-03-01"
}
```

生成的 Excel 列头（按规范）：
| 列序 | 中文列名 | 来源 | 格式 |
|---|---|---|---|
| 1 | 员工工号 | emp_id（固定） | — |
| 2 | 员工姓名 | emp_name（从 PT_USER 翻译） | — |
| 3 | 所属机构 | org_name（从 ext_org_info 翻译） | — |
| 4 | 周期 | cycleKey（固定） | `yyyy-MM` |
| 5 | 数据版本 | sys_control_version | — |
| 6 | 存款余额 | M_DEPOSIT_BAL 的 metric_name | `#,##0.00` |
| 7 | 贷款余额 | M_LOAN_BAL 的 metric_name | `#,##0.00` |
| 8 | 中间业务收入 | M_FEE_INCOME 的 metric_name | `#,##0.00` |

- `resource_type = REPORT_EXPORT`
- `operator_emp_id` / `operator_org_id`
- `reportType` / `queryParams`（完整 JSON）
- `rowCount`（实际命中行数）
- `duration`（执行耗时 ms）
- `result`（`SUCCESS` / `FAILED`）
- `file_object_id`（异步分支成功时）
- `reason`（若请求中包含，则落库）

**异步导出补写时机**：Worker 最终成功/失败时补写一条 `audit_log`。重试期间不记录中间状态。若任务被用户主动取消，记录一条 `CANCELLED` 审计。

### J.6 使用约定

1. 错误码通过 `RptException` 承载，最终由全局异常处理器映射到统一响应结构的错误码字段返回
2. SQL 探查类错误（42001-42009）必须写审计日志 + 发安全告警
3. 数据范围错误（40303/43013）在前端展示时应脱敏（不显示越权对象 ID 的明细）
4. 异步导出任务错误通过 E 章 E.1/E.2/E.3 接口返回，前端轮询时需妥善处理
5. 大屏子域导出/取数错误码统一走 43xxx 段（见 J.7），不新增前缀

### N.6 大屏取数 DATA_SCOPE 行级权限（`ScreenDataScopeGuard`，2026-07-17 spec §4）

`/api/screen/data`（N.3）与试跑端点不同，执行前会经 `ScreenDataScopeGuard.check` 做主体参数级行级校验，越权统一 **fail-close** 抛 `RPT-43013`：

| 当前用户 REPORT DataScope（`BizScopeApi.resolveScope`） | 校验规则 |
|---|---|
| `ALL` | 放行（含 GLOBAL 口径数据源） |
| `SELF` | `contextParams.empId` 必须=当前用户；`orgCode` 必须=主机构或不传 |
| `ORG` | `orgCode` 必须=主机构；`empId` 的主机构必须=主机构（经 `OrgApi.getUserMainOrg`） |
| `ORG_SUBTREE` | `orgCode`/`empId` 所属主机构必须落在主机构子树（`OrgApi.getOrgSubtreeCodes`） |
| `SELF_CREATED`/`SELF_ASSIGNED`/`WORKFLOW_PARTICIPANT`/解析失败 | **fail-close 一律拒绝**（大屏主体取数无对应谓词语义） |

**GLOBAL 口径**（数据源 `config_json.scopeMode=GLOBAL`，或 `SUBJECT` 型但配置/SQL 不消费任何主体参数——聚合形态 `WIDE_TABLE`、`CUSTOM_SQL` 无 `#{empId}`/`#{orgCode}` 占位——防绕过）：仅 `ALL`，或 `ORG_SUBTREE` 且主机构为省级顶层节点（`EXT_ORG_INFO ORG_LEVEL=1` / `P_ID='0'`）放行，否则拒绝。

**边界**：主体参数缺失不在本类拦截（属 `RPT-43010` 入参校验职责）；试跑端点（N.4.5，独立高危资源 `R_RPT_SCR_DS_TRY`）**不套本守卫**。

## O. DataScope Picker（报表对象选择数据范围，2026-07-19 新增）

### O.1 GET /api/reports/scope/picker — 对象选择数据范围

**用途**：`ReportScopeController` 提供报表"选择对象"控件（人员/机构选择器）的统一数据范围解析入口，供前端对象选择框复用，与查询执行层（`DynamicQueryService`）、A.5 员工搜索同源同口径（均调 `BizScopeApi.buildScopeContext`），**不写死角色码**——改某角色的可见范围，在权限配置页配 DataScope 即可对三处同时生效。

**权限**：`@BizAuth(bizType = REPORT, action = LIST)`，资源 `R_RPT_SCOPE_PICKER`

**请求参数（Query）**：
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `dim` | String | 否（默认 `EMP`） | 维度：`EMP`/`ORG`/其它 |

**业务规则**：按维度分流取用的 `BizType`，与 A.2 执行层、A.5 员工搜索一致：
| `dim` | 取用的 BizType |
|---|---|
| `ORG` | `REPORT_DYN_ORG` |
| `EMP` | `REPORT_DYN_EMP` |
| 其它 | `REPORT`（回退） |

`DataScopeType` → 返回 `mode` 的映射：
| DataScopeType | mode | orgCodes |
|---|---|---|
| `ALL` | `ALL` | 空 |
| `ORG_SUBTREE` | `ORG_SUBTREE` | 子树编码集合（为空则回退本机构一个编码） |
| `ORG` | `ORG_SUBTREE`（前端统一按 `orgCodes` 过滤机构树，`ORG` 只给本机构一个编码） | `[本机构编码]` |
| 其余（`SELF`/`SELF_CREATED`/`SELF_ASSIGNED`/`WORKFLOW_PARTICIPANT`/null） | `SELF` | `[本机构编码]`（若能取到） |

**响应**：`Map<String,Object>`（非强类型 DTO），字段：
| 字段 | 类型 | 说明 |
|---|---|---|
| `mode` | String | `ALL`/`ORG_SUBTREE`/`SELF` |
| `selfEmpId` | String | 当前用户工号 |
| `selfName` | String | 当前用户姓名（`displayName`） |
| `orgCodes` | List\<String\> | 可见机构编码列表（`ALL` 模式下为空列表） |

**与其他"数据范围解析"实现的关系（避免混淆）**：本端点是**通用对象选择器**入口；L 章自由报表的 `resolveRowScope()`（L.1）与 N.6 `ScreenDataScopeGuard` 是各自子域的**行级数据过滤**实现，三者思路一致（同一套 DataScopeType → mode 映射习惯）但**不是同一段代码**，分别服务于不同端点，不能相互替代。
