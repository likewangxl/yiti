# 报表分析中心 — 接口设计与报文

## 代码化经营大屏契约

零售模板使用独立指标与槽位，仅允许 RETAIL 屏与 RETAIL 来源，保存/发布/运行沿用原权限、CAS 和快照身份。分行槽与零售槽不能混用，共享 `branches` 只服务授权机构目录。字段、单位、范围与验收要求见 [零售设计与数据契约](../../retail-screen-design-and-acceptance.md#零售绑定契约)。

渲染和管理沿用 `/api/screen/admin/canvas/{id}`、`/save`、`/publish`、`/discard`、`/rollback`、`/api/screen/view/{screenCode}` 与 `/api/screen/data`，原 HTTP 方法与资源授权不变。统一展示目录见下文“大屏中心目录”。完整操作见 [代码化经营大屏](11-代码化经营大屏.md)。

- `CanvasStyleDTO.presentation`：可选强类型对象，`type=CODE`、`template=branch-overview-v1`、`retail-overview-v1` 或 `corporate-overview-v1`。未声明时保持历史画布；未知声明拒绝。CODE 的 `ChartWidget.propValue.bindingKey` 唯一标识模板数据槽位，实际数据身份仍为当前屏所属 `blockId` 和可信发布 `bindSnapshots`。
- `CanvasStyleDTO.dataNotice` 与 `CanvasStyleDTO.metricLabels`：可选的运行时展示元数据，继续保存在现有 `canvasStyle` JSON 中并随草稿/发布快照读取，不新增表字段或接口。`dataNotice` 必须是纯文本，最长 240 个 Unicode 码点；`metricLabels` 必须是对象，键仅允许当前代码化 KPI 白名单（`deposit`、`depositIncrease`、`depositAverage`、`loan`、`customers`、`revenue`、`rate` 及零售模板 KPI 键），值必须是最长 40 个 Unicode 码点的纯文本。控制字符、尖括号、未知键和非文本值均拒绝；未提供时运行时不显示额外来源说明。
- `CanvasStyleDTO.sourceAvailability`：可选的分行代码化页面数据可用性说明，继续保存在 `canvasStyle` 并随草稿、发布快照和运行视图返回。顶层键只允许分行模板十四个槽位；每个槽位必须声明 `status`，可选 `message`、`dataDate` 和按该槽位语义字段白名单声明的 `fields`。字段级对象使用同一状态、说明和日期结构，但不能继续嵌套。状态只允许 `AVAILABLE`、`NO_SOURCE`、`NO_ROWS`、`NO_VALUES`、`PARTIAL`、`HISTORICAL`；`message` 是最长 120 个 Unicode 码点的纯文本，`dataDate` 是有效的 `YYYY-MM-DD`。未知槽位、未知语义字段、未知属性、数组、空对象层级、控制字符、尖括号、无效日期和错误类型均拒绝。省略该对象时兼容既有画布。
- `bindJson.fields` 将槽位语义字段映射到数据源响应列；`units` 显式声明原始输入单位。服务端校验类型、槽位、必需字段、明确输入单位、输出列存在性及 DIM/METRIC 角色和正整数 `dsId`；保存、发布、预览及归档恢复均不得绕过。
- `ScreenRenderRespDTO.panoramaInstitutions`：仅 NAMED_GROUP 的 CODE 屏返回已授权机构画像的最小投影，包括机构编码/名称、城市、经营归属、经营层级/性质、合法坐标、`located` 及定位来源 `locationSource`（PROFILE / MANUAL / GEOCODE_VERIFIED；未定位时为空）。不返回详细地址、画像审计信息或 remark；DEPARTMENT 不作为网点，演示/无效坐标清空，可信位置台账可替换旧演示坐标。LEGACY 和历史画布不补全量目录。
- `ScreenDataReqDTO.contextParams.orgCode`：NAMED_GROUP 可选的单机构收窄参数。未传时保持授权机构集合；传入时必须属于授权集合，随后仅以该单机构构造 `serverOrgCodes`，越权拒绝。客户端 `orgCodes` 不能扩大集合。该语义用于选中支行后的独立趋势请求。
- 放弃草稿在同一版本 CAS 内同时恢复发布包的 `canvasStyle` 与组件树，避免模板声明与数据身份来自不同版本。

`citySummary` 身份列至少配置 `cityCode` 或 `orgCode`；机构身份仅通过已授权画像解析城市，一城市多行会明确拒绝该城市汇总，禁止盲聚合上下级数据。

`attention` 继续要求 `label` 和 `count`，并可选配置 DIM 字段 `orgCode`。省略 `orgCode` 时保持全局关注列表兼容语义；提供时，运行时只将机构号属于当前 `panoramaInstitutions` 授权目录且唯一的行关联到对应机构，缺失、重复或越目录机构号不得附着到机构详情。机构展示名由授权目录解析，数据行的 `label` 仍只表示关注事项；`orgCode` 不声明单位，也不参与或扩大后端数据范围。

CODE 模板兼容新增 `depositIncrease`（存款较上月净增）、`depositAverage`（存款月均余额）单值槽；两者必填 `value`，可选 `change` / `date`。`ranking` 的必填 `value` 仍为存款余额，可另映射金额字段 `increase` / `average`。`trend` 至少映射 `deposit`、`loan`、`depositIncrease` 之一并提供日期；`branchTrend` 契约不变。新增金额字段仅接受 METRIC 列及明确金额输入单位，错误角色、缺单位、未知字段拒绝。既有十二槽兼容；新绑定配置需在新后端校验器上线后保存。

`composition.fields` 支持互斥的两种形状：旧行式 `{name,value}` 或固定两列 `{corporate,retail}`。两列模式只允许 `WIDE_TABLE` / `ORG_INDEX_RESULT`，两列均为 METRIC 且分别声明原始单位；允许金额单位之间换算或比例单位之间换算，拒绝金额与比例混合、缺列、混用模式和缺单位。运行结果必须恰好一行，原子生成“对公业务”“零售业务”两项；无行、多行或无效值整槽报错，不擅自取首行或聚合。旧行式继续支持多行类别。此转换不开放表达式、任意 SQL 或额外机构范围，保存/发布/归档恢复使用同一校验器。

`sourceAvailability` 只解释为什么页面没有可展示值，不参与取数、授权、机构范围或计算。前端展示顺序固定为：已适配出的有效值优先；真实请求或非法数值、非法单位等适配错误其次；普通 `NO_VALUES` 缺值使用同字段或同槽位的静态中文原因。因而 `AVAILABLE` 不能掩盖失败，`NO_SOURCE` 或 `NO_VALUES` 也不能隐藏后来取得的有效值，缺失值不得按零处理，底层字段名不得作为面向业务用户的缺失文案。部分可用槽位应在 `fields` 中分别声明，例如：

```json
{
  "sourceAvailability": {
    "customers": {
      "status": "NO_SOURCE",
      "message": "客户主数据缺少机构归属，无法按当前机构范围汇总"
    },
    "composition": {
      "status": "PARTIAL",
      "dataDate": "2026-08-30",
      "fields": {
        "corporate": {"status": "NO_VALUES", "message": "当前周期无有效值"},
        "retail": {"status": "AVAILABLE", "dataDate": "2026-08-30"}
      }
    }
  }
}
```

`columnsMeta.amountScale` 延续展示预设语义，不能单独证明原始 rows 的单位；显式 `bindJson.units` 优先。历史未填单位的回退按元处理，真实接入必须声明经核对的原始单位。当前分行测试库指标的来源单位为空，绑定暂以 `YUAN` 作为测试联调展示假设并在页面标注，不能据此宣称业务单位已经确认。数据源列表引用信息改为请求内一次汇集，仍保守处理无法解析的发布/归档引用，不改变删除保护。

## 1. 通用约定

- 除明确说明的文件响应外，接口返回统一响应包装。
- 业务接口声明 BizAuth，业务类型为 REPORT，资源权限以 PT_RESOURCE 当前登记为准。
- 列表、详情、动态查询、导出、自由报表和大屏取数均在服务层应用当前用户数据范围。
- 日期参数使用 ISO 日期格式；分页参数使用 PageRequest。
- 请求 DTO 的必填、长度、枚举和版本条件由源码校验注解及 Service 二次校验共同决定；本文不复制易漂移字段清单。

### 7.2.1 运行时批次质量与不可变快照

`POST /api/screen/data` 的请求可选传入顶层 `batchId`。该值是性能批次的不可透明字符串：省略时按当前屏服务端机构组和完整授权机构集合调用最近批次，传入时锁定同一批次；客户端不能通过 `groupCode`、`serverOrgCodes` 或配置 JSON 改写服务端范围。`contextParams.orgCode` 只收窄响应行，批次选择和完整性仍按完整授权机构集合执行。

分行 `WIDE_TABLE` / `ORG_INDEX_RESULT` 数据源可以声明严格的 `batchPolicy`，对象存在即启用，允许字段只有 `maxAgeDays`（非负整数）和 `requiredComplete`（布尔值，缺省为 `true`）。机构组编码来自当前屏元数据；策略不允许在数据源配置中固定机构组。当前屏没有可见完整批次、批次为 `PARTIAL`、覆盖不足或日期晚于当前业务日时，接口返回 `rows: []` 和 `quality.status: "NO_COMPLETE_BATCH"`，不回退到全库最新日或部分合计。

`quality` 为向后兼容的可空扩展对象。使用不可变快照时，所有周期响应都携带同一 `batchId`；`STALE` 仍返回该完整批次的行，`ageDays > maxAgeDays` 才判定为过期。质量对象字段如下：

```json
{
  "batchId": "RUN-20260710-01",
  "dataDate": "2026-07-10",
  "version": "V2",
  "status": "COMPLETE",
  "dataClassification": "TEST",
  "calculatedAt": "2026-07-10T18:00:00+08:00",
  "sourceAsOf": {
    "financial": "2026-07-10",
```

### 7.3 大屏中心目录

`GET /api/screen/view/catalog` 不接收用户身份、角色、机构范围或草稿预览参数。沿用统一 `ResponseWrapper`，`data` 为 `ScreenEntryRespDTO[]`，字段为 `screenCode`、`screenName`、`viewLevel`、`bizLine`、`template`、`dataMode`。不返回机构组编码、白名单、数据源或画布内容。

目录固定登记以下代码化页面，不枚举历史设计器发布包：

| 权限关联屏编码 | 页面名称 | template | dataMode |
|---|---|---|---|
| SCR_PROVINCE | 分行经营总览 | branch-overview-v1 | TEST |
| SCR_RETAIL_OVERVIEW | 零售经营总览 | retail-overview-v1 | DEMO |
| SCR_CORP_OVERVIEW | 对公经营总览 | corporate-overview-v1 | DEMO / LIVE |

对应屏记录必须存在且 ACTIVE，逐屏复用运行时授权：白名单、NAMED_GROUP 同角色机构范围与 LEGACY_CONTEXT 兼容语义保持不变。SYS_ADMIN 不绕过屏级门禁。页面使用确定性演示模型，目录不依赖旧画布或发布状态，因此未发布的零售屏仍可在授权通过后显示。停用/缺失/无权项不返回，基础设施失败返回错误。

该端点受 `@BizAuth(REPORT, READ)` 和已登记的 `R_RPT_SCR_VIEW`（`GET /api/screen/view/*`）保护，不新增角色绑定。`catalog` 为保留屏编码和字面路由。既有 `/api/screen/view/{screenCode}`、`/api/screen/data` 的发布与取数授权不变。

前端入口 `/#/screens` 点击后进入受保护的 `/#/screen-pages/:template`。目标页面重新请求当前用户目录确认模板和对应的数据模式。分行 `TEST` 模式随后调用 `GET /api/screen/view/SCR_PROVINCE`，仅接受已发布、schemaVersion=2 且模板匹配的 CODE 包，通过 `PanoramaRuntime` 和 `POST /api/screen/data` 按发布绑定取数；刷新重新查询接口。页面醒目标注“测试库数据 · 非生产业务数据”，这表示使用已保存测试数据联调，不表示真实经营数据。数据日期、口径说明和缺失指标按接口及配置展示，不回填演示模型。

零售 `DEMO` 模式保留手写 `RetailDashboard` 与演示模型，标注“演示数据 · 非业务数据”，不查询分行业务数据。未知模板/数据模式、非法或旧坐标发布包、请求失败、退出、切换用户或迟到响应均不能展示旧内容。分行与零售仍留在受保护入口，不跳转 public 预览页；目录授权不代替详情及数据接口的后端权限校验。

## 8. 响应与错误处理

DTO 的字段、分页结构、文件名和错误码直接由当前源码提供。常见失败包括参数校验失败、无权访问、数据范围为空、版本冲突、任务未完成、文件不存在、SQL 安全校验失败和上游查询失败。调用方应根据统一错误码处理，不依赖历史文档中的错误码编号、数量或伪造的响应示例。

## 对公经营模板绑定

`corporate-overview-v1` 复用现有草稿保存、发布、取数与目录接口。仅接受CORP屏与CORP来源，对公槽与分行、零售槽互斥。字段、单位和数据源设计见[对公经营总览契约](../../corporate-screen-design-and-acceptance.md)。不新增REST路径或资源权限。

对公`LIVE`表示通过已发布包与数据接口取数，不表示生产环境或数据真实性已经认证。有匹配对公CODE模板的已发布包时返回LIVE；尚未发布或仅保留合法旧画布时，授权通过后返回DEMO，中心展示“演示数据”，受保护入口复用对公演示页，不读取旧业务发布包。损坏或CODE模板不匹配的发布包仍排除，接口失败不降级成演示。当前来源缺口见[对公接入核查](../../corporate-live-data-audit-20260914.md)。


## CODE 大屏数据分类与正式入口（2026-09-16）

CanvasStyleDTO 新增可选 dataClassification 字段，白名单 TEST、LIVE、PROD，其他值拒绝；该字段保存于既有画布 JSON，无数据库 schema 变更。目录只开放已授权 ACTIVE 屏的可信 schemaVersion=2 CODE 发布包，要求模板与注册项一致且绑定快照及数据源可验证。TEST 分类显示测试库数据；LIVE/PROD 仅表示接口接入，不认证经营真实性。旧画布、空包、损坏包不再回退到前端 DEMO。

画布分类是管理者声明的展示属性，与运行响应 quality.dataClassification（来自不可变批次）分开保存，不能替代后者的证据。运行时保留各槽 quality 与数据日期，数据说明、单位待核验、过期状态必须可检查。原接口 URL、RBAC、屏角色和命名机构组授权不变，无新增资源授权。


## 命名机构组固定来源扩展

M98_STAT只接受schemaVersion=2、scopeMode=NAMED_GROUP、mode=SUMMARY，以及CORP_REVENUE/RETAIL_REVENUE/RETAIL_LOAN/CORP_NPL_RATE/RETAIL_NPL_RATE五个profile；条线与profile必须匹配。禁止配置SQL、表名、列名和自定义过滤。返回单行data_date及amount或ratio；金额单位不推断，比例为百分数。CORP_REVENUE固定199全币折人民币，其余固定01人民币，不相加；员工归属通过OrgApi.listUniqueUserOrgs取得，空映射不查全表。非法数值和未知五级分类保留空值及质量说明，比例按合计分子/合计分母计算。

KPI_DETAIL新增命名组schema2/ORG/SNAPSHOT/SINGLE组合，仍校验ACTIVE方案；机构参数来自服务端授权全集及校验后的输出子集，共同日期由授权全集确定。固定列包含org_code/org_name/data_date/metric_code/metric_name/actual_value/target_value/completion_rate/gap，以及attention_label/attention_count。关注计数仅由合法的实际值、正目标值派生，缺值不补零。CUSTOM_SQL命名组、KPI_RESULT命名组、EMP/TREND组合仍拒绝。保存、元数据更新、画布保存、发布与运行快照使用统一准入策略。没有新增REST端点或资源授权。

### 支行经营测试批次数据源（FREE_REPORT）

既有数据源管理接口支持 `sourceKind=FREE_REPORT`、`dsType=SINGLE`、`bizLine=COMMON`。该受控来源只读取报表域自由报表批次，不支持自定义 SQL。配置严格为：

```json
{"schemaVersion":2,"scopeMode":"NAMED_GROUP","dataClassification":"TEST","profile":"BRANCH_OVERVIEW","batchId":"TEST_BRANCH_OPERATING_20260921"}
```

批次必须存在、状态为 SUCCESS、名称以 TEST_BRANCH_OPERATING 开头，列定义必须符合固定协议；配置不允许额外字段。只允许绑定到 `canvasStyle.dataClassification=TEST` 的屏幕，草稿保存、发布、运行时及被引用数据源的原地修改均校验分类。通过既有屏级角色和命名机构组授权，客户端不能覆盖批次或扩展机构范围。未新增 REST 端点及权限资源。

输出列为 `org_code, kind, key, name, data_date, unit, status, owner, value, yoy, mom, actual, target, rate, gap, deposit, loan, amount, increase, count, pending, days`。机构来自物理行 ORG_CODE；其他字段来自严格校验的 DATA_JSON。kind 支持 kpi/target/history/composition/marketing/project/team/attention。金额列使用元，百分比列使用百分点数值，数量列为计数；value 的单位由 unit（YUAN/COUNT/PERCENT）声明。运行时质量标记为 TEST，数据版本为批次 ID。查询超限、非法字段、授权范围不一致及损坏的批次均报错，不以缺省值替代。

支行专用页面默认使用 `SCR_BRANCH_OPERATING_TEST` 发布包，明确展示“测试数据 · 非实际经营数据”；`source=live` 保留系统存量来源。界面金额换算为万元，测试和存量来源分别请求，禁止失败后静默互相回退。
