# 大屏管理操作指南

> 拖拽设计器及专用编辑代码已退役。旧文件名和 `/screen-admin/designer` 地址保留以兼容引用，实际入口为代码化“大屏管理”。分行与零售模板、自动配置和核验见 [11-代码化经营大屏](11-代码化经营大屏.md)。历史发布包保留只读渲染。

> 适用模块：report-analytics-center
> 说明：本文记录当前管理端和运行时的操作顺序；接口字段以同目录接口文档和前端/后端 DTO 为准。

## 1. 使用前检查

### 统一展示入口

登录后从平台顶栏点击“大屏中心”，或访问 `/#/screens`。目录展示已授权的“分行经营总览”、“零售经营总览”和“对公经营总览”手写页面，支持搜索和条线筛选。点击后进入 `/screen-pages/:template`，返回按钮回到中心。旧设计器发布页面不再列入此目录。

当前两个页面使用演示模型，卡片和页面明确标注演示数据；这不表示真实指标已接入。目录关联已有屏级角色和机构权限，缺失、停用或无权记录不显示；发布状态不影响演示页面可见性。目标页面直达时会重新核验当前目录权限。请求失败支持重试，不能伪装为空目录。

### 管理准备

1. 当前用户具备大屏管理所需的 REPORT 资源权限，运行用户还必须满足屏查看角色白名单和机构范围。
2. 屏元数据应明确业务条线、视角层级和机构范围模式。
3. 数据源只能使用服务端支持并通过安全校验的类型；自定义 SQL 必须满足表白名单、禁用关键字和参数绑定规则。
4. 大屏取数依赖指标、KPI、组织和数据范围公开 API；权限或数据范围无法确认时不会返回数据。

屏范围模式：

- LEGACY_CONTEXT：按当前用户和既有上下文解析范围。
- NAMED_GROUP：按已配置的机构组解析范围，并要求机构组存在且与数据源的可证明范围约束一致。

## 2. 新建屏和配置元数据

1. 调用或在管理界面执行 POST /api/screen/admin/screens，创建只含元数据的空屏。
2. 设置屏名称、视角层级、业务条线和机构范围模式；使用 NAMED_GROUP 时同时填写有效机构组编码。
3. 后续只修改元数据时调用 PUT /api/screen/admin/screens/{id}/metadata，并提交当前 expectedVersion 和非空审计原因。此操作不携带画布区块。
4. 需要角色白名单时先读取 GET /api/screen/admin/screens/{id}/access-roles，再通过 PUT 覆盖保存；保存同样提交 expectedVersion、角色编码和原因。

元数据更新不应覆盖草稿、发布包或发布状态。版本冲突时重新加载详情，合并确认后的最新值再提交。

## 3. 配置数据源

1. 通过 GET /api/screen/admin/datasources 查看可用数据源；创建或编辑时选择 WIDE_TABLE、KPI_DETAIL 或 CUSTOM_SQL 等当前支持类型。
2. WIDE_TABLE 使用服务端已登记的表、主体列、指标列和聚合配置；KPI_DETAIL 绑定有效 KPI 方案，并使用支持的 EMP 或 ORG 主体；CUSTOM_SQL 只使用允许的模板参数和白名单表。
3. 保存或更新后，用 POST /api/screen/admin/datasources/try-run 试跑配置。试跑会做完整安全校验并产生高危审计。
4. 已保存数据源的列探测使用 POST /api/screen/admin/datasources/{id}/probe-columns，该入口具有独立高危授权。
5. 删除前检查草稿、当前发布包和归档是否仍引用该数据源。存在引用、关系无法确认或审计失败时保持拒绝。

NAMED_GROUP 屏只接受服务端能够映射机构组范围的数据源配置；不能用无法建立 org_code 约束的自定义 SQL 绕过机构组范围。

## 4. 配置代码化展示内容并保存草稿

新经营大屏可在 `presentation.displaySchemaVersion=1` 下保存类型化展示组件。每个展示组件使用稳定 `componentId`，配置受控区域、标题/说明、显示格式、内容和白名单交互，并通过 `dataRefs.blockId` 引用当前屏已有数据区块。标题可自定义或恢复自动继承；空字符串用于明确清空副标题/说明，不能在保存时被旧值补回。

展示配置不接受任意脚本、URL或物理SQL。来源原始单位不能为AUTO；显示单位必须与金额/计数/比例类型兼容。一个block可被多个展示组件复用，单组件不能重复引用；删除展示组件不等于删除数据源。

1. 通过 GET /api/screen/admin/canvas/{id} 加载草稿、区块和当前版本。
2. 选择分行或零售模板，再选择展示内容。系统尝试匹配语义、条线和粒度明确的来源；也可使用“一键配置空白内容”。已有手工配置保留，所有来源、字段、单位仍可修改。
3. 调用 POST /api/screen/admin/canvas/save 保存草稿，并携带 screenId、expectedVersion 和当前组件/区块数据。服务端会同步处理区块增删改单和版本 CAS。
4. 保存成功后使用响应中的新版本继续编辑；版本冲突保留本地编辑，核对后重新加载并合并，不能强行覆盖。
5. 点击“验证已保存草稿数据”，实际读取已保存组件，检查数据缺列、空值、重复、日期与授权机构覆盖。核验不会替用户保存或发布；未保存变更需要先保存再核验。
6. 代码化地图的机构身份与位置来自服务端授权目录和机构画像。旧 map-points 接口只服务历史地图兼容，不用于替代新模板的真实机构档案。

草稿保存不会改变线上发布态。画布中引用的区块必须属于当前屏；重复、缺失或无法验证的 blockId 不能进入发布流程。

新建数据区块首次还没有服务端blockId时，先保存区块，再在下一次保存中添加展示引用。系统不使用浏览器临时ID代替blockId，也不自动跨屏寻找同名区块。

数据来源选择按业务信息展示：指标来源、机构KPI和既有受控来源分别标识，并显示名称/编码、条线、主体维度、单值或时序形状、指标名称/单位和既有公式说明。搜索可使用来源名称、编码或指标名称/编码。停用、跨条线、形状不符及命名机构组不安全的来源保留禁用说明，不能选中后再由服务端兜底。

命名机构组的KPI细项只开放服务端现已支持的 `schema2 + ORG + SNAPSHOT + SINGLE`；员工KPI总分、EMP/TREND组合和CUSTOM_SQL不进入标准经营大屏绑定。列表或网络请求失败直接显示错误，不以空候选或mock成功替代。切换来源时清除新来源没有声明的字段和关联单位。

启用 `displaySchemaVersion=1` 后，配置页提供三栏工作台：左侧管理受控展示实例，中间显示本地即时预览，右侧编辑标题/说明、主展示字段、已有block来源、显示单位、小数位和白名单交互。组件可新增、复制、显隐、同区域排序和删除；这些动作只改变展示配置，删除实例不会删除block或数据源。

新增组件在绑定已有正整数blockId前标记为 `DRAFT_UNBOUND`，不能保存发布。自定义标题换源后显示复核提示；AUTO标题跟随已发布指标名称快照。取消本地修改恢复本次加载快照；保存成功后才清除dirty状态。版本冲突或保存失败保留本地会话，不自动覆盖服务端；存在未保存组件修改时，切屏和关闭页面会提示。

三栏中间区是本地样式预览，不代表真实数据已验证。真实草稿取数仍使用“验证已保存草稿数据”和受保护预览入口；下方高级字段映射继续用于字段/单位的精确绑定。

### 4.1 旧配置迁移预览

检测到旧版组件树时，先打开“旧配置迁移预览”。迁移器只依据旧组件的
`propValue.bindingKey`、`blockId → bindSnapshots[blockId].bind` 和 `metricLabels` 的明确编码/结构匹配，
不会根据中文标题猜测指标身份。预览逐项显示“已迁移、无法确定、缺字段、待确认”四种状态，并保留旧发布包回退快照。

“应用到当前草稿”只替换当前浏览器编辑会话中的新组件树，不调用保存、发布或共享数据源写接口；旧发布结果仍保持不变。
存在无法确定、缺字段或待确认项时，页面禁止声明“无损完成”，应先人工补齐或取消。重复打开/预览同一旧配置会生成相同且可追溯的组件 ID。
点击“取消”不产生草稿写入；确认应用后仍须使用页面现有的“保存草稿”流程，由服务端按当前 `expectedVersion` 执行 CAS，
保存冲突时保留本地草稿并重新核对，不强行覆盖。

## 5. 预览、发布和回滚

### 5.1 草稿预览

使用 GET /api/screen/view/{screenCode}?preview=draft 读取草稿渲染包。该状态仅供具备屏管理权限的登录用户预览；普通查看者只能读取发布态。

### 5.2 发布

1. 发布前确认组件、区块、数据源、业务条线、机构范围和角色白名单。
2. 调用 POST /api/screen/admin/canvas/publish，提交当前 expectedVersion 和审计原因。
3. 服务端重新校验画布，生成包含组件和可信数据源绑定快照的发布包，更新发布状态并写发布归档。
4. 发布成功后，GET /api/screen/view/{screenCode} 默认读取新的发布包。

发布是高风险操作，线上运行不依赖可变草稿区块。发布包缺少可信绑定、数据源已失效或范围不一致时按 Fail Close 拒绝。

### 5.3 放弃草稿和回滚

- POST /api/screen/admin/canvas/discard：按当前版本放弃草稿，以发布态恢复编辑数据。
- GET /api/screen/admin/canvas/{id}/publish-logs：读取可选发布归档。
- POST /api/screen/admin/canvas/rollback：从指定可信归档恢复发布态，并提交当前版本和审计原因。

回滚不应使用无法证明身份的归档内容；归档校验失败时拒绝操作。

## 6. 运行时取数

- GET /api/screen/view/{screenCode} 获取发布渲染包。
- POST /api/screen/data 按屏、区块、数据源和上下文参数取数。
- GET /api/screen/admin/screens/{id}/map-region-metrics 获取屏范围内地图经营指标。

服务端在运行时重新检查屏状态、屏级角色、机构组、业务条线、数据源快照和 REPORT 数据范围。调用者不能仅通过修改 screenCode、blockId、dsId 或主体参数扩大可见范围。

## 7. 常见问题排查

- 看不到屏：检查 REPORT 资源、屏角色白名单、机构组成员和当前用户数据范围。
- 草稿预览无数据：检查是否具备草稿权限、区块绑定快照是否完整、数据源试跑是否通过。
- 保存提示版本冲突：重新读取画布，确认其他编辑者的变更后再保存。
- 发布被拒绝：依次检查 blockId 双向一致性、数据源能力/条线、机构范围和发布包快照。
- 数据源不能删除：先在草稿、发布包和归档中查找引用；无法确认引用关系时不强行删除。
- 运行时返回拒绝：保留响应错误码和 traceId，核对屏角色、机构组、业务条线及数据范围，而不是把失败改成空数据展示。

### 对公经营总览

选择对公条线大屏后使用 `corporate-overview-v1`，配置对公存款、月日均、贷款、营业收入、有效客户、不良率以及趋势、客群、排名、目标和协调事项。只选择口径明确的CORP来源，缺失项保留待接入。数据口径与入口区别见[对公经营总览说明](../../corporate-screen-design-and-acceptance.md)。
