# 大屏设计器操作指南

> 代码模板入口已迁移为“大屏管理”，不再依赖拖拽布局。新模板配置、市级全景与支行联动见 [11-代码化经营大屏](11-代码化经营大屏.md)。本文的画布字段和旧设计器操作用于解释历史配置兼容与发布契约；新模板通过具名数据槽位完成绑定。

> 适用模块：report-analytics-center
> 说明：本文只保留当前设计器、管理端和运行时的操作顺序；接口字段以同目录接口文档和前端/后端 DTO 为准。

## 1. 使用前检查

1. 当前用户具备大屏管理所需的 REPORT 资源权限，运行用户还必须满足屏查看角色白名单和机构范围。
2. 屏元数据应明确业务条线、视角层级和机构范围模式。
3. 数据源只能使用服务端支持并通过安全校验的类型；自定义 SQL 必须满足表白名单、禁用关键字和参数绑定规则。
4. 大屏取数依赖指标、KPI、组织和数据范围公开 API；权限或数据范围无法确认时不会返回数据。

屏范围模式：

- LEGACY_CONTEXT：按当前用户和既有上下文解析范围。
- NAMED_GROUP：按已配置的机构组解析范围，并要求机构组存在且与数据源的可证明范围约束一致。

## 2. 新建屏和配置元数据

1. 调用或在管理界面执行 POST /api/screen/admin/screens，创建只含元数据的空屏。
2. 设置屏名称、视角层级、业务条线和机构范围模式；使用 NAMED_GROUP 时同时填写有效机构组编码。
3. 后续只修改元数据时调用 PUT /api/screen/admin/screens/{id}/metadata，并提交当前 expectedVersion 和非空审计原因。此操作不携带画布区块。
4. 需要角色白名单时先读取 GET /api/screen/admin/screens/{id}/access-roles，再通过 PUT 覆盖保存；保存同样提交 expectedVersion、角色编码和原因。

元数据更新不应覆盖草稿、发布包或发布状态。版本冲突时重新加载详情，合并确认后的最新值再提交。

## 3. 配置数据源

1. 通过 GET /api/screen/admin/datasources 查看可用数据源；创建或编辑时选择 WIDE_TABLE、KPI_DETAIL 或 CUSTOM_SQL 等当前支持类型。
2. WIDE_TABLE 使用服务端已登记的表、主体列、指标列和聚合配置；KPI_DETAIL 绑定有效 KPI 方案，并使用支持的 EMP 或 ORG 主体；CUSTOM_SQL 只使用允许的模板参数和白名单表。
3. 保存或更新后，用 POST /api/screen/admin/datasources/try-run 试跑配置。试跑会做完整安全校验并产生高危审计。
4. 已保存数据源的列探测使用 POST /api/screen/admin/datasources/{id}/probe-columns，该入口具有独立高危授权。
5. 删除前检查草稿、当前发布包和归档是否仍引用该数据源。存在引用、关系无法确认或审计失败时保持拒绝。

NAMED_GROUP 屏只接受服务端能够映射机构组范围的数据源配置；不能用无法建立 org_code 约束的自定义 SQL 绕过机构组范围。

## 4. 编辑和保存画布

1. 通过 GET /api/screen/admin/canvas/{id} 加载草稿、区块和当前版本。
2. 在设计器中新增或编辑组件，给需要取数的图表绑定数据源和必要的主体/时间参数。组件类型与数据源能力不匹配时，保存或发布会拒绝。
3. 调用 POST /api/screen/admin/canvas/save 保存草稿，并携带 screenId、expectedVersion 和当前组件/区块数据。服务端会同步处理区块增删改单和版本 CAS。
4. 保存成功后使用响应中的新版本继续编辑；版本冲突时放弃本地旧版本，重新加载后合并。
5. 地图点位使用 GET /api/screen/admin/map-points 查看，确认后通过 PUT /api/screen/admin/map-points 整表覆盖保存。

草稿保存不会改变线上发布态。画布中引用的区块必须属于当前屏；重复、缺失或无法验证的 blockId 不能进入发布流程。

## 5. 预览、发布和回滚

### 5.1 草稿预览

使用 GET /api/screen/view/{screenCode}?preview=draft 读取草稿渲染包。该状态仅供具备屏管理权限的登录用户预览；普通查看者只能读取发布态。

### 5.2 发布

1. 发布前确认组件、区块、数据源、业务条线、机构范围和角色白名单。
2. 调用 POST /api/screen/admin/canvas/publish，提交当前 expectedVersion 和审计原因。
3. 服务端重新校验画布，生成包含组件和可信数据源绑定快照的发布包，更新发布状态并写发布归档。
4. 发布成功后，GET /api/screen/view/{screenCode} 默认读取新的发布包。

发布是高风险操作，线上运行不依赖可变草稿区块。发布包缺少可信绑定、数据源已失效或范围不一致时按 Fail Close 拒绝。

### 5.3 放弃草稿和回滚

- POST /api/screen/admin/canvas/discard：按当前版本放弃草稿，以发布态恢复编辑数据。
- GET /api/screen/admin/canvas/{id}/publish-logs：读取可选发布归档。
- POST /api/screen/admin/canvas/rollback：从指定可信归档恢复发布态，并提交当前版本和审计原因。

回滚不应使用无法证明身份的归档内容；归档校验失败时拒绝操作。

## 6. 运行时取数

- GET /api/screen/view/{screenCode} 获取发布渲染包。
- POST /api/screen/data 按屏、区块、数据源和上下文参数取数。
- GET /api/screen/admin/screens/{id}/map-region-metrics 获取屏范围内地图经营指标。

服务端在运行时重新检查屏状态、屏级角色、机构组、业务条线、数据源快照和 REPORT 数据范围。调用者不能仅通过修改 screenCode、blockId、dsId 或主体参数扩大可见范围。

## 7. 常见问题排查

- 看不到屏：检查 REPORT 资源、屏角色白名单、机构组成员和当前用户数据范围。
- 草稿预览无数据：检查是否具备草稿权限、区块绑定快照是否完整、数据源试跑是否通过。
- 保存提示版本冲突：重新读取画布，确认其他编辑者的变更后再保存。
- 发布被拒绝：依次检查 blockId 双向一致性、数据源能力/条线、机构范围和发布包快照。
- 数据源不能删除：先在草稿、发布包和归档中查找引用；无法确认引用关系时不强行删除。
- 运行时返回拒绝：保留响应错误码和 traceId，核对屏角色、机构组、业务条线及数据范围，而不是把失败改成空数据展示。
