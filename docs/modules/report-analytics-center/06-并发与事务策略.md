# 报表分析中心 — 并发与事务策略

> 模块：report-analytics-center
> 口径：本文描述当前 Service 和 Mapper 的事务、状态及并发边界；不把旧的执行计划或性能数字写成契约。

## 1. 总体原则

- 报表查询只读上游业务数据；本模块不在查询请求中写入上游状态。
- 自有表的写入由 Service 控制，跨模块查询不与上游写事务拼接。
- 文件上传、下载和对象绑定由 governance 的 FileApi 完成，文件对象不作为报表数据库事务的替代。
- 权限、本人归属和 REPORT 数据范围在读写服务层再次校验；并发冲突或范围解析失败按 Fail Close 处理。

## 2. 查询方案

RPT_SAVED_QUERY 的保存、更新和删除在 Service 事务内执行。更新前检查方案归属，更新 SQL 同时带 id、emp_id 和 expectedVersion 条件；命中行数为零时返回版本冲突，不覆盖其他标签页的新内容。新增方案的数量约束和淘汰逻辑由当前 Service 实现执行，调用方不应自行推导上限。

## 3. 自由报表

Excel 导入在一个 Service 事务中完成批次和行数据写入；行数据使用批量 Mapper 写入，解析或持久化失败会回滚本次导入。相同操作人和报表名称的旧批次先移除其行数据和批次记录，再写入新批次；旧的共享文件对象不在替换流程中擅自删除。

批次状态变更、查询和下载按操作人及数据范围校验。批次删除先删除数据库中的行和批次，再按当前 FileApi 规则处理文件对象；文件服务失败不应伪造数据库删除成功以外的状态，也不得据此删除其他批次可能仍引用的共享对象。

## 4. SQL 探查与导出

### 4.1 探查执行

执行流程为：安全校验 → 写入 SQL_PROBE_HISTORY 的运行中记录 → 获取只读连接并执行 → 写入 SUCCESS、TIMEOUT 或 FAILED 终态 → 审计。并发控制在执行服务内完成；获取连接、SQL 超时、数据库异常或并发拒绝都会留下可查询的失败信息。历史详情仅允许本人访问。

SQL 探查使用独立只读数据源和查询超时；安全校验、结果限制和连接只读属性不能由调用方绕过。审计或历史更新失败不能掩盖原始执行结果，也不得向响应泄露内部凭据和连接信息。

### 4.2 SQL 导出

SQL 导出先校验并写入本人任务，再提交专用线程池。后台线程负责只读查询、生成 Excel 或压缩文件、通过 FileApi 上传并绑定文件引用，最后更新 SUCCESS 或 FAILED 和完成信息。任何异常都必须结束任务，不能长期停留在运行中；只有任务成功且存在文件引用时允许下载。

### 4.3 通用导出任务

动态查询、触达、绩效和客户池提交入口先登记 RPT_EXPORT_TASK 并返回任务标识。统一导出服务按当前策略维护 PENDING、RUNNING、SUCCESS、FAILED、CANCELLED 状态；当前部分策略在创建调用内执行，不能仅根据表名或 taskId 宣称后台异步。任务查询、取消和下载按 operator_id 做归属校验，终态任务不可重复取消，非成功任务不可下载。

## 5. 大屏并发和事务

### 5.1 屏元数据

创建、元数据更新、屏删除、地图点位覆盖和角色白名单覆盖由各自 Service 事务完成。元数据和角色保存使用当前画布版本做条件更新；expectedVersion 不匹配时拒绝写入。屏、角色、数据源和区块的归属及引用关系在事务内检查。

### 5.2 画布双态

画布保存事务同时处理 RPT_SCREEN 的版本 CAS 和 RPT_SCREEN_BLOCK 的增删改单；任一步失败则整体回滚。发布事务校验草稿组件、区块绑定、数据源能力、条线和机构范围，生成包含可信绑定快照的发布包，写入发布状态和发布日志。回滚从受信发布归档恢复发布包；放弃草稿以发布态恢复编辑数据。

已发布渲染包是运行时事实，不能在运行时用当前可变草稿区块补齐缺失绑定。数据源更新或删除若无法证明不会影响草稿、发布包或归档，直接拒绝。

## 6. 缓存与降级

代码化大屏沿用上述事务和发布协议。放弃草稿时，组件和 `canvasStyle` 必须在同一次版本 CAS 中恢复，防止代码模板声明与恢复后的组件类型错配。数据源列表只在本次请求内预读屏、区块和发布归档并建立引用索引；写入/删除前仍重新读取并校验引用，不复用列表结果或跨请求缓存。

Caffeine 缓存只用于仪表盘、汇总和元数据等查询加速，不存放任务终态、屏授权或数据范围判定。缓存失效后可回源查询；缓存异常不得扩大可见范围。跨模块 API 或只读数据源不可用时，按接口错误或既有空结果语义返回，不将半成品结果标记为成功。
