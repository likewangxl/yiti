# 代码化经营大屏

## 展示与绑定

`branch-overview-v1` 模板由 Vue 组件组织布局，由图表组件和真实行政区几何展示数据。省级总览点击城市打开市级全景；市级地图与支行列表按机构编码联动。页面几何和风格随代码发布，数据源与字段绑定随大屏草稿/发布配置管理。

管理入口沿用 `/screen-admin/designer` 的已授权资源，页面内容改为“大屏管理”。数据源维护仍在 `/screen-admin/datasources`。历史发布画布仍可展示；新模板不依赖拖拽设计器定位。转换只替换当前草稿，已发布屏不因未发布编辑发生改变。

绑定步骤：选择屏 → 选择展示内容（自动配置明确候选，或一键配置空白内容）→ 核对/修改来源、字段和原始单位 → 保存草稿 → 验证已保存草稿数据 → 预览 → 数据和口径核对通过后填写原因发布。版本冲突保留本地编辑，重新加载并合并；不能自动以旧配置覆盖新版本。拖拽编辑器、属性面板及专用 store 已删除，历史发布包仍可只读展示。

默认来源按当前条线、范围和返回粒度过滤；一行指标要求明确的一行来源，机构比较使用按机构结果，趋势使用按日期结果。等价的一行宽表候选可消歧，真正不同范围仍保留歧义；不将月均变化映射成时点净增，不将对公贷款映射成全行贷款。新批次金额列以 `columnsMeta.unit=YUAN`（元）作为原始单位，展示为亿元只是前端换算；`TEST` 发布配置允许显式单位覆写支持联调演示，但不代表正式签认，未经业务确认不得标为 `PROD`。身份字段不需要金额单位。来源返回空值仍是数据缺口，自动配置不意味着已经取数成功。

“验证已保存草稿数据”与下述静态接入检查独立：它使用服务端草稿身份取数，最多并发三项；未保存绑定、跨屏身份、版本变化、权限失败均废弃结果。显示每项返回行数、缺失、重复、日期和覆盖，零值中性展示；授权目录未返回时不能给出覆盖率，支行趋势只核验一个授权样本。该功能不证明指标业务口径与单位正确，也不自动发布。

分行顶部经营摘要只展示存款较上月变动、距目标的差距（或超额）与未完成目标的机构数量；以完整业务句子表达，并区分未提供完成率的数据。数据覆盖检查保留在配置核验中，混用净增/变化率/趋势的“下降机构数”不再放入经营摘要。地市顶部只展示本市目标完成家数及整体目标进度，支行存款位次和中位余额差放在选中支行详情中；切换支行不改变市级摘要。完成率是否达到100%依据原始数值，不能因显示舍入将99.99%误判为达标。

业务构成使用 `CompositionBreakdown` 的100%横向构成带和组成明细，替代大面积矩形树图；分段长度按占比，名称、占比和金额在明细中展示，避免图内外重复。只有统一明确单位、全部有限非负且合计大于零才计算金额占比；百分比来源仅在合计100%的浮点容差内绘制，不重新归一化。缺值、混单位、负值、全零或溢出保留原明细并说明不能计算，微小正值不会被格式化为零。

分行和市级经营摘要使用柔和蓝青色，不再整句标红；净减、未完成等含义由完整文字表达，错误提示和其他指标的颜色规则不受影响。可切换指标的 TOP10 经营矩阵、机构目录与趋势保留。地市不自动汇总父子机构或平均完成率。内容高度不足时保留可读行高和趋势图，通过页面或弹窗滚动访问。

三维地图使用 WebGL2，静态场景在数据、尺寸和交互变化时绘制，不持续空转。创建、绘制、尺寸变化或重建出错，以及运行中上下文丢失时，隐藏故障 canvas 并切换为基于同一真实行政区几何的 SVG 地图，继续支持缩放和机构选择。组件卸载时释放场景与 WebGL 上下文，避免反复切城累积资源；二维回退不代表机构没有数据，也不补造位置。

管理页增加“真实数据接入检查”，逐槽展示已选择的来源、字段、原始单位、周期、配置错误和待核对风险。它只作静态预检，不执行取数，不意味着数值正确、已联调或已发布；机构画像和当前屏直接机构组检查在点击后才读取管理接口。缺状态画像不再当作启用，格式错误与权限错误不伪装成零条。

业务构成支持“分类行”与“对公/零售两列”两种模式。切换模式清除另一模式的字段及单位；两列模式只支持机构指标宽表，并要求查询结果恰好一行。两列单位同属金额或比例，不能把交叉口径或父子机构汇总直接叠加。未填单位、非数值、缺列或多行将提示错误，不能以零或首行替代。

## 存储与身份

使用既有 `CANVAS_STYLE_JSON` 中强类型字段：

```json
{"presentation":{"type":"CODE","template":"branch-overview-v1"}}
```

旧声明继续兼容。启用可配置展示时，在同一节点增加可选子协议：

```json
{"presentation":{"type":"CODE","template":"branch-overview-v1","displaySchemaVersion":1,"display":{"components":[]}}}
```

展示组件支持指标卡、完成情况、趋势、公司/零售结构页签、排名、地图和明细表；标题、系列/列、单位、顺序、显隐与白名单交互使用类型化字段。它们只引用当前屏已有blockId，不替代 `bindJson`、权限或发布快照。协议字段、标题继承和单位规则见 [经营大屏展示子协议](../../screen-display-refactor/PRESENTATION_CONTRACT.md)。

版本号必须与 `display` 同时存在且位于presentation根。旧包未声明时走原展示；未知版本、字段或枚举拒绝。保存与组件树共用 `canvas_version` CAS；发布将display原样纳入不可变包，回滚/放弃草稿恢复同一版本。首次创建block后再保存展示引用，不将客户端临时ID持久化为数据身份。

新展示协议发布包还会在每个 `bindSnapshots` 项中写入服务端生成的 `sourceDefinition`。它固定来源类型、结果形状、条线、查询配置和周期配置，并用规范化SHA-256检测篡改；不接受客户端快照，也不保存连接凭据。运行时数值仍来自实时/既有批次业务结果，当前数据源停用、删除或不再满足权限时继续Fail Close。编辑共享数据源只影响新草稿和后续发布，不能静默改变已有新协议发布页；旧协议发布包保持历史兼容。

每个已配置数据槽位保存为现有 `ChartWidget` 绑定节点，`propValue.bindingKey` 表示稳定语义，`blockId` 仍由服务端管理。其 `bindJson` 包含 `dsId`、`period`、`fields`（语义名到响应列）和 `units`（原始输入单位）。代码模板忽略历史位置字段，但不忽略绑定身份。

周期复用现有取数契约：`LATEST`、`LAST_10D`、`LAST_1M`、`LAST_6M_EOM`。趋势默认近六个月月末，其余指标默认最新数据；本模板暂不开放需要额外起止日期的 `RANGE`。字段候选按维度/指标角色过滤；服务端保存和发布时仍校验列存在性及角色，不信任浏览器选择结果。字段候选来自已保存语义元数据和引擎确定的维度列，例如机构分组的 `org_code`、`org_name` 及日期分组的 `data_date`；不根据列名称猜测存贷款业务含义。

槽位：`deposit`、`depositIncrease`、`depositAverage`、`loan`、`customers`、`revenue`、`rate`、`trend`、`composition`、`ranking`、`attention`、`branches`、`branchTrend`、`citySummary`。未绑定项显示缺失状态。CODE 至少配置一个有效槽位；重复、未知槽位或非法字段声明拒绝保存/发布。发布包的组件和绑定快照必须一一对应，仍校验区块归属、条线和机构范围。

分行总览以中央地图为主，左右组织存款经营、业务构成、流程与经营关注、机构排名和目标进度，趋势可切换余额与净增。新增语义保持独立，不根据余额推算或复制：

| 展示内容 | 绑定字段 | 口径与缺失处理 |
| --- | --- | --- |
| 存款较上月净增 | `depositIncrease.value` | 金额单值；允许零和负数，必须由来源计算净增 |
| 存款月均余额 | `depositAverage.value` | 金额单值；不能用当前时点余额替代 |
| 净增趋势 | `trend.depositIncrease` | 日期序列；`trend` 至少映射余额、贷款或净增之一；`branchTrend` 保持原字段契约 |
| 机构排名与明细 | `ranking.value`、可选 `increase` / `average` | `value` 继续表示存款余额，另两项分别为净增/月均余额；切换排序只使用所选字段，缺失不填零 |
| 流程与经营关注 | `attention.label` / `count` | 使用明确配置的数据源事项与数量，不推断流程状态，也不相加可能重叠的事项 |

新增金额字段仍要求 METRIC 输出列，并由 `columnsMeta.unit=YUAN` 声明原始元单位；展示层是否换算为亿元不改变原始单位。计数和百分比列分别遵循 `COUNT`、`PERCENT`，不能用展示缩放值冒充原始单位。两个新单值槽与余额槽同样支持可选的比例 `change` 和维度 `date`。原十二槽配置仍有效；保存含新字段的配置前，须先部署兼容的新后端校验器，不能只更新前端。没有新增 REST 路径、资源授权或表结构。

不新增表、自动迁移或无授权 REST 入口。已有资源、草稿/发布权限、原因审计、CAS 和归档校验继续适用。放弃草稿时，在同一 CAS 中恢复发布态样式及组件，防止模板声明与组件版本分离。

## 机构、地域与权限

NAMED_GROUP 的代码模板运行响应提供 `panoramaInstitutions`。服务端根据屏级同角色授权的机构集合，调用 auth 公开机构画像 API，逐编码校验后输出最小字段。额外返回的机构不得泄漏，授权成员缺失/失效或查询异常拒绝。

- 机构组是直接成员集合，不会因为存在 `ownerOperatingOrgCode` 自动授权其子机构。要展示的支行必须纳入获准的机构组。
- `cityCode` 表示地图城市归属，`ownerOperatingOrgCode` 表示经营组织关系，两者不能互相猜测或替代。
- DEPARTMENT 不作为支行地图节点。无坐标机构仍可进入列表，坐标必须合法、成对且为 GCJ02 才允许标注。历史演示坐标不会作为真实坐标下发。
- LEGACY_CONTEXT 不从空授权集合推导全量画像。该模式需要数据源显式提供机构/城市字段；缺少映射时应补配置，不能从机构中文名称猜归属。
- 机构指标采用授权目录左连接数据源 `org_code`，缺指标保留机构和 null。NAMED_GROUP 的 `branches` 数据源必须为 `ORG_INDEX_RESULT` 宽表、按主体聚合，不能混用多机构日期汇总。
- 选择支行后，`branchTrend` 请求携带 `contextParams.orgCode`；后端验证其属于授权集合后，只收窄不可变批次的响应行，批次选择仍按完整授权机构组执行。越权机构拒绝，未传机构仍按原授权集合查询。

省级中央地图的“机构目录”仅消费同一授权机构模型，支持名称/编码搜索、待定位及城市待维护筛选。没有城市或坐标的机构仍可查看已绑定指标和单机构趋势；目录不请求全量管理名单，也不生成虚构城市或坐标。

市级汇总使用明确配置的 `citySummary`，身份映射为 `cityCode` 或 `orgCode`（至少一个）。机构编码只通过服务端授权画像目录解析城市；来源必须已有城市汇总口径。每城市出现多行则拒绝该城市汇总并提示重复，不会覆盖或自动相加，也不推定 PRIMARY 机构就是全市汇总。缺少汇总来源时显示未绑定，不能累加有上下级关系的所有机构，也不能把分行总量显示为城市总量。

## 数据质量与刷新

金额模型的原始单位由 `columnsMeta.unit=YUAN`（元）声明，前端按展示配置换算为亿元；客户模型原始单位为 `COUNT`（户），展示可换算为万户；完成率和变动率使用 `PERCENT`（百分数）。`DIM` 列不声明单位，展示缩放配置不能替代原始单位声明。`TEST` 联调允许显式单位覆写支持演示，但未正式签认的口径不得标为 `PROD`。零值与缺失值分开，禁止以演示值补齐失败请求。

独立请求并发有上限，相同请求去重；路由、屏配置和支行切换会废弃旧代际响应。权限失败清除本轮数据。关注项、图例和周期只展示绑定数据实际支持的能力。取数仍受服务端最大行数限制，机构覆盖和数据完整性不能仅由一张可见截图证明。

启用 `batchPolicy` 的分行源以不可变批次的 `quality` 为运行时质量事实：`sourceAsOf`、`dataDate`、`version`、`mixedPeriod`、机构覆盖、失败候选日期和 `status` 随每次响应返回。`STALE` 继续展示同一完整批次并提示年龄；`NO_COMPLETE_BATCH` 清空 rows 并显示缺失原因；`PARTIAL` 或机构覆盖不足不生成汇总。静态 `sourceAvailability` 只用于解释配置层可用性，不能覆盖运行时质量。

## 统一大屏入口

`/#/screens` 只列出“分行经营总览”和“零售经营总览”手写页面。受保护的 `/screen-pages/:template` 先通过后端目录核验权限，再展示对应 Dashboard；当前分行数据模式为 `TEST`、零售数据模式为 `DEMO`，页面分别保留测试/演示标识。目录按关联屏记录的启用状态、角色与机构范围过滤，不依赖历史画布发布包。此入口与以下 DEV/public 视觉预览路由独立，不能从目录跳入 public 预览绕过权限。

## 本地预览与上线验证

`/screen-preview` 只在 Vite 开发环境注册，明确标识本地演示，使用独立确定性示例数据，不调用业务 API，不进入生产路由。它用于验证两张已确认视觉稿和市/支行交互，不代表远端真实指标已全部绑定。

真实上线须核对机构组成员、坐标、数据源字段与口径，使用实际权限账户预览已保存草稿，再经发布流程切换。共享 `yiti` 的配置或权限写入遵守仓库数据库门禁；视觉验收不构成写入授权。

## 零售经营总览

`retail-overview-v1` 沿用中央地图与经营分析结构，独立展示零售 AUM、储蓄、收入、价值客户、个贷规模及不良率，提供客户分层、机构贡献/短板、金额目标与经营关注。管理页按模板显示对应槽位；零售模板要求 RETAIL 屏和来源，不能用全行字段自动补齐。分行/零售预览可互相切换，零售开发态入口为 `/screen-preview/retail`。具体口径、字段及真实接入边界见 [零售设计与验收](../../retail-screen-design-and-acceptance.md)。
