# 报表分析中心 — 后端架构

> **模块**: report-analytics-center
> **技术栈**: Spring Boot 3.2.3 + JDK 17 + MyBatis 3.0.3 + MySQL 8.0 + Redis 6.X
> **版本**: V1.0
> **最后更新**: 2026-04-10

---

## 1. 模块职责边界

### 1.1 负责的事项
| 类别 | 内容 |
|------|------|
| 动态指标查询 | 维度选择、指标组合、对象选择、结果展示 |
| 固定管理报表 | 分行行长仪表盘、触达任务监控、绩效汇总、客户池统计 |
| SQL 探查 | 受限 SQL 执行、安全校验、审计记录 |
| 快照任务 | V1 可选，将常用查询结果落地为快照 |
| 统计展示接口 | 为前端提供图表所需的聚合数据 |
| 查询方案管理 | 用户个人查询方案的 CRUD |
| 异步导出 | 大数据量报表的后台导出任务 |

### 1.2 不负责的事项
- **不反向写业务数据**：不持有业务状态，不调用业务模块的写接口
- **不承担审批流转**：审批由 workflow-center 处理
- **不作为业务查询中转站**：不为其他模块提供借道查询
- **不做实时聚合**：聚合由 performance-engine-center 完成

## 4. 分层规范

### 4.1 Controller 层
**职责**：
- 接收 HTTP 请求
- 参数校验（`@Validated`、`@NotNull` 等）
- 调用 Facade / Service
- 包装统一响应 `CommonResult<T>`
- 不含业务逻辑

**规范**：
- 所有 Controller 必须加 `@RestController` + `@RequestMapping`
- 所有接口必须加 `@BizAuth` 注解
- 所有接口必须有 Swagger 注解（`@Operation`、`@Parameter`）
- 请求路径规范：`/api/reports/**`

**示例**：
```java
@RestController
@RequestMapping("/api/reports/dynamic-query")
@Tag(name = "动态指标查询")
public class DynamicQueryController {

    @Resource
    private DynamicQueryFacade dynamicQueryFacade;

    @PostMapping
    @BizAuth(bizType = BizType.REPORT, action = BizAction.LIST)
    @Operation(summary = "执行动态查询")
    public CommonResult<DynamicQueryRespDTO> execute(
            @Validated @RequestBody DynamicQueryReqDTO req) {
        return CommonResult.success(dynamicQueryFacade.execute(req));
    }
}
```

### 4.2 Facade 层
**职责**：
- 跨模块编排（调用多个外部 Api）
- 调用多个本模块 Service
- 不含具体业务逻辑

**规范**：
- Facade 只做编排，不包含核心业务规则
- Facade 返回 DTO，不返回 Entity
- 跨模块调用的异常必须捕获并转换为本模块错误码

### 4.3 Service 层
**职责**：
- 核心业务逻辑
- 权限校验（Service 层二次校验）
- 数据访问（通过 Mapper）
- 缓存管理

**规范**：
- Service 只读方法无需 `@Transactional`
- 写方法（仅 `rpt_saved_query`、`sql_probe_history`）必须 `@Transactional`
- 所有 public 方法必须有中文注释
- Service 接口与实现分离

### 4.4 Mapper 层
**职责**：
- 本模块私有表的读写（仅 `rpt_saved_query`、`sql_probe_history`、`rpt_snapshot_task`）
- 不允许查询其他模块的私有表

**规范**：
- 所有 SQL 必须写在 XML 中
- 禁止使用 `@Select` 等注解方式
- XML 中禁止出现 `SELECT *`

### 4.5 Entity 层
**职责**：
- 对应数据库表
- 使用 Lombok `@Data`
- 时间字段使用 `LocalDateTime`

**规范**：
- Entity 不暴露给外部模块
- Entity 中禁止包含业务逻辑

## 5. SQL 探查安全校验层

### 5.1 独立的 SqlValidationService
`SqlValidationService` 是 SQL 探查的安全核心，负责：

#### 5.1.1 SQL 语法解析
- 使用 [JSqlParser](https://github.com/JSQLParser/JSqlParser) 解析 SQL
- 解析失败直接返回 `RPT-42001`

#### 5.1.2 语句类型校验
- 只允许 `SELECT` 语句
- 校验 `Statement instanceof Select`
- 非 SELECT 返回 `RPT-40001`

#### 5.1.3 表白名单校验
- 遍历 AST 中所有涉及的表（包括子查询、JOIN、UNION）
- 校验每个表是否在 `sql.probe.schema-whitelist` 配置中
- 不在白名单返回 `RPT-42002`

#### 5.1.4 禁用关键字校验
- 使用正则匹配危险关键字
- 关键字列表：`DROP|DELETE|UPDATE|INSERT|TRUNCATE|ALTER|CREATE|GRANT|REVOKE|CALL|EXEC`
- 存在返回 `RPT-42003`

#### 5.1.5 LIMIT 追加/校验
- 解析 SQL 后检查是否有 `LIMIT` 子句
- 无 LIMIT：自动追加 `LIMIT 1000`
- 有 LIMIT 但超出 1000：替换为 `LIMIT 1000`
- 有 LIMIT 且合规：保留

#### 5.1.6 子查询/JOIN/UNION 合规校验
- 递归检查所有子查询中涉及的表
- 每个表都必须在白名单中
- 不合规返回 `RPT-42002`

### 5.2 SqlExecutor 执行器
- 使用独立的 `DataSource`（配置低权限数据库账号）
- 超时控制：`statement.setQueryTimeout(30)`
- 并发控制：`Semaphore(10)`
- 结果集限制：`statement.setMaxRows(1000)`
- 异常处理：超时返回 `RPT-42005`，并发超限返回 `RPT-42006`

### 5.3 配置示例
```yaml
sql:
  probe:
    schema-whitelist:
      - rpt_saved_query
      - sql_probe_history
      - perf_kpi_snapshot
      - perf_org_summary
      - perf_customer_contribution
      - v_customer_pool
    query-timeout-seconds: 30
    concurrent-limit: 10
    max-rows: 1000
    max-sql-length: 5000
    forbidden-keywords:
      - DROP
      - DELETE
      - UPDATE
      - INSERT
      - TRUNCATE
      - ALTER
      - CREATE
      - GRANT
      - REVOKE
      - CALL
      - EXEC
```

## 8. 缓存设计

### 8.1 缓存 Key 约定
| Key 前缀 | 用途 | TTL |
|----------|------|-----|
| `report:dashboard:president:{dataVersion}` | 分行行长仪表盘 | 30 分钟 |
| `report:metric-tree:{dim}` | 指标树 | 1 小时 |
| `report:valid-data-version` | 有效数据版本 | 5 分钟 |
| `report:org-tree:{empId}` | 用户可见机构树 | 15 分钟 |
| `report:summary:touch-task:{dataVersion}` | 触达任务汇总 | 15 分钟 |
| `report:summary:perf:{dataVersion}` | 绩效汇总 | 15 分钟 |
| `report:export:task:{taskId}` | 导出任务状态 | 24 小时 |

### 8.2 缓存失效
- 订阅 `performance.sys-control.updated.v1` 事件时，删除所有 `report:dashboard:*`、`report:summary:*`、`report:valid-data-version` 缓存
- 订阅 `performance.kpi-calc.completed.v1` 时，删除对应 dataVersion 的缓存
- 订阅 `auth.permission.updated.v1` 时，删除该用户的 `report:org-tree:*`

### 8.3 缓存读取规范
- 所有缓存读取必须考虑 Fail-Close：缓存未命中时回源数据库
- 缓存写入失败不应阻塞主流程

## 9. 异步导出设计

### 9.1 导出任务状态机
```
PENDING → RUNNING → SUCCESS
                 ↓
               FAILED
```

### 9.2 任务注册表（Redis）
使用 Redis Hash 存储任务信息：
```
key: report:export:task:{taskId}
fields:
  - empId: 创建人
  - status: PENDING/RUNNING/SUCCESS/FAILED
  - createdTime: 创建时间
  - startedTime: 开始时间
  - completedTime: 完成时间
  - rowCount: 结果行数
  - fileUrl: 文件URL（MinIO）
  - errorMsg: 错误信息
```

### 9.3 执行流程
1. Controller 接收导出请求，生成 taskId，写入 Redis 状态为 `PENDING`
2. 提交到线程池执行
3. 线程池任务：
   - 更新状态为 `RUNNING`
   - 执行查询（复用动态查询引擎）
   - 使用 EasyExcel 生成 Excel 文件
   - 上传到 MinIO
   - 更新状态为 `SUCCESS` 或 `FAILED`
4. 用户轮询任务状态接口获取进度
5. 任务成功后，用户通过下载接口获取文件

### 9.4 线程池配置
```java
@Configuration
public class ReportExportConfig {
    @Bean("reportExportExecutor")
    public ThreadPoolTaskExecutor reportExportExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(5);
        executor.setMaxPoolSize(10);
        executor.setQueueCapacity(50);
        executor.setThreadNamePrefix("report-export-");
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        executor.initialize();
        return executor;
    }
}
```

## 12. 线程安全与并发

### 12.1 共享资源
| 资源 | 并发控制方式 |
|------|-------------|
| SQL 探查并发数 | `Semaphore(10)` |
| 缓存写入 | Redis 原子操作 |
| 导出任务状态 | Redis Hash 原子操作 |

### 12.2 避免的反模式
- 不使用 `synchronized` 锁静态对象
- 不使用 `ThreadLocal` 存储跨请求状态
- 不持有业务状态的 Service 单例
