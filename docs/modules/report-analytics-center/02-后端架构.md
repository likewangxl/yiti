# 报表分析中心 — 后端架构

> 模块：report-analytics-center
> 口径：只保留当前实现中的稳定边界、数据流和安全决策；具体字段与路径分别见本目录的接口、表结构和操作文档。

## 1. 模块边界

报表分析中心是 Spring Boot 模块化单体中的下游查询域。它从上游公开查询 API 或受控只读表读取数据，并维护自身的查询方案、导出任务、SQL 探查记录、自由报表和大屏配置。

报表模块不写入客户、触达、绩效、审批等上游业务状态，不直接调用 workflow-center，也不作为其他模块的查询中转层。当前模块没有对外提供给其他模块使用的公共 API。

## 2. 依赖与分层

### 2.1 当前依赖

- common-web、common-security、common-trace、common-aop、common-db：统一响应、鉴权、链路、审计切面和数据库能力。
- auth-permission-center：当前用户、组织、用户、数据范围、资源和机构组查询。
- system-governance-center：字典、审计、文件对象和下载地址能力。
- customer-marketing-center：客户和触达任务只读查询。
- performance-engine-center：指标、指标快照、KPI、分配预览等只读查询。

依赖以模块 pom.xml 和各上游 api 包为准；跨模块不得引用对方 mapper、entity 或内部 service。report 不能被业务模块当作查询中转层依赖。

### 2.2 层次职责

- Controller：接收 REST 请求、校验 DTO、声明 REPORT 业务鉴权并返回统一响应。
- Facade：编排当前用户、数据范围、文件和报表服务，隔离 Controller 与实体。
- Service：实现查询、事务、权限二次校验、状态转换和审计。
- Mapper：访问本模块自有表及明确登记的只读查询表。
- Entity/DTO：分别对应持久化模型和接口模型；Controller 不直接暴露持久化实体作为可变写入对象。

## 3. 数据流和存储边界

### 3.1 查询路径

动态查询先读取指标元数据和对象候选，再按 REPORT 数据范围过滤对象，最后通过 performance/customer 等公开查询 API 获取指标或业务数据。固定报表和大屏也必须在服务层校验当前用户范围，不能把前端传入的对象集合视为授权结果。

SQL 探查使用独立只读数据源，并在执行前做 SQL 安全校验。其他报表查询默认使用模块主数据源；报表自有写操作只写本模块表。

### 3.2 自有状态

模块自有状态包括保存方案、SQL 探查历史和导出任务、自由报表批次/行、大屏元数据/区块/数据源/地图点位/角色白名单/发布日志。上游表和数据湖表只读；绩效分配调整表在当前实现中是报表历史查询的直接读取例外，不改变报表模块不写上游状态的边界。

文件内容和下载 URL 由 governance 的 FileApi 管理。报表任务保存文件引用，不另建对象存储实现。

## 4. 关键架构决策

### 4.1 事务与并发

- 保存方案更新使用版本条件做乐观锁，并检查本人归属。
- 大屏画布和屏元数据使用版本条件做乐观锁；画布保存、发布、回滚、放弃草稿分别走明确的服务事务。
- 发布包包含组件和可信的数据源绑定快照；运行时读取发布包，不以可变草稿区块给已发布版本补证。
- 自由报表按报表名称替换本人旧批次时，批次和行数据在同一事务内处理，不删除共享文件对象。
- SQL 探查历史和 SQL 导出任务在执行、失败、超时和文件关联异常时更新可查询的终态。
- 任何跨模块读取失败均按当前请求失败或既有降级语义处理，不把不完整结果伪装成成功。

### 4.2 缓存

当前缓存由 report 的 Caffeine CacheManager 提供，并作为默认 CacheManager 供相关查询使用。缓存只用于查询加速，不能作为权限、发布状态、任务状态或业务数据的事实来源；失效或读取异常不得放宽数据范围。

### 4.3 大屏运行时

大屏管理端将元数据、数据源和画布分开维护。运行端默认读取发布态渲染包，草稿预览是受管理权限保护的显式状态。发布前校验组件与区块绑定、业务条线、机构范围和数据源能力；运行时继续校验屏角色白名单、机构组和 REPORT 数据范围，异常按 Fail Close 处理。

## 5. 安全与可观测性

每个业务 Controller 方法声明匹配的 REPORT BizAction 和 PT_RESOURCE。高风险 SQL 执行、SQL 导出、数据源试跑/列探测、大屏发布/回滚、角色白名单覆盖和删除使用独立授权及服务层审计。统一链路记录 traceId、耗时和结果；SQL、账号、文件标识等敏感内容按脱敏规则记录。
