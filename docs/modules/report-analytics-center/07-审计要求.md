# 报表分析中心 — 审计要求

> 模块：report-analytics-center
> 口径：审计动作和字段以当前 Controller、Service 与统一审计基础设施为准；不在本文固化保留年限、告警阈值或资源数量。

## 1. 统一要求

- REST 方法使用 REPORT 业务类型、匹配的 BizAction 和 PT_RESOURCE。
- 请求链路记录 traceId、操作人、资源 URL、HTTP 方法、结果和耗时。
- 所有读、详情、导出和下载先做当前用户及数据范围校验；拒绝结果保留统一错误语义。
- 写入本模块自有表的操作由 Service 审计和事务共同保护，Controller 不以日志替代审计。
- 审计记录不得包含密码、连接串、文件内容或未脱敏的账号、手机号、证件号和金额；SQL 文本按实现规则截断或脱敏。

## 2. 必须留痕的敏感动作

### 2.1 SQL 探查

SQL 执行和 SQL 导出使用 EXECUTE_SQL 业务动作及独立资源授权。记录操作人、历史或任务标识、请求来源、remark、校验后的 SQL 摘要、结果状态和错误原因。安全校验失败、并发受限、超时、数据库失败、文件上传或绑定失败都应留下可追踪的历史/任务状态；历史详情和导出文件仅允许本人访问。

SQL 执行需要审计原因。审计写入失败不应掩盖原始执行错误，也不得让调用方绕过安全校验继续执行。

### 2.2 大屏和数据源

以下操作使用独立资源、显式审计原因和服务层审计：

- 数据源创建、更新、删除；
- 配置态数据源试跑和已保存数据源列探测；
- 屏元数据、机构范围和查看角色白名单变更；
- 画布发布、回滚和放弃草稿；
- 屏删除、地图点位覆盖保存等配置写操作。

配置审计应包含目标类型和标识、请求方法和 URL、expectedVersion、原因、前后快照及新增/删除项。数据源配置、试跑和高危画布动作审计不能只写应用日志；治理审计不可用时按当前 Service 的 Fail Close 或既有拒绝语义处理。运行时因屏角色、机构组、业务条线或数据范围被拒绝时，记录拒绝码和最小必要上下文，不能记录完整敏感数据。

代码化大屏复用已有配置与运行时端点，不新增审计旁路。市级视图选中支行时，`contextParams.orgCode` 只能收窄到已授权机构组成员；组外机构必须拒绝。返回的机构目录只包含经营身份、城市归属和可用坐标，不返回画像备注、审计字段或其他管理信息。

### 2.3 导出、自由报表和方案

导出任务创建、取消、成功/失败、文件关联、下载和归属校验应通过统一链路日志及任务状态可追踪。自由报表导入、批次状态变更、删除和文件下载记录操作人、批次标识、报表名称、结果和数据范围判定；不记录文件内容。保存方案的新增、更新、删除至少保留请求身份、方案标识、版本结果和操作结果，不能越权读写他人方案。

仪表盘和固定报表的敏感读取按当前 Service 的审计实现留痕；审计失败按对应查询的 fail-soft 或错误处理语义执行，不能扩大数据范围。

## 3. 审计数据最小化

1. targetType 和 targetId 使用业务表和记录标识，不把完整请求体当作长期审计快照。
2. beforeSnapshot、afterSnapshot、addedItems、removedItems 只保存复核所需结构化差异。
3. SQL 探查、文件和数据范围字段按统一脱敏规则处理；日志中禁止输出凭据和完整文件内容。
4. 审计记录与任务状态、数据库变更应能通过 taskId、historyId、screenId 或 batchId 关联。
5. 审计记录的读取同样受治理域权限和数据范围保护；本文不新增额外查询入口。

## 4. 核查要点

发布、回滚、角色覆盖、数据源试跑/列探测、SQL 执行/导出和文件下载发生异常时，核对三件事：授权是否先于业务动作、业务状态是否处于可解释终态、审计或统一链路是否留下最小可追踪信息。不能用“接口返回成功”替代数据库状态和审计结果核验。
