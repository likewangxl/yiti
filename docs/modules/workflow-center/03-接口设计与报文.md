# 工作流中心——接口设计与报文

本文只描述当前实现可调用的 REST 契约。响应遵循平台 `ResponseWrapper`；分页结果为
`PageResult<T>`。除流程图 PNG 外，成功业务数据均放在统一响应体中。认证过滤器、资源
匹配器和服务层权限校验均有效；是否标注 `@BizAuth` 不能被理解为公开接口。

## 1. 任务 REST

根路径：`/api/workflow/tasks`。

当前任务查询和办理 Controller 未逐方法声明 `@BizAuth`，通过统一认证、资源登记和
当前员工过滤进入；服务层必须再次校验任务归属、候选资格和转交锁。

| 方法 | 路径 | 参数/请求体 | 成功响应 | 关键失败 |
| --- | --- | --- | --- | --- |
| GET | `/api/workflow/tasks` | `bizType?`、`keyword?`、`pageNo`（默认 1）、`pageSize`（默认 20） | `PageResult<TaskRespDTO>` | 参数校验、认证失败 |
| GET | `/api/workflow/tasks/done` | 同上 | `PageResult<TaskRespDTO>` | 参数校验、认证失败 |
| GET | `/api/workflow/tasks/{taskId}` | 路径 `taskId` | `TaskDetailRespDTO` | `WF-40403`、访问无权 |
| POST | `/api/workflow/tasks/{taskId}/claim` | 无请求体 | 空成功响应 | `WF-40403`、`WF-40904`、`WF-40913` |
| POST | `/api/workflow/tasks/{taskId}/approve` | `ApproveReqDTO` | 空成功响应 | `WF-40403`、任务未拥有、转交锁、引擎并发错误 |
| POST | `/api/workflow/tasks/{taskId}/reject` | `RejectReqDTO` | 空成功响应 | `WF-40403`、意见为空、任务未拥有、转交锁 |

### 1.1 请求体

```json
{
  "opinion": "审批意见",
  "formData": {
    "routeVariable": "value"
  }
}
```

`ApproveReqDTO.opinion` 可空，最长 500 个字符；`formData` 可空，用作节点表单或路由
流程变量。`RejectReqDTO.opinion` 必填，最长 500 个字符。驳回是当前实现的终止路径，
不表示任意运行时退回。

## 2. 流程 REST

根路径：`/api/workflow/processes`。提交和撤回由服务层补齐当前员工/机构并做业务守卫；
流程查询通过流程 ID访问，访问控制不能只依赖前端入口。

| 方法 | 路径 | 参数/请求体 | 成功响应 | 关键失败 |
| --- | --- | --- | --- | --- |
| POST | `/api/workflow/processes/submit` | `ProcessSubmitReqDTO` | `WorkflowLaunchResp` | `WF-40401`、`WF-40901`、校验失败 |
| POST | `/api/workflow/processes/{processInstanceId}/cancel` | `CancelProcessReqDTO` | 空成功响应 | `WF-40402`、`WF-40905`、权限失败 |
| GET | `/api/workflow/processes/{processInstanceId}` | 路径 ID | `ProcessInstanceInfo` | `WF-40402` |
| GET | `/api/workflow/processes/{processInstanceId}/diagram` | 路径 ID | `image/png` 原始字节 | `WF-40402`、引擎错误 |
| GET | `/api/workflow/processes/{processInstanceId}/history` | 路径 ID | `List<ApprovalLogDTO>` | `WF-40402` |
| GET | `/api/workflow/processes/{processInstanceId}/nodes` | 路径 ID | `ProcessDiagramDTO` | `WF-40402` |

### 2.1 提交流程

`ProcessSubmitReqDTO` 字段：

| 字段 | 约束/含义 |
| --- | --- |
| `bizType` | 必填，业务类型 |
| `bizId` | 必填，业务对象 ID |
| `businessKey` | 必填，最长 100；同一运行中业务键唯一 |
| `processDefinitionKey` | 必填，已部署流程定义键；设计器流程应先解析已发布 `DSN_` 键 |
| `title` | 必填，最长 200 |
| `variables` | 可选的流程变量 Map；由服务层补充启动用户/机构信息 |

返回 `WorkflowLaunchResp`：`processInstanceId`、原始 `businessKey`、首个用户任务的
`firstTaskId`（没有用户任务时为空）。

### 2.2 撤回/取消

`CancelProcessReqDTO` 只有必填的 `reason`（最长 500）。服务层只允许运行中实例的申请
人或系统管理员按当前权限撤回；删除运行时实例后更新映射并发布
`ProcessWithdrawnEvent`。驳回和撤回的流程状态通常为 `CANCELLED`，不能据此推断审批
结论，需结合事件或历史变量。

## 3. 流程映射 REST

`GET /api/workflow/process-map` 返回 `BizProcessMapDTO`，以下两种查询方式二选一：

- `businessKey`；或
- `bizType` 与 `bizId` 同时提供。

三者都缺失时请求无效；找不到映射返回 `WF-40402`。映射字段见第 7 节。

## 4. 监控 REST

根路径：`/api/workflow/monitor`。流程列表明确声明
`@BizAuth(WORKFLOW_MONITOR, LIST)`，服务层仍必须依据 `DataScopeContext` 过滤机构范围。

| 方法 | 路径 | 查询参数 | 成功响应 |
| --- | --- | --- | --- |
| GET | `/api/workflow/monitor/processes` | `status?`、`bizType?`、`keyword?`、`startedBy?`、`pageNo=1`、`pageSize=20` | `PageResult<ProcessMonitorItemDTO>` |

监控范围支持平台定义的全部、本机构和机构树语义；空值、未知范围和无法解析范围返回空
结果。监控只通过本模块映射和机构快照查询，不接收业务模块私有表参数。

## 5. 两阶段转交 REST

发起和候选名单属于监控转交域，声明
`@BizAuth(WORKFLOW_MONITOR, TRANSFER)`；流程转交历史声明
`@BizAuth(WORKFLOW_MONITOR, READ)`。收件箱、发件箱和决策接口由当前登录员工在服务层
判定接收人/发起人，并仍须登记独立 `PT_RESOURCE`。

| 方法 | 路径 | 请求体/参数 | 成功响应 | 关键失败 |
| --- | --- | --- | --- | --- |
| POST | `/api/workflow/monitor/tasks/{taskId}/transfer` | `TransferInitiateReqDTO` | 转交记录 ID | `WF-40403`、`WF-40910`～`WF-40912`、`WF-40918` |
| GET | `/api/workflow/monitor/tasks/{taskId}/transfer-candidates` | 路径 `taskId` | `List<TransferCandidateDTO>` | `WF-40403`、访问无权 |
| GET | `/api/workflow/monitor/processes/{processInstanceId}/transfers` | 路径流程 ID | `List<TransferHistoryDTO>` | 资源/数据范围失败 |
| GET | `/api/workflow/transfers/inbox` | 当前登录员工 | `List<TransferItemDTO>` | 认证失败 |
| POST | `/api/workflow/transfers/{id}/accept` | 路径转交 ID | 空成功响应 | `WF-40914`～`WF-40916`、`WF-40303` |
| POST | `/api/workflow/transfers/{id}/decline` | `TransferDecisionReqDTO` | 空成功响应 | `WF-40001`、`WF-40914`～`WF-40916`、`WF-40304` |
| GET | `/api/workflow/transfers/outbox` | 当前登录员工 | `List<TransferItemDTO>` | 认证失败 |
| POST | `/api/workflow/transfers/{id}/cancel` | 路径转交 ID | 空成功响应 | `WF-40914`、`WF-40915`、`WF-40305` |

`TransferInitiateReqDTO`：`toEmpId`、`reason` 均必填，原因最长 500；
`TransferDecisionReqDTO.reason` 必填且最长 500。发起产生 `PENDING_ACCEPT`，接受方
决策后才改变任务 assignee；待决策任务返回 `WF-40913` 锁定原操作。底层任务消失时
记录进入 `INVALIDATED`。

`TransferCandidateDTO` 返回 `empId`、展示姓名、机构编码和机构名称。
`TransferHistoryDTO` 返回转交 ID、节点、来源/发起/接收员工及姓名、状态、转交/拒绝原因、
发起时间和决策时间。
`TransferItemDTO` 在历史字段外包含流程实例 ID、任务 ID、业务键、业务类型和机构编码，
用于收件箱/发件箱列表。

## 6. 管理配置 REST

根路径：`/api/admin/workflow`；全部端点声明 `@BizAuth(SYS_CONFIG, CONFIG)`。请求体中
出现的实体字段必须按当前表模型校验，不应让前端绕过服务层直接写表。

| 方法 | 路径 | 查询/请求体 | 成功响应 |
| --- | --- | --- | --- |
| GET | `/api/admin/workflow/timeout-rules` | `processDefinitionKey?` | `List<TimeoutRuleRespDTO>` |
| GET | `/api/admin/workflow/timeout-rules/item/{id}` | 路径 ID | `WfTimeoutRule` |
| PUT | `/api/admin/workflow/timeout-rules/{id}` | `TimeoutRuleUpdateReqDTO` | 空成功响应 |
| POST | `/api/admin/workflow/timeout-rules` | `WfTimeoutRule` | 空成功响应 |
| GET | `/api/admin/workflow/node-candidates` | `processDefinitionKey?` | `List<NodeCandidateRespDTO>` |
| GET | `/api/admin/workflow/node-candidates/item/{id}` | 路径 ID | `WfNodeCandidateConf` |
| PUT | `/api/admin/workflow/node-candidates/{id}` | `NodeCandidateUpdateReqDTO` | 空成功响应 |
| POST | `/api/admin/workflow/node-candidates` | Map：流程定义键、节点键、类型、值 | 空成功响应 |
| GET | `/api/admin/workflow/node-forms` | `processDefinitionKey?` | `List<NodeFormRespDTO>` |
| GET | `/api/admin/workflow/node-forms/item/{id}` | 路径 ID | `WfNodeFormConf` |
| POST | `/api/admin/workflow/node-forms` | `WfNodeFormConf` | 空成功响应 |
| PUT | `/api/admin/workflow/node-forms/{id}` | `NodeFormUpdateReqDTO` | 空成功响应 |
| GET | `/api/admin/workflow/process-definitions` | `active`（默认 true） | `List<ProcessDefinitionRespDTO>` |

候选配置至少包含流程定义键、节点键、候选类型和值；表单配置包含字段定义、可编辑和
必填字段；超时规则包含预警小时数和超时小时数。候选、表单、规则必须与当前部署定义
和节点键匹配。具体配置要求见 `08-初始化数据清单.md`。

## 7. 设计器 REST

根路径：`/api/admin/workflow/flows`；全部端点声明 `@BizAuth(SYS_CONFIG, CONFIG)`。

| 方法 | 路径 | 请求体/参数 | 成功响应 |
| --- | --- | --- | --- |
| GET | `/api/admin/workflow/flows/meta/variables` | 必填 `bizType` | `List<FlowVariableDTO>` |
| GET | `/api/admin/workflow/flows/meta/approver-variables` | 必填 `bizType` | `List<FlowVariableDTO>` |
| GET | `/api/admin/workflow/flows` | 无 | `List<FlowDefDTO>` |
| GET | `/api/admin/workflow/flows/{id}` | 路径流程定义 ID | `FlowGraphDTO` |
| POST | `/api/admin/workflow/flows` | `FlowGraphDTO` | 草稿 ID |
| PUT | `/api/admin/workflow/flows/{id}` | `FlowGraphDTO` | 空成功响应 |
| POST | `/api/admin/workflow/flows/{id}/publish` | 路径草稿 ID | 空成功响应 |
| DELETE | `/api/admin/workflow/flows/{id}` | 只能草稿 | 空成功响应 |
| POST | `/api/admin/workflow/flows/import-existing` | 无 | 每个流程导入结果列表 |

`FlowGraphDTO` 由 `name`、`bizType`、`nodes`、`edges` 组成。节点包含 `nodeKey`、类型、
名称、审批模式/机构范围、布局坐标和审批人；边包含起止节点、默认标记、输出名称和
条件。条件由逻辑关系及变量、运算符、比较值组成，只能使用业务类型对应的变量目录。

创建/保存是完整图替换；发布前校验开始/结束、可达性、节点引用、候选、条件和审批模式。
发布部署为 `DSN_<flowKey>` 并记录定义 ID/版本；在途实例不随新发布版本改变。只读导入
定义不能通过草稿保存/删除接口修改。

当前导入入口支持的内置流程定义键为：
`perf_target_adjust_v1`、`perf_alloc_adjust_corp_v1`、`perf_alloc_adjust_retail_v1`。
每个键单独返回成功或失败信息，不应把导入入口当成业务模块启动流程的隐式回退。

## 8. 主要响应 DTO

### 8.1 任务、详情和进度

`TaskRespDTO` 当前字段：

| 类别 | 字段 |
| --- | --- |
| 标识 | `taskId`、`processInstanceId`、`businessKey`、`bizType`、`bizId` |
| 流程 | `title`、`processStatus`、`startTime` |
| 发起人 | `startUser`、`startUserName`、`startUserEmpNo`、`startOrgId`、`startOrgName`、`startOrgDeptNo` |
| 节点 | `taskName`、`nodeKey`、`taskCreateTime`、`assignee`、`candidateGroups` |
| SLA/操作提示 | `slaStatus`、`warningTime`、`timeoutTime`、`claimable` |
| 已办补充 | `completeTime`、`approvalResult`、`opinion` |

`processStatus` 为 `RUNNING`、`COMPLETED`、`CANCELLED`；`slaStatus` 为 `GREEN`、
`YELLOW`、`RED`。`claimable` 只用于界面提示，不能替代服务端鉴权。

`TaskDetailRespDTO` 包含：

- `taskInfo`：任务列表信息；
- `runtimeAccess`：`canClaim`、`canApprove`、`canReject`、`canTransfer`、`isAssignee`、
  `isCandidate` 等提示；
- `nodeFormConf`：流程定义键、节点键、字段定义、可编辑字段、必填字段；
- `processProgress`：流程节点及其状态；
- `approvalLogs`：操作人、节点、动作、意见和时间；
- `outgoingBranches`：仅动态 `DSN_` 流程提供的命名出边和路由变量，静态 BPMN 可为空。

服务层权限结论高于 DTO 提示字段；流程详情/历史访问必须应用统一数据范围。

`ProcessDiagramDTO` 包含流程实例 ID、流程定义键和节点列表。节点字段为任务 ID（用户
任务才有）、节点键/名称/类型、`COMPLETED`/`ACTIVE`/`PENDING` 状态、处理人和起止时间。

### 8.2 流程及监控

`BizProcessMapDTO` 字段：`id`、`businessKey`、`bizType`、`bizId`、`processDefinitionKey`、
`processInstanceId`、`processStatus`、`title`、`startUser`、`startOrgId`、
`currentAssignee`、`candidateGroups`、`startTime`、`endTime`。

流程详情 `ProcessInstanceInfo` 返回流程实例/定义信息、业务键、发起人、当前节点/处理人、
起止时间、耗时和状态。`ProcessMonitorItemDTO` 返回流程实例、业务键/类型/标题/状态、
发起人及其机构、当前处理人及其机构、当前活动任务 ID、起止时间。

### 8.3 历史

`ApprovalLogDTO` 字段为 `nodeKey`、`nodeName`、`operator`、`operatorEmpNo`、
`operatorName`、`operatorOrgName`、`action`、`opinion`、`operateTime`。
动作使用 `SUBMIT`、`APPROVE`、`REJECT`、`CLAIM`、`TRANSFER` 等当前实现值。

## 9. 资源和错误约定

每个实际 REST 方法都必须有匹配的 `PT_RESOURCE` 方法和 URL 注册；资源授权只控制入口，
服务层仍做目标实体、候选人、发起人和机构范围二次校验。错误通过平台统一错误响应返回，
当前工作流错误族包括：

- `WF-40001`：拒绝转交原因缺失；
- `WF-40303`～`WF-40305`：转交接收人/发起人身份不符；
- `WF-40401`～`WF-40405`：流程定义、实例、任务、候选配置或超时规则不存在；
- `WF-40901`、`WF-40904`、`WF-40905`、`WF-40906`：业务键、任务状态或发布校验冲突；
- `WF-40910`～`WF-40916`、`WF-40918`：转交状态、资格、锁或并发冲突；
- `WF-50001`：引擎/基础设施错误。

不要在客户端依赖内部异常文本、Mapper 字段或历史错误码；新增/变更端点时同步本文件、
`04-对外API契约.md`、资源数据和 `scripts/check-contract-docs.sh` 检查。
