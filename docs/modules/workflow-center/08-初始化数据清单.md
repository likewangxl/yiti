# 工作流中心——当前流程、候选与资源配置要求

## 1. 范围

本文只描述当前运行所需的流程、候选、表单、超时和 `PT_RESOURCE` 配置要求，不是种子
数据清单、可执行 SQL 或部署执行顺序。资源/配置的实际值以目标库和 Flowable
RepositoryService 查询为准；本文不固化一次性 ID、角色绑定、日期或历史迁移记录。

## 2. 流程定义配置

### 2.1 静态 BPMN

应用从当前配置的 classpath BPMN 位置加载定义（以 `bootstrap` 的
`process-definition-location-prefix` 和 suffix 为准）。仓库当前可见的静态定义为：

| 流程定义键 | 内容要求 |
| --- | --- |
| `lead_approve_v1` | 发起、审核用户任务、审批/拒绝排他分支和结束 |
| `loan_approve_v1` | 多级审核用户任务、排他网关和审批/拒绝结束 |

每个定义必须可部署、可激活，用户任务的节点键必须与候选、表单、超时配置一致。业务
模块启动前应以 `processDefinitionKey` 明确选择定义；不存在或未激活时 fail fast。

### 2.2 设计器流程

设计器保存完整图（名称、业务类型、节点、边、审批人和条件），发布后使用
`DSN_<flowKey>` 作为部署定义键。发布前必须通过开始/结束节点、可达性、节点引用、
条件变量、审批模式和候选配置校验。发布新定义只供后续启动，不能改写在途实例绑定的
定义版本。

当前内置流程导入入口支持以下 Flowable 定义键，并以只读导入模型保存：

- `perf_target_adjust_v1`；
- `perf_alloc_adjust_corp_v1`；
- `perf_alloc_adjust_retail_v1`。

导入入口的实际部署状态须以目标 Flowable 仓库核验，不得把导入失败静默降级为另一流程。

## 3. 候选人配置

### 3.1 节点规则

每个需要办理的用户任务至少配置流程定义键、节点键、候选类型和值。当前规则可表达：

- `ROLE`：按角色解析候选员工；
- `ORG`：按机构解析候选员工；
- `USER`：指定员工；
- 设计器支持的层级角色、机构角色或流程变量候选（由 `approverType`/目录约束）；
- `approveOrgScope`：`SELF`、`PARENT` 或不限制；
- `orgCode`：可选机构限定。

`candidateValue` 按当前序列化约定保存，由服务端解析。运行时 Flowable 身份链接是任务
事实；节点配置只作候选生成来源或无身份链接时的受控兜底。Flowable IDM 关闭，用户、
角色、组织和候选组必须来自 `auth-permission-center`。

### 3.2 审批逻辑

并行审批配置必须保持：

- 组间 `AND`：每个机构/审批组都要完成；
- 组内 `OR`：同一组任一合法成员完成即可；
- `GROUP_ALL`：按机构组执行会签，不能压平成全局任意一人。

候选列表、签收、审批和转交必须使用同一服务端候选解析口径。未知员工/组织/角色、
权限查询异常、空候选或机构范围无法解析时 fail close。

## 4. 节点表单与流程变量

### 4.1 表单配置

按流程定义键和节点键维护 `WF_NODE_FORM_CONF`：

- `formFields`：字段定义、展示标签和类型；
- `editableFields`：该节点允许提交的字段键；
- `requiredFields`：该节点业务上要求填写的字段键。

字段配置只用于节点表单展示和工作流变量边界；业务模块仍负责主单领域校验。审批提交
的 `formData` 只能写入允许的流程变量，不能由客户端直接更新配置表。当前实现对必填
字段的最终校验能力须以服务代码核验，不能仅凭配置宣称已完成业务校验。

### 4.2 变量目录

设计器按 `bizType` 提供变量目录和审批人变量目录；条件只允许目录内字段和受支持运算
符，避免手工变量名造成未定义路由。多实例和网关读取审批完成前已写入的流程变量。

## 5. 超时规则

按流程定义键和节点键维护 `WF_TIMEOUT_RULE`，每条规则包含 `warningHours` 和
`timeoutHours`，预警阈值不得晚于超时阈值。任务查询时由 `CalendarApi` 计算工作日耗时：

- 无规则或未达到预警：`GREEN`；
- 达到预警但未超时：`YELLOW`；
- 达到超时：`RED`。

工作流中心不创建独立 Quartz 扫描、缓存或日历实现；调度能力如有需要只能通过治理中心
的统一边界接入。

## 6. PT_RESOURCE 资源要求

每个 Controller 方法都必须在 `PT_RESOURCE` 注册 HTTP 方法和实际 URL（含路径通配规则），
并绑定有权访问的角色/业务权限。菜单是否展示不能替代接口资源授权。

### 6.1 任务和流程

| 资源 URL 分组 | 方法 | 权限要求 |
| --- | --- | --- |
| `/api/workflow/tasks`、`/api/workflow/tasks/done` | GET | 登录、当前员工任务范围 |
| `/api/workflow/tasks/{taskId}` | GET | 登录、任务/数据范围 |
| `/api/workflow/tasks/{taskId}/claim` | POST | 登录、任务候选/办理规则 |
| `/api/workflow/tasks/{taskId}/approve`、`/reject` | POST | 登录、服务层任务办理权限 |
| `/api/workflow/processes/submit` | POST | 登录、业务模块提交权限 |
| `/api/workflow/processes/{processInstanceId}/cancel` | POST | 发起人或管理员，服务层复核 |
| `/api/workflow/processes/{processInstanceId}`、`/diagram`、`/history`、`/nodes` | GET | 登录、流程访问范围 |
| `/api/workflow/process-map` | GET | 登录、业务键/流程访问范围 |

任务和流程 Controller 当前未逐方法声明 `@BizAuth`，不表示免认证或免资源登记；统一
认证过滤、资源匹配和服务层校验仍必须生效。

### 6.2 监控与转交

| 资源 URL | 方法 | 代码中的业务权限 |
| --- | --- | --- |
| `/api/workflow/monitor/processes` | GET | `WORKFLOW_MONITOR/LIST` |
| `/api/workflow/monitor/tasks/{taskId}/transfer` | POST | `WORKFLOW_MONITOR/TRANSFER` |
| `/api/workflow/monitor/tasks/{taskId}/transfer-candidates` | GET | `WORKFLOW_MONITOR/TRANSFER` |
| `/api/workflow/monitor/processes/{processInstanceId}/transfers` | GET | `WORKFLOW_MONITOR/READ` |
| `/api/workflow/transfers/inbox`、`/outbox` | GET | 登录，服务层按当前员工过滤 |
| `/api/workflow/transfers/{id}/accept`、`decline`、`cancel` | POST | 登录，服务层按接收人/发起人过滤 |

转交候选名单和历史是敏感监控信息，不能只登记发起动作。收件箱、发件箱和决策接口
虽然没有逐方法 `@BizAuth`，仍必须登记资源并保留独立审计。

### 6.3 管理与设计器

以下两组全部要求 `SYS_CONFIG/CONFIG`：

- `/api/admin/workflow/timeout-rules` 及其 `item/{id}` 的 GET/POST/PUT；
- `/api/admin/workflow/node-candidates` 及其 `item/{id}` 的 GET/POST/PUT；
- `/api/admin/workflow/node-forms` 及其 `item/{id}` 的 GET/POST/PUT；
- `/api/admin/workflow/process-definitions` 的 GET；
- `/api/admin/workflow/flows` 的 GET/POST/PUT/DELETE、`{id}/publish`、
  `meta/variables`、`meta/approver-variables` 和 `import-existing`。

配置修改和流程发布需独立资源、操作人校验、原因/审计策略和数据范围；不能将管理员
接口开放给普通任务办理角色。

## 7. 配置验收

- Flowable 中实际存在且激活的定义键与业务调用、映射记录一致；
- 每个用户任务都能解析出合法候选，组间 AND/组内 OR 语义未丢失；
- 候选、表单和超时规则只指向当前定义及节点，未知配置 fail close；
- 设计器保存/发布和只读导入权限独立，完整图校验有效；
- 所有当前 Controller 路由都有 `PT_RESOURCE` 方法/URL，监控和转交资源粒度正确；
- 资源授权、服务层二次校验、审计和脱敏配置均以目标环境实测结果为准。
