## 1. 模块职责边界

### 1.1 负责

| 职责 | 具体内容 |
|:---|:---|
| Flowable 集成 | 唯一的 Flowable 7.x 集成边界，封装所有引擎 API 调用 |
| 流程发起 | 接收 StartProcessCmd，启动流程实例，写入 biz_process_map |
| 待办 / 已办 | 提供统一的待办/已办列表查询服务 |
| Claim / Transfer | 签收与转交的完整生命周期管理 |
| 节点候选人管理 | 维护 wf_node_candidate_conf，解析候选组集合 |
| 节点表单权限 | 维护 wf_node_form_conf，控制节点级字段可见/可编辑/必填 |
| 流程映射 | 维护 biz_process_map，业务键与流程实例的映射关系 |
| 红绿灯 SLA | 维护 wf_timeout_rule，定时计算超时状态 |
| 流程进度图 | 提供流程实例的实时进度图数据 |
| 审批日志 | 记录并查询流程各节点的审批意见与操作日志 |
| 流程事件发布 | 流程完成/取消/任务创建等领域事件的发布 |
| 流程参与者判定 | 当前由模块内部逻辑承担；未来可再抽成统一参与者服务 |

### 1.2 不负责

| 不负责的事项 | 说明 |
|:---|:---|
| 业务主单数据保存 | 线索、资产投放、中场支持等业务主表由各业务模块持有 |
| 业务表状态更新 | workflow-center 不直接 UPDATE 业务模块的表 |
| 业务表单校验 | 表单必填、字典值、唯一性等校验由业务模块在调用 startProcess 前完成 |
| 权限权威源 | 用户/角色/组织权威数据由 auth-permission-center 持有 |

### 2.2 依赖详情

| 依赖方向 | 被依赖模块 | 依赖强度 | 调用方式 | 说明 |
|:---|:---|:---|:---|:---|
| workflow -> common | common | S（强依赖） | 编译期 | 基础组件：响应封装、异常处理、Trace、AOP、分页 |

| business -> workflow | workflow-center | S（强依赖） | API 接口 | 资产投放/中场支持/分配关系调整流程发起与查询 |
| performance -> workflow | workflow-center | S（强依赖） | API 接口 | 目标修正流程发起与查询 |
| portal -> workflow | workflow-center | S（强依赖） | API 接口 | 待办聚合查询、通知事件消费 |

### 2.3 禁止依赖

workflow-center **不依赖任何业务模块**，以下依赖路径被严格禁止：

- workflow -> customer-marketing-center
- workflow -> business-application-center
- workflow -> performance-engine-center
- workflow -> portal-content-center
- workflow -> report-analytics-center

## 4. 分层规范

### 4.1 Controller 层

| 规范项 | 说明 |
|:---|:---|
| 职责 | 仅负责 HTTP 请求/响应的转换，参数校验（@Valid），调用 Facade 层 |
| 禁止事项 | 不包含任何业务逻辑，不直接调用 Service/Mapper |
| 注解要求 | 每个接口必须声明 `@BizAuth`（待办接口除外，因为天然按用户过滤） |
| 路由规范 | 待办/已办：`/api/workflow/tasks/**`；流程查询：`/api/workflow/processes/**`；管理：`/api/admin/workflow/**` |
| 日志要求 | 统一记录入参/出参、traceId 和耗时 |

### 4.2 Facade 层

| 规范项 | 说明 |
|:---|:---|
| 职责 | 实现 `api/` 下的接口定义，编排多个 Service 的调用顺序 |
| 命名 | 以 `*Facade` 结尾 |
| 事务 | Facade 层为事务边界，使用 `@Transactional` |
| 禁止事项 | 不直接调用 Flowable API，不直接调用 Mapper |
| 跨模块调用 | 通过 `auth-permission-center`、`system-governance-center` 的 API 接口调用 |

### 4.3 Service 层

| 规范项 | 说明 |
|:---|:---|
| 职责 | 核心业务逻辑实现，封装 Flowable API 调用 |
| 命名 | 以 `*Service` 结尾 |
| 注释要求 | 所有 Service 类和 public 方法必须有注释 |
| Flowable 调用 | **只有 Service 层可以直接调用 Flowable API** |
| 禁止事项 | 不直接暴露给其他模块（通过 Facade/Api 暴露） |

### 4.4 Mapper 层

| 规范项 | 说明 |
|:---|:---|
| 职责 | 数据库访问，仅操作本模块的表（biz_process_map / wf_node_* / wf_timeout_rule） |
| 命名 | 接口以 `*Mapper` 结尾，XML 以 `*Mapper.xml` 结尾 |
| 禁止事项 | **严禁**被其他模块直接依赖；**严禁**直接查询 Flowable 引擎表（通过 Flowable API 查询） |
| XML 位置 | `classpath*:mapper/workflow/*Mapper.xml` |

### 4.5 Entity 层

| 规范项 | 说明 |
|:---|:---|
| 职责 | 数据库实体映射，贫血模型 |
| 命名 | 驼峰命名，对应表名 |
| 禁止事项 | **严禁**被其他模块直接依赖；跨模块传输使用 `api/dto/` 下的 DTO |

### 4.6 Listener 层

| 规范项 | 说明 |
|:---|:---|
| 职责 | 监听 Flowable 引擎事件，调用 Service 完成同步操作 |
| 可做的事 | 刷新 biz_process_map、记录流程元数据、准备通知上下文 |
| 禁止事项 | **不直接发布对外领域事件**（对外事件必须在事务提交后发布） |

### 4.7 Event 层

| 规范项 | 说明 |
|:---|:---|
| 职责 | 定义领域事件和事件发布器 |
| 发布时机 | 必须使用 `@TransactionalEventListener(phase = AFTER_COMMIT)` |
| 消费方 | 其他业务模块通过 Spring Event 监听消费 |

### 4.8 Convert 层

| 规范项 | 说明 |
|:---|:---|
| 职责 | Entity <-> DTO 的对象转换 |
| 实现方式 | 使用静态方法或 MapStruct |

## 5. 错误码

### 5.1 错误码前缀

所有工作流中心的错误码以 **`WF`** 为前缀。

### 5.2 完整错误码清单

| 错误码 | HTTP 状态码 | 说明 | 触发场景 |
|:---|:---|:---|:---|
| WF-40401 | 404 | 流程定义不存在 | processDefinitionKey 在 Flowable 中不存在或未激活 |
| WF-40901 | 409 | 业务键已存在进行中的流程 | biz_process_map 中已有相同 business_key 且 status=RUNNING |
| WF-40902 | 409 | 任务不存在或已完成 | taskId 在 ACT_RU_TASK 中不存在（已完成或已取消） |
| WF-40903 | 403 | 无权签收（非候选人） | 当前用户不在任务的候选组/候选人范围内 |
| WF-40904 | 409 | 任务已被签收 | 任务已有 assignee，不可重复签收 |
| WF-40905 | 403 | 无权办理（非当前 assignee） | 当前用户不是任务的 assignee |
| WF-40906 | 403 | 转交接收人不在候选范围 | targetEmpId 不属于节点候选集合 |
| WF-40907 | 403 | 转交接收人不满足组织边界 | targetEmpId 不满足节点配置的组织边界约束 |
| WF-42201 | 422 | 节点表单校验失败 | 提交的表单数据不满足节点配置的字段规则 |
| WF-42202 | 422 | 必填字段缺失 | required_fields 中的字段在提交数据中缺失 |
| WF-50001 | 500 | Flowable 引擎异常 | Flowable 内部错误（启动失败、任务完成失败等） |

## 6. Flowable 配置

### 6.1 嵌入式引擎

Flowable 7.0.1 以**嵌入式模式**运行，与应用共享同一个数据源和事务管理器：

```yaml
# application.yml 中 Flowable 相关配置
flowable:
  # 共用应用数据源，不单独配置 Flowable 数据源
  database-schema-update: true
  # 历史级别必须 >= audit
  history-level: audit
  # 异步执行器配置
  async-executor-activate: true
  # 引擎表前缀
  table-prefix: ACT_
  # 不使用 Flowable IDM
  idm:
    enabled: false
```

### 6.2 核心配置类

```java
/**
 * Flowable 引擎配置
 * 嵌入式引擎，共用应用数据源，history-level=audit
 */
@Configuration
public class FlowableConfig {

    /**
     * 配置流程引擎
     * - 使用应用数据源（不单独配置）
     * - 历史级别: audit（确保历史任务、参与者、变量完整记录）
     * - 异步执行器: 启用（用于定时任务、边界事件等）
     * - IDM: 禁用（使用本系统权限模型）
     */
    @Bean
    public EngineConfigurationConfigurer<SpringProcessEngineConfiguration> engineConfigurer() {
        return config -> {
            config.setHistoryLevel(HistoryLevel.AUDIT);
            config.setAsyncExecutorActivate(true);
            // 禁用 Flowable IDM，使用本系统权限模型
            config.setDisableIdmEngine(true);
        };
    }
}
```

### 6.5 缓存策略

```java
/**
 * 工作流缓存配置
 * 对高频查询且变更频率低的配置数据进行 Redis 缓存
 */
@Configuration
public class WorkflowCacheConfig {

    // 候选人配置缓存：按流程定义 Key 缓存，TTL 30 分钟
    // Key 格式: wf:candidate:{processDefinitionKey}
    // 变更时主动失效

    // 超时规则缓存：按流程定义 Key 缓存，TTL 30 分钟
    // Key 格式: wf:timeout:{processDefinitionKey}
    // 变更时主动失效

    // 节点表单配置缓存：按流程定义 Key + 节点 Key 缓存，TTL 30 分钟
    // Key 格式: wf:form:{processDefinitionKey}:{nodeKey}
    // 变更时主动失效

    // 用户候选组缓存：按用户工号缓存，TTL 5 分钟（较短，因角色变更需及时生效）
    // Key 格式: wf:groups:{empId}
    // 角色变更时由 auth-permission-center 发事件主动失效
}
```

## 7. Service 层核心类职责

### 7.1 ProcessStartService

```java
/**
 * 流程启动核心服务
 *
 * 职责：
 * 1. 校验流程定义存在且已激活
 * 2. 校验 business_key 唯一性
 * 3. 调用 IdentityService.setAuthenticatedUserId(startUser)
 * 4. 使用 RuntimeService.createProcessInstanceBuilder() 启动流程
 * 5. 写入 biz_process_map
 */
public class ProcessStartService {

    /**
     * 启动流程实例
     * @param cmd 流程启动命令
     * @return 流程启动响应（流程实例ID、业务键、首个任务ID）
     * @throws BizException WF-40401 流程定义不存在
     * @throws BizException WF-40901 业务键已存在进行中的流程
     * @throws BizException WF-50001 Flowable引擎异常
     */
    public WorkflowLaunchResp startProcess(StartProcessCmd cmd);
}
```

### 7.2 TaskOperationService

```java
/**
 * 任务操作服务
 *
 * 职责：封装 Claim / Approve / Reject / Transfer 四大操作
 * 每个操作均包含前置校验、Flowable API 调用、biz_process_map 刷新
 */
public class TaskOperationService {

    /**
     * 签收任务
     * @param taskId 任务ID
     * @param empId 签收人工号
     * @throws BizException WF-40902 任务不存在或已完成
     * @throws BizException WF-40903 无权签收（非候选人）
     * @throws BizException WF-40904 任务已被签收
     */
    public void claimTask(String taskId, String empId);

    /**
     * 审批通过
     * @param taskId 任务ID
     * @param empId 操作人工号
     * @param opinion 审批意见
```

## 8. Flowable API 调用映射（V1 冻结）

| 业务操作 | Flowable API | 说明 |
|:---|:---|:---|
| 启动流程 | `RuntimeService.createProcessInstanceBuilder().businessKey(bk).processDefinitionKey(key).name(title).start()` | 使用 builder 模式启动 |
| 设置发起人 | `IdentityService.setAuthenticatedUserId(empId)` | 启动前设置，用于历史记录 |
| 签收 | `TaskService.claim(taskId, empId)` | 候选组 -> assignee |
| 审批通过 | `TaskService.complete(taskId, variables)` | variables 包含 approvalResult=APPROVE |
| 驳回 | `TaskService.complete(taskId, variables)` | variables 包含 approvalResult=REJECT |
| 转交 | `TaskService.setAssignee(taskId, targetEmpId)` | 直接变更 assignee |
| 取消流程 | `RuntimeService.deleteProcessInstance(processInstanceId, reason)` | 仅系统管理员/异常兜底 |
| 查询待办 | `TaskService.createTaskQuery()` | 结合本系统候选组解析 |
| 查询已办 | `HistoryService.createHistoricTaskInstanceQuery()` | 查询历史任务 |
| 查询流程实例 | `HistoryService.createHistoricProcessInstanceQuery()` | 查询流程历史 |
| 查询流程定义 | `RepositoryService.createProcessDefinitionQuery()` | 查询已部署的流程定义 |
| 查询活动历史 | `HistoryService.createHistoricActivityInstanceQuery()` | 用于流程进度图 |
