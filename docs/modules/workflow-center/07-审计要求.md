# 工作流中心 — 审计要求

> 本文档定义 workflow-center 模块所有高危操作的审计日志要求，包括审计清单、日志格式和存储方案。
> 审计日志统一写入 system-governance-center 管理的审计表（通过 AuditLog 注解或 AuditApi）。

---

## 1. 高危动作清单

| 接口 | HTTP Method + URL | 动作标识 | 审计级别 | 说明 |
|---|---|---|---|---|
| 签收任务 | `POST /api/workflow/tasks/{taskId}/claim` | `CLAIM` | 敏感操作，需审计 | 改变任务归属，影响后续办理权 |
| 同意审批 | `POST /api/workflow/tasks/{taskId}/approve` | `APPROVE` | 需审计 | 推进流程，可能触发业务状态变更 |
| 驳回审批 | `POST /api/workflow/tasks/{taskId}/reject` | `REJECT` | 需审计 | 终止或回退流程 |
| 转交任务 | `POST /api/workflow/tasks/{taskId}/transfer` | `TRANSFER` | 高危，必须审计 | 将任务处理权转移给其他人员 |
| 修改超时规则 | `PUT /api/admin/workflow/timeout-rules/{id}` | `CONFIG_TIMEOUT` | 需审计 | 影响红绿灯预警阈值 |
| 修改节点候选人 | `PUT /api/admin/workflow/node-candidates/{id}` | `CONFIG_CANDIDATE` | 需审计 | 影响流程审批权限分配 |
| 修改节点表单 | `PUT /api/admin/workflow/node-forms/{id}` | `CONFIG_FORM` | 需审计 | 影响审批表单字段和校验规则 |

## 2. 审计日志字段规范

每条审计日志包含以下标准字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `action` | String | 是 | 操作动作标识（CLAIM/APPROVE/REJECT/TRANSFER/CONFIG_*） |
| `resource_type` | String | 是 | 资源类型（WORKFLOW_TASK/WORKFLOW_CONFIG） |
| `resource_id` | String | 是 | 资源ID（taskId 或 配置ID） |
| `business_key` | String | 条件必填 | 业务键（任务操作时必填，配置操作时可选） |
| `process_instance_id` | String | 条件必填 | 流程实例ID（任务操作时必填） |
| `operator_emp_id` | String | 是 | 操作人工号 |
| `operator_org_id` | String | 是 | 操作人所属机构编码 |
| `request_time` | String(ISO8601) | 是 | 请求时间（含时区） |
| `ip` | String | 是 | 客户端IP地址 |
| `trace_id` | String | 是 | 全链路追踪ID |
| `reason` | String | 条件必填 | 操作原因（转交操作必填，驳回操作必填） |
| `before` | String(JSON) | 条件必填 | 操作前状态快照（有状态变更时必填） |
| `after` | String(JSON) | 条件必填 | 操作后状态快照（有状态变更时必填） |
| `result` | String | 是 | 操作结果：SUCCESS/FAIL |
| `error_msg` | String | 否 | 失败时的错误信息 |

## 4. 审批日志存储

### 4.1 审批意见存储

审批意见（opinion/formData/result）通过 Flowable `TaskService.addComment()` 写入 `ACT_HI_COMMENT` 表：

| 字段 | 存储位置 | 说明 |
|---|---|---|
| 审批结果 | `ACT_HI_COMMENT.TYPE_` | `APPROVE` / `REJECT` |
| 审批意见文本 | `ACT_HI_COMMENT.MESSAGE_` | 审批人输入的意见内容 |
| 表单数据 | `ACT_HI_COMMENT.FULL_MSG_` | JSON 格式的完整表单数据 |
| 审批人 | `ACT_HI_COMMENT.USER_ID_` | 审批人工号 |
| 审批时间 | `ACT_HI_COMMENT.TIME_` | 审批时间戳 |
| 关联任务 | `ACT_HI_COMMENT.TASK_ID_` | 对应的任务ID |
| 关联流程 | `ACT_HI_COMMENT.PROC_INST_ID_` | 对应的流程实例ID |

### 4.2 Comment 写入格式

```java
// 写入审批意见
String commentType = approved ? "APPROVE" : "REJECT";
String fullMessage = objectMapper.writeValueAsString(Map.of(
    "result", commentType,
    "opinion", cmd.getOpinion(),
    "formData", cmd.getFormData(),
    "operatorEmpId", currentEmpId,
    "operatorOrgId", currentOrgCode,
    "operateTime", LocalDateTime.now().toString()
));
taskService.addComment(taskId, processInstanceId, commentType, cmd.getOpinion());
// FULL_MSG_ 存完整 JSON（Flowable 支持 addComment 的 fullMessage 参数）
```

### 4.3 审批日志统一查询

通过 `WorkflowQueryApi.getApprovalLogs()` 统一查询指定流程的所有审批日志：

```java
/**
 * 获取流程审批日志
 * 合并 Flowable 历史任务信息和 Comment 信息
 *
 * @param processInstanceId 流程实例ID
 * @return 按时间排序的审批日志列表
 */
List<ApprovalLogDTO> getApprovalLogs(String processInstanceId);
```

返回的 `ApprovalLogDTO` 结构：

```java
public class ApprovalLogDTO {
    /** 任务ID */
    private String taskId;
    /** 节点KEY */
    private String taskDefinitionKey;
    /** 节点名称 */
    private String taskName;
    /** 处理人工号 */
    private String assignee;
    /** 处理人姓名（通过 UserApi 查询） */
    private String assigneeName;
    /** 处理人机构 */
    private String assigneeOrgName;
    /** 审批结果 APPROVE/REJECT */
    private String result;
    /** 审批意见 */
    private String opinion;
    /** 表单数据（JSON） */
    private Map<String, Object> formData;
    /** 任务创建时间 */
    private LocalDateTime createTime;
    /** 任务完成时间 */
    private LocalDateTime endTime;
    /** 耗时（小时） */
    private Long durationHours;
}
```

### 4.4 查询实现

```java
public List<ApprovalLogDTO> getApprovalLogs(String processInstanceId) {
    // 1. 查询历史任务（按结束时间升序）
    List<HistoricTaskInstance> tasks = historyService.createHistoricTaskInstanceQuery()
        .processInstanceId(processInstanceId)
        .orderByHistoricTaskInstanceEndTime().asc()
        .list();

    // 2. 查询所有 Comment
    List<Comment> comments = taskService.getProcessInstanceComments(processInstanceId);
    Map<String, List<Comment>> commentsByTaskId = comments.stream()
        .filter(c -> c.getTaskId() != null)
        .collect(Collectors.groupingBy(Comment::getTaskId));

    // 3. 合并组装
    return tasks.stream().map(task -> {
        ApprovalLogDTO dto = new ApprovalLogDTO();
        dto.setTaskId(task.getId());
        dto.setTaskDefinitionKey(task.getTaskDefinitionKey());
        dto.setTaskName(task.getName());
        dto.setAssignee(task.getAssignee());
        dto.setCreateTime(task.getCreateTime());
        dto.setEndTime(task.getEndTime());

        List<Comment> taskComments = commentsByTaskId.getOrDefault(task.getId(), List.of());
        if (!taskComments.isEmpty()) {
            Comment latest = taskComments.get(taskComments.size() - 1);
            dto.setResult(latest.getType());
            dto.setOpinion(latest.getFullMessage());
            // 解析 FULL_MSG_ 中的 formData
            // ...
        }
        return dto;
    }).collect(Collectors.toList());
}
```

## 5. 审计实现方式

### 5.1 注解驱动

工作流中心的高危接口使用 `@AuditLog` 注解标记，由 AOP 切面自动采集审计信息：

```java
@PostMapping("/tasks/{taskId}/claim")
@BizAuth(bizType = BizType.WORKFLOW_TASK, action = BizAction.WRITE)
@AuditLog(action = "CLAIM", resourceType = "WORKFLOW_TASK")
public R<Void> claimTask(@PathVariable String taskId) {
    workflowTaskService.claim(taskId, currentUserApi.getCurrentEmpId());
    return R.ok();
}
```

### 5.2 before/after 快照采集

对于需要记录变更前后状态的操作（转交、配置修改），在 Service 层手动构建 before/after 快照：

```java
public void transferTask(String taskId, TransferCmd cmd) {
    Task task = taskService.createTaskQuery().taskId(taskId).singleResult();

    // 构建 before 快照
    String before = objectMapper.writeValueAsString(
        Map.of("assignee", task.getAssignee())
    );

    // 执行转交
    taskService.setAssignee(taskId, cmd.getTargetEmpId());
    bizProcessMapMapper.updateCurrentAssignee(task.getProcessInstanceId(), cmd.getTargetEmpId());

    // 构建 after 快照
    String after = objectMapper.writeValueAsString(
        Map.of("assignee", cmd.getTargetEmpId())
    );

    // 写入审计上下文（AOP 切面读取）
    AuditContext.setCurrent(before, after, cmd.getReason());
}
```

## 6. 敏感字段脱敏

审计日志中涉及的敏感字段需脱敏处理：

| 字段类型 | 脱敏规则 | 示例 |
|---|---|---|
| 工号(empId) | 不脱敏（内部标识） | `E10001` |
| IP地址 | 不脱敏（审计需要） | `192.168.1.100` |
| 手机号 | 中间4位掩码 | `138****5678` |
| 身份证号 | 仅保留前3后4 | `310***********1234` |
| 金额 | 不脱敏（审批金额需完整记录） | `500.00` |

> 注意：审计日志中一般不包含客户敏感信息（手机号、身份证等）。若审批表单中包含此类字段，在写入审计日志前需调用统一脱敏工具处理。

## 7. 审计日志保留策略

| 策略项 | 规则 |
|---|---|
| 保留期限 | 至少 3 年（符合银行合规要求） |
| 存储位置 | 系统审计表（system-governance-center 管理） |
| 归档策略 | 超过 1 年的审计日志可迁移至归档表或冷存储 |
| 查询权限 | 仅 `SYS_ADMIN` 和 `R_BACK_TECH` 角色可查询审计日志 |
| 不可篡改 | 审计日志表禁止 UPDATE/DELETE 操作（仅 INSERT） |
