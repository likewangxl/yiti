# 工作流中心——依赖契约摘要

## 1. 依赖方向

当前 Maven 依赖以 `workflow-center/pom.xml` 为准：公共 Web/追踪/安全/AOP/数据库能力、
`auth-permission-center`、`system-governance-center`、Flowable Spring Boot starter、
MyBatis-Plus 和 API 文档组件。

```text
workflow-center ──> common
workflow-center ──> auth-permission-center
workflow-center ──> system-governance-center
workflow-center ──> Flowable
业务模块 ──> workflow-center/api
```

工作流中心不依赖任何业务模块；业务模块不依赖工作流内部 Service、Mapper、Entity 或
Flowable 类型。根 POM 和各模块 POM 是依赖版本与聚合关系的唯一来源。

## 2. 认证与组织契约

### 2.1 CurrentUserApi

工作流 REST 通过当前用户 API 获取会话身份：

| 能力 | 用途 |
| --- | --- |
| 当前员工 ID、当前机构编码 | 提交、办理、撤回、转交发起和决策 |
| 当前候选组键 | 待办/已办候选过滤和参与业务键查询 |
| 系统管理员判断 | 流程撤回和监控数据范围的管理员分支 |

空身份、上下文缺失和候选组解析异常不得被当作管理员或全量范围。

### 2.2 UserApi

工作流使用认证中心的用户/候选解析能力完成展示和授权：

- 按员工 ID获取用户、姓名和批量用户展示信息；
- 按角色、角色+机构、机构查询员工集合；
- 按任意员工 ID计算候选组键，用于无会话 API、转交接收人和实时候选校验。

工作流不复制用户、角色、机构表，也不以 Flowable IDM 作为权限源。返回空集合、未知
角色或查询异常必须按 fail-close 处理。

### 2.3 OrgApi

工作流使用：

- 按机构编码获取机构及层级；
- 按员工获取主机构；
- 在转交中校验接收人与发起人的主机构边界；
- 在监控和历史展示中补充机构信息；
- 在机构快照写入前解析参与机构。

主机构不存在或机构服务异常不能扩大转交资格和监控范围。机构快照写入服务会吞并记录
旁路异常，以免阻断 Flowable 主操作。

## 3. 治理平台契约

### 3.1 CalendarApi

SLA 查询只使用 `CalendarApi.countWorkingDays(from, to)`，结合 `WF_TIMEOUT_RULE` 的
预警/超时小时数计算红黄绿状态。工作流不建立第二套日历、截止日期算法或 SLA 调度器。

### 3.2 NotifyApi

任务分配和转交接受/拒绝/取消使用治理 `NotifyApi` 发送单人或批量通知。通知命令包含
目标员工、标题、工作流通知类型及业务关联信息；通知不是 Flowable 状态源，也不应把
跨系统投递成功假定为数据库事务原子结果。

### 3.3 Quartz 与审计

Quartz 调度归 `system-governance-center`，工作流当前不直接注册调度任务。审计复用
common AOP 的 `@AuditLog` 和治理审计处理器；高危操作的原因、脱敏和失败审计按
`07-审计要求.md` 执行，不在工作流重复实现审计存储。

## 4. Flowable 契约

Flowable starter 提供 Repository/Runtime/Task/History 等引擎服务和事务集成。工作流中心
是唯一直接调用方，负责：

- 已部署定义查询和流程实例启动/取消；
- 运行时任务、身份链接、候选和办理；
- 历史任务、评论、变量和流程图查询；
- 设计器 BPMN 生成、部署和定义版本元数据。

Flowable IDM 关闭；候选用户/组解析必须调用认证中心。引擎表 `ACT_*` 只能经 Flowable
服务访问，业务模块不得直接查询。

## 5. 工作流公开契约

对外 Java 入口只有：

| 契约 | 内容 |
| --- | --- |
| `WorkflowApi` | 启动、取消、映射查询、结论查询、无会话审批/驳回、设计器已发布键解析 |
| `WorkflowQueryApi` | 待办/已办、详情、历史、节点、候选员工、映射和参与业务键查询 |
| `TodoQueryApi` | 按业务键批量反查待办/已办，含无会话员工 ID 版本 |
| `ProcessCompletedEvent` | 流程完成/驳回结论事件 |
| `ProcessWithdrawnEvent` | 流程撤回事件 |

接口只返回 `workflow.api.dto` DTO，不暴露 Flowable 对象、内部实体或实现 Service。方法
签名、字段和状态语义见 `04-对外API契约.md`；HTTP 路由见 `03-接口设计与报文.md`。

## 6. 公共基础设施和本地持久化

- `common-web`：统一响应、分页和异常；
- `common-trace`：traceId 与调用耗时上下文；
- `common-security`：认证过滤、`@BizAuth`、资源/数据范围门禁；
- `common-aop`：审计注解及统一处理器；
- `common-db`：MyBatis-Plus、事务和数据库公共配置；
- MyBatis-Plus：工作流自身映射表的 CRUD/自定义查询。

本地表仅承载业务键映射、节点配置、设计器图、机构快照和转交状态。跨模块不直接 join
对方私有表；数据库结构及当前目标库约束以 `05-表结构DDL.md` 的模型说明和 DBA 核对
结果为准。

## 7. 依赖验证要求

- 代码只从 `api` 包引用跨模块类型，未引入业务模块依赖或 Flowable 类型到业务模块；
- `CurrentUserApi`、`UserApi`、`OrgApi`、`CalendarApi`、`NotifyApi` 的异常/空值按
  fail-close 或旁路隔离规则处理；
- 公共响应、追踪、鉴权、审计和事务不被工作流自建实现替代；
- 修改 Controller/API/DTO/事件时同步 03/04、`PT_RESOURCE` 和契约检查；
- 调度、缓存、消息可靠投递和跨库补偿若需新增，先进行平台级架构评审，不在本摘要中
  预设未实现契约。
