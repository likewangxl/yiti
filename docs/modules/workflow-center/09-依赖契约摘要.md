# 工作流中心 — 依赖契约摘要

> 本文档摘录自被依赖模块的对外 API 契约，仅供 workflow-center 开发时快速查阅。
> **如有冲突，以源模块文档为准。**

---

## 1. 依赖 auth-permission-center（强依赖 S）

来源：`docs/modules/auth-permission-center/04-对外API契约.md`

### 1.1 本模块使用的接口

| 接口 | 方法签名 | 返回类型 | 用途 |
|---|---|---|---|
| `CurrentUserApi` | `getCurrentUserContext()` | `CurrentUserContext` | 获取当前用户完整上下文（鉴权拦截器/候选组解析） |
| `CurrentUserApi` | `getCurrentEmpId()` | `String` | 获取当前用户工号（待办过滤/签收校验/审批记录） |
| `CurrentUserApi` | `getCurrentOrgCode()` | `String` | 获取当前用户主机构编码（审计日志/组织边界校验） |
| `CurrentUserApi` | `getCurrentRoleCodes()` | `Set<String>` | 获取当前用户角色编码集合（候选组解析） |
| `CurrentUserApi` | `getCurrentCandidateGroupKeys()` | `Set<String>` | 获取当前用户候选组集合（**待办查询核心依赖**） |
| `CurrentUserApi` | `isSystemAdmin()` | `boolean` | 判断是否系统管理员（配置接口权限判断） |
| `BizScopeApi` | `resolveScope(empId, BizType)` | `DataScopeType` | 解析数据范围（办理权校验） |
| `BizScopeApi` | `buildScopeContext(empId, BizType, BizAction)` | `DataScopeContext` | 构建完整数据范围上下文 |
| `BizScopeApi` | `checkWritePermission(empId, BizType, orgId, createdBy)` | `boolean` | 校验写操作权限（转交/签收权限校验） |
| `OrgApi` | `getOrgSubtreeCodes(orgCode)` | `Set<String>` | 获取机构子树编码集合（组织边界校验/转交目标校验） |
| `OrgApi` | `getUserMainOrg(empId)` | `OrgDTO` | 获取用户主机构信息（审计日志/转交目标机构查询） |
| `ResourceApi` | `matchResource(url, method)` | `Optional<ResourceDTO>` | URL-资源匹配（鉴权拦截器中使用） |
| `ResourceApi` | `hasResourcePermission(empId, resourceId)` | `boolean` | 判断用户是否有指定资源权限 |

### 1.2 使用的 DTO 结构

#### CurrentUserContext

```java
package com.bank.branch.platform.common.security.context;

/**
 * 当前用户上下文（不可变对象，从 ThreadLocal 获取，无 DB IO）
 */
public record CurrentUserContext(
    String empId,              // 用户工号（PT_USER.USER_ID）
    String mainOrgCode,        // 主机构编码（EXT_USER_ORG.ORG_CODE）
    Set<String> roleIds,       // 角色ID集合
    Set<String> roleCodes,     // 角色编码集合
    Set<String> candidateGroupKeys, // 候选组Key集合，格式如 "ROLE:CUST_MANAGER"
    boolean systemAdmin        // 是否系统管理员
) {}
```

**workflow-center 使用场景**：
- `candidateGroupKeys`：待办查询时作为 Flowable `taskCandidateGroupIn()` 的参数
- `empId`：签收校验、审批记录
- `roleCodes`：TaskListener 中解析候选组配置时匹配角色

#### DataScopeContext

```java
package com.bank.branch.platform.auth.api.dto;

/**
 * 数据范围上下文（ThreadLocal 传递）
 */
public record DataScopeContext(
    DataScopeType scopeType,    // 数据范围类型
    String empId,               // 当前用户工号
    String orgCode,             // 当前用户主机构编码
    Set<String> orgSubtreeCodes, // 机构子树编码集合（ORG_SUBTREE 时填充）
    BizType bizType,            // 当前业务类型
    BizAction action            // 当前业务动作
) {}
```

#### OrgDTO

```java
package com.bank.branch.platform.auth.api.dto;

public class OrgDTO {
    private String orgCode;       // 机构编码
    private String orgName;       // 机构名称
    private Integer orgLevel;     // 机构等级（1总行/2分行/3支行）
    private String parentOrgCode; // 上级机构编码
    private Integer organState;   // 状态（0启用/1删除）
}
```

### 1.3 使用的枚举

#### BizType（与 workflow-center 相关的值）

| 枚举值 | 说明 | 对应流程 |
|---|---|---|
| `LEAD` | 线索 | lead_approve_v1 |
| `LEAD_IMPORT` | 线索批量导入 | lead_import_approve_v1 |
| `LEAD_DELETE` | 线索删除 | lead_delete_approve_v1 |
| `TOUCH` | 触达任务 | touch_process_v1 |
| `LOAN` | 资产投放 | loan_approve_v1 |
| `SUPPORT_SIMPLE` | 中场支持(产品直达) | support_simple_v1 |
| `SUPPORT_COMPLEX` | 中场支持(部门承接) | support_complex_v1 |
| `TARGET_ADJUST` | 目标修正 | target_adjust_approve_v1 |
| `ALLOC_ADJUST` | 分配关系调整 | alloc_adjust_approve_v1 |
| `WORKFLOW_TASK` | 工作流任务(仅用于BizAuth注解) | - |

#### BizAction（与 workflow-center 相关的值）

| 枚举值 | 说明 | 使用场景 |
|---|---|---|
| `READ` | 读取 | 待办/已办列表查询、任务详情查看 |
| `WRITE` | 写入 | 签收(Claim) |
| `APPROVE` | 审批 | 同意/驳回 |
| `TRANSFER` | 转交 | 任务转交 |
| `LIST` | 列表查询 | 带数据范围的列表查询 |
| `CONFIG` | 配置管理 | 候选人/表单/超时规则配置 |

#### DataScopeType（与 workflow-center 相关的值）

| 枚举值 | 说明 | workflow-center 中的含义 |
|---|---|---|
| `SELF` | 仅自己 | 只能看到自己的待办/已办 |
| `SELF_CREATED` | 自己创建的 | 只能看到自己发起的流程 |
| `SELF_ASSIGNED` | 自己被指派的 | 只能看到指派给自己的任务 |
| `WORKFLOW_PARTICIPANT` | 流程参与者 | 只能看到自己参与过的流程 |
| `ORG` | 本机构 | 可看到本机构的所有流程 |
| `ORG_SUBTREE` | 机构子树 | 可看到本机构及下属机构的所有流程 |
| `ALL` | 全部 | 可看到所有流程 |

### 1.4 调用约束

| 约束项 | 说明 |
|---|---|
| 调用方式 | 本地方法调用（Spring Bean 注入），无 RPC 开销 |
| 线程安全 | 所有 Api 方法线程安全 |
| 事务传播 | Api 方法参与调用方事务（REQUIRED 传播） |
| CurrentUserApi 前置条件 | 必须在 AuthenticationFilter 之后调用（否则 ThreadLocal 为空） |
| 缓存策略 | CurrentUserApi 无缓存（ThreadLocal）；BizScopeApi/OrgApi 有 Redis 缓存 TTL=5min |
| Fail Close | `resolveScope()` 在无配置时抛 `PermissionDeniedException`，默认拒绝访问 |

### 1.5 异常约定

| 异常类型 | 说明 | workflow-center 处理方式 |
|---|---|---|
| `AuthException` | 未登录/Session过期 | 透传给全局异常处理器，返回 401 |
| `PermissionDeniedException` | 权限拒绝 | 透传给全局异常处理器，返回 403 |
| `BizException(AUTH-40404)` | 机构不存在 | 转交校验时捕获，返回友好提示 |
| `BizException(AUTH-40403)` | 用户不存在或无机构 | 签收/转交时捕获，返回友好提示 |

### 1.6 事件监听

workflow-center 监听 auth-permission-center 发布的权限缓存失效事件：

```java
/**
 * 监听权限缓存失效事件
 * 当角色/资源/BizScope 变更时，清除本地缓存
 */
@EventListener
public void onPermissionCacheInvalidated(PermissionCacheInvalidatedEvent event) {
    // 清除本模块可能持有的权限相关本地缓存
    // 目前 workflow-center 不持有本地缓存，此监听器为扩展预留
    log.info("收到权限缓存失效事件: changeType={}, affectedRoles={}",
        event.getChangeType(), event.getAffectedRoleIds());
}
```

## 2. 依赖 system-governance-center（强依赖 S）

来源：`docs/modules/system-governance-center/04-对外API契约.md`（待生成时以实际文档为准）

### 2.1 本模块使用的接口

| 接口 | 方法签名 | 返回类型 | 用途 |
|---|---|---|---|
| `CalendarApi` | `isWorkingDay(LocalDate date)` | `boolean` | 判断指定日期是否工作日（红绿灯计算） |
| `CalendarApi` | `countWorkingDays(LocalDate from, LocalDate to)` | `int` | 计算两个日期之间的工作日天数（红绿灯计算） |
| `CalendarApi` | `getWorkingDays(int year)` | `Set<LocalDate>` | 获取指定年份全部工作日集合（批量红绿灯计算优化） |
| `DictApi` | `getDictItems(String dictType)` | `List<DictItemDTO>` | 获取字典项列表（审批表单下拉框数据源） |
| `NotifyApi` | `sendNotification(NotificationCmd cmd)` | `void` | 发送站内通知（流程完成通知/待办通知/超时预警通知） |

### 2.2 使用的 DTO 结构

#### DictItemDTO

```java
package com.bank.branch.platform.governance.api.dto;

public class DictItemDTO {
    private String dictCode;    // 字典编码
    private String dictLabel;   // 字典标签（显示名称）
    private String dictValue;   // 字典值
    private Integer sortOrder;  // 排序号
}
```

**workflow-center 使用场景**：
- 审批表单中 `type=SELECT` 且 `dictType` 不为空的字段，前端需要通过 `DictApi` 获取下拉选项
- 示例：`riskLevel` 字段的 `dictType=RISK_LEVEL`，前端调用 `getDictItems("RISK_LEVEL")` 获取选项

#### NotificationCmd

```java
package com.bank.branch.platform.governance.api.dto;

public class NotificationCmd {
    private String targetEmpId;   // 接收人工号
    private String title;         // 通知标题
    private String content;       // 通知内容
    private String bizType;       // 业务类型（用于分类筛选）
    private String bizId;         // 业务ID
    private String linkUrl;       // 跳转链接
}
```

**workflow-center 使用场景**：
- 流程完成时通知发起人
- 新待办任务时通知候选处理人
- 超时预警时通知当前处理人

### 2.3 调用约束

| 约束项 | 说明 |
|---|---|
| 调用方式 | 本地方法调用（Spring Bean 注入） |
| 事务传播 | REQUIRED（参与调用方事务） |
| CalendarApi 缓存 | `getWorkingDays()` 建议调用方缓存结果（年度数据变动极少） |
| DictApi 缓存 | 由 system-governance-center 内部缓存，调用方无需额外缓存 |
| NotifyApi 可靠性 | 通知发送失败不应影响主业务流程；建议在 `@TransactionalEventListener(AFTER_COMMIT)` 中调用 |

### 2.4 CalendarApi 调用示例

```java
/**
 * 红绿灯计算中使用 CalendarApi 的示例
 */
public int calculateWorkingHours(LocalDate taskCreateDate, LocalDate currentDate) {
    // 方式1：逐日判断（适合少量计算）
    int workingDays = calendarApi.countWorkingDays(taskCreateDate, currentDate);
    return workingDays * 8; // 每工作日 8 小时

    // 方式2：批量获取工作日集合（适合批量计算，推荐）
    Set<LocalDate> workingDays2026 = calendarApi.getWorkingDays(2026);
    long count = workingDays2026.stream()
        .filter(d -> !d.isBefore(taskCreateDate) && !d.isAfter(currentDate))
        .count();
    return (int) count * 8;
}
```

### 2.5 NotifyApi 调用示例

```java
/**
 * 流程完成后通知发起人
 */
@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
public void onProcessCompleted(ProcessCompletedEvent event) {
    notifyApi.sendNotification(new NotificationCmd(
        event.getStartUser(),                                    // 通知发起人
        "流程审批完成",                                             // 标题
        String.format("您发起的%s流程已审批完成", event.getBizTypeName()), // 内容
        event.getBizType(),                                       // 业务类型
        event.getBizId(),                                         // 业务ID
        "/workflow/detail/" + event.getProcessInstanceId()        // 跳转链接
    ));
}

/**
 * 新待办任务通知候选处理人
 */
public void notifyNewTask(String processInstanceId, String taskName,
                          List<String> candidateEmpIds) {
    for (String empId : candidateEmpIds) {
        notifyApi.sendNotification(new NotificationCmd(
            empId,
            "您有新的待办任务",
            String.format("待办任务：%s，请及时处理", taskName),
            "WORKFLOW_TASK",
            processInstanceId,
            "/workflow/todo"
        ));
    }
}
```

## 3. 依赖关系总览

```
workflow-center
├── auth-permission-center [强依赖 S]
│   ├── CurrentUserApi      ← 身份/角色/候选组
│   ├── BizScopeApi         ← 数据范围/权限校验
│   ├── OrgApi              ← 机构查询/组织边界
│   └── ResourceApi         ← 资源匹配/权限判断
│
└── system-governance-center [强依赖 S]
    ├── CalendarApi          ← 工作日历/红绿灯计算
    ├── DictApi              ← 字典数据/表单下拉选项
    └── NotifyApi            ← 站内通知/待办提醒
```

### 3.1 依赖级别说明

| 级别 | 含义 | 影响 |
|---|---|---|
| **强依赖 S** | 被依赖模块不可用时，本模块核心功能不可用 | 启动时检查依赖 Bean 是否存在 |
| 弱依赖 W | 被依赖模块不可用时，本模块降级运行 | V1 中 workflow-center 无弱依赖 |

### 3.2 启动顺序

模块化单体架构下，所有模块在同一个 Spring 容器中，无需考虑启动顺序。但 Bean 初始化顺序需注意：
1. `auth-permission-center` 的 Api Bean 先于 workflow-center 的 Service Bean 初始化
2. `system-governance-center` 的 Api Bean 先于 workflow-center 的 Service Bean 初始化
3. 通过 Spring 的依赖注入自动保证（构造函数注入）

### 3.3 接口变更影响评估

| 被依赖接口 | 变更风险 | 影响范围 |
|---|---|---|
| `CurrentUserApi.getCurrentCandidateGroupKeys()` | 高 | 待办查询核心逻辑，返回格式变更将导致待办列表异常 |
| `CalendarApi.countWorkingDays()` | 中 | 红绿灯计算，返回值含义变更将导致超时判定偏差 |
| `NotifyApi.sendNotification()` | 低 | 通知功能，接口变更不影响核心审批流程 |
| `OrgApi.getOrgSubtreeCodes()` | 中 | 组织边界校验，返回值不完整将导致权限判定异常 |
| `BizScopeApi.resolveScope()` | 高 | 数据范围解析，变更将影响所有带权限的查询和操作 |
