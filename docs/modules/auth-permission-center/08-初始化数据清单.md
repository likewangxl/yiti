## 3. AUTH 模块自身接口的资源登记清单

> 资源登记参考 `permission_code_skeleton_v1.md` 第 13 章
> 完整资源种子数据位于 `docs/schema/seed-v1.sql` 第 3 节

### 3.1 AUTH 模块资源

| RESOURCE_ID | RESOURCE_URL | RESOURCE_METHOD | MENU_NAME | ISMENU | BizType归属 |
|:---|:---|:---|:---|:---|:---|
| RES_AUTH_CURRENT | /api/auth/current-user | GET | 当前用户信息 | 1（非菜单） | - |
| RES_ORG_TREE | /api/org/tree | GET | 组织树 | 1（非菜单） | - |
| RES_ORG_SUBTREE | /api/org/subtree | GET | 组织子树 | 1（非菜单） | - |
| RES_ROLE_LIST | /api/sys/roles | GET | 角色列表 | 1（非菜单） | SYS_CONFIG |
| RES_ROLE_CREATE | /api/sys/roles | POST | 角色创建 | 1（非菜单） | SYS_CONFIG |
| RES_ROLE_UPDATE | /api/sys/roles/* | PUT | 角色更新 | 1（非菜单） | SYS_CONFIG |
| RES_ROLE_RES_LIST | /api/sys/roles/*/resources | GET | 角色资源查询 | 1（非菜单） | SYS_CONFIG |
| RES_ROLE_RES_REPLACE | /api/sys/roles/*/resources/replace | POST | 角色资源覆盖绑定 | 1（非菜单） | SYS_CONFIG |
| RES_ROLE_SCOPE_LIST | /api/sys/roles/*/biz-scopes | GET | 角色BizScope查询 | 1（非菜单） | SYS_CONFIG |
| RES_ROLE_SCOPE_REPLACE | /api/sys/roles/*/biz-scopes/replace | POST | 角色范围覆盖配置 | 1（非菜单） | SYS_CONFIG |

### 3.2 资源登记规则

1. **RESOURCE_ID 命名规范**：`RES_` + 模块缩写 + `_` + 功能描述，如 `RES_AUTH_CURRENT`
2. **URL 通配规则**：路径参数位置使用 `*`，如 `/api/sys/roles/*/resources`
3. **ISMENU 取值**：0 = 菜单项（前端导航渲染），1 = 非菜单项（按钮/接口动作）
4. **高危接口必须独立URL**：IMPORT/EXPORT/EXECUTE_SQL/RECALC 等高危动作需有独立 URL
5. **SYS_CODE 固定为 PLATFORM**：V1 只有一个系统编号

## 7. 初始化执行顺序

必须按以下顺序执行初始化 SQL，以满足逻辑外键依赖：

```
1. DDL 建表
   └── docs/schema/ddl-auth.sql

2. 基础种子数据
   ├── 2.1 角色数据 (PT_ROLE)                -- seed-v1.sql 第 2 节
   ├── 2.2 资源数据 (PT_RESOURCE)            -- seed-v1.sql 第 3 节
   └── 2.3 机构数据 (EXT_ORG_INFO)           -- 测试环境手工或导入

3. 关联种子数据
   ├── 3.1 角色-资源绑定 (PT_ROLE_RESOURCE)  -- seed-v1.sql 第 4 节
   └── 3.2 角色-BizScope (PT_ROLE_BIZ_SCOPE) -- seed-v1.sql 第 5 节

4. 测试数据（仅 DEV/TEST）
   ├── 4.1 测试用户 (PT_USER)
   ├── 4.2 用户角色绑定 (PT_USER_ROLE)
   └── 4.3 用户机构关联 (EXT_USER_ORG)
```

**幂等策略**：所有种子数据 SQL 使用 `INSERT IGNORE`，依赖主键/唯一约束防重复，可反复执行。
