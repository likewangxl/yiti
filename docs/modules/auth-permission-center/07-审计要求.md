# AUTH 认证授权中心 -- 审计要求

> AUTH 模块的所有权限变更操作均为高危动作，必须记录审计日志。
> 普通操作由 common-aop 的 `@AuditLog`/`AuditLogAspect` 采集；机构画像和命名机构组高危写操作由 auth 服务在自身事务内经同一审计 SPI 持久化结构化快照。

---

## 1. 高危动作清单

| # | 接口 | HTTP Method | 动作类型 | 审计级别 | 说明 |
|:---|:---|:---|:---|:---|:---|
| 1 | /api/admin/roles/{roleId} | DELETE | PERMISSION_CHANGE | 必须审计 | 角色逻辑删除 |
| 2 | /api/admin/roles/{roleId}/resources | POST | PERMISSION_CHANGE | 必须审计 | 批量绑定角色资源 |
| 3 | /api/admin/roles/{roleId}/resources | PUT | PERMISSION_CHANGE | 必须审计 | 全量更新角色资源（高危） |
| 4 | /api/admin/biz-scopes | POST | PERMISSION_CHANGE | 必须审计 | 保存/更新 BizScope 配置 |
| 5 | /api/admin/biz-scopes/{id} | DELETE | PERMISSION_CHANGE | 必须审计 | 删除 BizScope 配置 |
| 6 | /api/admin/users/{userId}/roles | POST | PERMISSION_CHANGE | 必须审计 | 用户绑定角色 |
| 7 | /api/admin/users/{userId}/roles/{roleId} | DELETE | PERMISSION_CHANGE | 必须审计 | 用户解绑角色 |
| 8 | /api/admin/resources/{resourceId} | DELETE | PERMISSION_CHANGE | 必须审计 | 资源删除 |
| 9 | /api/admin/org-profiles/{orgCode} | PUT | PERMISSION_CHANGE | 必须审计 | 机构本地画像、经营等级和坐标变更 |
| 10 | /api/admin/org-groups | POST | PERMISSION_CHANGE | 必须审计 | 新建命名机构组 |
| 11 | /api/admin/org-groups/{groupCode} | PUT | PERMISSION_CHANGE | 必须审计 | 机构组状态/名称变更 |
| 12 | /api/admin/org-groups/{groupCode}/members | PUT | PERMISSION_CHANGE | 必须审计 | 机构组直接成员覆盖 |
| 13 | /api/admin/org-groups/{groupCode}/roles | PUT | PERMISSION_CHANGE | 必须审计 | 角色-机构组绑定覆盖 |

机构画像、成员和角色绑定均使用独立 URL、独立 `PT_RESOURCE` 和 `@AuditLog` 动作。批量覆盖请求必须提交 `reason`；审计快照记录前后集合差异、操作者、traceId 和版本冲突结果，不能记录密码等敏感字段。

> 实现核对（2026-08-11）：`OrgGroupController` 的五个高危写端点均标记 `@AuditLog(..., serviceManaged=true)`。`OrgGroupService` 在写事务内调用 `OrgGroupAuditService`，后者只依赖 common-aop `AuditLogHandler`；治理模块的持久化实现把 `beforeSnapshot`、`afterSnapshot`、`addedItems`、`removedItems` 写入 `AUDIT_LOG`。若处理器不是持久化实现或 Mapper 写入失败，抛出 `AUTH-50003` 并回滚本次配置变更；普通控制器切面仍保留“审计失败不阻断主流程”的兼容策略。

## 2. 审计记录字段规范

每条审计记录包含以下字段：

| 字段名 | 数据类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| id | varchar(32) | 是 | 审计记录主键（UUID） |
| traceId | varchar(64) | 是 | 链路追踪ID |
| module | varchar(50) | 是 | 模块名（固定 `auth-permission-center`） |
| operator | varchar(50) | 是 | 操作人工号 |
| operatorName | varchar(200) | 是 | 操作人姓名 |
| operatorOrg | varchar(20) | 是 | 操作人机构编码 |
| action | varchar(50) | 是 | 动作类型（PERMISSION_CHANGE） |
| bizType | varchar(50) | 是 | 业务类型（SYS_CONFIG） |
| resourceUrl | varchar(256) | 是 | 接口URL |
| resourceMethod | varchar(10) | 是 | HTTP方法 |
| targetType | varchar(50) | 是 | 操作目标类型（ROLE/RESOURCE/BIZ_SCOPE/USER_ROLE等） |
| targetId | varchar(100) | 是 | 操作目标ID |
| beforeSnapshot | text | 否 | 变更前快照（JSON格式） |
| afterSnapshot | text | 否 | 变更后快照（JSON格式） |
| addedItems | text | 否 | 覆盖成员/角色时新增项的 JSON 数组 |
| removedItems | text | 否 | 覆盖成员/角色时移除项的 JSON 数组 |
| reason | varchar(500) | 是 | 操作原因（高危动作必填） |
| result | varchar(20) | 是 | 操作结果（SUCCESS / FAIL） |
| errorMessage | varchar(500) | 否 | 失败时的错误信息 |
| operateTime | datetime | 是 | 操作时间 |
| clientIp | varchar(50) | 是 | 客户端IP |
| requestBody | text | 否 | 请求体内容（脱敏后） |

## 4. 权限变更可追溯

### 4.1 快照策略

每次权限变更操作必须记录变更前后快照，确保可追溯：

| 变更类型 | beforeSnapshot 内容 | afterSnapshot 内容 |
|:---|:---|:---|
| 角色删除 | 角色完整信息（ID/Code/Name/Status） | 角色信息（Status变为1） |
| 角色资源全量更新 | 角色ID + 变更前资源ID列表 | 角色ID + 变更后资源ID列表 |
| 角色资源批量绑定 | null（增量操作无before） | 角色ID + 新增的资源ID列表 |
| BizScope 新增 | null（新增无before） | 完整的BizScope记录 |
| BizScope 更新 | 变更前的 BizScope 记录 | 变更后的 BizScope 记录 |
| BizScope 删除 | 被删除的 BizScope 记录 | null |
| 用户角色绑定 | 用户ID + 变更前角色ID列表 | 用户ID + 变更后角色ID列表 |
| 用户角色解绑 | 用户ID + 被解绑的角色信息 | null |
| 资源删除 | 资源完整信息 | 资源信息（Status变为1） |
| 机构画像保存 | 画像旧快照（新建时 null） | 画像新快照 |
| 机构组创建/修改 | 创建时 null / 修改前组快照 | 创建后 / 修改后组快照 |
| 机构组成员覆盖 | 组编码 + 旧直接成员列表 | 组编码 + 新直接成员列表；另存 `addedItems`/`removedItems` |
| 机构组角色覆盖 | 组编码 + 旧规范化角色编码列表 | 组编码 + 新规范化角色编码列表；另存 `addedItems`/`removedItems` |

### 4.2 快照查询接口

审计日志的查询由 system-governance-center 模块提供（不在 AUTH 模块范围内），但 AUTH 模块需要保证：

1. 所有快照数据以 JSON 格式存储，便于反序列化
2. 快照中的敏感字段需脱敏（如密码字段不应出现在快照中）
3. 快照数据量不超过 TEXT 字段的存储限制（约 64KB）

## 5. 审计注解使用规范

```java
// Controller 层使用 @AuditLog 注解标记高危接口
@DeleteMapping("/{roleId}")
@BizAuth(bizType = BizType.SYS_CONFIG, action = BizAction.PERMISSION_CHANGE)
@AuditLog(action = "ROLE_DELETE", resourceType = "PT_ROLE", reasonRequired = true)
public ResponseWrapper<Void> deleteRole(
    @PathVariable String roleId,
    @RequestParam @NotBlank String reason) {
    roleService.deleteRole(roleId, reason);
    return ResponseWrapper.success();
}
```

**`@AuditLog` 注解属性：**

| 属性 | 类型 | 说明 |
|:---|:---|:---|
| action | String | 审计动作 |
| resourceType | String | 通用资源类型 |
| reasonRequired | boolean | 是否要求请求携带 reason（默认 false） |
| serviceManaged | boolean | 是否由服务事务内持久化结构化审计（默认 false；true 时切面不重复写空快照） |

## 6. 审计日志保留策略

| 策略 | 说明 |
|:---|:---|
| 在线保留 | 至少 180 天（6个月） |
| 归档保留 | 至少 3 年 |
| 不可修改 | 审计日志表仅允许 INSERT，禁止 UPDATE 和 DELETE |
| 定期备份 | 每月全量备份一次，与数据库备份同步 |
