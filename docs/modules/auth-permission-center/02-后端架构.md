# AUTH 认证授权中心 -- 后端架构

---

## 1. 模块职责边界

### 1.1 负责

- 用户认证（登录/登出/Session管理）
- 当前用户上下文（CurrentUserContext 构建与提供）
- 资源匹配（URL + Method -> RESOURCE_ID）
- 角色资源授权（RBAC 校验）
- BizType 统一数据范围（DataScope 解析与合并）
- 组织树范围（机构子树查询与缓存）
- 权限变更管理与缓存失效
- 与定制框架的表适配：PT_USER / PT_ROLE / PT_RESOURCE / PT_ROLE_RESOURCE / PT_USER_ROLE / EXT_USER_ORG / EXT_ORG_INFO / PT_ROLE_BIZ_SCOPE

### 1.2 不负责

- 不承载客户、线索、触达等营销业务规则
- 不直接读写业务表（客户表、线索表、流程表等）
- 不承载工作流引擎逻辑（Flowable 由 workflow-center 封装）
- 不承载绩效计算、报表分析业务逻辑
- 不直接实现审计日志存储（审计接口定义在 common-aop，存储由 system-governance-center 实现）

### 2.2 依赖规则

| 规则 | 说明 |
|:---|:---|
| 只依赖 common | auth-permission-center 的 pom.xml 中只引入 common 模块 |
| 被所有业务模块依赖 | 所有业务模块通过依赖 auth-permission-center 的 api 包使用权限服务 |

## 4. 分层规范

### 4.1 Controller 层

| 职责 | 约束 |
|:---|:---|
| 接收 HTTP 请求 | 只处理参数接收和参数校验（@Valid） |
| 调用 Service | 不包含复杂业务编排逻辑 |
| 返回统一响应 | 使用 `ResponseWrapper<T>` 包装 |
| 声明权限注解 | 每个方法必须声明 `@BizAuth(bizType, action)` |
| 声明 Swagger 注解 | 使用 Knife4j 注解标注接口文档 |

### 4.2 Service 层

| 职责 | 约束 |
|:---|:---|
| 核心业务逻辑 | 鉴权逻辑、数据范围计算、缓存管理 |
| 事务管理 | 使用 `@Transactional` 管理数据库事务 |
| 权限校验 | 写操作必须在 Service 层做实体级二次权限校验 |
| 缓存管理 | 负责 Redis 缓存的读取、更新和失效 |
| 所有 Service 类和 public 方法必须有注释 | 注释说明业务含义，复杂逻辑须行注释 |

### 4.3 Facade 层

| 职责 | 约束 |
|:---|:---|
| 实现 Api 接口 | 每个 Facade 对应一个 Api 接口 |
| 编排 Service 调用 | 可组合多个 Service 完成跨领域编排 |
| 对外契约实现 | 作为其他模块通过 Api 接口调用的实现类 |
| 注册为 Spring Bean | 使用 `@Service` 或 `@Component` 注解 |

### 4.4 Mapper/Entity 层

| 职责 | 约束 |
|:---|:---|
| 数据库访问 | 模块私有，禁止跨模块引用 |
| MyBatis XML 映射 | 位于 `resources/mapper/auth/*.xml` |
| 实体类 | 与数据库表一一对应，使用驼峰命名 |
| 禁止外部访问 | 其他模块不得直接引用 auth 的 mapper 和 entity |

### 4.5 Security 层

| 组件 | 职责 | 加载顺序 |
|:---|:---|:---|
| `AuthenticationFilter` | 认证拦截（Session/Token校验），建立 CurrentUserContext | Filter（优先级最高） |
| `AuthorizationInterceptor` | RBAC + BizType + DataScope 鉴权主流程 | HandlerInterceptor |
| `ResourceMatcher` | URL + Method -> RESOURCE_ID 匹配（支持Ant通配） | 被 Interceptor 调用 |
| `BizMetaResolver` | 解析 @BizAuth 注解获取 BizType + BizAction | 被 Interceptor 调用 |
| `RbacAuthorizer` | 校验角色是否拥有该资源（查缓存） | 被 Interceptor 调用 |
| `CurrentUserProvider` | ThreadLocal 管理当前用户上下文 | 被 Filter 设置，全链路使用 |

## 5. 错误码

### 5.1 错误码规范

- 前缀：`AUTH`
- 格式：`AUTH-{HTTP状态码}{序号}`，如 `AUTH-40101`

### 5.2 完整错误码清单

| 错误码 | HTTP状态 | 说明 | 触发场景 |
|:---|:---|:---|:---|
| `AUTH-40101` | 401 | 用户名或密码错误 | 登录时用户名不存在或密码不匹配 |
| `AUTH-40102` | 401 | 用户账号已锁定 | PT_USER.ISLOCKED = 1 |
| `AUTH-40103` | 401 | 用户账号已过期 | PT_USER.ISEXPIRED = 1 |
| `AUTH-40104` | 401 | 用户账号未启用 | PT_USER.ISENABLED = 1（未启用） |
| `AUTH-40105` | 401 | 未登录或会话已过期 | Session 无效或已超时 |
| `AUTH-40106` | 401 | 密码错误次数超限 | PASS_WRONG_COUNT 达到阈值（默认5次） |
| `AUTH-40301` | 403 | 无接口访问权限（RBAC拒绝） | 用户角色未绑定该资源 |
| `AUTH-40302` | 403 | 资源未登记 | 请求URL未在PT_RESOURCE中注册 |
| `AUTH-40303` | 403 | 数据范围拒绝 | 用户的DATA_SCOPE不包含目标数据 |
| `AUTH-40304` | 403 | BizType未配置 | 接口未声明@BizAuth或BizType无法解析 |
| `AUTH-40305` | 403 | 实体归属校验失败 | 写操作目标实体不在用户数据范围内 |
| `AUTH-40306` | 403 | 状态约束拒绝 | 实体当前状态不允许该操作 |
| `AUTH-40307` | 403 | 高危动作缺少原因 | 高危操作未提供reason参数 |
| `AUTH-40308` | 403 | 权限缓存不可用（Fail Close） | Redis缓存失效且无法重建 |
| `AUTH-40401` | 404 | 角色不存在 | 根据ROLE_ID查询无结果 |
| `AUTH-40402` | 404 | 资源不存在 | 根据RESOURCE_ID查询无结果 |
| `AUTH-40403` | 404 | 用户不存在 | 根据USER_ID查询无结果 |
| `AUTH-40404` | 404 | 机构不存在 | 根据ORG_CODE查询无结果 |
| `AUTH-40405` | 404 | BizScope配置不存在 | 根据ID查询无结果 |
| `AUTH-40901` | 409 | 角色编码已存在 | 新增角色时ROLE_CODE重复 |
| `AUTH-40902` | 409 | 资源URL+Method已存在 | 新增资源时违反唯一约束 |
| `AUTH-40903` | 409 | BizScope配置已存在 | 同一角色同一BizType已有配置 |
| `AUTH-50001` | 500 | 权限服务内部错误 | 系统异常 |
| `AUTH-50002` | 500 | 缓存服务异常 | Redis连接失败等 |

## 6. 鉴权主流程时序

```
HTTP Request
    |
    v
[AuthenticationFilter] -- Filter 层
    |-- 1. 从 Session/Token 获取用户身份
    |-- 2. 查询 PT_USER + PT_USER_ROLE + EXT_USER_ORG
    |-- 3. 构建 CurrentUserContext 放入 ThreadLocal
    |-- 4. 白名单URL直接放行（/api/auth/login 等）
    |
    v
[AuthorizationInterceptor] -- Interceptor 层
    |-- 5. ResourceMatcher: URL + Method -> PT_RESOURCE
    |       └─ 未匹配 -> AUTH-40302
    |-- 6. RbacAuthorizer: 校验角色是否拥有该资源
    |       └─ 失败 -> AUTH-40301
    |-- 7. BizMetaResolver: 解析 @BizAuth 获取 BizType + Action
    |       └─ 未声明 -> AUTH-40304
    |-- 8. BizScopeService: 合并多角色 DATA_SCOPE
    |-- 9. 构建 DataScopeContext 放入 ThreadLocal
    |-- 10. 高危动作校验 reason 是否必填
    |
    v
[Controller] -> [Service] -> [Mapper]
    |-- 11. Service 层按需执行实体级写操作校验
    |-- 12. DAO 层使用 DataScopeContext 拼接 SQL 条件
    |
    v
[afterCompletion]
    |-- 13. 高危动作审计日志
    |-- 14. 清除 ThreadLocal（DataScopeContext / CurrentUserContext）
```

## 7. 缓存架构

### 7.1 缓存 Key 设计

| 缓存Key模式 | 数据内容 | TTL | 说明 |
|:---|:---|:---|:---|
| `auth:resource:all` | 全量资源列表（PT_RESOURCE） | 5min | 用于ResourceMatcher |
| `auth:role-resource:{roleId}` | 角色绑定的资源ID集合 | 5min | 用于RbacAuthorizer |
| `auth:user-roles:{empId}` | 用户的角色ID集合 | 5min | 用于用户上下文构建 |
| `auth:biz-scope:{roleId}` | 角色的BizType->DataScope映射 | 5min | 用于BizScopeService |
| `auth:org-subtree:{orgCode}` | 机构子树编码集合 | 5min | 用于ORG_SUBTREE范围计算 |
| `auth:org-tree` | 完整组织树 | 10min | 用于组织树展示 |

### 7.2 缓存失效策略

- 权限变更时主动删除受影响的缓存Key
- 同时发布 `permission-cache.invalidated.v1` 事件通知其他模块
- 缓存 TTL = 5分钟，与权限变更生效窗口对齐
- Fail Close：缓存不可用时默认拒绝访问
