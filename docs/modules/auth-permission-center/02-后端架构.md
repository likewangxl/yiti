# AUTH 认证授权中心 -- 后端架构

> 本文只记录当前仍需跨模块共同遵守的架构决策。接口、DTO、错误码和数据模型分别以源码及本模块的 `03`、`04`、`05` 文档为准；类和端点的完整清单不在此重复维护。

## 1. 模块职责与边界

AUTH 负责用户认证、Session 中的当前用户上下文、资源匹配、角色资源授权、BizType 数据范围、组织查询，以及机构本地画像和命名机构组授权。

AUTH 不负责客户、线索、触达、申请、绩效、报表等业务规则，不承载 Flowable 引擎逻辑，也不直接读写其他业务模块的表。外部组织/人员同步表按只读方式使用；画像、机构组及授权关系由 AUTH 自有服务维护。

跨模块调用只能依赖 AUTH `api/` 中的 `*Api`、`*QueryApi` 和 DTO；禁止依赖 mapper、entity、内部 service 或直接联表。AUTH 只依赖 common，不反向依赖业务模块。

## 2. 稳定架构决策

### 2.1 认证与授权

- `AuthenticationFilter` 从 HttpSession 恢复身份；对非白名单 API 实时校验账号状态，并按数据库中的全部有效角色刷新上下文。身份无效时销毁 Session，认证基础设施异常时 Fail Close。
- `AuthorizationInterceptor` 只处理 `/api/**` 的授权链路：先匹配 `PT_RESOURCE`，再执行角色资源校验，然后解析 `@BizAuth` 并构建数据范围上下文。未登记资源必须拒绝；认证自服务资源若有例外，必须在资源与测试中显式登记。
- 多角色授权取有效角色并集；`activeRoleId` 仅为旧客户端兼容字段，不收窄菜单、接口 RBAC、数据范围或流程候选组。
- `SYS_ADMIN` 只跳过代码明确实现的 RBAC 环节，不自动绕过业务白名单、机构组、机构画像或数据范围门禁。

### 2.2 数据读取与装配

- 权限热路径当前直接查询数据库；`PermissionCacheService` 保留的 `evict*` 方法是兼容性 No-op，不代表存在 Redis 或其他共享缓存。权限变更后下次查询读取最新数据库状态。
- 当前用户上下文由认证过滤器写入 `CurrentUserProvider`，数据范围上下文由授权拦截器写入 common 的 ThreadLocal。请求完成、异常和异步任务都必须清理上下文。
- 写操作必须在 Service 层基于目标实体再次校验归属、状态、流程和高危动作；数据库写入使用事务保证绑定、范围和机构配置不留下半套结果。

### 2.3 组件装配

- AUTH 的 `WebMvcAuthConfig` 通过 Spring Boot 自动装配注册认证 Filter 和 MVC 授权拦截器；生产装配受源码中的 profile 条件控制，测试 profile 使用隔离测试配置。
- `api/` 是唯一跨模块边界；`controller/` 只负责 REST 入参/出参，`facade/` 实现对外 API，`service/` 负责业务和事务，`mapper/`、`entity/` 只属于 AUTH 内部。
- common 提供统一响应、异常、链路、审计、数据范围上下文和数据库基础设施；AUTH 不在本模块复制这些公共实现。

## 3. 请求处理链路

```text
HTTP /api/** 请求
    |
    +--> common TraceIdFilter：生成或传播 traceId
    |
    +--> AUTH AuthenticationFilter
    |      +-- 白名单：直接放行
    |      +-- 其他路径：恢复 Session、重查账号状态和有效角色
    |      +-- 认证通过：写入 CurrentUserProvider
    |
    +--> AUTH AuthorizationInterceptor
    |      +-- ResourceMatcher：URL + Method 匹配 PT_RESOURCE
    |      +-- RbacAuthorizer：校验角色资源（自服务例外按显式规则处理）
    |      +-- BizMetaResolver：读取 @BizAuth
    |      +-- BizScopeApi：合并角色范围并写入 DataScopeContext
    |
    +--> Controller -> Service -> Mapper
    |      +-- Service 进行实体级写权限、状态、流程和事务校验
    |      +-- common-aop 记录接口、耗时及声明的审计信息
    |
    +--> common-web：统一异常与 ResponseWrapper 响应
    |
    +--> 完成请求：清理 CurrentUserProvider 和 DataScopeContext
```

`/api` 之外的静态资源和其他入口是否参与认证，以 `AuthenticationFilter`、`WebMvcAuthConfig` 及对应入口源码为准；新增白名单或自服务例外必须同步资源授权和安全测试。
