# AUTH 认证授权中心 -- 接口设计与报文

> 本文档是 AUTH 模块最重要的接口参考文件，所有接口均达到字段级可执行精度。
> 统一响应格式：`ResponseWrapper<T>`，包含 code/message/data/traceId/timestamp 五个字段。

> **2026-07-19 回填说明**：2026-04-08 版仅收录 27/57 端点（覆盖率 47%），本次按 8 个 Controller 源码逐一比对全量枚举，补齐缺失的 30 个端点（A.4-A.8 统一认证与角色切换/菜单、B.6 角色全量查询、D.6 + E.3-E.6 菜单分配与资源反查角色、G.4-G.6 机构增改删、新增 I 节用户通讯录 2 个端点、新增 J 节用户管理 14 个端点），字段/校验注解/错误码/PT_RESOURCE 均从源码与 `docs/superpowers/sql/` 最新对齐脚本、`docs/schema/seed-yiti-prod-golive.sql` 核实。顺带修正两处随之发现的既有偏差：C.2 漏收 `primaryRoleId` 字段；D.1/D.2/D.3 的 `isMenu` 字典方向写反（经 `ddl-auth.sql` 字段注释与 `selectMenus()` 实际 SQL、`seed-yiti-prod-golive.sql` 真实数据交叉验证，正确语义为 **1=是菜单，0=不是**，与本文档原「0是/1不是」相反）。

## A. 会话管理

### A.1 POST /api/auth/login -- 用户登录

- **权限**：无需认证（白名单URL）
- **说明**：验证用户名密码，创建Session，返回用户基本信息与角色列表

**请求体 LoginReqDTO：**

| 字段 | Java类型 | 必填 | 校验注解 | 字典/取值范围 | 示例值 |
|:---|:---|:---|:---|:---|:---|
| username | String | 是 | `@NotBlank @Size(max=50)` | PT_USER.USERNAME | `"E10001"` |
| password | String | 是 | `@NotBlank @Size(min=6, max=64)` | - | `"******"` |

**响应体 LoginRespDTO：**

| 字段 | Java类型 | 说明 |
|:---|:---|:---|
| empId | String | 工号（PT_USER.USER_ID） |
| username | String | 用户名 |
| displayName | String | 中文姓名（PT_USER.USERCHNNAME） |
| mainOrgCode | String | 主机构编码（EXT_USER_ORG.ORG_CODE） |
| mainOrgName | String | 主机构名称（EXT_ORG_INFO.ORG_NAME） |
| deptNo | String | **（2026-07-19 补漏）** 主机构编号（EXT_ORG_INFO.DEPT_NO），前端头部展示用 |
| roles | List\<RoleSimpleDTO\> | 角色列表（登录时按主角色置顶排序，见业务规则 7） |
| token | String | 会话令牌（Spring Session ID） |
| primaryRoleId | String | **（2026-07-19 补漏）** 主角色（当前登录角色）ID |
| primaryRoleCode | String | **（2026-07-19 补漏）** 主角色编码 |
| primaryRoleName | String | **（2026-07-19 补漏）** 主角色中文名 |

**RoleSimpleDTO：**

| 字段 | Java类型 | 说明 |
|:---|:---|:---|
| roleId | String | 角色ID |
| roleCode | String | 角色编码 |
| roleChName | String | 角色中文名 |
| primary | Boolean | **（2026-07-19 补漏）** 是否主角色（用户已分配角色中有且仅有一个为 `true`，即登录时的当前登录角色） |

**业务规则：**
1. 用户名不存在 -> AUTH-40101
2. 密码错误 -> AUTH-40101（不暴露"用户名存在但密码错误"）；同时 PASS_WRONG_COUNT + 1
3. PASS_WRONG_COUNT >= 5 -> 自动锁定（ISLOCKED = 1），返回 AUTH-40106
4. ISLOCKED = 1 -> AUTH-40102
5. ISEXPIRED = 1 -> AUTH-40103
6. ISENABLED = 1（未启用）-> AUTH-40104
7. 登录成功 -> PASS_WRONG_COUNT 重置为 0；查询用户角色列表，**用户无任何角色时禁止登录 -> AUTH-40107**（`USER_NO_ROLE`，2026-07-19 补漏）；取主角色（`PT_USER_ROLE.DEFAULT_ASSIGN=1`，缺失回退第一个角色）置顶排序、写入响应的 `primaryRoleId`/`primaryRoleCode`/`primaryRoleName`，并按"单一当前角色"构建 `CurrentUserContext`（`activeRoleId` = 主角色ID）创建 HttpSession——完整设计见 `auth-permission-center/CLAUDE.md`「session 单激活角色模型」

**错误响应示例：**

```json
{
  "code": "AUTH-40101",
  "message": "用户名或密码错误",
  "traceId": "a1b2c3d4e5f6",
  "data": null,
  "timestamp": "2026-04-01T10:30:00"
}
```

### A.4 POST /api/auth/uniauth/login -- 统一认证登录（开发期 mock / 编程式入口）

- **权限**：无需认证（`AuthenticationFilter.WHITELIST` + `AuthorizationInterceptor.excludePathPatterns` 双重放行，未在 `PT_RESOURCE` 登记）
- **说明**：跳过密码校验，按 `userDomainName` 查 `PT_USER` → 校验账号状态 → 调用行内统一认证边车（`S120030044`）查授权 → 建 Session；正式生产链路请走 A.5 `/uniauth/redirect` 重定向；本端点用于开发期直登或未来编程式集成

**请求体 UniAuthLoginReqDTO：**

| 字段 | Java类型 | 必填 | 校验注解 | 说明 | 示例值 |
|:---|:---|:---|:---|:---|:---|
| userDomainName | String | 是 | `@NotBlank` | AD 域账号 / 工号，对应 `PT_USER.USERNAME` | `"12050965"` |

**响应体**：`LoginRespDTO`（结构同 A.1）

**业务规则：**
1. `userDomainName` 查无用户 → AUTH-40101（`LOGIN_FAILED`，message 改写为"统一认证：用户不存在 userDomainName=..."）
2. 账号锁定/过期/未启用 → 分别 AUTH-40102 / AUTH-40103 / AUTH-40104（复用 `checkAccountStatus`，同 A.1）
3. `UniAuthSidecarClient` 为 `@Autowired(required=false)`，边车未启动时 Bean 为 null → AUTH-40101（message："统一认证客户端未就绪，请检查边车是否启动"）
4. 边车调用异常，或 `S120030044` 返回非成功（`uia.isSuccess()==false`）→ AUTH-40101（message 拼接 `returnCode`/`returnMsg`）
5. 成功后复用 A.1 `login()` 的"查角色 → `resolvePrimaryRoleAndOrder`（用户无任何角色抛 AUTH-40107）→ `buildContextForActiveRole` 建单角色会话上下文 → 写入 Session"逻辑；UIAS 返回的 `UserBscInfo`/`InstInfoList` 额外写入 Session 属性 `UIAS_USER_BSC_INFO`/`UIAS_INST_INFO_LIST`（供下游业务读取，非本接口 JSON 响应体字段）

### A.5 GET /api/auth/uniauth/redirect -- 跳转到 UIAS 单点登录页

- **权限**：无需认证（白名单）
- **说明**：前端"统一认证登录"按钮直接命中此端点；后端拼接 302 跳转 URL 后 `HttpServletResponse.sendRedirect()`，不返回 JSON

**请求参数**：无

**响应**：HTTP 302，`Location` = `platform.sidecar.uniauth.redirect-url`（默认 `"http://uias.uat.spdb.com/NIDP/"`）+ (`?`或`&`) + `ssoTargetParamName`（默认 `"ssotarget"`）+ `=` + URL-encode(`platform.sidecar.uniauth.callback-url`，默认 `"http://localhost:8090/api/auth/uniauth/callback"`)

**业务规则：**
1. 全部配置项来自 `UniAuthProperties`（`@ConfigurationProperties(prefix="platform.sidecar.uniauth")`），本端点不做任何鉴权/业务校验，纯 URL 拼接跳转

### A.6 GET\|POST /api/auth/uniauth/callback -- UIAS 回调端点

- **权限**：无需认证（白名单）
- **说明**：UIAS 认证完成后浏览器 302（简单 SSO）或表单 POST（SAML POST Binding）到此端点；解析用户身份 → 建 Session → 302 跳前端首页

**请求参数**：
- 优先按 **SAML 2.0 POST Binding** 解析：表单字段 `SAMLResponse`（Base64 编码的 SAML XML）
- 解析失败（无 `SAMLResponse` 或解析异常）退化为 query 参数：参数名取 `platform.sidecar.uniauth.user-param-name`（默认 `"userDomainName"`）

**响应**：无 JSON 响应体，一律 302 重定向：

| 结果 | 跳转目标 |
|:---|:---|
| 成功 | `platform.sidecar.uniauth.front-home-url`（默认 `"/#/workspace"`） |
| 缺失用户身份参数 | `/#/login?error=uniauth-missing-user` |
| 登录处理异常 | `/#/login?error=uniauth-failed&msg={URL编码后的异常信息}` |

**业务规则：**
1. SAML XML 解析显式禁用 DOCTYPE（`disallow-doctype-decl=true`）防 XXE，任何新增 XML 解析逻辑须沿用此防护
2. SAML 属性匹配优先级：`<saml:Attribute Name="{userParamName}">` → 兜底 `<saml:NameID>`
3. 取得 `userDomainName` 后复用 `AuthService.loginByUniAuth()`（同 A.4 业务规则 1、2、5）
4. 请求上下文（query 参数/headers/cookies 全量）在 `log.isInfoEnabled()` 时 dump 到日志，供首次联调定位 UIAS 实际传参字段名（定位后应改 `user-param-name` 配置或改取值方式，而非长期依赖日志排查）

### A.7 POST /api/auth/switch-role -- 切换当前角色

- **权限**：需认证（已登录用户）；`PT_RESOURCE` 已登记 `A_SWITCH_ROLE`（`POST /api/auth/switch-role`），并按 `2026-06-02` 对齐脚本（`docs/superpowers/sql/2026-06-02-pt-resource-switch-role-grant-all.sql`）授权给**全部角色**（对 `PT_ROLE` 全量插入 `PT_ROLE_RESOURCE`），等效于任意登录用户可访问；Controller 方法**未声明** `@BizAuth`，`AuthorizationInterceptor` 在 RBAC 通过后直接放行（仅构建含 empId/orgCode/candidateGroupKeys 的最小 `DataScopeContext`，不解析 BizType/DataScope）
- **说明**：切换本次会话的当前激活角色（仅本次 Session 生效，重新登录回落主角色），目标角色必须是当前用户已分配角色；切换后菜单（A.8）、接口 RBAC、DataScope 数据范围、工作流候选组均按新角色重新解析

**请求体 SwitchRoleReqDTO：**

| 字段 | Java类型 | 必填 | 校验注解 | 说明 | 示例值 |
|:---|:---|:---|:---|:---|:---|
| roleId | String | 是 | `@NotBlank @Size(max=64)` | 目标角色ID，必须为当前用户已分配角色之一 | `"R_RM"` |

**响应体**：`ResponseWrapper<RoleSimpleDTO>`（`primary` 固定返回 `true`，标记为切换后的当前激活角色）

**业务规则：**
1. 未登录 → AUTH-40105（`NOT_AUTHENTICATED`）
2. `roleId` 不在当前用户已分配角色列表中 → AUTH-40301（`RBAC_DENIED`，message："无法切换到未分配给当前用户的角色"，语义上更接近"角色不存在/不属于本人"而非常规 RBAC 拒绝，复用同一错误码）
3. 校验通过后按单角色重建 `CurrentUserContext`（`roleIds`/`roleCodes`/候选组仅含目标角色）覆盖写入 Session（`AuthService.SESSION_USER_KEY`）
4. 会话单激活角色模型的完整设计说明见 `auth-permission-center/CLAUDE.md`「session 单激活角色模型」一节

### A.8 GET /api/auth/my-menus -- 当前用户可见菜单树

- **权限**：需认证（已登录用户）；`PT_RESOURCE` 已登记 `A_MY_MENUS`（`GET /api/auth/my-menus`），种子数据中已对绝大多数角色授权；Controller 方法**未声明** `@BizAuth`，与 A.7 同一放行语义
- **说明**：按"本次请求生效角色"（`PermissionCacheService.getEffectiveRoleIds`：会话已切换角色时仅取当前激活角色，否则回退全部已分配角色）过滤菜单——取该角色集合绑定菜单 ID 的并集，再对全量菜单树剪枝：节点自身在集合中，或其后代节点在集合中，则保留，否则丢弃（保证父级分组节点在有子菜单命中时不会断链）

**请求参数**：无

**响应体**：`ResponseWrapper<List<ResourceTreeNodeDTO>>`（字段结构同 D.1）

**业务规则：**
1. `empId` 为空 → 直接返回空列表（不抛异常）
2. 当前生效角色均无绑定菜单（并集为空集）→ 返回空列表
3. 菜单树来源复用 `ResourceService.getMenuTree()`（`IS_MENU=1` 部分，按 `MENU_RANK_NO` 升序；`isMenu` 字典的正确方向见 D.1 更正说明）

## C. 用户角色绑定

### C.1 GET /api/admin/users/{userId}/roles -- 查询用户角色

### G.5 PUT /api/orgs/{orgCode} -- 更新机构信息

**路径参数**：orgCode (String) -- 机构编码

| 字段 | Java类型 | 必填 | 校验注解 | 说明 |
|:---|:---|:---|:---|:---|

- **权限**：`@BizAuth(bizType = SYS_CONFIG, action = CONFIG)`；`PT_RESOURCE` 已登记 `A_USER_UPDATE`

**路径参数**：userId (String)

**请求体 UserUpdateReqDTO（全部字段可选，"传了才更新"语义，不含密码字段）：**

| 字段 | Java类型 | 必填 | 校验注解 | 说明 |
|:---|:---|:---|:---|:---|
| username | String | 否 | `@Size(max=64)` | 非空白才覆盖 |
| userchnname | String | 否 | `@Size(max=64)` | 非空白才覆盖 |
| email | String | 否 | `@Email @Size(max=128)` | 非 `null` 即覆盖（可传空串清空） |
| remark | String | 否 | `@Size(max=256)` | 非 `null` 即覆盖 |
| userType | String | 否 | `@Size(max=8)` | 非 `null` 即覆盖；不传表示不改 |
| orgCode | String | 否 | `@Size(max=20)` | 非空白时 upsert `EXT_USER_ORG`（先 `UPDATE`，0 行受影响则 `INSERT`） |

**业务规则：**
1. userId 不存在 → AUTH-40403（`USER_NOT_FOUND`）

**响应体**：`ResponseWrapper<Void>`

### J.7 DELETE /api/admin/users/{ids} -- 批量删除用户（物理删除）

- **权限**：`@BizAuth(bizType = SYS_CONFIG, action = CONFIG)`（**非** `PERMISSION_CHANGE`，与角色/资源删除均标 `PERMISSION_CHANGE` 的约定不同，现状如此）；`PT_RESOURCE` 已登记 `A_USER_DELETE`
- **说明**：物理删除（`DELETE FROM PT_USER`），**非**逻辑删除

**路径参数**：ids (String[]，逗号分隔)

**业务规则：**
1. ids 为空/超过 `maxBatchIds`（50）/含空白元素 → AUTH-40002（`INVALID_USER_IDS`）

**响应体**：`ResponseWrapper<Integer>` -- 实际删除行数

### J.8 PUT /api/admin/users/me/password -- 当前用户修改密码

- **权限**：`@BizAuth(bizType = SYS_CONFIG, action = PERMISSION_CHANGE)`；`PT_RESOURCE` 已登记 `A_USER_CHANGE_PWD`
- **说明**：**路由声明顺序敏感**——Controller 源码显式注释要求本端点（静态路径 `/me/password`）必须声明在 `/{ids}/xxx` 系列之前，否则 `me` 会被误当作 `ids` 路由匹配

**请求体 ChangeMyPasswordReqDTO：**

| 字段 | Java类型 | 必填 | 校验注解 | 说明 |
|:---|:---|:---|:---|:---|
| oldPassword | String | 是 | `@NotBlank` | 旧密码明文 |
| newPassword | String | 是 | `@NotBlank @Size(min=6, max=64)` | 新密码明文 |

**业务规则：**
1. 旧密码不匹配 → AUTH-40001（`OLD_PASSWORD_MISMATCH`）
2. 校验通过后新密码 BCrypt 加密覆盖

**响应体**：`ResponseWrapper<Void>`

### J.9 PUT /api/admin/users/{userId}/password -- 管理员为指定用户设置新密码

- **权限**：`@BizAuth(bizType = SYS_CONFIG, action = PERMISSION_CHANGE)`；`PT_RESOURCE` 已登记 `A_USER_SETPWD`
- **说明**：区别于 J.8（用户改自己需校验旧密码），本接口由管理员直接覆盖目标用户密码，**不校验旧密码**

**路径参数**：userId (String)

**请求体 AdminSetPasswordReqDTO：**

| 字段 | Java类型 | 必填 | 校验注解 | 说明 |
|:---|:---|:---|:---|:---|
| newPassword | String | 是 | `@NotBlank @Size(min=6, max=64)` | 新密码明文 |
| reason | String | 否 | `@Size(max=200)` | 操作原因；**非强制必填**（与角色/资源类高危写操作"reason 必填"约定不同） |

**业务规则：**
1. userId 不存在 → AUTH-40403（`USER_NOT_FOUND`）
2. 新密码 BCrypt 加密后直接覆盖 `PWD`

**响应体**：`ResponseWrapper<Void>`
