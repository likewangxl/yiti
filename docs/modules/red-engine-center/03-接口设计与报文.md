# 红色引擎接口设计与报文

> 本文以当前 Controller、Service 和 DTO 为准。所有 JSON 接口使用 ResponseWrapper；分页接口使用 PageResult；文件下载返回二进制。资源授权以 PT_RESOURCE、角色关系和源码 BizAuth 的交集为准。

## 1. 通用规则

红色引擎所有业务接口使用 BizType.RED_ENGINE。Service 层按当前用户、党组织/支部范围、任务 assignment 或材料实体再次校验，不能只依赖前端入口或角色隐藏。未知对象、跨范围对象和无效状态按业务错误返回。

任务接口的枚举、分页默认值和字段约束由 api/dto 中的请求对象定义。任务周期按北京时间自然日计算，周期窗口首尾包含；定时任务支持周/月/季度的周期起始或结束窗口，临时任务使用明确的开始和结束时间。

## 2. 党组织与用户映射

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/re/orgs/tree | 查询党组织树 |
| GET | /api/re/orgs/{id} | 查询党组织详情 |
| POST | /api/re/orgs | 创建党组织，入参 RePartyOrgReqDTO |
| PUT | /api/re/orgs/{id} | 修改党组织 |
| DELETE | /api/re/orgs/{id} | 删除党组织，reason 必填；存在下级组织时拒绝 |
| GET | /api/re/user-party-maps | 分页查询用户党组织映射 |
| POST | /api/re/user-party-maps | 绑定/更新用户党组织映射 |

映射中的用户编号来自 PT_USER 的用户目录，partyRole 是展示和任务分配依据，不代替 RBAC 授权。绑定操作会校验用户和党组织，并同步当前开放任务的报送员分配/待办；已完成记录保留，待处理待办按实体归属调整。

## 3. 材料上报与材料审核

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /api/re/submits | 创建材料上报，入参 ReSubmitCreateReqDTO |
| GET | /api/re/submits/my | 查询当前用户材料，pageNo/pageSize 默认值由 Controller 定义 |
| GET | /api/re/submits/{id} | 查询材料详情 |
| GET | /api/re/reviews/queue | 材料审核队列，支持 PENDING/PASSED/REJECTED 页签 |
| GET | /api/re/reviews/{id}/preview | 审核预览 |
| POST | /api/re/reviews/{id}/approve | 审核通过，可附评分和反馈 |
| POST | /api/re/reviews/{id}/reject | 审核驳回，可附反馈 |

材料上报的 RE_SUBMIT.status 使用 0（草稿兼容值）、1（已提交）、2（通过）、3（驳回）。审核范围按审核人所属支部/组织和实体重新判断；自审被拒绝。材料附件使用治理 FileApi 的文件对象编号，不在红色引擎提供独立上传存储端点。

当上报请求同时携带 taskId、taskInstanceId、taskAssignmentId 时，四维材料与任务提交版本建立桥接并更新维度进度；三项上下文均缺失时，保留独立材料上报语义，不伪造任务分配、待办或桥接记录。任务版本被驳回后再次上报才创建下一版本，审核中的当前版本不能被旧入口绕过。

## 4. 任务管理

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/re/tasks | 查询已发布任务分页 |
| POST | /api/re/tasks | 创建并发布任务，返回任务信息 |
| GET | /api/re/tasks/{taskId} | 查询任务定义详情 |
| GET | /api/re/tasks/{taskId}/assignments | 查询任务下支部填报汇总 |
| GET | /api/re/tasks/eligible-users | 按关键字/支部查询可选报送员 |

任务创建请求定义标题、说明、任务性质、业务类型、周期/临时时间、有效范围、文件要求和目标对象。任务性质为 SCHEDULED 或 TEMPORARY（兼容查询值 PERIODIC）；业务类型支持 FOUR_DIMENSION 或 GENERAL。目标对象只能使用全部支部、指定支部或指定员工之一，不能混用或重复。

任务发布写入 PUBLISHED 定义、文件类型、目标范围和状态历史，并按当前有效窗口建立实例、支部 assignment 和报送员待办。尚未进入窗口的定时任务由调度补偿生成；待办以窗口开始时间为可用时间，到点前不展示。任务定义和已生成实例的历史窗口不通过列表编辑回写。

## 5. 任务填报与两级工作台

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/re/tasks/my-assignments | 报送员任务列表/筛选/分页 |
| GET | /api/re/tasks/assignments/{assignmentId} | assignment 当前详情 |
| POST | /api/re/tasks/submissions | 提交或重提任务，入参 ReTaskSubmissionReqDTO |
| GET | /api/re/reviews/tasks/branch/queue | 支部审核队列兼容入口 |
| GET | /api/re/tasks/branch-review | 支部审核队列入口 |
| GET | /api/re/reviews/tasks/branch/{assignmentId} | 支部审核详情兼容入口 |
| GET | /api/re/tasks/branch-review/{assignmentId} | 支部审核详情入口 |
| POST | /api/re/reviews/tasks/branch/{assignmentId}/approve | 支部审核通过兼容入口 |
| POST | /api/re/tasks/branch-review/{assignmentId}/approve | 支部审核通过入口 |
| POST | /api/re/reviews/tasks/branch/{assignmentId}/reject | 支部驳回兼容入口，意见必填 |
| POST | /api/re/tasks/branch-review/{assignmentId}/reject | 支部驳回入口，意见必填 |
| POST | /api/re/reviews/tasks/branch/{assignmentId}/submit-to-org | 提交组织审核兼容入口 |
| POST | /api/re/tasks/branch-review/{assignmentId}/submit-to-org | 提交组织审核入口 |
| GET | /api/re/reviews/tasks/org/queue | 组织审核队列兼容入口 |
| GET | /api/re/tasks/org-review | 组织审核队列入口 |
| GET | /api/re/reviews/tasks/org/{assignmentId} | 组织审核详情兼容入口 |
| GET | /api/re/tasks/org-review/{assignmentId} | 组织审核详情入口 |
| POST | /api/re/reviews/tasks/org/{assignmentId}/approve | 组织审核通过兼容入口 |
| POST | /api/re/tasks/org-review/{assignmentId}/approve | 组织审核通过入口 |
| POST | /api/re/reviews/tasks/org/{assignmentId}/reject | 组织驳回兼容入口，意见必填 |
| POST | /api/re/tasks/org-review/{assignmentId}/reject | 组织驳回入口，意见必填 |

标准任务提交状态为 BRANCH_PENDING、BRANCH_APPROVED、ORG_PENDING、APPROVED，以及支部/组织驳回状态。支部通过后必须单独执行 submit-to-org；驳回后报送员在同一 assignment 上递增提交版本，旧版本和状态历史保留。详情只读取 assignment 指向的当前版本，普通任务正文来自 content/formData，四维任务正文和明细来自桥接的 RE_SUBMIT；两者附件均按当前版本读取。

`GET /api/re/tasks/assignments/{assignmentId}`、支部审核详情和组织审核详情返回
`ReTaskWorkflowAssignmentDTO.reviewHistory`。该字段只包含审核处理历史，不包含报送员的
`SUBMIT:*` 幂等记录；允许的 `actionCode` 为 `APPROVE_BRANCH`、`REJECT_BRANCH`、
`SUBMIT_TO_ORG`、`APPROVE_ORG`、`REJECT_ORG`。每项同时返回 `actionLabel`、`stageLabel`、
`operatorId`、`operatorName`、`occurredAt`、`opinion`、`fromStatus` 和 `toStatus`。
`SUBMIT_TO_ORG` 的动作标签固定为“提交组织审核”，不表示组织已审批。历史按
`occurredAt` 升序、再按历史主键 `id` 升序返回，重复驳回不会去重；用户姓名通过 auth 的公开
`UserApi` 批量补充。分页工作台列表为避免逐行读取历史，`reviewHistory` 返回空集合，打开
assignment 详情后再加载完整轨迹。本变更复用既有 assignment 端点，不新增 REST 端点或
`PT_RESOURCE`。

## 6. 任务附件与导出

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/re/tasks/assignments/{assignmentId}/attachments | 查询当前提交版本附件 |
| GET | /api/re/tasks/{taskId}/assignments/{assignmentId}/attachments/{fileId}/download | 下载任务附件 |
| POST | /api/re/tasks/{taskId}/exports | 创建任务导出 |
| GET | /api/re/task-exports/{exportId} | 查询导出任务状态 |
| GET | /api/re/task-exports/{exportId}/download | 下载成功且未过期的导出文件 |

导出任务以任务、操作者和选定明细项生成幂等键，状态由 PENDING/RUNNING/SUCCESS/FAILED/过期等阶段驱动。后台 worker 在事务提交后执行，生成 Excel/ZIP 并通过 FileApi 保存；状态非成功、文件过期或归属校验失败时禁止下载。

## 7. 首页、驾驶舱与逾期

当前首页入口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/re/home/summary | 首页汇总 |
| GET | /api/re/home/ranking | 支部排名 |
| GET | /api/re/home/warning-pool | 红黄牌预警池 |
| GET | /api/re/home/overdue | 任务逾期列表 |
| POST | /api/re/home/overdue/execute | 执行逾期扣分，reason 必填 |

兼容驾驶舱入口仍由 ReCockpitController 提供：

- GET /api/re/cockpit/overview、/ranking、/overdue；
- GET /api/re/cockpit/warning/red、/warning/yellow；
- POST /api/re/cockpit/overdue/execute（reason 必填）。

逾期服务按实例窗口结束时间、assignment/提交状态判断；已在截止时间前提交或已完成的记录不进入可执行候选。执行时重新校验归属和逾期条件，在事务中写扣分、状态历史和审计。红牌分数低于 60，黄牌为不低于 60 且低于 80；分数阈值以服务常量为准。旧入口是否开放由当前资源状态决定，不以本文绕过授权。

## 8. 接口与状态约束

任务管理、填报、审核、附件、导出、首页和组织接口均要求 RED_ENGINE 资源授权。写接口在 Service 层使用当前实体再次校验，状态不满足时返回冲突；文件只接受治理 FileApi 返回的对象引用。所有操作记录统一审计，拒绝、撤回、逾期扣分、任务发布和导出下载必须保留原因或关联业务键。
