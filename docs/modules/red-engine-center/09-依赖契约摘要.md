# 红色引擎依赖契约摘要

> 本文只记录源码实际消费的公开 API 和边界。完整方法签名、DTO 与异常以依赖模块 api/ 和源码为准。

## 1. 依赖矩阵

| 依赖模块 | API | 用途 |
| --- | --- | --- |
| auth-permission-center | CurrentUserApi | 当前登录员工和会话身份 |
| auth-permission-center | UserApi | 用户、员工、姓名、主机构和可选报送员查询 |
| system-governance-center | DictApi | RE_ITEM_CODE 等启用字典项校验和标签 |
| system-governance-center | FileApi | 材料/任务附件、文件元数据和导出文件 |
| system-governance-center | JobApi | 固定任务窗口补偿的注册/注销 |

红色引擎不消费 workflow-center 的 API 或 Flowable；审核由本模块任务/材料状态机完成。源码也不消费 NotifyApi、BizScopeApi 或其他未列入表中的公开 API。

## 2. CurrentUserApi 与 UserApi

Controller 从 CurrentUserApi 获取当前员工编号，Service 再按目标实体、assignment、党组织映射和角色范围校验。UserApi 用于：

- 任务指定员工和可选报送员查询；
- 用户党组织映射的员工存在性校验；
- 任务/材料展示的姓名、登录名和机构快照；
- 任务导出中主体名称补全。

用户编号、党组织映射和 RED_ENGINE 角色不是同一概念；映射的 partyRole 不自动授予资源权限。

## 3. DictApi

RE_ITEM_CODE 由治理字典维护。任务创建、四维明细和导出会校验编码是否存在且启用，并保留必要的编码/名称快照。红色引擎不直接查询 SYS_DICT，不创建本地字典副本。

## 4. FileApi

附件和导出流程只在红色引擎表中保存 fileObjectId 及展示快照：

- 材料上报、任务提交和提交版本附件在业务实体范围校验通过后读取；
- 文件类型配置由任务定义保存，实际文件由 FileApi 管理；
- 导出 worker 生成 Excel/ZIP 后通过 FileApi 保存，任务表只写对象引用；
- 下载必须先校验任务/assignment/提交版本归属和数据范围。

不能绕过 FileApi 访问 FILE_OBJECT、OBS 或治理 Mapper；对象存储实现由治理模块决定。

## 5. JobApi

ReTaskScheduler 只注册固定 jobKey RED_ENGINE_TASK_WINDOW 和固定 Job 类，执行当前窗口补偿。任务创建请求不接受 jobKey、类名或任意 Cron，调度状态以治理模块为最终事实。它只有在 `spring.quartz.enabled` 和 `redengine.task.scheduler.enabled` 都为 `true`（未设置时均按 `true`）时才装配；任一开关关闭时，任务发布和手动查询仍使用本地服务能力，但窗口补偿不应被文档描述为已运行。

## 6. 本模块的边界

红色引擎目前没有供其他模块调用的 *Api/*QueryApi。其他模块需要党建数据时，不得依赖本模块 entity、mapper 或私有表；应先新增经评审的公开查询 API 和 DTO。报表模块不能把红色引擎表作为通用报表中转层。

## 7. 权限与失败语义

所有跨模块调用都在 Service 层处理空结果、超时和异常；用户/组织/字典/文件查询失败不应被静默替换成越权或错误对象。REST 资源、角色和菜单由 auth-permission-center 管理，业务状态和对象归属由红色引擎管理。API 变更必须同步 03、08 文档与契约测试。
