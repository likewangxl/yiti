# 红色引擎审计要求

> 版本：v1.0
> 最后更新：2026-08-31
> 适用范围：任务发布、任务填报、支部/组织审核、异步导出、逾期扣分

本文记录当前红色引擎任务域的审计动作和留痕边界。审计由平台 `@AuditLog`、common-aop
及治理中心审计处理器统一落库；本文不新增平行审计表或审计实现。资源授权、服务层实体
校验和审计是三个独立门禁，不能用前端隐藏菜单替代任一门禁。

## 1. 当前任务域审计动作

以下动作以当前 Controller 注解为准。`PT_RESOURCE` 是接口调用门禁，`resourceType` 是审计
对象类型，两者不是同一字段。

| 动作 | 方法与路径 | `@AuditLog` | `PT_RESOURCE` | 原因要求 | 备注 |
|---|---|---|---|---|---|
| 发布任务 | `POST /api/re/tasks` | `RE_TASK_PUBLISH` / `RE_TASK` | `P_RE_TASK_CREATE` | 否 | 组织审核员和系统管理员可新增发布；服务层仍校验任务定义 |
| 提交填报 | `POST /api/re/tasks/submissions` | `RE_TASK_SUBMIT` / `RE_TASK_SUBMISSION` | `P_RE_TASK_SUBMIT` | 否 | 报送员提交或重提；版本和状态由任务服务落库 |
| 支部通过 | `POST /api/re/reviews/tasks/branch/{assignmentId}/approve`（兼容别名同理） | `RE_TASK_BRANCH_APPROVE` / `RE_TASK_SUBMISSION` | `P_RE_WF_BAC`、`P_RE_WF_BA` | 否 | 通过后可再提交组织审核 |
| 支部驳回 | `POST /api/re/reviews/tasks/branch/{assignmentId}/reject`（兼容别名同理） | `RE_TASK_BRANCH_REJECT` / `RE_TASK_SUBMISSION` | `P_RE_WF_BRC`、`P_RE_WF_BR` | 是 | 驳回意见由请求 DTO 强制非空 |
| 提交组织审核 | `POST /api/re/reviews/tasks/branch/{assignmentId}/submit-to-org`（兼容别名同理） | `RE_TASK_SUBMIT_TO_ORG` / `RE_TASK_SUBMISSION` | `P_RE_WF_BSC`、`P_RE_WF_BS` | 否 | 支部书记操作，服务层校验当前支部归属 |
| 组织通过 | `POST /api/re/reviews/tasks/org/{assignmentId}/approve`（兼容别名同理） | `RE_TASK_ORG_APPROVE` / `RE_TASK_SUBMISSION` | `P_RE_WF_OAC`、`P_RE_WF_OA` | 否 | 组织审核完成后进入通过态 |
| 组织驳回 | `POST /api/re/reviews/tasks/org/{assignmentId}/reject`（兼容别名同理） | `RE_TASK_ORG_REJECT` / `RE_TASK_SUBMISSION` | `P_RE_WF_ORC`、`P_RE_WF_OR` | 是 | 驳回意见必填，任务回退报送员 |
| 创建导出 | `POST /api/re/tasks/{taskId}/exports` | `RE_TASK_EXPORT` / `RE_TASK` | `P_RE_TASK_EXP_NEW` | 否 | 记录任务范围、明细项快照和异步导出请求 |
| 下载导出 | `GET /api/re/task-exports/{exportId}/download` | `RE_TASK_EXPORT_DOWNLOAD` / `RE_TASK_EXPORT` | `P_RE_TASK_EXP_DL` | 否 | 先校验导出任务归属和成功状态，再读取文件对象 |
| 执行逾期扣分 | `POST /api/re/home/overdue/execute` | `RE_TASK_OVERDUE_DEDUCTION` / `RE_TASK_DEDUCTION` | `P_RE_HOME_EXEC` | 是 | 仅 `SYS_ADMIN`；扣分和幂等校验由服务层完成 |

任务状态查询、队列查询、任务详情和附件下载属于读操作，不另造审计动作；如平台审计策略
要求记录读操作，应沿用治理中心统一查询审计规范，不在红色引擎新增旁路记录。

## 2. 既有资源的审计边界

党组织新增、修改、删除和用户党组织绑定继续使用既有 `RE_ORG_ADD`、`RE_ORG_UPD`、
`RE_ORG_DEL`、`RE_MAP_BIND` 动作。删除党组织的原因已在请求 DTO 中必填；本次角色调整不
改变这些动作的语义。

材料上报、旧审核及驾驶舱历史接口的既有审计动作仍由源码负责；年度归档、旧数据导出和旧
逾期执行资源已在 RBAC 数据中停用，任务域的新审计动作不能通过旧 URL 绕行。历史审计记录
不得因角色合并而删除或重写。

## 3. 留痕数据最小化和脱敏

- 必须记录操作人、动作、资源类型、业务主键、结果、发生时间、traceId（若平台提供）和
  必填原因；失败也应遵循 common-aop 的异常审计策略。
- 任务说明、填报全文、附件二进制、文件对象凭据、Session、令牌和外部存储地址不写入
  审计消息。需要定位时只记录任务/assignment/export 的业务 ID及受控摘要。
- 组织、用户和支部信息以平台审计脱敏规则为准；日志和审计表不得出现完整手机号、证件号、
  账号凭据或 OBS 密钥。
- 导出动作只记录导出任务 ID、任务 ID、选择的明细编码快照及结果状态，不复制 ZIP/Excel
  内容；下载审计不暴露文件内容。

## 4. 验收要点

1. 逐个调用上述写端点，确认动作名、`resourceType`、操作人和业务主键进入统一审计链；
   驳回、删除和逾期扣分缺少原因时在参数校验阶段拒绝。
2. 用无资源角色、错误支部或非组织审核员身份请求写端点，确认 RBAC 与服务层均 fail-close，
   且不产生成功审计记录。
3. 重复提交、重复扣分和重复下载请求按业务幂等/状态规则处理，审计记录可区分尝试与成功。
4. 审计验证使用隔离库和脱敏证据，不读取或修改生产库；本次 RBAC DML 与执行边界见
   `08-初始化数据清单.md`。
