# 红色引擎审计要求

> 审计动作以当前 Controller 的 AuditLog 注解和统一审计组件为准；本文不新增平行审计表或日志链路。

## 1. 当前审计动作

| 领域 | action / resourceType | reason |
| --- | --- | --- |
| 党组织 | RE_ORG_ADD/UPD/DEL / RE_PARTY_ORG | 删除必填 |
| 用户映射 | RE_MAP_BIND / RE_USER_PARTY_MAP | 不强制 |
| 材料上报 | RE_SUBMIT_ADD / RE_SUBMIT | 按接口要求 |
| 材料审核 | RE_REVIEW_APPROVE/REJECT / RE_SUBMIT | 按接口要求 |
| 任务发布 | RE_TASK_PUBLISH / RE_TASK | 按接口要求 |
| 任务填报 | RE_TASK_SUBMIT / RE_TASK_SUBMISSION | 按接口要求 |
| 支部工作台 | RE_TASK_BRANCH_APPROVE/REJECT、RE_TASK_SUBMIT_TO_ORG / RE_TASK_SUBMISSION | 驳回必填 |
| 组织工作台 | RE_TASK_ORG_APPROVE/REJECT / RE_TASK_SUBMISSION | 驳回必填 |
| 逾期处理 | RE_TASK_OVERDUE_DEDUCTION / RE_TASK_DEDUCTION | 必填 |
| 驾驶舱兼容逾期 | RE_OVERDUE_EXECUTE / RE_OVERDUE_DEDUCTION | 必填 |
| 任务导出 | RE_TASK_EXPORT / RE_TASK；RE_TASK_EXPORT_DOWNLOAD / RE_TASK_EXPORT | 按接口要求 |

普通列表、详情和附件查询不在红色引擎 Controller 上单独记录 AuditLog，但仍须保留统一访问日志所需的 traceId、操作者和耗时。

## 2. 留痕内容

写操作至少记录操作者、业务主键、traceId、动作、请求摘要、执行结果和失败原因。状态机动作还应记录 fromStatus、toStatus、任务/实例/assignment/提交版本和意见；任务发布应记录窗口、目标范围和文件要求摘要；导出应记录任务选项、行数/文件引用和下载结果。

审计快照只保存定位和复核所需的最小字段，不写正文、附件内容、完整 SQL、凭据或整份对象 JSON。驳回意见和逾期扣分原因保留原业务语义，敏感字段按治理中心脱敏规则处理。

## 3. 一致性与权限

审计调用不能替代 Service 层实体权限校验。状态、历史、待办、文件关系提交成功后才视为业务动作完成；失败事务不得留下成功审计。异步导出区分创建、执行成功/失败和下载，不能把创建任务记为文件已生成。

同一请求的兼容工作流路径复用同一服务和审计动作，不能通过旧 URL 绕过资源授权。高风险动作使用独立资源和 reasonRequired；SYS_ADMIN 仍受业务对象和数据范围校验约束。

## 4. 验收

验收逐项核对：Controller 的 AuditLog 与 PT_RESOURCE 绑定一致；reasonRequired 接口缺少 reason 会被拒绝；状态转换、驳回、逾期和导出任务均可按 traceId/业务主键关联；日志和审计中不存在明文账号、手机号、证件号、金额或文件内容。
