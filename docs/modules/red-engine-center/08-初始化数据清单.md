# 红色引擎初始化数据清单

> 版本：v1.3
> 最后更新：2026-09-03
> 适用范围：任务域菜单、API 资源、角色合并及历史资源停用

本文是初始化数据设计与验收清单，不是 DDL，也不是无审批即可执行的生产脚本。任务域已有配套
RBAC DML 为 `docs/superpowers/sql/2026-08-31-redengine-task-rbac-align.sql`；本次书记 legacy
材料授权补充 DML 为 `docs/superpowers/sql/2026-09-03-redengine-secretary-material-review-grant.sql`。
补充脚本已在隔离库 `yiti_test` 首次新增 3 条资源关系，幂等复跑后仍为 3 条；`yiti` 尚未执行。

本轮同步契约文档并新增上述补充 SQL，但不声称生产库已完成授权。投产 DML 必须按现行数据库门禁，
幂等补齐 `R_RE_SECR` 与 `P_RE_REVIEW_Q`、`P_RE_REVIEW_APPR`、`P_RE_REVIEW_REJ` 的资源关系；
这三项资源分别覆盖 legacy 队列/预览、通过和驳回。若目标库仍按旧对齐脚本将这些关系改挂停用的
`R_RE_BRREV`，书记调用 `/api/re/reviews/**` 会得到已确认的 `AUTH-40301`，须先完成审批、隔离库
验证和生产 DML，再以第 7 节验收；不能把本文档存在当作数据库权限已生效。

## 1. 初始化前置条件

- 目标库应已由 DBA 实施并核验任务域表结构；本文不生成或替代结构变更。
- 执行前保存目标库受控备份、表/行数清单和 RBAC 摘要；每次执行只连接明确目标库：隔离验证阶段
  只写 `yiti_test`，生产确认前不写 `yiti`，生产执行时也不得连带修改其他 schema。
- 脚本只能使用事务控制、`INSERT` 和 `UPDATE`；不包含 DDL、`DELETE`、独立检查查询、
  临时表、存储过程、事件或触发器。只读盘点和执行后验收必须在脚本外完成。

## 2. 菜单资源

所有菜单资源使用 `SYS_CODE='RE'`，挂在现有 `M_RE_ENGINE` 下，页面继续复用红色引擎
布局。资源编码和菜单标题如下：

| RESOURCE_ID | URL | 菜单标题 |
|---|---|---|
| `M_RE_REPORT` | `/redengine/report` | 四大维度材料上报 |
| `M_RE_RECORDS` | `/redengine/records` | 任务处理 |
| `M_RE_BRANCH_WORK` | `/redengine/branch-review` | 任务处理 |
| `M_RE_COCKPIT` | `/redengine/cockpit` | 全局数据驾驶舱 |
| `M_RE_WARNING` | `/redengine/warning` | 红黄牌预警池 |
| `M_RE_REVIEW_WORK` | `/redengine/review` | 工作台 |
| `M_RE_TASK_MGMT` | `/redengine/task-management` | 任务管理 |
| `M_RE_ORG_MANAGE` | `/redengine/org-manage` | 党组织管理 |
| `M_RE_USER_MAP` | `/redengine/user-map` | 用户党组织映射 |

菜单绑定只控制页面可见性，不自动推导 API 权限；API 资源必须按下表单独授权。
`M_RE_RECORDS` 与 `M_RE_BRANCH_WORK` 虽使用相同的用户可见标题“任务处理”，仍分别对应报送员任务处理
和支部书记待办处理，路由、资源及角色授权不合并。

## 3. API 资源范围

DML 登记任务、首页、工作流、附件和异步导出端点，资源 URL 以当前 Controller 为准：

- 首页：`P_RE_HOME_SUM`、`P_RE_HOME_RANK`、`P_RE_HOME_WARN`、`P_RE_HOME_OVER`、
  `P_RE_HOME_EXEC`；逾期列表和执行动作只授予 `SYS_ADMIN`。
- 任务管理：`P_RE_TASK_LIST`、`P_RE_TASK_CREATE`、`P_RE_TASK_ELIGIBLE`、`P_RE_TASK_GET`、
  `P_RE_TASK_ASG_LIST`。
- 报送与附件：`P_RE_TASK_MY`、`P_RE_TASK_ASG_GET`、`P_RE_TASK_SUBMIT`、
  `P_RE_TASK_F_LIST`、`P_RE_TASK_F_DOWN`。
- legacy 材料审核路径：`P_RE_REVIEW_Q`（队列/预览）、`P_RE_REVIEW_APPR`、`P_RE_REVIEW_REJ`；
  该组资源支撑无任务上下文的 `RE_SUBMIT` 来源，必须正式绑定 `R_RE_SECR`，不能因 `R_RE_BRREV`
  停用而从书记任务处理能力中移除。`source=material` 只作前端来源标识，不能替代这组资源或复用标准
  task URL。
- 支部工作流：`P_RE_WF_BQ`、`P_RE_WF_BG`、`P_RE_WF_BA`、`P_RE_WF_BR`、
  `P_RE_WF_BS` 及标准路径对应的 `P_RE_WF_BQC`、`P_RE_WF_BGC`、`P_RE_WF_BAC`、
  `P_RE_WF_BRC`、`P_RE_WF_BSC`。
- 组织工作流：`P_RE_WF_OQ`、`P_RE_WF_OG`、`P_RE_WF_OA`、`P_RE_WF_OR` 及标准路径
  对应的 `P_RE_WF_OQC`、`P_RE_WF_OGC`、`P_RE_WF_OAC`、`P_RE_WF_ORC`。
- 异步导出：`P_RE_TASK_EXP_NEW`、`P_RE_TASK_EXP_GET`、`P_RE_TASK_EXP_DL`。

标准工作流路径的队列资源 `MENU_RANK_NO=-20`、详情和动作资源 `-10`，用于确保具体路径
先于宽泛路径匹配；任务详情通配资源按当前契约使用 `MENU_RANK_NO=10`。legacy
`P_RE_REVIEW_Q` 继续覆盖 `/api/re/reviews/**` 的旧队列/预览路径，不能抢先匹配标准任务工作流路径。

## 4. 角色与菜单/API授权矩阵

| 角色 | 当前菜单 | 任务/工作流能力 | 特别限制 |
|---|---|---|---|
| `R_RE_REPORT` | 首页、四维材料上报、任务处理、红黄牌预警池 | 我的任务、任务详情、提交和附件读写 | 不可管理任务或审核 |
| `R_RE_SECR` | 首页、任务处理、红黄牌预警池 | 支部书记任务 assignment 待办、legacy 四维材料队列/预览/通过/驳回、任务详情和附件读取 | 不展示四维材料上报、报送员任务处理、任务管理、组织管理；legacy 读写必须限制当前书记支部范围；不可组织审核 |
| `R_RE_ORGREV` | 首页、驾驶舱、红黄牌预警池、工作台、任务管理、党组织管理、用户映射 | 任务新增发布、任务可选员工查询、任务支部进度、组织工作流、附件读取、异步导出、组织管理和映射；旧四维审核资源关系仅作历史保留，当前 legacy 接口不授予该角色 | 不授予四维材料上报、报送员任务处理、支部书记任务处理；逾期扣分不授予 |
| `SYS_ADMIN` | 全部当前菜单（不含历史归档/旧导出） | 全部任务、支部/组织工作流、导出、组织管理、映射和逾期扣分 | 仍受业务服务层实体校验 |

`R_RE_BRREV` 角色停用。原支部审核员用户通过 `INSERT ... SELECT` 补齐 `R_RE_SECR` 平台
角色；`RE_USER_PARTY_MAP.PARTY_ROLE='BRANCH_REVIEWER'` 更新为 `SECRETARY`。既有平台角色
关系不删除，支部书记角色旧的报送/驾驶舱/组织/旧审核关系改挂已停用角色，以达到合并后的有效
权限边界并保留审计历史。

红牌、黄牌预警池（`M_RE_WARNING` / `P_RE_HOME_WARN`）对全部启用的红色引擎角色开放；
逾期上报待执行扣分（`P_RE_HOME_OVER` / `P_RE_HOME_EXEC`）只向 `SYS_ADMIN` 授权。

书记任务处理的 API 授权由两组资源共同组成：新任务 assignment 使用 `P_RE_WF_*`，无任务上下文的
legacy `RE_SUBMIT` 使用并必须正式绑定到 `R_RE_SECR` 的 `P_RE_REVIEW_Q`/`P_RE_REVIEW_APPR`/
`P_RE_REVIEW_REJ`。后者对 `R_RE_SECR` 的生效不等于开放旧的“四维材料上报”菜单；菜单仍只显示
“任务处理”，服务端还必须对 `RE_SUBMIT.orgId` 执行当前书记支部范围实体校验。首页 `P_RE_HOME_SUM`
同样在任务待办之外汇总该范围内 `status=1` 的 legacy 材料。标准 task URL 只处理 assignment 来源，
不作为无任务材料的权限或接口兼容替代。

## 5. 历史资源处理

以下旧入口只更新 `PT_RESOURCE.STATUS=1`，不删除资源或关系：

- `P_RE_CKPT_ANNUAL`：年度考核归档；
- `P_RE_EXPORT`：旧同步数据导出；
- `P_RE_CKPT_EXEC`：旧驾驶舱逾期执行入口。逾期扣分已迁移到首页新接口，且该旧入口的
  服务层没有新的系统管理员专属守卫，停用它用于避免绕过新门禁。

历史菜单/关系和审计记录不因停用而删除；新任务管理及异步导出资源单独登记和授权。

## 6. 字典与跨模块边界

本清单不插入 `RE_ITEM_CODE` 字典值，也不创建物理 `RE_ITEM_CODE` 表。当前明细项来自治理
中心 `SYS_DICT` 的既有分组；正式实现通过 `DictApi` 校验启用编码。任务域不再维护只读投影，
也不能通过初始化 DML 新增字典物理表或扩大治理数据。

文件、调度、通知分别通过治理 `FileApi`、`JobApi`、`NotifyApi` 边界；本 DML 不写治理表、
Quartz/Session/锁表或通知表。

## 7. 执行后验收

在脚本外只读核验：菜单/API 资源存在且 URL、方法、排序和父资源正确；所有新资源无重复；
四个角色有效资源矩阵符合第 4 节；投产 DML 完成后 `R_RE_SECR` 同时具备 `P_RE_WF_*` 与
`P_RE_REVIEW_Q`/`P_RE_REVIEW_APPR`/`P_RE_REVIEW_REJ` legacy 审核资源，且
legacy 队列/预览/动作均按书记支部范围 fail-close；书记首页只追加本支部 `RE_SUBMIT.status=1`；
`R_RE_BRREV` 已停用且用户角色/党内角色完成迁移；三项历史资源为停用；首次执行只补齐基线缺失关系，
重复执行前后目标关系数量和摘要保持一致；未作为本次目标的其他 schema 与业务表不发生变化。

验收证据应脱敏、最小化并限制留存。生产执行仍需 DBA 审批和独立隔离验证，不以本清单或
`yit_test` 成功作为生产授权。
