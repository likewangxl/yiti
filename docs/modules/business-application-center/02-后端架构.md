# 业务申请中心 — 后端架构

> 模块代码：`business-application-center`
> 基础包名：`com.bank.branch.platform.bizapp`
> 文档版本：V1.0

---

## 1. 模块职责边界

### 1.1 负责

- **资产投放申请**：`loan_apply` 表建模、字段校验、状态机、与 `workflow-center` 的流程绑定
- **中场支持申请**：`support_request` 表建模、来源规则、场景 A/B 路由、多产品拆单、双视图权限
- **秘书派单**：秘书视角下的派单、转交动作
- **业务表单校验**：公司部审核节点的信贷会字段等节点专属字段
- **业务侧状态机**：`BizStateMachine` 统一管理 LOAN/SUPPORT 的状态迁移
- **跨业务查询聚合**：`BizApplyQueryApi` 提供按客户维度的统计能力

### 1.2 不负责

- **不管理客户池**：仅持有 `custId` 外键，所有客户信息通过 `CustomerQueryApi` 获取
- **不维护产品资料**：仅持有 `productId` 外键，产品元数据由 `portal-content-center` 维护
- **不计算 KPI**：绩效指标由 `performance-engine-center` 基于领域事件或只读查询计算
- **不直接操作 Flowable**：Flowable API 的唯一出口是 `workflow-center`
- **不维护通讯录**：员工信息、组织架构由 `portal-content-center` 维护
- **不维护字典**：字典由 `system-governance-center` 维护，本模块仅消费

## 4. 分层规范

### 4.1 Controller 层

**职责**：

- HTTP 请求路由
- 请求参数绑定与字段级校验（`@Valid` + JSR 380）
- `@BizAuth` 注解声明业务类型 + 动作 + 数据范围
- 委托到 Service 层，不写业务逻辑
- 返回统一 `R<T>` 响应

**规范**：

```java
@RestController
@RequestMapping("/api/loans")
@Tag(name = "资产投放申请")
@Slf4j
public class LoanController {

    private final LoanService loanService;
    private final LoanApplyService loanApplyService;

    @GetMapping("/{id}")
    @Operation(summary = "资产投放申请详情")
    @BizAuth(bizType = "LOAN", action = "READ")
    public R<LoanApplyDetailRespDTO> detail(@PathVariable @NotBlank String id) {
        return R.success(loanService.getDetail(id));
    }

    @PostMapping
    @Operation(summary = "创建资产投放草稿")
    @BizAuth(bizType = "LOAN", action = "WRITE")
    public R<LoanApplyRespDTO> create(@Valid @RequestBody LoanApplyCreateReqDTO req) {
        return R.success(loanApplyService.createDraft(req));
    }

    // ... 其他接口
}
```

**禁止**：

- Controller 直接调用 Mapper
- Controller 直接调用外部模块的 Api（除非是"辅助查询型"的纯代理，且必须通过单独的 QueryController）
- Controller 持有业务状态

### 4.2 Service 层

**职责**：

- 业务编排（Transaction 边界在此）
- 跨模块 Api 调用
- 状态机迁移
- 调用 Mapper 持久化
- 发布领域事件

**规范**：

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class LoanService {

    private final LoanApplyService loanApplyService;
    private final LoanFormValidator loanFormValidator;
    private final BizStateMachine bizStateMachine;
    private final WorkflowApi workflowApi;
    private final CustomerQueryApi customerQueryApi;
    private final EventPublisher eventPublisher;

    /**
     * 提交资产投放申请进入审批流程
     * <p>
     * 1. 校验草稿状态
     * 2. 校验客户有效性（公司客户 + 已审批）
     * 3. 状态迁移 DRAFT → IN_APPROVAL
     * 4. 调用 WorkflowApi.startProcess 启动流程
     * 5. 回写 process_instance_id
     * 6. 发布 LoanSubmittedEvent
     */
    @Transactional(rollbackFor = Exception.class)
    public SubmitRespDTO submit(String loanId) {
        // 1. 锁行并读草稿
        LoanApply loan = loanApplyService.lockForSubmit(loanId);

        // 2. 校验客户
        if (!customerQueryApi.isCompanyApproved(loan.getCustId())) {
            throw new BizException(BizAppErrorCode.CUSTOMER_NOT_VALID_COMPANY);
        }

        // 3. 状态迁移
        bizStateMachine.transitLoan(loan, LoanStatus.IN_APPROVAL);

        // 4. 启动流程
        Map<String, Object> vars = buildProcessVariables(loan);
        String piid = workflowApi.startProcess(
            "loan_approve_v1",
            loan.getBusinessKey(),
            vars
        );

        // 5. 回写 processInstanceId
        loanApplyService.updateProcessInstanceId(loan.getId(), piid);

        // 6. 发布事件
        eventPublisher.publish(new LoanSubmittedEvent(loan.getId(), piid));

        return SubmitRespDTO.of(piid);
    }
}
```

**规范要点**：

- `@Transactional` 只在业务 Service 层标注
- 跨模块 Api 调用 **不在事务内**（应该通过预查询 + 事后发事件解耦）
- 所有 public 方法必须有 Javadoc 注释
- 敏感字段（金额、身份证）日志输出必须脱敏

### 4.3 Mapper 层

- 使用 MyBatis XML 映射
- 所有查询都通过 `<include>` 复用字段列表，禁止 `SELECT *`
- 所有更新带 `deleted = 0` 或 `version` 乐观锁
- 分页使用 `PageHelper`

### 4.4 Entity 层

- 字段直接映射数据库列
- 使用 Lombok `@Data` + `@Builder`
- 继承 `BaseEntity`（含 `createdBy/createdTime/updatedBy/updatedTime/deleted`）
- **禁止** 在 Entity 中写业务方法

### 4.5 Convert 层（MapStruct）

```java
@Mapper(componentModel = "spring")
public interface LoanConvert {
    LoanConvert INSTANCE = Mappers.getMapper(LoanConvert.class);

    LoanApplyDTO toDTO(LoanApply entity);

    List<LoanApplyDTO> toDTOList(List<LoanApply> entities);

    @Mapping(target = "id", ignore = true)
    @Mapping(target = "applyNo", ignore = true)
    @Mapping(target = "status", constant = "DRAFT")
    @Mapping(target = "businessKey", ignore = true)
    @Mapping(target = "processInstanceId", ignore = true)
    LoanApply toEntity(LoanApplyCreateReqDTO req);
}
```

### 4.6 Facade 层

- 实现 `api/` 下的 `*Api` 接口
- 内部委托到 Service 层
- 不含事务
- 不做权限校验（调用方已自行校验）
- 添加 `@Component` 由 Spring 扫描，对外通过 `@Resource` 注入

```java
@Component
@RequiredArgsConstructor
public class LoanApiImpl implements LoanApi {

    private final LoanApplyService loanApplyService;
    private final LoanConvert loanConvert;

    @Override
    public Optional<LoanApplyDTO> getLoanApply(String applyId) {
        LoanApply entity = loanApplyService.getById(applyId);
        return Optional.ofNullable(entity).map(loanConvert::toDTO);
    }

    // ...
}
```

| BIZ-40906 | 409 | 同产品已有进行中的中场支持 | 同一客户 + 同一产品已有 IN_APPROVAL/IN_PROGRESS 记录 |
| BIZ-40907 | 409 | 同客户在途申请数达上限 | 触发并行数阈值（未带确认 Header） |
| BIZ-42201 | 422 | 节点表单必填字段缺失 | 公司部审核节点未填 isNeedCreditMeeting |

| BIZ-42204 | 422 | 担保方式不在字典范围 | guaranteeType 值不在 GUARANTEE_TYPE 字典内 |

| BIZ-50002 | 500 | 拆单事务失败 | 多产品拆单过程中发生异常 |

- 前缀固定 `BIZ-`
- 5 位数字：第 1 位=数量级，后 2 位对齐 HTTP Status，最后 2 位=序号
- 所有错误码统一在 `BizAppErrorCode.java` 枚举中声明

## 6. 场景路由逻辑（SupportScenarioRouter）

### 6.1 路由器签名

```java
@Service
public class SupportScenarioRouter {

    /**
     * 判定场景 A / B
     */
    public SupportScenario route(List<String> productIds, String otherDemand, String supportDeptId) {
        boolean hasProduct = productIds != null && !productIds.isEmpty();
        boolean hasOtherDemand = StringUtils.hasText(otherDemand);

        if (!hasProduct && !hasOtherDemand) {
            throw new BizException(BizAppErrorCode.MISSING_PRODUCT_OR_DEMAND);
        }

        // 场景 B 判定：有其他需求 或 未选产品
        if (hasOtherDemand || !hasProduct) {
            if (!StringUtils.hasText(supportDeptId)) {
                throw new BizException(BizAppErrorCode.SCENARIO_B_NEED_DEPT);
            }
            return SupportScenario.B;
        }

        return SupportScenario.A;
    }

    /**
     * 根据场景选择流程定义 Key
     */
    public String getProcessDefKey(SupportScenario scenario) {
        return switch (scenario) {
            case A -> "support_simple_v1";
            case B -> "support_complex_v1";
        };
    }
}
```

### 6.2 多产品拆单逻辑

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class SupportProductSplitService {

    private final SupportRequestMapper supportRequestMapper;
    private final WorkflowApi workflowApi;
    private final SupportScenarioRouter scenarioRouter;
    private final ProductApi productApi;
    private final EventPublisher eventPublisher;

    /**
     * 多产品拆单提交
     *
     * 规则：
     *   - 每个 productId 生成独立的 support_request 记录
     *   - 同批申请共享 submit_group_id
     *   - 每条记录独立启动流程
     *   - 任一条失败整体回滚（事务内完成拆单和流程发起）
     */
    @Transactional(rollbackFor = Exception.class)
    public SupportRequestCreateRespDTO createSplit(
            SupportRequestCreateReqDTO req,
            String currentEmpId,
            String currentOrgId) {

        String submitGroupId = IdUtils.uuid();
        List<SubmitResultItem> results = new ArrayList<>();

        for (String productId : req.getProductIds()) {
            // 1. 校验产品
            ProductDTO product = productApi.getProduct(productId)
                .orElseThrow(() -> new BizException(BizAppErrorCode.PRODUCT_NOT_FOUND));
            if (!Boolean.TRUE.equals(product.getSupportForSupportRequest())) {
                throw new BizException(BizAppErrorCode.PRODUCT_NOT_SUPPORT);
            }

            // 2. 生成实体
            SupportRequest entity = buildEntity(req, productId, submitGroupId, currentEmpId, currentOrgId);
            entity.setStatus(SupportStatus.IN_APPROVAL.name());
            supportRequestMapper.insert(entity);

            // 3. 启动流程（场景 A）
            String processDefKey = scenarioRouter.getProcessDefKey(SupportScenario.A);
            Map<String, Object> vars = Map.of(
                "supportRequestId", entity.getId(),
                "productId", productId,
                "candidateEmpIds", product.getResponsibleEmpIds()
            );
            StartProcessCmd startCmd = new StartProcessCmd();
            startCmd.setBizType("SUPPORT");
            startCmd.setBizId(entity.getId());
            startCmd.setBusinessKey(entity.getBusinessKey());
            startCmd.setProcessDefinitionKey(processDefKey);
            startCmd.setStartUser(currentEmpId);
            startCmd.setStartOrgId(currentOrgId);
            startCmd.setTitle("中场支持申请-" + entity.getId());
            startCmd.setVariables(vars);
            WorkflowLaunchResp launchResp = workflowApi.startProcess(startCmd);
            supportRequestMapper.updateProcessInstanceId(entity.getId(), launchResp.getProcessInstanceId());

            // 4. 发事件
            eventPublisher.publish(new SupportSubmittedEvent(entity.getId(), piid, submitGroupId));

            results.add(SubmitResultItem.of(entity.getId(), productId, piid));
        }

        return SupportRequestCreateRespDTO.of(submitGroupId, results);
    }
}
```

## 7. 节点表单校验

### 7.1 LoanFormValidator

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class LoanFormValidator {

    private final WorkflowApi workflowApi;

    /**
     * 节点表单校验
     *
     * 调用时机：Controller 接到节点办理请求后，在调用 workflow-center 当前任务办理入口之前
     *
     * @param nodeKey  节点 Key（如 loan_corp_review）
     * @param formData 处理人提交的表单数据
     */
    public void validateNodeForm(String nodeKey, Map<String, Object> formData) {
        // 1. 读节点配置（从 workflow-center 获取）
        NodeFormConfigDTO config = loadNodeFormConfigFromWorkflow(taskId, nodeKey);

        // 2. 校验必填字段
        for (String field : config.getRequiredFields()) {
            if (!formData.containsKey(field) || formData.get(field) == null) {
                if ("isNeedCreditMeeting".equals(field)) {
                    throw new BizException(BizAppErrorCode.MISSING_IS_NEED_CREDIT_MEETING);
                }
                throw new BizException(BizAppErrorCode.NODE_FORM_MISSING, field);
            }
        }

        // 3. 条件必填：isNeedCreditMeeting=true 时 creditMeetingConclusion 必填
        if ("loan_corp_review".equals(nodeKey)) {
            Boolean isNeedCreditMeeting = (Boolean) formData.get("isNeedCreditMeeting");
            if (Boolean.TRUE.equals(isNeedCreditMeeting)) {
                Object conclusion = formData.get("creditMeetingConclusion");
                if (!(conclusion instanceof String s) || !StringUtils.hasText(s)) {
                    throw new BizException(BizAppErrorCode.MISSING_CREDIT_MEETING_CONCLUSION);
                }
            }
        }
    }
}
```

## 8. 业务状态机

### 8.1 BizStateMachine

```java
@Service
@Slf4j
public class BizStateMachine {

    private static final Map<LoanStatus, Set<LoanStatus>> LOAN_TRANSITIONS = Map.of(
        LoanStatus.DRAFT, Set.of(LoanStatus.IN_APPROVAL),
        LoanStatus.IN_APPROVAL, Set.of(LoanStatus.COMPLETED, LoanStatus.REJECTED, LoanStatus.CANCELLED),
        LoanStatus.COMPLETED, Set.of(),
        LoanStatus.REJECTED, Set.of(),
        LoanStatus.CANCELLED, Set.of()
    );

    private static final Map<SupportStatus, Set<SupportStatus>> SUPPORT_TRANSITIONS = Map.of(
        SupportStatus.DRAFT, Set.of(SupportStatus.IN_APPROVAL),
        SupportStatus.IN_APPROVAL, Set.of(
            SupportStatus.IN_PROGRESS,
            SupportStatus.COMPLETED,
            SupportStatus.REJECTED,
            SupportStatus.CANCELLED
        ),
        SupportStatus.IN_PROGRESS, Set.of(SupportStatus.COMPLETED, SupportStatus.REJECTED),
        SupportStatus.COMPLETED, Set.of(),
        SupportStatus.REJECTED, Set.of(),
        SupportStatus.CANCELLED, Set.of()
    );

    public void transitLoan(LoanApply loan, LoanStatus to) {
        LoanStatus from = LoanStatus.valueOf(loan.getStatus());
        if (!LOAN_TRANSITIONS.getOrDefault(from, Set.of()).contains(to)) {
            throw new BizException(BizAppErrorCode.ILLEGAL_STATE_TRANSITION,
                "Loan " + loan.getId() + ": " + from + " -> " + to);
        }
        loan.setStatus(to.name());
    }

    public void transitSupport(SupportRequest support, SupportStatus to) {
        SupportStatus from = SupportStatus.valueOf(support.getStatus());
        if (!SUPPORT_TRANSITIONS.getOrDefault(from, Set.of()).contains(to)) {
            throw new BizException(BizAppErrorCode.ILLEGAL_STATE_TRANSITION,
                "Support " + support.getId() + ": " + from + " -> " + to);
        }
        support.setStatus(to.name());
    }
}
```

## 9. 事件监听（订阅 workflow-center 事件）

### 9.1 LoanProcessCompletedListener

```java
@Component
@RequiredArgsConstructor
@Slf4j
public class LoanProcessCompletedListener {

    private final LoanApplyService loanApplyService;
    private final BizStateMachine bizStateMachine;
    private final EventPublisher eventPublisher;

    /**
     * 资产投放流程完成回调
     *
     * 订阅的事件：workflow.process.completed.v1
     * 过滤条件：business_key 以 "LOAN:" 开头
     */
    @EventListener
    @Transactional(rollbackFor = Exception.class)
    public void onProcessCompleted(WorkflowProcessCompletedEvent event) {
        if (!event.getBusinessKey().startsWith("LOAN:")) {
            return;
        }
        String loanId = event.getBusinessKey().substring("LOAN:".length());
        LoanApply loan = loanApplyService.lockById(loanId);

        LoanStatus target = event.getFinalOutcome() == WorkflowFinalOutcome.APPROVED
            ? LoanStatus.COMPLETED
            : LoanStatus.REJECTED;

        bizStateMachine.transitLoan(loan, target);
        loanApplyService.updateStatus(loan);

        // 发布业务事件
        if (target == LoanStatus.COMPLETED) {
            eventPublisher.publish(new LoanApprovedEvent(loan.getId()));
        } else {
            eventPublisher.publish(new LoanRejectedEvent(loan.getId()));
        }
    }
}
```

## 11. 事务与锁

### 11.1 事务边界

| 操作 | 事务范围 | 锁 |
|---|---|---|
| 创建草稿 | insert | 无 |
| 更新草稿 | update | `SELECT ... FOR UPDATE`（按主键行锁） |
| 提交审批 | update + 调用 workflowApi（**在事务内**） | `SELECT ... FOR UPDATE` |
| 多产品拆单 | 多条 insert + 多次调用 workflowApi（**整体事务**） | 无 |
| 秘书派单 | update | `SELECT ... FOR UPDATE` |
| 流程完成回调 | update | `SELECT ... FOR UPDATE` |

### 11.2 并发注意事项

- 提交审批时必须先锁行，避免用户多次点击造成重复启动流程
- 秘书派单时必须先锁行，确保 `assigned_emp_id` 不会被并发覆盖
- 流程完成回调必须是幂等的（幂等 Key = `processInstanceId`）

## 12. 性能注意

- 列表查询必须走索引：`idx_loan_cust_status(cust_id, status, deleted)`，`idx_loan_creator(created_by, status, deleted)`，`idx_support_dept(support_dept_id, status, deleted)`，`idx_support_assigned(assigned_emp_id, status, deleted)`
- 详情页的流程图和审批日志查询延迟加载（前端分步请求）
- 跨模块查询使用批量接口，避免 N+1
- 列表页的客户名称、产品名称等冗余字段通过 `BizApplySearchService` 批量填充，单次列表查询最多触发 3 次外部 Api 调用
