## 1. 高危动作清单

本模块所有写接口必须登记到 `PT_RESOURCE`，高危动作必须记录审计日志。

### 1.1 资产投放申请（LOAN）

| 序号 | 接口 | HTTP | 资源编码 | 动作 | 审计级别 | 必填字段 |
|-----|-----|------|--------|-----|--------|--------|
| 1 | POST `/api/loans` | POST | `BIZAPP:LOAN:DRAFT_CREATE` | CREATE | 普通 | 创建人、客户ID |
| 2 | PUT `/api/loans/{id}` | PUT | `BIZAPP:LOAN:DRAFT_UPDATE` | UPDATE | 普通 | before/after |
| 3 | DELETE `/api/loans/{id}` | DELETE | `BIZAPP:LOAN:DRAFT_DELETE` | DELETE | 普通 | 申请ID |
| 4 | POST `/api/loans/{id}/submit` | POST | `BIZAPP:LOAN:SUBMIT` | **SUBMIT** | **需审计** | 金额、客户ID、流程实例ID |
| 5 | POST `/api/loans/{id}/cancel` | POST | `BIZAPP:LOAN:CANCEL` | CANCEL | 需审计 | 取消原因 |
| 6 | GET `/api/loans/export` | GET | `BIZAPP:LOAN:EXPORT` | **EXPORT** | **高危** | 导出条件、数据量 |
| 7 | POST `/api/loans/{id}/tasks/{taskId}/complete` | POST | `BIZAPP:LOAN:TASK_COMPLETE` | APPROVE | 需审计 | 审批意见、表单字段 |

### 1.2 中场支持申请（SUPPORT 发起侧）

| 序号 | 接口 | HTTP | 资源编码 | 动作 | 审计级别 | 必填字段 |
|-----|-----|------|--------|-----|--------|--------|
| 8 | POST `/api/support-requests` | POST | `BIZAPP:SUPPORT:BATCH_CREATE` | **SUBMIT** | **需审计(多产品拆单)** | submit_group_id、产品数量、ID列表 |
| 9 | PUT `/api/support-requests/{id}` | PUT | `BIZAPP:SUPPORT:DRAFT_UPDATE` | UPDATE | 普通 | before/after |
| 10 | POST `/api/support-requests/{id}/submit` | POST | `BIZAPP:SUPPORT:SUBMIT` | **SUBMIT** | **需审计** | 流程实例ID |
| 11 | DELETE `/api/support-requests/{id}` | DELETE | `BIZAPP:SUPPORT:DRAFT_DELETE` | DELETE | 普通 | 申请ID |
| 12 | POST `/api/support-requests/{id}/cancel` | POST | `BIZAPP:SUPPORT:CANCEL` | CANCEL | 需审计 | 取消原因 |
| 13 | GET `/api/support-requests/export` | GET | `BIZAPP:SUPPORT:EXPORT` | **EXPORT** | **高危** | 导出条件、数据量 |

### 1.3 中场支持承接侧（SUPPORT_DEPT）

| 序号 | 接口 | HTTP | 资源编码 | 动作 | 审计级别 | 必填字段 |
|-----|-----|------|--------|-----|--------|--------|
| 14 | POST `/api/support-dept/requests/{id}/dispatch` | POST | `BIZAPP:SUPPORT_DEPT:DISPATCH` | **DISPATCH** | **高危** | 派单人、被派单人 |
| 15 | POST `/api/support-dept/requests/{id}/transfer` | POST | `BIZAPP:SUPPORT_DEPT:TRANSFER` | **TRANSFER** | **高危,reason必填** | before/after assignee、reason |
| 16 | POST `/api/support-dept/requests/{id}/complete` | POST | `BIZAPP:SUPPORT_DEPT:COMPLETE` | **COMPLETE** | **需审计** | 办理结果、表单字段 |
| 17 | POST `/api/support-dept/requests/{id}/reject` | POST | `BIZAPP:SUPPORT_DEPT:REJECT` | REJECT | 需审计 | 驳回原因 |
| 18 | GET `/api/support-dept/requests/export` | GET | `BIZAPP:SUPPORT_DEPT:EXPORT` | **EXPORT** | **高危** | 导出条件、数据量 |

### 1.4 审计级别定义

| 级别 | 含义 | 留存时长 | 告警 |
|-----|-----|--------|-----|
| 普通 | 一般业务动作,记录但不告警 | 1 年 | 无 |
| 需审计 | 状态变更、关键节点动作 | 2 年 | 异常时告警 |
| 高危 | 数据范围扩散/权限转移/批量导出 | 3 年 | 实时告警 |

## 3. 节点表单字段审计

### 3.1 审计范围

**`loan_approve_v1` 流程的 `corp_review` 节点（公司部审核）**包含两个业务决策字段：

| 字段 | 类型 | 标签 | 必填 | 审计要求 |
|------|------|-----|-----|--------|
| isNeedCreditMeeting | SELECT | 是否需要上信贷会 | 是 | 必须审计 |
| creditMeetingConclusion | TEXTAREA | 信贷会结论 | 是(当 isNeedCreditMeeting=YES 时) | 必须审计 |

**`loan_approve_v1` 流程的 `credit_approval` 节点（信贷审批）**包含三个关键审批字段：

| 字段 | 类型 | 标签 | 必填 | 审计要求 |
|------|------|-----|-----|--------|
| approvalOpinion | TEXTAREA | 审批意见 | 是 | 必须审计 |
| approvedAmount | DECIMAL | 批准金额 | 是 | 必须审计(可能与申请金额不一致) |
| approvedTerm | NUMBER | 批准期限(月) | 是 | 必须审计 |

### 3.2 存储位置

| 存储位置 | 用途 | 保留时间 |
|--------|-----|--------|
| Flowable `ACT_HI_VARINST` | 流程运行时与历史变量 | 由流程保留策略决定 |
| 审计日志 `audit_log.after` | 审计留痕 | 2 年 |
| **V2 规划**: `loan_apply` 业务冗余字段 | 业务查询 | 永久 |

### 3.3 审计记录方式

节点办理接口 (`POST /api/loans/{id}/tasks/{taskId}/complete`) 通过 AOP 注解自动审计：

```java
@BizAuth(
    resource = "BIZAPP:LOAN:TASK_COMPLETE",
    action = "APPROVE",
    audit = true,
    auditTitle = "完成资产投放审批节点",
    afterExpression = "#cmd"  // 将请求的 cmd 序列化作为 after
)
@PostMapping("/api/loans/{id}/tasks/{taskId}/complete")
public ApiResult<Void> completeTask(
    @PathVariable String id,
    @PathVariable String taskId,
    @RequestBody CompleteTaskCmd cmd
) {
    loanApplyApi.completeTask(id, taskId, cmd);
    return ApiResult.ok();
}
```

**AOP 拦截器内部：**
```java
@Around("@annotation(bizAuth)")
public Object around(ProceedingJoinPoint pjp, BizAuth bizAuth) throws Throwable {
    AuditLogCmd auditCmd = buildAuditBefore(pjp, bizAuth);
    try {
        Object result = pjp.proceed();
        auditCmd.setResult("SUCCESS");
        auditCmd.setAfter(serialize(extractAfter(pjp, bizAuth)));
        auditApi.log(auditCmd);  // REQUIRES_NEW 事务,不影响主流程
        return result;
    } catch (Exception e) {
        auditCmd.setResult("FAILED");
        auditCmd.setErrorCode(extractErrorCode(e));
        auditCmd.setErrorMessage(e.getMessage());
        auditApi.log(auditCmd);
        throw e;
    }
}
```

### 3.4 节点字段敏感性分级

| 字段 | 敏感度 | 脱敏策略 |
|------|-------|--------|
| isNeedCreditMeeting | 低 | 明文记录 |
| creditMeetingConclusion | 中 | 明文记录,导出时脱敏 |
| approvalOpinion | 中 | 明文记录 |
| approvedAmount | **高** | 明文记录,但报表显示时可脱敏为"万元"或区间 |
| approvedTerm | 低 | 明文记录 |

## 4. 审计日志规范

### 4.1 通用字段

所有审计日志必须包含以下字段（由 AuditApi 统一约束）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|-----|-----|
| action | string | 是 | 动作类型: CREATE/UPDATE/DELETE/SUBMIT/APPROVE/REJECT/CANCEL/DISPATCH/TRANSFER/COMPLETE/EXPORT |
| resource_type | string | 是 | 资源类型: LOAN_APPLY/SUPPORT_REQUEST/... |
| resource_code | string | 是 | PT_RESOURCE 中的资源编码 |
| resource_id | string | 否 | 资源ID(列表类操作可为空) |
| business_key | string | 否 | 流程业务键(有流程时记录) |
| operator_emp_id | string | 是 | 操作人工号 |
| operator_emp_name | string | 是 | 操作人姓名 |
| operator_org_id | string | 是 | 操作人机构编码 |
| operator_role_keys | array | 否 | 操作人角色(可选) |
| request_id | string | 是 | 请求ID(可追溯) |
| trace_id | string | 是 | 全链路追踪ID |
| request_time | datetime | 是 | 请求时间 |
| request_uri | string | 是 | 请求URI |
| request_method | string | 否 | HTTP方法 |
| client_ip | string | 是 | 客户端IP |
| user_agent | string | 否 | 客户端UserAgent |
| before | text | 否 | 操作前数据(JSON) |
| after | text | 否 | 操作后数据(JSON) |
| reason | text | 条件必填 | 操作原因(TRANSFER/CANCEL/REJECT 必填) |
| result | string | 是 | SUCCESS / FAILED |
| error_code | string | 条件必填 | 失败时的错误码 |
| error_message | string | 条件必填 | 失败时的错误消息 |
| duration_ms | number | 是 | 操作耗时 |
| severity | string | 否 | HIGH/MEDIUM/LOW(高危动作标记) |
| module | string | 是 | 来源模块名 |

### 4.2 敏感字段脱敏

| 字段 | 脱敏规则 |
|-----|--------|
| 手机号 | `138****5678` |
| 身份证 | `110101********1234` |
| 客户姓名 | `张*` (单字母) 或 `张三*` (多字) |
| 账号 | `6222********1234` |
| 金额 | 不脱敏,但禁止导出到外部系统时原样输出 |

脱敏由 `common-aop` 模块提供统一注解 `@Sensitive(type = SensitiveType.MOBILE)` 处理。

### 4.3 审计时机

| 时机 | 实现方式 |
|------|--------|
| 方法执行前 | 记录 before 快照 |
| 方法执行后(成功) | 更新 after、result=SUCCESS |
| 方法执行后(失败) | 更新 error_code、error_message、result=FAILED |
| 事务提交后 | 审计日志独立事务(REQUIRES_NEW) |

### 4.4 审计存储

审计日志由 `system-governance-center` 的 `audit_log` 表存储：

```sql
-- 简化示例,完整定义见 governance 模块 DDL
CREATE TABLE audit_log (
  id VARCHAR(32) PRIMARY KEY,
  action VARCHAR(32) NOT NULL,
  resource_type VARCHAR(64),
  resource_code VARCHAR(128),
  resource_id VARCHAR(64),
  business_key VARCHAR(100),
  operator_emp_id VARCHAR(32),
  operator_org_id VARCHAR(50),
  trace_id VARCHAR(64),
  request_time DATETIME,
  before TEXT,
  after TEXT,
  reason TEXT,
  result VARCHAR(16),
  severity VARCHAR(8),
  module VARCHAR(64),
  duration_ms INT,
  KEY idx_operator (operator_emp_id),
  KEY idx_resource (resource_type, resource_id),
  KEY idx_time (request_time),
  KEY idx_business_key (business_key),
  KEY idx_severity_time (severity, request_time)
);
```

## 5. 高危操作审批链路

### 5.1 导出操作

| 动作 | 日志 | 告警 |
|------|-----|-----|
| 导出触发 | EXPORT 审计日志 | 无 |
| 导出数据量 > 5000 条 | EXPORT + severity=HIGH | 实时告警 |
| 导出数据量 > 50000 条 | 二次确认 + severity=CRITICAL | 强制告警 + 审计主管抄送 |
| 导出频次 > 10 次/天 | 频次告警 | 安全团队分析 |

**导出频次监控实现：**
```java
@Component
public class ExportRateLimiter {
    public void checkAndMark(String empId) {
        String key = "export_count:" + empId + ":" + LocalDate.now();
        Long count = redisTemplate.opsForValue().increment(key);
        redisTemplate.expire(key, Duration.ofDays(2));
        if (count != null && count > 10) {
            auditApi.log(buildHighRateAuditLog(empId, count));
            // 不拒绝,但记录告警
        }
    }
}
```

### 5.2 转交操作

| 规则 | 说明 |
|-----|-----|
| reason 必填 | 空原因直接拒绝 |
| reason 长度 ≥ 10 | 防止无意义原因 |
| 同一单次转交频次限制 | 1 小时内不可超过 3 次 |
| 转交对象校验 | 必须是同部门员工 |

### 5.3 金额阈值审计

| 字段 | 阈值 | 处理 |
|-----|-----|-----|
| loan_apply.credit_amount > 1000 万 | 高危 | severity=HIGH |
| loan_apply.credit_amount > 5000 万 | 重大 | severity=CRITICAL + 主管告警 |

## 7. AOP 注解规范

### 7.1 `@BizAuth` 注解使用

本模块所有写接口必须声明 `@BizAuth`：

```java
@BizAuth(
    resource = "BIZAPP:LOAN:SUBMIT",   // 必须登记在 PT_RESOURCE
    action = "SUBMIT",
    audit = true,                       // 开启审计
    auditTitle = "提交资产投放申请",
    dataScope = true,                   // 开启数据范围过滤
    bizType = BizType.LOAN              // 数据范围类型
)
@PostMapping("/api/loans/{id}/submit")
public ApiResult<LoanSubmitResp> submit(@PathVariable String id) {
    return ApiResult.ok(loanApplyApi.submitForApproval(id));
}
```

### 7.2 注解字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|-----|-----|
| resource | string | 是 | PT_RESOURCE 资源编码 |
| action | string | 是 | 动作类型 |
| audit | boolean | 否 | 是否记录审计日志(默认 false) |
| auditTitle | string | 否 | 审计标题,便于检索 |
| severity | enum | 否 | LOW/MEDIUM/HIGH/CRITICAL |
| dataScope | boolean | 否 | 是否启用数据范围过滤 |
| bizType | enum | 否 | 数据范围业务类型 |
| reasonRequired | boolean | 否 | 是否要求 reason 字段 |
| auditBefore | string | 否 | SpEL 表达式,抓取 before |
| auditAfter | string | 否 | SpEL 表达式,抓取 after |

### 7.3 TRANSFER 动作强制要求 reason

```java
@BizAuth(
    resource = "BIZAPP:SUPPORT_DEPT:TRANSFER",
    action = "TRANSFER",
    audit = true,
    severity = Severity.HIGH,
    reasonRequired = true   // AOP 层面强制校验 reason
)
@PostMapping("/api/support-dept/requests/{id}/transfer")
public ApiResult<Void> transfer(@PathVariable String id, @RequestBody TransferCmd cmd) {
    supportDeptApi.transfer(id, cmd);
    return ApiResult.ok();
}
```

**AOP 拦截处理：**
```java
if (bizAuth.reasonRequired()) {
    Object reasonValue = extractReasonFromArgs(pjp.getArgs());
    if (reasonValue == null || StrUtil.isBlank(reasonValue.toString())) {
        throw new BizException("BIZAPP.4000.REASON_REQUIRED", "该操作必须填写原因");
    }
    if (reasonValue.toString().length() < 10) {
        throw new BizException("BIZAPP.4000.REASON_TOO_SHORT", "原因不少于10个字符");
    }
}
```

## 9. 审计与流程日志的关系

本模块业务审计与 `workflow-center` 的流程日志是**互补关系**：

| 内容 | 本模块审计(audit_log) | workflow 审批日志(ACT_HI_*) |
|------|-------------------|---------------------------|
| 创建草稿 | ✅ | ❌ |
| 更新草稿 | ✅ | ❌ |
| 提交审批 | ✅ | ✅(ProcessInstance 创建) |
| 节点办理(审批) | ✅ | ✅(TaskInstance 完成) |
| 节点表单字段 | ✅(after 字段) | ✅(ACT_HI_VARINST) |
| 流程被驳回 | ✅(通过事件回写) | ✅ |
| 秘书派单 | ✅ | ✅(Task assignee) |
| 导出操作 | ✅ | ❌ |

**查询时需要同时查两套日志：**
- 业务维度查询：查 `audit_log`（按 `business_key` 或 `resource_id`）；
- 流程维度查询：查 workflow-center 提供的流程历史查询入口（当前实现态为 `GET /api/workflow/processes/{processInstanceId}/history`）；
- 完整链路追溯：用 `trace_id` 跨系统关联。
