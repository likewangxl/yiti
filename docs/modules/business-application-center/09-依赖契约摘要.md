## 依赖关系总览

```
business-application-center (核心域)
       ↓
       ├── auth-permission-center         (强依赖 S)
       ├── workflow-center                (强依赖 S)
       ├── customer-marketing-center      (强依赖 S)
       ├── portal-content-center          (强依赖 S)
       └── system-governance-center       (间接依赖，通过 common-aop)

被依赖方（单向被依赖）:
       ├── performance-engine-center      (弱依赖 W，只读查询)
       └── report-analytics-center        (弱依赖 W，只读查询)
```

**依赖强度说明:**

- **S (强依赖 Sync)**: 同步调用，调用失败直接影响主链路。
- **W (弱依赖 Weak)**: 异步事件、事后通知或批任务，不阻断主链路。

## 1. 依赖 auth-permission-center（强依赖 S）

来源：`docs/modules/auth-permission-center/04-对外API契约.md`

### 1.1 本模块使用的接口

| 接口 | 方法签名 | 用途 |
|---|---|---|
| CurrentUserApi | `getCurrentUserContext() → CurrentUserContext` | 权限上下文获取 |
| CurrentUserApi | `getCurrentEmpId() → String` | 发起人工号（loan_apply.created_by / support_request.created_by） |
| CurrentUserApi | `getCurrentOrgCode() → String` | 发起人机构（loan_apply.owner_org_id / support_request.owner_org_id） |
| CurrentUserApi | `getCurrentRoleCodes() → Set<String>` | 角色校验（仅客户经理可发起） |
| CurrentUserApi | `isSystemAdmin() → boolean` | 系统管理员兜底权限 |
| BizScopeApi | `resolveScope(empId, BizType) → DataScopeType` | 解析 LOAN / SUPPORT / SUPPORT_DEPT 的数据范围 |
| BizScopeApi | `buildScopeContext(empId, BizType, BizAction) → DataScopeContext` | 构建完整范围上下文（含组织子树） |
| BizScopeApi | `checkWritePermission(empId, BizType, ownerOrgId, createdBy) → boolean` | 写前校验（编辑/删除草稿、派单/转交） |
| OrgApi | `getOrg(orgCode) → OrgDTO` | 机构信息查询（支持部门展示） |
| OrgApi | `getOrgSubtree(orgCode) → List<OrgDTO>` | 机构子树（ORG_SUBTREE 范围计算） |
| OrgApi | `getOrgSubtreeCodes(orgCode) → Set<String>` | 机构子树编码集合（经营机构负责人视角） |
| OrgApi | `getUserMainOrg(empId) → OrgDTO` | 用户主机构（派单校验接收人是否同部门） |

### 1.2 使用的 DTO / 枚举

| 类型 | 说明 |
|---|---|
| `CurrentUserContext(empId, mainOrgCode, roleIds, candidateGroupKeys, systemAdmin)` | 当前用户上下文 |
| `DataScopeContext(bizType, action, scope, empId, orgCode, orgSubtreeCodes, candidateGroupKeys)` | 数据范围上下文 |
| `OrgDTO(orgCode, orgName, orgLevel, parentOrgCode)` | 组织节点信息 |
| `BizType.LOAN` / `BizType.SUPPORT` / `BizType.SUPPORT_DEPT` | 本模块涉及的业务域 |
| `BizAction.READ / LIST / WRITE / EXPORT / TRANSFER / APPROVE / REJECT` | 本模块涉及的动作 |
| `DataScopeType.SELF_CREATED / ORG / ORG_SUBTREE / WORKFLOW_PARTICIPANT / SELF_ASSIGNED / ALL` | 本模块涉及的范围枚举 |

### 1.3 典型调用场景

- **发起资产投放申请**：`checkWritePermission(LOAN, WRITE)` + 校验角色为客户经理
- **经营机构负责人查看**：`buildScopeContext(LOAN, LIST)` → scope = ORG_SUBTREE → 过滤 `loan_apply.owner_org_id IN (:orgSubtree)`
- **授信审查人员查看**：scope = `WORKFLOW_PARTICIPANT` → 这是目标态能力；当前 `workflow-center` 尚未公开 `WorkflowParticipantService` Java 契约，实施时需先补齐上游接口或采用显式查询适配方案
- **中场支持秘书派单**：`buildScopeContext(SUPPORT_DEPT, WRITE)` → 仅允许操作本部门 `support_request.support_dept_id = :orgCode`

## 2. 依赖 workflow-center（强依赖 S）

来源：`docs/modules/workflow-center/04-对外API契约.md`

### 2.1 当前可用接口与差异说明

> 实现差异（2026-04-14）：`workflow-center` 当前公开的跨模块 Java Bean 只有 `WorkflowApi`。旧稿中的 `WorkflowQueryApi`、`WorkflowParticipantService` 仍是规划态名称，不能按“当前可直接注入”理解。

| 形态 | 当前契约 | 用途 | 说明 |
|---|---|---|---|
| Java | `WorkflowApi.startProcess(StartProcessCmd cmd)` | 发起资产投放 / 中场支持审批流程 | 已实现 |
| Java | `WorkflowApi.cancelProcess(String processInstanceId, String reason)` | 撤销流程（异常兜底） | 已实现 |
| Java | `WorkflowApi.getProcessByBusinessKey(String businessKey)` | 按 businessKey 查询流程映射 | 已实现 |
| Java | `WorkflowApi.getProcessByBizTypeAndBizId(String bizType, String bizId)` | 按业务类型 + ID 查询流程映射 | 已实现 |
| REST | `/api/workflow/tasks/**`、`/api/workflow/processes/**`、`/api/workflow/process-map` | 任务详情、办理、流程图、历史、流程映射 | 当前只存在 workflow 自身 REST 控制器，无 QueryApi Bean |
| 规划态 | `WorkflowParticipantService` | 参与者可读范围、运行时权限 | 当前未对外落地 |

### 2.2 使用的流程定义

| 流程定义 Key | 业务 | business_key 格式 |
|---|---|---|
| `loan_approve_v1` | 资产投放审批 | `LOAN:{applyId}` |
| `support_simple_v1` | 中场支持场景 A（明确产品） | `SUPPORT:{requestId}` |
| `support_complex_v1` | 中场支持场景 B（含模糊需求） | `SUPPORT:{requestId}` |

### 2.3 资产投放流程节点序列（loan_approve_v1）

```
客户经理提交
  ↓
branch_manager_approve      (经营机构负责人审核)
  ↓
corp_dept_review            (公司业务部审核 — 信贷会字段必填)
  ↓
credit_check                (授信审查)
  ↓
credit_approval             (授信批复)
  ↓
END
```

**公司部审核节点专属字段（wf_node_form_conf）:**
- `isNeedCreditMeeting`（是否需要上信贷会，必填）
- `creditMeetingConclusion`（信贷会结论，必填）

### 2.4 中场支持流程节点序列

**场景 A（support_simple_v1）:**
```
客户经理提交
  ↓
product_owner_handle        (产品负责人办理，候选人=product_info.responsibleEmpIds)
  ↓
END
```

**场景 B（support_complex_v1）:**
```
客户经理提交
  ↓
dept_secretary_dispatch     (部门秘书派单，候选组=部门秘书岗位)
  ↓
support_staff_handle        (具体支持人员办理，候选组=初审人员同部门人员)
  ↓
END
```

### 2.5 StartProcessCmd 必填字段

| 字段 | 类型 | 资产投放示例 | 中场支持示例 |
|---|---|---|---|
| bizType | String | "LOAN" | "SUPPORT" |
| bizId | String | applyId | requestId |
| businessKey | String | `LOAN:{applyId}` | `SUPPORT:{requestId}` |
| processDefinitionKey | String | "loan_approve_v1" | "support_simple_v1" / "support_complex_v1" |
| startUser | String | 当前 empId | 当前 empId |
| startOrgId | String | owner_org_id | owner_org_id |
| title | String | "资产投放申请-{custName}" | "中场支持申请-{productName or other}" |
| variables | Map | custId/productType/creditAmount/... | custId/productId/supportDeptId/... |

### 2.6 订阅事件（通过 Spring Event / ApplicationListener）

| 事件 | 来源 | 本模块响应 |
|---|---|---|
| `workflow.process.completed.v1` | workflow-center | 消费流程完成事件，回写 loan_apply.status / support_request.status；发布 `bizapp.loan.approved.v1` 等本模块事件；发送通知 |

**消费实现要点:**
- 使用 `@TransactionalEventListener(phase = AFTER_COMMIT)` 保证流程侧事务提交后再回写
- 消费幂等：按 `business_key + processInstanceId` 去重
- 失败重试：通过 `common-aop` 的事件补偿机制（见 common-dev-guide §7）

## 3. 依赖 customer-marketing-center（强依赖 S）

来源：`docs/modules/customer-marketing-center/04-对外API契约.md`

### 3.1 本模块使用的接口

| 接口 | 方法签名 | 用途 |
|---|---|---|
| CustomerQueryApi | `getCustomer(custId) → Optional<CustomerDTO>` | 获取客户详情（发起申请时自动带出） |
| CustomerQueryApi | `listCustomers(custIds) → List<CustomerDTO>` | 批量客户信息（列表冗余展示 custName） |
| CustomerQueryApi | `searchCustomers(keyword, limit) → List<CustomerDTO>` | 客户选择器模糊搜索（发起资产投放时可搜索） |
| CustomerQueryApi | `isValidCustomer(custId) → boolean` | 校验客户是否有效（存在、未删除、已审批通过） |
| CustomerQueryApi | `isClaimedByOrg(custId, orgCode) → boolean` | 校验客户是否被本机构已认领（存量客户来源校验） |
| CustomerQueryApi | `hasRunningProcess(custId, bizType) → boolean` | 校验客户是否存在指定 BizType 的在途流程（并行流程提示） |
| TouchTaskQueryApi | `getTouchTask(taskId) → Optional<TouchTaskDTO>` | 来源触达任务获取（自动带出客户信息） |

### 3.2 使用的 DTO

| DTO | 关键字段 |
|---|---|
| `CustomerDTO` | id, custNo, custName, unifiedCreditCode, industry, customerType, status |
| `TouchTaskDTO` | id, custId, assigneeEmpId, orgId, taskStatus, businessKey |

### 3.3 关键业务校验

| 校验点 | 调用 | 错误码 |
|---|---|---|
| 资产投放客户必须是已审批通过的公司客户 | `CustomerQueryApi.isValidCustomer(custId)` | BIZ-40301 |
| 中场支持来源 TOUCH_TASK：发起人必须是触达执行人 | `TouchTaskQueryApi.getTouchTask(taskId).assigneeEmpId == currentEmpId` | BIZ-40302 |
| 中场支持来源 EXISTING_CUSTOMER：客户必须在本机构已认领范围内 | `CustomerQueryApi.isClaimedByOrg(custId, currentOrgCode)` | BIZ-40303 |
| 并行流程提示（不拦截，仅二次确认） | `CustomerQueryApi.hasRunningProcess(custId, "LOAN"/"SUPPORT")` | 无（前端弹窗） |

### 3.4 订阅事件

| 事件 | 来源 | 本模块响应 |
|---|---|---|
| `customer.customer.deleted.v1` | customer-marketing-center | 检查客户在途申请，若有则拒绝删除或级联取消（需业务确认） |

## 7. 依赖变更影响评估

### 7.1 上游变更对本模块的影响

| 上游模块 | 可能的变更 | 本模块风险 | 应对策略 |
|---|---|---|---|
| auth-permission-center | CurrentUserContext 字段新增/废弃 | 中 | 使用 record 保证二进制兼容，新增字段不破坏 |
| workflow-center | Flowable 流程定义升级（loan_approve_v2） | 高 | 冻结 V1 流程定义 Key，新版本使用 _v2 后缀；business_key 格式保持不变 |
| customer-marketing-center | CustomerDTO 字段变更 | 中 | 本模块仅依赖 id / custName / customerType / status 核心字段 |
| portal-content-center | ProductDTO.supportForSupportRequest 逻辑变化 | 低 | 通过单一标志位判断，不会有语义漂移 |
| system-governance-center | DictApi 字典项变更 | 低 | 字典项变更需同步更新 V1 字典校验白名单 |

### 7.2 本模块变更对下游的影响

| 本模块变更 | 影响的下游模块 | 缓解措施 |
|---|---|---|
| `LoanApplyDTO` 字段变更 | performance / report | 新增字段向后兼容；废弃字段标记 `@Deprecated` 保留 2 个版本 |
| `loan_apply.status` 状态机新增 | performance / report | 下游使用 Optional 处理未知状态 |
| BusinessKey 格式变更 | workflow（反向影响） | V1 冻结 `LOAN:{applyId}` / `SUPPORT:{requestId}` 格式，不允许变更 |

### 11.1 本模块表与 DATA_SCOPE 字段映射

| 表 | 过滤字段 | BizType | 常用范围 |
|---|---|---|---|
| `loan_apply` | `owner_org_id` / `created_by` | LOAN | SELF_CREATED / ORG_SUBTREE / ALL |
| `support_request`（发起侧） | `owner_org_id` / `created_by` | SUPPORT | SELF_CREATED / ORG_SUBTREE |
| `support_request`（承接侧-部门） | `support_dept_id` | SUPPORT_DEPT | ORG_SELF（仅本部门） |
| `support_request`（承接侧-个人） | `assigned_emp_id` | SUPPORT_DEPT | SELF_ASSIGNED |

### 11.2 loan_apply 列表查询

```xml
<select id="listLoanApplies" resultType="LoanApplyEntity">
    SELECT * FROM loan_apply
    <where>
        AND deleted = 0
        <if test="status != null">AND status = #{status}</if>
        <include refid="loanDataScopeFilter"/>
    </where>
    ORDER BY created_time DESC LIMIT #{offset}, #{limit}
</select>

<sql id="loanDataScopeFilter">
    <choose>
        <when test="dataScope.type == 'ALL'"/>
        <when test="dataScope.type == 'ORG_SUBTREE'">
            AND owner_org_id IN
            <foreach collection="dataScope.orgSubtree" item="o" open="(" close=")" separator=",">#{o}</foreach>
        </when>
        <when test="dataScope.type == 'SELF_CREATED'">
            AND created_by = #{dataScope.empId}
        </when>
        <otherwise>AND 1 = 0</otherwise>
    </choose>
</sql>
```

### 11.3 support_request 双视图过滤

本模块最复杂的地方：**同一张表**，**两种数据范围过滤逻辑**。

#### 发起侧 SUPPORT 过滤

```xml
<sql id="supportDataScopeFilter">
    <choose>
        <when test="dataScope.type == 'ALL'"/>
        <when test="dataScope.type == 'ORG_SUBTREE'">
            AND owner_org_id IN
            <foreach collection="dataScope.orgSubtree" item="o" open="(" close=")" separator=",">#{o}</foreach>
        </when>
        <when test="dataScope.type == 'SELF_CREATED'">
            AND created_by = #{dataScope.empId}
        </when>
        <otherwise>AND 1 = 0</otherwise>
    </choose>
</sql>
```

#### 承接侧 SUPPORT_DEPT 过滤（秘书/支持人员视图）

```xml
<sql id="supportDeptDataScopeFilter">
    <choose>
        <when test="dataScope.type == 'ORG_SELF'">
            <!-- 秘书视角：本部门全部 -->
            AND support_dept_id = #{dataScope.orgCode}
        </when>
        <when test="dataScope.type == 'SELF_ASSIGNED'">
            <!-- 支持人员视角：仅自己的 -->
            AND assigned_emp_id = #{dataScope.empId}
        </when>
        <otherwise>AND 1 = 0</otherwise>
    </choose>
</sql>
```

**关键说明**：SUPPORT 与 SUPPORT_DEPT 是**两个不同的 BizType**。物理表同一张，通过 Controller 路由到不同 Mapper 方法，各自应用不同的过滤逻辑。

### 11.4 DATA_SCOPE 规则对应表

| 角色 | LOAN | SUPPORT | SUPPORT_DEPT |
|---|---|---|---|
| R_RM（客户经理） | SELF_CREATED | SELF_CREATED | — |
| R_BRANCH_MGR | ORG_SUBTREE | ORG_SUBTREE | — |
| R_CORP_DEPT | ALL | ALL | — |
| R_SUPPORT_SEC（秘书） | — | — | ORG_SELF |
| R_SUPPORT_STAFF（支持人员） | — | — | SELF_ASSIGNED |
| R_CREDIT_REVIEWER / R_CREDIT_APPROVER | 通过 workflow 看待办任务 | — | — |
