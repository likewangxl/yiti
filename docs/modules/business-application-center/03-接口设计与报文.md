# 业务申请中心 — 接口设计与报文

> 模块代码：`business-application-center`
> 文档版本：V1.0
> 统一前缀：所有接口返回 `R<T>`（来自 `common-web`），含 `code/message/data/traceId`

### A.3 POST /api/loans — 创建申请草稿

**功能**：创建资产投放申请草稿。

**鉴权**：`@BizAuth(bizType = "LOAN", action = "WRITE")`

**请求体**：`LoanApplyCreateReqDTO`

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| custId | String | ✅ | `@NotBlank` `@Size(max=32)` | 客户 ID（必须已审批通过） |
| sourceTouchTaskId | String | ❌ | `@Size(max=64)` | 来源触达任务 ID |
| projectType | String | ✅ | `@NotBlank` 字典 `PROJECT_TYPE` | 项目类型 |
| bizType | String | ✅ | `@NotBlank` 字典 `BIZ_TYPE` | 业务类型 |
| guaranteeType | String | ✅ | `@NotBlank` 字典 `GUARANTEE_TYPE` | 主要担保方式 |
| creditAmount | BigDecimal | ✅ | `@DecimalMin("0.01")` `@Digits(integer=12, fraction=2)` | 授信金额（万元） |
| creditExposureAmount | BigDecimal | ✅ | `@DecimalMin("0.00")` `@Digits(integer=12, fraction=2)` | 授信敞口金额（万元） |
| attachmentIds | List\<String\> | ❌ | `@Size(max=20)` | 附件 ID 列表 |

**业务校验**：

1. `custId` 调用 `CustomerQueryApi.getCustomerBrief` 校验存在且为公司类客户
2. 调用 `CustomerQueryApi.isCompanyApproved` 校验客户已审批通过，否则 `BIZ-40301`
3. `creditAmount >= creditExposureAmount`，否则 `BIZ-40905`
4. 字典字段必须在启用项范围内，否则 `BIZ-40904`

**请求示例**：

```json
{
  "custId": "cust_1001",
  "sourceTouchTaskId": "touch_001",
  "projectType": "NEW_CREDIT",
  "bizType": "WORKING_CAPITAL",
  "guaranteeType": "MORTGAGE",
  "creditAmount": 5000.00,
  "creditExposureAmount": 5000.00,
  "attachmentIds": ["file_001"]
}
```

**响应**：`R<LoanApplyRespDTO>`

```json
{
  "code": "0",
  "data": {
    "id": "loan_2026030400001",
    "applyNo": "LN20260304000001",
    "status": "DRAFT",
    "businessKey": "LOAN:loan_2026030400001",
    "createdTime": "2026-03-04 10:20:00"
  }
}
```

### A.4 PUT /api/loans/{id} — 更新草稿

**功能**：更新资产投放申请草稿（仅 DRAFT 状态可编辑）。

**鉴权**：`@BizAuth(bizType = "LOAN", action = "WRITE")`

**业务规则**：

- 仅 `createdBy == 当前用户 && status == DRAFT` 可编辑，否则 `BIZ-40305` / `BIZ-42303`
- `applyNo`、`businessKey` 不可修改

**请求体**：`LoanApplyUpdateReqDTO`（字段同 A.3，全部可选）

**响应**：`R<Void>`

### A.5 POST /api/loans/{id}/submit — 提交审批

**功能**：将草稿状态的申请提交到审批流程。

**鉴权**：`@BizAuth(bizType = "LOAN", action = "WRITE")`

**业务流程**：

1. 锁行读取草稿
2. 校验草稿状态：`status == DRAFT`，否则 `BIZ-42303`
3. 校验发起人：`createdBy == 当前用户`
4. 校验客户有效性
5. 校验字段完整性（必填字段、字典值）
6. 检查并行上限：调用 `BizApplyQueryApi.countRunningApplications(custId)`，超限且未带 `X-Confirm-Parallel: true` 时抛 `BIZ-40907`
7. 状态迁移：`DRAFT → IN_APPROVAL`
8. 调用 `WorkflowApi.startProcess("loan_approve_v1", businessKey, variables)`
9. 回写 `process_instance_id`
10. 发布 `LoanSubmittedEvent`

**请求头**（可选）：

- `X-Confirm-Parallel: true` — 已确认并行

**请求体**：无

**响应**：`R<SubmitRespDTO>`

```json
{
  "code": "0",
  "data": {
    "processInstanceId": "piid_abc123"
  }
}
```

**功能**：删除草稿状态的申请（逻辑删除）。

- 仅 `status == DRAFT && createdBy == 当前用户` 可删除

**请求体**：无

**响应**：`R<Void>`

### A.7 POST /api/loans/{id}/cancel — 撤回申请

**功能**：发起人撤回审批中的申请。

**鉴权**：`@BizAuth(bizType = "LOAN", action = "WRITE")`

**业务规则**：

- 仅 `status == IN_APPROVAL && createdBy == 当前用户` 可撤回
- 流程尚未到达 `loan_credit_review`（授信审查）节点
- 流程已进入授信审查后，撤回会被 `workflow-center` 拒绝，抛 `BIZ-50001`

**业务流程**：

1. 校验权限与状态
2. 调用 `WorkflowApi.cancelProcess(processInstanceId, reason)`
3. 状态迁移：`IN_APPROVAL → CANCELLED`
4. 发布 `LoanCancelledEvent`（可选）

**请求体**：

```json
{
  "reason": "客户主动放弃"
}
```

**响应**：`R<Void>`

### A.8 GET /api/loans/export — 导出

**功能**：按当前查询条件导出资产投放申请 Excel。

**鉴权**：`@BizAuth(bizType = "LOAN", action = "EXPORT")` （高危）

**请求参数**：同 A.1

**导出规范**：遵循 [附录 H 导出接口统一规范](#h-导出接口统一规范附录)
- **同步阈值**：≤ 5000 行同步流式返回；5000 < N ≤ 100000 走异步任务；> 100000 拒绝（`BIZ-42207`）
- **文件名**：`bizapp_loan_{filterHash}_{yyyyMMddHHmmss}.xlsx`
- **同步响应**：`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，Excel 二进制流
- **异步响应**：`R<ExportTaskRespDTO>`，详见 §H.3
- **列定义（14 列）**：详见 §H.7.1

**数据范围**：LOAN 按 `owner_org_id` + DATA_SCOPE 过滤

**审计**：级别 `HIGH`，记录导出条件、实际命中行数、耗时、结果。

### C.3 POST /api/support-requests — 创建中场支持申请（含多产品拆单）

**功能**：创建中场支持申请，若多产品自动拆单。

**鉴权**：`@BizAuth(bizType = "SUPPORT", action = "WRITE")`

**请求体**：`SupportRequestCreateReqDTO`

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| sourceType | String | ✅ | `@NotBlank` | `TOUCH_TASK` / `EXISTING_CUSTOMER` |
| sourceTouchTaskId | String | 条件必填 | `@Size(max=64)` | sourceType=TOUCH_TASK 时必填 |
| custId | String | ✅ | `@NotBlank` | 客户 ID |
| productIds | List\<String\> | 否 | `@Size(max=10)` | 产品 ID 列表（场景 A） |
| otherDemand | String | 否 | `@Size(max=2000)` | 其他需求（场景 B） |
| supportDeptId | String | 条件必填 | `@Size(max=64)` | 场景 B 必填，机构编码 |
| confirmParallel | Boolean | 否 | — | 并行流程二次确认 |
| attachmentIds | List\<String\> | 否 | `@Size(max=20)` | 附件 ID 列表 |

**业务校验**：

1. `productIds` 和 `otherDemand` 至少一个非空，否则 `BIZ-40903`
2. 场景 B（`otherDemand` 非空或 `productIds` 为空）必须填写 `supportDeptId`，否则 `BIZ-40902`
3. 来源 `TOUCH_TASK` 时：
   - 调用 `TouchTaskQueryApi.getTouchTask(sourceTouchTaskId)`
   - 校验 `executorEmpId == 当前用户`，否则 `BIZ-40302`
   - `custId` 必须等于触达任务的客户（锁定）
4. 来源 `EXISTING_CUSTOMER` 时：
   - 调用 `CustomerQueryApi.isCustomerOwnedByOrg(custId, 当前用户.orgId)`
   - false 则抛 `BIZ-40303`
5. 所有 `productId` 必须满足 `ProductApi.getProduct().getSupportForSupportRequest() == true`，否则 `BIZ-40901`
6. 并行校验：`BizApplyQueryApi.countRunningApplications(custId)`，超限时要求 `confirmParallel=true`

**请求示例**：

场景 A（多产品拆单）：

```json
{
  "sourceType": "TOUCH_TASK",
  "sourceTouchTaskId": "touch_001",
  "custId": "cust_1001",
  "productIds": ["prod_001", "prod_002"],
  "otherDemand": null,
  "supportDeptId": null,
  "confirmParallel": false,
  "attachmentIds": ["file_002"]
}
```

场景 B：

```json
{
  "sourceType": "EXISTING_CUSTOMER",
  "sourceTouchTaskId": null,
  "custId": "cust_1001",
  "productIds": [],
  "otherDemand": "客户希望了解结构性存款的整体方案",
  "supportDeptId": "dept_wealth",
  "confirmParallel": false,
  "attachmentIds": []
}
```

**响应**：`R<SupportRequestCreateRespDTO>`

| 字段 | 类型 | 说明 |

### D.2 POST /api/support-dept/requests/{id}/dispatch — 秘书派单

**功能**：秘书为中场支持申请指派具体办理人员。

**鉴权**：`@BizAuth(bizType = "SUPPORT_DEPT", action = "WRITE")`

**业务规则**：

- 当前用户必须是 `support_dept_id` 部门的秘书（通过 ORG 数据范围）
- 申请 `status == IN_APPROVAL` 且 `assigned_emp_id IS NULL`
- `assignedEmpId` 必须属于 `support_dept_id` 部门，否则 `BIZ-40304`

**请求体**：`DispatchReqDTO`

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| assignedEmpId | String | ✅ | `@NotBlank` `@Size(max=64)` | 被派单员工 |
| dispatchRemark | String | ❌ | `@Size(max=500)` | 派单备注 |

**业务流程**：

1. 锁行读取申请
2. 校验权限（秘书 + 部门匹配）
3. 校验 `assignedEmpId` 属于本部门
4. 更新 `assigned_emp_id`、`dispatch_emp_id`、`dispatch_time`
5. 状态迁移：`IN_APPROVAL → IN_PROGRESS`
6. 调用 workflow-center 当前任务入口推进派单（当前实现态需要结合 `POST /api/workflow/tasks/{taskId}/claim` 与业务侧派单信息更新，旧稿中的 `WorkflowApi.claimAndAssign(...)` 尚未落地）
7. 发布 `SupportDispatchedEvent`

**请求示例**：

```json
{
  "assignedEmpId": "emp_4001",
  "dispatchRemark": "请王五同学承办"
}
```

**响应**：`R<Void>`

### D.4 POST /api/support-dept/requests/{id}/complete — 支持人员办理完成

**功能**：支持人员提交办理结果，完成中场支持流程。

**鉴权**：`@BizAuth(bizType = "SUPPORT_DEPT", action = "WRITE")`

**业务规则**：

- 当前用户 `empId == assigned_emp_id`，否则 `BIZ-40304`
- 申请 `status in (IN_APPROVAL, IN_PROGRESS)`
- 场景 A 申请直接由候选人拾取后调用本接口
- 场景 B 申请必须在派单后由指派人员调用

**请求体**：`SupportCompleteReqDTO`

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| result | String | ✅ | `@NotBlank` 枚举 | `SUCCESS` / `FAILED` / `CANCELLED` |
| summary | String | ✅ | `@NotBlank` `@Size(max=2000)` | 办理总结 |
| outputAttachmentIds | List\<String\> | ❌ | `@Size(max=20)` | 办理成果附件 |

**业务流程**：

1. 校验权限
2. 状态迁移：

   - result=CANCELLED → `CANCELLED`
3. 调用 workflow-center 当前任务办理入口（实现态为 `POST /api/workflow/tasks/{taskId}/approve`，并通过 `formData` 传递办理结果）
4. 发布 `SupportCompletedEvent`

**请求示例**：

```json
{
  "result": "SUCCESS",
  "summary": "已为客户制定结构性存款产品组合方案，包含保本型与浮动型两个方向，具体方案见附件。",
  "outputAttachmentIds": ["file_output_001"]
}
```

**响应**：`R<Void>`

## H. 导出接口统一规范（附录）

本章节为本模块所有 `action = EXPORT` 的接口（A.8、C.7）提供统一的同步/异步分支规则、文件命名、异步任务 DTO、列定义原则、错误码与审计要求。**落地** `docs/common-dev-guide.md §8.2 第 5 条` 的规范（"超过 5000 行必须走异步导出"）。

### H.1 同步 / 异步分支规则

| 命中行数 N | 处理方式 | 响应类型 | 说明 |
|---|---|---|---|
| N ≤ 5000 | 同步流式返回 | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` | 直接 HTTP 流式写出 |
| 5000 < N ≤ 100000 | 异步任务 | `R<ExportTaskRespDTO>` | 返回任务 ID，前端轮询状态 |
| N > 100000 | 拒绝 | `BIZ-42207` | 引导增加过滤条件 |

**判定流程**：
1. 进入导出接口先执行 `SELECT count(*)`（含 DATA_SCOPE 过滤）
2. 按行数命中分支
3. 异步分支：写入 `sys_async_task`（governance 提供）
4. 异步完成后上传 MinIO，发通知给发起人

### H.2 文件命名规则

格式：`{module}_{business}_{filterHash}_{yyyyMMddHHmmss}.xlsx`

| 片段 | 说明 | 示例 |
|---|---|---|
| `{module}` | 固定 `bizapp` | `bizapp` |
| `{business}` | `loan` / `support` | `loan` |
| `{filterHash}` | 请求参数 MD5 前 8 位 | `a3f9b2c4` |
| `{yyyyMMddHHmmss}` | 导出时刻 | `20260410153022` |

示例：
- `bizapp_loan_a3f9b2c4_20260410153022.xlsx`
- `bizapp_support_b7e2c1d5_20260410153022.xlsx`

### H.3 异步任务响应 DTO：`ExportTaskRespDTO`

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|---|---|
| `taskId` | String | 是 | 异步任务唯一 ID，格式 `EXP{yyyyMMddHHmmss}{4位随机}` |
| `bizType` | String | 是 | `LOAN` / `SUPPORT` |
| `status` | String | 是 | `PENDING` / `RUNNING` / `SUCCESS` / `FAILED` |
| `estimatedRows` | Long | 是 | 预估行数 |
| `statusUrl` | String | 是 | `/api/async-tasks/{taskId}` |
| `downloadUrl` | String | 否 | SUCCESS 时才有值 |
| `createdTime` | LocalDateTime | 是 | 任务创建时间 |
| `expireAt` | LocalDateTime | 是 | 文件链接过期时间（默认 24 小时） |
| `errorMsg` | String | 否 | FAILED 时才有值 |

### H.4 列定义规范

每个导出接口必须明确：列顺序、中文列名、字段来源、格式规则（金额/日期/字典/脱敏）。金额字段统一 `DECIMAL(20,4)`，导出时保留 2 位小数。日期统一 `yyyy-MM-dd HH:mm:ss`。

### H.5 错误码

| code | HTTP | 说明 |
|---|---|---|
| `BIZ-42207` | 422 | 导出行数超过上限（100000） |
| `BIZ-42208` | 422 | 异步导出任务不存在或已过期 |
| `BIZ-42209` | 403 | 不能下载他人创建的导出任务 |
| `BIZ-50002` | 500 | 导出文件生成失败 |

### H.6 审计要求

所有 EXPORT 接口都是高危动作，参考 07-审计要求.md §1，必须记录：
- `action = EXPORT`
- `resource_type = LOAN` / `SUPPORT`
- `operator_emp_id` / `operator_org_id`
- `filter` 参数（完整 JSON）
- `rowCount`（实际命中行数）
- `duration`（执行耗时 ms）
- `result`（`SUCCESS` / `FAILED`）
- `file_object_id`（异步分支成功时）

### H.7 本模块导出接口清单

| 接口 | BizType | 同步阈值 | 硬上限 | 具体列定义 |

## I. 错误码完整汇总（2026-04-10 新增）

本附录汇总 business-application-center 模块的所有错误码，格式 `BIZ-{HTTP_STATUS}{SEQ}`，前缀固定 `BIZ`。

### I.1 403xx 权限 / 数据范围

| code | HTTP | 消息 |
|---|---|---|
| `BIZ-40301` | 403 | 您未分配该客户的资产投放权限（见 AllocApi.hasAllocation 校验） |
| `BIZ-40302` | 403 | 无权发起该产品的中场支持申请 |
| `BIZ-40303` | 403 | 无权派单给本部门以外的支持人员 |
| `BIZ-40304` | 403 | 无权操作他人的申请 |
| `BIZ-40305` | 403 | 数据范围越权 |

### I.2 409xx 业务状态冲突 / 幂等

| code | HTTP | 消息 |
|---|---|---|
| `BIZ-40901` | 409 | 申请编号重复 |
| `BIZ-40902` | 409 | 申请已处于终态（COMPLETED/REJECTED/CANCELLED），不可修改 |
| `BIZ-40903` | 409 | 申请状态不允许此操作（如草稿状态下不能撤回） |
| `BIZ-40904` | 409 | 非草稿状态不可删除 |
| `BIZ-40905` | 409 | 客户存在在途资产投放/中场支持流程，不允许重复发起 |
| `BIZ-40907` | 409 | 幂等键重复提交 |

### I.3 422xx 参数校验 / 业务规则

| code | HTTP | 消息 |
|---|---|---|
| `BIZ-42207` | 422 | 导出行数超过上限（100000） |
| `BIZ-42208` | 422 | 异步导出任务不存在或已过期 |
| `BIZ-42209` | 403 | 不能下载他人创建的导出任务 |
| `BIZ-42303` | 422 | 多产品拆单时 `productIds` 为空或包含无效产品 |

### I.4 500xx 系统错误

| code | HTTP | 消息 |
|---|---|---|
| `BIZ-50001` | 500 | 系统内部错误 |
| `BIZ-50002` | 500 | 导出文件生成失败 |

### I.5 使用约定

1. 错误码在 `CommonResult.errorCode` 字段返回，`code` 字段为 HTTP 状态码同值
2. 所有高危操作失败（EXPORT/TRANSFER/DELETE）必须写审计日志，即使被错误码拦截也要记录
3. 业务状态冲突（40901-40907）前端应显示友好消息并引导用户下一步
4. 资产投放（LOAN）和中场支持（SUPPORT/SUPPORT_DEPT）共享同一套错误码，不按 BizType 拆分
5. 参数校验错误（42xxx 开头）由 `GlobalExceptionHandler` 统一转换，含 `fieldErrors` 列表
