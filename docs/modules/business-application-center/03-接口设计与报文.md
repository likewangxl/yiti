### A.3 POST /api/loans — 创建申请草稿

**功能**：创建资产投放申请草稿。

**鉴权**：`@BizAuth(bizType = "LOAN", action = "WRITE")`

**请求体**：`LoanApplyCreateReqDTO`

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| custId | String | ✅ | `@NotBlank` `@Size(max=32)` | 客户 ID（必须已审批通过） |
| sourceTouchTaskId | String | ❌ | `@Size(max=64)` | 来源触达任务 ID |
| projectType | String | ✅ | `@NotBlank` 字典 `PROJECT_TYPE` | 项目类型 |
| bizType | String | ✅ | `@NotBlank` 字典 `BIZ_TYPE` | 业务类型 |
| guaranteeType | String | ✅ | `@NotBlank` 字典 `GUARANTEE_TYPE` | 主要担保方式 |
| creditAmount | BigDecimal | ✅ | `@DecimalMin("0.01")` `@Digits(integer=12, fraction=2)` | 授信金额（万元） |
| creditExposureAmount | BigDecimal | ✅ | `@DecimalMin("0.00")` `@Digits(integer=12, fraction=2)` | 授信敞口金额（万元） |
| attachmentIds | List\<String\> | ❌ | `@Size(max=20)` | 附件 ID 列表 |

**业务校验**：

1. `custId` 调用 `CustomerQueryApi.getCustomerBrief` 校验存在且为公司类客户
2. 调用 `CustomerQueryApi.isCompanyApproved` 校验客户已审批通过，否则 `BIZ-40301`
3. `creditAmount >= creditExposureAmount`，否则 `BIZ-40905`
4. 字典字段必须在启用项范围内，否则 `BIZ-40904`

**请求示例**：

```json
{
  "custId": "cust_1001",
  "sourceTouchTaskId": "touch_001",
  "projectType": "NEW_CREDIT",
  "bizType": "WORKING_CAPITAL",
  "guaranteeType": "MORTGAGE",
  "creditAmount": 5000.00,
  "creditExposureAmount": 5000.00,
  "attachmentIds": ["file_001"]
}
```

**响应**：`R<LoanApplyRespDTO>`

```json
{
  "code": "0",
  "data": {
    "id": "loan_2026030400001",
    "applyNo": "LN20260304000001",
    "status": "DRAFT",
    "businessKey": "LOAN:loan_2026030400001",
    "createdTime": "2026-03-04 10:20:00"
  }
}
```

### A.5 POST /api/loans/{id}/submit — 提交审批

**功能**：将草稿状态的申请提交到审批流程。

**鉴权**：`@BizAuth(bizType = "LOAN", action = "WRITE")`

**业务流程**：

1. 锁行读取草稿
2. 校验草稿状态：`status == DRAFT`，否则 `BIZ-42303`
3. 校验发起人：`createdBy == 当前用户`
4. 校验客户有效性
5. 校验字段完整性（必填字段、字典值）
6. 检查并行上限：调用 `BizApplyQueryApi.countRunningApplications(custId)`，超限且未带 `X-Confirm-Parallel: true` 时抛 `BIZ-40907`
7. 状态迁移：`DRAFT → IN_APPROVAL`
8. 调用 `WorkflowApi.startProcess("loan_approve_v1", businessKey, variables)`
9. 回写 `process_instance_id`
10. 发布 `LoanSubmittedEvent`

**请求头**（可选）：

- `X-Confirm-Parallel: true` — 已确认并行

**请求体**：无

**响应**：`R<SubmitRespDTO>`

```json
{
  "code": "0",
  "data": {
    "processInstanceId": "piid_abc123"
  }
}
```

### A.7 POST /api/loans/{id}/cancel — 撤回申请

**功能**：发起人撤回审批中的申请。

**鉴权**：`@BizAuth(bizType = "LOAN", action = "WRITE")`

**业务规则**：

- 仅 `status == IN_APPROVAL && createdBy == 当前用户` 可撤回；业务行使用 `SELECT ... FOR UPDATE` 锁定
- `processInstanceId` 必须存在；服务端通过 `WorkflowQueryApi.getProcessNodes(processInstanceId)` 查询当前活动节点
- 仅当流程返回**恰好一个** `ACTIVE` 的 `userTask`，且其 `nodeKey` 为 `branch_approve` 或 `corp_review` 时允许撤回；多个 ACTIVE 用户节点（即使其中包含允许节点）、未知节点，或节点查询失败/返回空时一律 Fail Close，返回 `BIZ-50001`
- 进入 `credit_check` 或 `credit_approval` 表示公司部审核已通过，不允许撤回，返回 `BIZ-42304`
- 撤回原因必填，长度不超过 500 个字符；Loan/LOAN 与 `/api/loans` 路径保持兼容，用户界面术语使用“资产立项”

**业务流程**：

1. 校验权限、状态、创建人、流程实例和当前活动节点
2. 调用 `WorkflowApi.cancelProcess(processInstanceId, reason)`
3. 仅在流程取消成功后，使用 `WHERE status = 'IN_APPROVAL'` 条件更新迁移到 `CANCELLED`
4. 发布 `LoanCancelledEvent`（可选）

**请求体**：

```json
{
  "reason": "客户主动放弃"
}
```

**响应**：`R<Void>`

### C.3 POST /api/support-requests — 创建中台支持申请（含多产品拆单）

**功能**：创建中台支持申请，若多产品自动拆单。

**鉴权**：`@BizAuth(bizType = "SUPPORT", action = "WRITE")`

**请求体**：`CreateSupportReq`

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| sourceType | String | 否（新客户端建议传） | — | `TOUCH_TASK` / `EXISTING_CUSTOMER`；省略时由 `sourceTouchTaskId` 推断 |
| sourceTouchTaskId | String | 条件必填 | `@Size(max=64)` | sourceType=TOUCH_TASK 时必填 |
| custId | String | ✅ | `@NotBlank` | 客户 ID |
| productIds | List\<String\> | 否 | `@Size(max=10)` | 产品 ID 列表（场景 A） |
| otherDemand | String | 否 | `@Size(max=2000)` | 其他需求（场景 B） |

| confirmParallel | Boolean | 条件必填 | — | 客户存在在途中台支持时必须显式确认 |
| attachmentIds | List\<String\> | 否 | — | 创建页上传的文件 ID，拆单后关联到每条申请 |

当前 Java `CreateSupportReq` 接收上述全部字段；`sourceType` 仅作入口校验，不新增旧表字段。`confirmParallel` 为本次创建确认信号，不持久化；`attachmentIds` 通过 `FileApi` 以 `SUPPORT_REQUEST` 关联到拆单后的每条申请。办理过程照片则在 D.1.3 通过 `fileIds` 绑定到 `SUPPORT_LOG`。

**业务校验**：

1. `productIds` 和 `otherDemand` 至少一个非空，否则 `BIZ-40903`
2. 场景 B（`otherDemand` 非空或 `productIds` 为空）必须填写 `supportDeptId`，否则 `BIZ-40902`
3. 来源 `TOUCH_TASK` 时：

   - `custId` 必须等于触达任务的客户（锁定）
4. 来源 `EXISTING_CUSTOMER` 时：

   - false 则抛 `BIZ-40303`
5. 所有 `productId` 必须满足 `ProductApi.getProduct().getSupportForSupportRequest() == true`，否则 `BIZ-40901`
6. 并行提示：服务端在创建前调用 `countRunningByCustomer(custId)`；有在途申请且 `confirmParallel != true` 时返回 `BIZ-40907` 及当前数量。页面弹窗确认后携带 `confirmParallel=true` 重试，后端仍作防绕过校验。

## F. 通用响应与错误

### F.1 统一响应结构

```json
{
  "code": "0",
  "message": "success",
  "data": {},
  "traceId": "xxx",
  "timestamp": 1709540000000
}
```

| 字段 | 说明 |
|---|---|
| code | "0" = 成功，其他 = 错误码（如 BIZ-40301） |
| message | 成功为 "success"，失败为错误描述 |
| data | 业务数据 |
| traceId | 全链路 TraceID |
| timestamp | 服务器时间戳 |

```json
{
  "code": "BIZ-40301",
  "message": "客户非有效公司客户",
  "data": null,
  "traceId": "a1b2c3d4",

}
```

### F.3 分页参数标准

- `pageNo` 从 1 开始
- `pageSize` 默认 20，最大 100
- 响应格式 `PageResult<T>`：含 `pageNo/pageSize/total/list`

## H. 导出接口统一规范（附录）

本章节为本模块所有 `action = EXPORT` 的接口（A.8、C.7）提供统一的同步/异步分支规则、文件命名、异步任务 DTO、列定义原则、错误码与审计要求，**设计目标对齐** `docs/common-dev-guide.md §8.2 第 5 条` 的规范（"超过 5000 行必须走异步导出"）。

> ⚠️ **现状标注（2026-07-19）**：A.8 `GET /api/loans/export`、C.7 `GET /api/support-requests/export` 当前均为 501 占位实现，本规范尚未落地，`BIZ-42208`/`BIZ-42209`（本附录 §H.5）为该未来设计预留的码值，`BizAppErrorCode` 枚举中尚不存在，不属于附录 I 的"完整汇总"范围。

### H.1 同步 / 异步分支规则

| 命中行数 N | 处理方式 | 响应类型 | 说明 |
|---|---|---|---|
| N ≤ 5000 | 同步流式返回 | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` | 直接 HTTP 流式写出 |
| 5000 < N ≤ 100000 | 异步任务 | `R<ExportTaskRespDTO>` | 返回任务 ID，前端轮询状态 |
| N > 100000 | 拒绝 | `BIZ-42207` | 引导增加过滤条件 |

**判定流程**：
1. 进入导出接口先执行 `SELECT count(*)`（含 DATA_SCOPE 过滤）
2. 按行数命中分支
3. 异步分支：写入 `sys_async_task`（governance 提供）
4. 异步完成后上传 MinIO，发通知给发起人

### H.2 文件命名规则

格式：`{module}_{business}_{filterHash}_{yyyyMMddHHmmss}.xlsx`

| 片段 | 说明 | 示例 |
|---|---|---|
| `{module}` | 固定 `bizapp` | `bizapp` |
| `{business}` | `loan` / `support` | `loan` |
| `{filterHash}` | 请求参数 MD5 前 8 位 | `a3f9b2c4` |
| `{yyyyMMddHHmmss}` | 导出时刻 | `20260410153022` |

示例：
- `bizapp_loan_a3f9b2c4_20260410153022.xlsx`
- `bizapp_support_b7e2c1d5_20260410153022.xlsx`

### H.3 异步任务响应 DTO：`ExportTaskRespDTO`

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|---|---|
| `taskId` | String | 是 | 异步任务唯一 ID，格式 `EXP{yyyyMMddHHmmss}{4位随机}` |
| `bizType` | String | 是 | `LOAN` / `SUPPORT` |
| `status` | String | 是 | `PENDING` / `RUNNING` / `SUCCESS` / `FAILED` |
| `estimatedRows` | Long | 是 | 预估行数 |
| `statusUrl` | String | 是 | `/api/async-tasks/{taskId}` |
| `downloadUrl` | String | 否 | SUCCESS 时才有值 |
| `createdTime` | LocalDateTime | 是 | 任务创建时间 |
| `expireAt` | LocalDateTime | 是 | 文件链接过期时间（默认 24 小时） |
| `errorMsg` | String | 否 | FAILED 时才有值 |

### H.4 列定义规范

每个导出接口必须明确：列顺序、中文列名、字段来源、格式规则（金额/日期/字典/脱敏）。金额字段统一 `DECIMAL(20,4)`，导出时保留 2 位小数。日期统一 `yyyy-MM-dd HH:mm:ss`。

### H.5 错误码

| code | HTTP | 说明 |
|---|---|---|
| `BIZ-42207` | 422 | 导出行数超过上限（100000） |
| `BIZ-42208` | 422 | 异步导出任务不存在或已过期 |
| `BIZ-42209` | 403 | 不能下载他人创建的导出任务 |
| `BIZ-50002` | 500 | 导出文件生成失败 |

### H.6 审计要求

所有 EXPORT 接口都是高危动作，参考 07-审计要求.md §1，必须记录：
- `action = EXPORT`
- `resource_type = LOAN` / `SUPPORT`
- `operator_emp_id` / `operator_org_id`
- `filter` 参数（完整 JSON）
- `rowCount`（实际命中行数）
- `duration`（执行耗时 ms）
- `result`（`SUCCESS` / `FAILED`）
- `file_object_id`（异步分支成功时）

### I.7 使用约定

1. 错误码通过 `BizException(code, message)` 抛出，由 `common-web` 的 `GlobalExceptionHandler.handleBizException` 统一捕获；响应 HTTP 状态固定为 200，`code` 字段回填完整错误码字符串（如 `"BIZ-40301"`），并非字面意义的 HTTP 状态码
2. 所有高危操作失败（EXPORT/TRANSFER/DELETE）必须写审计日志，即使被错误码拦截也要记录
3. 业务状态冲突（40901-40907）前端应显示友好消息并引导用户下一步
4. 资产投放（LOAN）和中台支持（SUPPORT/SUPPORT_DEPT）共享同一套错误码，不按 BizType 拆分
5. `EXPORT_ROW_LIMIT_EXCEEDED`（`BIZ-42207`）及 §H 的导出异步规范当前均未接入真实导出流程（见 A.8/C.7 现状标注），暂无实际触发路径
