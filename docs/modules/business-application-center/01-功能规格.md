# 业务申请中心 — 功能规格

> 模块代码：`business-application-center`
> 当前事实以 `business-application-center/src/main/java`、测试和目标库实际结构为准；本文只记录当前仍由本模块承载的中场支持申请。

## 1. 模块定位与边界

本模块维护 `SUPPORT_REQUEST` 申请、场景路由、多产品拆单、承接部门办理和申请查询。客户主档/认领关系由 `customer-marketing-center` 提供，产品及产品负责人由 `portal-content-center` 提供，流程引擎由 `workflow-center` 提供，通知由 `system-governance-center` 提供。

模块内的跨模块访问只使用对方 `api/` 契约和 DTO，不直接访问对方的 Mapper、Entity 或私有表。业务状态由 `BizStateMachine` 校验，流程实例以 `businessKey=SUPPORT:{id}` 关联。

## 2. 中场支持申请

### 2.1 创建与场景路由

创建请求 `CreateSupportReq` 的字段为：

| 字段 | 必填 | 说明 |
|---|---|---|
| `custId` | 是 | 有效客户 ID |
| `productIds` | 条件 | 产品直达场景的产品列表 |
| `otherDemand` | 条件 | 无明确产品时的补充需求 |
| `supportDeptId` | 条件 | 部门承接场景的承接机构编码 |
| `sourceTouchTaskId` | 否 | 来源触达任务 ID，仅保存来源关联 |

`SupportScenarioRouter` 按以下规则判定：

| 场景 | 条件 | 流程定义 |
|---|---|---|
| A（产品直达） | `productIds` 非空且 `otherDemand` 为空 | `support_simple_v1` |
| B（部门承接） | `productIds` 为空，或 `otherDemand` 非空 | `support_complex_v1` |

场景 B 必须提供 `supportDeptId`；`productIds` 与 `otherDemand` 同时为空时拒绝。创建前校验客户有效，场景 A 逐个校验产品存在且 `supportForSupportRequest=true`。

### 2.2 多产品拆单

场景 A 每个产品生成一条 `DRAFT` 记录；本次创建的记录共享一个 `submitGroupId`，各自拥有申请编号、ID 和业务键。场景 B 生成一条不带 `productId` 的 `DRAFT` 记录并同样生成 `submitGroupId`。创建响应的 `processInstanceId` 在草稿阶段为 `null`。

同一客户同一产品在 `IN_APPROVAL` 或 `IN_PROGRESS` 中的活动申请达到重复阈值时拒绝（`BIZ-40906`）；客户活动申请统计由 `countRunningByCustomer` 提供，不能把统计接口当作额外确认协议。

### 2.3 提交、撤回与删除

1. 只有创建人可以提交或删除自己的申请；删除仅允许 `DRAFT`，通过 `deleted=1` 逻辑删除。
2. 提交使用行锁读取申请，校验 `DRAFT → IN_APPROVAL`，调用 `WorkflowApi.startProcess`，写入流程实例 ID，并发布 `SupportSubmittedEvent`。多产品拆单的每条记录独立提交、独立启动流程。
3. 撤回使用行锁，允许 `IN_APPROVAL` 或 `IN_PROGRESS → CANCELLED`。当前实现只更新业务表，不调用流程取消接口；Controller 没有撤回请求体。

### 2.4 承接侧办理

承接侧以 `SUPPORT_DEPT` 业务权限访问：

| 操作 | 前置状态与权限 | 结果 |
|---|---|---|
| 派单 | `IN_APPROVAL`；承接部门人员操作 | 写入 `assignedEmpId`、`dispatchEmpId`、`dispatchTime`，转 `IN_PROGRESS`，发布 `SupportDispatchedEvent` |
| 转交 | 当前承接人操作 | 更新 `assignedEmpId`；发布领域事件不是当前实现的一部分 |
| 办理完成 | 当前承接人操作 | `success=true` 转 `COMPLETED`，否则转 `REJECTED`，发布 `SupportCompletedEvent` |

### 2.5 状态机

```text
DRAFT ──提交──> IN_APPROVAL
                  ├─派单（部门承接）──> IN_PROGRESS
                  ├─流程通过/办理成功──> COMPLETED
                  ├─流程驳回/办理失败──> REJECTED
                  └─发起人撤回──> CANCELLED

DRAFT 只能逻辑删除，其他状态不可删除。
```

合法迁移由 `BizStateMachine` 统一校验，非法迁移返回 `BIZ-42301`。流程回调把 `IN_APPROVAL` 条件更新为 `COMPLETED` 或 `REJECTED`；重复回调影响行数为 0 时不重复发布事件。

## 3. REST 入口

发起侧 `SupportController`：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/support-requests` | 按 `keyword`、`status` 分页查询；默认 `pageNo=1`、`pageSize=20` |
| GET | `/api/support-requests/{id}` | 申请详情 |
| POST | `/api/support-requests` | 创建申请并按场景处理拆单 |
| POST | `/api/support-requests/{id}/submit` | 提交单条草稿 |
| DELETE | `/api/support-requests/{id}` | 删除草稿 |
| POST | `/api/support-requests/{id}/cancel` | 撤回申请 |
| GET | `/api/support-requests/export` | 当前返回 HTTP 业务码 `501 / Not Implemented`，不得按导出设计文档调用 |
| GET | `/api/support-requests/available-products` | 代理 `ProductApi.listSupportAvailableProducts()` |

承接侧 `SupportDeptController`：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/support-dept/requests` | 按 `supportDeptId`、`status`、`assignedEmpId` 分页查询 |
| POST | `/api/support-dept/requests/{id}/dispatch` | 请求体 `assignedEmpId`、可选 `dispatchRemark` |
| POST | `/api/support-dept/requests/{id}/transfer` | 请求体 `newAssignedEmpId` |
| POST | `/api/support-dept/requests/{id}/complete` | 请求体 `success` |

所有端点均通过 `@BizAuth` 声明业务类型和动作，并登记 `PT_RESOURCE`。列表和详情返回 DTO，不暴露 `deleted` 等内部字段。

## 4. 权限、数据范围与审计

`SUPPORT` 发起侧按 `owner_org_id`、`created_by` 施加统一数据范围；`SUPPORT_DEPT` 承接侧按 `support_dept_id` 或 `assigned_emp_id` 施加部门/个人范围。写操作在 Service 层再次校验目标申请和操作者。

创建、提交、删除、撤回、派单、转交、办理完成和导出均使用源码中的 `@AuditLog` 配置；转交、撤回和导出标记 `reasonRequired=true`。审批结果回写由 `SupportWorkflowListener` 处理，通知失败不回滚业务状态。

## 5. 对外查询与事件

本模块通过 `SupportApi` 提供按 ID、业务键、客户、`submitGroupId` 和 ID 列表的只读查询；`SupportQueryApi` 提供分页及按创建人/承接人、时间范围统计已完成数量。

发布事件及载荷以源码 record/class 为准：

| 事件 | 发布时机 |
|---|---|
| `SupportSubmittedEvent` | 单条申请提交并写入 `IN_APPROVAL` 后 |
| `SupportDispatchedEvent` | 部门承接侧派单后 |
| `SupportCompletedEvent` | 承接办理成功，或流程审批通过后 |
| `SupportRejectedEvent` | 流程审批驳回后 |

`BizApplyQueryApi` 的 Java 兼容字段仍可能使用 `runningLoanCount`、`totalLoans` 等历史命名；当前值中的资产统计由客户营销模块的 `AssetProjectQueryApi` 提供，本模块不再维护对应实体、表或 REST 入口。
