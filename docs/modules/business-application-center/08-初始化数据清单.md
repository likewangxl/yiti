# 业务申请中心 — 初始化配置要求

> 本文只保留当前中场支持申请运行所需的资源和流程配置要求。配置由相应平台模块按审批流程实施；本文不包含一次性 SQL、执行顺序、回滚脚本或环境验证命令。

## 1. 数据与字典边界

本模块没有自有字典表或初始化种子。`custId`、`productIds`、`supportDeptId` 等值分别由客户营销、门户产品和权限/组织公开 API 校验；若产品模块或平台在页面展示字典，字典维护归 `system-governance-center`。

## 2. 工作流配置

`workflow-center` 必须提供以下流程定义，流程键由 `SupportScenario` 使用：

| 流程键 | 场景 | 业务含义 |
|---|---|---|
| `support_simple_v1` | A 产品直达 | 提交后由产品负责人处理 |
| `support_complex_v1` | B 部门承接 | 提交后由承接部门派单并办理 |

启动流程时，业务模块传入 `bizType=SUPPORT`、`bizId`、`businessKey=SUPPORT:{id}`、流程定义键、发起人、发起机构和标题。流程完成后由 workflow-center 发布 `ProcessCompletedEvent`；本模块仅消费 `SUPPORT:` 业务键并回写支持申请。

流程节点的候选人和办理表单由 workflow-center 的流程/任务契约管理，本模块不在 `SUPPORT_REQUEST` 增加节点表单列，也不登记未实现的任务委派、流程取消或异步导出配置。

## 3. 资源登记

以下 Controller 端点必须在 `PT_RESOURCE` 登记，并与源码 `@BizAuth` 的 `bizType/action` 保持一致：

| 业务类型 | 动作 | 方法与路径 |
|---|---|---|
| `SUPPORT` | `LIST` | `GET /api/support-requests` |
| `SUPPORT` | `READ` | `GET /api/support-requests/{id}`、`GET /api/support-requests/available-products` |
| `SUPPORT` | `WRITE` | `POST /api/support-requests`、`POST /api/support-requests/{id}/submit`、`DELETE /api/support-requests/{id}`、`POST /api/support-requests/{id}/cancel` |
| `SUPPORT` | `EXPORT` | `GET /api/support-requests/export`（当前 501，占位资源仍按注解登记） |
| `SUPPORT_DEPT` | `LIST` | `GET /api/support-dept/requests` |
| `SUPPORT_DEPT` | `WRITE` | `POST /api/support-dept/requests/{id}/dispatch`、`POST /api/support-dept/requests/{id}/complete` |
| `SUPPORT_DEPT` | `TRANSFER` | `POST /api/support-dept/requests/{id}/transfer` |

资源 URL、资源类型、父子菜单关系和角色授权由 `auth-permission-center` 管理。菜单文案不应被本文的技术路径推导；资源登记必须覆盖所有实际公开 Controller 方法，不能为不存在的 `VIEW`、`REJECT` 或其他动作补写资源。

## 4. 运行配置要求

- `SUPPORT_REQUEST` 表及其索引先按目标库实际 schema 准备；逻辑删除值为 `deleted=0/1`。
- `PT_RESOURCE` 与角色数据必须在启用端点前完成审批和登记。
- `support_simple_v1`、`support_complex_v1` 的部署状态由 workflow-center 管理；业务模块只依赖流程键和完成事件契约。
- 数据库会话、锁、Quartz、对象存储和通知等平台能力沿用公共模块配置，不在本模块复制配置段。

## 5. 配置验收口径

上线前只需确认：支持申请表可被 Mapper 查询、上述资源与 `@BizAuth` 一致、两个流程键可被 `WorkflowApi.startProcess` 启动、完成事件能按 `SUPPORT:{id}` 回写状态。具体数据库盘点和资源数据验收应在目标环境以只读检查完成，原始证据不写入本文。
