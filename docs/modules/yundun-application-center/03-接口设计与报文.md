# 浦爱云盾应用中心 REST 接口契约

> 模块：`yundun-application-center`，统一前缀：`/api/yundun`。
> 代码核对基准：`yundun-application-center/src/main/java/com/bank/branch/platform/yundun`。
> 本文只描述当前源码已经存在的接口；规划中的异步导出、对象存储和新的数据范围字段不视为已交付能力。

## 0. 公共约定

### 0.1 认证、资源和审计

两个 Controller 的每个 HTTP 公共方法均声明 `@BizAuth`，业务类型均为
`BizType.VIOLATION`。URL、方法、动作和当前审计注解如下：

| HTTP | 路径 | `@BizAuth` | 当前 `@AuditLog` |
| --- | --- | --- | --- |
| GET | `/api/yundun/accountability-violations` | `LIST` | 无 |
| GET | `/api/yundun/accountability-violations/{id}` | `READ` | 无 |
| POST | `/api/yundun/accountability-violations` | `WRITE` | `YD_ACCOUNTABILITY_ADD` |
| PUT | `/api/yundun/accountability-violations/{id}` | `WRITE` | `YD_ACCOUNTABILITY_UPDATE` |
| POST | `/api/yundun/accountability-violations/batch-delete` | `DELETE` | `YD_ACCOUNTABILITY_DELETE`，`reasonRequired=true` |
| GET | `/api/yundun/accountability-violations/export` | `EXPORT` | `YD_ACCOUNTABILITY_EXPORT`，当前未要求 reason |
| GET | `/api/yundun/accountability-violations/import-template` | `IMPORT` | 无 |
| POST | `/api/yundun/accountability-violations/import` | `IMPORT` | `YD_ACCOUNTABILITY_IMPORT`，`reasonRequired=true` |
| GET | `/api/yundun/credit-violations` | `LIST` | 无 |
| GET | `/api/yundun/credit-violations/{id}` | `READ` | 无 |
| POST | `/api/yundun/credit-violations` | `WRITE` | `YD_CREDIT_ADD` |
| PUT | `/api/yundun/credit-violations/{id}` | `WRITE` | `YD_CREDIT_UPDATE` |
| POST | `/api/yundun/credit-violations/batch-delete` | `DELETE` | `YD_CREDIT_DELETE`，`reasonRequired=true` |
| GET | `/api/yundun/credit-violations/export` | `EXPORT` | `YD_CREDIT_EXPORT`，当前未要求 reason |
| GET | `/api/yundun/credit-violations/import-template` | `IMPORT` | 无 |
| POST | `/api/yundun/credit-violations/import` | `IMPORT` | `YD_CREDIT_IMPORT`，`reasonRequired=true` |

以上 REST 资源须分别登记到 `PT_RESOURCE`，并按角色配置 `PT_ROLE_RESOURCE` 与
`PT_ROLE_BIZ_SCOPE`。本次配套的纯资源 DML 为
`docs/superpowers/sql/2026-08-19-yundun-resource-align.sql`；它不含 DDL，提交代码也不代表已在目标库执行。
导入模板下载资源必须独立登记，不能因为它与导入接口使用同一个 `BizAction.IMPORT` 就省略 URL 级资源授权。

### 0.2 统一响应

JSON 接口使用 `ResponseWrapper`。分页接口当前源码返回 `data=null`，分页内容位于 `page`：

```json
{
  "code": "0",
  "message": "success",
  "traceId": "trace-id",
  "page": {
    "pageNo": 1,
    "pageSize": 20,
    "total": 120,
    "records": []
  },
  "timestamp": "2026-08-19T09:00:00Z"
}
```

详情、新增、修改、删除和导入接口的业务数据位于 `data`；文件下载接口直接返回文件流，不套 JSON
响应。错误响应由统一异常处理器生成，业务错误码见 0.5。

### 0.3 分页参数

列表查询使用 `ViolationPageQuery`：

| 参数 | 类型 | 必填 | 默认值 | 约束 |
| --- | --- | --- | --- | --- |
| `pageNo` | Integer | 否 | 1 | `@Min(1)`；服务层缺省/非法值归一化为 1 |
| `pageSize` | Integer | 否 | 20 | `@Min(1) @Max(100)`；服务层上限归一化为 100 |

服务端固定按 `create_time DESC, id DESC` 排序，不接受前端排序列名或排序方向。

### 0.4 ID、数据范围和隐私边界

- 路径 `id` 为 1～19 位十进制 `Long`。不存在的记录返回对应 `YD-404xx`。
- MyBatis-Plus 的 `in_use` 是逻辑删除字段，正常列表、详情和导出只处理 `in_use=1` 的记录；删除将其置为
  `0`，不物理删除。
- `@BizAuth` 只建立 `DataScopeContext`，当前云盾 Service/Mapper 尚未消费该上下文。两张现有实体表
  没有明确的 `created_by/owner_org_id` 数据范围列；虽然有 `institution_name`/`affiliated_institution`，
  但它们是业务文本而非经授权的机构编码。因此当前实现不能安全推导 `SELF`、`ORG` 或 `ORG_SUBTREE`，
  非 `ALL` 范围的落地需要先由主代理确定字段映射、SQL 和权限资源，不能在前端隐藏入口代替。
- 人员违规列表只脱敏姓名；信贷风险列表脱敏责任认定对象姓名，并对 1～4 个汉字组成的客户名称脱敏。
  详情保持业务所需的明文；导出按服务规则脱敏身份证号/姓名/客户名称。详情接口必须有独立 `READ` 资源授权。

### 0.5 云盾错误码

| 错误码 | HTTP 语义 | 使用场景 |
| --- | --- | --- |
| `YD-40001` | 400 | 导入文件为空、无有效数据，或导入行缺少唯一必填工号 |
| `YD-40002` | 400 | 导出结果超过 5000 条 |
| `YD-40003` | 400 | 单次导入超过 3000 条数据行 |
| `YD-40004` | 400 | Excel 解析失败或表头/字段格式不匹配 |
| `YD-40005` | 400 | 上传文件超过 10MB |
| `YD-40401` | 404 | 人员违规记录不存在 |
| `YD-40402` | 404 | 信贷风险记录不存在 |

参数校验失败（分页、JSON body、reason 等）使用统一参数校验错误响应；不得把数据库异常、堆栈或
SQL 原文返回给调用方。

## 1. 人员违规问责

实体表：`t_accountability_for_violations`；对应 Controller：`AccountabilityViolationController`；
响应模型：`AccountabilityViolationDTO`。

### 1.1 GET `/api/yundun/accountability-violations` —— 分页列表

权限：`VIOLATION/LIST`。请求参数为分页参数加下列 `AccountabilityViolationQuery` 字段；未填写的字段
不参与过滤。文本字段按源码实际使用 `LIKE` 或精确匹配，多值的 `name`、`workNumber` 使用逗号、中文
逗号、分号、中文分号或换行分隔，去空格、去重后使用 `IN`，每个多值字段最多 100 个值。

| 参数 | 类型 | 查询语义 |
| --- | --- | --- |
| `accountabilityNumber`, `accountabilitySource`, `specificSource`, `affiliatedInstitution`, `violationAreaLevelOne`, `violationAreaLevelTwo`, `reconsideration` | String | 模糊/业务文本过滤 |
| `name`, `workNumber` | String | 多值精确 `IN` |
| `institutionName`, `deptName`, `postAtTheTime`, `accountabilityPositions`, `idNumber`, `rankAtTheTimeOfTheViolation`, `accountabilityRanks`, `otherAreas`, `factsOfTheViolation`, `partyAttitude`, `processingBasis`, `accountabilityDocumentsAndNumbers`, `penaltyPeriod`, `withholdingInstructions`, `remark` | String | 模糊过滤 |
| `gender`, `roleClassification`, `typeOfPerson`, `documentType`, `highestEducation`, `thePoliticalLandscape`, `isDimission`, `institutionalHierarchy`, `attributionOfViolations`, `typeOfResponsibility`, `primaryAndSecondaryResponsibility`, `circumstancesOfTheViolation`, `violationCharacteristics`, `areasOfViolation`, `whetherToSubmitSupervision`, `generalHandling`, `disciplinaryAction`, `economicTreatment` | String | 精确/业务选项过滤 |
| `timeOfDepartureStart`, `timeOfDepartureEnd`, `penaltyTimeStart`, `penaltyTimeEnd`, `penaltyReleaseTimeStart`, `penaltyReleaseTimeEnd`, `submissionTimeStart`, `submissionTimeEnd` | LocalDateTime | ISO 日期时间范围，包含边界 |
| `withholdingAmountMin`, `withholdingAmountMax` | BigDecimal | 扣发金额范围，包含边界 |

响应：`ResponseWrapper.page(PageResult<AccountabilityViolationDTO>)`。列表 DTO 包含保存模型字段以及
`id/createTime/updateTime`；`name` 为脱敏值，其他字段按当前列表服务规则返回。

### 1.2 GET `/api/yundun/accountability-violations/{id}` —— 详情

权限：`VIOLATION/READ`。路径 `id` 为数字 `Long`。成功时返回
`ResponseWrapper<AccountabilityViolationDTO>`；详情为当前可用记录的明细，姓名和证件号按详情服务保持
业务明文。记录不存在返回 `YD-40401`。

### 1.3 POST `/api/yundun/accountability-violations` —— 新增

权限：`VIOLATION/WRITE`，审计动作 `YD_ACCOUNTABILITY_ADD`。请求体为
`AccountabilityViolationSaveReq`，字段如下；Excel 表头中的 `(*)` 只是导入模板提示，Java Bean
实际唯一 `@NotBlank` 字段是 `workNumber`。

| 字段 | 类型 | 校验/说明 |
| --- | --- | --- |
| `accountabilityForViolationsId` | String | `@Size(max=100)`，业务主键兼容字段 |
| `accountabilityNumber`, `institutionName`, `accountabilitySource`, `specificSource`, `institutionalHierarchy`, `affiliatedInstitution`, `attributionOfViolations`, `name` | String | 业务字段 |
| `workNumber` | String | `@NotBlank`，唯一必填 |
| `gender`, `typeOfPerson`, `postAtTheTime`, `accountabilityPositions`, `documentType`, `idNumber`, `highestEducation`, `thePoliticalLandscape`, `isDimission` | String | 人员及岗位字段 |
| `timeOfDeparture`, `penaltyTime`, `penaltyReleaseTime`, `submissionTime` | LocalDateTime | 日期时间字段 |
| `typeOfResponsibility`, `violationCharacteristics`, `areasOfViolation`, `violationAreaLevelOne`, `violationAreaLevelTwo`, `factsOfTheViolation`, `processingBasis`, `accountabilityDocumentsAndNumbers`, `generalHandling`, `disciplinaryAction`, `economicTreatment`, `reconsideration`, `penaltyPeriod`, `whetherToSubmitSupervision`, `withholdingInstructions`, `remark` | String | 违规、处置及备注字段 |
| `withholdingAmount` | BigDecimal | 扣发金额 |
| `deptName`, `roleClassification`, `businessArea`, `primaryAndSecondaryResponsibility`, `circumstancesOfTheViolation`, `rankAtTheTimeOfTheViolation`, `accountabilityRanks`, `otherAreas`, `partyAttitude` | String | 历史兼容字段，仍可由保存接口接收 |
| `inUse` | Integer | `@ExcelIgnore`，系统维护字段；创建时服务端强制设为 1 |

成功返回 `ResponseWrapper<AccountabilityViolationDTO>`。新增在 Service 事务内完成，审计字段由公共
数据库组件填充；写入范围二次校验仍需按 0.4 的数据范围决策补齐。

### 1.4 PUT `/api/yundun/accountability-violations/{id}` —— 修改

权限：`VIOLATION/WRITE`，审计动作 `YD_ACCOUNTABILITY_UPDATE`。路径 `id` 与请求体规则同 1.3；
Service 先读取目标实体，复制保存字段但不接受请求体覆盖 `inUse`，再更新并返回最新 DTO。不存在返回
`YD-40401`。写入前必须执行目标实体的数据范围二次校验；当前代码只有存在性检查。

### 1.5 POST `/api/yundun/accountability-violations/batch-delete` —— 批量逻辑删除

权限：`VIOLATION/DELETE`，审计动作 `YD_ACCOUNTABILITY_DELETE`，reasonRequired=true。

请求体：

```json
{
  "ids": [101, 102],
  "reason": "重复导入，清理无效记录"
}
```

`ids` 必填、非空、最多 100 个；`reason` 必填且最多 500 字符。Service 先逐条确认记录存在，再通过
逻辑删除批量更新；当前事务边界覆盖检查和删除。成功 `data` 为实际影响条数，找不到记录返回
`YD-40401`。

### 1.6 GET `/api/yundun/accountability-violations/export` —— 导出

权限：`VIOLATION/EXPORT`，审计动作 `YD_ACCOUNTABILITY_EXPORT`。请求参数复用 1.1 的查询字段，另有
可选重复参数 `ids`：

- `ids` 非空时按选中 ID 导出，输入 ID 数量最多 5000，服务端再次限定 `in_use=1`；
- 未传 `ids` 时按当前筛选条件导出；
- 实际导出结果超过 5000 条时返回 `YD-40002`，避免同步响应占用无界内存；
- 文件为 `.xlsx`，响应 `Content-Type` 为 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，
  文件名为 URL 编码的 `人员违规信息_yyyyMMddHHmmss.xlsx`；
- 导出行使用 `AccountabilityViolationSaveReq`，不输出 `inUse`，姓名和证件号按导出规则脱敏。

当前接口没有 reason 参数，前端也未提交导出原因；按照平台高危导出要求，这一审计契约仍是待补项，
见 `07-审计要求.md`，不能将当前标注误解为已完成高危原因校验。

### 1.7 GET `/api/yundun/accountability-violations/import-template` —— 导入模板

权限：`VIOLATION/IMPORT`，无业务审计记录。返回不含数据的单层表头 `.xlsx`，只保留当前导入列：
`AccountabilityViolationSaveReq` 的新版模板字段，排除 `deptName`、`roleClassification`、`businessArea`、
`primaryAndSecondaryResponsibility`、`circumstancesOfTheViolation`、`rankAtTheTimeOfTheViolation`、
`accountabilityRanks`、`otherAreas`、`partyAttitude` 等历史导出兼容列和 `inUse`。文件名为
`人员违规信息导入模板_yyyyMMddHHmmss.xlsx`。

### 1.8 POST `/api/yundun/accountability-violations/import` —— Excel 导入

权限：`VIOLATION/IMPORT`，审计动作 `YD_ACCOUNTABILITY_IMPORT`，reasonRequired=true。请求为
`multipart/form-data`：

| 字段 | 类型 | 必填/限制 |
| --- | --- | --- |
| `file` | MultipartFile | 必填，非空，大小不超过 10MB |
| `reason` | String | 必填，最多 500 字符 |

解析使用单层表头（`headRowNumber=1`），支持公共文本日期转换器；数据行最多 3000 条，且每行的
`workNumber` 必须非空白。Service 在同一个事务内按每批 500 条生成多值 `INSERT`，任何一批失败都回滚
全部批次。成功 `data` 为导入行数；文件、表头、字段解析失败返回 `YD-40004`，超过文件大小返回
`YD-40005`，超过行数返回 `YD-40003`，空文件或缺少工号返回 `YD-40001`。

## 2. 信贷风险责任认定

实体表：`t_credit_violation`；对应 Controller：`CreditViolationController`；响应模型：`CreditViolationDTO`。

### 2.1 GET `/api/yundun/credit-violations` —— 分页列表

权限：`VIOLATION/LIST`。请求参数为分页参数加 `CreditViolationQuery`：

| `clientName`, `responsiblePersonName`, `employeeNumber` | String | 多值精确 `IN`，逗号/中文逗号/分号/中文分号/换行分隔，去空格去重，单字段最多 100 个值 |

权限：`VIOLATION/WRITE`，审计动作 `YD_CREDIT_UPDATE`。路径和请求体规则同 2.3；Service 先确认目标
存在，复制保存字段但不允许覆盖 `inUse`，成功返回最新 DTO，不存在返回 `YD-40402`。当前代码尚未
执行目标实体的数据范围二次校验。

### 2.5 POST `/api/yundun/credit-violations/batch-delete` —— 批量逻辑删除

权限：`VIOLATION/DELETE`，审计动作 `YD_CREDIT_DELETE`，reasonRequired=true。请求体与人员违规
一致：`ids` 非空且最多 100 个，`reason` 必填且最多 500 字符。Service 在事务内先逐条确认，再将
`in_use` 置为 0；成功 `data` 为实际影响条数；不存在返回 `YD-40402`。

### 2.6 GET `/api/yundun/credit-violations/export` —— 导出

权限：`VIOLATION/EXPORT`，审计动作 `YD_CREDIT_EXPORT`。请求参数复用 2.1，`ids` 可重复传递。
未传 ID 时按筛选条件导出，传 ID 时最多 5000 个并由服务端再次过滤 `in_use=1`；结果超过 5000
条返回 `YD-40002`。文件为 `信贷风险信息_yyyyMMddHHmmss.xlsx`，Content-Type 为标准 XLSX 类型，
使用四层表头及写处理器：第 1 行视觉留空，第 2 行为责任认定对象所在机构/责任认定/经济扣发/违规问责
分组，第 3 行在违规问责下设置经济处理，第 4 行为字段列名。连续记录中客户字段 A～H 和 AE 的相同值按
规则纵向合并；`inUse` 不输出，客户名称和责任对象姓名按导出规则脱敏。

当前未接收导出 reason，见 07 的待办审计契约。

### 2.7 GET `/api/yundun/credit-violations/import-template` —— 导入模板

权限：`VIOLATION/IMPORT`，无业务审计记录。返回不含数据的四行表头模板
`信贷风险信息导入模板_yyyyMMddHHmmss.xlsx`：第 1 行留空；第 2 行包含四个业务分组；第 3 行包含
机构字段、责任字段、经济扣发字段以及“经济处理”等子分组；第 4 行为字段列名。排除历史导出兼容列
`responsibilityDetermination`、`isEconomicDeduction`、`recycleAndReturn`、`isFalseBuckle`、
`otherProcessing`、`responsibilityDeterminationTime`、`isReportToTheBankingRegulatoryCommission`、
`submissionTime`、`remark` 和系统字段 `inUse`。

### 2.8 POST `/api/yundun/credit-violations/import` —— Excel 导入

权限：`VIOLATION/IMPORT`，审计动作 `YD_CREDIT_IMPORT`，reasonRequired=true。请求为
`multipart/form-data`，字段为非空 `file`（最大 10MB）和必填 `reason`（最大 500 字符）。后端先用
Apache POI 展开数据区客户字段的纵向合并单元格（A～H、AE），再以四行表头解析；支持文本日期转换。
最多 3000 条数据行，每行 `employeeNumber` 必须非空白；Service 在一个事务中按每批 500 条执行多值
`INSERT`，任一批失败回滚全部批次。成功 `data` 为导入行数；错误码按 0.5 返回。

## 3. 事务、并发和当前未闭环项

- 两类新增、修改、批量删除和批量导入 Service 均声明 `@Transactional(rollbackFor = Exception.class)`；
  导入先做总量及必填工号校验，再开始任何批量写入。
- 列表和导出均为同步查询；导出硬上限 5000 条，导入硬上限 3000 行、单批 500 行，未实现异步导出任务。
- 当前实体没有可直接用于 `SELF/ORG/ORG_SUBTREE` 的授权归属字段，列表、详情、导出和写操作的统一
  DataScope 仍需主代理结合真实 schema、权限配置和 SQL 决定；本文件不新增 DDL。
- 当前导出缺少 reason 参数及前端采集，不能宣称已满足平台“高危导出必须有原因”的要求。
