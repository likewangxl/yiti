# 浦爱云盾应用中心审计要求

> 本文与当前 Controller、Service 和 `common-aop` 实现对照维护。审计日志由公共
> `@AuditLog`/`AuditLogAspect` 采集，治理模块负责持久化；本模块不直接写审计表，也不新增 DDL。

## 1. 审计动作矩阵

| 业务动作 | HTTP 路径（两类台账同构） | `@BizAuth` | `@AuditLog` action | reason 要求 | 当前状态 |
| --- | --- | --- | --- | --- | --- |
| 列表查询 | `GET .../accountability-violations`、`GET .../credit-violations` | `LIST` | 无 | 否 | 已实现，无写审计 |
| 详情查询 | `GET .../{id}` | `READ` | 无 | 否 | 已实现，需独立详情资源授权 |
| 人员新增 | `POST .../accountability-violations` | `WRITE` | `YD_ACCOUNTABILITY_ADD` | 否 | 已实现 |
| 人员修改 | `PUT .../accountability-violations/{id}` | `WRITE` | `YD_ACCOUNTABILITY_UPDATE` | 否 | 已实现 |
| 人员删除 | `POST .../accountability-violations/batch-delete` | `DELETE` | `YD_ACCOUNTABILITY_DELETE` | 是，≤500 字符 | DTO 和注解均声明；Service 事务已实现 |
| 人员导出 | `GET .../accountability-violations/export` | `EXPORT` | `YD_ACCOUNTABILITY_EXPORT` | **平台要求是；当前接口未收集** | 待补跨前后端契约 |
| 人员模板下载 | `GET .../accountability-violations/import-template` | `IMPORT` | 无 | 否 | 已实现；仍需独立 PT_RESOURCE |
| 人员导入 | `POST .../accountability-violations/import` | `IMPORT` | `YD_ACCOUNTABILITY_IMPORT` | 是，≤500 字符 | DTO 和注解均声明；导入行工号已补校验 |
| 信贷新增 | `POST .../credit-violations` | `WRITE` | `YD_CREDIT_ADD` | 否 | 已实现 |
| 信贷修改 | `PUT .../credit-violations/{id}` | `WRITE` | `YD_CREDIT_UPDATE` | 否 | 已实现 |
| 信贷删除 | `POST .../credit-violations/batch-delete` | `DELETE` | `YD_CREDIT_DELETE` | 是，≤500 字符 | DTO 和注解均声明；Service 事务已实现 |
| 信贷导出 | `GET .../credit-violations/export` | `EXPORT` | `YD_CREDIT_EXPORT` | **平台要求是；当前接口未收集** | 待补跨前后端契约 |
| 信贷模板下载 | `GET .../credit-violations/import-template` | `IMPORT` | 无 | 否 | 已实现；仍需独立 PT_RESOURCE |
| 信贷导入 | `POST .../credit-violations/import` | `IMPORT` | `YD_CREDIT_IMPORT` | 是，≤500 字符 | DTO 和注解均声明；导入行工号已补校验 |

模板下载使用 `BizAction.IMPORT` 是为了沿用导入权限语义，但 URL 必须有独立 `PT_RESOURCE`，不能
以页面按钮隐藏或只登记 `POST .../import` 代替授权。

## 2. 审计字段与敏感信息

当前 `AuditLogAspect` 从方法注解、`DataScopeContext` 和 HTTP 请求读取：

| 字段 | 来源/要求 |
| --- | --- |
| `action`, `resourceType` | 上表中 `@AuditLog` 固定值 |
| 操作人工号、机构、业务类型 | `DataScopeContext`、方法 `@BizAuth`；缺上下文时不得伪造 |
| URL、HTTP 方法、IP、User-Agent、traceId、耗时、状态码、异常消息 | 公共切面采集；异常路径也要保留失败状态 |
| `reason` | 反射调用参数的 `getReason()`；删除/导入由 DTO 提供，文件参数本身不写日志 |
| before/after | 当前云盾 Controller 未提供 `serviceManaged` 快照，公共切面记录为空；不得把完整 DTO 或 Excel 内容直接塞进审计日志 |

姓名、证件号、客户名称等敏感字段按 REST 契约的展示/导出规则脱敏。审计 reason 只保留业务原因，
不得填写或记录密码、凭据、完整证件号、完整客户名单等敏感内容。Controller 的普通业务日志也不应
输出原始 Excel、完整查询结果或身份证号。

## 3. 高危操作和阻断项

1. 删除和导入是高危写操作，必须同时满足：独立 `PT_RESOURCE`、`@BizAuth`、请求 reason 非空且长度
   不超过 500、Service 事务以及目标实体的数据范围二次校验。
2. 导出属于高危数据外带操作。当前两个导出接口虽然有 `@AuditLog`，但没有 `reasonRequired=true`、
   没有 reason 请求字段，前端 `exportViolations` 也未提交 reason；这不是已完成的高危审计闭环。主代理
   需要同步修改 REST、前端 prompt/请求和实际前置校验，并补资源/测试后才能关闭该项。
3. 当前 `common-aop` 的 `reasonRequired` 是注解元数据，`AuditLogAspect` 负责提取 reason 但不直接以
   注解属性阻断请求；云盾删除/导入的实际阻断来自 `ViolationBatchDeleteReq`/`ViolationImportReq`
   的 `@NotBlank`。若要修复导出原因，不能只把注解属性改成 `true`，必须确保请求 DTO/参数和前置校验
   链路一致。
4. 当前两张源表没有明确的授权归属机构/创建人字段，Service 也不读取 `DataScopeContext`。在确定字段
   映射和 SQL 过滤前，不能把非 `ALL` 角色范围当作已生效，也不能以 SYS_ADMIN 绕过屏级资源、机构组或
   数据范围门禁。

## 4. 审计验收清单

- 每个 URL+HTTP Method 在 `PT_RESOURCE` 有独立、启用的资源，详情、导出、模板下载不共享错误资源。
- 每个 Controller 公共方法都有 `@BizAuth`，动作与 LIST/READ/WRITE/DELETE/IMPORT/EXPORT 语义一致。
- 删除和导入使用合法 reason；空白、超长 reason 在进入 Service 前失败，且失败不产生写入。
- 导出补齐 reason 后，审计事件中包含操作人、机构、BizType、URL、状态、traceId、耗时和 reason。
- 审计日志不包含 Excel 内容、原始证件号、密码、token 或未脱敏的大批量客户数据。
- 以不同数据范围角色验证列表、详情、导出、修改、删除和导入；直传 ID 不能越权访问或修改记录。
- 审计持久化及留存策略由 `system-governance-center` 的治理实现和生产配置确认，本模块不自行声明留存年限。
