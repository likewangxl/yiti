# 浦爱云盾应用中心依赖契约摘要

> 本文只记录当前模块实际依赖、调用边界和未闭环风险。跨模块 Java 契约以提供方 `api/` 源码为准，
> 数据库结构以目标库只读盘点为准；本模块不新增 DDL，配套权限 DML 仅作为待授权执行的交付物。

## 1. Maven 与公共能力

`yundun-application-center/pom.xml` 当前依赖：

| 依赖 | 强度 | 用途 |
| --- | --- | --- |
| `common-web` | 强 | `ResponseWrapper`、`PageResult`、`BizException`、统一 Web 异常和文件响应基础 |
| `common-security` | 强 | `@BizAuth`、`BizType.VIOLATION`、`BizAction`、`DataScopeContext` |
| `common-aop` | 强 | `@AuditLog` 与审计 SPI/切面 |
| `common-trace` | 强 | traceId/MDC 传播 |
| `common-db` | 强 | MyBatis-Plus、分页、逻辑删除和审计字段填充 |
| `auth-permission-center` | 强 | 认证拦截、`PT_RESOURCE`/RBAC、`PT_ROLE_BIZ_SCOPE` 数据范围上下文 |
| `system-governance-center` | 强 | 公共治理自动配置及审计持久化实现；本模块不直接引用其 mapper/entity |
| EasyExcel、Apache POI（由依赖树提供） | 强 | XLSX 模板、导入、导出、多级表头和合并单元格处理 |

本模块没有对外 `*Api`/`*QueryApi`，也不向其他业务模块暴露 Java facade；当前跨模块边界是 REST 页面
消费者、公共安全/审计能力和自有 Mapper。

## 2. 认证、资源与数据范围依赖

### 2.1 资源登记

源码端点必须与以下资源语义一一对应（最终 ID 以目标库现场盘点为准）：

| 资源语义 | 资源 URL/方法 |
| --- | --- |
| 人员列表/详情/新增/修改/删除/导出/导入 | `/api/yundun/accountability-violations` 及其子路径，方法分别为 GET/POST/PUT |
| 人员导入模板 | `/api/yundun/accountability-violations/import-template`，GET |
| 信贷列表/详情/新增/修改/删除/导出/导入 | `/api/yundun/credit-violations` 及其子路径，方法分别为 GET/POST/PUT |
| 信贷导入模板 | `/api/yundun/credit-violations/import-template`，GET |

配套资源 DML `docs/superpowers/sql/2026-08-19-yundun-resource-align.sql` 使用
`P_YD_ACCT_*`、`P_YD_CREDIT_*`，模板资源为 `P_YD_ACCT_IMP_TPL`、`P_YD_CREDIT_IMP_TPL`。
脚本入库不是目标库执行证明；仍需由 DBA/授权流程处理资源增量并验证角色授权关系。

### 2.2 BizScope 前置契约

所有端点通过 `BizType.VIOLATION` 建立数据范围上下文。期望的闭环是：

1. auth 根据员工、角色和 `PT_ROLE_BIZ_SCOPE` 解析 `ALL`、`ORG`、`ORG_SUBTREE` 或个人范围；
2. 列表、详情、导出在 SQL/Service 层使用同一范围；
3. 修改、删除、导入在写入前针对目标实体做二次校验；
4. 未知、空值或范围计算异常 Fail Close。

当前实体只有业务机构文本字段，没有明确的 `owner_org_id`、创建人工号或员工归属列，当前 Service
只依赖 `in_use` 和查询条件，未读取 `DataScopeContext`。因此这是一个需要主代理结合真实 schema、
权限配置和业务口径完成的依赖缺口；不能凭文档把非 `ALL` 范围写成已实现，也不能新增临时 DDL 绕过审批。

## 3. 数据库与文件边界

- 本模块自有表：`t_accountability_for_violations`、`t_credit_violation`；Mapper 只访问对应表，不跨模块
  join 私有表。
- `in_use` 是逻辑删除列，值 `1` 表示可用、`0` 表示已删除；两个实体的 `@TableLogic` 必须与真实
  schema 一致。
- 批量导入通过模块 XML Mapper 生成每批最多 500 行的多值 `INSERT`；总量 3000 行限制和事务边界在
  Service 内完成。导出使用 MyBatis-Plus 查询，结果最多 5000 行后写入同步 XLSX。
- 当前模块不使用 OBS/MinIO、不创建临时文件、不维护文件元数据；Excel 仅在 HTTP 请求内读写，未来如
  改为异步/对象存储，需另行补充治理文件契约和清理策略。

## 4. 前端 REST 消费契约

当前前端消费者为 `xanzc_frontend/src/api/yundun.js` 与
`xanzc_frontend/src/views/yundun/ViolationManagement.vue`：

| 前端调用 | 后端接口 | 说明 |
| --- | --- | --- |
| `listViolations(kind, params)` | GET 列表 | 读取 `page.records/page.total` |
| `getViolation(kind, id)` | GET 详情 | 受保护的明细请求 |
| `createViolation`/`updateViolation` | POST/PUT | 保存 DTO，页面表单规则应与 Bean 校验一致 |
| `batchDeleteViolations(kind, ids, reason)` | POST batch-delete | 已传删除原因 |
| `importViolations(kind, file, reason)` | POST import | multipart 文件和导入原因 |
| `downloadViolationImportTemplate(kind)` | GET import-template | blob 文件下载 |
| `exportViolations(kind, params, filename)` | GET export | 当前只传筛选/ID，没有导出 reason |

若主代理按平台高危规范补齐导出 reason，必须同步这两个前端调用点、页面 prompt、API 契约测试和真实
浏览器验收；本次云盾文档/后端任务不直接修改前端。

## 5. 版本与验收边界

- 本模块当前测试覆盖 DTO Bean 校验、查询条件白名单/多值上限、逻辑删除标记、导入分批与总量、模板和
  多级表头、文本日期、合并单元格、隐私脱敏和导出上限；测试不等于 PT_RESOURCE/真实数据库/真实浏览器
  鉴权已验收。
- Maven 单模块全量测试应使用隔离的本地仓库参数，并在报告中区分“代码单测通过”和“目标库/资源授权未验证”。
- 本次资源 DML 已随代码提交，但未对真实库执行；任何执行或 schema 变更仍须先只读盘点 `yiti_test`、走审批，
  并由主代理单独报告 SQL/权限闭环。
