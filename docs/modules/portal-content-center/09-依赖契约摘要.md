# 门户与内容中心 — 依赖契约摘要

## 1. 规则和方向

portal-content-center 是通用门户模块，直接依赖 auth、governance、workflow 和 common；不依赖 customer、business、performance、report 等核心域。模块间只通过提供方公开的 `*Api`/`*QueryApi` 及 DTO 交互，不能引用对方 mapper、entity、内部 service 或私有表。

门户公开给其他模块的接口及 DTO 见 `04-对外API契约.md`。本文件只记录 portal 实际使用的上游边界、降级和存量风险，不复制完整 POM、包、类或表清单。

## 2. auth-permission-center

### 2.1 当前用户 `CurrentUserApi`

portal 使用 `getCurrentEmpId()`、`getCurrentOrgCode()`、`getCurrentUserContext()` 和 `isSystemAdmin()` 确定当前操作者、机构、公告发布人及产品维护权限。当前用户方法从认证上下文取值，不应被当作任意员工查询接口；空上下文必须按未登录/无权限处理。

### 2.2 用户目录 `UserDirectoryApi`

portal 通过以下公开方法取得通讯录主数据和联系方式：

```java
PageResult<UserDirectoryDTO> pageActiveUsers(String keyword, String orgCode,
                                             int pageNo, int pageSize);
UserDirectoryDTO getEmployee(String userId);
List<UserDirectoryDTO> getEmployeesByIds(List<String> userIds);
List<UserDirectoryDTO> searchEmployees(String keyword, int limit);
UserDirectoryDTO updateCurrentUserContact(String mobile, String email);
```

数据口径为 `PT_USER` + `EXT_USER_ORG` + `EXT_ORG_INFO`；规范员工标识是 `PT_USER.USER_ID`。目录查询不到返回空结果/`null`，portal 负责将其转换为门户错误码或空列表。门户不再直接读取旧 `ADDRBOOK_EMPLOYEE`。

### 2.3 范围和组织

产品分页使用 `BizScopeApi.buildScopeContext(empId, BizType.PRODUCT, BizAction.LIST)`，再由 `DataScopeAdapter` 转为门户查询上下文。写路径另行校验实体维护机构和系统管理员身份。

产品展示和导出使用 `OrgApi.getOrgsByCodes(Collection<String>)` 批量装配机构名称；缺失机构只影响展示，不应由 portal 写回 auth 组织表。需要机构树时应使用 `OrgApi` 的公开查询方法，不能直接读组织 mapper。

### 2.4 角色查询

通讯录 Facade 使用 `UserApi.getUserRoleCodes(empId)` 判断客户经理角色；担保列表使用 `UserApi.getUsersByUsernames(usernames)` 将经办人工号批量解析为姓名。两者都只是展示/业务校验，不授予 Controller 权限。

## 3. system-governance-center

### 3.1 文件 `FileApi`

文档和公告附件使用 `upload`、`getDownloadUrl`、`getFileContent`，文档列表还使用批量文件大小查询。治理 API 屏蔽对象存储细节，当前实现的实际对象存储为华为云 OBS；portal 不直接注入对象存储客户端。文件对象 ID 可为空或无命中，调用方必须处理治理侧错误；公告附件的本地 `file_path` 列存的是对象 ID，不是本地路径。

### 3.2 通知 `NotifyApi`

工作台使用：

```java
int countUnread(String empId);
PageResult<NotificationDTO> queryNotifications(String empId,
                                               Boolean isRead,
                                               PageRequest page);
```

通知发送方使用 `sendNotification(NotificationCmd)` 或批量发送方法；portal 不写治理通知表。`NotifyApi` 在工作台中可选注入，Bean 缺失或调用异常时通知数量为 `0`、列表为空并保留聚合错误。

### 3.3 字典 `DictApi`

产品导出通过 `batchGetDictItems` 获取 `PRODUCT_CATEGORY` 显示标签；字典缺失时导出回退为存储代码。其他模块字典展示应继续经治理 `DictApi`，不要在 portal 复制字典表或初始化值。

### 3.4 审计 `AuditApi`

导航、产品、产品导出、文档和本人通讯录维护通过 `AuditApi.log(AuditLogCmd)` 写审计。各 Service 当前以安全包装捕获审计异常并告警，不能把成功调用视为强制落库；公告和担保路径目前未接入门户审计。审计字段、独立事务和脱敏规则以治理公开 DTO 及 `07-审计要求.md` 为准。

### 3.5 缓存实现的存量风险

导航和支持产品当前直接使用治理 `MemoryCacheService`（Caffeine）及 portal 缓存键。该类不是治理 `api` 公开契约，属于现存实现耦合；新增跨模块缓存能力应先由治理提供稳定公开接口，并定义多实例一致性和失效语义，不得据此引入 Redis。

## 4. workflow-center

门户只通过公开 `WorkflowQueryApi` 的以下方法查询工作台数据：

```java
int countPendingTasks(String empId);
List<TaskRespDTO> listRecentPendingTasks(String empId, int limit);
```

`WorkflowQueryAdapter` 将 `TaskRespDTO` 投影为门户待办 DTO。工作流 Bean 缺失或调用异常时返回 `0`/空列表并记录日志；portal 不直接调用 Flowable，也不读取 `ACT_*`、流程私有 Mapper 或实体。

`WorkflowApprovalNotificationListener` 是当前代码中的存量边界例外，仍直接引用 workflow 内部 mapper/entity/事件和治理内部通知 Service。它不是可复用契约；新增流程查询、事件和通知必须由 workflow 提供公开 `api`/事件，再经治理 `NotifyApi` 使用。

## 5. performance-engine-center

`MetricAdapter.fetchForWorkspace(empId)` 调用 `MetricApi.getPersonalCoreMetricCards(empId)`；`PerformanceMetricApiBridge` 原样透传员工号并投影 `previousValue`、`comparisonType`、`sourceType`、`changeRate` 和 `dataTime`。个人核心路径固定 `comparisonType=PREVIOUS_MONTH_END`、`sourceType=EMP_LATEST_IMPORT`；兼容性的 `getUserMetricCards` 保持独立且不设置来源标记，目标值和达成率允许为空。

portal 模块不在 POM 中直接依赖 performance。portal 定义自己的 `adapter.MetricApi`，bootstrap 的 `PerformanceMetricApiBridge` 注入 performance 公开 `MetricApi.getPersonalCoreMetricCards(empId)`，再把指标卡片投影成 portal DTO；兼容性的 `getUserMetricCards` 保持独立。桥接 Bean 缺失或调用异常时 `MetricAdapter` 返回空列表，工作台其他区域继续可用。

performance 通过 portal 的 `AddressBookApi` 校验员工时，只能依赖公开 DTO；门户不反向读取 performance 表或内部 Service。性能 API 的其他指标定义、版本和数据日期方法不属于 portal 工作台契约，不能在本文件扩展成调用承诺。

## 6. common

portal 复用 common 的统一响应 `ResponseWrapper`/`PageResult`、Trace/MDC、`@BizAuth`、`BizType`/`BizAction`、异常和数据范围类型。公共契约变化时，必须同步 REST 文档、审计/资源要求和所有消费者测试；portal 不建立平行响应、鉴权或锁实现。

## 7. 降级矩阵

| 上游 | 使用场景 | 缺失/异常时的当前行为 |
| --- | --- | --- |
| `WorkflowQueryApi` | 待办数量/最近待办 | `0`/空列表，记录日志 |
| portal `adapter.MetricApi`（bootstrap 桥接） | 指标卡片 | 空列表，记录日志 |
| `NotifyApi` | 工作台通知 | `0`/空列表，聚合错误可见 |
| `UserDirectoryApi` | 通讯录 | 单条转业务不存在或空结果，批量返回空列表 |
| `OrgApi`/`DictApi` | 名称/标签装配 | 保留代码或空展示，不写回来源 |
| `FileApi` | 文档/公告文件 | 按治理错误处理，不直连其他存储 |
| `AuditApi` | 当前已接入写操作 | 当前 Service 告警并继续主流程；高风险缺口见 `07` |

降级只适用于契约明确的查询/辅助信息；权限解析失败、目标实体权限校验失败和写入失败必须 fail close，不能用空数据掩盖越权或数据损坏。

## 8. 变更门禁

修改上游公开方法、DTO、事件、资源或数据范围时，先核对提供方 `api/` 源码和所有消费者，再同步 `03`、`04`、`07`、`08` 及本文件。禁止通过修改 portal 文档来掩盖缺少 API、资源绑定或运行配置；未实现能力不写入当前契约。
