# 门户与内容中心 — 资源与运行配置要求

## 1. 使用边界

本文只保留当前运行所需的资源登记、通知边界和配置要求。它不是种子数据、测试数据、DDL、执行顺序或生产操作脚本；部署和权限变更前必须在目标库只读核对 `PT_RESOURCE`、`PT_ROLE_RESOURCE` 及治理配置，实际数据库状态优先。

## 2. 当前 REST 资源登记

除工作台和快捷入口的登录态架构例外外，所有 Controller 业务方法都要同时满足 `@BizAuth`、资源 URL+HTTP 方法匹配和角色授权。工作台/快捷入口虽然不标注 `@BizAuth`，仍应保留资源登记以便资源管理、审计和架构测试追踪。下表是当前代码路径对应的稳定资源标识；标识是否已落库需现场查询，不在本文提供 DML。

## 3. 通知边界

工作台只通过治理 `NotifyApi` 读取未读数量和通知分页列表：

- `countUnread(empId)` 提供角标数量；
- `queryNotifications(empId, isRead, PageRequest)` 提供工作台最近通知；
- `NotifyApi` Bean 缺失或调用失败时，工作台返回 `0`/空列表并在聚合错误中保留可诊断信息。

通知发送仍由治理 `NotifyApi.sendNotification`/`batchSendNotifications` 负责，portal 不写通知表。现存 `WorkflowApprovalNotificationListener` 直接调用治理内部通知 Service 属于存量技术债；新增代码必须改用公开 API，不能把该监听器当作初始化要求或复制模板。

## 4. 文件和运行配置

### 4.1 文件

文档和公告附件只保存治理文件对象 ID，上传、下载和内容读取统一经 `FileApi`。当前对象存储为华为云 OBS；portal 不配置或直连 MinIO、本地磁盘或其他对象存储客户端。

### 4.2 工作台执行器

`PortalAsyncConfig` 提供工作台聚合专用的有界执行器，队列满时使用调用线程策略，避免静默丢弃请求。并行路数、线程池大小和超时属于源码配置，修改后以 `PortalAsyncConfig`/`WorkspaceService` 同步检查为准，本文不复制易漂移数值。

### 4.3 门户缓存

`PortalCacheConfig` 当前定义导航启用列表和支持中场支持产品列表的缓存键、基准 TTL 及抖动工具；`NavService`、`ProductService` 使用治理 `MemoryCacheService` 执行 Cache-Aside，写入后失效对应键。实际实现是本地 Caffeine，缓存不跨实例共享，单条 TTL 是否生效以治理实现为准；不能据此声明 Redis 已部署。

### 4.4 担保同步任务

`GuaranteeSyncJob` 的任务键为 `GUARANTEE_INFO_SYNC`，计划由治理 `sys_job_conf` 管理。任务调用门户 `GuaranteeSyncService`，读取前一日 `clms_ed_credit_info`，更新/补入 `zh_guarantee_info` 并归集合同数据；Quartz 的调度、集群锁、启停和执行日志由治理中心统一负责。本文不复制 cron、Quartz 表数据或一次性启停顺序。

### 4.5 环境要求

运行环境应提供 auth 当前用户/用户目录/数据范围 API、治理文件/通知/审计 API 和 workflow 查询 API；performance 指标通过 bootstrap 桥接提供，桥接缺失时工作台指标为空。测试或隔离环境必须按根目录数据库、外联、Quartz、对象存储和消息隔离门禁配置，不使用本文作为测试数据来源。
