## 3. 通讯录同步初始化

### 3.1 数据来源

| 来源字段 | 来源表 | portal 目标字段 |
|---|---|---|
| `emp_id` | `PT_USER.emp_id` | `addrbook_employee.emp_id` |
| `emp_name` | `PT_USER.emp_name` | `addrbook_employee.emp_name` |
| `mobile` | `PT_USER.mobile` | `addrbook_employee.mobile` |
| `email` | `PT_USER.email` | `addrbook_employee.email` |
| `org_code` | `EXT_USER_ORG.org_code` | `addrbook_employee.org_code` |
| `org_name` | `EXT_ORG_INFO.org_name`（基于 org_code join） | `addrbook_employee.org_name` |
| `status` | `PT_USER.status` | `addrbook_employee.status`（映射） |

**状态映射：**
| PT_USER.status | portal.status |
|---|---|
| `ACTIVE` | `ACTIVE` |
| `LOCKED` | `ACTIVE`（锁定仍显示在通讯录） |
| `DISABLED`/`RESIGNED` | `RESIGNED` |

### 3.2 初始化 SQL（手工执行 portal_addrbook_init.sql）

```sql
-- 初始化通讯录：基于 auth 模块 PT_USER 全量同步
INSERT INTO addrbook_employee
  (emp_id, emp_name, mobile, email, org_code, org_name, position, status,
   maintainer_emp_id, created_by, created_time, updated_time, deleted)
SELECT
  u.emp_id,
  u.emp_name,
  u.mobile,
  u.email,
  uo.org_code,
  o.org_name,
  u.position,
  CASE
    WHEN u.status IN ('DISABLED','RESIGNED') THEN 'RESIGNED'
    ELSE 'ACTIVE'
  END AS status,
  NULL AS maintainer_emp_id,   -- 初始维护人为空，由管理台后续指定
  'SYSTEM' AS created_by,
  CURRENT_TIMESTAMP,
  CURRENT_TIMESTAMP,
  0
FROM PT_USER u
LEFT JOIN EXT_USER_ORG uo ON uo.emp_id = u.emp_id AND uo.is_primary = 1
LEFT JOIN EXT_ORG_INFO o  ON o.org_code = uo.org_code
WHERE NOT EXISTS (
    SELECT 1 FROM addrbook_employee ae WHERE ae.emp_id = u.emp_id
);
```

### 3.3 初始化后校验

```sql
-- 数量对齐校验
SELECT
  (SELECT COUNT(*) FROM PT_USER WHERE status IN ('ACTIVE','LOCKED')) AS pt_user_active_count,
  (SELECT COUNT(*) FROM addrbook_employee WHERE deleted = 0 AND status = 'ACTIVE') AS addrbook_active_count;

-- 机构关联校验
SELECT COUNT(*) FROM addrbook_employee WHERE deleted = 0 AND org_code IS NULL;
-- 期望：0；若 >0 表示 EXT_USER_ORG 中缺少主机构关联，需 auth 模块补数据
```

### 3.4 增量同步（运行时）

初始化完成后，后续增量由事件驱动：
- `auth.user.created.v1` → INSERT
- `auth.user.updated.v1` → UPDATE
- `auth.user.disabled.v1` → UPDATE status=RESIGNED
- `auth.user.org-changed.v1` → UPDATE org_code + org_name

详见 `05-表结构DDL.md` 第 7.1 节。

## 10. 初始化验证 Checklist

执行完初始化脚本后，必须通过以下验证：

```sql
-- 1. 导航数据检查
SELECT nav_category, COUNT(*) FROM portal_nav WHERE status='ACTIVE' GROUP BY nav_category;
-- 期望：HQ_SYSTEM=4, BRANCH_SYSTEM=4, EXTERNAL_SYSTEM=2, REGULATORY=2, LEARNING=2

-- 2. 快捷入口检查
SELECT COUNT(*) FROM portal_shortcut WHERE shortcut_type='SYSTEM' AND status='ACTIVE';
-- 期望：9

-- 3. 通讯录同步检查
SELECT
  (SELECT COUNT(*) FROM PT_USER WHERE status IN ('ACTIVE','LOCKED')) AS pt_user,
  (SELECT COUNT(*) FROM addrbook_employee WHERE deleted=0 AND status='ACTIVE') AS addrbook;
-- 期望：两者相等

-- 4. 资源登记检查
SELECT COUNT(*) FROM PT_RESOURCE WHERE module='portal-content-center' AND status='ACTIVE';
-- 期望：>= 30（含所有 API）

-- 5. 字典依赖检查
SELECT dict_code, COUNT(*) FROM DICT_ITEM
WHERE dict_code IN ('NAV_CATEGORY','PRODUCT_CATEGORY','DOC_CATEGORY','POSITION')
GROUP BY dict_code;
-- 期望：4 个字典均有数据

-- 6. 定时任务检查
SELECT job_key, status FROM sys_job_conf WHERE job_key LIKE 'PORTAL%' OR job_key IN
  ('ADDR_BOOK_REMIND','PRODUCT_REMIND','ADDR_BOOK_FULL_SYNC','PRODUCT_RESPONSIBLE_CONSISTENCY_CHECK');
-- 期望：全部 ACTIVE

-- 7. 通知模板检查
SELECT template_code, status FROM sys_notify_template WHERE template_code IN
  ('ADDR_BOOK_STALE_REMIND','PRODUCT_STALE_REMIND');
-- 期望：均 ACTIVE
```

## 11. 回滚脚本

初始化失败时按反向顺序回滚：

```sql
DELETE FROM sys_notify_template WHERE template_code IN ('ADDR_BOOK_STALE_REMIND','PRODUCT_STALE_REMIND');
DELETE FROM sys_job_conf WHERE job_key IN
  ('ADDR_BOOK_REMIND','PRODUCT_REMIND','ADDR_BOOK_FULL_SYNC','PRODUCT_RESPONSIBLE_CONSISTENCY_CHECK');
DELETE FROM PT_RESOURCE WHERE module='portal-content-center';
TRUNCATE TABLE addrbook_employee;
DELETE FROM portal_shortcut WHERE shortcut_type='SYSTEM' AND created_by='SYSTEM';
DELETE FROM portal_nav WHERE created_by='SYSTEM';
-- 注意：字典数据由 governance 管理，portal 不回滚
```

## 12. 共享基线脚本指引（2026-04-10 新增）

本模块的部分种子数据并非完全由本文档定义，而是分散在项目级**共享基线脚本**中。以下清单明确指向这些共享脚本中属于 portal-content-center 的段落，避免重复维护和定义漂移。

### 12.1 共享 DDL

| 脚本 | 内容 | 说明 |
|---|---|---|
| `docs/schema/ddl-portal.sql` | 本模块的建表 DDL（portal_nav / portal_shortcut / addrbook_employee / product_info / doc_info） | 首次建库执行 |
| `docs/schema/ddl-auth.sql` | PT_USER / PT_ROLE / PT_RESOURCE 等共享权限表 | 由 auth 模块维护，portal 只读使用 |
| `docs/schema/ddl-governance.sql` | sys_dict / sys_config_kv / file_object / biz_file_rel | 由 governance 模块维护，portal 的文档/产品附件依赖 biz_file_rel |

### 12.2 共享种子数据 `docs/schema/seed-v1.sql`

本模块依赖的段落：

| seed-v1.sql 章节 | 属于本模块的范围 |
|---|---|
| §1.1 YES_NO | 通用字典 |
| §1.29 PRODUCT_CATEGORY | 产品分类字典（portal 产品库使用） |
| §1.30 DOC_CATEGORY | 文档分类字典（portal 文档库使用） |
| §3.2 portal-content-center 资源 | **本模块所有接口的 PT_RESOURCE 登记** |
| §4.1-4.12 PT_ROLE_RESOURCE | 各业务角色对 portal 资源的绑定 |
| §5.1-5.12 PT_ROLE_BIZ_SCOPE | 各角色对 PORTAL_NAV / PORTAL_DOC / PORTAL_PRODUCT 等 BizType 的数据范围 |

**重要**：本文档 §1-11 中的种子数据（预置导航、快捷入口、通讯录同步脚本、字典依赖清单等）是**本模块专属**，与 seed-v1.sql 互补而非重复。

### 12.3 使用方式

**首次建库 (DEV/TEST)**：

```bash
# Step 1: 建表（所有模块 DDL 可并行执行）
mysql -uroot -p onepl < docs/schema/ddl-auth.sql
mysql -uroot -p onepl < docs/schema/ddl-governance.sql
mysql -uroot -p onepl < docs/schema/ddl-portal.sql
# ... 其他模块

# Step 2: 写入共享种子（字典、角色、资源、绑定）
mysql -uroot -p onepl < docs/schema/seed-v1.sql

# Step 3: 补充本模块专属种子（本文档 §1-§9）
# 按本文档各小节顺序执行 SQL
```

**升级现有库**：
- **不要**直接重跑 `seed-v1.sql`，会覆盖运行时已修改的数据
- 在 `docs/superpowers/sql/YYYY-MM-DD-portal-align.sql` 创建带日期前缀的增量对齐脚本
- 执行前备份：`docs/superpowers/sql/backup/YYYY-MM-DD-portal-before-align.sql`
