# 门户与内容中心 — 并发与事务策略

## 1. 总原则

读操作不以门户事务包裹跨模块调用；写操作由 Service 明确事务边界，并在写入前再次校验当前用户、实体归属和状态。事务只保护本模块数据库操作，不能把 auth、OBS、通知或其他外部 API 的副作用误写成同一事务。

数据库结构和锁行为以当前实体、Mapper/XML 及目标库为准；本文不引入新的锁、缓存或异步任务模型。

## 2. 工作台聚合

`GET /api/portal/workspace` 是只读聚合，不开启业务写事务。`WorkspaceService` 将快捷入口、待办数量、最近待办、未读通知、最近通知和指标卡片并行提交到专用有界执行器，整体设置当前超时。任一分支异常时写入 `aggregateErrors` 并返回 `0`、空列表或已完成的其他分支；整体超时也不阻断默认响应。

待办和指标分别由 `WorkflowQueryAdapter`、`MetricAdapter` 降级；`NotifyApi` Bean 缺失时通知数量和列表为空。适配器不能通过复制流程/绩效表来“补数据”。线程池和超时的具体参数以 `PortalAsyncConfig`、`WorkspaceService` 源码为准，文档不另维护一份数值配置。

## 3. 快捷入口

`PUT /api/portal/shortcuts` 在一个事务内对当前用户的自定义入口执行“删除旧记录—批量插入新记录”。请求身份来自 `CurrentUserApi`，不接收任意员工 ID；系统级入口不会被删除。事务回滚可避免只写入部分新列表，但当前请求 DTO 要求列表非空，不能通过该 REST 报文清空全部入口。

## 4. 导航

导航新增、部分更新和逻辑删除当前由单次 Mapper 写入完成，Service 方法未声明事务；写入后清理导航缓存并写审计，缓存或审计失败只记录告警，不回滚主写入。名称唯一性在服务层以“启用记录”为口径预检，仍应由目标库约束和并发测试确认竞态行为。

批量排序方法声明事务，在同一事务内更新提交的排序项并失效缓存；排序当前没有独立审计调用。排序项的 ID 和非负排序校验由 Controller DTO 完成，服务层不把不存在 ID 自动创建成导航。

## 5. 通讯录与负责人关系

### 5.1 本人维护

`PUT /api/employees/me` 由服务层从当前认证上下文取得操作者，先读当前用户，再校验联系方式和负责人产品。联系方式通过 auth `UserDirectoryApi` 更新，负责人通过门户关系服务整组替换。省略联系方式保留原值，空串清空；省略关系不修改，空列表清空。

该方法声明事务，关系表写入可回滚；auth API 的用户更新是跨模块调用，若其持久化不在同一数据库事务中，事务回滚不能撤销已经成功的外部更新，调用方需要按运行失败日志核对。

### 5.2 关系替换

关系服务先规范化、去重 ID，再计算差异；产品侧和用户侧的替换都在事务中完成，批量插入按实现的批次上限分片，复合键防止重复关系。产品必须存在、启用且满足对应业务条件；不合法输入在写关系前失败。

## 6. 产品资料

- 新增、编辑、逻辑删除均声明事务；编辑和删除通过 `selectByIdForUpdate` 获取未删除记录行锁。
- 新增执行产品代码重复预检、维护机构权限和负责人在职校验，再写产品及关系；编辑是非空字段部分更新，维护机构变化同步 `ownerOrgId`。
- 删除在锁内检查负责人引用，有引用即拒绝；通过 `deleted=1` 软删除，不物理移除产品记录。
- 写入完成后清理支持产品缓存；缓存失效失败不会使主事务失败。产品服务显式做重复预检，是否有数据库唯一约束必须由实际 schema 复核，不能仅依赖预检消除并发竞态。
- 产品列表使用 `BizScopeApi` 构建数据范围；详情、跨模块 Facade 和导出查询各有实现路径，不能从分页查询的范围推断所有路径自动具备同样过滤。

产品导出同步生成 XLSX；当命中行数超过 ExportService 的服务能力时直接返回业务错误，不创建不存在的异步任务或导出状态记录。导出完成后写产品导出审计。

## 7. 文档、公告和担保

### 7.1 文档

文档新增声明事务，文档更新和逻辑删除当前 Service 方法未声明事务，由单次 Mapper 更新完成。删除只把 `status` 置为 `DISABLED`，不删除治理文件对象。文档对象下载 URL 的获取是外部 `FileApi` 调用，不与本地状态更新组成分布式事务。

### 7.2 公告

公告新增、逻辑删除和置顶切换声明事务；公开查询和管理查询为只读。附件上传先经 `FileApi` 写 OBS，再插入 `ANNOUNCEMENT_FILE` 关联，方法未声明事务，OBS 对象和本地关联可能出现短暂不一致，异常处理需依赖运行日志与治理侧对象核对。公告当前没有门户 `AuditApi` 调用。

### 7.3 担保

担保新增、编辑和批量删除声明事务。新增在同一事务内检查客户重复、查询合同并选择“合同批量映射”或“手工单条落库”；编辑按主键更新；批量删除是物理删除。合同和同步来源表只读查询，不因门户删除而回写。

担保导出读取筛选结果后同步生成 XLSX，超过服务能力直接拒绝；当前导出服务没有 `AuditApi` 调用。金额转换（万元输入、元存储、万元展示）属于业务转换，不是并发控制。

`GuaranteeSyncService.processing` 声明事务，先判断前一日来源数据，再执行担保更新、担保插入、合同归集和更新时间刷新。Quartz Job 顶层捕获异常并记录，任务调度和集群锁由治理中心管理。

## 8. 缓存一致性

当前缓存项由 `PortalCacheConfig` 定义：导航启用列表和支持中场支持产品列表。服务采用 Cache-Aside：读命中直接返回，未命中查询数据库后回填；相关写操作完成后尝试失效键。

实际读写由治理 `MemoryCacheService`（Caffeine）执行，`PortalCacheConfig` 传入的 TTL 只是调用参数，是否按条目生效以治理实现为准；当前实现不是跨实例共享缓存。缓存读写或失效异常必须记录并回退数据库/主流程，不把缓存作为业务事实来源。

## 9. 不采用的并发模型

当前没有门户级幂等 token、分布式锁、异步导出任务、60 天提醒扫描或读写分离实现。若后续新增，必须先定义持久化状态、重试/补偿、跨实例一致性和审计，再同步本文件及相关契约；不能把规划写成现行行为。
