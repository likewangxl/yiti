# 门户与内容中心 — 审计要求

## 1. 适用范围

审计写入统一调用治理中心 `AuditApi.log(AuditLogCmd)`，不在门户自建平行审计表或日志格式。业务操作的审计事实以 Service 当前调用为准；本文同时标出尚未接入审计的高风险路径，避免把要求误写成已完成能力。

`AuditLogCmd` 的核心上下文包括 `traceId`、操作人工号、`bizType`、`bizAction`、资源 URL、HTTP 方法、脱敏后的请求摘要和响应状态；需要变更前后快照时使用治理命令提供的结构化字段。审计查询由治理模块统一提供。

## 2. 当前显式审计

| 业务操作 | 当前 Service 动作 | 资源 |
| --- | --- | --- |
| 导航新增/编辑/删除 | `NAV/CREATE`、`NAV/EDIT`、`NAV/DELETE` | `/api/admin/nav` 及其 ID 路径 |
| 产品新增/编辑/删除 | `PRODUCT/CREATE`、`PRODUCT/EDIT`、`PRODUCT/DELETE` | `/api/products` 及其 ID 路径 |
| 产品导出 | `PRODUCT/EXPORT` | `/api/products/export` |
| 文档新增/编辑/删除 | `DOC/CREATE`、`DOC/EDIT`、`DOC/DELETE` | `/api/admin/documents` 及其 ID 路径 |
| 本人通讯录维护 | `EMPLOYEE/EDIT_SELF` | `/api/employees/me` |

产品负责人关系变更随产品编辑动作进入当前审计调用，但现实现只记录产品和请求摘要，并未保证提供关系集合的完整前后快照。导航排序、快捷入口保存、公告全部管理操作、担保新增/编辑/删除/导出当前没有门户 `AuditApi` 调用。

## 3. 高风险操作要求与现状

导出、删除和会改变对外可见内容的操作必须同时具备独立资源授权、服务层权限校验和可追溯审计。当前产品导出以及产品/文档/导航删除已具备显式审计调用；担保批量删除、担保导出和公告删除仍存在审计缺口，不能在接口或交付说明中宣称“已审计”。修复这些缺口时需同步 `03`、资源登记和测试，但不在本文伪造日志结果。

审计写入失败在当前产品、文档、导航和通讯录 Service 中由 `safeAuditLog` 捕获并记录告警，不阻断主业务写入；因此“调用过 AuditApi”不等于“审计一定落库”。高风险场景若改为 fail-close，必须同时定义事务和用户可见错误语义。

## 4. 脱敏

- 跨模块 `AddressBookApi` 返回的手机号由 Facade 脱敏；产品导出中的负责人手机号也使用脱敏值。
- REST 本人维护因编辑回填需要返回原联系方式，但不得把原值放入审计请求摘要、普通业务日志、异常堆栈或 URL。
- 审计及日志不得记录密码、Session/Token、完整证件号、原始手机号、敏感凭据；邮箱和文件对象信息只在业务确需追踪时保留最小摘要。
- 审计 `requestParams` 只保存识别业务所需的 ID、动作和筛选摘要，避免拼接完整请求体。产品/文档现有实现会记录部分名称和文件对象 ID，后续扩展必须继续遵守脱敏规则。

## 5. 业务与事务关系

审计调用发生在业务 Service 写入路径中，治理 `AuditApi` 按其公开契约同步写入并使用独立事务。门户的 `safeAuditLog` 会吞掉审计异常，因此审计缺失不会自动回滚业务事务；附件 OBS 写入、公告关联、担保来源同步等外部副作用也不能通过审计日志假设获得原子性。

## 6. 维护要求

新增或修改 Controller、业务动作、资源 URL、数据范围或敏感字段时，应同步本文件、`03-接口设计与报文.md` 和 `09-依赖契约摘要.md`，并核对治理 `AuditLogCmd`、`PT_RESOURCE` 及相关测试。本文不维护日志行数、保留期限、告警阈值或完整数据库列清单；这些属于治理配置和目标环境事实。
