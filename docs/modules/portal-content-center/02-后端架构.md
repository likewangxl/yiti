# 门户与内容中心 — 后端架构

## 1. 边界

portal-content-center 负责工作台聚合、快捷入口、导航、通讯录视图、产品资料、文档、担保信息和公告。客户、业务申请、绩效、报表等核心域的状态不在本模块复制或维护。

本模块直接依赖 `common-*`、`auth-permission-center`、`system-governance-center` 和 `workflow-center`。不直接依赖 customer、business、performance、report 等核心域；需要绩效卡片时由 bootstrap 负责桥接。实际依赖以当前根 POM 和模块 POM 为准，本文不复制版本和完整依赖清单。

## 2. 组件关系

```text
REST Controller ──> Service ──> Mapper ──> portal 自有表
       │               │
       │               ├──> auth 公开 API（用户、组织、范围、当前用户）
       │               ├──> governance 公开 API（文件、通知、字典、审计）
       │               └──> adapter ──> workflow 查询 API / 指标桥接
       │
Facade ──> portal/api 与 api/dto（跨模块只读契约）
```

### 2.1 Controller

Controller 只负责 HTTP 映射、参数校验、响应包装和 DTO 转换。业务权限由 `@BizAuth` 声明，工作台和快捷入口的登录态访问是经过架构测试认可的显式例外。Controller 不直接调用其他模块的 mapper、entity 或内部 service。

### 2.2 Service

Service 负责状态变化、数据范围、实体归属复核、事务边界、关系表整组替换、缓存失效和审计调用。所有写操作的最终权限判断必须在 Service 层完成；前端隐藏按钮不是权限边界。

### 2.3 Facade 与公开 API

`portal/api` 只暴露跨模块需要的只读能力及稳定 DTO。Facade 负责把门户实体转换成 API DTO，单项缺失用 `Optional.empty()`，批量缺失不填充；不把内部分页、Mapper 或控制器 DTO 暴露给调用方。

### 2.4 Adapter

工作台通过适配器隔离上游差异：

个人工作台指标经 `adapter.MetricApi.getPersonalCoreMetricCards(empId)` 读取，由 `PerformanceMetricApiBridge` 投影到门户 DTO，并标记 `sourceType=EMP_LATEST_IMPORT`；兼容性的 `getUserMetricCards` 不参与个人核心指标查询。

- `WorkflowQueryAdapter` 只调用 workflow 的 `WorkflowQueryApi`，将任务映射为门户待办；上游 Bean 缺失或异常时返回数量 `0`/空列表并记录日志；
- portal 自己定义 `adapter.MetricApi`，`bootstrap` 的 `PerformanceMetricApiBridge` 调用 performance 公开 `MetricApi.getPersonalCoreMetricCards(empId)` 并完成 DTO 投影；兼容性的 `getUserMetricCards` 保持独立，桥接缺失或异常时指标卡片为空；
- 适配器只提供当前契约要求的空值降级，不在门户表中复制流程或绩效状态。

## 3. 稳定设计决策

### 3.1 用户和机构数据

员工主数据通过 auth 的 `UserDirectoryApi` 获取，来源是 `PT_USER` 与 `EXT_USER_ORG`/`EXT_ORG_INFO`；门户不再依赖旧通讯录镜像表。负责人关系是门户自己的用户—产品关系表，避免把反向 JSON 写回用户主表。

### 3.2 文件、通知和字典

文件上传、下载和对象关联统一经治理 `FileApi`，实际对象存储为华为云 OBS；portal 不注入对象存储客户端。工作台通知通过可选的 `NotifyApi`，缺失时按工作台契约降级；字典展示通过 `DictApi`。审计通过 `AuditApi`，审计失败的降级边界由各 Service 的 `safeAuditLog` 明确处理。

### 3.3 数据范围

需要范围控制的查询使用 auth 的 `BizScopeApi` 构建上下文，并由门户 Mapper 应用过滤。产品分页查询当前使用产品数据范围；其他内容是否全局可见以各 REST/API 契约和 Service 查询为准。任何跨模块查询都不能通过直接 JOIN 对方私有表实现。

### 3.4 缓存

门户缓存键和 TTL 常量集中在 `PortalCacheConfig`，当前导航和支持产品服务使用治理的 `MemoryCacheService`（Caffeine）执行 Cache-Aside；写入后尝试失效对应键，失效失败不阻断主写入。这里没有 Redis 契约，也不应把缓存常量或历史注释扩展成 Redis 依赖。缓存的实际过期和多实例一致性以 `MemoryCacheService` 实现为准。

### 3.5 事务和文件外部副作用

产品、担保、快捷入口关系替换、导航排序以及公告的指定写操作在 Service 层划定事务；文档新增有事务，文档更新/删除当前由 Mapper 写入但未在 Service 方法上声明事务。公告附件的 OBS 上传和本地附件关联不在同一数据库事务中，必须把失败补偿作为运维关注点，不能宣称原子一致。

### 3.6 存量边界例外

`WorkflowApprovalNotificationListener` 仍存在直接引用 workflow mapper/entity/内部事件和治理内部通知 Service 的存量实现。这是待治理的技术债，不是推荐架构；新增代码必须使用 workflow 的公开事件/查询 API 和治理 `NotifyApi`，不得复制该模式。

## 4. 运行组件

- 工作台使用专用有界异步执行器并采用调用线程拒绝策略；整体聚合超时和分支降级由 `WorkspaceService` 实现，具体参数以 `PortalAsyncConfig` 源码为准。
- Quartz 由治理中心统一管理。担保同步 Job 只负责调用门户 Service，任务计划来自治理的 `sys_job_conf`，不在门户文档中维护一份平行 cron。
- MyBatis-Plus Mapper 负责本模块表的查询和写入；跨表聚合或批量 SQL 仅保留在 Mapper XML，不能被包装成跨模块私有契约。

## 5. 维护原则

公开 API、Controller、DTO、权限标识或错误码变更时，同步 `03-接口设计与报文.md`、`04-对外API契约.md`、`07-审计要求.md` 和 `09-依赖契约摘要.md`。数据模型仅在 `05-表结构DDL.md` 记录语义，不新增 DDL；事务、锁和幂等语义集中在 `06-并发与事务策略.md`。历史日期、版本流水和未实现接口不作为当前架构依据。
