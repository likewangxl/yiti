# 门户与内容中心 — REST 接口与报文

## 1. 约定

本文以当前 Controller、DTO 和 Service 为准，保留可联调的 REST 路径、权限、请求和状态语义。模块统一响应类型是 `ResponseWrapper<T>`，成功码为 `0`；链路标识由公共 Web/Trace 基础设施填充。

标准分页接口使用 `ResponseWrapper.page(PageResult<T>)`，分页字段为 `pageNo`、`pageSize`、`total`、`records`。公告接口当前直接把 MyBatis-Plus `IPage<AnnouncementRespDTO>` 放在 `ResponseWrapper.data`，字段为 `current`、`size`、`total`、`records`，不要按标准 `page` 字段读取。导出和公告附件下载直接写 XLSX/二进制响应，不包装 `ResponseWrapper`。

除工作台和快捷入口的登录态例外外，权限以 Controller 上的 `@BizAuth` 和 `PT_RESOURCE` 的 URL+HTTP 方法匹配为准；资源标识见 `08-初始化数据清单.md`。鉴权通过不等于跳过 Service 数据范围和实体权限校验。

## 2. 工作台与快捷入口

### A.1 `GET /api/portal/workspace`

- 权限：登录态例外，Controller 不标注 `@BizAuth`；不代表匿名可访问。
- 参数：无。
- 返回：`ResponseWrapper<WorkspaceDTO>`。

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `todoCount` | `int` | 当前用户待办数量 |
| `unreadNotificationCount` | `int` | 当前用户未读通知数量 |
| `recentTodos` | `List<TodoItemDTO>` | 最近待办；上游不可用时为空 |
| `recentNotifications` | `List<NotificationItemDTO>` | 最近通知；NotifyApi 不可用时为空 |
| `metricCards` | `List<PortalMetricCard>` | 绩效桥接卡片；桥接不可用时为空 |
| `shortcuts` | `List<ShortcutDTO>` | 系统级和当前用户自定义入口 |
| `aggregateErrors` | `Map<String,String>` | 分支异常信息，正常时为空对象 |

`TodoItemDTO` 包含 `taskId`、`processInstanceId`、`processName`、`taskTitle`、`initiatorName`、`initiatedTime`、`lightStatus`、`overdueInfo`、`bizDetailUrl`。当前 workflow 适配器对未提供的超时信息和业务链接返回 `null`。

`NotificationItemDTO` 包含 `notificationId`、`title`、`summary`、`sentTime`、`readStatus`（`READ`/`UNREAD`）、`bizType`、`bizId`、`bizDetailUrl`。

`PortalMetricCard` 包含 `metricCode`、`metricName`、字符串形式的 `currentValue`/`targetValue`、`completionRate`、`trend`（`UP`/`DOWN`/`FLAT`）、`changeRate`、`dataTime` 和 `unit`。

聚合分支并行执行，整体超时或单分支异常时返回已完成结果及默认空值，并把可诊断信息放入 `aggregateErrors`；不存在固定卡片数量或固定业务域列表的契约。

### A.2 `GET /api/portal/shortcuts`

- 权限：登录态例外，Controller 不标注 `@BizAuth`。
- 参数：可选 query `shortcutType`。
- 返回：`ResponseWrapper<List<ShortcutDTO>>`。

| `shortcutType` | 结果 |
| --- | --- |
| 未传、空串、`ALL` | `SYSTEM` + 当前用户 `CUSTOM` |
| `SYSTEM` | 系统级入口 |
| `CUSTOM` | 当前用户自定义入口 |
| 其他值 | 空列表 |

`ShortcutDTO` 字段为 `id`（字符串 ID）、`shortcutName`、`shortcutUrl`、`shortcutIcon`、`shortcutType`、`targetType`、`sortOrder`。

### A.3 `PUT /api/portal/shortcuts`

- 权限：登录态例外；目标用户由当前认证上下文确定。
- 请求：`ShortcutSaveReqDTO`，顶层 `shortcuts` 必填且非空；每项字段如下。

| 字段 | 类型 | 校验/语义 |
| --- | --- | --- |
| `shortcutName` | `String` | 必填，最长 100 |
| `shortcutUrl` | `String` | 必填，最长 500 |
| `shortcutIcon` | `String` | 可选，最长 100 |
| `targetType` | `String` | 必填，`INTERNAL`/`EXTERNAL` |
| `sortOrder` | `Integer` | 必填，非负 |

返回 `ResponseWrapper<Void>`。服务层在事务中删除当前用户旧 `CUSTOM` 记录并批量插入新记录，`SYSTEM` 记录不受影响；请求 DTO 当前不允许提交空列表。

## 3. 网址导航

### B.1 `GET /api/nav`

- 权限：`@BizAuth(NAV, READ)`。
- 参数：`category` 可选，`status` 可选。
- 返回：`ResponseWrapper<NavGroupRespDTO>`，结构为 `groups[]`，每项含 `category` 和 `navs[]`。

状态选择规则：未传状态时只查 `ACTIVE`；传分类时按分类查启用导航；`status=ALL` 查全部状态；其他状态值精确过滤。导航按 `sortOrder` 升序分组返回。`NavDTO` 字段为字符串 `id`、`navName`、`navUrl`、`navIcon`、`navCategory`、整数 `sortOrder`、`status`（`ACTIVE`/`DISABLED`）。

### B.2 `POST /api/admin/nav`

- 权限：`@BizAuth(NAV, WRITE)`。
- 请求 `NavCreateReqDTO`：`navName` 必填且最长 100；`navUrl` 必填、最长 500 且匹配 `^https?://.+`；`navIcon` 最长 100；`navCategory` 最长 50；`sortOrder` 可选且非负。
- 返回：`ResponseWrapper<String>`，新导航 ID。
- 规则：同一分类的启用名称不得重复，状态初始为 `ACTIVE`；写入导航审计。

### B.3 `PUT /api/admin/nav/{id}`

- 权限：`@BizAuth(NAV, WRITE)`。
- 路径：`id` 为字符串 ID。
- 请求 `NavUpdateReqDTO`：`navName`、`navUrl`、`navIcon`、`navCategory`、`sortOrder`、`status` 均为可选；长度/URL/非负排序/`ACTIVE|DISABLED` 校验与 DTO 一致。
- 返回：`ResponseWrapper<Void>`。
- 规则：非空字段部分更新；名称或分类变化时再次校验启用名称唯一；写入编辑审计。

### B.4 `DELETE /api/admin/nav/{id}`

- 权限：`@BizAuth(NAV, WRITE)`。
- 返回：`ResponseWrapper<Void>`。
- 规则：将现有记录状态改为 `DISABLED`，不物理删除；写入删除审计。不存在返回 `PORTAL-40001`。

### B.5 `PUT /api/admin/nav/sort`

- 权限：`@BizAuth(NAV, WRITE)`。
- 请求：`List<NavSortItemReqDTO>`，每项 `id` 必填字符串、`sortOrder` 必填且非负。
- 返回：`ResponseWrapper<Void>`。
- 规则：在单事务中批量更新排序并失效导航缓存；当前无单独审计调用。

## 4. 通讯录

### C.1 `GET /api/employees`

- 权限：`@BizAuth(ADDRBOOK, LIST)`。
- 查询参数：`keyword`、`orgCode`、`position`、`status`、`pageNo`、`pageSize` 均来自 `EmployeeQueryReqDTO`，默认页码/页大小为 1/20，服务端对页大小设上限。
- 返回：`ResponseWrapper.page(PageResult<EmployeeDetailDTO>)`。

数据由 auth `UserDirectoryApi.pageActiveUsers(keyword, orgCode, pageNo, pageSize)` 提供，关键字口径由 auth 目录定义。`position`、`status` 在当前门户 Service 中保留作兼容字段，不传给 auth 查询，实际只查在职用户。响应包含员工 ID/姓名、联系方式、机构、岗位、状态、更新时间和 `responsibleProductIds`/`responsibleProducts`；auth 无岗位说明、自我描述来源时相应字段为空。REST 列表联系方式按当前 Controller 口径返回，跨模块 Facade 另行脱敏。

### C.2 `GET /api/employees/{empId}`

- 权限：`@BizAuth(ADDRBOOK, READ)`。
- 路径：`empId` 为 `PT_USER.USER_ID` 字符串。
- 返回：`ResponseWrapper<EmployeeDetailDTO>`，在职用户及其负责人产品简要信息。
- 不存在：`PORTAL-40002`。

### C.3 `PUT /api/employees/me`

- 权限：`@BizAuth(ADDRBOOK, WRITE)`；不接受目标用户 ID。
- 请求 `EmployeeSelfUpdateReqDTO`：

| 字段 | 类型 | 校验/语义 |
| --- | --- | --- |
| `mobile` | `String` | 可选，最长 20，空串清空；省略保留当前值 |
| `email` | `String` | 可选，`@Email`，最长 100，空串清空；省略保留 |
| `responsibleProductIds` | `List<String>` | 可选；省略不修改，空列表清空，服务层规范化去重 |

返回 `ResponseWrapper<Void>`。服务层从当前用户上下文取操作者，校验产品存在、`ACTIVE` 且支持中场支持，再调用 auth 更新联系方式并替换关系表。姓名、机构、岗位、状态和任意其他员工资料不可写；写入本人维护审计。

### C.4 `GET /api/employees/search`

- 权限：`@BizAuth(ADDRBOOK, READ)`。
- 参数：必填 `keyword`；可选 `limit`，默认 20，Controller/Service 将返回规模限制在服务能力内。
- 返回：`ResponseWrapper<List<EmployeeSearchDTO>>`，每项含 `empId`、`empName`、`orgCode`、`orgName`、`position`。当前 Controller 不接收 `orgCode` 等额外筛选参数，结果来自 auth 在职搜索。

## 5. 产品资料库

### D.1 `GET /api/products`

- 权限：`@BizAuth(PRODUCT, LIST)`。
- 参数：`keyword`、`category`、`productDeptOrgCode`、`supportForSupportRequest`、`status`、`pageNo`、`pageSize`；页码默认 1、页大小默认 20，DTO 限制页大小上限。
- 返回：`ResponseWrapper.page(PageResult<ProductDTO>)`。
- 规则：关键字匹配产品代码或名称；查询使用 `BizScopeApi` 构建产品数据范围，并排除逻辑删除记录。状态和其他过滤以当前 DTO/Mapper 为准。

`ProductDTO` 字段为 `id`、`productCode`、`productName`、`productCategory`、`productCategoryDesc`、`description`、`supportForSupportRequest`、`productDeptOrgCode`、`productDeptOrgName`、`fileObjectId`、`fileName`、`responsibleEmpIds`、`responsibleEmpNames`、`status`、`createdTime`、`updatedTime`。展示名称、机构名、文件名和负责人姓名按 REST 装配能力提供，跨模块 Facade 可能只填基础字段。

### D.2 `GET /api/products/{id}`

- 权限：`@BizAuth(PRODUCT, READ)`。
- 路径：`id` 为匹配 `[A-Za-z0-9_-]{1,64}` 的字符串 ID。
- 返回：`ResponseWrapper<ProductDTO>`，包含负责人 ID 和可解析的负责人姓名。
- 不存在：`PORTAL-40003`。

### D.3 `GET /api/products/support-available`

- 权限：`@BizAuth(PRODUCT, READ)`。
- 参数：无。
- 返回：`ResponseWrapper<List<ProductSimpleDTO>>`；每项为 `id`、`productCode`、`productName`、`productCategory`、`productDeptOrgCode`。
- 规则：只返回 `status=ACTIVE`、`support_for_support_request=true` 且未逻辑删除的产品，使用门户支持产品缓存。

### D.4 `POST /api/products`

- 权限：`@BizAuth(PRODUCT, WRITE)`。
- 请求：`ProductCreateReqDTO` 的 `productCode`、`productName`、`productCategory`、`description`、`supportForSupportRequest`、`productDeptOrgCode`、`fileObjectId`、`responsibleEmpIds`。代码/名称/类别/描述/机构/文件的长度和必填规则以当前 DTO 注解为准，支持标记必填，负责人列表受 DTO 限制。
- 返回：`ResponseWrapper<String>`，产品字符串 ID。
- 规则：非管理员只能创建本机构维护的产品；代码重复、负责人非在职均拒绝；初始 `ACTIVE`、`deleted=0`，负责人关系单独写入并审计。

### D.5 `PUT /api/products/{id}`

- 权限：`@BizAuth(PRODUCT, WRITE)`。
- 路径：同 D.2。
- 请求：`ProductUpdateReqDTO` 所有字段可选：`productName`、`productCategory`、`productDeptOrgCode`、`description`、`supportForSupportRequest`、`fileObjectId`、`responsibleEmpIds`、`status`（`ACTIVE|DISABLED`）。
- 返回：`ResponseWrapper<Void>`。
- 规则：行锁内部分更新；维护机构可修改且同步 `ownerOrgId`；负责人列表传入时整组替换；完成后失效支持产品缓存并审计。

### D.6 `DELETE /api/products/{id}`

- 权限：`@BizAuth(PRODUCT, DELETE)`。
- 返回：`ResponseWrapper<Void>`。
- 规则：服务层加行锁并复核机构权限；仍有负责人关系时返回 `PORTAL-40905`，否则设置 `deleted=1`，不物理删除；写删除审计。产品不存在为 `PORTAL-40003`。

### D.7 `GET /api/products/export`

- 权限：`@BizAuth(PRODUCT, EXPORT)`，独立高危资源。
- 参数：可选 `keyword`、`category`、`status`；状态缺省按服务当前默认值处理。
- 返回：XLSX 二进制，文件名为 `product_export_{yyyyMMddHHmmss}.xlsx`。
- 规则：同步导出，行数超过 ExportService 当前能力返回 `PORTAL-42207`；列包括产品编码、名称、类别、说明、是否支持中场支持、维护组织、负责人姓名/脱敏手机号、状态和更新时间；完成后写 `PRODUCT/EXPORT` 审计。

## 7. 公告

公告端点统一复用 `BizType.SYS_CONFIG`，按 Controller 当前动作标注权限。公告分页直接返回 `IPage`，不是标准 `PageResult`。

### J.1 `GET /api/portal/announcements`

`SYS_CONFIG/LIST`。参数 `pageNo` 默认 1、`pageSize` 默认 20、可选 `keyword`（标题模糊）。返回 `ResponseWrapper<IPage<AnnouncementRespDTO>>`，只查 `is_deleted=0`，按置顶和发布日期倒序；列表 `files` 不回填。

### J.2 `GET /api/portal/announcements/recent`

`SYS_CONFIG/LIST`。可选 `limit`，默认 10；返回 `ResponseWrapper<List<AnnouncementRespDTO>>`，查询未删除公告并按置顶/发布日期排序后取限制数量。

### J.3 `GET /api/portal/announcements/{id}`

`SYS_CONFIG/READ`。路径 `id` 为字符串 UUID，返回 `ResponseWrapper<AnnouncementRespDTO>`，包含附件数组。响应字段为 `id`、`title`、`content`、`publisherId`、`publisherName`、`publishDate`、`isPinned`、`status`（`已发布`/`已删除`）和 `files`；附件字段为 `id`、`fileName`、`fileSize`、`uploadTime`。公告不存在返回当前实现的 `PORTAL-40401`。

### J.4 `GET /api/portal/announcements/files/{fileId}/download`

`SYS_CONFIG/READ`。路径 `fileId` 为字符串；直接返回 `application/octet-stream`，通过 `FileApi.getFileContent` 读取 OBS 字节，设置 UTF-8 文件名和长度。文件不存在当前复用 `PORTAL-40401`。

### J.5 `GET /api/admin/announcements`

`SYS_CONFIG/LIST`。参数同 J.1；返回 `ResponseWrapper<IPage<AnnouncementRespDTO>>`，不过滤 `is_deleted`，用于管理端查看全部状态。

### J.6 `POST /api/admin/announcements`

`SYS_CONFIG/WRITE`。请求 `AnnouncementCreateReqDTO`：`title` 必填最长 200，`content` 必填（当前无长度注解）。返回新公告字符串 ID；发布人和时间来自当前认证上下文/服务器时间。

### J.7 `POST /api/admin/announcements/{announcementId}/files`

`SYS_CONFIG/WRITE`。请求为 `multipart/form-data`，字段名 `file`；返回 `ResponseWrapper<AnnouncementFileDTO>`。文件先经 `FileApi.upload` 写 OBS，OBS 文件 ID 复用写入 `ANNOUNCEMENT_FILE.filePath`，响应返回文件名、大小和上传时间；IOException 当前返回硬编码 `PORTAL-50001`。

### J.8 `PUT /api/admin/announcements/{id}/toggle-pin`

`SYS_CONFIG/WRITE`。无请求体，返回 `ResponseWrapper<Void>`；读取 `isPinned` 后取反保存。公告不存在复用 `PORTAL-40401`。

### J.9 `DELETE /api/admin/announcements/{id}`

`SYS_CONFIG/DELETE`。无请求体，返回 `ResponseWrapper<Void>`；将 `is_deleted` 置为 1，不删除附件记录或 OBS 文件。不存在或已删除复用 `PORTAL-40401`；当前公告 Service 没有 `AuditApi` 调用。

## 8. 担保信息

担保端点复用 `BizType.PRODUCT`，主键为正则 `[0-9]{1,19}` 的 `Long`。

### K.1 `GET /api/guarantee`

`PRODUCT/LIST`。参数 `clientName` 可选模糊匹配，`pageNo` 默认 1，`pageSize` 默认 20，服务层归一化到合法分页范围。返回标准 `ResponseWrapper.page(PageResult<GuaranteeDTO>)`，按 `id` 倒序。

`GuaranteeDTO` 字段为 `id`、`clientNo`、`clientName`、`notionalAmount`、`occupyNotionalAmount`、`usableNominalSum`、`lastExpire`、`userName`、`userDisplayName`、`createTime`、`updateTime`。金额展示为万元字符串，`userDisplayName` 通过 auth `UserApi` 批量解析，查无回退工号。

### K.2 `GET /api/guarantee/{id}`

`PRODUCT/READ`。返回 `ResponseWrapper<GuaranteeDTO>`；不存在为 `PORTAL-40006`。

### K.3 `POST /api/guarantee`

`PRODUCT/WRITE`。请求 `GuaranteeSaveReqDTO`：`clientNo` 可选最长 50，`clientName` 必填最长 100，三个金额字段、`lastExpire`、`userName` 为可选字符串，长度以 DTO 注解为准。返回 `GuaranteeCreateResultDTO`：`source` 为 `CONTRACT` 或 `MANUAL`、`count` 为实际落库条数、`id` 仅手工单条来源有值。

服务层先按客户号+名称查重；命中 `ccms_business_contract` 时批量映射合同记录并忽略手工金额，未命中时落库单条手工数据。手工金额按万元接收、清洗 `¥`/`,` 后乘 10000 按元保存；合同金额按元原值映射。重复客户为 `PORTAL-40906`。

### K.4 `PUT /api/guarantee/{id}`

`PRODUCT/WRITE`。路径和请求体同 K.3，返回 `ResponseWrapper<Void>`；金额转换同新增，更新 `updateTime`；不存在为 `PORTAL-40006`。

### K.5 `POST /api/guarantee/batch-delete`

`PRODUCT/DELETE`。请求 `{ "ids": [Long, ...] }`，`ids` 必填且非空；返回 `ResponseWrapper<Integer>` 实际删除行数。当前使用 `deleteBatchIds` 物理删除，资源方法也是 POST。

### K.6 `GET /api/guarantee/export`

`PRODUCT/EXPORT`。可选 `clientName`；可选 `ids`，非空时仅导出选中记录并忽略名称过滤。返回同步 XLSX `guarantee_export_{yyyyMMddHHmmss}.xlsx`；超过 ExportService 当前能力返回 `PORTAL-42207`。当前导出行按既有表字符串原值输出，金额未执行列表展示的元→万元转换；担保导出当前没有门户 `AuditApi` 调用。
