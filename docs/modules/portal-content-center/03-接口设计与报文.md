`UserDirectoryApi` 提供，portal 仅维护 `PORTAL_USER_PRODUCT_REL`。保留查询路径兼容，

## 约定说明

### 通用响应格式
所有接口响应统一使用 `ApiResult<T>` 格式：
```json
{
    "code": "0",
    "message": "success",
    "data": {},
    "traceId": "abc123",
    "timestamp": "2026-04-10T10:00:00"
}
```

### 分页响应格式
```json
{
    "code": "0",
    "message": "success",
    "data": {
        "pageNo": 1,
        "pageSize": 20,
        "total": 100,
        "list": []
    }
}
```

### 通用错误响应
```json
{
    "code": "PORTAL-40003",
    "message": "产品不存在",
    "data": null,
    "traceId": "abc123"
}
```

### 权限标识说明
- `@BizAuth(bizType, action)` 表示需要对应的业务权限
- 部分接口天然受登录态约束，无需 `@BizAuth`

## C. 通讯录接口

### C.1 GET /api/employees — 通讯录列表（分页，查询兼容）

**权限**：`@BizAuth(bizType = "ADDRBOOK", action = "LIST")`

**请求参数**：
| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| keyword | query | String | 否 | 由 auth 目录匹配用户 ID、登录名、姓名、电话或邮箱 |
| orgCode | query | String | 否 | 主机构编码精确过滤 |
| position | query | String | 否 | 兼容参数；无权威岗位来源，不产生有效过滤 |
| status | query | String | 否 | `ACTIVE`（默认）/`RESIGNED`/`ALL`，按 auth 状态映射 |
| pageNo | query | Integer | 否 | 页码，默认 1 |
| pageSize | query | Integer | 否 | 每页数量，默认 20，最大 100 |

**数据来源**：通过 auth `UserDirectoryApi.pageActiveUsers` 查询
`PT_USER + EXT_USER_ORG + EXT_ORG_INFO`；`empId` 固定为 `PT_USER.USER_ID`。

**响应体**：`PageResult<EmployeeDTO>`。`position`、`positionDesc`、`selfDesc` 恒为 `null`；
`responsibleProductIds` 按 `PORTAL_USER_PRODUCT_REL` 派生，手机号按权限脱敏。

### C.2 GET /api/employees/{empId} — 员工详情（查询兼容）

**权限**：`@BizAuth(bizType = "ADDRBOOK", action = "READ")`

**请求路径参数**：
| 参数 | 类型 | 说明 |
|---|---|---|
| empId | String | `PT_USER.USER_ID`，不是旧通讯录表工号字段 |

**响应体**：`EmployeeDetailDTO`（扩展 `EmployeeDTO`）。

**字段口径**：人员和机构来自 auth `UserDirectoryApi.getEmployee`，负责人列表按

**错误码**：`PORTAL-40002`：用户目录中不存在该 `USER_ID`。

### C.3 PUT /api/employees/me — 本人通讯录信息维护

**权限**：`@BizAuth(bizType = "ADDRBOOK", action = "WRITE")`；目标用户从当前认证上下文取得。

**请求体 EmployeeSelfUpdateReqDTO**：
| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| mobile | String | 否 | `@Size(max=20)`，按平台手机号规则校验 | 写入 `PT_USER.MOBILE`，空值表示清空 |
| email | String | 否 | `@Email @Size(max=100)` | 写入 `PT_USER.EMAIL`，空值表示清空 |
| responsibleProductIds | List&lt;String&gt; | 否 | trim、去空、去重；产品必须存在且可用 | 整组替换 `PORTAL_USER_PRODUCT_REL` 关系 |

请求体只允许上述三个字段；姓名、机构、岗位、状态、自我描述和任意目标 `empId` 均不可写。

**事务与副作用**：
1. 从认证上下文取得 `PT_USER.USER_ID`，不得信任客户端目标 ID。
2. 校验产品 ID 后调用 `UserDirectoryApi.updateCurrentUserContact` 更新联系方式，并复用
   `PT_USER.UPDATE_TIME`。
3. 调用 `UserProductRelationService.replaceProductsForUser` 原子替换关系行。
4. 记录联系方式（脱敏）和负责人关系的 before/after 审计差异；不写负责人 JSON，
   不发布旧通讯录/负责人同步事件。

**响应**：`ApiResult<Void>`（或实现约定的更新后 `EmployeeDTO`）。

**错误码**：
- `PORTAL-40002`：当前用户不存在
- `PORTAL-40902`：当前用户非在职状态，禁止维护
- `PORTAL-40904`：负责产品数量超出平台上限
- `PORTAL-42200`：请求字段或产品 ID 校验失败

---

## G. 接口通用约定

### G.1 分页参数约定
- `pageNo`：页码，从 1 开始，默认 1
- `pageSize`：每页数量，默认 20，最大 100
- 超过最大值时返回 `COMMON-42200 参数校验失败`

### G.2 排序参数约定
- 查询接口默认排序：按 `updated_time DESC`
- 支持的自定义排序字段：`created_time`、`updated_time`、`sort_order`
- 不支持任意字段排序（避免 SQL 注入）

### G.3 数据范围约定
所有 `LIST` 和 `READ` 类接口必须应用 `DATA_SCOPE`：
- `ALL`：全部数据
- `ORG`：本组织及下级组织数据
- `SELF`：仅本人数据

### G.4 审计要求
以下接口必须写入审计日志：
- 所有 `WRITE` 类接口（新增/编辑/删除）
- 所有 `EXPORT` 类接口
- `PUT /api/employees/me`（记录联系方式和负责人关系的 before/after 差异）
- 产品编辑（记录 before/after 差异）

### G.5 敏感字段脱敏
以下字段在响应中必须脱敏：
- 手机号：`138****8888`
- 邮箱：`zhang***@example.com`（日志中）
- 非通讯录列表接口中的邮箱不脱敏（已登录员工间可见）

### G.6 响应时间要求
| 接口 | P95 目标 |
|---|---|
| 所有聚合接口 | < 500ms |
| 所有列表查询 | < 300ms |
| 所有详情查询 | < 200ms |
| 所有写接口 | < 500ms |
| 导出接口（V1 同步分支） | < 5s |

## H. 导出接口统一规范（附录）

本章节为本模块所有 `action = EXPORT` 的接口提供 **V1 同步导出** 的规则、文件命名、列定义原则、错误码与审计要求。当前实现尚未落地异步导出任务。

### H.1 V1 导出分支规则

| 命中行数 N | 处理方式 | 响应类型 | 说明 |
|---|---|---|---|
| N ≤ 5000 | 同步流式返回 | `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` | 直接 HTTP 流式写出，前端触发浏览器下载 |
| N > 5000 | 拒绝 | `PORTAL-42207` | V1 不支持异步导出，前端引导用户增加过滤条件 |

**判定流程**：
1. 进入导出接口先执行一次 `SELECT count(*)` 取精确命中行数（走 DATA_SCOPE 过滤）
2. 按行数命中分支
3. 若命中行数大于 5000，直接返回 `PORTAL-42207`

### H.2 文件命名规则

格式：`{module}_{business}_{filterHash}_{yyyyMMddHHmmss}.xlsx`

| 片段 | 说明 | 示例 |
|---|---|---|
| `{module}` | 固定 `portal` | `portal` |
| `{business}` | 业务域名（小写） | `product` |
| `{filterHash}` | 请求参数 JSON 序列化后 MD5 前 8 位 | `a3f9b2c4` |
| `{yyyyMMddHHmmss}` | 导出发起时刻 | `20260410153022` |

完整示例：`portal_product_a3f9b2c4_20260410153022.xlsx`

### H.3 当前限制

- V1 **不提供异步任务 DTO 和状态查询接口**
- 相关能力待后续版本补齐后再回到本章节扩展

### H.4 列定义规范

每个导出接口必须在其接口段落明确以下四项：

1. **列顺序**：从左到右的顺序号
2. **中文列名**：Excel 表头显示文案
3. **字段来源**：对应的 DTO 字段名
4. **格式规则**：类型、字典翻译、脱敏、金额精度、日期格式

### H.5 错误码

| code | HTTP | 说明 | 触发条件 |
|---|---|---|---|
| PORTAL-42207 | 422 | 导出行数超过 V1 同步阈值（5000） | count > 5000 |
| PORTAL-50002 | 500 | 导出文件生成失败 | Excel 生成或 MinIO 上传异常 |

### H.6 审计要求

所有 EXPORT 接口都是高危动作，参考 `docs/common-dev-guide.md §6.1` 高危动作清单，必须记录：
- `operator_emp_id` / `operator_org_id`
- `filter` 参数（完整 JSON）
- `rowCount`（实际命中行数）
- `duration`（执行耗时 ms）
- `result`（`SUCCESS` / `FAILED`）
- `file_object_id`（当前 V1 不涉及，可预留给后续异步方案）

### H.7 本模块导出接口清单

| 接口 | BizType | 同步阈值 | 硬上限 | 具体列定义 |
|---|---|---|---|---|
| D.7 `GET /api/products/export` | PRODUCT | 5000 | 5000 | 见 §H.7.1 |
| K.6 `GET /api/guarantee/export` | PRODUCT（复用） | 5000 | 5000 | 见 §H.7.2 |

### I.7 使用约定

1. 错误码在 `CommonResult.errorCode` 字段返回，`code` 字段为 HTTP 状态码同值数字
2. 业务模块禁止绕过本表自创错误码；需要新码时先在本表登记再使用
3. 错误码的中文消息在 `i18n/messages.properties` 统一维护，支持多语言切换
4. 错误码与 `@BizAuth` 注解、`DataScopeChecker` 的集成参见 `docs/common-dev-guide.md §2`

### I.8 已知偏离：`AnnouncementService` 未走 `PortalErrorCode` 枚举（2026-07-19 新发现，如实记录不改代码）

`AnnouncementService`（对应 §J 全部端点）在 5 处 `throw new BizException(...)` 中直接硬编码字符串错误码，未引用 `PortalErrorCode` 枚举，与本表规则第 2 条冲突：

| 硬编码 code | 消息 | 触发场景 | 问题 |
|---|---|---|---|
| `PORTAL-40401` | 公告不存在 | J.3 详情、J.9 删除、J.8 置顶（记录不存在） | 该码在枚举中已被 `DOC_NOT_FOUND`（"文档不存在"）占用（见 I.3），此处复用同一 code 值但消息不同，前端按 code 分支处理时可能误判为文档域错误 |
| `PORTAL-40401` | 文件不存在 | J.4 下载公告附件（`getFile` 查无记录） | 同上，且与"公告不存在"共用同一 code，两种不同语义无法靠 code 区分，只能靠 message 文本判断 |
| `PORTAL-50001` | 文件保存失败: {IOException信息} | J.7 上传公告附件（`fileApi.upload` 抛 `IOException`） | 未在 `PortalErrorCode` 枚举中登记，前端/测试若按枚举表核对会找不到此码 |

**权限**：`@BizAuth(bizType = BizType.PRODUCT, action = BizAction.LIST)`；PT_RESOURCE：`RES_GUARANTEE_LIST`

**请求参数 GuaranteeQueryReqDTO**：
| 参数 | 位置 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| clientName | query | String | 否 | — | 客户名称模糊匹配 |
| pageNo | query | Integer | 否 | 1 | 页码（`normalizedPageNo()` 兜底最小 1） |
| pageSize | query | Integer | 否 | 20 | 每页条数（`normalizedPageSize()` 兜底 `[1,100]`，超 100 截断为 100，非报错） |

**响应体**：`ResponseWrapper.page(PageResult<GuaranteeDTO>)`（本模块标准分页信封，与 J 组的 `IPage` 不同）

**GuaranteeDTO**：
| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long | 主键 |
| clientNo | String | 客户号（对应物理列 `client_num`，注意列名与属性名不同） |
| clientName | String | 客户名称 |
| notionalAmount | String | 业务额度（万元，由库内「元」÷10000 保留 2 位小数得出） |
| occupyNotionalAmount | String | 剩余额度（万元，同上换算） |
| usableNominalSum | String | 融资额度（万元，同上换算） |
| lastExpire | String | 授信到期日（原值透传，varchar 列） |
| userName | String | 经办人工号（对应物理列 `operator`） |
| userDisplayName | String | 经办人姓名（按 `userName` 批量反查 `UserApi.getUsersByUsernames` 解析；查无/离职/异常均回退展示工号本身，一次 `IN` 查询避免逐行 N+1） |
| createTime | String | 数据变动日期，`yyyy-MM-dd HH:mm:ss` |
| updateTime | String | 变更日期（原值透传，varchar 列，非强制格式） |

**业务逻辑**：按 `clientName` 模糊匹配（`LambdaQueryWrapper.like`），按 `id` 倒序

### K.3 POST /api/guarantee — 新增担保信息

**权限**：`@BizAuth(bizType = BizType.PRODUCT, action = BizAction.WRITE)`；PT_RESOURCE：`RES_GUARANTEE_CREATE`

**请求体 GuaranteeSaveReqDTO**：
| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| clientNo | String | 否 | `@Size(max=50)` | 客户号（前端不再录入，恒为空；服务层仍保留判断逻辑，空值天然不命中） |
| clientName | String | 是 | `@NotBlank` `@Size(max=100)` | 客户名称 |
| notionalAmount | String | 否 | `@Size(max=30)` | 业务额度（万元，前端录入） |
| occupyNotionalAmount | String | 否 | `@Size(max=30)` | 剩余额度（万元） |
| usableNominalSum | String | 否 | `@Size(max=20)` | 融资额度（万元） |
| lastExpire | String | 否 | `@Size(max=30)` | 授信到期日（`yyyy-MM-dd`） |
| userName | String | 否 | `@Size(max=20)` | 经办人工号 |

**响应体 GuaranteeCreateResultDTO**：
| 字段 | 类型 | 说明 |
|---|---|---|
| source | String | `CONTRACT`（合同批量导入）/ `MANUAL`（前端单条录入） |
| count | int | 实际落库条数 |
| id | Long | 新记录主键（仅 `MANUAL` 有值，`CONTRACT` 为 `null`） |

**业务逻辑（按客户号+客户名称驱动的三段式）**：
1. 先查 `zh_guarantee_info` 是否已存在该客户（`clientNo`+`clientName` 同时匹配），存在则拒绝
2. 不存在则反查 `ccms_business_contract`（按 `customer_id`+`customer_name`）：命中 → **忽略前端表单数据**，按合同记录批量映射落库（金额取合同「元」原值不换算，`type` 固定 `'1'`）
3. 合同表无命中 → 落库前端录入的单条数据（金额先清洗 `¥`/`,` 再 ×10000 转「元」存储）

**错误码**：`PORTAL-40906`「客户已存在」（`PortalErrorCode.GUARANTEE_CLIENT_EXISTS`）

### K.4 PUT /api/guarantee/{id} — 编辑担保信息

**权限**：`@BizAuth(bizType = BizType.PRODUCT, action = BizAction.WRITE)`；PT_RESOURCE：`RES_GUARANTEE_UPDATE`

**请求路径参数**：`id`（Long，正则约束 `[0-9]{1,19}`）

**请求体**：同 K.3 `GuaranteeSaveReqDTO`

**响应**：`ResponseWrapper<Void>`

**业务逻辑**：金额字段清洗+换算规则同 K.3 第 3 步；`updateTime` 记录为服务器当前时间（`yyyy-MM-dd HH:mm:ss` 字符串，非新增/编辑共用的合同映射路径）

**错误码**：`PORTAL-40006`「担保信息不存在」

### K.6 GET /api/guarantee/export — 导出担保信息（V1 同步导出）

**权限**：`@BizAuth(bizType = BizType.PRODUCT, action = BizAction.EXPORT)`（高危）；PT_RESOURCE：`RES_GUARANTEE_EXPORT`

**请求参数**：
| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| clientName | query | String | 否 | 客户名称过滤（`ids` 为空时生效） |
| ids | query | List&lt;Long&gt; | 否 | 选中主键列表；非空时**仅导出选中记录**，忽略 `clientName` |

**响应**：`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，Excel 二进制流；文件名 `guarantee_export_{yyyyMMddHHmmss}.xlsx`（经 `URLEncoder` 编码）

**列定义**：见 §H.7.2（8 列，**注意金额三列未做「元→万元」换算**，导出值与 K.1/K.2 展示口径不一致，属已知偏离，见 §H.7.2 详细说明）

**业务逻辑**：先取 `listForExport(clientName, ids)` 全量结果集，命中行数 `> 5000` 直接抛 `PORTAL-42207`（`EXPORT_ROWS_LIMIT_EXCEEDED`）

**审计**：级别 HIGH，同 D.7/H.6 通用要求
