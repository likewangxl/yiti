# 门户与内容中心 — 接口设计与报文

> 文档版本: v1.0
> 对应模块: `portal-content-center`
> 精度: 字段级可执行，可直接用于前后端联调

## 约定说明

### 通用响应格式
所有接口响应统一使用 `ApiResult<T>` 格式：
```json
{
    "code": "0",
    "message": "success",
    "data": {},
    "traceId": "abc123",
    "timestamp": "2026-04-10T10:00:00"
}
```

### 分页响应格式
```json
{
    "code": "0",
    "message": "success",
    "data": {
        "pageNo": 1,
        "pageSize": 20,
        "total": 100,
        "list": []
    }
}
```

### 通用错误响应
```json
{
    "code": "PORTAL-40003",
    "message": "产品不存在",
    "data": null,
    "traceId": "abc123"
}
```

### 权限标识说明
- `@BizAuth(bizType, action)` 表示需要对应的业务权限
- 部分接口天然受登录态约束，无需 `@BizAuth`

### C.3 PUT /api/employees/{empId} — 编辑员工信息

**权限**：`@BizAuth(bizType = "ADDRBOOK", action = "WRITE")`

**请求路径参数**：
| 参数 | 类型 | 说明 |
|---|---|---|
| empId | String | 员工工号 |

**请求体 EmployeeUpdateReqDTO**：
| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| mobile | String | 否 | @Size(max=20) @Pattern(regexp="^1\\d{10}$") | 手机号 |
| email | String | 否 | @Email @Size(max=100) | 邮箱 |
| position | String | 否 | @Size(max=100) | 岗位（从 POSITION 字典） |
| selfDesc | String | 否 | @Size(max=1000) | 自我描述 |
| responsibleProductIds | List&lt;String&gt; | 否 | | 负责产品 ID 列表 |

**后端校验规则**：
- 仅本人（`operatorEmpId == targetEmpId`）或组织负责人可编辑
- `responsibleProductIds` 中的产品必须是 `status = ACTIVE` 且 `support_for_support_request = true` 的产品
- 单员工负责产品数量不得超过 20（`PORTAL-40904`）
- 员工状态必须为 `ACTIVE`，离职员工禁止编辑（`PORTAL-40902`）

**响应**：`ApiResult<Void>`

**错误码**：
- `PORTAL-40002`：通讯录员工不存在
- `PORTAL-40301`：无权编辑本人以外的通讯录
- `PORTAL-40902`：员工已离职
- `PORTAL-40904`：负责产品数量超限

**副作用**：
- 同步更新 `product_info.responsible_emp_ids`
- 发布 `AddrbookUpdatedEvent` 事件
- 发布 `ProductResponsibleUpdatedEvent` 事件（若负责产品有变化）
- 写入审计日志（记录 before/after 差异）

---

### D.3 GET /api/products/support-available — 查询所有支持中场支持的产品

**权限**：`@BizAuth(bizType = "PRODUCT", action = "READ")`

**请求参数**：无（无需分页，全量返回）

**响应体**：`List<ProductBriefDTO>`

**业务用途**：供 `business-application-center` 的"中场支持申请"页面调用

**缓存策略**：缓存 TTL 5 分钟，key = `portal:product:support-available:all`

**业务逻辑**：
```sql
SELECT id, product_code, product_name, product_category, product_dept_org_code
FROM product_info
WHERE support_for_support_request = 1
  AND status = 'ACTIVE'
  AND deleted = 0
ORDER BY product_name
```

## G. 接口通用约定

### G.1 分页参数约定
- `pageNo`：页码，从 1 开始，默认 1
- `pageSize`：每页数量，默认 20，最大 100
- 超过最大值时返回 `COMMON-42200 参数校验失败`

### G.2 排序参数约定
- 查询接口默认排序：按 `updated_time DESC`
- 支持的自定义排序字段：`created_time`、`updated_time`、`sort_order`
- 不支持任意字段排序（避免 SQL 注入）

### G.3 数据范围约定
所有 `LIST` 和 `READ` 类接口必须应用 `DATA_SCOPE`：
- `ALL`：全部数据
- `ORG`：本组织及下级组织数据
- `SELF`：仅本人数据

### G.4 审计要求
以下接口必须写入审计日志：
- 所有 `WRITE` 类接口（新增/编辑/删除）
- 所有 `EXPORT` 类接口
- 通讯录编辑（记录 before/after 差异）
- 产品编辑（记录 before/after 差异）

### G.5 敏感字段脱敏
以下字段在响应中必须脱敏：
- 手机号：`138****8888`
- 邮箱：`zhang***@example.com`（日志中）
- 非通讯录列表接口中的邮箱不脱敏（已登录员工间可见）

### G.6 响应时间要求
| 接口 | P95 目标 |
|---|---|
| 所有聚合接口 | < 500ms |
| 所有列表查询 | < 300ms |
| 所有详情查询 | < 200ms |
| 所有写接口 | < 500ms |
| 导出接口（V1 同步分支） | < 5s |

## H. 导出接口统一规范（附录）

本章节为本模块所有 `action = EXPORT` 的接口提供 **V1 同步导出** 的规则、文件命名、列定义原则、错误码与审计要求。当前实现尚未落地异步导出任务。

### H.1 V1 导出分支规则

| 命中行数 N | 处理方式 | 响应类型 | 说明 |
|---|---|---|---|
| N ≤ 5000 | 同步流式返回 | `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` | 直接 HTTP 流式写出，前端触发浏览器下载 |
| N > 5000 | 拒绝 | `PORTAL-42207` | V1 不支持异步导出，前端引导用户增加过滤条件 |

**判定流程**：
1. 进入导出接口先执行一次 `SELECT count(*)` 取精确命中行数（走 DATA_SCOPE 过滤）
2. 按行数命中分支
3. 若命中行数大于 5000，直接返回 `PORTAL-42207`

### H.2 文件命名规则

格式：`{module}_{business}_{filterHash}_{yyyyMMddHHmmss}.xlsx`

| 片段 | 说明 | 示例 |
|---|---|---|
| `{module}` | 固定 `portal` | `portal` |
| `{business}` | 业务域名（小写） | `product` |
| `{filterHash}` | 请求参数 JSON 序列化后 MD5 前 8 位 | `a3f9b2c4` |
| `{yyyyMMddHHmmss}` | 导出发起时刻 | `20260410153022` |

完整示例：`portal_product_a3f9b2c4_20260410153022.xlsx`

### H.3 当前限制

- V1 **不提供异步任务 DTO 和状态查询接口**
- 相关能力待后续版本补齐后再回到本章节扩展

### H.4 列定义规范

每个导出接口必须在其接口段落明确以下四项：

1. **列顺序**：从左到右的顺序号
2. **中文列名**：Excel 表头显示文案
3. **字段来源**：对应的 DTO 字段名
4. **格式规则**：类型、字典翻译、脱敏、金额精度、日期格式

### H.5 错误码

| code | HTTP | 说明 | 触发条件 |
|---|---|---|---|
| PORTAL-42207 | 422 | 导出行数超过 V1 同步阈值（5000） | count > 5000 |
| PORTAL-50002 | 500 | 导出文件生成失败 | Excel 生成或 MinIO 上传异常 |

### H.6 审计要求

所有 EXPORT 接口都是高危动作，参考 `docs/common-dev-guide.md §6.1` 高危动作清单，必须记录：
- `operator_emp_id` / `operator_org_id`
- `filter` 参数（完整 JSON）
- `rowCount`（实际命中行数）
- `duration`（执行耗时 ms）
- `result`（`SUCCESS` / `FAILED`）
- `file_object_id`（当前 V1 不涉及，可预留给后续异步方案）

### H.7 本模块导出接口清单

| 接口 | BizType | 同步阈值 | 硬上限 | 具体列定义 |
|---|---|---|---|---|
| D.7 `GET /api/products/export` | PRODUCT | 5000 | 5000 | 见 §H.7.1 |

#### H.7.1 产品导出列清单（D.7）

| 列序 | 中文列名 | 字段 | 类型 | 格式规则 | 脱敏 |
|---|---|---|---|---|---|

## I. 错误码完整汇总（2026-04-10 新增）

本附录汇总 portal-content-center 模块的所有错误码，供前端、测试、运维快速查阅。码按 HTTP 段分组。格式：`PORTAL-{HTTP_STATUS}{SEQ}`，前缀固定 `PORTAL`。

| `PORTAL-40003` | 400 | 产品不存在 | D.2-D.6 产品详情/新增/编辑/删除 |

| code | HTTP | 消息 | 典型触发接口 |

| `PORTAL-40304` | 403 | 无权维护文档 | E.3-E.5 文档上传/编辑/删除 |

### I.3 404xx 资源不存在（HTTP 404）

| code | HTTP | 消息 | 典型触发接口 |

| code | HTTP | 消息 | 典型触发接口 |

### I.7 使用约定

1. 错误码在 `CommonResult.errorCode` 字段返回，`code` 字段为 HTTP 状态码同值数字
2. 业务模块禁止绕过本表自创错误码；需要新码时先在本表登记再使用
3. 错误码的中文消息在 `i18n/messages.properties` 统一维护，支持多语言切换
4. 错误码与 `@BizAuth` 注解、`DataScopeChecker` 的集成参见 `docs/common-dev-guide.md §2`
