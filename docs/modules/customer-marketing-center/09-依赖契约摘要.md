# 客户营销中心 — 依赖契约摘要

> 本文档摘录自被依赖模块的对外 API 契约，仅供客户营销中心开发快速查阅。
> **如有冲突，以源模块最新文档为准**。
> 依赖强度：S (Strong) — 强依赖，缺失不可运行；W (Weak) — 弱依赖，降级可用。

---

## 1. 依赖 auth-permission-center（强依赖 S）

### 1.1 接口清单

| 接口类 | 方法签名 | 用途 | 调用场景 |
|---|---|---|---|
| CurrentUserApi | `CurrentUserContext getCurrentUserContext()` | 获取当前登录用户完整上下文 | 所有接口入口 |
| CurrentUserApi | `String getCurrentEmpId()` | 获取当前员工工号 | 审计、创建记录、权限判定 |
| CurrentUserApi | `String getCurrentOrgCode()` | 获取当前机构代码 | 创建业务记录的 owner_org_id |
| CurrentUserApi | `List<String> getCurrentRoles()` | 获取当前用户角色列表 | 权限分支判定（如管理员专属接口） |
| BizScopeApi | `DataScopeType resolveScope(String empId, BizType bizType)` | 解析员工对某业务类型的数据范围 | 列表查询加 DataScope 过滤 |
| BizScopeApi | `boolean checkWritePermission(String empId, BizType bizType, String resourceId, String ownerOrgId)` | 写操作前校验 | 更新/删除前的二次权限检查 |
| BizScopeApi | `ScopeFilter buildScopeFilter(String empId, BizType bizType)` | 构造数据范围过滤条件 | 复用到 Mapper 查询 |
| OrgApi | `Set<String> getOrgSubtreeCodes(String orgCode)` | 获取某机构的子树全部机构代码 | 负责人权限 DataScope (DEPARTMENT_AND_BELOW) |
| OrgApi | `OrgDTO getUserMainOrg(String empId)` | 获取员工主机构 | 创建业务记录的归属机构 |
| OrgApi | `OrgDTO getOrgByCode(String orgCode)` | 按代码查询机构详情 | 展示机构名称 |

### 1.3 调用示例

#### 示例 A — 列表查询附加数据范围

```java
public PageResult<CustMasterDTO> listCustomers(CustomerQueryCmd cmd, Pageable page) {
    String empId = currentUserApi.getCurrentEmpId();
    // CUSTOMER 的数据范围按 cust_claim 判定
    ScopeFilter scope = bizScopeApi.buildScopeFilter(empId, BizType.CUSTOMER);
    cmd.setScopeFilter(scope);
    return custMasterMapper.selectPageWithScope(cmd, page);
}
```

#### 示例 B — 写操作前权限校验

```java
public void transferCustomer(String custId, String newMaintainerEmpId) {
    String empId = currentUserApi.getCurrentEmpId();
    CustMaster cust = custMasterMapper.selectById(custId);
    // 写前校验：当前用户对该客户是否有写权限
    boolean allowed = bizScopeApi.checkWritePermission(
        empId, BizType.CUSTOMER, custId, cust.getOwnerOrgId());
    if (!allowed) {
        throw new BizException("NO_WRITE_PERMISSION", "无权限操作该客户");
    }
    // ... 执行转交 ...
}
```

#### 示例 C — 负责人数据范围（DEPARTMENT_AND_BELOW）

```java
public PageResult<CustLeadDTO> listLeadsAsManager() {
    String empId = currentUserApi.getCurrentEmpId();
    DataScopeType scope = bizScopeApi.resolveScope(empId, BizType.LEAD);
    if (scope == DataScopeType.DEPARTMENT_AND_BELOW) {
        // 获取本机构及下级全部子节点
        OrgDTO mainOrg = orgApi.getUserMainOrg(empId);
        Set<String> orgs = orgApi.getOrgSubtreeCodes(mainOrg.getOrgCode());
        // 传递给 Mapper 过滤
        return custLeadMapper.selectPageByOrgs(orgs);
    }
    // ... 其他 scope ...
}
```

## 2. 依赖 workflow-center（强依赖 S）

### 2.1 当前可用接口与差异说明

> 实现差异（2026-04-14）：`workflow-center` 当前真正公开的跨模块 Java Bean 只有 `WorkflowApi`。旧稿中的 `WorkflowQueryApi`、`WorkflowParticipantService` 仍属于规划态名称，若要落地为模块间 Java 依赖，需要 workflow-center 先补齐正式 `*Api` 契约。

| 形态 | 当前契约 | 用途 | 当前状态 |
|---|---|---|---|
| Java | `WorkflowApi.startProcess(StartProcessCmd cmd)` | 启动线索审批 / 触达相关流程 | 已实现 |
| Java | `WorkflowApi.cancelProcess(String processInstanceId, String reason)` | 取消流程实例 | 已实现 |
| Java | `WorkflowApi.getProcessByBusinessKey(String businessKey)` | 查询流程映射 | 已实现 |
| Java | `WorkflowApi.getProcessByBizTypeAndBizId(String bizType, String bizId)` | 查询流程映射 | 已实现 |
| REST | `GET /api/workflow/tasks` 等 | 待办、详情、办理、流程图、历史查询 | 当前只有 workflow 模块自身 REST 控制器，无 QueryApi Bean |
| 规划态 | `WorkflowParticipantService` | 参与者判定 / 运行时权限 | 当前未对外落地 |

### 2.3 使用的流程定义

| 流程定义 Key | 流程名称 | BusinessKey 格式 | 发起场景 |
|---|---|---|---|
| `lead_approve_v1` | 单条线索审批 | `LEAD:{leadId}` | POST /api/leads/{id}/submit |
| `lead_import_approve_v1` | 批量线索审批 | `LEAD:IMP_{batchId}` | POST /api/leads/import |
| `touch_process_v1` | 触达任务流程 | `TOUCH:{taskId}` | POST /api/customer-pool/{custId}/claim（认领后自动触发）|
| `lead_delete_approve_v1` | 客户删除审批 | `LEAD_DELETE:{leadId}` | POST /api/customers/{id}/delete-apply |

### 2.4 BusinessKey 规范

| 格式 | 示例 | 说明 |
|---|---|---|
| `LEAD:{leadId}` | `LEAD:abc123def456` | 单条线索审批 |
| `LEAD:IMP_{batchId}` | `LEAD:IMP_xyz789` | 批量导入批次审批 |
| `TOUCH:{taskId}` | `TOUCH:tt_001` | 触达任务流程 |
| `LEAD_DELETE:{leadId}` | `LEAD_DELETE:l3_uuid` | 客户删除审批 |

**约定**：
- BusinessKey 在 Flowable 全局唯一
- BusinessKey 一经创建不可修改
- 业务表的 `business_key` 字段必须与 Flowable 一致

### 3.4 降级策略（W 级）

portal-content-center 不可用时的降级方案：

- **产品列表**：返回空列表 + 前端提示"产品服务暂不可用，请稍后重试"；触达任务仍可完成但不记录产品
- **通讯录搜索**：返回空结果 + 前端提示"员工搜索暂不可用"；转交功能暂时不可用
- **客户经理判定**：降级为查询 auth-permission-center 的角色（ROLE_CUSTOMER_MANAGER），但可能数据不一致，仅作兜底

### 3.5 缓存策略

- `productApi.listSupportAvailableProducts()` 本地 Caffeine 缓存 10 分钟
- `addressBookApi.isCustomerManager(empId)` Redis 缓存 30 分钟

```java
@PostMapping("/touch-tasks/{id}/photos")
public ApiResult<List<String>> uploadPhotos(@PathVariable String id,

    String empId = currentUserApi.getCurrentEmpId();

}
```

| 场景 | 单文件上限 | 总数上限 |

### 4.6 AuditApi 性能要求

- `logAsync` 默认异步，< 5ms 返回
- 本模块所有审计均使用 `logAsync`（除非业务上要求同步，如删除操作）
- AuditApi 服务不可用时降级本地日志文件

## 7. 契约变更流程

### 7.1 契约冻结范围

本文档中明确列出的接口签名、数据结构、BusinessKey 格式、异常码均为契约冻结范围。未经协商不得单方面修改。

### 7.2 变更流程

1. 提出方（上游模块）在版本迭代前 1 周发起契约变更提案
2. 客户营销中心 Owner 评估影响范围，反馈兼容性问题
3. 双方确认后，上游模块更新文档并同步到本文档
4. 联调环境先行验证，通过后上生产

### 7.3 兜底原则

- 上游接口不可用时，客户营销中心必须保证核心流程（列表查询、认领、触达）可用（降级）
- 降级策略由客户营销中心自行实现，不依赖上游提供
- 所有降级场景必须记录日志和告警，便于排查

## 9. DATA_SCOPE SQL 过滤片段具化示例（2026-04-10 新增）

本章节将 `docs/common-dev-guide.md §5` 的 7 种 DataScopeType 通用模板具化到本模块的实际表字段。

### 9.1 本模块表与 DATA_SCOPE 字段映射

| 表 | 过滤字段 | BizType | 常用范围 |
|---|---|---|---|
| `cust_tag` | — | TAG | 全行共享，仅读接口用 `ALL` |
| `cust_lead` | `owner_org_id` / `created_by` | LEAD | SELF_CREATED / ORG_SUBTREE / ALL |
| `cust_master` + `cust_claim` | `cust_claim.org_id` + `cust_claim.claimed_by_emp_id` | CUSTOMER | SELF / ORG_SUBTREE（通过 cust_claim 连接） |
| `cust_claim` | `org_id` / `claimed_by_emp_id` | CLAIM | SELF / ORG_SUBTREE |
| `touch_task` | `assignee_emp_id` / `org_id` | TOUCH_TASK | SELF_ASSIGNED / ORG_SUBTREE |

### 9.2 cust_lead 列表查询（完整示例）

```xml
<!-- CustLeadMapper.xml -->
<select id="listLeads" resultType="CustLeadEntity">
    SELECT * FROM cust_lead
    <where>
        AND deleted = 0
        <if test="keyword != null">AND cust_name LIKE CONCAT('%', #{keyword}, '%')</if>
        <if test="leadStatus != null">AND lead_status = #{leadStatus}</if>
        <include refid="leadDataScopeFilter"/>
    </where>
    ORDER BY created_time DESC LIMIT #{offset}, #{limit}
</select>

<sql id="leadDataScopeFilter">
    <choose>
        <when test="dataScope.type == 'ALL'"/>
        <when test="dataScope.type == 'ORG_SUBTREE'">
            AND owner_org_id IN
            <foreach collection="dataScope.orgSubtree" item="o" open="(" close=")" separator=",">#{o}</foreach>
        </when>
        <when test="dataScope.type == 'SELF_CREATED'">
            AND created_by = #{dataScope.empId}
        </when>
        <otherwise>AND 1 = 0</otherwise>
    </choose>
</sql>
```

### 9.3 cust_master 通过 cust_claim 过滤（关键模式）

客户主档的数据范围**不是**直接过滤 `cust_master`，而是通过 `cust_claim` 表间接过滤（只有被本人或本机构认领的客户才可见）：

```xml
<!-- CustMasterMapper.xml -->
<select id="listMyCustomers" resultType="CustomerVO">
    SELECT m.*, c.claimed_by_emp_id, c.org_id AS claim_org_id
    FROM cust_master m
    INNER JOIN cust_claim c ON c.cust_id = m.id
    <where>
        AND m.deleted = 0 AND c.status = 'CLAIMED'
        <choose>
            <when test="dataScope.type == 'ALL'"/>
            <when test="dataScope.type == 'ORG_SUBTREE'">
                AND c.org_id IN
                <foreach collection="dataScope.orgSubtree" item="o" open="(" close=")" separator=",">#{o}</foreach>
            </when>
            <when test="dataScope.type == 'SELF'">
                AND c.claimed_by_emp_id = #{dataScope.empId}
            </when>
            <otherwise>AND 1 = 0</otherwise>
        </choose>
    </where>
    ORDER BY m.updated_time DESC LIMIT #{offset}, #{limit}
</select>
```

**关键说明**：这是本模块的核心设计原则 —— 客户认领即"数据范围的入口"。没有 `cust_claim` 记录的客户在常规列表中**不可见**，仅在"待认领客户池"（§5）中可见。

### 9.4 touch_task SELF_ASSIGNED 示例

```xml
<select id="listMyTouchTasks" resultType="TouchTaskEntity">
    SELECT * FROM touch_task
    <where>
        AND deleted = 0
        <if test="taskStatus != null">AND task_status = #{taskStatus}</if>

            </when>
            <otherwise>AND 1 = 0</otherwise>
        </choose>
    </where>
    ORDER BY sla_deadline ASC, created_time DESC
</select>
```
