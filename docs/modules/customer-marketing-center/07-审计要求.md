# 客户营销中心 — 审计要求

> 审计动作、资源类型和原因要求以当前 Controller 的 `@BizAuth`/`@AuditLog` 注解为准；公共审计存储、traceId 和脱敏由平台基础设施提供。

## 1. 高风险动作与动作名

| 领域 | 当前动作（`@AuditLog.action`） | 资源/原因 |
|---|---|---|
| 客户 | `EXPORT_CUSTOMER_LIST`、`TRANSFER` | `CUSTOMER`；导出/转交要求原因 |
| 客户历史/标签 | `VIEW_CROSS_ORG_CUSTOMER_HISTORY`、`ADD_CUSTOMER_TAGS`、`REMOVE_CUSTOMER_TAG` | `CUSTOMER`；跨机构历史要求原因 |
| 认领 | `CANCEL_CLAIM`、`RE_TOUCH_CLAIM`、`START_FIRST_TOUCH` | `CLAIM`；取消/重新触达要求原因 |
| 转交 | `TRANSFER_CUSTOMER` | `CUSTOMER`；要求原因 |
| 线索导入/审批 | `CREATE_MARKETING_LEAD_IMPORT_BATCH`、`CONFIRM_MARKETING_LEAD_IMPORT_BATCH`、`EXPORT` | `LEAD`/`LEAD_APPROVAL` |
| 线索写入/审批 | `CREATE_MARKETING_LEAD`、`UPDATE_MARKETING_LEAD`、`SUBMIT_MARKETING_LEAD`、`CANCEL_MARKETING_LEAD`、`APPROVE_MARKETING_LEAD`、`REJECT_MARKETING_LEAD` | `LEAD`；取消要求原因 |
| 标签 | `IMPORT`、`EXPORT_TAG_CUSTOMERS`、`CREATE_MARKETING_CUSTOMER_TAG`、`UPDATE_MARKETING_CUSTOMER_TAG` | `TAG`/`TAG_CUSTOMER`；导出要求原因 |
| 标签审批 | `APPROVE_MARKETING_CUSTOMER_TAG`、`REJECT_MARKETING_CUSTOMER_TAG`、`APPROVE_MARKETING_TAG_CUSTOMER`、`REJECT_MARKETING_TAG_CUSTOMER` 及批量动作 | `TAG` |
| 触达 | `MARK_TOUCH_TASK_SUCCESS`、`CANCEL_TOUCH_TASK`、`ADD_TOUCH_LOG`、`EXPORT_TOUCH_REPORT` | `TOUCH_TASK`/`TOUCH_REPORT`；取消/导出要求原因 |
| 管理触达 | `LIST_ADMIN_TOUCH_TASKS`、`EXPORT_ADMIN_TOUCH_TASKS`、`BATCH_ASSIGN_TOUCH_TASKS` | `TOUCH_TASK`；批量分配要求原因 |

传统 `/api/tags`、`/api/leads`、`/api/customers` 与 `/api/marketing/*` 路径的审计以各自 Controller 注解为准，不能因路径相似合并资源授权。

## 2. 审计记录字段

公共审计至少关联：操作人、操作机构、时间、traceId、动作、资源类型、资源 ID、结果、失败码和耗时。写操作附带目标状态变化、版本号/锁版本和关键业务键；批量导入、批量分配和批量审核记录批次 ID及明细结果。

高风险操作还需记录：

- 导入：文件对象 ID/校验摘要、批次、模式、有效/失败结果；
- 导出：查询条件、操作人和响应结果；当前导出为直接 HTTP 响应，不写异步导出任务；
- 转交/主办权：变更前后人员与机构、接收人和原因；
- 审批/删除/撤回：目标业务键、原状态、目标状态、审批/撤回原因；
- 资产加急：主申请 ID、节点、加急原因和流程实例。

## 3. 权限与二次校验

- 所有非白名单端点声明匹配 `@BizAuth` 并登记 `PT_RESOURCE`；高危动作使用独立 URL、资源和审计动作。
- 列表、详情、历史、导出和管理端查询都应用统一数据范围；不能只在前端隐藏按钮。
- Service 层基于目标客户、线索、认领、任务、标签、申请和锁版本再次校验操作者；系统管理员只在源码明确允许的检查处获得额外能力。
- 跨机构历史、跨机构营销审核、主办权转交和资产撤回/加急不因普通客户读权限自动放开。

## 4. 敏感字段与日志

日志和审计载荷禁止明文输出凭据；手机号、联系人、统一社会信用代码、客户地址、导入原始行和文件下载信息按公共脱敏策略处理。业务日志优先记录 ID、编号、状态和 traceId，不打印完整请求体或工作日志内容。

文件对象只记录受控的文件 ID/摘要，下载操作仍走治理模块的对象访问和审计链路。

## 5. 事件和流程回写

线索、客户删除、触达、资产立项和跨机构流程回调在 `AFTER_COMMIT` 的新事务中进行条件状态更新；重复回调不得重复创建客户、触达或关系。领域事件（如 `LeadRejectedEvent`、`ClaimCancelledEvent`、`ClaimTransferredEvent`、`TouchCompletedEvent`、`CustomerDeletedEvent`）使用业务 ID、操作人和结果与审计关联。

## 6. 维护要求

修改 Controller、`@BizAuth`、`@AuditLog`、DTO、错误码或事件字段时同步更新 `03-接口设计与报文.md`、资源数据和契约检查。本文不定义版本号、留存年限、告警阈值、归档脚本或尚未实现的审计扩展属性。
