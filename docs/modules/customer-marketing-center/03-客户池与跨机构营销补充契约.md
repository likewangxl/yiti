# 客户池与跨机构营销补充契约

> 生效范围：2026-08-27 起的待认领线索池、已认领线索池和跨机构营销接口。
> 数据边界与业务规则详见《10-营销客户管理前后端功能设计》第 16 节。

## 1. 待认领线索池

- `GET /api/customer-pool`：仅返回已审批、公开分配、池状态可认领且客户无有效主办的目标营销线索。
- 响应同时返回 `sourceLeadId`、线索编号/类型、客户资料、标签、分配方式、有效认领人数和下发时间。
- `POST /api/claims`：请求以 `sourceLeadId` 作为认领对象；服务端重新锁定线索和客户主档，并按 `source_lead_id + claimed_by` 防重。

## 2. 已认领线索池

- `GET /api/claims/mine/customers`：支持 `tab=UNTOUCHED|TOUCHED`、`keyword`、`sourceType=PUBLIC|SCOPE|OWNER`、`pageNo` 和 `pageSize`。
- 数据事实来源为 `MARKETING_CUSTOMER_CLAIM`；触达状态优先读取 `MARKETING_TOUCH_TASK`，迁移期兼容旧 `TOUCH_TASK`。
- `POST /api/claims/{id}/cancel`、`POST /api/claims/{id}/touch` 和 `POST /api/claims/{id}/re-touch` 保持原路径，数字 ID 路由到目标认领关系。

## 3. 跨机构营销

- `GET /api/cross-org-marketing/validate?custId=...`：按目标营销客户 ID 校验四项规则，规则数据只取客户主档和业绩关系快照。
- `POST /api/cross-org-marketing`：创建申请，保存四项校验快照，初始状态为 `IN_APPROVAL`。
- `GET /api/cross-org-marketing`、`GET /api/cross-org-marketing/{id}`：普通员工只见本人申请，审核人可见审核范围内记录，并返回 `canReview`。
- `POST /api/cross-org-marketing/{id}/approve`：仅生成申请人的跨机构触达任务，不改变主办、认领或业绩关系。
- `POST /api/cross-org-marketing/{id}/reject`：退回原因必填。

## 4. 数据库实施边界

本契约只描述代码行为；目标表 DDL 尚未由本次改造执行。联调环境必须先完成 DBA 评审、建表和基础规则数据初始化。
