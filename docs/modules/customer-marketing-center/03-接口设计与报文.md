# 客户营销中心 — 接口设计与报文

> 版本：v1.0
> 最后更新：2026-04-10
> 模块编码：customer-marketing-center
> 统一前缀：`/api`
> 统一响应：`ApiResponse<T>`（见 common-dev-guide）
> 所有接口必须登记到 `PT_RESOURCE` 表
> 所有接口必须声明 `@BizAuth` 注解
> 本文是可执行的接口契约，开发时直接参考字段级定义

---

## 0. 公共约定

### 0.1 统一响应结构
```json
{
  "code": "0",              // "0" 表示成功
  "message": "success",
  "data": { },              // 业务数据
  "traceId": "xxx-xxx",
  "timestamp": 1712750400000
}
```

### 0.2 错误响应结构
```json
{
  "code": "CUST-40002",
  "message": "标签名称已存在",
  "data": null,
  "traceId": "xxx-xxx",
  "timestamp": 1712750400000,
  "fieldErrors": [                  // 参数校验错误时出现
    { "field": "tagName", "message": "不能为空" }
  ]
}
```

### 0.3 分页请求参数
| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| pageNo | Integer | 1 | 页码（从 1 开始） |
| pageSize | Integer | 20 | 每页条数（最大 100） |
| sortField | String | 无 | 排序字段 |
| sortOrder | String | desc | asc/desc |

### 0.4 分页响应结构
```json
{
  "pageNo": 1,
  "pageSize": 20,
  "totalCount": 100,
  "totalPages": 5,
  "records": [ ]
}
```

### 0.5 @BizAuth 注解参数说明
| 参数 | 说明 |
|---|---|
| bizType | 业务类型（TAG/LEAD/CUSTOMER/CUSTOMER_POOL/CLAIM/TOUCH_TASK/TOUCH_REPORT） |
| action | 动作（LIST/READ/WRITE/DELETE/TRANSFER/IMPORT/EXPORT） |
| dataScope | 是否应用数据范围（默认 true） |
| highRisk | 是否高危操作（默认 false） |

### 0.6 统一响应 Code
- `0` — 成功
- `CUST-XXYYY` — 客户营销业务错误
- `AUTH-XXYYY` — 认证/权限错误
- `COMMON-XXYYY` — 通用错误

## A.7 GET /api/tags/{id}/customers/export — 导出标签客户

**权限**：`@BizAuth(bizType = TAG, action = EXPORT, highRisk = true)`
**描述**：导出某标签关联的所有客户 Excel

### 导出规范
遵循 [附录 K 导出接口统一规范](#k-导出接口统一规范附录)
- **同步阈值**：≤ 5000 行同步流式返回；5000 < N ≤ 100000 走异步任务；> 100000 拒绝（`CUST-42207`）
- **文件名**：`cust_tag_customers_{filterHash}_{yyyyMMddHHmmss}.xlsx`（替换原 `filename=tag_customers_{tagId}_...` 命名）
- **同步响应**：`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，Excel 二进制流
- **异步响应**：`R<ExportTaskRespDTO>`，详见 §K.3
- **列定义（8 列）**：详见 §K.7.1

### 业务规则
- 仅导出未逻辑删除的客户
- 按 `cust_tag_rel` 过滤关联关系，按 `cust_master` 取档案详情
- 审计级别 HIGH，记录 filter + rowCount + duration

## C.2 POST /api/leads/import — 执行导入

**权限**：`@BizAuth(bizType = LEAD, action = IMPORT, highRisk = true)`

### 请求参数
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| file | MultipartFile | 是 | Excel 文件 |
| confirmToken | String | 是 | 预览返回的 Token |

### 业务流程
```
1. 校验 confirmToken 有效性（Redis 缓存）
```

# K. 导出接口统一规范（附录）

本章节为本模块所有 `action = EXPORT` 的接口（A.7、D.6、H.3）提供统一的同步/异步分支规则、文件命名、异步任务 DTO、列定义原则、错误码与审计要求。**落地** `docs/common-dev-guide.md §8.2 第 5 条` 的规范（"超过 5000 行必须走异步导出"）。

## K.1 同步 / 异步分支规则

| 命中行数 N | 处理方式 | 响应类型 | 说明 |
|---|---|---|---|
| N ≤ 5000 | 同步流式返回 | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` | 直接 HTTP 流式写出，前端触发浏览器下载 |
| 5000 < N ≤ 100000 | 异步任务 | `R<ExportTaskRespDTO>` | 后端返回任务 ID，前端轮询任务状态 |
| N > 100000 | 拒绝 | `CUST-42207` | 引导用户增加过滤条件 |

**判定流程**：
1. 进入导出接口先执行一次 `SELECT count(*)` 取精确命中行数（走 DATA_SCOPE + cust_claim 过滤）
2. 按行数命中分支
3. 异步分支：写入 `sys_async_task`（governance 提供），状态 `PENDING → RUNNING → SUCCESS / FAILED`
4. 异步完成后：上传 Excel 到 MinIO，持久化 `file_object_id`，调用 `NotifyApi.sendUserNotify(empId, "导出完成", downloadUrl)`
5. 发布事件 `customer.export.completed.v1`（可选，供审计汇总消费）

## K.2 文件命名规则

格式：`{module}_{business}_{filterHash}_{yyyyMMddHHmmss}.xlsx`

| 片段 | 说明 | 示例 |
|---|---|---|
| `{module}` | 固定 `cust` | `cust` |
| `{business}` | 业务域名 | `tag_customers` / `customers` / `touch_tasks` |
| `{filterHash}` | 请求参数 JSON 序列化后 MD5 前 8 位 | `a3f9b2c4` |
| `{yyyyMMddHHmmss}` | 导出发起时刻 | `20260410153022` |

示例：
- `cust_tag_customers_a3f9b2c4_20260410153022.xlsx`
- `cust_customers_b7e2c1d5_20260410153022.xlsx`
- `cust_touch_tasks_c1f5a3b9_20260410153022.xlsx`

## K.3 异步任务响应 DTO：`ExportTaskRespDTO`

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|---|---|
| `taskId` | String | 是 | 异步任务唯一 ID，格式 `EXP{yyyyMMddHHmmss}{4位随机}` |
| `bizType` | String | 是 | 业务类型（TAG / CUSTOMER / TOUCH_REPORT） |
| `status` | String | 是 | `PENDING` / `RUNNING` / `SUCCESS` / `FAILED` |
| `estimatedRows` | Long | 是 | 预估行数（从 count 取得） |
| `statusUrl` | String | 是 | 状态查询 URL：`/api/async-tasks/{taskId}` |
| `downloadUrl` | String | 否 | 下载 URL，`SUCCESS` 时才有值 |
| `createdTime` | LocalDateTime | 是 | 任务创建时间 |
| `expireAt` | LocalDateTime | 是 | 文件下载链接过期时间（默认 24 小时） |
| `errorMsg` | String | 否 | 错误信息，`FAILED` 时才有值 |

## K.4 列定义规范

每个导出接口必须在其接口段落明确以下四项：列顺序、中文列名、字段来源、格式规则（脱敏/字典翻译/金额精度/日期格式）。本模块涉及金融客户数据，**敏感字段默认脱敏**：

| 字段 | 脱敏规则 | 示例 |
|---|---|---|
| 客户手机号 | 保留前 3 后 4 | `138****5678` |
| 法人身份证号 | 保留前 3 后 4 | `310****4321` |
| 统一社会信用代码 | 不脱敏（公开信息） | `91310...` |
| 授信金额 | 不脱敏（业务必需） | `12000000.00` |
| 客户经理手机号 | 保留前 3 后 4 | `138****5678` |

## K.5 错误码

| code | HTTP | 说明 | 触发条件 |
|---|---|---|---|
| `CUST-42207` | 422 | 导出行数超过上限（100000） | count > 100000 |
| `CUST-42208` | 422 | 异步导出任务不存在或已过期 | taskId 无效 / 文件链接过期 |
| `CUST-42209` | 403 | 不能下载他人创建的导出任务 | taskId 的 createdBy ≠ 当前用户 |
| `CUST-42210` | 422 | 导出过滤条件未通过 DATA_SCOPE 校验 | 数据范围校验失败 |
| `CUST-50002` | 500 | 导出文件生成失败 | Excel 生成或 MinIO 上传异常 |

## K.6 审计要求

- `result`（`SUCCESS` / `FAILED`）

审计记录示例（参考 07-审计要求.md §2 对应条目）。

## L.6 使用约定

1. 错误码在 `CommonResult.errorCode` 字段返回，`code` 字段为 HTTP 状态码同值
2. 所有高危操作失败（IMPORT/EXPORT/DELETE/TRANSFER）必须写审计日志，即使被错误码拦截也要记录
3. 业务状态冲突类错误（40901-40911）前端应显示友好消息并提示用户下一步操作
4. 文档交叉引用：各接口的具体错误码触发条件见本文档对应接口段落
