# 客户营销中心 — 接口设计与报文

> 版本：v1.0
> 最后更新：2026-04-10
> 模块编码：customer-marketing-center
> 统一前缀：`/api`
> 统一响应：`ApiResponse<T>`（见 common-dev-guide）
> 所有接口必须登记到 `PT_RESOURCE` 表
> 所有接口必须声明 `@BizAuth` 注解
> 本文是可执行的接口契约，开发时直接参考字段级定义

---

## 0. 公共约定

### 0.1 统一响应结构
```json
{
  "code": "0",              // "0" 表示成功
  "message": "success",
  "data": { },              // 业务数据
  "traceId": "xxx-xxx",
  "timestamp": 1712750400000
}
```

### 0.2 错误响应结构
```json
{
  "code": "CUST-40002",
  "message": "标签名称已存在",
  "data": null,
  "traceId": "xxx-xxx",
  "timestamp": 1712750400000,
  "fieldErrors": [                  // 参数校验错误时出现
    { "field": "tagName", "message": "不能为空" }
  ]
}
```

### 0.3 分页请求参数
| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| pageNo | Integer | 1 | 页码（从 1 开始） |
| pageSize | Integer | 20 | 每页条数（最大 100） |
| sortField | String | 无 | 排序字段 |
| sortOrder | String | desc | asc/desc |

### 0.4 分页响应结构
```json
{
  "pageNo": 1,
  "pageSize": 20,
  "totalCount": 100,
  "totalPages": 5,
  "records": [ ]
}
```

### 0.5 @BizAuth 注解参数说明
| 参数 | 说明 |
|---|---|
| bizType | 业务类型（TAG/LEAD/CUSTOMER/CUSTOMER_POOL/CLAIM/TOUCH_TASK/TOUCH_REPORT） |
| action | 动作（LIST/READ/WRITE/DELETE/TRANSFER/IMPORT/EXPORT） |
| dataScope | 是否应用数据范围（默认 true） |
| highRisk | 是否高危操作（默认 false） |

### 0.6 统一响应 Code
- `0` — 成功
- `CUST-XXYYY` — 客户营销业务错误
- `AUTH-XXYYY` — 认证/权限错误
- `COMMON-XXYYY` — 通用错误

## B.5 POST /api/leads/{id}/submit — 提交审批

**权限**：`@BizAuth(bizType = LEAD, action = WRITE)`
**描述**：提交线索审批，调用 `WorkflowApi.startProcess(lead_approve_v1, LEAD:{leadId})`

### 请求体
无（可选 remark 审批备注）
```json
{
  "remark": "请审批"
}
```

### 响应体
```json
{
  "code": "0",
  "data": {
    "leadId": "2001",
    "leadStatus": "PENDING_APPROVAL",
    "processInstanceId": "proc-inst-xxx",
    "businessKey": "LEAD:2001"
  }
```

### 业务校验
1. 线索必须为 DRAFT 状态
2. `cust_name` 幂等校验：
   - 不能与 `cust_master.cust_name`（status=VALID）冲突
   - 不能与其他 PENDING_APPROVAL/APPROVED 的 `cust_lead` 冲突
3. 必填字段完整性

### 错误码
- `CUST-40003` 线索不存在
- `CUST-40906` 线索非草稿状态不可编辑
- `CUST-40901` 客户名称已存在

## C.2 POST /api/leads/import — 执行导入

**权限**：`@BizAuth(bizType = LEAD, action = IMPORT, highRisk = true)`

### 请求参数
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| file | MultipartFile | 是 | Excel 文件 |
| confirmToken | String | 是 | 预览返回的 Token |

### 业务流程
```
1. 校验 confirmToken 有效性（Redis 缓存）
2. 校验 fileMd5 匹配
3. 创建 lead_import_batch（status=CREATED）
4. 行级完整校验（再次）
5. 若任一失败 → 整批回滚 → 返回 CUST-42201
6. 批量 INSERT cust_lead（每 500 行一批）
7. 调用 WorkflowApi.startProcess(lead_batch_approve_v1, LEAD:IMP_{batchId})
8. 更新批次状态 PENDING_APPROVAL
9. 发布事件 customer.lead.batch.submitted.v1
```

### 响应体
```json
{
  "code": "0",
  "data": {
    "importBatchId": "3001",
    "batchNo": "LEAD_IMP_20260410_0001",
```

- `CUST-40005` 触达任务不存在
- `CUST-40302` 无权访问非本人触达任务
- `CUST-40907` 触达任务非 PENDING/IN_PROGRESS 状态
- `CUST-42206` 触达日志缺少必填字段
- `CUST-42207` 照片数量超限

## G.4 POST /api/touch-tasks/{id}/cancel — 触达取消

**权限**：`@BizAuth(bizType = TOUCH_TASK, action = WRITE)`

### 请求体 `TouchCancelReqDTO`
| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| cancelReason | String | 是 | `@NotBlank @Size(max=500)` | 取消原因 |
| clientUuid | String | 是 | `@NotBlank` | 幂等键 |
| logContent | String | 否 | `@Size(max=2000)` | 可选备注 |

### 业务流程
```
1. 校验 SELF_ASSIGNED + 状态
2. 幂等检查
3. UPDATE touch_task.task_status=CANCELLED, cancel_reason, finish_result=CANCELLED
4. 若有 logContent，INSERT touch_log
5. 发布事件 customer.touch.completed.v1（result=CANCELLED）
6. 调用 WorkflowApi.cancelProcess
```

### 响应体
```json
{ "code": "0", "data": { "taskId": "6001", "taskStatus": "CANCELLED" } }
```
