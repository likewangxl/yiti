# 客户营销中心 — 接口设计与报文

> 当前 REST 契约以 `customer-marketing-center/src/main/java/.../controller` 的映射、入参 DTO 和返回类型为准。本文删去版本流水和设计态伪接口；公共 Java 查询契约见 `04-对外API契约.md`。

## 1. 公共约定

- 普通 JSON 接口返回 `common-web` 统一响应；分页使用 Controller 实际的 `pageNo/pageSize` 参数和 `PageResult`。
- 文件导入使用 `multipart/form-data`，文件来源、校验结果和批次状态由对应 Service 管理；文件导出按当前 Controller 的直接响应执行，不套用异步任务/对象存储设计。
- 非白名单接口必须同时声明 `@BizAuth` 并在 `PT_RESOURCE` 登记；写操作在 Service 层按目标数据再次校验。
- 具体错误码和消息以 `CustomerErrorCode.java` 及各 Service 直接抛出的业务码为准；本文不列出未被当前路径消费的预留码。

## 8. 权限、错误和响应边界

业务类型包括 `TAG`、`LEAD`、`CUSTOMER`、`CUSTOMER_POOL`、`CLAIM`、`TOUCH_TASK`、`CROSS_ORG_MARKETING`、`ASSET_PROJECT` 等，以 Controller 注解为准。常见错误包括资源不存在（`CUST-404xx`）、越权（`CUST-403xx`）、状态/重复冲突（`CUST-409xx`）和导入/日志/业务校验失败（`CUST-422xx`）。

导入、导出、转交、删除申请、跨机构审核、资产撤回/加急等高危端点同时要求独立资源授权和审计；手机号、统一社会信用代码、联系人和文件信息按公共脱敏规则输出。
