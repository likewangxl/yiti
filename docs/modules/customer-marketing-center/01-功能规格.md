# 客户营销中心 — 功能规格

> 模块代码：`customer-marketing-center`。本文只描述源码中仍提供的客户、线索、标签、触达、跨机构营销和资产立项能力；REST 细节见 `03-接口设计与报文.md`，跨模块 Java 契约见 `04-对外API契约.md`。

## 1. 定位与边界

本模块拥有客户营销主档、线索录入与审批、标签及客户标签关系、客户认领/转交、触达任务与工作日志、跨机构营销申请、资产立项及其加急申请。认证、组织、工作流、字典/文件/通知和审计基础设施由平台模块提供。

当前客户主档实体类 `CustMaster` 映射 `CUSTOMER_MARKET_CUSTOMER`；`M98CustMaster` 映射 `CUST_MASTER`，只用于 M98 同步/查询场景，不能把它当作营销写入主表。资产立项实体及接口均归本模块，业务申请中心通过 `AssetProjectQueryApi` 只读统计。

## 2. 线索与客户主档

### 2.1 线索录入和审批

- 手工线索和文件批次均支持预览/校验、保存、提交和审批查询；线索状态为 `DRAFT`、`SUBMITTED`、`IN_APPROVAL`、`APPROVED`、`REJECTED`。
- 线索使用 `leadOp=CREATE/UPDATE/DELETE` 表达操作类型；有效名称/统一社会信用代码按源码规则校验。
- 提交调用 workflow-center，流程完成回调以条件更新推进状态。审批通过后由客户服务组装或更新 `CUSTOMER_MARKET_CUSTOMER`，审批驳回保留线索记录。
- 旧 `/api/leads` 与当前 `/api/marketing/leads`、对应批次/审批路径同时存在，调用方以实际 Controller 契约选择，不把页面草稿字段当作公共 API。

### 2.2 客户列表、主办权和删除

- 客户列表、详情、历史和标签关系均受统一数据范围控制；未分配客户按业务规则可见，已分配客户按本人、机构或机构树过滤。
- `/api/marketing/customers/{id}/profile` 只维护允许编辑的资料字段，并要求资料版本、锁版本和修改原因；主键、客户号、统一社会信用代码、开户状态及主办权不由资料编辑接口修改。
- 主办权通过转交接口使用 `ASSIGN`、`TRANSFER`、`UNASSIGN`；管理员可取消主办，其他操作需当前主办人权限。使用 `lock_version` CAS 并记录转交日志/接收人。
- 客户删除走删除申请及工作流；在途触达/业务流程等校验不通过时拒绝删除。

## 3. 标签与客户标签关系

- 标签支持新增、编辑、启停、删除及审核；启用标签通过 `TagApi.listEnabledTags` 提供给其他模块。
- 传统 `/api/tags` 和当前 `/api/marketing/customer-tags` 两组接口均由源码提供。标签客户关系支持单条/批量、JSON/文件导入和客户导出。
- 当前营销标签文件导入先落批次/明细，批次按校验和审批状态推进；标签未审核或未启用时不能将其作为有效客户标签。
- 触达周期由 `/api/touch-limit-rules` 维护，周期单位来自 `DAY/WEEK/MONTH/QUARTER/YEAR`。

## 4. 客户池、认领与跨机构营销

- 待认领客户池和已认领客户池按机构、员工和认领状态展示；认领状态为 `CLAIMED`、`CANCELLED`，同一员工/机构的重复认领由服务层和唯一性约束共同防护。
- 认领后可创建首次触达任务；取消认领和重新触达均校验当前状态、权限及进行中任务限制。
- 跨机构营销申请在创建前校验客户主办权、申请机构、业绩归属和重复申请，状态按当前服务的 `IN_APPROVAL`、`APPROVED`、`REJECTED` 处理；审核由独立资源和 Service 权限控制。

## 5. 触达任务与报表

- 触达任务类型为 `FIRST_TOUCH`、`FOLLOW_UP`；状态为 `PENDING`、`IN_PROGRESS`、`SUCCESS`、`CANCELLED`。
- 任务可写工作日志及图片/参与人，工作日志以 `(task_id, client_uuid)` 做幂等；成功、取消和管理员批量分配均记录审计。
- 触达限制按客户标签与周期计算；任务列表、统计、导出和管理员视图使用统一数据范围。公共查询契约只返回 DTO，不暴露任务实体。

## 6. 资产立项

资产立项 REST 根路径为 `/api/marketing/asset-projects`，申请状态为 `DRAFT`、`IN_APPROVAL`、`COMPLETED`、`REJECTED`、`CANCELLED`。创建/编辑仅允许草稿，提交启动 `loan_approve_v1`，撤回只允许审批中的可撤回节点并调用 workflow-center 取消流程。

立项申请保存客户、来源触达/工作日志、项目与金额、申请人机构、状态、流程键/实例和 `lock_version`；金额、客户来源和字典值由 Service 校验。详情通过治理文件 API、工作流查询 API组装附件、当前节点和审批历史。

审批中的资产项目可在允许节点申请一次加急；加急申请单独使用 `ASSET_PROJECT_URGENT:{id}` 业务键和流程结果，活动加急申请由 `activeDedupKey` 防重。

## 7. 权限、审计和数据边界

- 非白名单端点声明匹配的 `@BizAuth` 并登记 `PT_RESOURCE`；所有写操作在 Service 层按目标行做二次权限校验。
- 高危动作（导入、导出、转交、删除申请、跨机构审核、资产撤回/加急等）使用独立资源和 `@AuditLog`；原因字段按注解要求提供。
- 手机号、统一社会信用代码、客户联系人及文件信息按公共日志/审计脱敏规则处理；跨模块只使用公开 API、DTO 和领域事件，不跨模块直连表。
