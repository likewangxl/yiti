# 客户营销中心 — 初始化数据清单

> 本文只记录当前源码仍依赖的平台配置。数据库结构由 DBA 按审批实施；本文件不提供可执行 DDL/DML，也不记录一次性执行步骤。

## 1. 字典配置

客户营销中心不维护平台字典表，展示标签由 system-governance-center 的 DictApi 提供。当前源码明确读取的字典类型为：

| 类型编码 | 使用场景 |
|---|---|
| INDUSTRY | 线索/客户行业展示 |
| CUSTOMER_TYPE | 客户类型展示 |
| GROUP_TYPE | 集团类型展示 |
| ENTERPRISE_TYPE | 企业类型展示 |

线索、标签、触达和资产立项的状态/枚举由本模块 Service 与 DTO 校验；没有源码消费证据的字典项不在本模块配置清单中。字典变更应保持编码稳定，并由治理中心完成启停和审计。

## 2. 工作流配置

工作流定义、任务资源和流程实例由 workflow-center 统一管理；本模块只通过 WorkflowApi 发起、取消或查询流程。当前业务流程键如下：

| 流程键 | 业务键格式 | 使用场景 |
|---|---|---|
| lead_approve_v1 | LEAD:{leadId} | 单条线索及当前营销线索提交审批 |
| lead_delete_process | LEAD_DELETE:{leadId} | 已有客户删除申请 |
| loan_approve_v1 | 由资产立项 Service 生成 | 资产立项主申请及加急申请 |

流程完成事件必须带回业务键、流程实例和审批结果；本模块按状态条件更新线索、客户删除申请或资产申请。流程定义不存在、业务键不匹配或任务权限不足时，业务状态不得自行推进。

## 3. 资源与权限配置

所有非白名单 REST 方法必须在 PT_RESOURCE 登记与源码 @BizAuth 一致的业务类型和动作，并由角色/数据范围配置授予。当前需要维护的资源域为：

| 业务类型 | 当前资源职责 |
|---|---|
| TAG | 标签列表、维护、审核、客户关系导入/查询/导出、标签导入批次 |
| LEAD | 线索列表、维护、版本、导入、审批及导出 |
| CUSTOMER | 客户列表/详情/资料、主办权转交、删除申请和导出 |
| CUSTOMER_POOL | 客户池查询与认领入口 |
| CLAIM | 认领、取消认领、重新触达、首次触达及认领查询 |
| TOUCH_TASK | 触达任务、工作日志、图片/参与人和管理员分配 |
| TOUCH_REPORT | 触达统计和报表导出 |
| CROSS_ORG_MARKETING | 跨机构营销校验、申请、列表、审批和驳回 |
| ASSET_PROJECT | 资产立项草稿、提交、编辑、删除/撤回及加急申请 |

资源动作以 Controller 上的 LIST、READ、WRITE、CREATE、UPDATE、DELETE、SUBMIT、IMPORT、EXPORT、APPROVE、REJECT、TRANSFER 等实际注解为准；不要按页面数量或旧清单补充未消费资源。高危动作（删除、撤回、转交、导出、批量分配、审批）须使用独立资源并保持审计原因要求。

## 4. 文件、通知和调度

- 导入源文件、附件和导出文件通过治理中心 FileApi 完成上传、绑定、读取和下载；不在本模块另建对象存储或文件表。
- 审批、认领、触达和资产立项的通知通过治理中心通知能力发送；通知失败不得改变已提交的业务状态。
- 当前 Quartz 任务由治理中心 SYS_JOB_CONF 管理，源码提供以下任务类，配置时须使用实际 job_key 和类名：

  | job_key | 执行类 | 作用 |
  |---|---|---|
  | CUST_INFO_SYNC | CustMasterSyncJob | 将外部客户统计数据同步到 CUST_MASTER |
  | LEAD_CALLBACK_COMPENSATE | LeadCallbackCompensateQuartzJob | 巡检并补偿线索审批回调 |

调度周期、启停和错过策略以治理中心当前任务配置为准；不得在本模块文档固化易漂移的 Cron 或虚构的 SLA/清理任务。

## 5. 配置验收边界

配置变更只需核对字典编码、流程键、资源授权、文件/通知依赖和任务注册与源码一致。任何目标库盘点、脚本执行、流程部署或权限投产均须遵循仓库数据库与发布门禁，证据另行留存，不写入本清单。
