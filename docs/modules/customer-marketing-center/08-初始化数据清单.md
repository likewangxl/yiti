# 客户营销中心 — 初始化数据清单

> 本文档列出客户营销中心模块在系统初始化/上线时必须预置的数据。
> 所有种子数据通过 Flyway/手工 SQL 脚本注入，位于 `src/main/resources/db/seed/customer/` 目录。
> 生产环境首次部署时必须执行；已有环境升级时按需补充（使用 ON DUPLICATE KEY UPDATE 或 INSERT IGNORE）。

---

## 1. 预置字典引用

客户营销中心自身不维护字典表，所有字典均引用 `system-governance-center` 的 `PT_DICT_TYPE` / `PT_DICT_ITEM`。

## 3. 定时任务配置

客户营销中心需要配置以下定时任务，统一由 `system-governance-center` 的 `PT_SCHEDULED_TASK` 表管理，并通过 Quartz/Spring Scheduled 执行。

### 3.1 任务清单

| 任务编码 | 任务名称 | Cron 表达式 | 执行类 | 说明 |
|---|---|---|---|---|
| `TOUCH_SLA_REFRESH` | 触达任务SLA刷新 | `0 */30 * * * ?` | `TouchSlaRefreshJob` | 每 30 分钟更新触达任务的 sla_status（GREEN→YELLOW→RED） |
| `LEAD_EXPIRE_CHECK` | 线索草稿过期检查 | `0 0 2 * * ?` | `LeadExpireCheckJob` | 每日凌晨 02:00 清理超过 30 天的 DRAFT 线索草稿 |
| `TOUCH_TASK_TIMEOUT_ALERT` | 触达任务超时告警 | `0 0 9 * * ?` | `TouchTaskTimeoutAlertJob` | 每日 09:00 发送 RED 状态触达任务告警 |
| `CLAIM_ORPHAN_DETECT` | 认领异常检测 | `0 30 0 * * ?` | `ClaimOrphanDetectJob` | 每日 00:30 检测认领取消但有未完成任务的异常 |
| `TOUCH_LOG_ARCHIVE` | 触达日志归档 | `0 0 3 1 * ?` | `TouchLogArchiveJob` | 每月 1 日 03:00 归档 6 个月前的触达日志 |
| `LEAD_BATCH_EXPIRE` | 导入批次过期清理 | `0 0 4 * * ?` | `LeadBatchExpireJob` | 每日 04:00 清理 3 年前的已完成批次数据到归档表 |
| `AUDIT_HIGHRISK_REPORT` | 高危动作日报 | `0 0 8 * * ?` | `AuditHighRiskReportJob` | 每日 08:00 生成前一日高危动作汇总报表 |

### 3.2 TOUCH_SLA_REFRESH 任务示例

```java
@Component
public class TouchSlaRefreshJob {
    
    @Scheduled(cron = "0 */30 * * * ?")
    public void refresh() {
        LocalDateTime now = LocalDateTime.now();
        // 1. GREEN -> YELLOW: 到达 warning_time 但未到 plan_finish_time
        touchTaskMapper.updateSlaStatus("YELLOW", "GREEN", now);
        // 2. YELLOW -> RED: 到达 plan_finish_time
        touchTaskMapper.updateSlaStatus("RED", "YELLOW", now);
        log.info("TouchSlaRefreshJob completed at {}", now);
    }
}
```

对应 SQL：

```sql
-- GREEN -> YELLOW
UPDATE touch_task
SET sla_status = 'YELLOW', updated_time = NOW()
WHERE task_status = 'PENDING'
  AND sla_status = 'GREEN'
  AND warning_time <= #{now}
  AND plan_finish_time > #{now};

-- YELLOW -> RED
UPDATE touch_task
SET sla_status = 'RED', updated_time = NOW()
WHERE task_status = 'PENDING'
  AND sla_status IN ('GREEN','YELLOW')
  AND plan_finish_time <= #{now};
```

## X. 共享基线脚本指引（2026-04-10 新增）

本模块的多数种子数据（字典、资源、角色绑定、流程配置）并**不在本文档内**，而是集中在项目级共享脚本中。以下清单明确指向共享脚本中属于 customer-marketing-center 的段落。

### X.1 共享 DDL

| `docs/schema/ddl-customer.sql` | 本模块建表 DDL（cust_tag / cust_tag_rel / cust_lead / cust_master / cust_claim / touch_task / touch_log 等） | 首次建库执行 |
| `docs/schema/ddl-auth.sql` | PT_* 权限表 | auth 维护，customer 只读 |

### X.2 共享种子数据 `docs/schema/seed-v1.sql`

| §4.2 R_RM（客户经理）资源绑定 | 客户经理对 customer 资源的绑定 |

### X.3 共享流程配置 `docs/schema/workflow-seed-v1.sql`

| 流程 key | 节点 | 说明 |
|---|---|---|

| `touch_process_v1` | `touch_execute` | 触达任务流程 |

**种子数据位置**：
- `wf_node_candidate_conf`：在 `workflow-seed-v1.sql §1.1-1.4` 定义上述 4 个流程的节点候选角色

- `wf_node_form_conf`：在 `workflow-seed-v1.sql` 的对应章节（节点表单绑定）
- `biz_process_map`：需在 workflow-center 的初始化脚本中配置 `LEAD_SINGLE → lead_approve_v1` 等映射

### X.4 使用方式

**首次建库 (DEV/TEST)**：

```bash
# Step 1: 建表（所有模块 DDL 可并行执行）
mysql -uroot -p onepl < docs/schema/ddl-auth.sql
mysql -uroot -p onepl < docs/schema/ddl-governance.sql

# Step 4: 部署 BPMN 流程定义（由 workflow-center 启动时自动部署）

# Step 5: 补充本模块专属种子（本文档 §1-§8）
```

- 执行前备份：`docs/superpowers/sql/backup/YYYY-MM-DD-customer-before-align.sql`
