## 1. 模块职责边界

### 1.1 核心职责
| 职责 | 说明 |
|---|---|
| 标签管理 | 全行统一标签字典与客户关联 |
| 线索管理 | 单条/批量录入、版本化编辑、审批单据构造 |
| 客户主档 | 客户信息唯一视图、跨机构历史只读 TAB |
| 客户池 | 待认领池展示、已认领列表 |
| 认领管理 | 争抢认领、转交、取消认领 |
| 触达任务 | 首次触达、二次触达、日志+拍照 |
| 触达管理视图 | 机构汇总 + 全行明细 + 导出 |
| 对外 API | CustomerQueryApi / LeadApi / ClaimApi / TouchTaskQueryApi / TagApi |

### 1.2 明确不负责
- ❌ **Flowable 引擎直接操作**：只通过 `WorkflowApi` 发起/查询流程
- ❌ **资产投放审批**：归 `business-application-center`
- ❌ **中场支持审批**：归 `business-application-center`
- ❌ **绩效计算**：归 `performance-engine-center`
- ❌ **产品字典维护**：归 `portal-content-center`
- ❌ **员工组织结构维护**：归 `auth-permission-center`

### 1.3 并发与一致性边界
- **线索审批**：通过 `workflow-center` 异步流程 + 事件回写，保证最终一致
- **认领争抢**：依赖数据库唯一键 `UK(cust_id, org_id)` 做互斥，无分布式锁
- **触达幂等**：依赖 `UK(touch_task_id, client_uuid)` 做去重
- **标签导入**：整批事务 + 乐观锁，一失败整批回滚

## 4. 错误码（前缀 CUST）

### 4.1 错误码规范
- **前缀**：CUST
- **格式**：`CUST-XXYYY`
  - XX：HTTP 类别（40x/50x）
  - YYY：3 位业务序号

## 7. 事务边界

### 7.1 事务场景矩阵
| 场景 | 事务范围 | 隔离级别 |
|---|---|---|
| 单条线索新建 | 单实体 | READ_COMMITTED |
| 单条线索提交审批 | 单实体 + 调用 WorkflowApi | READ_COMMITTED |
| 批量导入执行 | 批次 + 多行 cust_lead + WorkflowApi | READ_COMMITTED |
| 标签批量导入 | cust_tag_rel 全量覆盖 | READ_COMMITTED |
| 认领操作 | cust_claim + touch_task + WorkflowApi | READ_COMMITTED |
| 触达成功 | touch_task + touch_log + 事件 | READ_COMMITTED |
| 线索审批回调 | cust_lead + cust_master + 事件 | READ_COMMITTED |

### 7.2 事务边界设计原则
1. **事务内不调远程接口**：`WorkflowApi.startProcess` 也是同模块调用（在一个 Spring 上下文内），视为本地调用，可包含在事务内
2. **事件发布使用本地事件总线**：`ApplicationEventPublisher` → `@TransactionalEventListener(phase=AFTER_COMMIT)` 保证事务提交后才发布
3. **异步监听器标注 `@Async`**：避免阻塞主事务

### 7.3 示例代码
```java
@Service
public class LeadService {
    @Transactional
    public Long submitLead(Long leadId) {
        // 1. 查询线索
        CustLead lead = leadMapper.selectById(leadId);
        // 2. 校验状态
        if (!LeadStatus.DRAFT.equals(lead.getLeadStatus())) {
            throw new BizException(CustomerErrorCode.LEAD_NOT_DRAFT);
        }
        // 3. 幂等校验 cust_name
        validateCustNameUnique(lead.getCustName(), leadId);
        // 4. 生成 business_key
        String businessKey = "LEAD:" + leadId;
        // 5. 调用 WorkflowApi 发起流程
        String processInstanceId = workflowApi.startProcess(
            "lead_approve_v1", businessKey, Map.of("leadId", leadId));
        // 6. 更新线索状态
        leadMapper.updateStatusAndProcess(leadId, LeadStatus.PENDING_APPROVAL, businessKey);
        // 7. 发布事件（AFTER_COMMIT）
        eventPublisher.publishEvent(new LeadSubmittedEvent(leadId));
        return leadId;
    }
}
```

## 14. 风险与注意事项

### 14.1 常见坑
1. **基础可见性冻结口径违反**：新增查询接口时忘记接入 `cust_claim` 过滤 → 代码审查必须检查
2. **lead.cust_name 幂等规则遗漏**：提交审批时忘记查 `cust_master` → 导致脏数据
3. **批次不允许重提**：业务人员期望"重试" → 必须文档/UI 明确
4. **触达照片 URL 泄漏**：审计日志直接打印照片 URL → 违反脱敏规范
5. **跨机构历史越权**：在普通详情接口加 `includeHistory=true` 参数 → 严禁
6. **认领后触达任务创建失败**：事务边界问题 → 认领成功但任务未创建 → 必须同事务

### 14.2 性能注意事项
1. **客户列表**：EXISTS 子查询需要 `cust_claim(cust_id, org_id, claim_status)` 联合索引
2. **触达日志照片**：`photo_urls` JSON 字段不建索引，前端分页展示
3. **批次审批回写**：批次内记录多（5000 行）时需要分批 UPDATE（每批 500 行）
4. **标签导入覆盖**：大客户标签（万级）时 `DELETE + INSERT` 可能锁表 → 改为 `差异化 UPDATE`
