# 客户营销中心 — 后端架构

> 本文只保留稳定的职责边界、分层和组件归属；实现与依赖以源码和 `customer-marketing-center/pom.xml` 为准。

## 1. 职责边界

本模块负责客户营销主档、线索、标签、认领/转交、触达、跨机构营销和资产立项。认证与数据范围来自 `auth-permission-center`，流程交互来自 `workflow-center`，字典/文件/通知来自 `system-governance-center`。模块不直接操作这些模块的 Mapper、Entity 或私有表。

`CUSTOMER_MARKET_CUSTOMER` 是营销客户主档；`CUST_MASTER` 仅由 M98 兼容读取/同步场景使用。资产立项表、加急表和其流程回调由本模块负责；业务申请中心只调用本模块的 `AssetProjectQueryApi`。

## 2. 依赖关系

| 依赖 | 当前用途 |
|---|---|
| `common-web` / `common-trace` / `common-security` / `common-aop` / `common-db` | 统一响应、链路、鉴权、审计和 MyBatis 基础能力 |
| `auth-permission-center` | 当前用户、用户/机构查询、角色和 `BizScopeApi` |
| `workflow-center` | 启动流程、查询任务/历史、接收 `ProcessCompletedEvent` |
| `system-governance-center` | `DictApi`、`FileApi`、`NotifyApi` 和公共审计能力 |
| MyBatis-Plus / EasyExcel | 持久化和导入导出实现 |

本模块不依赖 `portal-content-center`；产品等其他业务资料不能通过未声明的跨模块引用进入本模块。

## 3. 分层与组件归属

```text
controller -> service -> mapper/entity
     |           |
     v           +--> auth / workflow / governance API
    DTO

workflow ProcessCompletedEvent -> listener -> 条件状态更新 -> 领域事件/通知
```

| 层 | 归属与边界 |
|---|---|
| `api` | `CustomerQueryApi`、`LeadApi`、`TagApi`、`ClaimApi`、`TouchTaskQueryApi`、`AssetProjectQueryApi` 及 DTO；跨模块只读契约 |
| `controller` | 客户、线索、标签、认领、触达、跨机构营销、资产立项及管理端 REST；声明 `@BizAuth`，组装统一响应 |
| `service` | 业务校验、状态机、数据范围、主办权/认领、导入导出、资产立项与加急事务 |
| `facade` | 实现 `api` 并将 Entity 转为 DTO；隐藏 Mapper 和内部字段 |
| `mapper/entity` | 维护本模块实体和表映射；新访问统一使用 MyBatis-Plus，复杂查询保留 XML |
| `listener/event` | 处理线索、触达、资产立项和跨机构流程结果，发布本域事件 |
| `job/quartz` | 需要调度的同步/统计任务接入平台 Quartz；不在业务 Service 中自行创建调度器 |

## 4. 关键一致性边界

- 线索提交与资产立项提交在业务事务内启动 workflow-center 流程并保存流程实例；流程完成后由 `@TransactionalEventListener(AFTER_COMMIT)` 监听器在 `REQUIRES_NEW` 事务中条件更新业务状态。
- 客户主办权、认领、标签导入和资产立项使用行锁或 `lock_version`/条件更新防止并发覆盖；具体规则见 `06-并发与事务策略.md`。
- 列表、详情、导出和管理端查询必须应用统一数据范围；写操作必须基于目标行二次鉴权。
- 审计由 `@AuditLog` 与公共审计能力记录；敏感字段由统一脱敏规则处理。

## 5. 资源与契约维护

非白名单 REST 方法必须在 `PT_RESOURCE` 登记，并与 `@BizAuth` 的业务类型、动作和 URL 一致。修改 Controller、DTO、公开 API、错误码或事件字段时同步更新 `03`、`04`、资源数据和契约检查；本文不保留重复类清单、版本号或测试执行记录。
