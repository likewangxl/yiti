# 绩效计算中心后端架构

> 模块：performance-engine-center
> 本文只保留稳定的边界和架构决策；类、端点和字段清单以源码及 03 文档为准。

## 1. 模块边界

绩效中心是 Spring Boot 模块化单体中的业务模块，负责指标、KPI、目标、客户分配、计算任务、评价和导入导出。认证/RBAC、组织用户、字典、文件、调度和流程能力由平台模块提供。

结果数据按 EMP、ORG、CUST 维度写入本模块结果表；上游数据通过数据任务状态接口进入计算链路。报表等消费者只能通过本模块 api/ 下的公开 API 或受控查询契约访问，不得依赖 mapper、entity 或私有实现。

## 2. 依赖与分层

稳定的跨模块依赖为：

| 依赖 | 用途 |
| --- | --- |
| auth-permission-center | 当前用户、用户目录、权限和数据范围 |
| system-governance-center | 字典、审计、文件、Quartz JobApi、锁及公共 Web 能力 |
| workflow-center | 调整审批命令/查询和流程完成事件 |
| customer-marketing-center | 客户主数据与客户查询 |
| portal-content-center | 通讯录/员工信息等受控查询 |

模块内保持 api、controller、facade、service、mapper、entity、config 分层。Controller 负责协议和参数校验，Facade 负责跨服务编排与对外 DTO，Service 负责业务规则和事务，Mapper 负责持久化。跨模块调用从 facade 进入，禁止把数据库对象作为模块契约。

## 3. 数据版本与计算架构

SYS_CONTROL 是结果读取的版本指针。版本初始化、切换、回滚由 Service 在事务内完成，由 Facade 持有 LockManager 锁；发布完成后再发布模块事件。指标计算先解析有效版本，再按维度路由到结果宽表；槽位和动态列名必须经过服务层校验。

单指标异步执行采用“预建任务 + 后台执行”：请求阶段校验日期、版本和权限并写入 PENDING，计算线程更新 RUNNING/成功或失败；线程池提交被拒绝时立即写 FAILED。批量级别计算写入独立的 PERF_METRIC_CALC_TASK/LOG，并保持前置级别与机构阶段的顺序。试运行只读执行，不写运行任务或结果表。

KPI 计算不以一个长事务包住整批主体，单主体失败隔离；运行任务/计算日志单独记录失败状态。指标计算完成后的 KPI 级联监听在事务提交后异步执行，使用 LockManager 防重，失败由健康检查或运维查询发现，不回滚已提交的指标结果。

## 4. 审批与异步事件

分配调整由 workflow-center 承载审批。流程完成事件在 AFTER_COMMIT 阶段消费，落库 listener 使用独立事务；批准才写入生效关系，拒绝只更新申请状态。目标调整当前是提交即生效的本地事务路径，并在提交后发布领域事件。事件消费者必须幂等，通知或后续计算失败不得反向修改已提交数据。

导入和导出都以批次/任务状态作为可观察边界。文件对象经 system-governance-center 的 FileApi 写入 OBS；业务表只保存文件引用。导出提交、状态查询和下载分离，过期或失败任务不返回文件内容。

## 5. 调度决策

应用通过 PerformanceSchedulingConfig 开启本地调度，仅承载指标调度健康巡检。MetricSchedulerService 仍负责启动同步和注销入口，但当前 register 不向 SYS_JOB_CONF/Quartz 写入任务；任何自动调度是否启用以源码和治理模块实际配置为准，不在模块文档中维护一份任务清单。

## 6. 安全架构

业务 Controller 使用源码标注的 BizAuth 和 PT_RESOURCE。读取、详情、统计和导出在服务层执行统一数据范围；写操作再次按目标对象校验权限。试运行 SQL/Groovy、回算、版本切换、审批、导入和敏感导出按高风险动作审计，日志统一脱敏。

## 7. 失败与一致性原则

- 输入校验、业务校验和数据范围校验在写入前完成，未知状态和查询异常按 Fail Close 处理。
- 唯一键、版本字段和状态转换由数据库约束与 Service 双重保护；重复提交返回既有任务或明确冲突。
- 事务只覆盖同一业务边界，跨事务动作通过 AFTER_COMMIT 事件或任务状态衔接。
- 不在业务模块复制 Session、锁、对象存储或调度实现；公共能力的配置和生命周期由平台模块负责。
