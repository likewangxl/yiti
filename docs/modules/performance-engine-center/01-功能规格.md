# 绩效计算中心功能规格

> 模块：performance-engine-center
> 本文只描述当前代码提供的业务能力；接口细节以同目录 03-接口设计与报文.md 和源码为准。

## 1. 职责与边界

绩效计算中心负责指标定义、指标结果计算、KPI 方案与得分、目标值、客户分配关系、调整审批、数据导入导出以及考核评价。结果按员工（EMP）、机构（ORG）、客户（CUST）维度保存，并通过 SYS_CONTROL 指向当前可见数据版本。

模块不拥有认证、组织主数据、字典、文件对象、流程引擎或客户主数据；这些能力通过对应模块的公开 API 使用。指标结果上报入口 /api/data-task/status 供数据任务调用，不把上游表直接暴露给其他模块。

## 2. 数据版本与结果

SYS_CONTROL 按 scope_dim 保存最新数据日期、当前版本和有效标记。初始化、切换和回滚在服务事务内完成，切换时先使旧有效记录失效，再写入新有效记录；Facade 使用平台 LockManager 防止同一维度并发切换。查询类业务先读取有效控制记录，再以 data_date + version 读取结果宽表。

指标结果写入 EMP_INDEX_RESULT、ORG_INDEX_RESULT 或 CUST_INDEX_RESULT。PERF_METRIC_DEF.val_slot 与维度共同定位宽表的 val_n 列，服务在拼接列名和写入前校验槽位范围；维度为空的定义不进入宽表计算。

## 3. 指标定义与计算

指标定义的核心属性为编码、名称、维度、层级、频率、计算模式、计算逻辑、表达式或 SQL、引用指标、汇总规则、槽位和状态。当前状态包含 DRAFT、ACTIVE、DISABLED（兼容数据中可能出现 PUBLISHED）；软删除记录不参与查询和计算。

计算逻辑由源码支持的执行器决定：SQL 和表达式（Groovy）走通用计算路径；PROC、SUMMARY 由相应业务路径处理或排除自动调度。引用指标按其 token 指定的取值日期和当前数据版本读取。结果写入前清理同一日期、版本和槽位的旧值，随后批量落库；单主体失败不应污染其他主体的结果。

指标可执行方式：

- 试运行执行已保存定义或新建页面提交的临时 SQL/表达式，只返回样本，不写结果宽表，也不创建 PERF_RUN_TASK。
- 单指标执行默认异步。请求先校验日期和版本并创建 PENDING 运行任务，后台完成计算；线程池拒绝时任务标记 FAILED。同步请求直接返回实际终态。
- 批量入口按指标级别登记 PERF_METRIC_CALC_TASK，检查前置级别；员工/客户阶段完成后再计算机构阶段，单指标失败记录在任务中。

自动指标的资格由 ACTIVE、AUTO、未软删除、有维度且不是 PROC/SUMMARY 共同决定。应用启动会按配置同步可调度定义；指标调度注册当前由 MetricSchedulerService.register 短路，注销仍调用治理模块 JobApi。本地调度仅用于健康巡检。

## 4. KPI 与目标

KPI 方案由方案主表和指标项组成。指标项关联指标、维度、权重、倍数、上下限、公式和 SQL 表达式。计算读取指定数据日期、版本、目标值和基础值：

1. 以指标槽位取得实际值，缺失实际值按计算服务约定处理；
2. 使用指标项公式计算原始分并按最小/最大分截断；
3. 按权重加权，权重总和必须大于零，结果写入 KPI_RESULT/评分表，并保留明细 JSON；
4. 单主体异常隔离，批次状态和计算日志保留成功、跳过、失败数量。

目标方案绑定 KPI 方案，目标值按方案、主体、周期键和指标唯一定位；单条与批量写入均校验主体、方案和指标关系。当前目标调整入口提交后在同一服务事务中直接 upsert 目标值并发布领域事件，申请记录保留变更信息。

## 5. 客户分配与调整

CUST_ALLOC_RELATION 保存客户、业务种类、分配维度、员工、比例、有效期和来源批次等关系。查询支持当前关系、历史关系、汇总和按员工/客户的批量查询。分配调整申请主表与明细表保存申请快照和审批信息，支持创建、草稿、提交、撤回、待办/已办/我的申请、详情和审批历史。审批完成监听器在独立事务中更新关系并发布后续事件；失败或拒绝不应部分写入。

原分配预览的当前查询口径见 原业绩分配预览查询口径.md，该文档只保留仍被页面和服务使用的查询规则。

## 6. 数据导入、导出与展示

导入入口按 importType 接收文件，建立导入批次，校验并写入对应业务表；批次、错误行、源文件和重试均可查询。文件对象统一经治理模块 FileApi 保存到 OBS。需要整批一致的导入在一个事务中完成，错误批次不作为有效结果发布。

绩效导出支持 KPI、指标、分配关系和明细四类提交及任务查询；导出任务记录状态、文件引用、行数、大小和过期时间。财务统计展示、员工/客户指标卡片、运行任务和员工搜索提供只读查询。

## 7. 考核评价与奖励

评价子域维护评价标签、用户标签、评价规则及规则组，创建评价任务后为符合规则的被评价人生成目标；评价人只能对被授权目标提交一次评分，任务关闭或批量提交后按规则组加权计算最终分。奖励待办、奖励批次、分配导入与发布、统一任务查询均由 /api/eval 和 /api/admin/eval 下的当前控制器提供。

## 8. 权限与审计

管理接口使用 BizType.PERF_CONFIG，KPI 结果计算查询使用源码标注的 KPI_CALC，评价接口使用 EVAL。所有读取、详情和导出都在服务层应用数据范围；写操作在服务层重新校验目标对象。指标试运行、计算、回算、版本切换、导入、调整审批和敏感导出均记录审计事件，原因字段按接口约束提供。手机号、账号、证件号、金额及凭据不得以明文写入日志。

## 9. 对外调用约定

可被其他模块调用的接口只限 api/ 下的 *Api/*QueryApi 及 DTO。当前公开能力覆盖客户分配、客户名称、数据任务状态、KPI、指标、目标、审批和运行任务查询；不得通过 mapper、entity 或私有表跨模块调用。流程审批只由 workflow-center 直接访问 Flowable，绩效通过审批 API/事件协作。
