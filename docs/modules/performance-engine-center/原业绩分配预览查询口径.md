# 业绩调整 ·「原业绩分配」预览查询口径

> 适用页面：xanzc 前端 **新建调整申请**（以及查看/审批的只读回显）「原业绩分配」区。
> 最近核对：2026-08-27（当前原分配按 `CUST_ALLOC_RELATION` 最新来源批次读取，员工登录名批量解析）。

## 1. 调用链路

```
Adjust.vue loadPreview()
  └─ GET /api/report/alloc-preview?custNo=&allocDim=&custType=&accountNo=&statisDt=
       └─ report: AllocPreviewController.preview(...)            // 只取 custNo + allocDim
            └─ perf: AllocApi.getLastApprovedAllocPreview(custId, allocDim)
                 └─ AllocAdjustPreviewService.getLastApprovedAllocPreview(custId, allocDim)
                      └─ CustAllocRelationMapper.selectCurrentOriginalByCust(custId, allocDim)
```

- 报表端点 `/api/report/alloc-preview` 还接收 `custType / accountNo / statisDt`，但**实际查询只用 `custNo(=custId)` + `allocDim`**，其余参数被忽略。
- 前端把 `dlg.form.custId` 作为 `custNo` 传给报表端点（cust_no 字段已并入 cust_id，值即用户输入的客户编号）。

## 2. 前端触发条件（Adjust.vue）

- 监听 `[dlg.form.custId, dlg.form.allocDim]`：当**客户编号长度 ≥ 2** 且（客户编号或分配维度）变化时，**防抖 600ms** 后调 `loadPreview()`。
- 查看 / 审批的**只读模式不实时查**，直接读提交时快照。
- `allocDim=NEW`（新开户）不要求原业绩分配，页面不应把其他维度的当前关系当作原分配。
- `hasOriginalOwners = (preview.allocList.length > 0)` —— 决定页面是"只读展示历史原业绩分配"还是"手工录入原业绩分配"，并影响"交原业绩所属人审批"是否可选。

## 3. 后端查询条件（权威口径）

当前新增/编辑页面的核心 SQL（`selectCurrentOriginalByCust`）：

```sql
WITH candidate_rows AS (
    SELECT <base columns>,
           CASE
             WHEN source_batch_id IS NULL OR TRIM(source_batch_id) = ''
               THEN CONCAT('ROW:', id)
             ELSE CONCAT('BATCH:', source_batch_id)
           END AS batch_key
    FROM CUST_ALLOC_RELATION
    WHERE cust_id = #{custId}       -- ① 客户编号匹配
      AND is_original = '2'         -- ② 当前原分配
      -- ACCOUNT 仅保留 ACCOUNT；RULE/null 保留 RULE + ACCOUNT
), ranked_batches AS (
    SELECT batch_key,
           MAX(source_process_date) AS batch_process_date,
           MAX(created_time) AS batch_created_time,
           MAX(id) AS stable_id
    FROM candidate_rows
    GROUP BY batch_key
), latest_batch AS (
    SELECT batch_key
    FROM ranked_batches
    ORDER BY batch_process_date DESC,
             batch_created_time DESC,
             stable_id DESC,
             batch_key DESC
    LIMIT 1
)
SELECT <base columns>
FROM candidate_rows
WHERE batch_key IN (SELECT batch_key FROM latest_batch)
ORDER BY (alloc_dim = 'ACCOUNT'), emp_id ASC, id ASC;
```

`source_batch_id` 非空时，同一批次的全部关系行共享一个 `batch_key`；`NULL` 或空白批次号的历史行使用自身 `id` 独立成批次。批次选择先比较 `source_process_date`，再比较 `created_time`，最后用稳定主键/批次键消歧；选中批次后返回该批次的全部候选行。

### 条件汇总

| # | 条件 | 说明 |
|---|------|------|
| ① | `cust_id = 用户输入的客户编号` | cust_no 字段已删除并入 cust_id |
| ② | `is_original = '2'` | 只取当前原分配关系 |
| ③ | `alloc_dim` 维度候选 | `allocDim=ACCOUNT` → 只在 ACCOUNT 候选中选最新批次；`allocDim=RULE` 或空 → 在 RULE + ACCOUNT 候选中选整体最新批次 |
| ④ | 来源批次 | 非空 `source_batch_id` 分组；空/NULL 按自身 `id` 独立成批次 |
| ⑤ | 批次排序 | `source_process_date DESC` → `created_time DESC` → 稳定主键/批次键 DESC |
| ⑥ | 返回顺序 | 仅返回选中批次的全部关系行，按 RULE 优先、ACCOUNT 其次，再按 `emp_id`、`id` 稳定排序 |

## 4. 关键说明

- 新增/编辑时的自动预览来源是实时 `CUST_ALLOC_RELATION` 当前有效关系；保存草稿或提交时，后端将该关系复制为申请内 `ORIGIN` 快照，后续编辑和详情优先使用快照，避免当前关系变化覆盖申请内容。
- 申请详情优先读取该申请内已保存的 `ORIGIN` 快照；旧数据或 RULE/ACCOUNT 草稿缺少 ORIGIN 快照时，才回退当前有效关系。`NEW` 维度不回退当前关系。
- 预览直接读取关系行快照：`empChnName=fullname`（PT_USER.USERCHNNAME）、`orgCode=dept_no`、`orgName=dept_name`、`ratio=ratio`；`empId=emp_id` 保存 PT_USER.USER_ID。
- `username` 不从关系表猜测：由 perf 通过 `UserApi.mapEmpIdsToUsername` 对本批次去重后的 `empId` 一次批量映射为 PT_USER.USERNAME；用户不存在或映射为空时回退展示 `empId`，禁止逐行 N+1 查询。
- 保存草稿/提交时，预览关系可复制为申请内 `ORIGIN` 快照；申请详情优先读该快照。快照 `username` 为空的历史申请仍回退展示工号。
- 某维度查不到记录 → 该维度返回空，前端转为"手工录入原业绩分配"。
- `custId` 为空 → 直接返回空列表，不查表。
