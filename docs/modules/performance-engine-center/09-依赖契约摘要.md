# 绩效计算中心 — 依赖契约摘要

> 模块: performance-engine-center
> 版本: v1.0
> 最后更新: 2026-04-10
>
> **说明**: 本文档摘录自被依赖模块的对外 API 契约, 仅供绩效计算中心开发时快速查阅。如有冲突, 以源模块文档为准。

---

## 依赖关系图

```
performance-engine-center
    │
    ├── (S强依赖) auth-permission-center        # 鉴权、数据范围、组织树
    │
    ├── (S强依赖) system-governance-center      # 字典、审计、通知、调度、日历、文件
    │
    ├── (S强依赖) workflow-center                # 工作流引擎
    │
    └── (S强依赖) customer-marketing-center     # 客户信息
```

所有依赖均为"强依赖 (S)", 即 performance-engine-center 启动时如发现任一依赖模块 Bean 不可用, 应阻止启动并记录异常。

### 1.2 权限资源申请

本模块在 `PT_RESOURCE` 中登记的资源 (见 `08-初始化数据清单.md` 第 5 节), 需要:
- `bizModule = 'performance-engine-center'`
- 资源码以 `PERF_` 开头, 便于按模块筛选

### 1.3 BizScope 解析示例

```java
// 查询 KPI 结果列表前解析数据范围
BizScope scope = bizScopeApi.resolveScope(currentEmpId, "PERF_CONFIG");
// scope 可能返回:
// - type = ALL           (系统管理员, 无过滤)
// - type = ORG_SUBTREE   (按机构子树过滤, orgCodes = [...])
// - type = OWN           (只看自己, empIds = [当前emp_id])
// - type = CUSTOM        (自定义范围, 具体逻辑由业务决定)

// 应用到 MyBatis 查询
if (scope.getType() == ScopeType.ORG_SUBTREE) {
    params.put("orgCodeRange", scope.getOrgCodes());
} else if (scope.getType() == ScopeType.OWN) {
    params.put("empId", currentEmpId);
}
```

### 1.4 @BizAuth 注解集成

所有 performance 接口必须使用 `@BizAuth` 注解:

```java
@BizAuth(
    resourceCode = "PERF_METRIC_EXECUTE",
    action = "EXECUTE",
    bizModule = "performance-engine-center",
    dataScope = DataScope.ORG_SUBTREE,
    requireReason = true
)
@PostMapping("/api/perf/metrics/{metricCode}/execute")
public Result<MetricRunDTO> executeMetric(...) { ... }
```

### 2.4 JobApi (任务调度 API)

| 接口 | 方法签名 | 用途 |
|---|---|---|
| `JobApi` | `String startJobRun(String jobCode, Map<String, Object> params)` | 通知治理中心某定时任务开始, 返回 runId |
| `JobApi` | `void completeJobRun(String runId, Map<String, Object> result)` | 报告任务成功 |
| `JobApi` | `void failJobRun(String runId, String errorMsg)` | 报告任务失败 |
| `JobApi` | `JobRunDTO getJobRun(String runId)` | 查询任务运行记录 |

**本模块调度任务**: `DAILY_METRIC_CALC`、`DAILY_KPI_CALC`、`DAILY_ALLOC_SYNC`、`CLEAN_PERF_RUN_TASK` (见 `08-初始化数据清单.md` 第 4 节)

**任务执行模板**:
```java
@Bean
public Object metricCalcJobBean() {
    return new Object() {
        public void runDailyCalc(Map<String, Object> params) {
            String runId = jobApi.startJobRun("DAILY_METRIC_CALC", params);
            try {
                MetricRunResult result = metricCalcService.runDaily(params);
                jobApi.completeJobRun(runId, Map.of(
                    "totalMetrics", result.getTotal(),
                    "successMetrics", result.getSuccess(),
                    "failedMetrics", result.getFailed()
                ));
            } catch (Exception e) {
                jobApi.failJobRun(runId, e.getMessage());
                throw e;
            }
        }
    };
}
```

### 2.5 CalendarApi (工作日历 API)

| 接口 | 方法签名 | 用途 |
|---|---|---|
| `CalendarApi` | `boolean isWorkingDay(LocalDate date)` | 判断是否工作日 (排除法定节假日和调休) |
| `CalendarApi` | `LocalDate getLastWorkingDay(LocalDate date)` | 获取 date 前最近一个工作日 |
| `CalendarApi` | `LocalDate getNextWorkingDay(LocalDate date)` | 获取 date 后最近一个工作日 |
| `CalendarApi` | `List<LocalDate> getWorkingDaysBetween(LocalDate start, LocalDate end)` | 获取区间内所有工作日 |
| `CalendarApi` | `int getWorkingDaysCount(LocalDate start, LocalDate end)` | 计算工作日数量 (用于日均值计算) |

**本模块使用场景**:
- 考核周期边界计算 (月度 KPI 以工作日结尾为最后考核日)
- 日均指标的"工作日数" N 用于 `日均 = 累计值 / N` 的分母
- 判断指标计算任务的触发时机

**示例**:
```java
// 计算某月日均值的分母
LocalDate monthStart = LocalDate.of(2026, 4, 1);
LocalDate monthEnd = LocalDate.of(2026, 4, 30);
int workingDays = calendarApi.getWorkingDaysCount(monthStart, monthEnd);
BigDecimal dailyAvg = totalAmount.divide(BigDecimal.valueOf(workingDays), 4, RoundingMode.HALF_UP);
```

### 3.3 流程定义映射

本模块在 workflow-center 注册两个流程定义:

| processKey | 流程名 | 触发接口 |
|---|---|---|
| `target_adjust_approve_v1` | 目标修正审批 | `POST /api/perf/target-adjust-apply` |
| `alloc_adjust_approve_v1` | 分配关系调整审批 | `POST /api/perf/alloc-adjust-apply` |

**流程部署**: 流程定义 BPMN 文件位于 `performance-engine-center/src/main/resources/workflow/bpmn/`, 启动时由 `FlowableBootstrapService` 自动部署。

### 3.4 BusinessKey 格式

| 业务 | BusinessKey 格式 | 示例 |
|---|---|---|
| 目标修正 | `TARGET_ADJUST:{applyId}` | `TARGET_ADJUST:118` |
| 分配关系调整 | `ALLOC_ADJUST:{applyId}` | `ALLOC_ADJUST:89` |

BusinessKey 是 performance 和 workflow 之间的唯一关联, 必须唯一且可反查。

### 3.5 启动流程示例

```java
// 发起目标修正审批
StartProcessCmd cmd = StartProcessCmd.builder()
    .processKey("target_adjust_approve_v1")
    .businessKey("TARGET_ADJUST:" + apply.getId())
    .starterEmpId(currentEmpId)
    .starterOrgCode(currentOrgCode)
    .variables(Map.of(
        "applyId", apply.getId(),
        "applyNo", apply.getApplyNo(),
        "planId", apply.getPlanId(),
        "metricCode", apply.getMetricCode(),
        "subjectType", apply.getSubjectType(),
        "subjectId", apply.getSubjectId(),
        "oldValue", apply.getOldTargetValue(),
        "newValue", apply.getNewTargetValue(),
        "reason", apply.getReason(),
        "ownerOrgId", apply.getOwnerOrgId()
    ))
    .attachments(null) // 目标修正一般无附件
    .build();
StartProcessResult result = workflowApi.startProcess(cmd);
// 保存流程实例 ID
apply.setProcessInstanceId(result.getProcessInstanceId());
apply.setBusinessKey(cmd.getBusinessKey());
apply.setStatus("IN_APPROVAL");
```

### 7.2 兼容性原则

- 依赖方 API 升级时必须保证**向后兼容** (只增不删)
- 如必须破坏性变更, 提前 1 个迭代周期通知 performance 模块
- 契约变更走 ADR (Architecture Decision Record) 流程

### 7.3 健康检查

performance-engine-center 启动时在 `HealthIndicator` 中检查依赖 Bean 可用性:

```java
@Component
public class DependencyHealthIndicator implements HealthIndicator {
    @Override
    public Health health() {
        Map<String, Object> details = new HashMap<>();
        details.put("auth", checkBean(CurrentUserApi.class));
        details.put("governance", checkBean(DictApi.class));
        details.put("workflow", checkBean(WorkflowApi.class));
        details.put("customer", checkBean(CustomerQueryApi.class));
        boolean allHealthy = details.values().stream().allMatch("UP"::equals);
        return allHealthy ? Health.up().withDetails(details).build()
                          : Health.down().withDetails(details).build();
    }
}
```
