# 绩效计算中心初始化与配置要求

> 本文只记录当前运行所需的配置和初始化边界，不承载建表、种子 SQL 或环境执行记录。数据库结构以目标库和获准的 DBA 变更为准。

## 1. 初始化前提

部署前必须具备：

- 根 POM 聚合的绩效模块及其公开依赖；
- auth-permission-center 的用户、组织、资源和角色数据；
- system-governance-center 的字典、审计、文件（OBS）、锁和 JobApi；
- workflow-center 中与分配/目标调整对应的流程及候选人配置；
- customer-marketing-center/portal-content-center 提供的客户和员工查询契约。

SYS_CONTROL 的 EMP、ORG、CUST 维度必须先建立可用基线，指标结果上报和计算才可按版本读取。可以通过当前 sys-control 初始化接口幂等建立基线；具体基线日期、版本号和权限由部署工单确定，不在文档固化环境值。

## 2. 字典要求

字典由治理模块统一维护，绩效服务按代码读取，不在本模块复制字典表。评价导入和展示当前依赖：

- EVAL_IMPORT_TYPE：评价/奖励导入类型；
- EVAL_WEIGHT_TAG：评价权重标签；
- EVAL_SCORE_TYPE：评分类型。

指标、目标、分配、运行任务和导入状态以服务中的枚举/校验为准；新增字典项必须同步服务校验和前端使用方。

## 3. 资源与角色

所有非白名单 Controller 方法都要在 PT_RESOURCE 登记与 HTTP 方法、路径匹配的资源，并绑定源码使用的 BizAuth。部署校验至少覆盖指标、KPI、目标、导入、分配调整、目标调整、版本控制、计算/回算、导出、运行任务、统计展示和评价管理/评分资源。

角色授权由 auth-permission-center 管理，至少区分：

- 绩效配置/管理员：维护定义、方案、目标和导入；
- 计算/运维：触发计算、回算并查询任务；
- 分配/目标审批人：仅处理其数据范围内的审批；
- 评价管理员与评价参与者：分别维护规则/任务和提交评分；
- 普通业务用户：只读本人或数据范围内的结果。

资源清单和角色授权不得从本文复制静态数量；以 PT_RESOURCE、角色表和当前 Controller 注解的交集为验收依据。

## 4. 运行配置

| 配置项 | 作用 |
| --- | --- |
| perf.engine.groovy-enabled | 是否允许表达式执行 |
| perf.engine.sql-timeout-seconds | SQL/Groovy 执行超时 |
| perf.engine.cascade-max-depth | 指标级联深度上限 |
| perf.engine.import-batch-size | 导入批量写入大小 |
| perf.scheduler.startup-sync.enabled | 是否在应用就绪时扫描可调度指标 |
| perf.scheduler.health-check.enabled | 是否启用本地调度健康巡检 |
| perf.import.local-dir | 兼容读取旧本地导入文件的目录；新文件经 FileApi |
| perf.eval.import.batch-insert-size | 评价导入批写大小 |
| perf.eval.import.error-keep | 评价导入错误明细保留上限 |
| perf.eval.import.compensation.enabled | 是否启用评价导入补偿检查 |
| perf.job.run-task-cleanup.retention-days | 成功运行任务清理保留周期 |
| perf.job.sys-control-cleanup.keep-count | SYS_CONTROL 历史记录保留量 |

当前 scheduler 注册入口不向 Quartz 写入指标任务；健康巡检和启动扫描只按配置执行检查。修改配置必须在实际 profile 中核对，并重启后验证日志和治理 JobApi 状态。

## 5. 文件与外部服务

导入源文件、错误文件、评价模板和导出文件必须通过 FileApi 管理并保存对象引用；不得把新流程切回本地文件或另建对象存储客户端。外部 API 的地址、凭据和开关由 bootstrap/application 配置管理，不写入初始化文档。

## 6. 初始化验收

初始化完成后按目标环境只读核验：

1. 三个结果维度存在有效 SYS_CONTROL 基线；
2. PT_RESOURCE 与 Controller 路径/方法/BizAuth 一致；
3. 角色可访问的资源符合数据范围，未授权请求被拒绝；
4. 字典、FileApi、JobApi、LockManager 和 workflow 依赖可用；
5. 用非生产样例完成指标试运行、任务状态查询、导入源文件查询和导出任务查询。

验收命令、SQL 和环境特定数据放在部署工单或受控脚本中，不提交到本模块初始化文档。
