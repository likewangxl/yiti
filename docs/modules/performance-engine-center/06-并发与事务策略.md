# 绩效计算中心并发与事务策略

> 本文描述当前实现采用的并发、事务和异步边界。具体状态值与接口参数以源码和 03 文档为准。

## 1. 基本原则

业务写入以数据库事务和唯一约束保证原子性；跨模块动作通过公开 API 或提交后事件衔接。锁只用于保护无法由单条 SQL 解决的竞态，不把锁当作业务状态。未知状态、数据范围校验失败和依赖查询异常均 Fail Close。

## 2. 事务边界

| 场景 | 当前边界 |
| --- | --- |
| 指标定义、引用和槽位维护 | Service 事务；槽位锁在 Facade/Service 编排边界申请 |
| SYS_CONTROL 初始化、切换、回滚 | Facade 在事务外申请维度锁，Service 在一个事务内完成失效旧记录与写入新记录 |
| 目标值单条/批量写入 | Service 事务，按目标值唯一键执行 upsert |
| 分配/目标调整申请 | 申请主表、明细、流程业务键在同一 Service 事务内写入 |
| 分配审批完成 | workflow 事件 AFTER_COMMIT 消费；listener 使用独立事务，批准时批量写生效分配，拒绝只改申请状态 |
| 目标调整提交 | Service 单事务写申请并 upsert 目标值，提交后发布领域事件 |
| 指标计算 | 结果按主体/批次短事务或单条写入；失败任务状态独立记录，避免大事务回滚抹掉失败痕迹 |
| KPI 计算与评分 | 按主体/指标处理并 upsert 结果；计算服务不包一笔覆盖整批主体的外层事务 |
| 导入 | 批次解析、校验和对应业务写入按导入策略的事务边界执行；整批校验失败不发布有效结果 |
| 导出 | 先创建任务并更新状态，生成文件后写文件引用和行数；下载只读任务状态 |

## 3. 版本切换与槽位竞争

SYS_CONTROL 同一 scope_dim 的切换和回滚共用 LockManager 锁。获得锁后由事务原子地使旧有效记录失效并插入新记录，数据库约束作为第二道保护；释放锁失败不改变已提交结果，依靠锁租期和平台清理。

指标槽位分配在 Facade/Service 的锁保护下完成。槽位写入后不随普通编辑改变；状态切换到 ACTIVE 时补分配缺失槽位，维度为空不分配。动态宽表列只接受服务验证过的槽位。

## 4. 外部任务上报幂等

POST /api/data-task/status 以请求 taskId 作为幂等键。服务先查库，再使用平台 LockManager 对同一 taskId 互斥并二次查库，写入后释放锁；数据库唯一键仍是最终兜底。重复上报返回既有运行任务并标记为未新受理，SUCCESS/FAILED 只允许写入对应终态。

## 5. 计算任务与并发

单指标异步执行先写 PERF_RUN_TASK=PENDING，再提交后台执行器；执行器更新 RUNNING、SUCCESS 或 FAILED。提交被拒绝时任务直接 FAILED。级别批量任务先检查前置级别，非机构阶段完成后才运行机构阶段；阶段内允许受控并发，单指标失败不取消其他指标。

KPI 级联监听在指标事务提交后异步执行，以方案、周期、版本等业务键通过 LockManager 防重复。级联失败记录日志/健康状态，不回滚已提交的指标结果。

导出任务状态按实现流转，只有成功且文件引用有效时允许下载；失败、过期或不存在的任务不得返回文件。导入重试必须重新经过批次状态和权限校验，不得绕过原始校验。

## 6. 审批状态一致性

调整申请状态、流程业务键和生效表写入必须由同一消费事务协调。listener 先按业务键查申请，不存在时幂等跳过；批准只处理对应明细，拒绝不写生效表；未知 outcome 不修改业务数据。提交后事件失败不能把已提交的申请伪装成回滚。

## 7. 查询与缓存

结果查询以 SYS_CONTROL 当前版本和数据日期作为读取边界。缓存仅通过平台 CacheManager 使用，并在定义、方案、目标或版本变化后按现有实现失效；不得以缓存命中代替权限、数据范围或数据库状态判断。分配关系和目标值的高频批量写入不依赖本地缓存保证一致性。
