# 绩效计算中心 — 接口设计与报文

> 模块编码: `performance-engine-center`
> 关联文档: `01-功能规格.md` / `02-后端架构.md` / `04-对外API契约.md`
> 统一响应模型: `R<T>` / `PageResult<T>` 详见 `docs/common-dev-guide.md`

---

## 0. 通用约定

### 0.1 URL 前缀

- 业务接口统一前缀: `/api/perf`
- 外部系统上报接口前缀: `/api/data-task`

### 0.2 请求/响应格式

- Content-Type 统一 `application/json;charset=UTF-8`, 上传接口为 `multipart/form-data`
- 所有响应遵循 `R<T>`:

```json
{
  "code": "0",
  "message": "success",
  "traceId": "abcd1234ef5678",
  "data": { ... }
}
```

- 分页响应遵循 `PageResult<T>`:

```json
{
  "code": "0",
  "message": "success",
  "data": {
    "pageNo": 1,
    "pageSize": 20,
    "total": 128,
    "list": [...]
  }
}
```

### 0.3 鉴权

- 所有接口 (除 G 组外部接口) 经 `common-security` 过滤器鉴权
- 每个接口必须标注 `@BizAuth(bizType, action)`, 对应资源注册到 `PT_RESOURCE`
- `bizType` 取值:
  - `PERF_CONFIG` — 指标/KPI/目标/计算管理 (高权限)
  - `PERF_QUERY` — 绩效结果/分配关系查询 (普通用户)
  - `PERF_ADJUST` — 分配调整/目标修正申请 (普通员工可发起)

### 0.4 数据范围

所有"查询"接口通过 `DataScopeHelper` 自动注入数据范围 SQL 片段, 默认按员工/机构权限过滤。

### A.3 POST /api/perf/metrics — 新增指标

**鉴权:** `@BizAuth(bizType = "PERF_CONFIG", action = "WRITE")`

**请求体 `MetricCreateReqDTO`:**

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| metricCode | String | 是 | `@NotBlank @Size(max=64) @Pattern("^[A-Z_0-9]+$")` |
| metricName | String | 是 | `@NotBlank @Size(max=200)` |
| metricNameEn | String | 否 | `@Size(max=200)` |
| description | String | 否 | `@Size(max=1000)` |
| baseDim | String | 是 | `@NotBlank @In({"EMP","ORG","CUST"})` |
| metricLevel | Integer | 是 | `@NotNull @Range(min=1, max=3)` |
| calcFreq | String | 是 | `@NotBlank`, 取值来源字典 `PERF_CALC_FREQ` |
| calcMode | String | 是 | `@In({"AUTO","MANUAL"})` |
| calcLogicType | String | 条件必填 | `AUTO` 时必填, `@In({"SQL","PROC","EXPR","SUMMARY"})` |
| sqlText | String | 条件必填 | `metricLevel=1 && calcMode=AUTO && calcLogicType=SQL` 时必填 |
| procName | String | 条件必填 | `calcLogicType=PROC` 时必填 |
| exprText | String | 条件必填 | `metricLevel in (2,3) && calcMode=AUTO && calcLogicType=EXPR` 时必填 |
| summaryRule | String | 条件必填 | `calcLogicType=SUMMARY` 时必填, 格式 `SUM/AVG/MAX/MIN/COUNT:<metricCode>` |
| refMetricCodes | List\<String\> | 条件必填 | `metricLevel in (2,3)` 时必填, `@Size(min=1, max=20)` |
| valSlot | Integer | 否 | `@Range(min=1, max=200)`, 空则系统自动分配 |
| ownerDept | String | 否 | `@Size(max=64)` |
| remark | String | 否 | `@Size(max=1000)` |

**业务校验:**

1. `metricCode` 未在 `perf_metric_def` 中存在, 否则 `PERF-40002`
2. 层级引用严格匹配: 三级引用的 `refMetricCodes` 必须全部是二级指标, 二级引用必须全部是一级, 否则 `PERF-40003`
3. `valSlot` 在 `(baseDim, valSlot)` 不重复, 否则 `PERF-40004`
4. SQL 语法校验: Druid AST 检查仅允许 `SELECT`, 否则 `PERF-42201`
5. Groovy 语法与沙箱校验, 否则 `PERF-42202`
6. 循环依赖检查, 否则 `PERF-42206`

**响应 `R<MetricDefRespDTO>`**

### A.4 PUT /api/perf/metrics/{metricCode} — 编辑指标

**鉴权:** `@BizAuth(bizType = "PERF_CONFIG", action = "WRITE")`

**请求体 `MetricUpdateReqDTO`:** 除 `metricCode`/`baseDim`/`metricLevel`/`valSlot` 外其他字段可改, 这些核心字段一经创建不可变更 (需删除重建)。

**业务校验:** 同 A.3 的 2/4/5/6

**特殊规则:**

- 状态从 `PUBLISHED` 改到 `DISABLED` 时, 检查是否存在下游引用, 存在则 `PERF-40906`
- 从 `DRAFT` 改为 `PUBLISHED` 视为发布, 发布后状态不可回到 `DRAFT`
- 修改 `sqlText/exprText` 会触发版本自增 `perf_metric_def.version`, 审计记录 before/after

### A.8 DELETE /api/perf/metrics/{metricCode} — 删除指标

**鉴权:** `@BizAuth(bizType = "PERF_CONFIG", action = "DELETE")` (高危)

**业务规则:**

- 存在下游引用, 禁止删除, 抛 `PERF-40906`

## E. 分配关系调整

### E.1 POST /api/perf/alloc-adjust-apply — 发起分配关系调整

**鉴权:** `@BizAuth(bizType = "PERF_ADJUST", action = "WRITE")`

**请求体 `AllocAdjustCreateReqDTO`:**

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| custId | String | 是 | `@NotBlank @Size(max=64)` |
| allocDim | String | 是 | `@In({"RULE","ACCOUNT"})` |
| bizKinds | List\<String\> | 是 | `@NotEmpty`, `allocDim=ACCOUNT` 时 `@Size(max=1)` (只能单选) |
| accountNo | String | 条件 | `allocDim=ACCOUNT` 时 `@NotBlank` |
| effectiveDate | LocalDate | 是 | 不得早于今天, 不得跨入已结束年度 |
| adjustItems | List\<AllocItemReqDTO\> | 是 | `@NotEmpty @Size(min=1, max=50) @Valid` |
| remark | String | 否 | `@Size(max=500)` |
| attachmentIds | List\<String\> | 否 | 零售客户必填佐证附件 |

**`AllocItemReqDTO`:**

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| empId | String | 是 | `@NotBlank`, 必须存在于 `emp_info` 且在职 |
| ratio | BigDecimal | 是 | `@NotNull @DecimalMin("1.00") @DecimalMax("100.00")` |

**业务校验:**

1. 客户存在: 调用 `customerQueryApi.getCustomerInfo`, 不存在抛 `PERF-40012`
2. 零售客户时 `attachmentIds` 不能为空, 否则 `PERF-42203`
3. `sum(ratio) = 100.00`, 否则 `PERF-40902`
4. 同一 `empId` 不能重复, 否则 `PERF-42203`
5. `effectiveDate` 不得早于今天, 不得落入冻结年度, 否则 `PERF-40903`
6. 调用 `WorkflowApi.startProcess` 发起审批流, 对公走 `perf_alloc_adjust_corp_v1`, 零售走 `perf_alloc_adjust_retail_v1`

## G. 外部接口 (独立数据同步系统调用)

### G.1 POST /api/data-task/status — 数据处理状态上报

**鉴权:** 无前端登录, 使用 API Token (Header `X-Api-Token`), 在 `sys_api_token` 中注册, 由 `system-governance-center` 统一校验

**请求体 `DataTaskStatusReqDTO`:**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| taskId | String | 是 | 全局唯一任务 ID (幂等键), `@NotBlank @Size(max=128)` |
| dataType | String | 是 | `ALLOC_RELATION` / `EMP_INDEX_RESULT` / `ORG_INDEX_RESULT` / `CUST_INDEX_RESULT` |
| dataDate | String | 是 | `YYYY-MM-DD` |
| version | String | 是 | 版本号 |
| status | String | 是 | `SUCCESS` / `FAILED` |
| rowCount | Integer | 否 | 行数 |
| errorMsg | String | 否 | 错误信息 |
| sourceSystem | String | 否 | 来源系统标识 |
| timestamp | String | 否 | 上报时间戳 |

**幂等性:** 同一 `taskId` 重复上报时返回 `200` + 既有结果, 不重复处理

**处理逻辑:**

1. 查 `perf_run_task WHERE task_key=taskId`, 存在则直接返回既有结果
2. 不存在时创建 `perf_run_task (task_type=EXTERNAL_DATA)`, `params_json` 存请求体
3. 根据 `dataType` 触发对应的 `sys_control` 发布:
   - `ALLOC_RELATION` → `dim=CUST` 版本发布, 并触发未冻结年度的 KPI 回算
   - `EMP_INDEX_RESULT` → `dim=EMP` 版本发布
   - `ORG_INDEX_RESULT` → `dim=ORG` 版本发布
   - `CUST_INDEX_RESULT` → `dim=CUST` 版本发布
4. `status=FAILED` 时不发布版本, 但记录 `perf_run_task` 并通知资财部

**响应:**

```json
{
  "code": "0",
  "message": "success",
  "data": {
    "taskId": "EXT_20260410_ALLOC_01",
    "accepted": true,
    "perfRunTaskId": 9102
  }
}
```

## I. 校验注解说明

- `@NotBlank` / `@NotNull` / `@NotEmpty` / `@Size` / `@Pattern` / `@DecimalMin` / `@DecimalMax` / `@Range` — 标准 `jakarta.validation` 注解
- `@In` — 自定义注解, 限制字符串取值集合
- `@BizDate` — 自定义注解, 校验业务日期格式

校验失败统一由 `GlobalExceptionHandler` 转换为 `R` 响应, `code=PERF-42200`, `message` 包含字段明细。
