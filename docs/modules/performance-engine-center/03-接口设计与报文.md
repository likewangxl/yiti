# 绩效计算中心接口设计与报文

> 统一返回使用 ResponseWrapper；分页使用 PageResult；具体 DTO、校验注解和错误码以源码为准。除文件下载外，接口返回 JSON。

## 1. 通用约定

管理接口位于 /api/perf，通常使用 BizType.PERF_CONFIG；KPI 结果查询/导出使用源码标注的 KPI_CALC；评价接口位于 /api/eval 或 /api/admin/eval，使用 EVAL。Controller 的资源必须在 PT_RESOURCE 登记，Service 仍执行对象权限和数据范围校验。

高风险写操作的请求体包含 reason，并由统一审计切面记录。日期使用 yyyy-MM-dd；分页参数由各 DTO 的默认值和上限处理，不能依据本页自行推导隐藏参数。

## 2. 指标定义与执行

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/perf/metrics | 按维度、层级、状态、关键字查询指标列表；当前返回全量列表 |
| GET | /api/perf/metrics/categories | 查询指标分类 |
| GET | /api/perf/metrics/cust-index-values | 按客户、日期和指标编码读取客户指标值 |
| GET | /api/perf/metrics/{metricCode} | 指标详情 |
| GET | /api/perf/metrics/{metricCode}/refs | 查询引用指标 |
| GET | /api/perf/metrics/{metricCode}/ref-by | 查询反向引用 |
| GET | /api/perf/metrics/val-slots | 按维度查询槽位使用情况 |
| POST | /api/perf/metrics | 创建指标定义，入参 CreateMetricReqDTO |
| PUT | /api/perf/metrics/{metricCode} | 更新指标定义 |
| DELETE | /api/perf/metrics/{metricCode} | 软删除/停用指标，reason 必填 |
| PUT | /api/perf/metrics/{metricCode}/status | 切换 DRAFT、ACTIVE、DISABLED 状态，reason 必填 |
| POST | /api/perf/metrics/{metricCode}/slot/release | 释放槽位，reason 必填 |
| POST | /api/perf/metrics/{metricCode}/trial-run | 已保存定义的试运行，只返回样本，不写结果或运行任务 |
| POST | /api/perf/metrics/{metricCode}/execute | 单指标执行；默认异步，可选择级联和分配日期 |
| POST | /api/perf/metrics/batch-execute | 批量执行指标；请求体包含 metricCodes、dataDate、async、reason |

指标逻辑支持 SQL、表达式等源码执行路径；槽位由服务校验。单指标异步响应的 PENDING 只表示已受理，线程池拒绝时返回/记录 FAILED；真实终态通过运行任务查询取得。

## 7. 外部数据任务状态

POST /api/data-task/status 接收 taskId、dataType、dataDate、version、status 等字段；dataType 当前支持 ALLOC_RELATION、EMP_INDEX_RESULT、ORG_INDEX_RESULT、CUST_INDEX_RESULT，status 只接受 SUCCESS 或 FAILED。taskId 幂等命中时返回既有 PERF_RUN_TASK，不创建重复任务。该入口无通用 BizAuth 注解，按外部认证链路保护，并记录 DATA_TASK_STATUS_REPORT 审计。

## 9. 错误与兼容性

业务错误统一使用 performance 的错误码和 ResponseWrapper，不在文档维护一份独立完整列表。调用方应处理资源未授权、数据范围冲突、版本冲突、任务不存在/过期、校验失败和下游文件/流程失败，并以实际 HTTP 响应为准。
