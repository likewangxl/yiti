# COMMON 基础层 — 后端架构

> 本文只记录稳定的装配边界和请求链路。具体类、依赖版本和子模块清单以源码与 POM 为准，不在此维护重复目录。

## 1. 架构决策与边界

- common 是平台公共基础设施层，向业务模块提供统一 Web 模型、链路追踪、安全元数据、AOP 和数据库基础设施；不承载客户、流程、绩效等业务规则。
- 依赖方向保持单向：业务模块可以依赖 common，common 不依赖任何业务模块。common 不提供业务 Controller，不直接持有业务 Entity/Mapper，也不接入 Flowable、业务对象存储或业务数据表。
- `common-web` 负责统一响应/异常、分页、JDBC 锁和 sidecar 通用客户端；`common-trace` 负责 traceId/MDC；`common-security` 负责 `@BizAuth`、数据范围上下文和安全工具；`common-aop` 负责接口日志、计时和审计 SPI；`common-db` 负责 MyBatis-Plus、审计字段、分页及慢 SQL 基础设施。
- 跨模块公共契约使用 common 暴露的强类型 DTO、注解、枚举和上下文。鉴权判定由 auth-permission-center 执行，Flowable 由 workflow-center 执行，审计持久化由治理模块提供实现。
- 跨实例互斥使用 common-web 的 `LockManager`/`JdbcLockManager` 与 `PT_LOCK`；Session 使用 Spring Session JDBC。common 不以 Redis 作为这两类能力的替代实现。

## 2. 自动装配边界

每个 common 子模块通过 `src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 声明自己的自动配置。自动配置只装配本模块公共基础设施，并允许按 Spring profile 或配置属性禁用/调整；新增自动配置时必须同步 imports 并用最小上下文测试验证。

装配职责保持如下边界：

| 能力 | 装配责任 |
|:---|:---|
| Web 模型、全局异常、CORS、锁和 sidecar 客户端 | common-web |
| traceId Filter/Interceptor 与 MDC | common-trace |
| 数据范围清理 Filter、安全上下文与安全工具 | common-security |
| API 日志、耗时、审计切面及 Handler SPI | common-aop |
| MyBatis-Plus、Druid、分页、审计字段和慢 SQL | common-db |

业务模块通过依赖对应 common 子模块获得能力；不得绕过自动配置自行 `new` 公共实现，也不得在业务模块复制平行拦截器链。

## 3. 请求处理链路

```text
HTTP 请求
    |
    +--> TraceIdFilter：读取或生成 traceId，写入 MDC
    |
    +--> 业务模块的认证/授权入口
    |      +-- auth-permission-center 建立 CurrentUserContext
    |      +-- 授权模块解析资源、@BizAuth 和数据范围
    |      +-- common-security DataScopeContext 保存请求级范围
    |
    +--> Controller -> Service -> Mapper
    |      +-- common-aop 按注解记录接口、耗时和审计事件
    |      +-- common-db 提供分页、审计字段和 SQL 拦截基础设施
    |
    +--> GlobalExceptionHandler：映射可预期异常
    |
    +--> ResponseWrapper 或明确声明的文件流/重定向响应
    |
    +--> 请求完成：清理 MDC、CurrentUserContext 和 DataScopeContext
```

ThreadLocal 上下文必须在正常、异常和异步任务路径清理；Filter 兜底不能替代异步任务的显式传播与清理。分页排序字段必须经过白名单校验，数据库实体映射必须以真实 schema 为准。
