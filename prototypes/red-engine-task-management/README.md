# 红色引擎任务管理与任务处理原型

这是独立的前端可交互原型，用于演示红色引擎新增“任务管理”“任务处理”页面及工作台待办分支。原型延续现有红色引擎后台的 275px 深棕侧栏、60px 红色顶栏、浅灰内容背景、白色卡片和 Element Plus 风格的表格/表单/分页密度；不改动现有生产页面。

## 新增功能说明

- 任务管理：组织管理员查看已发布任务，按标题、任务性质、任务类型和周期查询，并从“新增任务”发布定时任务或临时任务。
- 新增任务：支持四大维度材料上报、党建学习、通知确认、整改反馈和其他任务类型；任务对象默认本组织全员，也可选择指定人员；按需开启文件上传并选择允许的 PDF、Word、Excel、图片或压缩包类型。
- 任务处理：一线员工查看当前时间窗内收到的任务，支持标题、性质、状态、周期筛选；普通任务可进入详情、上传文件（若任务要求）并提交。
- 工作台待办：仅展示当前处于时间窗且未完成的任务。提交普通任务后变为已完成，并从首页待办中移除。
- 四大维度分支：四大维度材料任务点击后进入只读说明态，明确继续使用现有“四大维度材料上报”入口，不重做原页面。
- 链接与上传：任务说明中只有 `http://`、`https://` URL 转为新窗口安全链接；上传要求为“否”时隐藏文件类型，要求为“是”时类型必填并在详情显示限制。

## 入口说明

左侧导航保留现有菜单，并仅新增以下两个入口：

1. 任务管理：组织管理员入口，默认展示已发布任务列表；点击“新增任务”进入发布表单。
2. 任务处理：一线员工入口，展示当前时间窗内收到的任务列表。
3. 工作台：待办事项卡片展示当前任务；点击普通任务进入通用详情，点击四大维度任务进入既有上报入口说明态。

右上角“演示身份”仅是原型辅助切换，不代表正式业务权限：

- 组织管理员：切换到任务管理。
- 一线员工：切换到工作台，可再进入任务处理。

## 字段清单

| 字段 | 适用场景 | 说明 |
| --- | --- | --- |
| 任务性质 | 全部 | 定时任务 / 临时任务 |
| 任务类型 | 全部 | 四大维度材料上报、党建学习、通知确认、整改反馈、其他 |
| 任务标题 | 全部 | 单行文本，必填 |
| 任务说明 | 全部 | 多行文本，必填；可粘贴网页链接 |
| 任务对象 | 全部 | 本组织全员（默认）或指定人员，必填 |
| 周期 | 定时任务 | 每周初、每周末、每月初、每月末、每季度初、每季度末 |
| 持续天数 | 定时任务 | 正整数；不能超过对应自然周期 |
| 开始时间 / 截止时间 | 临时任务 | 均必填，截止时间不能早于开始时间 |
| 是否要求上传文件 | 全部 | 是 / 否；默认否 |
| 允许文件类型 | 上传要求为是 | PDF、Word、Excel、图片、压缩包，多选且至少一种 |

列表字段包含标题、任务类型、任务性质、周期/时间窗、任务对象、文件要求、发布时间、状态和操作；详情字段包含上述任务信息、说明链接、上传控件及扩展名限制。

## 业务分支说明

- 定时任务从下一个完整周期生效。开始锚点型周期（每周初、每月初、每季度初）从锚点日开始顺延；结束锚点型周期（每周末、每月末、每季度末）从锚点日向前倒推 `持续天数 - 1` 天。
- 自然日包含首尾。周最大 7 天；月、季度按实际生成周期校验，超出时发布校验失败。
- 若结束锚点型周期的当前窗口已经开始，则跳过当前窗口，计算下一自然周期，避免任务发布后补进已开始的窗口。
- 任务发布后生成员工任务实例；只有窗口开始后进入工作台待办。任务处理列表可继续展示已完成记录，但首页待办只过滤 `pending` 状态。
- 四大维度材料任务不进入通用任务详情填报，进入现有上报入口的说明态。

## 原型假设/待产品确认

- 原型用本地 mock 数据演示“本组织全员”和指定人员，实际人员范围、组织树和权限由正式 RBAC 契约确认。
- “发布后生成员工实例”在原型中由内存状态模拟；正式实现需确定实例幂等、周期重复生成、跨组织数据范围和截止后状态规则。
- 四大维度材料上报的真实入口地址、完成回写和文件交接契约需与现有页面确认。
- 文件大小、病毒扫描、对象存储路径、重复上传和文件删除规则暂未定义；原型只展示允许扩展名。
- 预览以本地浏览器日期计算；定时任务仅支持指定的六种周期，不包含任意 Cron 表达式。

## 非目标/验证边界

- 纯前端演示数据，不接 API、数据库、RBAC、OBS、Quartz、消息或真实员工数据。
- 不是联调结果，也不是生产实现；不会修改 `xanzc_frontend` 现有页面、路由、接口、配置或后端模块。
- 不审计现有页面缺陷，不优化既有逻辑，不重做四大维度材料上报页面。
- 浏览器刷新会丢失本次发布和提交状态；原型不提供持久化、登录和退出能力。

## 本地运行

在 macOS/Linux 或已安装 Node.js 的终端中：

```bash
npm install --prefer-offline --no-audit --no-fund
npm run dev -- --host 127.0.0.1 --port 4173 --strictPort
```

浏览器打开 `http://127.0.0.1:4173`。

### Windows 演示

Windows 需要预先安装 Node.js 18 或更高版本（自带 npm）。将整个原型目录复制到 Windows 后，双击项目根目录的 [`start-windows.cmd`](./start-windows.cmd)。脚本会检查 `node`/`npm`，首次在 Windows 运行时执行 `npm install --prefer-offline --no-audit --no-fund`，以避免误用从 Linux 复制来的平台相关依赖；随后启动 Vite 到固定地址 `http://127.0.0.1:4173` 并打开默认浏览器。

首次安装依赖需要可用的 npm 网络或本地缓存；依赖安装完成后，启动原型可离线运行。脚本不需要 Java、MySQL 或任何后端服务，不包含凭据，也不会修改项目目录之外的文件。依赖安装失败时会保留命令窗口并输出中文提示，便于检查错误。
