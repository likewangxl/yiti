# 红色引擎任务协同原型

这是独立的前端可交互原型，仅演示本轮新增与调整的任务、填报、支部审核、组织审核和预警池流程。原型复用现有红色引擎后台的 275px 深色侧栏、60px 红色顶栏、浅灰内容区、白卡片、表格密度和 Tabler 图标，不修改生产前后端或既有页面元素。

## 新增功能说明

- 报送员端将原上报记录重命名为“上报信息”，任务处理合并为四个页签：待处理、审核中、已通过、已驳回。
- 报送员待处理/审核中页签支持任务标题、任务性质、周期查询。四大维度材料任务进入既有材料上报入口；临时任务标题实际打开独立窗口，支持多行填报、附件上传和提交。
- 临时任务统一按 reporter-pending → branch-pending → org-pending → approved/rejected 流转。提交后父窗口通过 postMessage 同步为审核中；组织驳回后回到报送员已驳回页。
- 支部书记只保留首页、支部审核工作台和红黄牌预警池。支部工作台同样有四个页签，待处理详情支持先“审核通过”，再“提交至组织审核”。
- 组织审核员不展示四大维度材料上报和上报信息，使用原沉浸式工作台更名后的“工作台”，左侧可筛选四大维度材料上报/临时任务；临时任务可查看支部内容、下载附件、驳回或提交通过。
- 任务管理列表支持查看各支部填报时间、内容和附件。一键导出展示 ZIP 结构预览，Excel 字段为任务名称、任务发布时间、结束时间、提交人、提交时间、填报内容；附件按党支部子文件夹归档。原型只模拟结构，不生成真实压缩包。
- 四大维度材料任务支持每个明细项重复上传；某明细上传次数大于等于 1 即判定该季度完成。明细项示例包含联建规范度、合作契约化、业务转换实质，实际来源按字典配置扩展。
- 首页按角色展示不同指标：组织管理员和组织审核员保留任务概览，并在待办区域并列展示支部排名（支部名称、得分、排名）；报送员和支部书记展示所在机构得分、所在机构排名，不展示全员达标率。
- 组织管理员和组织审核员均不展示“年度考核归档”“数据导出”菜单，相关查看与导出能力由任务管理承接。
- 红黄牌预警池对所有角色开放红牌支部、黄牌支部；只有组织管理员显示逾期上报待执行扣分板块，并提供查询、分页、扣分录入。逾期未上报不进入表格，页面保留后续通知说明。

## 入口说明

- 组织管理员：任务管理、上报信息、四大维度材料上报、红黄牌预警池及其余管理菜单；不展示年度考核归档、数据导出。
- 报送员：首页、四大维度材料上报、上报信息、红黄牌预警池。
- 支部书记：首页、支部审核工作台、红黄牌预警池。
- 组织审核员：组织管理员的其余管理能力、任务管理、工作台、红黄牌预警池；不展示四大维度材料上报、上报信息、年度考核归档和数据导出。
- 左上侧栏中的“任务处理”入口已完全移除。右上角“演示身份”用于切换四种原型视角，不代表正式 RBAC。

## 字段清单

首页：组织角色的待办事项、已完成任务、本组织任务和支部排名（支部名称、得分、排名）；报送员/支部书记的待办事项、所在机构得分、所在机构排名。

任务管理/新增任务：任务性质、任务类型、任务标题、任务说明、任务对象、周期、持续天数、开始时间、截止时间、是否要求上传文件、允许文件类型、发布时间。

上报信息/支部审核：任务标题、任务说明、任务性质、周期或临时任务标识、截止时间、提交人、提交时间。历史页签中，四大维度保留维度、考核项、审核状态、审核意见、端员得分；临时任务仅展示维度=临时任务、考核项=任务标题、提交人、提交日期。

组织工作台/任务详情：任务配置、支部、填报时间、填报人、填报内容、附件下载、审核操作。导出预览字段固定为任务名称、任务发布时间、结束时间、提交人、提交时间、填报内容。

预警池：红牌支部、黄牌支部；组织管理员另有任务类型、任务名称、任务内容、对应党支部、任务开始时间、任务结束时间、上报人、上报时间、扣分。

## 业务分支说明

1. 报送员提交临时任务后 stage 变为 branch-pending，报送员看到审核中，支部书记看到待处理。
2. 支部书记必须先审核通过，随后才能提交至组织审核；stage 变为 org-pending，报送员和支部书记均看到审核中。
3. 组织审核员提交通过时进入 approved；直接驳回时进入 rejected，报送员在已驳回页查看组织审核意见。
4. 四大维度材料任务保持既有入口分支。材料明细上传可以重复，单明细首次上传即完成本季度该明细。
5. 结束锚点型定时周期从周期末向前倒推，开始锚点型从周期初向后顺延，持续天数不能超过对应自然周期；此规则沿用前一版原型域逻辑。
6. 预警规则文案暂定红牌为连续两季度排名倒数第一、黄牌为连续两季度倒数前五，后续规则可调整。逾期未上报数据不进入扣分列表，另行通知相关角色。

## 原型假设与验证边界

- 数据全部为浏览器内存 mock，不接真实 API、数据库、RBAC、Quartz、OBS、消息服务或组织数据。
- popup 使用同源 URL 和 postMessage 模拟跨窗口回传；浏览器禁止弹窗时，自动回退到当前窗口填报。
- 附件下载、ZIP 导出、原有四维度入口均为原型模拟动作；不写入文件、不生成真实 ZIP，也不重做原有材料页面。
- 组织树、人员范围、文件大小/病毒扫描/存储策略、通知方式、导出真实格式和字典维护接口留待正式契约确认。
- 不审计既有页面缺陷，不优化既有逻辑，不修改 xanzc_frontend、后端模块、Sites 配置、既有证据或设计 QA 文件。

## 本地运行

需要 Node.js 18 或更高版本。进入本目录执行 npm install --prefer-offline --no-audit --no-fund，再执行 npm run dev -- --host 127.0.0.1 --port 4173 --strictPort，浏览器打开 http://127.0.0.1:4173。

Windows 可双击 start-windows.cmd；脚本会检查 Node/npm，首次运行安装依赖并启动 Vite。原型不需要 Java、MySQL 或后端服务。

## 验证命令

node --test tests/*.test.mjs

npm run build

npm run test:sites

构建后应生成 dist/client/index.html、dist/server/index.js 和 dist/.openai/hosting.json。浏览器验收需使用官方 playwright-cli，对角色菜单、popup 提交、两步支部审核、组织通过/驳回、任务详情/导出预览、四维重复上传和预警池差异进行检查。
